# Исполнение шага роадмапа (docs-first)

## На какой вопрос отвечает этот файл

Как устроен процесс исполнения одного шага продуктового
роадмапа.

## Назначение

Процесс описывает последовательность под-шагов, через которые
проходит каждый шаг роадмапа от старта до завершения. Подход —
**docs-first**: концепция в `docs/` доводится до целостности
**до** написания кода; код пишется по проработанной концепции и
при отклонении синхронизирует доки.

## Под-шаги

Один шаг роадмапа исполняется по следующей последовательности.

### 1. Tooling (создать агенты/скиллы под потребность)

Если для исполнения шага нужны новые агенты, скиллы или процессы
— создаются здесь. По потребности шага, не превентивно. Если
ничего нового не нужно — под-шаг проходится без артефактов.

**Статус шага:** `TOOLING`.

### 2. Проверка целостности концепции доков

Сквозной обход документации, релевантной шагу: модели, lifecycles,
процессы, правила, словарь. Цель — найти пробелы в концепции
(несогласованности, пустоты, неотвеченные вопросы), которые
помешают писать корректный код.

Помимо концептного фокуса (`concept-review`) проверка включает
**торговый фокус** (`trading-review`) — адверсариальный проход по
торговой корректности модели. Торговые находки — отдельная
категория пробелов в том же gap-отчёте, не отдельная петля (см.
«Торговая категория в петле» ниже).

**Статус шага:** `DOCS_CHECK_N`, где N — номер итерации (1, 2, ...).

### 3. Закрытие пробелов концепции

По каждому найденному пробелу: разбор → решение → правка доков.
Находки разбирает **CC автономно** в ролях владельцев по карте
(`.claude/processes/question-delegation.md`): проектные развилки
решаются на месте и фиксируются в дайджесте решений
(`.claude/work/decision-digest.md`); пользователю выносится только
дефицит `подтверждение` (цели, приоритеты, продуктовый scope и
намерение, численный риск-аппетит, сроки). Источниковый дефицит не
закрывается выдумкой — эскалация (`question-delegation.md`
§«Источниковый дефицит»).

**Закрытие находки — по её собственному списку цитат.** Закрытие
любой находки `DOCS_CHECK_N` обязано пройти по списку цитат самой
находки из отчёта и отметить каждую цитату: правлено / не требует
правки — почему. Перечень носителей берётся из отчёта, а не
собирается заново: находка называет носители поимённо, и класс
дефекта «обоснование верно для части носителей, а дано безусловно»
воспроизводится, когда список не перепроверяется при закрытии.

**Правка политики идёт через её дом.** У каждой политики один
носитель-дом; остальные носители ссылаются, не пересказывают
(`.claude/rules/policy-home.md`). Закрытие меняет формулировку **в
доме** и проверяет **указатели**; обнаруженный по пути пересказ
политики вне дома сводится к ссылке той же правкой.

**Популяция правила предъявляется до правки, а не после** (решение
держателя 2026-08-31,
`.claude/decisions/closure-completeness-by-population.md`). Закрытие
гейтящего узла **начинается** с перечня состояний и носителей, на которых
правило узла обязано выполняться, и правит правило **по перечню**, а не по
состоянию, породившему находку. Процедура построения перечня — осей,
механическая добыча членов, критерий предъявленности — живёт в скилле
`.claude/skills/closure-population.md`; дом процесса её не пересказывает.
Здесь — норма и её место в порядке действий:

- перечень строится **до первой правки узла**: собранный после, он
  описывает сделанное, а не задаёт границу;
- у каждого члена перечня **ровно один** записанный исход — правило
  выполняется (назван носитель либо актор и момент), правило правлено этим
  закрытием (сказано, чем), член недостижим (названо, **чем именно** он
  исключён). Пустая клетка закрытием не считается: то же требование, что у
  писателя значения (`docs/rules/writer-named-for-every-value.md`),
  поднятое со значений перечня на состояния и носители вообще;
- **перечень выводится из предмета, а не из наличного текста.** У оси,
  выразимой в исполнимой спецификации, популяция несёт ключ `derive`:
  либо `command` — команду, выводящую членов из предмета (объявление enum
  в `<дерево кода>/src/**`, таблица переходов lifecycle-дока, поверхность источника по
  контракту, перечень действий эталонного артефакта) — плюс `from`,
  артефакты, которые команда обязана читать; либо `incomplete` —
  названную причину, по которой ось выводима **только грунтом**. Сверка
  объявленного перечня с выведенным — `python3 tools/population-derive-check.py`;
  объявленная неполнота печатается поимённо, молчаливого пропуска нет;
- **член покрыт проверкой правила на нём, а не присутствием кортежа.**
  Популяция называет ключом `rule` величины **правила**, и пример
  засчитывается покрытием члена, только когда ожидает хотя бы одну из
  них. Недостижимый член предъявляет контрпример с ключом `unreachable`,
  тоже проверяющий на нём правило;
- **фильтр участия называет исключаемый класс и выразим только
  операндами.** При ключе `where` обязателен `excludes` — имя класса,
  который фильтр выводит из популяции; ссылка фильтра на объявленную
  величину запрещена: вычисленный вердикт в условии участия выводит из
  перечня ровно те состояния, на которых правило и проверяется. Все три
  требования — препятствия базового гейта `bash tools/spec-run.sh`, оси
  доказаны батареей `bash tools/spec-mutation-check.sh` (25-32);
- **собственный артефакт закрытия — член популяции.** Ключ спеки, строка
  таблицы, предписание исполнителю, написанные самим закрытием, читаются
  **как текст** и прогоняются своим инструментом. Класс, против которого
  клауза стои́т: дубль ключа в спеке, персистентная запись ниже ветви
  пропуска и ложное расписание в предписании — все внесены закрытием и
  найдены следующим прогоном, потому что критика смотрела на конструкцию,
  а не на текст правки.

Требование **не** заменяет обхода потребителей: обход — механическое
средство добычи носительской оси, перечень — форма записи её исхода.
Исполнение — гейтом при смене статуса
(`.claude/skills/update-roadmap-progress.md` §«Гейт выхода из
`GAPS_CLOSE_N`»). Класс, против которого норма заведена: правка
принималась по тому, что верна на состояниях, ради которых писалась, — и
пять узлов подряд вернулись гейтящими после собственного закрытия, каждый
на популяции, в перебор не вошедшей.

**Редакция происхождения и критерия покрытия — решение держателя
2026-08-31** (`.claude/decisions/population-origin-and-code-gate.md`).
Первая редакция нормы вводила перечень и его исполнимость, но не
называла ни происхождения членов, ни критерия покрытия — и перечень
собирался из того же текста, который проверял: члены совпадали с
кортежами наличных примеров, фильтр `where` исключал фальсифицирующее
состояние, покрытие считалось присутствием кортежа. Три линзы предъявили
это порознь, каждая пробой. Снятая формулировка предписывала популяции **отдельную величину,
считающую покрытие**, и её мутационную пробу: механизм такой величины не
производит и никогда не производил — покрытие считает раннер по ключу
`populations`. Предписание было неисполнимо в трёх носителях сразу.

**Гейтящий узел закрывается до исполнимой глубины, а не до
формулировки** (решение держателя 2026-08-29,
`.claude/decisions/gating-node-closure-depth.md`). Закрытие гейтящего
узла состоялось, только когда доведены **все четыре** пункта:

- политика/решение сформулировано;
- носитель назван и **существует** (дом политики, модель, спека) — не
  обещан будущим ходом — и обойдены **все потребители** введённой или
  правленной величины/предиката (усиление пункта — пассаж ниже);
- механика прописана: кто читает, когда срабатывает, чем резолвится;
- если клейм счётный (формула, предикат, инвариант) — исполнимый
  spec-пример (`docs/spec/`, прогон `tools/spec-run.sh` /
  `SpecRunnerTest`).

**Узел отвечает за всех потребителей, не только за собственный механизм**
(решение держателя 2026-08-29, поправка по итогам первого измерения —
`.claude/decisions/closure-mechanism-amendments.md`). Для введённой или
правленной величины/предиката все **писатели и читатели** перечисляются
механическим средством по корпусу (греп имени величины и терминов её
тропы чтения по `docs/**`, `<дерево кода>/src/**` и живым `.claude/**`), и каждый
сверяется с новой редакцией; перечень — в чек-лист глубины пофайлово, с
исходом «согласован / правлен / не потребитель — почему». Класс, против
которого пункт усилен, — «следующий слой того же узла»:
предикат заведён и верен, назначенный читатель назван, а прочие
потребители — писатели персистируемых чисел, соседние предикаты — о нём
не знают. Граф-артефакт связей не строится: обход делается механическим
поиском на каждом закрытии (отвергнутая альтернатива — в решении).

**Обход идёт двумя формами поиска, и одного имени мало** (уточнение
первым применением). Носитель, который требует величину
**прозой** («базу риска не двигает», «закреплённая деталь стратегии
есть»), имени поля не содержит, и греп по имени его не берёт. Поэтому
рядом с грепом имени идёт греп по **формулировке тропы чтения**, и оба —
**терпимые к переносу строки** (`grep -rlUzP '(?s)…'`): построчный проход
не видит фразу, разорванную переносом. Замер, на котором записано: по
одной величине греп имени дал 12 файлов, прозаический — 21, и среди
добавленных был писатель, чью редакцию правка обязана была затронуть.
Перечень потребителей, собранный **только** грепом имени, пунктом глубины
не засчитывается.

**Каталог обхода — не только `docs/**`.** Предписания исполнителю живут в
живых `.claude/**` (`work/backlog.md`, `work/progress/`, правила,
процессы, тесты), и потребитель величины там — такой же потребитель.
Обход, ограниченный корпусом, пропускает ровно тот класс, где инструкция
исполнителю отстаёт от конструкции: CODE-инструкция описывала две ветки
из трёх и предписывала затирание, ради запрета которого третья ветка
заведена. Клауза охвата стои́т здесь, а не в отчёте узла: записанная в
отчёт, она до соседних узлов того же закрытия не доезжает — измерено на закрытии, где второй узел с тем же дефектом охвата остался
незатронутым.

**`grep -P` в этой среде требует `LC_ALL=C.UTF-8`.** Без него проход
падает с ошибкой в stderr и **пустым** списком файлов, что читается как
чистый свип.

**`\w`, `` и `\d` в `grep -P` кириллицу не берут, и молчат об этом.**
PCRE по умолчанию считает эти классы ASCII-только, поэтому шаблон по
русскому слову (`окружени\w+`, `снят\w+ редакци\w+`) даёт **ноль
попаданий на корпусе, который весь написан по-русски**, и ноль читается
как «вхождений нет». Замер, на котором записано (обе стороны, одна
команда, разница только в классе): `окружени\w+` по `docs/**` — **0**
файлов, `окружени[а-яё]+` по тому же корпусу — **3**, и все три были
носителями правленого правила. Рабочих форм две: класс кириллицы
явным диапазоном (`[а-яё]+`) либо модификатор `(*UCP)` **в самом начале**
шаблона, до `(?s)` — внутри группы `(?s...)` он не разбирается и валит
разбор («unrecognized character after (? or (?-»). Это тот же класс, что
у локали абзацем выше и у `python3`-заглушки: команда, недомерившая
молча, неотличима от команды, не нашедшей нарушений.

*Инструментов это не касается механически:* `re` в Python считает `\w`
юникодным по умолчанию, а команды `tools/derive/` матчат ASCII-идентификаторы
(`[A-Z_]`, `[A-Za-z]`) либо объявляют кириллический диапазон явно. Ловушка
живёт ровно там, где шаблон пишут **разово** — в свипах закрытия. Класс тот же, что у `python` и `python3` против `py`:
обе заглушки печатают «Python» и выходят, ничего не выполнив, поэтому
мутация, поданная через них heredoc-ом, файл **не меняет**, а следующий
прогон читается зелёным — подмену проверяют грепом до прогона. Команда,
провалившаяся молча, выглядит как команда, не нашедшая нарушений.

**Отрицательный клейм собирается с полного вывода, а не с первого
экрана.** «Других читателей нет», «носителей не осталось», «вхождений
ноль» — утверждения про **хвост** выдачи, поэтому команда, оканчивающаяся
`| head -N`, доказать их не может: она читала начало. Отрицательные клеймы
подтверждаются счётом (`| wc -l`) или полным выводом. Кейс, на котором
записано: узел объявил, что у правленого предиката читатель один, — второй
стоя́л в хвосте вывода той же команды, усечённой `| head`, и был найден
только независимой сверкой. Ординал строки сюда не выписан намеренно: он
величина того состояния корпуса и задним числом не пересчитывается, а
механизм от неё не зависит.

**Измерительная команда проверяется на полноту формы предмета.** Все
ловушки выше — частные случаи одного: команда меряет **одну письменную
форму** того, что предъявлено как измеренное целиком. Класс встретился в
одном закрытии трижды и каждый раз давал заниженное число, которое
выглядело точным: счёт долга видел `§«Имя»` и не видел `§Имя` (141 против
201 — треть долга); перечень потребителей видел имя величины и не видел
её прозаическую формулировку; счёт перекрёстий видел адреса со словом
«выше»/«ниже» и не видел прочие (шесть против сорока двух). Поэтому,
предъявляя число как измеренное, называют **и** команду, **и** то, какие
формы предмета она берёт; а прежде чем на него опереться — проверяют
команду встречной формой, которую она по построению не видит. Число без
названного охвата — оценка, а не измерение, и в клейм полноты не годится.

**Пример засчитывается, только если он падает на прежней форме**
(уточнение первым применением). Зелёный прогон
показывает, что пример **исполняется**, а не что он **проверяет**:
величина, объявленная константой, и пример, проходящий на обеих формах,
не доказывают ничего. Доказательство — **откат**: прежняя форма
возвращается во временную копию (`SPEC_DIR=target/probe-… bash
tools/spec-run.sh`), и в отчёт идут **обе стороны** — сколько расхождений
дала прежняя форма и что прогон зелен после возврата. Пример, проходящий
на обеих формах, помечается **парным** и доказательством не считается.
Кейс: величина-константа `expr: "false"` проходила любой прогон и ловила
ноль, тогда как откат соседнего узла на тех же правилах дал шесть
расхождений.

**Пример стои́т на достижимом состоянии.** Состояние, недостижимое по
построению тропы (цена эпизода на первом входе, непустой результат при
нулевом филле), доказывает несуществующее: правку оно пропускает, а
дефект — нет. Проверка достижимости — часть пункта, а не отдельная
любезность.

**Там, где код уже написан, достижимость проверяется и по нему**
(уточнение первым применением). Валидация, стоящая в
`<дерево кода>/src/**`, отсекает часть состояний до того, как до них доберётся любая
проверка корпуса, — и пример, предъявляющий такое состояние законным,
описывает вход, который система отвергает. Замер: узел закрывал дыру,
достижимую лишь при необязательном поле, тогда как api-модель держала это
поле обязательным, а валидатор отвергал запрос без него; два примера из
трёх стояли на состоянии, которого система не принимает. Побочный вывод
того же кейса: **обязательность, живущая только в коде, — дефект
корпуса.** Правило, которое система исполняет, обязано иметь дом в
`docs/**`; ненайденное в корпусе не означает несуществующего в системе, и
обход потребителей поэтому включает `<дерево кода>/src/**` наравне с корпусом и живыми
`.claude/**`.

**То же — у команды, объявленной проверкой.** Воспроизводимая команда
(греп, `diff`, скрипт) засчитывается носителем проверки счётного клейма
только после прогона на **двух** состояниях: до правки (вывод непуст) и
после (пуст). Один прогон показывает, что команда исполняется, а не что
она меряет тот предмет. Кейс: команда сверки двух реестров, написанная
против конкретной находки, на состоянии, эту находку породившем,
давала пустой вывод — она сравнивала множества там, где дефект был в
парах.

**Оси проверочной команды доказываются поимённо** (решение держателя
2026-08-29, `.claude/decisions/closure-mechanism-amendments.md`).
Команда, объявляющая несколько осей (предметов измерения), доказывается
**падающей пробой по каждой объявленной оси**, а не фактом падения хоть
на чём-то: падение на одной оси не устанавливает остальных. Проба —
воспроизводимая мутация во временной копии носителя, вводящая дефект
ровно этой оси; засчитывается, только когда даёт ненулевой код/непустой
вывод при зелёном прогоне на действительном состоянии (зелёная проба —
признак, что мутация перестала попадать в носитель, и проба
переякоривается). Кейс: скрипт предусловий был «доказан» регрессией на
одной оси из трёх объявленных — и отвечал «СОШЛОСЬ» на дефекте оси
разведённости слота (`ДЕФЕКТ` в stderr при коде возврата 0) и на
нечитаемой форме плановой стороны слот-сверки; ложный зелёный успел
сработать доказательством в слое верификации.

**Мутационная проба — условие приёмки спеки, а не только правки**
(решение держателя 2026-08-30,
`.claude/decisions/proof-method-change.md`). Величина исполнимой
спецификации считается проверенной, только когда объявленные проверки
падают на её нейтрализации (замена выражения константой, гашение
предиката). Это обобщение стандарта §«Оси проверочной команды
доказываются поимённо» с команд на спеки и распространение правила
§«Пример засчитывается, только если он падает на прежней форме» с
дельты правки на **наличное тело спек**: клейм «спека проверена»
подтверждается мутационным замером по всему телу величин, а не по
дельте закрытия. Механизм, применяемый только к правкам, до
накопленного не достаёт — измерено прогоном, где при четырёх зелёных
инструментах нейтрализацию пережили 47 из 350 величин, среди них
восемь create-проверок и пятнадцать инвариантов, чьи ноты дословно
требовали падения.

**Команда замера введена и прогоняется по всему телу спек** —
`bash tools/spec-mutation-check.sh`. Она подменяет каждую объявленную
величину константой — базовым набором и **литералами самого корпуса**,
поэтому число, ожидаемое во всех примерах одним и тем же номиналом,
ловится наравне с предикатом, ожидаемым везде одним исходом. Батарея осей
исполняется **той же командой** до замера. Код возврата 1 при непустом
перечне, 2 — замер не проводился; клейм «спека проверена» без её нулевого
прогона не даётся.

**Охранный инвариант доказывается предъявленным контрпримером**
(решение держателя 2026-08-30,
`.claude/decisions/acceptance-by-measurement.md`). Часть охранных
инвариантов ложна на всём достижимом пространстве состояний по построению
модели («снятие холда не переводит объект в рабочее состояние»), и
фальсифицирующего примера **среди достижимых** у них нет. Ярлыка-исключения
для них не заводится: ярлык удостоверяет наличие указателя, а не свойство
величины. Вместо ярлыка — **предъявленное состояние**: пример с ключом
`"unreachable": "<чем состояние исключено>"`, на котором инвариант
принимает запрещённое значение. Величина с контрпримером падает на
нейтрализации наравне со всеми.

**Инвариант, для которого контрпримера не существует, — не величина, а
переобъявление.** Если запрещённое значение недостижимо ни при каком
состоянии операндов, содержание инварианта целиком влечётся соседней
формулой, и он есть второй носитель её истины (`.claude/rules/carrier-levels.md`).
Такой инвариант снимается, а его клейм переезжает в **ноту величины-дома**
с указанием примеров, которые клейм несут. Замер: из пятнадцати величин,
стоявших на снятом ярлыке, двенадцать оказались переобъявлением, две
получили контрпримеры, одна — дефектом, ложным на достижимом состоянии.

Приёмка каждой новой или правленной величины доказывается пробой
нейтрализации с обеими сторонами в отчёте; наличное тело спек доведено
до стандарта дизайн-проходом приёмки: недоказательных **ноль** при
полном перечне величин. Число величин здесь не хранится — его печатает
прогон.

**Измерительная команда отказывается, когда мерить нечего** (решение
держателя 2026-08-30, `.claude/decisions/acceptance-by-measurement.md`).
У команды-проверки **три исхода, а не два**: `0` — измерено, дефектов нет;
`1` — измерено, дефекты есть; **`2` — не измерялось**. Третий код отделяет
«дефектов нет» от «мерить было нечем» — различение, отсутствие которого и
давало ложный зелёный. Обязательны все три условия отказа:

- **базовый гейт** — вход разобран и непуст (каталога нет, предмета нет,
  индекс пуст, немутированный корпус не зелен ⇒ код 2);
- **системный отказ отделён от расхождения** — нечитаемый артефакт,
  неразобранный файл, несобранное состояние падением проверки **не**
  засчитываются: иначе сломанный вход выглядит лучше здорового, и «упало
  везде» читается как «проверка сработала везде»;
- **батарея осей исполняется той же командой** и до измерения; недоказанная
  ось ⇒ измерение не проводится. Отдельных `*-probe.sh` больше нет:
  батарея, которую можно не запустить, принимается по тому же основанию,
  которое стандарт снимает.

Кейс, на котором записано: замер, объявленный воротами приёмки спеки, на
корпусе с непрочитываемыми артефактами печатал «ВСЕ ВЕЛИЧИНЫ
ДОКАЗАТЕЛЬНЫ» с кодом 0, тогда как прогон примеров того же корпуса падал
с кодом 1.

**Полнота письменных форм предмета — обязательное свойство детектора**
(то же решение). Детектор **объявляет в шапке**, какие письменные формы
своего предмета он видит, и **доказывает каждую** осью батареи. Форма, не
названная в перечне, им не измерена, и клейма полноты он на неё не даёт.
Пассаж §«Измерительная команда проверяется на полноту формы предмета»
выше говорит то же про **разовую** команду закрытия; здесь требование
поднято до **свойства инструмента**: перечень форм живёт в самом
инструменте и проверяется его же прогоном. Замер: три детектора корпуса
мерили одну форму из пяти, одну из трёх и половину собственного правила —
и печатали числа, выглядевшие полными.

Чек-лист глубины проставляется в отчёте закрытия по каждому гейтящему
узлу — пунктами поимённо, не общей фразой. Если глубина недостижима
из-за источникового дефицита или дефицита `подтверждение` — это
**штатная эскалация** (`.claude/processes/question-delegation.md`), а
не повод опустить планку: узел помечается незакрытым, эскалация — в
отчёт. Дефект, против которого критерий заведён: узел закрывался
формулировкой, следующий прогон находил, что у формулировки нет
носителя, следующий — нюансы носителя; петля обратной связи по глубине
решения была длиной в полнокорпусный прогон — свипы проверяют
следствия правки, но не глубину решения, а детектор стагнации ловит
рецидив узла только пост-фактум. Исполнение — гейтом при смене
статуса: `.claude/skills/update-roadmap-progress.md` §«Гейт выхода из
`GAPS_CLOSE_N`» (та же конструкция встречного якоря, что у гейта
свипов).

**Закрытие гейтящего узла проходит мини-петлю критики до приземления в
корпус** (то же решение). Результат закрытия гейтящего узла до
приземления в корпус проходит узкую независимую критику концепт-линзой
(`reviewer`, стойка `concept-review`). Предмет критики — **само
закрытие этого узла**: глубина по критерию выше и согласованность с
соседями (носители, которые закрытие обязано было увидеть); не полный
корпус.

**У критики два предмета, и второй — текст правки** (решение держателя
2026-08-31, `.claude/decisions/closure-completeness-by-population.md`).
Предмет 1 — **конструкция**: верна ли она, полна ли популяция, сходятся ли
соседи. Предмет 2 — **текст, который закрытие написало**: ключи и примеры,
добавленные в спеку, строки таблиц, ноты величин, предписания исполнителю
— перечитанные целиком и прогнанные своим инструментом. Критика, ведомая
только предметом 1, пропускает дефект, внесённый самим закрытием:
конструкция при этом верна, а текст её не выражает. Класс измерен: дубль
ключа в исполнимой спеке, персистентная запись, стоящая ниже ветви
пропуска, и ложное расписание в предписании исполнителю — внесены
закрытием, не пойманы его мини-петлёй, найдены следующим полнокорпусным
прогоном.

Рамки:

- максимум **два раунда** критика → доработка на узел; не сошлось за
  два — остаток фиксируется находкой в отчёте закрытия, узел **не
  считается чистым**;
- потолок раундов ограничивает **пинг-понг доработки, но не отменяет
  проверку финальной правки** (решение держателя 2026-08-29,
  `.claude/decisions/closure-mechanism-amendments.md`): ни одна правка
  закрытия не приземляется без независимого взгляда, включая правки
  последнего раунда — финальная доработка возвращается критику на
  верификацию без права новой доработки (не сошлось → остаток находкой,
  узел не чист). Класс, против которого клауза заведена, — «дефект в
  собственном артефакте закрытия»: правки последнего
  раунда приземлялись непроверенными;
- независимость: критик закрытие не дорабатывает, автор закрытия сам
  себя не критикует;
- правки по итогам критики — хвост закрытия и проходят по правилу
  хвоста (§«Хвост закрытия — такое же закрытие»: свои свипы, свой
  раздел отчёта);
- мини-петля **не заменяет** полнокорпусный `DOCS_CHECK`, не меняет
  условий гейта `CODE`; детектор стагнации работает как раньше.

В отчёте закрытия по каждому гейтящему узлу — **исход мини-петли**:
число раундов, что поймано, что осталось, верифицирована ли финальная
правка. Исполнение — тем же гейтом выхода из `GAPS_CLOSE_N`.

**Узлы закрытия идут посерийно** (решение держателя 2026-08-30,
`.claude/decisions/proof-method-change.md`). Закрытие ведёт гейтящие
узлы строго последовательно: следующий узел не открывается, пока
текущий не чист **со всеми ветками** — мини-петля пройдена, обход
потребителей закончен, финальная правка верифицирована — либо узел
явно помечен незакрытым с остатком-находкой. **Оговорка: межузловые
стыки посерийностью не покрываются.** Стык двух узлов держат обход
потребителей (§«Узел отвечает за всех потребителей, не только за
собственный механизм») и единственность дома стыковой истины
(`.claude/rules/carrier-levels.md`); посерийность их не отменяет и не
заменяет: узел, чистый внутри себя, всё равно обязан обойти стороны
своих стыков.

**`GAPS_CLOSE_N` диспозиционирует все находки прогона** (решение
держателя 2026-08-29,
`.claude/decisions/closure-mechanism-amendments.md`). Каждая находка
`DOCS_CHECK_N` — гейтящая, прочая, гигиена — получает в отчёте закрытия
явный исход: **закрыта** (чем) либо **явно припаркована** с адресатом,
условием возврата и причиной. Как выбирается адресат — дом правила
`.claude/rules/parking-address.md` (носитель, который позицию оживит);
здесь перечень домов не пересказывается. Молчаливого «отдельным
заходом» нет: отложенное без названного носителя и владельца — не
диспозиция, а потеря. Сводка — счётом в отчёте (находок
прогона всего / закрыто / припарковано), и счёт обязан сойтись с итогом
прогона. Класс, против которого правило заведено, — «не взятое в охват
закрытия»: 66 прочих находок и 9 позиций гигиены
предыдущего прогона систематически не закрывались, а отложенные
«отдельным заходом» хенд-оффы не состоялись. Исполнение — гейтом выхода
из `GAPS_CLOSE_N` (`.claude/skills/update-roadmap-progress.md`).

**Диспозиция находки начинается с уровня пробела** (решение держателя
2026-08-30, `.claude/decisions/proof-method-change.md`). Прежде рода
закрытия определяется уровень пробела — продукт / концепция-стык /
носитель / доказательство / гигиена — по классификатору
`.claude/skills/classify-gap-level.md`; уровень задаёт род
закрывающего действия и его минимальный объём. Закрытие уровнем ниже
пробела (правка одного носителя при пробеле стыка, правка
формулировки при пробеле доказательства) выглядит закрытием и
возвращает узел следующим прогоном. Таблица уровней живёт в скилле;
дом процесса её не пересказывает (отвергнутая альтернатива — в
решении).

**Раскладка находок по узлам проверяется встречным счётом от линз, а не
от списка запущенных узлов** (уточнение первым применением).
Владельца получает каждая находка **перечня линзы**;
проверка идёт с той стороны — по перечням, — и только потом сверяется с
тем, что запущено. Класс, который ловится этим и не ловится обратным
порядком: узел не заведён, потому что нужный периметр занят соседним
узлом, и находка остаётся без владельца **молча** — не отложенной, а
пропущенной. Замер: пять узлов и шестнадцать гейтящих находок вначале
владельца не имели, и обнаружилось это только пересборкой раскладки из
перечней.

**Политикоменяющее закрытие завершается свипом по терминам старой
политики.** Если закрытие меняет политику (снимает или заменяет
правило, а не доуточняет структуру), список цитат находки —
необходимый, но не достаточный вход. Такое закрытие завершается
**свип-грепом по терминам снимаемой формулировки** по всем живым
носителям — `docs/**`, `<дерево кода>/src/**`, `.claude/rules/**`,
`.claude/processes/**`, `.claude/tests/**` и рабочим файлам
(`backlog.md`, `open-questions.md`, `questions/tasks/*`, roadmap
`phase-N.md`, `progress/`). Термины берутся из **снимаемой**
формулировки, и их обычно несколько (политика живёт в нескольких
словах). Рабочие файлы опаснее доков — они адресованы исполнителю
следующего под-шага. В отчёте закрытия по каждому свипу: команда
поиска (дословно, воспроизводимо) + пофайловая таблица исходов
(файл → правлено что именно / не требует правки — почему). Полный
вывод грепа в отчёт не вклеивается — адреса проверяемы повторным
запуском команды.

**У свипа по снятым терминам есть энфорсер** (решение держателя
2026-08-30, `.claude/decisions/acceptance-by-measurement.md`). Закрытие,
снимающее редакцию, заводит запись в реестре снятых редакций
(`tools/retired-check.py`): опознавательные термины, дату, решение-источник
и разрешённые места. Команда свипает живые носители по плоскому тексту и
падает на каждом вхождении вне разрешённых мест.

**Свип снятой редакции идёт по популяции носителей, а не только по форме
термина** (решение держателя 2026-08-31,
`.claude/decisions/closure-completeness-by-population.md`). Запись реестра
несёт, сверх опознавательного шаблона, **две обязательные величины**:
шаблон **пришедшей** редакции (что теперь обязано стоять на месте снятой)
и **популяцию носителей** — перечень мест, где снятая редакция стоя́ла и
где пришедшая обязана появиться. Команда падает трижды: на вхождении
снятого термина вне разрешённых мест (прежняя ось), на носителе популяции,
где пришедшей редакции нет, и на строке популяции, которой в корпусе
больше не существует. Класс, который закрывается только так, —
**встречная форма**: носитель, выражающий снятую редакцию другими словами,
шаблоном не ловится по построению, но в популяции он назван и обязан
предъявить пришедшую редакцию. Замер, на котором записано: снятая редакция
дедупа отчёта жила в шести носителях при зелёном прогоне энфорсера, а
канон гейта держал снятый исход глаголом закрытия **перед** термином —
форма, которой объявленный шаблон не видел. **Разрешённые места —
только носители пайплайна:** файл продуктового корпуса в них не попадает
никогда, потому что `docs/concept.md` §«Опровержение правит на месте»
запрещает слой опровержения в корпусе. Прежде правило единственности дома
(`.claude/rules/carrier-levels.md`, `.claude/rules/policy-home.md`) вошло в
корпус записью и энфорсера не имело: механической проверки, что правка
политики дошла до потребителей, не существовало ни одной — и 27 из 39
гейтящих находок прогона оказались непройденным обходом потребителей.

**Исполнение свипа проверяется гейтом при смене статуса.** Требование
выше было записано и не исполнялось: отчёт закрытия без раздела свипов
проходил дальше, а его непроведённые следствия становились находками
следующего прогона. Проверка — в скилле, который **исполняется** при
простановке статуса: `.claude/skills/update-roadmap-progress.md` §«Гейт
выхода из `GAPS_CLOSE_N`» (та же конструкция встречного якоря, что у
гейта закрытия фазы). Кейс: закрытие меняло политику трижды, свипов в
отчёте не было, девять из одиннадцати гейтящих находок следующего
прогона — непроведённые следствия его же правок.

**Форм предмета у свипа три, и третья — объём действия.** Имя величины
отвечает на «где она лежит», прозаическая тропа чтения — на «как её
читают», и обе были названы раньше. Носитель, описывающий **на что
распространяется действие** («вся биржа», «все сделки биржи», «по всему
контуру»), не содержит ни имени величины, ни тропы её чтения, и обеими
формами не берётся. Правку, меняющую **радиус** чего бы то ни было, свип
обязан пройти всеми тремя.

*Замер, на котором записано: свип двумя формами взял 48 носителей и
закрыл их все; следующий прогон нашёл двенадцать, выражавших снятый
радиус третьей формой. Там же измерена цена ошибки шаблона: `\w` в
`grep -P` кириллицу не берёт, и первая попытка построить шаблон третьей
формы дала 6 файлов вместо 45.*

**Свип идёт по конструкции, а не только по снимаемым терминам.**
Греп по снимаемой формулировке находит носитель, где термин **звучит**;
носителя, выражающего ту же вещь другими словами, он не находит
никогда. Поэтому у свипа два предмета, и второй обязателен:

- **предмет 1 — снимаемые термины** (перечень выше): что перестало быть
  верным дословно;
- **предмет 2 — введённая конструкция**: всякая формула, предикат,
  инвариант или счётный клейм, которые закрытие **вводит или меняет**,
  проверяются независимо — на арифметику, на область определения
  операндов и на согласованность с соседями, — **кем-то, кроме автора
  правки, либо отдельным проходом**. Конструкция, пришедшая последней,
  чаще всего не получает ни одного свипа: свипы прогоняются по тому,
  что снято, а она — то, что добавлено.

**Хвост закрытия — такое же закрытие.** Правка, пришедшая после свипов
(ответ держателя отдельным заходом, доспроектированная механика,
исправление по ходу), получает **свои** свипы обоих предметов, свой
независимый взгляд (ни одна правка закрытия не приземляется без него —
для гейтящего узла это мини-петля) и свой раздел в отчёте. Иначе она
проходит в `CODE` непроверенной по построению.

*Кейс, на котором это записано: закрытие прогнало и записало все
свипы, а следующий прогон нашёл двенадцать гейтящих находок — следствий
этого же закрытия. Диагноз был не «свипы не прогнали» (их прогнали), а
«свипы прогнали не по тому предмету»: новая формула ошибалась
арифметически и не свипалась никем, потому что пришла хвостом; правка
не доезжала до носителя, где снимаемый термин не звучал; правило
«перечень, а не счёт» применялось к строкам сборки, но не к объектам
внутри строк.*

**Свип покрывает и носитель уровня, на который переехала
собственность.** Когда закрытие переносит владение (перечень команд —
с handler'а на действие, метрику — с компонента на компонент), свип
покрывает **оба** конца переноса: на принимающем уровне старых
терминов может не быть вовсе, текстовый греп его не найдёт.

**Правка, вводящая поле или тропу чтения, завершается свипом по
структурным носителям.** Поле, которого нет, текстом не находится —
недостаёт структуры. Закрытие, вводящее поле, колонку, операнд или
тропу чтения, проходит по фиксированному перечню и отмечает каждый
носитель: §Структура доменной модели; §Персистентность; schema-дельта
шага; состав `*ExternalSnapshot` и used/unused нативного инвентаря;
mapping-таблицы (включая счёт цепочки); инвентарь читателей у
владельца данных (если введена тропа чтения); **контракт вызова у
создателя сущности** — перечень «что передаёт вызывающий» и врезки
«чем заполняется каждое обязательное поле». Признак применимости —
закрытие называет новое имя либо фразу «резолвится через …». Исход —
пофайлово в отчёте; структурных правок не было — пишется явно.

*Контракт вызова добавлен в перечень поимённо (замер): обязательное поле
дошло до модели, до схемы и до вызывающего, но не до вызываемого —
единственного писателя строки, — и его врезка «чем заполняется каждое
обязательное поле» осталась ложным клеймом полноты вместе со ссылкой на
неё из модели. Ни одна из шести прежних позиций перечня этот носитель не
брала: имени поля в нём не было по построению, потому что поля не было
вовсе.*

**Правка, меняющая РАДИУС, свипается перечнем предикатов, а не формой
слова.** Радиус не имя: он выражается неограниченным числом прозаических
форм («вся биржа», «по инструменту», «по этому инструменту», перечень
передаваемых полей), и всякий шаблон берёт лишь те, которые автор
шаблона вспомнил. Популяция такой правки строится **от предмета**:
выписываются **предикаты и выборки, читающие радиус** — детекторы,
гейты входа, предусловия снятия ступеней, исходы отбора, ключи
уникальности и индексы, — и каждый проверяется на радиус поимённо.
Формы слова остаются средством **добыть носители** уже найденного
класса, а не способом найти класс.

*Замер, на котором записано: один узел радиуса дал находки три прогона
подряд. Первый свип двумя формами взял 48 носителей и закрыл все; второй
прогон нашёл двенадцать в форме «объём действия»; третий — десять в форме
«предикат по инструменту» и один контракт вызова. Перечень предикатов
строится за один проход и исчерпывается: их конечное число задаёт модель.*

**Правка, меняющая кардинальность, предикат или инвариант, идёт своим
свипом — по производным носителям.** Признак применимости другой: имя
не вводится, поэтому текстовый греп по имени не находит ничего, а
структурный свип по полям проходит чисто. Перечень:

- **сборщики контекста** — что и в каком объёме загружается в проход
  (ослабленная кардинальность делает «ограниченную» загрузку молча
  неполной);
- **исполнители-читатели изменившейся коллекции** — предикаты, писавшиеся
  под «ровно один», и клеймы вида «единственная строка»;
- **предикаты-соседи того же поля** — те, что читали его как write-once,
  как единственное или как гарантированно непустое;
- **сборка schema-дельты шага** — ключи и индексы, выражавшие снятый
  инвариант;
- **клаузы, объявляющие «этого не бывает»** — прежний инвариант мог быть
  доводом чужого решения.

Кейс, на котором перечень записан: правка кардинальности `Position`
(«≤1 на сделку» → «≤1 живая») и предикатов отбора риск-чисел дала
**восемь из десяти** гейтящих находок следующего прогона — все
непроведённые следствия, ни одного нового поля.

**Отдельный проход — по носителям с клеймом полноты**, затронутым
правкой. Клейм полноты («счёт цепочки N = N = N», «перечень
закрытый», «это и есть единственное, что выходит») запрещает писателю
искать дальше, превращая пропуск в инструкцию, — поэтому клеймы
проходятся списком и отмечаются поимённо.

- **Клейм проверяется по объектам, а не по строкам, и пересобирается из
  своего перечня.** Счёт («детекторов два», «два частичных ключа»)
  правится **вместе** с перечнем, из которого он выведен, а не
  отдельно; перечень производителей сверяется с реестром **колонкой**,
  а не пополняется по памяти правки. Правка, затронувшая перечень и не
  затронувшая его текстом счёт, оставляет ложный клейм — то есть
  инструкцию «дальше не искать».
- **Проход идёт и по клеймам, которых правка текстом не касалась**, но
  чей предмет она изменила: клейм живёт в другом файле и своих слов о
  правке не содержит, поэтому греп по терминам правки его не находит.

**Отложенный хвост проверяется на сцепленность с тем, что шаг
поставляет.** Прежде чем отложить хвост на следующий шаг, проверяется:
не зависит ли от него артефакт, который поставляет **текущий** шаг
(два хвоста, отложенных порознь, могут вместе обнулять вводимый
сейчас guard). Обратная сторона: починка одного из сцепленных хвостов
может немедленно активировать второй — при закрытии хвоста
проверяется, что именно он оживляет.

**Разведочный режим guard'а называет условие выхода и его носителя.**
Если шаг отгружает контроль с заведомо пустым конфигом или
неоткалиброванной величиной, закрытие называет: что выводит его из
разведочного режима, кто/что это фиксирует и к чему привязан срок.
Без условия выхода разведочный режим становится постоянным.

**Ревизия used/unused инвентаря источника сверяется с правилом
`Auditable`.** Поля времени создания и обновления, отдаваемые
источником, в unused не выводятся — у них структурный носитель, а не
прикладной потребитель (`docs/models/domain/other/Auditable.md`).

**Статус шага:** `GAPS_CLOSE_N`, где N — номер итерации.

### 4. Итерация под-шагов 2-3

Чередовать проверку и закрытие пробелов до тех пор, пока
проверка не пройдёт чисто (новых пробелов не выявлено). После
чистой проверки — переход к под-шагу 5 по гейту `CODE`
(см. «Гейты»).

**Закрывающий прогон идёт до гейта одним заходом.** Итерация
`DOCS_CHECK_N → GAPS_CLOSE_N → DOCS_CHECK_{N+1}` — **один прогон**, а не
серия заходов, каждый из которых ждёт нового промпта. Граница итерации
есть точка простановки статуса и выпуска отчёта (§«Фиксация статуса —
часть каждого под-шага»), но **не** точка возврата к держателю:
следующая итерация начинается тем же ходом. Прогон, остановленный на
границе итерации ради подтверждения, что можно продолжать,
останавливает работу, останавливать которую никто не просил, — и цена
этого не нулевая: каждый заход перечитывает корпус заново, а держатель
получает вопрос вместо результата.

**Условий остановки три, а не два.** Сверху прогон закрывает чистая
проверка; снизу — детектор стагнации (пассаж ниже); третье —
**позиция, чей блокер не работа**: она ждёт носителя, которого в корпусе
нет по построению (чужой шаг, ещё не заведённая величина, внешний факт,
ответ держателя). Такая позиция **паркуется немедленно**
(`.claude/rules/parking-address.md`), и прогон идёт дальше по остальным.
Тянуть прогон ради позиции, которую он не может закрыть по построению, —
не тщательность: закрываемой она от ожидания не станет.

**Шаг закрывается с парковками в отчёте.** Парковка — штатный исход
находки, а не признак незакрытого шага: гейт требует, чтобы каждая
находка была **задиспозиционирована** (§«`GAPS_CLOSE_N`
диспозиционирует все находки прогона»), а не чтобы все были закрыты.
Шаг, ждущий последней позиции, которая ждёт чужого шага, не закроется
никогда.

**Срок задаёт держатель, объём захода — нет.** Названный держателем срок
превращает всё незакрытое к нему в парковку, а не в основание тянуть
прогон. Срок не назван — прогон идёт до чистой проверки; собственного
«достаточно на сегодня» у прогона нет, и остановка по усталости
исполнителя условием остановки не является.

**У эскалации детектора есть третий исход — смена рамки** (решение
держателя 2026-09-01, `.claude/decisions/code-contact-as-gate.md`).
Эскалация выносит держателю выбор из двух — сменить концепцию узла или
продолжать итерации, — и **обе позиции лежат внутри доковой петли**:
первая чинит её машину, вторая работает по ней дальше. Держатель вправе
закрыть эскалацию третьим ходом — **остановить петлю и перенести
проверку решений на контакт с кодом**, — и на шаге 7 фазы 1 он так и
сделал. Позиция «сменить саму рамку проверки» в перечне эскалации не
стояла, хотя ось структурной свободы обязательна
(`.claude/templates/docs/gap-report.md` §«Состав перебора»): перебор был
неполон ровно тем классом, который детектор меряет сигналом С4.
**Следствие для будущих эскалаций:** перечень выносится с этой позицией
наравне с двумя прежними, и её цена называется так же — какие клеймы
поедут в код непроверенными чтением.

**Итерация имеет условие остановки не только сверху, но и снизу.**
Сверху петлю закрывает чистый прогон; снизу — **детектор стагнации**
(`.claude/skills/stagnation-detection.md`): серия прогонов меряется на
схождение, и когда узел возвращается с гейтящими находками после
собственного закрытия, когда закрытие даёт находок столько же, сколько
закрывает, когда стоимость прогонов не убывает или перебор второй раз
подряд оказывается неполным — итерации по узлу **останавливаются**.
Вместо очередной развилки внутри узла поднимается эскалация
«концептуальный дефицит»: диагноз, почему латание не сходится, и выбор
держателю «сменить концепцию или продолжать итерации» — вместо
очередного вопроса внутри старой концепции. Пороги, состав эскалации и
калибровка — в скилле; исполнение — гейтом при простановке статуса
(`.claude/skills/update-roadmap-progress.md` §«Гейт входа в
`GAPS_CLOSE_N`»). Замер идёт по **реестру прогонов** в хронике шага, и
строка реестра — часть выпуска отчёта прогона.

**Сбор внешнего грунта не ждёт чистого прогона.** По умолчанию
проверочные прогоны против источника (контур
`.claude/processes/source-api-testing.md`) идут после чистого
`DOCS_CHECK` — перед `CODE`. Но находка, у которой **единственный**
блокер — ярлык дефицита `грунт` (не хватает внешнего факта, а не
проектирования и не решения пользователя), этим порядком образует петлю:
факт собирается после чистого прогона, а прогон без факта чистым не
станет. Такие находки выносятся на сбор грунта **сразу**, не дожидаясь
чистоты остальных: их закрытие ничего в концепции не двигает, оно только
подставляет недостающее число или подтверждает поведение источника.

Признак петли: находка несёт `грунт` **без** сопутствующего `работа` или
`подтверждение`. Несёт вместе с ними — грунт собирается в общем порядке
(сначала проектное решение, потом проверка его посылок).

Кейс: четыре находки ждали рантайм-факта
источника (оси адресации истории позиций; инвентарь типов bill; поведение
`realizedPnl` при cross-ccy-издержке; эндпоинт котировки), при том что
сама фикстура была запланирована «после чистого прогона». Порядок при этом
**нигде не был записан** — он накопился практикой и в носители процесса не
попадал; правило вводится вместе с исключением.

### Торговая категория в петле (под-шаги 2-4)

Торговые находки (фокус `trading-review` роли `reviewer`) идут той
же машиной `DOCS_CHECK_N` / `GAPS_CLOSE_N` — отдельная категория
находок, не отдельная петля.

- **Приоритет по тяжести, не по категории.** Торговые находки
  ложатся в существующие оси: блокирующее / неблокирующее,
  содержательное / гигиена. Внутри содержательного торговое
  **ведёт**: его правки переформируют модель, поэтому после
  торговой правки концептная проверка прогоняется заново (рябь).
- **Гейтинг `CODE`.** Содержательно-блокирующее гейтит переход к
  `CODE`, включая ключевой кейс «модель не выражает нужное торговое
  правило» (жёсткий гейт). Гигиена / name-level / торговые заметки
  на будущие фазы — не гейтят.
- **Два касания торговли во времени:**
  - *конструктив* — торговый специалист
    (`.claude/agents/trading-specialist.md`) по ходу
    проектирования: на торговой развилке отвечает и предлагает
    торгово-обоснованные варианты (front-load, чтобы не закреплять
    торгово-наивные решения);
  - *критика* — торговый фокус ревьюера в петле: адверсариальный
    проход, валидирует результат, в том числе предложенное
    специалистом и выбранное пользователем (независимость от
    автора).
- **Применение — по текущему шагу роадмапа**, изолированно.
  Forward-находки, упирающиеся в ещё незрелые шаги, паркуются как
  **cross-cutting** — поднимаются рано, не решаются до своего шага
  (штатно — открытый вопрос с пометкой шага-владельца).

### 5. Код

Пишется код по проработанной концепции: написание (`code-writer`)
+ ревью-итерации адверсариального ревьюера по фокусам
(`conventions` / `performance` / `disaster`; с шага 9 фазы 1 к ним
добавлен `security` — реактивирован там, где заводится предмет его
проверки, см. `.claude/skills/security-review.md`) + аппрув.
Синхронизация доков в этот под-шаг **не входит** — она вынесена в
отдельный под-шаг `SYNC_DOCS_FROM_CODE` (ниже): пока код не
утверждён, неясно, к чему приводить доки.

Аппрув `CODE` — зафиксированный исход адверсариальных фокусов, не
устное согласие (см. «Гейты»).

**Статус шага:** `CODE`.

### 6. Синхронизация доков под утверждённый код

После аппрува `CODE` доки приводятся к утверждённому коду.
Направление — **docs←code**: утверждённый код считается истиной
(вопрос «код или доки неверны» снят аппрувом). Сверка полная:
добавления, изменения, удаления. Проход одиночный (без `_N`):
аппрув уже зафиксировал истину, итерировать не по чему.

Внутри под-шага:

- **детект расхождений** — фокус `divergence` адверсариального
  ревьюера (`.claude/skills/divergence-review.md`): список
  add / change / remove;
- **реконсиляция** — `knowledge-curator`: добавления идут штатным
  потоком размещения; изменения и удаления —
  `.claude/skills/reconcile-knowledge.md`.

**Аппрув `SYNC_DOCS_FROM_CODE` — зафиксированный исход `divergence`.**
Синхронизация считается выполненной, только когда `divergence`-фокус
адверсариального ревьюера **прогнан с зафиксированным исходом** (список
add / change / remove в отчёте) и расхождения реконсилированы. «Доки ок
на глаз» / сверка автором синхронизацией **не является** — детект
расхождений ведёт независимый фокус, не автор кода.

**Статус шага:** `SYNC_DOCS_FROM_CODE`.

### 6a. Пост-хок концепт-гейт для CODE-инкрементов

**Концепт-инкремент, въехавший через CODE, требует пост-хок
концепт-гейта.**

Концепт/контракт-инкремент — новая семантика контракта или модели
сверх утверждённой концепции шага; признак: сопровождается решением с
обоснованием или закрывает ранее открытый концепт-пробел (а не просто
добавляет поля). В норме такой инкремент проектируется
(`solution-designer`) и проходит концепт-гейт (`DOCS_CHECK`) **до**
CODE.

Если инкремент по необходимости вошёл уже на под-шаге CODE — он
миновал концепт-гейт: `DOCS_CHECK` идёт по докам *до* CODE, а на
`SYNC_DOCS_FROM_CODE` активен только `divergence` (механическая сверка
код↔доки, концепт не проверяет).

**Remedy:** после `SYNC_DOCS_FROM_CODE`, когда доки приведены к коду,
прогнать `concept-review` по обновлённым докам — прежде чем шаг уходит
в `DONE`. Концепт ревьюится на доках, раз на коде его проверить нельзя.
Прогон идёт по машине под-шагов 2-3: найдены пробелы — закрыть узким
`GAPS_CLOSE` и перепрогнать, пока концепт-проверка пост-sync доков не
пройдёт чисто; только тогда шаг уходит в `DONE`.

**Применимость — по наличию концепт-инкремента.** Если на CODE вошли
только поля/механика без новой контрактной семантики (нет
сопровождающего решения и не закрыт концепт-пробел) — пост-хок гейт не
нужен, `SYNC_DOCS_FROM_CODE` → `DONE` напрямую. Признак-триггер —
решение с обоснованием или закрытый концепт-пробел, въехавшие на CODE.

**Статус шага:** прогон ведётся как `DOCS_CHECK_N` (concept-review по
пост-sync докам), при находках — `GAPS_CLOSE_N`; продолжает сквозную
нумерацию итераций шага.

### 7. Завершение шага

После того как код утверждён, доки синхронизированы **и пройден
пост-хок концепт-гейт** (§6a, если на CODE вошёл концепт-инкремент) —
шаг переходит в `DONE` по гейту `DONE` (см. «Гейты»).

**Статус шага:** `DONE`.

## Гейты

Канон гейтов процесса; под-шаги 4, 5 и 7 ссылаются сюда.

**Гейт `CODE` — покомпонентный, а не пороговый** (решение держателя
2026-09-01, `.claude/decisions/code-contact-as-gate.md`; пересматривает
решение того же держателя от 2026-08-31). Статус шага переводится на
`CODE`, когда реестр гейтов существует и разобран; дальше гейт
срабатывает **на каждом компоненте**, а не один раз на переходе.

1. **Позиция реестра гейтит свой компонент.** Каждая гейтящая находка
   последнего прогона получает класс
   (`.claude/skills/classify-code-blocking.md`), **компонент**, которого
   она касается, и диспозицию в реестре
   `.claude/work/code-gate-ledger.json`. Исполнимая форма —
   `python3 tools/code-gate-check.py`:
   - **`КОД`** («написанный по докам код повёл бы себя неверно») —
     позиция обязана быть закрыта **до или в момент кодирования своего
     компонента**: решением явным, с правкой доков тем же ходом.
     Компонент, у которого статус кодирования не `не начат`, а позиция
     открыта, — гейт не проходит;
   - **`РИСК`** («денежная механика») — все позиции класса закрыты
     **прежде, чем начат любой компонент торговой тропы** (отправляющий
     заявку на биржу либо считающий деньги). Признак торговой тропы —
     величина компонента в реестре, не суждение исполнителя;
   - всякая прочая гейтящая находка — **задиспозиционирована**: закрыта
     (сказано чем) либо явно припаркована с **адресатом** (файл + пассаж,
     разрешимый машиной) и **условием возврата** — по
     `.claude/rules/parking-address.md`;
   - **каждая позиция несёт компонент** — имя из таблицы компонентов
     реестра либо явное «вне компонентов» с названной причиной. Позиция
     без компонента гейт не проходит: непривязанная находка не гейтит
     ничего и теряется.

   **Закрытие `КОД` — решение, а не кодогенерация.** Позиция закрывается
   явным проектным решением с правкой доков; «код написан, доки
   потом» критерия не исполняет. Мотив, на котором поправка стои́т: 25
   позиций `КОД`/`РИСК` — живые проектные развилки, и они не должны
   приниматься молча внутри кодового захода.

   **Снятая редакция — «`КОД` и `РИСК` в ноль незакрытых до перевода
   статуса»** (2026-08-31). Она снята не как неверная, а как
   **несходящаяся**: девять прогонов подряд закрытие производило больше
   половины находок следующего прогона (бумеранг 53 % и 55 % на двух
   последних), и планка не бралась. Ещё раньше снята редакция «чистый
   `DOCS_CHECK`» — как недостижимая по построению.
2. **Гейт грунта — тоже покомпонентный.** Если у шага есть реестр
   гейтящих предусловий, открытый слот «пункт × кейс» гейтит **тот
   компонент, которому нужен добытый факт**, а не шаг целиком. **Чем
   именно слот закрывается — предмет реестра, и здесь этот перечень не
   пересказывается:** дом правила и таблица слотов — реестр шага (для
   шага 7 фазы 1 — `.claude/tests/source-api/okx/code-preconditions.md`
   §«Правило гейта»). Исполнение —
   `.claude/skills/update-roadmap-progress.md` §«Гейт грунта».

   Покомпонентное чтение второго условия — **вывод из поправки
   держателя, а не её содержание**: механика та же (неизвестное,
   приезжающее в код молча), и ответ на неё поправка даёт привязкой к
   компоненту. Обоснование и право вето —
   `.claude/decisions/code-contact-as-gate.md` §«Покомпонентное чтение
   гейта грунта».
3. **Гейт инструментов корпуса** — все проверочные команды прогоняются
   перед сменой статуса, ненулевой код любой не пропускает
   (`.claude/skills/update-roadmap-progress.md` §«Гейт инструментов
   корпуса»).

**Заморозка усиления измерения снята по своему собственному условию.**
Решение 2026-08-31 замораживало новые эпистемические этажи — классы
инструментов, осей, детекторов — **до входа в `CODE`**; вход состоялся,
и условие снятия сработало. Ремонт существующего инструмента под
изменившийся критерий заморозкой не был запрещён и прежде.

**Аппрув `CODE` — зафиксированный исход фокусов, не устное согласие.**
Аппрув под-шага `CODE` — это **не** «ок» от `code-writer` (автора),
самопроверки на глаз или устного согласия пользователя, а **прогнанные
адверсариальные ревьюер-фокусы** (`conventions` / `performance` /
`disaster`) **с зафиксированным исходом** (отчёт фокуса в истории шага)
**и закрытыми находками**. Независимость обязательна: автор кода свой код
не аппрувит. Без зафиксированного исхода фокусов под-шаг `CODE` не
завершён, как бы ни выглядел код «на глаз».

**Гейт `DONE` — зафиксированный исход адверсариального ревью.**
Статус **не** переводится в `DONE`, пока не выполнены **все** условия
с **зафиксированным исходом** (отчёты фокусов в истории шага), а не
устным согласием автора/пользователя:

1. аппрув `CODE` пройден (фокусы прогнаны независимым ревьюером,
   находки закрыты — см. выше);
2. `SYNC_DOCS_FROM_CODE` — `divergence`-фокус прогнан, расхождения
   реконсилированы (аппрув под-шага 6);
3. пост-хок концепт-гейт §6a пройден (если на `CODE` въехал
   концепт-инкремент).

Нет зафиксированного исхода любого из них → шаг **остаётся в пред-`DONE`
статусе** до прогона фокуса и закрытия находок. Устное «ок» гейт не
закрывает. Если шаг уже помечен `DONE` мимо этого условия — статус
**откатывается** в пред-`DONE` до фактического прохождения гейтов
(статус отражает реально пройденное, не намерение).

## Фиксация статуса — часть каждого под-шага

Завершение **любого** под-шага включает перевод статуса шага в
роадмапе через `.claude/skills/update-roadmap-progress.md` (новая
итерация / следующий под-шаг / шаг закрыт). Под-шаг **не считается
завершённым**, пока статус не проставлен в `phase-<N>.md` и не
пересчитан ролляп фазы в `roadmap.md`.

Это часть работы под-шага, не отдельное напоминание и не действие «по
сигналу»: закрыл под-шаг (например, выпустил gap-отчёт `DOCS_CHECK_N`
или закрыл эскалации `GAPS_CLOSE_N`) — сразу прогнал
`update-roadmap-progress`. Производящий артефакт скилл (фокусы
`reviewer`, `code-writer` и т. п.) сам статус не ведёт — оркестрацию
держит этот процесс.

## Канонический набор статусов шага

Источник истины для статусов шага роадмапа. Скилл ведения
прогресса (`.claude/skills/update-roadmap-progress.md`) и
таблицы фаз в `.claude/work/roadmap/` ссылаются сюда.

| Статус | Смысл |
|---|---|
| `HOLD` | Шаг не начат. |
| `TOOLING` | Под-шаг 1: создание агентов/скиллов. |
| `DOCS_CHECK_N` | Под-шаг 2: проверка целостности концепции, N — номер итерации. |
| `GAPS_CLOSE_N` | Под-шаг 3: закрытие пробелов концепции, N — номер итерации. |
| `CODE` | Под-шаг 5: написание кода + ревью-итерации (фокусы) + аппрув. |
| `SYNC_DOCS_FROM_CODE` | Под-шаг 6: синхронизация доков под утверждённый код (docs←code), одиночный проход. |
| `DONE` | Шаг завершён. |

`DOCS_CHECK_N` / `GAPS_CLOSE_N` обычно — под-шаги 2-3 (до CODE), но та
же машина переиспользуется **пост-CODE** как пост-хок концепт-гейт
(под-шаг 6a) для концепт-инкрементов, въехавших через CODE: прогон
идёт после `SYNC_DOCS_FROM_CODE` по приведённым докам, нумерация
итераций сквозная.

## Конец фазы

В конце каждой фазы — отдельные шаги **«Тесты»** и **«Фронт»**.
Оба исполняются по этому же процессу (docs-first), как любые
другие шаги. Зрелость фронта — атрибут самого шага (простой для
прогонов до архитектурного рубежа; полноценный после).

# Режим автономии: кто решает развилки

## На какой вопрос отвечает этот файл

Как устроен режим автономии: кто решает развилки, что доходит до
пользователя и как фиксируются решения.

## Суть

**До конца фазы 1 действует режим автономии** (решение держателя
2026-08-26, по итогам
`.claude/work/2026-08-26-step-7-question-flow-analysis.md`): все
категории владельцев — на автономии. Проектные развилки CC решает сам
и фиксирует в **дайджесте решений**; пользователю выносится только
дефицит `подтверждение`.

## Карта владельцев

Маршрутизация развилки по компетенции (кто прорабатывает и решает):

| Категория развилки | Владелец |
|---|---|
| Классификация / размещение знания | `knowledge-curator` |
| Торговые развилки | `trading-specialist` |
| Детали уровня кода | `code-writer` (под-шаг `CODE`) |
| Проектирование концепции / архитектурные развилки | `solution-designer` |
| Интеграция (контракты/спеки внешних источников, нативные модели API) | `integrator` |
| Тестирование (тест-планы / кейсы / отчёты контура тестов API источника) | `tester` |

## Что доходит до пользователя

Только дефицит **`подтверждение`**: цели, приоритеты, продуктовый
scope и намерение, численный риск-аппетит, сроки. Формат — как для
substantive-decision в чате (`.claude/chat/chat-project-instructions.md`),
один вопрос за раз. Всё остальное — проектные развилки любого уровня,
включая проектирование моделей и компонентов, — владелец финализирует
сам.

## Дайджест решений

Каждое автономно принятое проектное решение фиксируется в
`.claude/work/decision-digest.md`:

- **форма записи:** решение одной строкой + альтернативы одной
  строкой + почему так;
- **накопление:** записи копятся за итерацию;
- **выдача:** отдаются пользователю пакетом **на чтение** (не как
  вопросы) — с правом вето постфактум;
- **вето** возвращается CC обычной задачей (переделать с учётом
  решения держателя), не адъюдицируется в чате;
- **после чтения** разобранные пункты переезжают в `history/`.

Дайджест — фиксация принятого, не очередь на подтверждение: работа не
ждёт чтения дайджеста.

## Источниковый дефицит — эскалация всегда

Не изменилось: если владелец связан источником/корпусом (торговый
специалист — торговым корпусом, интегратор — офдоком и т. п.) и
нужного знания в источнике нет — дефицит **не закрывается выдумкой**.
Эскалация: дефицит `подтверждение` — пользователю; остальное —
открытый вопрос (`.claude/work/questions/open-questions.md`) с
пометкой в дайджесте.

## Взвешивание срока (now-vs-later)

Когда владелец решает вопрос сейчас, а когда откладывает:

- **Дедлайн фазы.** Все открытые вопросы в охвате фазы должны быть
  решены до шага тестов этой фазы. К тестам ничего открытого не
  остаётся.
- **Блокер текущего шага решается сейчас.** Не-блокер может быть
  отложен вплоть до конца фазы (перед тестами).
- **По каждому не-блокеру владелец взвешивает now-vs-later.** Решать
  сейчас — только если это что-то даёт: снимает текущий блок,
  применяет уже принятый устойчивый инвариант, либо ловит
  скоропортящееся. Откладывать — если ответ зависит от исхода
  будущего шага и от вопроса ничего текущего не висит.
- **При откладывании — называть горизонт:** конец фазы перед тестами
  либо конкретный шаг/фаза.
- **«Устойчиво/выводимо сейчас» — само по себе не основание решать
  сейчас.** Устойчивое решение без текущего потребителя откладывается
  до материализации потребителя.

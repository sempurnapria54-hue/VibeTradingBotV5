# Гейтящие предусловия `CODE` шага 7

## На какой вопрос отвечает этот файл

Какие факты источника обязаны быть добыты до входа шага 7 в `CODE`.

## Почему реестр здесь, а не в `docs/`

Прежний дом реестра — `docs/rules/pnl-reconciliation.md`, и это было
ошибкой размещения: реестр отвечает на вопрос **проверочной
деятельности** («что обязано быть измерено до того, как писать код»), а
не на продуктовый вопрос («как сверяется результат сделки»). Переписывание
корпуса по `docs/concept.md` вычистило процессную арматуру из `docs/` — и
вместе с ней снесло реестр, **не перенеся** его: четыре дока остались
ссылаться на несуществующие номера.

Дом восстановлен здесь по `.claude/rules/structure.md` — строка
`.claude/tests/{testType}/{source}/`: «Планы — артефакт проверочной
деятельности (пайплайн), не продуктовое знание об источнике».

Восстановлено `GAPS_CLOSE_26`; содержание собрано из
`.claude/work/backlog.md` §«Шаг 7 (сделки и P&L) — исполнительный хвост»
и меток «ГЕЙТИТ `CODE`» в `plan.md`.

## Правило гейта

**Шаг 7 не входит в `CODE`, пока хотя бы один слот реестра не закрыт.**

- **Слот** — пара «пункт × кейс». Пункт закрыт, когда закрыты **все** его
  слоты: у двух пунктов носителей факта два (п. 1 — `AG1.5` и `AG1.9`;
  п. 2 — `AG6.1` и `AG6.2`), и наблюдение одного кейса второй слот не
  закрывает.
- **Слот закрывается прогоном своего кейса** в контуре
  `.claude/processes/source-api-testing.md`; исход `OBSERVED_ABSENT`
  закрывает слот наравне с наблюдением — по механике §«Закрытие исходом
  `OBSERVED_ABSENT`» ниже.

Предусловие несёт дефицит **`грунт`**: не хватает внешнего факта, а не
проектирования и не решения держателя. По
`.claude/processes/roadmap-step-execution.md` §4 такие пункты уходят на
сбор **сразу**, не дожидаясь чистого `DOCS_CHECK`, — иначе образуется
петля: факт ждёт чистого прогона, а прогон без факта чистым не станет.

**Этот файл — дом правила гейта грунта.** Встречный якорь со стороны
события — `.claude/skills/update-roadmap-progress.md` §«Гейт грунта»
(пункт `CODE` в §«Гейт-предусловие перехода (`CODE` / `DONE`)» на неё
ссылается): проверка **исполняется** в момент простановки статуса
`CODE`, а не тогда, когда кто-то вспомнит открыть реестр. Скилл правило
не пересказывает — он читает таблицу ниже.

### Сверка реестра с планом — исполнимой проверкой

Проверку несёт скрипт **`tools/preconditions-check.sh`** (запуск из корня
репозитория, без аргументов — умолчания контура OKX):

```bash
bash tools/preconditions-check.sh
# СОШЛОСЬ: слоты реестра == гейт-пометки плана     → код возврата 0
```

Он меряет **три** оси, каждая поднимает дефект до кода возврата, и
первые две — ровно та конструкция, которую реестр ввёл:

1. **Слот-сверка.** Множество пар «пункт × кейс» реестра обязано совпадать
   с множеством пар, объявленных гейт-заголовками плана
   (`**ГЕЙТИТ `CODE`** (предусловия п. N …)`). Сравниваются **пары**, а не
   множества кейсов: расхождение «кейс в реестре есть, но не на том
   пункте» множеством кейсов не ловится вовсе. Плановая сторона разбирает
   формы «п. N», «пп. N и M» и «пп. N, M и K» (номера принимаются только
   в списке, открытом маркером «п.»/«пп.»).
2. **Разведённость слота.** В строке реестра — ровно один кейс. Два кейса
   в одной ячейке означают, что статус наблюдения нельзя назначить
   покейсно, и это отдельный `ДЕФЕКТ`, а не расхождение множеств.
3. **Носители прогона — сверкой клейма с фактикой.** По каждому кейсу
   клейм колонки «Носитель прогона» (называет ли она код-тест / запрос
   коллекции; по кейсу — объединение его строк) сверяется с грепом по
   каталогу код-тестов и по коллекции. Расхождение в **обе** стороны —
   `ДЕФЕКТ`: носитель объявлен, но не найден, либо носитель существует,
   а колонка говорит «нет». Перечень кейсов берётся **из колонки «Кейс»
   той же таблицы**, не хардкодом: реестр пополнится — проверка увидит
   новый кейс сама.

**Колонки берутся по именам шапки** («Пункт»/«№», «Кейс», «Носитель
прогона»), не по позиции, и при неразобранной шапке таблицы скрипт
**падает громко** (код возврата 3, `ОШИБКА: шапка таблицы реестра не
разобрана`), а не меняет смысл вывода молча. Тот же контракт — при
нулевом разборе гейт-заголовков плана и при отсутствии входных файлов
или каталога код-тестов. Клейм проверен пробами: переименованная колонка
шапки и историческая редакция без колонки «Носитель прогона» дают `rc=3`.

**Каждая ось доказана падающей пробой** — по стандарту
`.claude/processes/roadmap-step-execution.md` §«Оси проверочной команды
доказываются поимённо» (решение держателя 2026-08-29): падение на одной
оси не устанавливает остальных, поэтому проб — по одной на ось и сторону.
Прежняя редакция скрипта была «доказана» падением на одной оси и на двух
других молчала: `ДЕФЕКТ` разведённости уходил в stderr при коде возврата
0, форма «пп. N, M и K» терялась разбором, ось носителей на код возврата
не влияла (F1 `DOCS_CHECK_28`; ещё раньше проверка-предшественник
сравнивала множества кейсов и была зелена на породившем её дефекте — B2
мини-петли критики `GAPS_CLOSE_27`).

Батарея проб (мутации во временных копиях; рабочие файлы не трогаются).
Проба засчитана, только если **падает**; зелёная проба означает, что
мутация перестала попадать в носитель (изменилась опорная строка), и
проба переякоривается:

```bash
t=$(mktemp -d); P=.claude/tests/source-api/okx/plan.md; R=.claude/tests/source-api/okx/code-preconditions.md

# ось 1, плановая сторона (форма «пп. N, M и K»): гейт-пометке добавлены несуществующие пункты
sed 's/(предусловие п\. 1)/(предусловия пп. 1, 20 и 21)/' "$P" > "$t/plan.md"
bash tools/preconditions-check.sh "$t/plan.md" "$R"   # → «< AG1.5 20», «< AG1.5 21», rc=1

# ось 1, реестровая сторона: строка слота AG1.9-п.1 удалена
grep -v 'обратной стороны' "$R" > "$t/reg.md"
bash tools/preconditions-check.sh "$P" "$t/reg.md"    # → «< AG1.9 1», rc=1

# ось 2: два кейса в одной строке
sed '/Агрегирует ли источник/ s/`AG1.5`/`AG1.5`, `AG1.9`/' "$R" > "$t/reg.md"
bash tools/preconditions-check.sh "$P" "$t/reg.md"    # → «ДЕФЕКТ: пункт 1 — в одной строке 2 кейса…», rc=1

# ось 3, «объявлен — не найден»: AG1.5 объявляет код-тест, которого нет
sed '/`AG1.5`/ s/| нет |/| код-тест `AgX` |/' "$R" > "$t/reg.md"
bash tools/preconditions-check.sh "$P" "$t/reg.md"    # → «реестр объявляет код-тест, грепом … не найден», rc=1

# ось 3, «существует — не назван»: носители AG6.1 скрыты за «нет»
sed '/AG6.1/ s/| [^|]*код-тест[^|]*|/| нет |/' "$R" > "$t/reg.md"
bash tools/preconditions-check.sh "$P" "$t/reg.md"    # → два «ДЕФЕКТ … колонка … не называет», rc=1

# контракт формы: переименованная колонка шапки
sed 's/| Кейс |/| Case |/' "$R" > "$t/reg.md"
bash tools/preconditions-check.sh "$P" "$t/reg.md"    # → «ОШИБКА: шапка … не разобрана», rc=3

bash tools/preconditions-check.sh                     # действительное состояние → «СОШЛОСЬ», rc=0
```

Историческая редакция, породившая F1 `DOCS_CHECK_27`, адресуется
**неподвижно** — редакция `GAPS_CLOSE_26`, `git show d132a37:<файл>`
(относительный адрес `git show HEAD` протух в момент коммита — F3
`DOCS_CHECK_28`). Нынешний скрипт на ней падает громко с `rc=3`: та
редакция реестра ещё не несла колонку «Носитель прогона». Канон
доказательства — батарея проб выше: она не зависит от истории git.

Расхождение слотов означает одно из двух: пара «пункт × кейс» помечена
гейтящей в плане и не заведена в реестр (гейт не сработает) либо названа
в реестре и снята с гейта в плане (гейт держит шаг без основания).
Правится **вместе** — план и реестр несут одно множество пар, а не два.

### Колонка «Носитель прогона» — почему она отдельная

Колонка «Статус наблюдения» отвечает только на вопрос «факт добыт?».
Вопрос «а есть ли чем добывать?» она не выражает вовсе, и потому
одиннадцать «⏳ не собрано» читались как «осталось нажать кнопку», тогда
как прогонять нечего: код-тест и запрос коллекции есть у **одного** кейса
из десяти, и тот производит не то наблюдение (F2, F3 `DOCS_CHECK_27`).

Цена решения названа: колонка в одной таблице, связность нулевая,
проверяемость — ось 3 `tools/preconditions-check.sh`: клейм колонки
сверяется с фактикой (перечень кейсов берётся из этой же таблицы,
грепается по каталогу код-тестов и по коллекции; расхождение клейма с
фактикой — `ДЕФЕКТ`, а не справка).

Отвергнуто: расширять статус кейса в плане (правка конвенции по 17
заголовкам и шаблону `templates/docs/test-plan.md` при той же
разрешающей способности) и «читать состояние носителя из плана» — план
его тоже не различает: `⏳ PENDING` стоит и у кейса с код-тестом, и без.

### Закрытие исходом `OBSERVED_ABSENT`

Механику исходов держит `.claude/tests/source-api/okx/plan.md` §«Исходы
содержательного кейса — их три, и третий закрывает гейт» (решение
держателя П18 валидации `GAPS_CLOSE_17`). Здесь — **место**, куда
обязательная запись ложится: слот, закрытый этим исходом, получает
строку в перечне ниже, а его ячейка «Статус наблюдения» — значение
`✅ OBSERVED_ABSENT (<дата>)`. Молча закрыть слот этим исходом нельзя:
без строки в перечне гейт считает слот открытым.

Форма строки: `<пункт> / <кейс> (<дата прогона>) — посылка проверкой не
подтверждена: событие за прогон не наблюдалось; допущение — <дословная
формулировка>`.

**Закрытых этим исходом слотов нет.** Первый ожидаемый кандидат — п. 10
(`AG1.8`, след автоделевериджа): событие инициирует биржа, заказать его
на demo нельзя.

## Что в реестр НЕ входит

- **Пункт 8 — калибратор допуска сверки** — гейтом быть перестал решением
  держателя (`GAPS_CLOSE_19`): в `CODE` выходим с некалиброванным
  допуском, он калибруется до боевой торговли
  (`.claude/work/backlog.md` §«Закрытие фазы 1 — снятие разведочного
  режима допуска сверки»). Номер назван явно: пока он молчал, ссылка
  «предусловие `CODE` п. 8» жила в рабочем файле как действующая
  (F8 `DOCS_CHECK_27`).
- **Пункт 13 — цена доведения шага до `CODE` при незакрытых разрывах** —
  решён держателем 2026-08-23 и гейтом не является: клеймы полноты шага 7
  непроверяемы до реализации системного слоя, и «чисто» на `DOCS_CHECK`
  означает «доки не противоречат друг другу», а не «спецификация
  реализуема». Отчёт прогона обязан различать эти два утверждения явно.
- **Номера 3, 4, 11, 12** — снятые редакции реестра до его переноса; их
  предмет ни в одном живом носителе гейтящим не значится. Номера не
  переиспользуются и не сдвигаются (`.claude/rules/closed-work-transfer.md`
  §«Ссылочная целостность»); действующее множество гейтящих пунктов
  задаётся **таблицей выше** и сверяется с планом командой §«Сверка
  реестра с планом».
- **`M15.7` (семантика `actualPx`)** — гейтом не размечен ни планом, ни
  реестром.
- **Знаки трёх операндов записи и bill'а штрафа** (`AG1.7`, пункт 7
  §«Грунт `integrator`» backlog) — гейта не образуют: знак выясняется
  прогоном и правится по факту. Кейс общий с пп. 7 и 14, предусловие —
  нет.

## Почему грунт не собран

Состояние на **2026-08-29**: кейсы **описаны** на все тринадцать слотов,
**исполнимый носитель** есть у одного кейса из десяти, собрано **ноль**.
Блокеров два, и они независимы.

**Блокер 1 — носителей прогона нет** (колонка «Носитель прогона»). У
девяти кейсов из десяти нет ни код-теста, ни запроса коллекции; у
десятого (`AG6.1`) код-тест есть, но ассертит **мощность** справочника
(`observe(...)` печатает `data.size`), а предусловиям пп. 2 и 16 нужен
**перечень** — то есть перепрогон в нынешнем виде воспроизведёт тот же
дефект. Написание носителей — этап 4 контура
(`.claude/processes/source-api-testing.md`), и он идёт **после** аппрува
пары план + коллекция: семнадцать кейсов шага 7 в коллекции не
представлены, аппрув 2026-06-19 их не покрывает.

**Блокер 2 — среда.** Прогон контура требует поднятого приложения на
профиле `test`, а среда его не даёт. Проверено фактически (командой), не
выведено:

| Что нужно контуру | Состояние | Чем проверено |
|---|---|---|
| Maven (`mvn -o test -Dgroups=source-api-live`) | **отсутствует**; wrapper'а `mvnw` в репозитории нет | `mvn` → `command not found`; `Get-Command mvn` пусто |
| Java 25 (проект — Java 25) | доступна только **11** | `java.exe` → `Amazon Corretto jdk11.0.28_6` |
| Docker (поднять `docker-compose.yml`) | **отсутствует** | `docker` → `command not found`; каталогов Docker Desktop нет |
| Vault `127.0.0.1:8200` — demo-креды OKX (`secret/tradingbot/okx-test`) | **не отвечает** | `curl /v1/sys/health` → нет ответа |
| Postgres-test `5441` (datasource профиля `test`) | **не слушает** | `Test-NetConnection 127.0.0.1:5441` → `False` |
| Сеть до биржи | **есть** | публичный `GET /api/v5/public/time` → `HTTP 200` |

Средовой блокер живёт своим пунктом: `.claude/work/backlog.md`
§«Средовой дефицит автономного RUN тестов (контур source-api)» — там
состав работ (wrapper в репо, проброс Vault-токена, инвариант роли
`tester`). Здесь — только указатель: «что мешает» читается там же, где
гейт.

**Что это значит для гейта.** Дефицит слотов остаётся `грунт`, и
`.claude/processes/roadmap-step-execution.md` §4 отправляет их на сбор
немедленно — но сбор упирается в носители и среду, а не в очередь работ.
Слоты **не** закрываются исходом `OBSERVED_ABSENT`: он означает «кейс

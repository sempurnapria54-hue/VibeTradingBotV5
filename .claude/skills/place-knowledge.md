# Размещение знания

## На какой вопрос отвечает этот файл

Как именно разместить фрагмент знания в репозитории.

## Когда применять

Шаг 5 процесса классификации знания: после того как известны
область, тип и тема фрагмента — нужно положить его в файл.

## Шаги

1. **Найти каталог типа.** По таблице в
   `.claude/rules/structure.md` для уже определённого типа
   находится физический путь (например, тип «правило» →
   `.claude/rules/`).

2. **Найти файл темы в каталоге.**
   - Если есть файл, соответствующий теме фрагмента, —
     фрагмент размещается в нём.
   - Если нет — создаётся новый файл. Имя — по правилам в
     `.claude/rules/naming.md` (kebab-case / PascalCase / с
     датой и т. д., в зависимости от типа).

3. **Разместить фрагмент.**
   - В новом файле — создать структуру разделов под содержание.
   - В существующем — добавить в подходящий раздел или
     завести новый раздел.
   - Не дублировать содержимое: одна формулировка живёт в
     одном месте.

4. **Проверить раздел «На какой вопрос отвечает этот файл».**
   - В новом файле — обязательно создать этот раздел в начале
     с одной фразой-формулировкой вопроса.
   - В существующем — убедиться, что после добавления фрагмента
     раздел всё ещё корректно описывает содержание файла. Если
     нет — пересмотреть размещение (возможно, фрагмент должен
     быть в другом файле или образует новый файл).

5. **`git add`** на созданный/изменённый файл (staging, не
   commit).

## Кандидат в процесс: проверка материализации

Если фрагмент опознан кандидатом в **процесс**
(`recognize-knowledge` / `classify-type`: поток/оркестрация над
несколькими сущностями, координация джобы — в т. ч. встроенный в
другую задачу), то **перед** созданием `docs/processes/<X>.md`
прогнать двухусловный критерий. Файл создаётся, только если
выполнено **хотя бы одно** условие:

1. **Собственное содержание про оркестрацию** — связное описание
   потока (последовательность шагов, входы/выходы между
   компонентами, условия запуска), которое не дублируется ни в
   одном компоненте и не покрывается lifecycle какой-то одной
   модели.
2. **Точка композиции для других процессов** — процесс вызывается
   другим процессом как подпроцесс (композиция потоков); нужна
   устойчивая точка ссылки между кластерами знаний.

Если не выполнено ни одно условие — отдельный файл процесса **не
создаётся**: содержание распределяется по владельцам (правило идёт
к своему первоисточнику, см. `classify-type` §«Первоисточник
правила» и `.claude/decisions/rule-source-of-truth.md`). Обоснование
критерия и прогон по кандидатам —
`.claude/decisions/process-materialization-criterion.md`.

# Размещение знания

## На какой вопрос отвечает этот файл

Как именно разместить фрагмент знания в репозитории.

## Когда применять

При появлении нового фрагмента знания (правило, решение,
описание, наблюдение, задача, вопрос), который нужно где-то
зафиксировать. Не для каждого предложения в чате — только для
того, что должно остаться в репозитории.

## Шаги

1. **Прочитать фрагмент.** Понять, о чём он.

2. **Сформулировать вопрос**, на который этот фрагмент
   отвечает. Если фрагмент отвечает на несколько вопросов —
   зафиксировать все.

3. **Сверить с таблицей в `.claude/rules/structure.md`.**
   Найти строку с этим вопросом.

4. **Если совпадение однозначное:**
   - Имя файла — по правилам в `.claude/rules/naming.md`.
   - Создать файл по указанному пути.
   - Если файл уже существует — добавить фрагмент в подходящий
     раздел или создать раздел.
   - В начале файла обязателен раздел «На какой вопрос отвечает
     этот файл» с формулировкой вопроса из шага 2.

5. **Если фрагмент отвечает на несколько вопросов:**
   - Разнести по местам: каждая часть — в свой файл.
   - Если части тесно связаны и не делятся — положить в
     основной тип, в других файлах оставить ссылки.
   - Не дублировать содержимое: одна формулировка живёт в
     одном месте.

6. **Если фрагмент не подходит ни под один вопрос из таблицы:**
   - НЕ угадывать.
   - НЕ изобретать новый тип сразу.
   - Завести открытый вопрос в
     `.claude/work/questions/open-questions.md`: «Куда положить
     <описание фрагмента>?».
   - Обсудить с пользователем.
   - После решения — зафиксировать его в `decisions/`. Решение
     может ввести новый тип в `structure.md`, переразложить
     фрагмент на существующие, или что-то ещё.

## Граничные случаи

- **Фрагмент похож на правило, но это разовое наблюдение.**
  Признак правила — повторяющееся применение, обязательность.
  Признак наблюдения — разовость, фиксация факта. Сомневаешься
  — в `notes/`. Если потом окажется, что это правило — оформим
  как decision и перенесём в `rules/`.

- **Фрагмент — решение, но без явных альтернатив.** Если
  альтернативы не рассматривались и решение тривиальное —
  это правило (`rules/`), не decision. Decisions оформляются
  только когда есть выбор и его нужно объяснить.

- **Фрагмент — описание чего-то нового в продукте.** Если это
  доменная модель — `docs/models/`. Если процесс системы —
  `docs/processes/`. Если жизненный цикл объекта —
  `docs/lifecycles/`. Если поведенческое или структурное
  правило — `docs/rules/`. Если термин — `docs/dictionary/`.

# Ревью безопасности

## На какой вопрос отвечает этот файл

Как именно сделать ревью безопасности кода (фокус `security`).

## Статус: деактивирован

**Фокус `security` деактивирован** до шага «Безопасность» Фазы 1
(`.claude/work/roadmap/phase-1.md`). На под-шаге `CODE` текущих шагов
**не применяется**. Активные `CODE`-фокусы сейчас: `conventions`,
`performance`, `disaster`. Реактивируется на шаге «Безопасность»,
где строится auth-инфраструктура (Spring Security, `@PreAuthorize`,
`SecurityFilterChain`). Стаб ниже — placeholder на момент
реактивации.

## Когда применять

Под-шаг `CODE` процесса
`.claude/processes/roadmap-step-execution.md` — фокус `security`
адверсариального ревью кода. Действует **после реактивации** на
шаге «Безопасность».

## Назначение и границы

Адверсариальный проход по коду шага с фокусом на безопасность. В
фокусе:

- секреты и ключи (в т. ч. ключи OKX) — не утекают в логи, код,
  репозиторий;
- валидация входов — наш API (что принимаем) и потребление чужого
  (ответы биржи);
- безопасность ордеров — что именно посылаем на биржу.

Находим и формулируем замечания; не чиним, не размещаем, не решаем
(адверсариальная стойка).

## Скелет

- **Вход:** утверждаемый код шага + контекст шага.
- **Выход:** список замечаний по безопасности.
- **Принцип:** независимость, свежий взгляд — ищем брешь, а не
  подтверждаем безопасность.

## Доработка

Процедура и форма замечаний дорабатываются по ходу; форма снимается
с первого реального применения на под-шаге `CODE`. Спекулятивную
процедуру здесь не фиксируем.

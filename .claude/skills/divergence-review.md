# Ревью расхождений код↔доки

## На какой вопрос отвечает этот файл

Как найти расхождения утверждённого кода с доками (фокус
`divergence`).

## Когда применять

Статус `REVIEW` машины шага
(`.claude/processes/roadmap-step-execution.md` §«`REVIEW`») — фокус
`divergence` адверсариального ревью. Детект расхождений; реконсиляцию делает
`.claude/skills/reconcile-knowledge.md` (изменения/удаления) и
штатный поток curator (добавления).

## Назначение и границы

Независимый проход, сверяющий утверждённый код с доками и
выписывающий, где они разошлись. Направление сверки — docs←code: код
прошёл `CODE` с зелёным реактором и считается истиной; расхождение —
либо пробел `DOCS`, либо находка по коду, и отчёт называет, какое из
двух. Полная сверка — добавления, изменения, удаления.

Находим и формулируем расхождения; не чиним, не размещаем, не решаем
(адверсариальная стойка).

## Скелет

- **Вход:** утверждённый код шага + релевантные доки.
- **Выход:** список расхождений, классифицированных как
  add / change / remove (что в коде есть, а в доках нет; что
  разошлось; чего в коде больше нет, а в доках осталось).
- **Принцип:** независимость — свежий взгляд, без опоры на авторский
  замысел доков или кода.

## Доработка

Метод сравнения (как именно сопоставляются код и доки) и форма
списка расхождений дорабатываются по ходу sync-прогонов.
Спекулятивную процедуру здесь не фиксируем.

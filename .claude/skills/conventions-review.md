# Ревью конвенций

## На какой вопрос отвечает этот файл

Как именно сделать ревью соответствия кода конвенциям (фокус
`conventions`).

## Когда применять

Под-шаг `CODE` процесса
`.claude/processes/roadmap-step-execution.md` — фокус `conventions`
адверсариального ревью кода.

## Назначение и границы

Адверсариальный проход по коду шага на соответствие зафиксированным
правилам: `codestyle` (стиль написания) и `tech-radar` (выбор
технологий). В фокусе — расхождения написанного кода с этими
правилами. Эталон правил живёт в `codestyle`/`tech-radar` (сюда не
копируем); здесь — процедура прохода и перечень признаков, что искать.

Находим и формулируем замечания; не чиним, не размещаем, не решаем
(адверсариальная стойка).

## Скелет

- **Вход:** утверждаемый код шага + `codestyle` + `tech-radar`.
- **Выход:** список замечаний о расхождениях с конвенциями.
- **Принцип:** независимость, свежий взгляд — сверяемся с правилами,
  а не с замыслом автора.

## Процедура

1. Берём дифф/код шага и идём по чеклисту признаков ниже — класс за
   классом, не полагаясь на «вроде нормально».
2. На каждое расхождение — отдельное замечание (см. форму).
3. Не чиним и не решаем: формулируем и возвращаем. Неоднозначное
   (правило не покрывает случай / развилка между опциями) — в чат.

## Чеклист признаков

Признаки нарушения, по разделам `codestyle` (детальная формулировка
правила — там же):

- **Поля и доступ.** Не-`private` поле; вручную написанный
  геттер/сеттер/конструктор-аксессор вместо Lombok.
- **Примитивы и обёртки.** Примитив в параметре/возврате метода
  контрактной поверхности или в Lombok-поле; избыточный `X.valueOf`
  на call-site (должен быть автобоксинг).
- **Слои.** «Client» вместо «Integration»; контроллер видит
  integration DTO / `OkxRestClient`; маппинг не на границе слоёв.
- **Идентичность наружу.** API отдаёт `id` из БД вместо `internalId`;
  path-параметр — числовой id, не `internalId`.
- **Enum'ы.** Enum вне доменного слоя; в api/persistence/integration
  поле под enum не `String`.
- **Auditable по слоям.** Переиспользование доменного `Auditable` в
  другом слое вместо своего базового с постфиксом слоя.
- **Маппинг.** Ручной маппинг вместо MapStruct; имя метода не
  отражает слои-участники; избыточный `@Mapping` при совпадающих
  именах; срезанный слой в цепочке `api → domain → …`.
- **Константы.** Magic-число/строка вне `util.Constants` (кроме
  локальных технических и лог-сообщений).
- **Статические импорты.** Утилитные предикаты (`Objects.isNull` /
  `nonNull`, `CollectionUtils`, `BooleanUtils`, `StringUtils`)
  вызваны с именем класса вместо статического импорта (искл.
  `Objects.equals`).
- **Swagger / API.** Поле api-модели без `@Schema` с описанием
  назначения; больше двух `@RequestParam` без `@ParameterObject`;
  API-путь не «от общего к частному».
- **Джобы.** Джоба вне `domain.jobs`; внерасписанный запуск не через
  асинхронный фасад; нет выключателя `enabled` или CRON захардкожен
  (не из `@ConfigurationProperties`); тик не обёрнут
  `JobExecutionGuard.runExclusively`.
- **Выборка данных.** Сущность тянется целиком ради одного поля;
  `getRequiredBy…().get<Field>()` вместо проекции / `getRequired<Field>By…`;
  потенциально большая выборка без окна/пагинации (безлимитное
  `findAll`-подобное чтение).
- **Схема БД.** Имя таблицы в единственном числе (должно быть
  множественное, snake_case); FK-колонки/constraint'ы — наоборот, в
  единственном.
- **Deprecated API.** Использование deprecated классов/методов/констант
  (проверка — компиляция с `-Dmaven.compiler.showDeprecation=true` без
  предупреждений в нашем коде).
- **Логирование.** Секрет (`apiKey` / `secret` / `passphrase`) в
  лог-сообщении; ошибка внешнего API залогирована без контекста
  (endpoint, параметры, `code`/`msg`).
- **Вложенность и rich-модели.** Глубокая вложенность `if`; проверка
  состояния/инвариант в сервисе вместо метода модели.
- **Строгие правила.** `== null` / `!= null`; прямое отрицание вместо
  `BooleanUtils`; `.toList()` вместо `Collectors.toList()`; `New` в
  имени метода; `getRequiredById` не в `DataService`; внутренний
  класс/рекорд в сервисе; `a.equals(b)` вместо `Objects.equals`.
- **Неиспользуемый код.** Метод (репозиторный запрос, метод сервиса /
  маппера, хелпер), который никто не вызывает.
- **Tech-radar.** Библиотека/техника вне радара или со статусом
  `hold`.

Чеклист не закрыт: пополняется по мере появления конвенций в
`codestyle`/`tech-radar`.

## Форма замечания

- Одно замечание = одно расхождение: **что** (с точкой в коде) →
  **почему** (какое правило `codestyle`/`tech-radar`) → **как чинить**
  (кратко; на развилке — варианты, без навязанной рекомендации).
- На развилке или непокрытом правилом случае — в чат, по одному
  вопросу за раз.

# Подбор примеров из реального кода

## На какой вопрос отвечает этот файл

Как подобрать примеры из реального кода проекта для дозаполнения
доков (после написания кода).

## Когда применять

**После написания кода** (пост-код), при дозаполнении / обогащении
доков примерами — под-шаг `SYNC_DOCS_FROM_CODE` (docs←code) процесса
`.claude/processes/roadmap-step-execution.md`. Применяется
`knowledge-curator` (`.claude/agents/knowledge-curator.md`): когда
доку нужен иллюстрирующий пример, скилл находит его в уже написанном
коде проекта.

## Назначение и границы

Смотрит в **реальный написанный код проекта** и выдаёт релевантные
текущей доке примеры. Подход example-based: источник — сам код, а не
отдельный слой «референс-доков» (такого слоя нет). Подбирает примеры;
код не пишет, доки сам не размещает (размещение — `knowledge-curator`).

**Граница с код-шаблонами.** Это **другой инструмент для другой
фазы**. Абстрактные паттерны/шаблоны кода (плейсхолдеры `<Model>`) —
вход для *написания* кода — живут отдельным тиром
`.claude/templates/code/` и применяются `code-writer` на под-шаге
`CODE`. `find-code-examples` — пост-код, над реальным кодом, для
доков. См. `.claude/decisions/code-templates-vs-examples.md`.

## Скелет

- **Вход:** дока на дозаполнение (что иллюстрируем) + реальный
  написанный код проекта.
- **Выход:** релевантные примеры из кода для доки.
- **Принцип:** опора на реальный код проекта, а не на умозрительный
  пример.

## Доработка

Процедура подбора и форма примеров дорабатываются по ходу; форма
снимается с первого реального применения на под-шаге
`SYNC_DOCS_FROM_CODE`. Спекулятивную процедуру здесь не фиксируем.

# Прогон тест-плана

## На какой вопрос отвечает этот файл

Как именно прогнать утверждённый тест-план контура тестов API
источника.

## Когда применять

Этап **RUN** процесса
`.claude/processes/source-api-testing.md` — после аппрува плана и
написания код-тестов (`test-code`). Роль — `tester`.

## Назначение и границы

Прогон **код-тестов** (исполнитель) по утверждённому плану против API
источника на уровне сырья и фиксация результата. Самостоятельная
операция: регрессия гоняется по существующим код-тестам **без
пересоставления** плана (пересоставление — `test-design`).

Прогон до аппрува не запускается. Контур — **demo/non-prod**:
профиль-гейт держит код-тесты от prod структурно (`test-code`). Прод
вне контура.

## Известный скелет

- **Вход:** утверждённый план + код-тесты (`test-code`).
- **Исполнение:** код-тесты в порядке цепочек графа предусловий;
  **дешёвый негатив — первым**; создание реальных demo-сущностей;
  teardown в каждом кейсе — прогон не оставляет висящих ордеров /
  позиций / algo.
- **Выход:** бланк отчёта = **таблицы плана в структуре метод → кейсы →
  таблица** (durable, не пересобирается) с заполненной колонкой «Факт +
  наблюдения» (ожидание vs факт), плюс расхождения и неожиданности, не
  предусмотренные кейсом; раздел **«расхождения с апидоками»** (вход для
  C3-сверки). Отчёт — в `history` (датированный).

**Отчёт полный всегда**, независимо от режима (полнота логирования
от режима не зависит). Автоматический pass/fail код-теста не отменяет
фиксацию факта в бланке.

## Незадокументированное — не выдумывается

Если факт расходится с ожиданием, а спека не задаёт нормы, — tester не
подгоняет вердикт: фиксирует факт + наблюдение, помечает находкой
интегратору (этап «разбор находок»). Источниковый дефицит — эскалация
всегда.

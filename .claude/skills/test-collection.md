# Построение тест-коллекции

## На какой вопрос отвечает этот файл

Как именно построить исполняемую тест-коллекцию (Postman) по
тест-плану.

## Когда применять

Этап **DESIGN** процесса
`.claude/processes/source-api-testing.md`, вместе с построением
плана (`test-design`). Роль — `tester`. Коллекция строится на
DESIGN, **до запуска** (RUN).

## Назначение и границы

По тест-плану строится исполняемая Postman-коллекция (v2.1) —
материализация кейсов плана в запросы через наш прокси. Скилл
**строит** коллекцию; не ревьюит (это `reviewer`, фокус
`test-review`) и не прогоняет (это `test-run`, этап RUN). Скоуп —
**API источника через наш клиентский слой**, граничная поверхность
прокси-контроллера (`OkxProxyController` для OKX); домен (Deal, FSM,
executors) вне охвата.

## Ключевые правила

- **Через наш прокси.** Все запросы идут на прокси-путь источника
  (`/api/proxy/okx/*`). Подпись и креды — на стороне app (signing
  interceptor): в Postman подпись **не считается**, кредов в Postman
  **не нужно**.

- **demo/prod — профилем поднятого app**, не тумблером в Postman.
  Тот же proxy-путь; demo vs prod определяет профиль запущенного
  приложения. base URL — **переменной** (`base_url`). Окружение —
  шаблон с `base_url`; **кредов в шаблон не класть**.

- **Структура — папка ↔ таблица плана (кейс).** 1 папка коллекции =
  1 таблица плана (один кейс): структурное соответствие
  план ↔ коллекция, папка повторяет кейс один-к-одному (осмысленное
  имя по кейсу, **не** деление read-only/write). Папки с
  write-кейсами помечать в описании: на prod-профиле — **реальные
  ордера/эффекты на бирже**.

- **Подпись кейсом плана.** Каждый запрос несёт в имени/описании
  метку своего кейса плана (`N1`, `C1`, `A3`, …), чтобы сценарии
  читались.

- **Per-request — проверки наличия полей.** Проверки наличия полей в
  ответе прокси ставятся на **фактических response-формах нашего
  клиентского слоя** (mapped DTO / `*ExternalSnapshot`,
  `ExchangeAck`) по реальным полям + статус-код. Поле, которое слой
  на границу не выводит (например, адаптер-инварианты на снапшоте),
  через прокси не наблюдаемо — помечается как surface-gap, проверка
  не выдумывается.

- **Проверки кодируют ожидание плана.** Где открытая находка делает
  текущее поведение иным — **фейл проверки по дизайну показывает
  находку** (проверку не подгоняют под текущее поведение). Где
  вердикт плана частично неизвестен (рантайм-снятие) — проверка
  кодирует гипотезу, а её фейл = сигнал находки на разбор, не
  pass/fail с готовым ответом.

- **Цена ордера — live с биржи, минимальный риск.** Кейс, ставящий
  ордер, не зашивает цену константой: коллекция сперва тянет live-цену
  с биржи через прокси (ticker / mark), кладёт её в переменную и от
  неё формирует цену ордера — **заведомо неисполнимую, с минимальным
  риском** (проверяем интеграцию, не теряем деньги; критично на prod).
  **Предусловие:** у прокси есть эндпоинт live-цены. Нет такого
  эндпоинта — **surface-gap**: помечается в описании папки/пункта,
  запрос цены не выдумывается, gap закрывается при регенерации (или
  заводится находкой).

- **Цепочка переменных.** id из write-ответа (`ordId`/`algoId` →
  `ExchangeAck.externalId`) сохраняется в переменную коллекции и
  потребляется зависимыми запросами — **без ручной вставки** между
  шагами. Stable client id (`clOrdId`/`algoClOrdId`) генерится
  pre-request-скриптом и переиспользуется по цепочке.

- **Кейс, не покрываемый прокси.** Кейс плана без proxy-эндпоинта
  (surface-gap, напр. свечи) или требующий уровня ниже прокси
  (сырой клиентский вызов) — **помечается в описании** папки/пункта,
  запрос **не выдумывается**.

## Общий жизненный цикл с планом

Коллекция — **поверхность ревью наравне с планом**. Ревьюится
(`test-review`), аппрувится и правится **вместе с планом**: одни и
те же замечания правят оба, аппрув — на оба. Прогон (RUN) — по
утверждённой паре план + коллекция.

## Вход / Выход

- **Вход:** тест-план (`.claude/tests/{testType}/{source}/`);
  прокси-контроллер источника (фактические пути, параметры,
  response-формы); response-DTO/снапшоты клиентского слоя.
- **Выход:** Postman-коллекция (v2.1) + шаблон окружения (`base_url`,
  без кредов) в `.claude/tests/{testType}/{source}/`.

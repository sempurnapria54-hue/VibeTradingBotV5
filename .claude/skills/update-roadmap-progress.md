# Обновление прогресса роадмапа

## На какой вопрос отвечает этот файл

Как обновить статус шага в роадмапе и пересчитать статус фазы.

## Когда применять

**По завершении любого статуса шага — как его часть, не по сигналу**
(`.claude/processes/roadmap-step-execution.md` §«Гейты», пассаж «Фиксация
статуса — часть каждого статуса»): записал апрув ревью концепции, довёл
код до зелёного реактора, положил доки, получил апрув держателя — сразу
прогнал этот скилл. Статус не считается пройденным, пока следующий не
проставлен и ролляп фазы не пересчитан. Исполнитель — Claude Code; вход —
фаза + шаг + новый статус.

Гейты живут здесь, в скилле, который **исполняется** при смене статуса, а
не в файлах, которые в этот момент никто не откроет: условие, записанное
только в правиле, читает тот, кому оно и так нужно.

## Вход

- Номер фазы (например, `2`).
- Номер шага в фазе (например, `12`).
- Новое значение статуса для шага.

## Канонический набор статусов шага

`HOLD` → `CONCEPT` → `CONCEPT_REVIEW` → `CODE` → `DOCS` → `REVIEW` → `DONE`.
Источник истины и смысл каждого —
`.claude/processes/roadmap-step-execution.md` §«Машина шага»; здесь набор
не пересказывается. Итерационных номеров у статусов нет; счёт под-шага
(`CODE·<k>/<n>`) номером захода не является и стои́т у шага с объявленным
перечнем под-шагов — форма и её довод живут в том же §«Машина шага».

## Канонический набор статусов фазы

| Статус | Когда |
|---|---|
| `HOLD` | Все шаги фазы — `HOLD`. |
| `DONE` | Все шаги фазы — `DONE`. |
| `IN_PROGRESS` | Иначе (хотя бы один шаг отличается от `HOLD`, не все в `DONE`). |
| `FOLDED` | Ставится вручную решением держателя: фаза растворена в новом роадмапе. Ролляп не считается. |

## Шаги

1. **Валидация значения.** Проверить, что новый статус шага — из
   канонического набора и следует за текущим по машине (откат назад —
   только с названной причиной в хронике).

   **У шага с объявленным перечнем под-шагов валидируется и счёт**
   (`CODE·<k>/<n>`): суффикс стои́т только у `CODE`, `n` равно длине
   объявленного перечня, `k` — от `1` до `n` и отвечает под-шагу, который
   шаг взял. Переход к следующему под-шагу есть смена статуса и идёт этим же
   скиллом — со своим прогоном `--статус <фаза>-<шаг>=CODE·<k>/<n>` до
   записи, как всякая другая. **Разборщики роадмапа эту ось не мерят:** они
   отвергают лишь рваную форму, а верность счёта — обязанность пишущего
   (`.claude/processes/roadmap-step-execution.md` §«Машина шага», остаток
   назван там же).

2. **Гейт-предусловие перехода** — §ниже, по целевому статусу. Не пройден
   → статус не проставлять; сигналить, что именно не пройдено.

3. **Открыть детальный файл фазы.** Путь —
   `.claude/work/roadmap/phase-<N>.md`. Если файла нет —
   остановиться, сигналить в чат: для этой фазы детальный файл
   ещё не создан.

4. **Обновить ячейку «Статус» строки шага.** Найти строку с
   указанным номером шага, заменить значение в колонке «Статус».
   Остальные ячейки не трогать.

5. **Пересчитать статус фазы.** Собрать значения «Статус» по
   всем шагам файла. Применить правила ролляпа из таблицы выше.
   **Ролляп дал `DONE` → пройти §«Гейт закрытия фазы» (ниже) до шага 7.**

6. **Открыть главный файл роадмапа.** Путь —
   `.claude/work/roadmap/roadmap.md`.

7. **Обновить ячейку «Статус» строки фазы.** Найти строку фазы
   с указанным номером, заменить значение в колонке «Статус»
   результатом ролляпа.

8. **`git add`** на оба изменённых файла (staging, не commit).

## Гейт-предусловие перехода

Перед простановкой каждого статуса — проверить **зафиксированный исход**
предыдущего (источник правила — `.claude/processes/roadmap-step-execution.md`
§«Машина шага»). Зафиксированный исход = запись в хронике шага либо отчёт
в `work/progress/`, **не** устное согласие и не самопроверка.

- **`CONCEPT`** — держатель решил о входе в шаг (на границе закрытого шага
  цепочка остановилась и была перезапущена, либо держатель сказал в чате).
- **`CONCEPT_REVIEW`** — носитель концепции назван в хронике шага
  (`.claude/processes/roadmap-step-execution.md` §«Термин «концепция»»).
- **`CODE`** — отчёт ревью концепции записан
  (`work/progress/phase-<N>-step-<M>-concept-review.md`) с исходом
  «апрув»: открытых **гейтящих** вопросов класса `подтверждение` нет.
  Проверка механическая — по вердиктам гейтинга
  `.claude/work/questions/open-questions.md` (команда — там же,
  §«Вердикт гейтинга — обязательное поле вопроса»): вопрос с вердиктом
  «гейтит» у этого шага статус не пропускает.
- **`DOCS`** — реактор зелен (§«Сборка — реактор»), гейт инструментов
  корпуса зелен, хроника называет, что построено; у шага «Тесты» — все
  три под-шага `CODE` пройдены в своём порядке, апрув кейсов (под-шаг 2)
  записан.
- **`REVIEW`** — доки построенного лежат на своих местах и названы в
  хронике; гейт инструментов корпуса зелен.
- **`DONE`** — исходы фокусов ревью зафиксированы отчётами, каждая находка
  получила исход (закрыта / припаркована с домом, оживителем и причиной),
  **апрув держателя записан в хронику датой**; гейт инструментов корпуса
  и реактор зелены; `backlog-check.py` прогнан с подменой статуса.

## Гейт инструментов корпуса

**Все проверочные команды корпуса прогоняются перед сменой статуса, и
ненулевой код любой из них статус не пропускает.** Гейт заведён встречным
якорем: детектор, у которого нет носителя-гейта, красен и незаметен.

```bash
bash tools/spec-run.sh                    # примеры исполняются и сходятся
bash tools/spec-mutation-check.sh         # каждая величина что-то проверяет
python3 tools/spec-scope-check.py docs/spec   # области видимости и копии формы
python3 tools/spec-pointer-check.py       # указатель ведёт в дом величины
python3 tools/anchor-check.py             # §-адреса .claude/**: новых битых нет
python3 tools/retired-check.py            # снятая редакция не жива в носителях
python3 tools/population-derive-check.py  # перечень популяции спеки выведен из предмета
python3 tools/deploy-layout-check.py      # раскладка кода и манифестов == её домам
python3 tools/doc-pointer-check.py        # доковые указатели тела кода ведут в существующие файлы
python3 tools/self-count-check.py         # число и исход, написанные о себе, сходятся с предметом
python3 tools/command-carrier-check.py    # команда, объявленная воспроизводимой, стоит блоком кода
python3 tools/backlog-check.py            # секция бэклога и перечня проверок на проде несёт владельца и машинное условие; сработавшее условие получило исход
python3 tools/surface-path-check.py       # корень контроллера начинается именем своей единицы
python3 tools/ownership-map-check.py      # карта владельцев-сервисов покрывает фактику корпуса
python3 tools/enum-domain-pointer-check.py     # компонент содержимого, выведенный у писателя, несёт указатель на дом перечня
```

**`python3` в этой среде — заглушка Windows Store**; команды зовутся через
`py` (`.claude/rules/measurement-commands.md` §«Ловушки среды»).

**`backlog-check.py` прогоняется с подменой статуса, который сейчас
проставляется:** `py tools/backlog-check.py --статус <фаза>-<шаг>=<новый
статус>` (при закрытии прод-рубежа — `--рубеж=DONE`). Условие «шаг DONE»
срабатывает **самой простановкой**, и без подмены гейт пропустил бы статус,
а следующая сессия встретила бы красный прогон на чужой правке. Секция,
чей оживитель сработал, получает исход — закрыта в `history/`,
перевооружена или взята в работу — тем же ходом, что и статус
(`.claude/rules/backlog-section-form.md` §«Исход сработавшего условия»).

**Код возврата 2 у любой из них означает «не измерялось», а не «дефектов
нет»** (`.claude/rules/measurement-commands.md` §«Измерительная команда
отказывается, когда мерить нечего»): такой исход статус не пропускает
наравне с кодом 1. Батареи осей исполняются теми же командами — отдельных
проб-скриптов нет.

## Сборка — реактор

Если статус проставляется после правки дерева кода
(`git diff --name-only <база захода> -- services/ web/` непуст), к
перечню добавляется прогон реактора, и **команда называется в хронике
дословно**. Ненулевой код статус не пропускает.

```bash
bash tools/reactor-test.sh   # реактор из корня: компиляция ВСЕХ деревьев + весь unit-набор
```

**Голый `mvn -o test` гейтом не является.** Maven считает модуль собранным,
пока его `target/classes` новее исходников, и печатает «Nothing to compile»
— классы при этом могли быть собраны против прежней редакции общей
библиотеки. Обёртка сносит классы, прогоняет реактор и отказывается
объявлять зелёное, пока в логе есть «Nothing to compile»; её оси доказаны
батареей, исполняемой той же командой. Точечная форма — `mvn -o -am -pl
<модуль> test -Dtest=<Класс>`: `-am` собирает то, от чего модуль зависит;
сборка одного дерева через `-f` разрешала бы зависимости из локального
репозитория, то есть проверяла бы предыдущую сборку.

**`mvn` на `PATH` в этой среде отсутствует** — рабочий бинарь и
переменные окружения названы в `.claude/skills/environment-commands.md`
§«Воспроизводимые команды»; здесь они не дублируются.

## Гейт закрытия фазы

**Ролляп фазы в `DONE` — момент срабатывания правил с условием снятия «конец
фазы N».** Такие правила по построению не прочитываются в нужный момент:
условие живёт внутри правила, а открывает его тот, кому оно и так нужно.
Поэтому проверка — здесь, в скилле, который **исполняется** при смене
ролляпа.

Перед простановкой фазе `DONE` (шаг 7) — **найти носители механически, по
строке-маркеру**, и пройти каждый:

```bash
grep -n '^\*\*Встречный якорь\.\*\*' .claude/work/backlog.md .claude/work/prod-checks.md
```

Файлов два: рабочий бэклог и перечень проверок на проде
(`.claude/decisions/prod-checks-split.md`) — якорь с условием «прод-рубеж»
живёт по большей части во втором, и грепом по одному бэклогу он не находится.
Каждая секция любого из двух, несущая условие снятия, которое сама снимаемая
политика прочитать не может, обязана нести эту строку-маркер в своём теле.
Гейт берёт **весь** её вывод — перечня носителей в скилле нет: поимённый
перечень, растущий вручную, и есть ровно то, против чего гейт заведён.

**Что гейт требует от найденного носителя** — зависит от того, чем задано
его условие, и это читается в самой секции:

- **условие по фазе** («до конца фазы N») — пункты обязаны быть
  **выполнены**: правило снято, миграции пересмотрены, флаг убран;
- **условие по данным или по событию после фазы** («по данным первого
  периода живой торговли», «по измеренному базису») — гейт **не** требует
  исполнения: он требует, чтобы пункт был **жив и передан вперёд** — секция
  на месте, её условие названо.

**Встречная проверка обязательна и при непустом выводе.** Маркеры находят
секции, которые кто-то **не забыл** пометить; правило, чьё условие снятия
называет конец фазы, а секции ни в одном из двух файлов формы не получило,
маркером не находится по построению. Поэтому вторым ходом — **всегда**:

```bash
grep -rln 'конц[ае] фазы\|конец фазы\|до конца фазы' .claude/rules/
```

По каждому попаданию: есть ли у правила секция с маркером — в `backlog.md`
либо, если её условие возврата целиком продовское, в `prod-checks.md`
(`.claude/rules/backlog-section-form.md`)? Нет — завести её **до**
простановки `DONE`.

Гейт **не пройден → фазе `DONE` не проставлять**; сигналить, какой пункт
закрытия не выполнен.

## Граничные случаи

- **Шаг с указанным номером не найден.** Не угадывать; сигналить
  в чат, ждать уточнения.
- **Несогласованность ролляпа.** Если статус фазы в главном файле до
  пересчёта отличается от ожидаемого по правилам ролляпа — после
  обновления привести к корректному значению, отметить в отчёте.
- **Прод-рубеж** в главной таблице — не фаза, ролляп для него не считается;
  статус ведётся вручную, его прохождение исполняет §«Гейт закрытия фазы»
  по встречным якорям бэклога.

## Отчёт

После выполнения — короткое сообщение в чат:
- какой шаг и в какой фазе обновлён;
- предыдущее и новое значение статуса шага;
- какой статус получила фаза после ролляпа (с пометкой
  «без изменений», если ролляп не сдвинул статус фазы).

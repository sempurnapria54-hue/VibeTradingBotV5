# Обновление прогресса роадмапа

## На какой вопрос отвечает этот файл

Как обновить статус шага в роадмапе и пересчитать статус фазы.

## Когда применять

**По завершении любого под-шага — как его часть, не по сигналу**
(`.claude/processes/roadmap-step-execution.md` §«Фиксация статуса —
часть каждого под-шага»): выпустил gap-отчёт, закрыл находки, получил
аппрув фокуса — сразу прогнал этот скилл. Под-шаг не считается
завершённым, пока статус не проставлен и ролляп фазы не пересчитан.
Исполнитель — Claude Code; вход — фаза + шаг + новый статус.

**Формулировка «по сигналу из чата» снята.** Она
делала скилл — а вместе с ним и все его гейты — зависимым от того,
вспомнит ли кто-то его позвать: гейт выхода из `GAPS_CLOSE_N` заведён
**против** незамечаемого пропуска и сам страдал тем же. Встречный якорь
со стороны события у него теперь тот же, что у всей простановки
статуса, — обязанность процесса, а не память исполнителя. (У гейта
закрытия фазы якорь другой и остаётся: §«Гейт закрытия фазы» ниже —
секции `.claude/work/backlog.md`, несущие строку-маркер
`**Встречный якорь.**`.)

## Вход

- Номер фазы (например, `1`).
- Номер шага в фазе (например, `4`).
- Новое значение статуса для шага.

## Канонический набор статусов шага

| Статус | Смысл |
|---|---|
| `HOLD` | Шаг не начат. |
| `TOOLING` | Создание агентов/скиллов для шага. |
| `DOCS_CHECK_N` | Проверка целостности концепции, N — номер итерации. |
| `GAPS_CLOSE_N` | Закрытие пробелов концепции, N — номер итерации. |
| `CODE` | Написание кода + ревью-итерации (фокусы) + аппрув. |
| `SYNC_DOCS_FROM_CODE` | Синхронизация доков под утверждённый код (docs←code). |
| `DONE` | Шаг завершён. |

Развёрнутое описание под-шагов — `.claude/processes/roadmap-step-execution.md`.

## Канонический набор статусов фазы

| Статус | Когда |
|---|---|
| `HOLD` | Все шаги фазы — `HOLD`. |
| `DONE` | Все шаги фазы — `DONE`. |
| `IN_PROGRESS` | Иначе (хотя бы один шаг отличается от `HOLD`, не все в `DONE`). |
| `FOLDED` | Ставится **вручную** решением держателя: фаза растворена в новом роадмапе — выполненные шаги остаются `DONE`, снятые убраны из таблицы, гейт закрытия фазы не исполняется (его пункты переякорены). Ролляп фазу со статусом `FOLDED` **не пересчитывает**. Происхождение — `.claude/decisions/roadmap-rebuild-for-service-platform.md`. |

Строка **прод-рубежа** (`.claude/work/roadmap/prod-gate.md`) — не фаза:
ролляп не считается, статус ведётся вручную; перевод её в `DONE` исполняет
§«Гейт закрытия фазы» ниже по маркерам встречных якорей.

## Шаги

1. **Валидация значения.** Проверить, что новый статус шага —
   из канонического набора. Для `DOCS_CHECK_N` / `GAPS_CLOSE_N`
   убедиться, что N — целое положительное число.

2. **Открыть детальный файл фазы.** Путь —
   `.claude/work/roadmap/phase-<N>.md`. Если файла нет —
   остановиться, сигналить в чат: для этой фазы детальный файл
   ещё не создан.

3. **Обновить ячейку «Статус» строки шага.** Найти строку с
   указанным номером шага, заменить значение в колонке «Статус».
   Остальные ячейки не трогать.

4. **Пересчитать статус фазы.** Собрать значения «Статус» по
   всем шагам файла. Применить правила ролляпа из таблицы выше.
   **Ролляп дал `DONE` → пройти §«Гейт закрытия фазы» (ниже) до шага 6.**

5. **Открыть главный файл роадмапа.** Путь —
   `.claude/work/roadmap/roadmap.md`.

6. **Обновить ячейку «Статус» строки фазы.** Найти строку фазы
   с указанным номером, заменить значение в колонке «Статус»
   результатом ролляпа.

7. **`git add`** на оба изменённых файла (staging, не commit).

## Гейт-предусловие перехода (`CODE` / `DONE`)

Перед простановкой `CODE` или `DONE` — проверить **зафиксированный
исход** требуемого гейта (источник правила —
`.claude/processes/roadmap-step-execution.md`):

- **`CODE`** — пройден **исполнимый критерий выхода** (`python3
  tools/code-gate-check.py` вернул 0; дом критерия —
  `.claude/processes/roadmap-step-execution.md` §Гейты, признак класса —
  `.claude/skills/classify-code-blocking.md`). Критерий **покомпонентный**
  (решение держателя 2026-09-01,
  `.claude/decisions/code-contact-as-gate.md`): на переходе он требует,
  чтобы реестр существовал, разбирался, у каждой позиции стоял компонент
  и прочие классы были задиспозиционированы, — а `КОД` и `РИСК`
  срабатывают **на кодовых заходах**, по мере того как компоненты
  начинаются. Поэтому **скрипт прогоняется не только здесь, но и перед
  каждым кодовым заходом**, после простановки статуса кодирования
  компонента. Далее — пройден §«Гейт грунта» (ниже) **и** пройден
  §«Гейт инструментов корпуса» (ниже).

  Снятые редакции: **чистый прогон** (2026-08-31, недостижим по
  построению) и **`КОД`/`РИСК` в ноль до перевода статуса** (2026-09-01,
  несходящаяся). Снята вместе с последней и сверка актуальности входа по
  полю «прогон» = последняя итерация `DOCS_CHECK_N`: итераций больше
  нет, реестр стал сквозным носителем фазы кода. Актуальность его входа
  теперь держит **таблица компонентов** — позиция без компонента и
  компонент без статуса кодирования скрипт не пропускает.

  **Компоненты СВОЕГО шага внесены в реестр — отдельный пункт гейта.**
  Реестр сквозной по фазе кода и новым шагом не пересобирается
  (`.claude/rules/structure.md`), но **пополняется им**: у каждого
  исполнителя, которого шаг кодирует, в реестре стои́т строка со статусом
  кодирования и признаком торговой тропы. Без этого пункта обязанность
  держалась памятью исполнителя: скрипт мерит **состав реестра** и о
  ненаписанном компоненте не знает — шаг с пустой долей проходит гейт так
  же, как шаг с полной.

  **Перечень исполнителей шаг выводит из своей дельты `CODE` чтением, и
  прогона у этого вывода нет — ограничение названо, а не умолчано.** Дельта
  ключуется предметом правки, не исполнителем: часть её позиций исполнителя
  не имеет вовсе (миграция, индекс, поле содержимого, манифест, тест), и
  механически отделить одни от других нечем. Поэтому пункт предъявляется
  так же, как прочие зафиксированные исходы гейта — **названным перечнем в
  отчёте перехода**: кого шаг кодирует и какой строкой реестра каждый
  представлен. Скрипт после этого мерит уже внесённое: позиция без
  компонента и компонент без статуса кодирования его не проходят.
- **`DONE`** — **зафиксированные исходы** адверсариальных фокусов:
  `conventions` / `performance` / `disaster` на `CODE` (находки закрыты;
  с шага 9 фазы 1 в перечень входит и `security`),
  `divergence` на `SYNC_DOCS_FROM_CODE` (расхождения реконсилированы),
  пост-хок концепт-гейт `.claude/processes/roadmap-step-execution.md` §6a
  (если применим).

Зафиксированный исход = отчёт фокуса в истории шага, **не** устное
согласие автора/пользователя и не самопроверка. Нет зафиксированного
исхода → статус **не** проставлять; сигналить, какой фокус не прогнан.

## Гейт инструментов корпуса

**Все проверочные команды корпуса прогоняются перед сменой статуса, и
ненулевой код любой из них статус не пропускает.** Гейт заведён встречным
якорем: детектор, у которого нет носителя-гейта, красен и незаметен —
измерено прогоном, где три новых детектора не были назван ни одним
исполняемым носителем, а один из них был красен прямо в момент прогона.

```bash
bash tools/spec-run.sh                    # примеры исполняются и сходятся
bash tools/spec-mutation-check.sh         # каждая величина что-то проверяет
python3 tools/spec-scope-check.py docs/spec   # области видимости и копии формы
python3 tools/spec-pointer-check.py       # указатель ведёт в дом величины
python3 tools/anchor-check.py             # §-адреса .claude/**: новых битых нет
python3 tools/retired-check.py            # снятая редакция не жива в носителях
python3 tools/population-derive-check.py  # перечень популяции выведен из предмета
bash tools/preconditions-check.sh         # реестр == план == фактика
python3 tools/deploy-layout-check.py      # раскладка кода и манифестов == её домам
python3 tools/doc-pointer-check.py        # доковые указатели тела кода ведут в существующие файлы
python3 tools/self-count-check.py         # число и исход, написанные о себе, сходятся с предметом
python3 tools/edit-kind-check.py          # классификация корпусного захода полна по словарю родов
python3 tools/command-carrier-check.py    # команда, объявленная воспроизводимой, стоит блоком кода
python3 tools/backlog-check.py            # секция бэклога несёт владельца и машинное условие; сработавшее условие получило исход
python3 tools/surface-path-check.py       # корень контроллера начинается именем своей единицы
python3 tools/ownership-map-check.py      # карта владельцев-сервисов покрывает фактику корпуса
python3 tools/insertion-neighborhood-check.py  # окрестность точки вставки предъявлена (проба О2 по дельте от метки)
python3 tools/enum-domain-pointer-check.py     # компонент содержимого, выведенный у писателя, несёт указатель на дом перечня
```

**Четыре последних введены межшаговым окном 2-10 → 2-11** (решение держателя
2026-09-11): они закрывают шесть задач-энфорсеров, взятых в работу переходом
шага 10 в `DONE`. Две из шести не завели своей команды, а **расширили** область
и нормализацию у `tools/retired-check.py` — отдельной строки гейта им поэтому
не положено.

**`backlog-check.py` прогоняется с подменой статуса, который сейчас
проставляется:** `python3 tools/backlog-check.py --статус <фаза>-<шаг>=<новый
статус>` (при закрытии прод-рубежа — `--рубеж=DONE`). Условие «шаг DONE»
срабатывает **самой простановкой**, и без подмены гейт пропустил бы статус, а
следующая сессия встретила бы красный прогон на чужой правке. Секция, чей
оживитель сработал, получает исход — закрыта в `history/`, перевооружена или
взята в работу — тем же ходом, что и статус
(`.claude/rules/backlog-section-form.md` §«Исход сработавшего условия»).

Перед простановкой **`CODE`** к ним добавляется `python3
tools/code-gate-check.py` — исполнимый критерий выхода (§«Гейт-предусловие
перехода (`CODE` / `DONE`)» выше). До `CODE` он отказывает кодом 2, пока
реестра диспозиции нет, и это правильный исход: критерий не измерялся.

**Правило правило `src/` — предъявляется зелёная сборка.** Если под-шаг,
чей статус проставляется, изменил хоть один файл в дереве кода
(`git diff --name-only <база под-шага> HEAD -- donor/ services/`
непуст), к перечню добавляется прогон тестов, и **команда называется в
отчёте перехода дословно**. Ненулевой код статус не пропускает.

```bash
bash tools/reactor-test.sh   # реактор из корня: компиляция ВСЕХ деревьев + весь unit-набор
```

**Голый `mvn -o test` гейтом больше не является, и это не вкусовая
замена.** Maven считает модуль собранным, пока его `target/classes` новее
исходников, и печатает «Nothing to compile — all classes are up to date».
Классы при этом могли быть собраны против **прежней** редакции общей
библиотеки: реактор отчитается `BUILD SUCCESS` и зелёными тестами, ни разу
не проверив, компилируется ли дерево вообще. Ровно это и наблюдалось на
аппруве `CODE` шага 8 фазы 2: «BUILD SUCCESS, 908 тестов» при нуле
скомпилированных файлов и **сломанной сборке донора**, которую настоящая
компиляция показала семью ошибками. Обёртка сносит классы, прогоняет
реактор и отказывается объявлять зелёное, пока в логе есть «Nothing to
compile»; её оси доказаны батареей, исполняемой той же командой. Смысл
правила от этого не меняется — меняется то, что команда теперь **мерит**.

**Команда одна на все деревья, и это следствие реактора.** С шага 3 фазы 2
деревьев больше одного (`donor`, `services/common/model/domain`), и агрегирующий
`pom.xml` в корне собирает их в порядке зависимостей. Прежняя редакция
предписывала называть затронутое дерево своим `-f`; она снята: у донора
теперь есть зависимость на общий артефакт, и сборка **только** донора
разрешала бы её из локального репозитория, то есть проверяла бы
предыдущую сборку вместо нынешней.

**Точечная форма тоже стала реакторной, и это проверено прогоном, а не
рассуждением.** `mvn -o -f donor/pom.xml test -Dtest=<Класс>` теперь
падает `Could not find artifact com.example:domain-model` — донор один не
собирается вовсе. Рабочая форма — `mvn -o -am -pl donor test
-Dtest=<Класс>`: `-am` собирает то, от чего донор зависит. Первая
редакция этой клаузы утверждала обратное («точечный `-f` остаётся
законным») и была написана без прогона — снята прогоном обеих форм.

**`mvn` на `PATH` в этой среде отсутствует** — рабочий бинарь и
переменные окружения названы в
`.claude/tests/source-api/okx/code-preconditions.md`
§«Воспроизводимые команды»; здесь они не дублируются. Гейт заведён по
кейсу: закрытие завело значение енума, не добавив ветвь в `switch`, —
дерево перестало компилироваться и пролежало так через **два**
полнокорпусных прогона, потому что линзы читают корпус, а не собирают
код.

**Код возврата 2 у любой из них означает «не измерялось», а не «дефектов
нет»** (`.claude/processes/roadmap-step-execution.md` §«Измерительная
команда отказывается, когда мерить нечего»): такой исход статус не
пропускает наравне с кодом 1. Батареи осей исполняются теми же командами
— отдельных проб-скриптов нет.

## Гейт грунта

**Перед простановкой `CODE` — прогнать проверку полноты реестра
гейтящих предусловий шага и проверить, что закрыты все его слоты.**
Реестр шага 7 фазы 1 — `.claude/tests/source-api/okx/code-preconditions.md`;
он же — **дом** правила (§«Правило гейта»).

Шаги ниже — **исполнимая процедура гейта**, а не пересказ политики: гейт
заведён для того, кто дом не открыл, и обязан отработать без его
открытия. Правило одно, живёт в доме; при расхождении формулировок верен
дом (`.claude/rules/policy-home.md`). Прежняя редакция заявляла «скилл
правило не пересказывает» и тут же его пересказывала — снят **клейм**,
не процедура.

Проверка механическая, и **полнота таблицы проверяется раньше её
содержимого**:

1. у шага есть реестр предусловий? Нет — гейт не применяется, записать
   это в отчёт перехода явно (а не пропустить молча);
2. есть — **прогнать `bash tools/preconditions-check.sh`** (из корня
   репозитория; у другого контура — свой вызов, названный его реестром).
   Ненулевой код возврата → статус **не** проставлять; сигналить вывод
   скрипта дословно. Прогон идёт **раньше следующего пункта** потому, что
   тот читает колонку **«Статус наблюдения» реестра**, а слот, в таблицу
   **не заведённый**, такой ячейки не имеет вовсе и проходит гейт молча.
   Полноту самой таблицы — пары «пункт × кейс» реестра против
   гейт-заголовков плана, разведённость слота, соответствие колонки
   «Носитель прогона» фактике — меряет только этот скрипт;
3. каждый слот таблицы («пункт × кейс») закрыт **прогоном своего
   кейса** — то есть наблюдением? Исход «событие не наступило»
   (`OBSERVED_ABSENT`) слот **не закрывает** ни при какой записанной
   строке допущения: он есть запись наблюдения, а не наблюдение факта
   (решение держателя 2026-08-30, дом — `.claude/tests/source-api/okx/`
   `code-preconditions.md` §«Правило гейта»). Не собралась фикстура —
   слот тоже открыт: «не собралась» и «не наступило» — разные вещи, и ни
   одна слот не закрывает. Прогона своего кейса нет — слот считается
   открытым, сколько бы ни стоял его статус;
4. **строка слота объявляет двухшаговый контракт?** Если да — прогон
   кейса закрывает только **грунтовую половину**, и слот закрыт, лишь
   когда предъявлена **вторая**: названный артефакт, зафиксированный
   названным писателем. Слот, у которого есть прогон и нет артефакта
   второго шага, считается **открытым**, сколько бы ни стоял его статус
   (дом класса — `.claude/tests/source-api/okx/code-preconditions.md`
   §«Правило гейта»). Механическая часть — пятая ось
   `preconditions-check.sh`: строка с двухшаговым контрактом обязана
   называть артефакт;
5. **открытый слот гейтит свой компонент, а не шаг** (решение держателя
   2026-09-01 в покомпонентном чтении CC,
   `.claude/decisions/code-contact-as-gate.md` §«Покомпонентное чтение
   гейта грунта»). При простановке `CODE`: открытые слоты **называются
   поимённо** в отчёте перехода вместе с компонентами, которые они
   гейтят, и эти компоненты получают в реестре гейтов признак «ждёт
   грунта»; статус шага открытый слот не держит. Перед **кодовым
   заходом** по такому компоненту гейт срабатывает жёстко: слот открыт →
   компонент не начинать;
6. слот открыт, а компонент, которому нужен его факт, не назван → статус
   **не** проставлять: непривязанный слот не гейтит ничего и теряется
   ровно так же, как непривязанная находка реестра.

Гейт заведён по той же причине, что и остальные встречные якоря этого
скилла: условие, записанное **только внутри** реестра, читает тот, кому
оно и так нужно, — а статус `CODE` проставляет скилл, который до этого о
реестре не знал вовсе (ни одной входящей ссылки на
реестр из `.claude/skills/` и `.claude/processes/`). Прогон проверки — тот же
дефект уровнем ниже: про **проверку** полноты реестра до
о нём не знал никто, кроме самого реестра.

## Гейт входа в `GAPS_CLOSE_N`

**Перед простановкой `GAPS_CLOSE_N` — проверить, что отчёт
`DOCS_CHECK_N` содержит раздел детектора стагнации**
(`.claude/skills/stagnation-detection.md`).

Детектор меряет серию прогонов, а не прогон: узел, возвращающийся с
гейтящими находками после собственного закрытия; закрытие, дающее
находок столько же, сколько закрывает; неубывающая стоимость прогонов;
повторяющийся дефект полноты перебора. Проверка живёт здесь по той же
причине, что и остальные гейты: она обязана исполниться в момент
перехода, а не тогда, когда кто-то вспомнит её позвать.

Проверка механическая — по отчёту `DOCS_CHECK_N`:

1. в хронике шага есть **строка реестра прогонов** на этот прогон
   (находок / гейтящих / узлы гейтящих / доля следствий предыдущего
   закрытия / объём отчёта / дефект перебора в закрытии)? Нет —
   прогон детектором не измерим, статус **не** проставлять;
2. в отчёте есть раздел детектора с замером **всех четырёх** сигналов
   прогонной серии (С1-С4) и выводом «сработал / не сработал» по каждому?
   С5 и С6 здесь не мерятся — их момент другой
   (`.claude/skills/stagnation-detection.md` §«Когда применять»);
3. сигнал сработал — в отчёте есть раздел «Эскалация: концептуальный
   дефицит» полного состава (что сработало, диагноз, предложение
   цельного дизайн-прохода, вынос держателю выбором из двух)? Нет —
   статус **не** проставлять; сигналить, какой сигнал сработал и чего
   в эскалации не хватает;
4. сигнал сработал и эскалация выпущена — `GAPS_CLOSE_N`
   проставляется, но **узел эскалации в это закрытие не входит**:
   итерации по нему остановлены до выбора держателя. При машинных
   сигналах (С2/С3) статус закрытия не проставляется вовсе, пока
   выбор не сделан;
5. **выбор держателя может быть «остановить петлю»** — тогда
   `GAPS_CLOSE_N` не проводится вовсе и гейт не применяется: закрывать
   нечего, статус идёт в тот, который назвало решение
   (`.claude/processes/roadmap-step-execution.md` §4, пассаж «У эскалации
   детектора есть третий исход — смена рамки»). Такой исход
   **записывается решением** в `.claude/decisions/`, а не проставляется
   молча;
6. **форма реестра диспозиции — та, которую назвало решение держателя.**
   Форм две, и переключает их **решение**, а не факт, что где-то идут
   прогоны (`.claude/rules/structure.md`, строка `code-gate-ledger.json`).
   **До остановки петли** реестр пересобирается под каждый прогон: поле
   «прогон» `.claude/work/code-gate-ledger.json` равно `DOCS_CHECK_N`, счёт
   записей сходится со сводкой отчёта полинзово. **После остановки** реестр
   — сквозной носитель фазы кода: он не пересобирается, поля «прогон» и
   «отчёт» указывают на прогон, который пересобирал его последним, а новый
   шаг добавляет в него свои **компоненты**, не переставляя эти поля.
   Прежняя редакция этого пункта привязывала форму к факту идущих
   прогонов и на шаге, чьи прогоны идут после остановки, требовала обеих
   форм разом.

**При С5 «выбор» делает CC, а не держатель** (решение держателя
2026-09-08, дом — `.claude/rules/stopped-node-disposition.md`). Пункты 4-5
выше читаются от этого так: «до выбора держателя» = «до выбора реакции»,
и гейт требует, чтобы реакция была **записана решением** — строкой
дайджеста плюс, если она меняет норму, файлом в `.claude/decisions/`.
Область — С5 и С6 (`.claude/rules/stopped-node-disposition.md` §«Область
действия — сигналы петли внутри закрытия, и граница объявлена»); при
С1-С4 выбор остаётся держательским.

**Эскалация не заменяет закрытия остальных находок.** Гейт
останавливает узел, а не шаг: прочие находки прогона закрываются
штатно.

## Гейт выхода из `GAPS_CLOSE_N`

**Перед простановкой `DOCS_CHECK_N+1` (или `CODE`) — проверить отчёт
`GAPS_CLOSE_N` по шести предметам: предъявленную популяцию каждого
гейтящего узла** (решение держателя 2026-08-31,
`.claude/decisions/closure-completeness-by-population.md`), **классификацию
каждого корпусного захода по родам и исполненные обязанности сыгранных
родов** (проход 2026-09-08, дом —
`.claude/rules/edit-kind-obligations.md`), **чек-листы глубины
закрытия гейтящих узлов, исходы мини-петли критики** (решение держателя
2026-08-29, `.claude/decisions/gating-node-closure-depth.md`), **полную
диспозицию находок прогона** (решение держателя 2026-08-29,
`.claude/decisions/closure-mechanism-amendments.md`) **и записи выноса
держателю** (Д433, 2026-09-03; дом —
`.claude/processes/question-delegation.md`).

**Предмет гейта — корпус, и это ограничение читается раньше шести
предметов** (решение держателя 2026-09-08; дом —
`.claude/rules/docs-loop-limits.md` §«Предмет гейта выхода — корпус»).
Красным прогон делает дефект **корпуса**: доков и спек, правил, процессов,
скиллов, решений, рабочих файлов, инструментов, дельты `CODE`. Дефект,
живущий **только** в тексте о работе — отчёт прогона, отчёт закрытия и
рационал узла, отчёт захода мини-петли, хроника, снапшот, дайджест, — идёт
находкой прогона и статуса не держит.

- **Отсутствие мандатного поля гейтит по-прежнему.** Популяции нет вовсе,
  классификации захода по родам нет вовсе, свипов нет вовсе — полнота
  закрытия не мерилась ничем, и это код 2 («не измерялось»), а не «дефектов
  нет». Пункты ниже, говорящие «нет → статус **не** проставлять», читаются
  об отсутствии поля.
- **Дефект предъявленного поля прогон доводит сам.** Счёт разошёлся с
  выдачей, адрес устарел, блок читает несвязанное имя, команда не
  исполняется — прогон **исполняет исправленную пробу** и гейтит по её
  исходу на корпусе, а не по тексту отчёта. Исправленная команда и её
  выдача стоя́т в отчёте прогона.
- **Форму отчёта мерит машина, а не это чтение.** `py tools/edit-kind-check.py`,
  `py tools/self-count-check.py`, `py tools/command-carrier-check.py` входят
  в §«Гейт инструментов корпуса», и ненулевой код любой из них статус не
  пропускает.

**Потолок прогонов гейта — два на закрытие** (`.claude/rules/docs-loop-limits.md`
§«Потолок прогонов гейта выхода — два на закрытие»). Первый красен — находки
закрываются, второй прогон ведёт сессия, их закрытия не писавшая. Второй
красен **по корпусу** — закрытие помечается **остановленным**, поднимается
сигнал С6 (`.claude/skills/stagnation-detection.md` §«С6 — ряд прогонов
гейта выхода не сходится»), реакция выбирается по
`.claude/rules/stopped-node-disposition.md` и записывается решением;
третьего прогона нет. Остановленное закрытие статус не держит: его
корпусные дефекты паркуются поимённо в `.claude/work/code-gate-ledger.json`
и гейтят свои компоненты.

`.claude/processes/roadmap-step-execution.md` §3 обязывает
политикоменяющее закрытие завершиться свип-грепом по терминам снимаемой
формулировки, а отчёт — нести **команду поиска дословно** и **таблицу исходов,
соразмерную выдаче**. Требование записано, но исполнения ничто не
проверяло: отчёт закрытия такого раздела не содержал, и девять
из одиннадцати гейтящих находок следующего прогона оказались
непроведёнными следствиями его же правок.

Проверка механическая — по отчёту `GAPS_CLOSE_N`:

1. у каждого **корпусного захода** узла (первая правка, доработка мини-петли,
   приземление, хвост) проставлена классификация по родам — таблица «род →
   что ввёл заход → исход» по **всему** словарю
   (`.claude/rules/edit-kind-obligations.md` §«Словарь родов — закрытый»),
   без пустых клеток? Нет → статус **не** проставлять; сигналить, у какого
   захода классификации нет. Форму сверяет `py tools/edit-kind-check.py`;
2. род `снятие` сыгран — в отчёте есть раздел со **свипами**: на каждый
   снятый термин команда поиска (воспроизводимая дословно) и таблица
   «член → правлено что именно / не требует правки — почему», **соразмерная
   выдаче** (клетка на ту единицу, в которой выдача напечатана; свёртка —
   только классом, выделенным командой-фильтром, со сходящимся `Итого` —
   `.claude/rules/edit-kind-obligations.md` §«Обязанность полноты кончается
   разбором выдачи, а не её предъявлением»), плюс запись в
   реестре `tools/retired-check.py` либо названный отказ от неё. **Команда
   проверяется прогоном, а не чтением, и стои́т блоком кода, а не клеткой
   таблицы** (`.claude/processes/roadmap-step-execution.md` §«Команда,
   объявленная воспроизводимой, стои́т блоком кода, а не клеткой таблицы»);
   форму мерит `py tools/command-carrier-check.py`, но она мерит только живые
   отчёты и только **три статически различимые** формы невоспроизводимости —
   команду в клетке таблицы, `-P`-шаблон, разорванный переносом строки внутри
   аргумента, и имя, которое блок читает и сам не связывает. Прочитанная, а не
   прогнанная команда остаётся на гейте: причины
   отказа, различимые лишь исполнением, инструмент не ловит по построению —
   исполнять блоки markdown он не вправе. **Прежние редакции говорили «только
   одну форму», затем «только две»** и становились ложными с вводом осей 7 и 9
   (находки П1 и Ш2 пятого и шестого прогонов гейта выхода из `GAPS_CLOSE_4`
   шага 10 фазы 2);
3. род сыгран, а обязанностей его дома в отчёте нет → статус **не**
   проставлять; сигналить, какой род какого захода остался без исхода.

**Свип сыгранного рода считается по дельте ЭТОГО захода.** Перечень
производных носителей, унаследованный от предыдущего захода единицы, гейт не
принимает: он собран до того, как заход ввёл своё, и потому его конструкции
по построению не видит (`.claude/rules/edit-kind-obligations.md` §«Предмет
обязанностей — дельта захода, а не находки, на которые он отвечает»).

**Перечень, оставленный ЧУЖОМУ заходу, гейт спрашивает отдельно от свипа.**
Закрытие, передающее работу кодовому под-шагу (секция парковки, позиция
реестра, слот грунта), предъявляет **единицу** перечня — ту, которой мерит
гейт адресата, — и **оба входа** его вывода: закрытый реестр этих единиц и
исполнителей, названных домами изменённой редакции
(`.claude/rules/handoff-worklist.md`). **Спрашивается вывод, а не полнота
файлового перечня:** какие файлы правит адресат, гейт не считает вовсе — он
смотрит, чем перечень выведен и какой единицей назван. Перечень, выведенный из
выдачи свипа, гейт не принимает, и клейм полноты над находками мельче единицы
— дефект, а не оформление. Нет ни единицы, ни входов → статус **не**
проставлять; сигналить, какой перечень какого узла выведен шаблоном.

**Прежняя редакция спрашивала один вопрос — «меняло ли закрытие политику», —
и на «нет» гейт не применялся вовсе.** Правка, заведшая дом или введшая
величину, политики не меняла и мимо гейта проходила целиком; классификация по
родам это прочтение снимает: гейт применяется всегда, а «род не играется»
становится записанным исходом, а не молчанием.

**Четвёртого перечня носителей в §3 не заводится.** Пропущенные носители
(соседние секции тех же файлов, рабочие файлы) покрыты **первым**
перечнем; следствия, прошедшие мимо прогнанных свипов, — не пробел в
списке, а другой **предмет** свипа
(`.claude/processes/roadmap-step-execution.md` §«Свип идёт по
конструкции, а не только по снимаемым терминам»). Гейт проверяет
**исполнение**, а не полноту перечня.

**Хвост закрытия проверяется этим же гейтом.** Если после свипов в
отчёт добавились правки — ответ держателя пришёл отдельным заходом,
доспроектировали механику, **доработали узел по находке критики или
верификации**, — гейт спрашивает и про них: это корпусные заходы
(`.claude/rules/edit-kind-obligations.md`), и своя классификация со своими
свипами у каждого — в отчёте, своим разделом. Хвост без классификации —
статус не проставлять.

**Глубина закрытия гейтящих узлов.** Источник правила —
`.claude/processes/roadmap-step-execution.md` §«Гейтящий узел
закрывается до исполнимой глубины, а не до формулировки». Проверка
механическая — по отчёту `GAPS_CLOSE_N`, по каждому гейтящему узлу:

1. чек-лист глубины проставлен пунктами поимённо: политика
   сформулирована; носитель назван и существует, **потребители
   обойдены** (писатели и читатели правленной величины/предиката
   перечислены механическим поиском **двумя формами** — по имени и по
   прозаической формулировке тропы чтения, обе терпимые к переносу
   строки, — и каждый сверен соразмерно выдаче: у команды с `-l` это
   пофайлово, и исход о файле утверждает о файле целиком
   (`.claude/rules/edit-kind-obligations.md` §«Обязанность полноты кончается
   разбором выдачи, а не её предъявлением»); перечень, собранный только грепом
   имени, гейт не проходит);
   механика прописана (кто читает, когда срабатывает, чем резолвится);
   для счётного клейма — исполнимый spec-пример (либо явное «клейм не
   счётный»)? Нет → статус **не** проставлять; сигналить, какой пункт
   какого узла не доведён;
2. пункт не доведён из-за источникового дефицита или дефицита
   `подтверждение` → гейт **пропускает**, если в отчёте
   зафиксирована штатная эскалация и узел помечен незакрытым.
   Недоведённость без эскалации гейт не пропускает: планка не
   опускается.

**Исход мини-петли критики.** Источник правила —
`.claude/processes/roadmap-step-execution.md` §«Закрытие
гейтящего узла проходит мини-петлю критики до приземления в корпус».
Проверка — по каждому гейтящему узлу отчёта `GAPS_CLOSE_N`:

1. исход мини-петли записан: число раундов, **число верификаций**, что
   поймано, что осталось? Нет → статус **не** проставлять; сигналить, по
   каким узлам критика не пройдена. Число верификаций — операнд сигнала С5,
   и исход без него гейт не проходит. **Оба числа стоя́т порождённым
   блоком** (`passes:`), а не словом: написанные от руки, они отстают ровно
   на доработке, ради которой петля и существует. Форма и её прогон —
   `.claude/rules/self-description-form.md`; блок, разошедшийся с выводом,
   роняет `py tools/self-count-check.py`, и статус не проставляется.
   **Отчёт каждого захода лежит своим файлом** — дом требования
   `.claude/processes/roadmap-step-execution.md` §«Отчёт каждого захода —
   сохраняемый носитель, а не черновик»; блок
   `passes:` считает заходы **по этим именам**, поэтому узел с ненулевым
   исходом и без файлов гейт не проходит;
2. правки последнего раунда получили верификацию критика (финальный
   взгляд записан в исходе)? Правка, приземлённая после последнего
   взгляда критика непроверенной, → статус **не** проставлять. **Доработка
   по блокирующим находкам верификации законна и обязана получить свою
   верификацию** (решение держателя 2026-09-07 по `PROC-Q7`, дом —
   `.claude/decisions/mini-loop-verification-ceiling.md`); прежний запрет
   дорабатывать после верификации снят;
3. верификаций у узла больше двух? → статус **не** проставлять: потолок
   исчерпан, и по нему полагается не третья доработка, а эскалация С5
   (`.claude/skills/stagnation-detection.md` §«С5 — мини-петля узла не
   сходится»). Узел при этом помечен **остановленным**, его правки в
   корпус не приземлены, и в отчёте есть раздел эскалации с диагнозом
   посылки — иначе гейт не пропускает. Реакцию на эскалацию выбирает CC
   по `.claude/rules/stopped-node-disposition.md`, и она записана
   решением;
4. не сошлось за два раунда → **по какому носителю остаток**?
   Правки, идущие в корпус, — узел помечен не чистым, статус **не**
   проставлять. Рационал закрытия — остаток зафиксирован находкой отчёта,
   узел чист и приземляется (поправка держателя 2026-09-07, дом —
   `.claude/decisions/per-node-closure-frame.md` §«Поправка держателя:
   чистота узла меряется по носителю»); при этом в исходе названо, чем
   подтверждён регресс корпусных правок. Остаток **без исхода** не проходит
   ни по какому носителю.

**Предъявленная популяция гейтящего узла.** Источник правила —
`.claude/processes/roadmap-step-execution.md` §«Популяция правила
предъявляется до правки, а не после»; процедура —
`.claude/skills/closure-population.md`. Проверка механическая — по отчёту
`GAPS_CLOSE_N`, по каждому гейтящему узлу, все четыре пункта признака:

1. правило узла названо одной фразой? Нет → статус **не** проставлять:
   неизвестно, чьей популяцией является перечень;
2. названы ось (или оси, включая обязательную носительскую и —
   у захода, правящего существующий носитель, — окрестностную) и
   **команда**, которой перечень членов собран, дословно и воспроизводимо?
   Перечень без команды пересобрать нельзя, и гейт его не принимает. У
   окрестностной оси команда вывода **двойная**: отправная метка захода и
   `git diff` по ней — перечень его точек
   (`.claude/rules/edit-kind-obligations.md` §«Предмет обязанностей — дельта
   захода, а не находки, на которые он отвечает»), — плюс четыре пробы
   (`.claude/skills/closure-population.md` §«Четыре пробы окрестности»), исход
   каждой на каждой точке вставки корпусного захода; пустая проба — законный
   исход, необъявленная — нет. Перечень точек, собранный по находкам, которые
   заход закрывает, гейт не принимает: он мерит предшественника;
3. таблица «член → исход» без пустых клеток, у каждого недостижимого члена
   названо, **чем именно** он исключён, и таблица **соразмерна выдаче**?
   Пустая клетка, недостижимость без причины либо клетка крупнее единицы
   выдачи (попадания свёрнуты к файлу или к классу, названному прозой) →
   статус **не** проставлять; сигналить, какой член какого
   узла остался без исхода. Свёртка законна классом, выделенным
   командой-фильтром, со сходящимся `Итого`
   (`.claude/rules/edit-kind-obligations.md` §«Обязанность полноты кончается
   разбором выдачи, а не её предъявлением»); у пробы, исполняемой чтением,
   прочитанное приводится дословно
   (`.claude/skills/closure-population.md` §«Четыре пробы окрестности»);
4. для выразимой оси — объявленная в спеке популяция с ключами `rule`
   (величины правила), `derive` (`command` + `from` либо названная
   `incomplete`) и — при `where` — `excludes`, плюс исходы двух прогонов:
   `bash tools/spec-run.sh` и `python3 tools/population-derive-check.py`;
   для закрытия, снимавшего редакцию, — запись популяции носителей в
   реестре `tools/retired-check.py` (шаблон пришедшей редакции + перечень
   мест). Ось объявлена невыразимой — записано явно, чем именно.
   Прежняя формулировка требовала имя отдельной величины, считающей
   покрытие, и исход её мутационной пробы; она снята — механизм такой
   величины не производит, покрытие считает раннер по ключу
   `populations`.

**Мини-петля проверяется по обоим предметам.** Исход мини-петли называет,
что критик читал: конструкцию **и** текст правки (ключи и примеры спеки,
строки таблиц, предписания исполнителю). Исход, называющий только
конструкцию, гейт не проходит.

**Полная диспозиция находок.** Источник правила —
`.claude/processes/roadmap-step-execution.md` §«`GAPS_CLOSE_N`
диспозиционирует все находки прогона». Проверка — по отчёту
`GAPS_CLOSE_N` против итога прогона `DOCS_CHECK_N`:

1. каждая находка прогона — гейтящая, прочая, гигиена — несёт исход:
   «закрыта» (чем) либо «припаркована»? Молчаливое «отдельным заходом»
   исходом не считается;
2. у каждой парковки — все три величины `.claude/rules/parking-address.md`
   (дом, что оживит, причина), и дом выбран по носителю, который позицию
   оживит. Парковка без условия возврата либо в рабочем файле
   закрывающегося шага исходом не считается → статус **не** проставлять;
3. сводка-счёт (всего / закрыто / припарковано) сходится с итогом
   прогона? Не сходится либо есть находки без исхода → статус **не**
   проставлять; сигналить поимённо.

**Записи выноса держателю.** Источник правила —
`.claude/processes/question-delegation.md` §«Вынос проходит самопроверку,
и она записывается». Проверка — по отчёту, по каждому вопросу, ушедшему
держателю:

1. записаны обе половины самопроверки — что владелец закрыл сам и чем
   именно остаток не выводится (пассаж концепции либо класс: риск-аппетит
   / scope и намерение / срок)? Нет → статус **не** проставлять;
   сигналить, какой вопрос выносился без записи;
2. вариант в тексте вопроса ссылается на концепцию как на основание
   выбора? Тогда развилка выводима, вынос неверен — вопрос возвращается
   владельцу, статус **не** проставлять;
3. под каждый вынесенный вопрос назван **припаркованный узел**: что
   именно ждёт ответа и где живёт. Прогон, остановленный вопросом
   целиком, несёт названную причину остановки — «небезопасно под любым
   допущением» либо «бесполезно при неверном допущении»
   (`.claude/processes/question-delegation.md` §«Вопрос держателю не
   останавливает прогон»); причины нет → статус **не** проставлять;
4. вопросов держателю не было — записать это в отчёт перехода явно, а не
   пропустить молча.

## Гейт закрытия фазы

**Ролляп фазы в `DONE` — момент срабатывания правил с условием снятия «конец
фазы N».** Такие правила по построению не прочитываются в нужный момент:
условие живёт внутри правила, а открывает его тот, кому оно и так нужно.
Поэтому проверка — здесь, в скилле, который **исполняется** при смене
ролляпа, а не в файле, который в этот момент никто не откроет.

Перед простановкой фазе `DONE` (шаг 6) — **найти носители механически, по
строке-маркеру**, и пройти каждый:

```bash
grep -n '^\*\*Встречный якорь\.\*\*' .claude/work/backlog.md
```

Каждая секция `backlog.md`, несущая условие снятия, которое сама снимаемая
политика прочитать не может, обязана нести эту строку-маркер в своём теле.
Гейт берёт **весь** её вывод — перечня носителей в скилле нет.

**Почему по маркеру, а не по шаблону заголовка.**
Прежняя редакция искала секции §«Закрытие фазы N …» и называла три
носителя поимённо. Четвёртый якорь того же класса — `.claude/work/backlog.md` §«Снятие ограничения
`MARK`-only — по измеренному базису» — под шаблон заголовка не попадал и в
перечне назван не был: при ролляпе фазы его не проверяло ничто. Дефект
классовый, а не единичный — пятый якорь повторил бы его; поимённый
перечень, растущий вручную, и есть ровно то, против чего гейт заведён.

**Что гейт требует от найденного носителя** — зависит от того, чем задано
его условие, и это читается в самой секции:

- **условие по фазе** («до конца фазы N») — пункты обязаны быть
  **выполнены**: правило снято, миграции пересмотрены, флаг убран;
- **условие по данным или по событию после фазы** («по данным первого
  периода живой торговли», «по измеренному базису») — гейт **не** требует
  исполнения: он требует, чтобы пункт был **жив и передан вперёд** — секция
  на месте, её условие названо. Пункт с условием «после конца фазы», не
  проверяемый в момент закрытия фазы, теряется ровно так же, как правило с
  условием снятия внутри себя.

**Встречная проверка обязательна и при непустом выводе.** Маркеры
находят секции, которые кто-то **не забыл** пометить; правило, чьё
условие снятия называет конец фазы, а секции в `backlog.md` не получило,
маркером не находится по построению. Поэтому вторым ходом — **всегда**,
а не только при нуле маркеров:

```bash
grep -rln 'конц[ае] фазы\|конец фазы\|до конца фазы' .claude/rules/
```

По каждому попаданию: есть ли у правила секция в `backlog.md` с
маркером? Нет — завести её **до** простановки `DONE`; правило,
действовавшее «до конца фазы», после ролляпа продолжает разрешать
небезопасное. Проверка односторонняя (маркер → секция) оставляет ровно
тот класс, против которого гейт заведён, — и это его второй вход,
а не запасной.

Гейт **не пройден → фазе `DONE` не проставлять**; сигналить, какой пункт
закрытия не выполнен. Правило, действовавшее «до конца фазы», после ролляпа
в `DONE` продолжает разрешать то, что уже небезопасно, — и это не
обнаруживается ничем, кроме упавшей миграции.

## Граничные случаи

- **Шаг с указанным номером не найден.** Не угадывать; сигналить
  в чат, ждать уточнения.
- **Несогласованность ролляпа.** Если статус фазы в главном
  файле до пересчёта отличается от ожидаемого по правилам
  ролляпа (рассинхрон) — после обновления привести к корректному
  значению, отметить в отчёте про рассинхрон.
- **Архитектурный рубеж** в главной таблице — не основная фаза,
  ролляп для него не считается; статус ведётся вручную как для
  любой строки.

## Отчёт

После выполнения — короткое сообщение в чат:
- какой шаг и в какой фазе обновлён;
- предыдущее и новое значение статуса шага;
- какой статус получила фаза после ролляпа (с пометкой
  «без изменений», если ролляп не сдвинул статус фазы).

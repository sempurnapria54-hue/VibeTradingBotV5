# Обновление прогресса роадмапа

## На какой вопрос отвечает этот файл

Как обновить статус шага в роадмапе и пересчитать статус фазы.

## Когда применять

**По завершении любого под-шага — как его часть, не по сигналу**
(`.claude/processes/roadmap-step-execution.md` §«Фиксация статуса —
часть каждого под-шага»): выпустил gap-отчёт, закрыл находки, получил
аппрув фокуса — сразу прогнал этот скилл. Под-шаг не считается
завершённым, пока статус не проставлен и ролляп фазы не пересчитан.
Исполнитель — Claude Code; вход — фаза + шаг + новый статус.

**Формулировка «по сигналу из чата» снята.** Она
делала скилл — а вместе с ним и все его гейты — зависимым от того,
вспомнит ли кто-то его позвать: гейт выхода из `GAPS_CLOSE_N` заведён
**против** незамечаемого пропуска и сам страдал тем же. Встречный якорь
со стороны события у него теперь тот же, что у всей простановки
статуса, — обязанность процесса, а не память исполнителя. (У гейта
закрытия фазы якорь другой и остаётся: §«Гейт закрытия фазы» ниже —
секции `.claude/work/backlog.md`, несущие строку-маркер
`**Встречный якорь.**`.)

## Вход

- Номер фазы (например, `1`).
- Номер шага в фазе (например, `4`).
- Новое значение статуса для шага.

## Канонический набор статусов шага

| Статус | Смысл |
|---|---|
| `HOLD` | Шаг не начат. |
| `TOOLING` | Создание агентов/скиллов для шага. |
| `DOCS_CHECK_N` | Проверка целостности концепции, N — номер итерации. |
| `GAPS_CLOSE_N` | Закрытие пробелов концепции, N — номер итерации. |
| `CODE` | Написание кода + ревью-итерации (фокусы) + аппрув. |
| `SYNC_DOCS_FROM_CODE` | Синхронизация доков под утверждённый код (docs←code). |
| `DONE` | Шаг завершён. |

Развёрнутое описание под-шагов — `.claude/processes/roadmap-step-execution.md`.

## Канонический набор статусов фазы

| Статус | Когда |
|---|---|
| `HOLD` | Все шаги фазы — `HOLD`. |
| `DONE` | Все шаги фазы — `DONE`. |
| `IN_PROGRESS` | Иначе (хотя бы один шаг отличается от `HOLD`, не все в `DONE`). |

## Шаги

1. **Валидация значения.** Проверить, что новый статус шага —
   из канонического набора. Для `DOCS_CHECK_N` / `GAPS_CLOSE_N`
   убедиться, что N — целое положительное число.

2. **Открыть детальный файл фазы.** Путь —
   `.claude/work/roadmap/phase-<N>.md`. Если файла нет —
   остановиться, сигналить в чат: для этой фазы детальный файл
   ещё не создан.

3. **Обновить ячейку «Статус» строки шага.** Найти строку с
   указанным номером шага, заменить значение в колонке «Статус».
   Остальные ячейки не трогать.

4. **Пересчитать статус фазы.** Собрать значения «Статус» по
   всем шагам файла. Применить правила ролляпа из таблицы выше.
   **Ролляп дал `DONE` → пройти §«Гейт закрытия фазы» (ниже) до шага 6.**

5. **Открыть главный файл роадмапа.** Путь —
   `.claude/work/roadmap/roadmap.md`.

6. **Обновить ячейку «Статус» строки фазы.** Найти строку фазы
   с указанным номером, заменить значение в колонке «Статус»
   результатом ролляпа.

7. **`git add`** на оба изменённых файла (staging, не commit).

## Гейт-предусловие перехода (`CODE` / `DONE`)

Перед простановкой `CODE` или `DONE` — проверить **зафиксированный
исход** требуемого гейта (источник правила —
`.claude/processes/roadmap-step-execution.md`):

- **`CODE`** — соответствующий `DOCS_CHECK` прошёл **чисто** (отчёт в
  истории шага), пройден §«Гейт грунта» (ниже) **и** пройден §«Гейт
  инструментов корпуса» (ниже).
- **`DONE`** — **зафиксированные исходы** адверсариальных фокусов:
  `conventions` / `performance` / `disaster` на `CODE` (находки закрыты),
  `divergence` на `SYNC_DOCS_FROM_CODE` (расхождения реконсилированы),
  пост-хок концепт-гейт §6a (если применим).

Зафиксированный исход = отчёт фокуса в истории шага, **не** устное
согласие автора/пользователя и не самопроверка. Нет зафиксированного
исхода → статус **не** проставлять; сигналить, какой фокус не прогнан.

## Гейт инструментов корпуса

**Все проверочные команды корпуса прогоняются перед сменой статуса, и
ненулевой код любой из них статус не пропускает.** Гейт заведён встречным
якорем: детектор, у которого нет носителя-гейта, красен и незаметен —
измерено прогоном, где три новых детектора не были назван ни одним
исполняемым носителем, а один из них был красен прямо в момент прогона.

```bash
bash tools/spec-run.sh                    # примеры исполняются и сходятся
bash tools/spec-mutation-check.sh         # каждая величина что-то проверяет
python3 tools/spec-scope-check.py docs/spec   # области видимости и копии формы
python3 tools/spec-pointer-check.py       # указатель ведёт в дом величины
python3 tools/anchor-check.py             # §-адреса .claude/**: новых битых нет
python3 tools/retired-check.py            # снятая редакция не жива в носителях
bash tools/preconditions-check.sh         # реестр == план == фактика
```

**Код возврата 2 у любой из них означает «не измерялось», а не «дефектов
нет»** (`.claude/processes/roadmap-step-execution.md` §«Измерительная
команда отказывается, когда мерить нечего»): такой исход статус не
пропускает наравне с кодом 1. Батареи осей исполняются теми же командами
— отдельных проб-скриптов нет.

## Гейт грунта

**Перед простановкой `CODE` — прогнать проверку полноты реестра
гейтящих предусловий шага и проверить, что закрыты все его слоты.**
Реестр шага 7 фазы 1 — `.claude/tests/source-api/okx/code-preconditions.md`;
он же — **дом** правила (§«Правило гейта»).

Шаги ниже — **исполнимая процедура гейта**, а не пересказ политики: гейт
заведён для того, кто дом не открыл, и обязан отработать без его
открытия. Правило одно, живёт в доме; при расхождении формулировок верен
дом (`.claude/rules/policy-home.md`). Прежняя редакция заявляла «скилл
правило не пересказывает» и тут же его пересказывала — снят **клейм**,
не процедура.

Проверка механическая, и **полнота таблицы проверяется раньше её
содержимого**:

1. у шага есть реестр предусловий? Нет — гейт не применяется, записать
   это в отчёт перехода явно (а не пропустить молча);
2. есть — **прогнать `bash tools/preconditions-check.sh`** (из корня
   репозитория; у другого контура — свой вызов, названный его реестром).
   Ненулевой код возврата → статус **не** проставлять; сигналить вывод
   скрипта дословно. Прогон идёт **раньше следующего пункта** потому, что
   тот читает колонку **«Статус наблюдения» реестра**, а слот, в таблицу
   **не заведённый**, такой ячейки не имеет вовсе и проходит гейт молча.
   Полноту самой таблицы — пары «пункт × кейс» реестра против
   гейт-заголовков плана, разведённость слота, соответствие колонки
   «Носитель прогона» фактике — меряет только этот скрипт;
3. каждый слот таблицы («пункт × кейс») закрыт **прогоном своего
   кейса** — то есть наблюдением? Исход «событие не наступило»
   (`OBSERVED_ABSENT`) слот **не закрывает** ни при какой записанной
   строке допущения: он есть запись наблюдения, а не наблюдение факта
   (решение держателя 2026-08-30, дом — `.claude/tests/source-api/okx/`
   `code-preconditions.md` §«Правило гейта»). Не собралась фикстура —
   слот тоже открыт: «не собралась» и «не наступило» — разные вещи, и ни
   одна слот не закрывает. Прогона своего кейса нет — слот считается
   открытым, сколько бы ни стоял его статус;
4. хотя бы один слот открыт → статус **не** проставлять; сигналить
   **поимённо**, какие пункты и кейсы открыты.

Гейт заведён по той же причине, что и остальные встречные якоря этого
скилла: условие, записанное **только внутри** реестра, читает тот, кому
оно и так нужно, — а статус `CODE` проставляет скилл, который до этого о
реестре не знал вовсе (ни одной входящей ссылки на
реестр из `.claude/skills/` и `.claude/processes/`). Прогон проверки — тот же
дефект уровнем ниже: про **проверку** полноты реестра до
о нём не знал никто, кроме самого реестра.

## Гейт входа в `GAPS_CLOSE_N`

**Перед простановкой `GAPS_CLOSE_N` — проверить, что отчёт
`DOCS_CHECK_N` содержит раздел детектора стагнации**
(`.claude/skills/stagnation-detection.md`).

Детектор меряет серию прогонов, а не прогон: узел, возвращающийся с
гейтящими находками после собственного закрытия; закрытие, дающее
находок столько же, сколько закрывает; неубывающая стоимость прогонов;
повторяющийся дефект полноты перебора. Проверка живёт здесь по той же
причине, что и остальные гейты: она обязана исполниться в момент
перехода, а не тогда, когда кто-то вспомнит её позвать.

Проверка механическая — по отчёту `DOCS_CHECK_N`:

1. в хронике шага есть **строка реестра прогонов** на этот прогон
   (находок / гейтящих / узлы гейтящих / доля следствий предыдущего
   закрытия / объём отчёта / дефект перебора в закрытии)? Нет —
   прогон детектором не измерим, статус **не** проставлять;
2. в отчёте есть раздел детектора с замером **всех четырёх** сигналов
   и выводом «сработал / не сработал» по каждому?
3. сигнал сработал — в отчёте есть раздел «Эскалация: концептуальный
   дефицит» полного состава (что сработало, диагноз, предложение
   цельного дизайн-прохода, вынос держателю выбором из двух)? Нет —
   статус **не** проставлять; сигналить, какой сигнал сработал и чего
   в эскалации не хватает;
4. сигнал сработал и эскалация выпущена — `GAPS_CLOSE_N`
   проставляется, но **узел эскалации в это закрытие не входит**:
   итерации по нему остановлены до выбора держателя. При машинных
   сигналах (С2/С3) статус закрытия не проставляется вовсе, пока
   выбор не сделан.

**Эскалация не заменяет закрытия остальных находок.** Гейт
останавливает узел, а не шаг: прочие находки прогона закрываются
штатно.

## Гейт выхода из `GAPS_CLOSE_N`

**Перед простановкой `DOCS_CHECK_N+1` (или `CODE`) — проверить отчёт
`GAPS_CLOSE_N` по пяти предметам: предъявленную популяцию каждого
гейтящего узла** (решение держателя 2026-08-31,
`.claude/decisions/closure-completeness-by-population.md`), **раздел
свипов в предписанной форме**, **чек-листы глубины
закрытия гейтящих узлов, исходы мини-петли критики** (решение держателя
2026-08-29, `.claude/decisions/gating-node-closure-depth.md`) **и полную
диспозицию находок прогона** (решение держателя 2026-08-29,
`.claude/decisions/closure-mechanism-amendments.md`).

`.claude/processes/roadmap-step-execution.md` §3 обязывает
политикоменяющее закрытие завершиться свип-грепом по терминам снимаемой
формулировки, а отчёт — нести **команду поиска дословно** и **пофайловую
таблицу исходов**. Требование записано, но исполнения ничто не
проверяло: отчёт закрытия такого раздела не содержал, и девять
из одиннадцати гейтящих находок следующего прогона оказались
непроведёнными следствиями его же правок.

Проверка механическая — по отчёту `GAPS_CLOSE_N`:

1. закрытие меняло политику (снимало или заменяло правило, а не
   доуточняло структуру)? Нет — гейт не применяется, записать это в
   отчёт перехода явно;
2. да — в отчёте есть раздел со **свипами**: на каждый снятый термин
   команда поиска (воспроизводимая дословно) и таблица «файл → правлено
   что именно / не требует правки — почему»;
3. раздела нет либо в нём нет команд → статус **не** проставлять;
   сигналить, какие термины остались непросвипованными.

**Четвёртого перечня носителей в §3 не заводится.** Пропущенные носители
(соседние секции тех же файлов, рабочие файлы) покрыты **первым**
перечнем; следствия, прошедшие мимо прогнанных свипов, — не пробел в
списке, а другой **предмет** свипа
(`.claude/processes/roadmap-step-execution.md` §«Свип идёт по
конструкции, а не только по снимаемым терминам»). Гейт проверяет
**исполнение**, а не полноту перечня.

**Хвост закрытия проверяется этим же гейтом.** Если после свипов в
отчёт добавились правки (ответ держателя пришёл отдельным заходом,
доспроектировали механику), гейт спрашивает и про них: свипы хвоста —
в отчёте, своим разделом. Хвост без свипов — статус не проставлять.

**Глубина закрытия гейтящих узлов.** Источник правила —
`.claude/processes/roadmap-step-execution.md` §«Гейтящий узел
закрывается до исполнимой глубины, а не до формулировки». Проверка
механическая — по отчёту `GAPS_CLOSE_N`, по каждому гейтящему узлу:

1. чек-лист глубины проставлен пунктами поимённо: политика
   сформулирована; носитель назван и существует, **потребители
   обойдены** (писатели и читатели правленной величины/предиката
   перечислены механическим поиском **двумя формами** — по имени и по
   прозаической формулировке тропы чтения, обе терпимые к переносу
   строки, — и каждый сверен пофайлово; перечень, собранный только грепом
   имени, гейт не проходит);
   механика прописана (кто читает, когда срабатывает, чем резолвится);
   для счётного клейма — исполнимый spec-пример (либо явное «клейм не
   счётный»)? Нет → статус **не** проставлять; сигналить, какой пункт
   какого узла не доведён;
2. пункт не доведён из-за источникового дефицита или дефицита
   `подтверждение` → гейт **пропускает**, если в отчёте
   зафиксирована штатная эскалация и узел помечен незакрытым.
   Недоведённость без эскалации гейт не пропускает: планка не
   опускается.

**Исход мини-петли критики.** Источник правила — там же, §«Закрытие
гейтящего узла проходит мини-петлю критики до приземления в корпус».
Проверка — по каждому гейтящему узлу отчёта `GAPS_CLOSE_N`:

1. исход мини-петли записан: число раундов, что поймано, что
   осталось? Нет → статус **не** проставлять; сигналить, по каким
   узлам критика не пройдена;
2. правки последнего раунда получили верификацию критика (финальный
   взгляд записан в исходе)? Правка, приземлённая после последнего
   взгляда критика непроверенной, → статус **не** проставлять;
3. не сошлось за два раунда → остаток зафиксирован находкой и узел
   помечен не чистым? Иначе — статус **не** проставлять.

**Предъявленная популяция гейтящего узла.** Источник правила —
`.claude/processes/roadmap-step-execution.md` §«Популяция правила
предъявляется до правки, а не после»; процедура —
`.claude/skills/closure-population.md`. Проверка механическая — по отчёту
`GAPS_CLOSE_N`, по каждому гейтящему узлу, все четыре пункта признака:

1. правило узла названо одной фразой? Нет → статус **не** проставлять:
   неизвестно, чьей популяцией является перечень;
2. названы ось (или оси, включая обязательную носительскую) и **команда**,
   которой перечень членов собран, дословно и воспроизводимо? Перечень без
   команды пересобрать нельзя, и гейт его не принимает;
3. таблица «член → исход» без пустых клеток, у каждого недостижимого члена
   названо, **чем именно** он исключён? Пустая клетка либо недостижимость
   без причины → статус **не** проставлять; сигналить, какой член какого
   узла остался без исхода;
4. для выразимой оси — имя величины-счётчика покрытия и исход её
   мутационной пробы; для закрытия, снимавшего редакцию, — запись
   популяции носителей в реестре `tools/retired-check.py` (шаблон
   пришедшей редакции + перечень мест). Ось объявлена невыразимой —
   записано явно, чем именно.

**Мини-петля проверяется по обоим предметам.** Исход мини-петли называет,
что критик читал: конструкцию **и** текст правки (ключи и примеры спеки,
строки таблиц, предписания исполнителю). Исход, называющий только
конструкцию, гейт не проходит.

**Полная диспозиция находок.** Источник правила —
`.claude/processes/roadmap-step-execution.md` §«`GAPS_CLOSE_N`
диспозиционирует все находки прогона». Проверка — по отчёту
`GAPS_CLOSE_N` против итога прогона `DOCS_CHECK_N`:

1. каждая находка прогона — гейтящая, прочая, гигиена — несёт исход:
   «закрыта» (чем) либо «припаркована» с адресатом и местом (владелец +
   носитель)? Молчаливое «отдельным заходом» исходом не считается;
2. сводка-счёт (всего / закрыто / припарковано) сходится с итогом
   прогона? Не сходится либо есть находки без исхода → статус **не**
   проставлять; сигналить поимённо.

## Гейт закрытия фазы

**Ролляп фазы в `DONE` — момент срабатывания правил с условием снятия «конец
фазы N».** Такие правила по построению не прочитываются в нужный момент:
условие живёт внутри правила, а открывает его тот, кому оно и так нужно.
Поэтому проверка — здесь, в скилле, который **исполняется** при смене
ролляпа, а не в файле, который в этот момент никто не откроет.

Перед простановкой фазе `DONE` (шаг 6) — **найти носители механически, по
строке-маркеру**, и пройти каждый:

```bash
grep -n '^\*\*Встречный якорь\.\*\*' .claude/work/backlog.md
```

Каждая секция `backlog.md`, несущая условие снятия, которое сама снимаемая
политика прочитать не может, обязана нести эту строку-маркер в своём теле.
Гейт берёт **весь** её вывод — перечня носителей в скилле нет.

**Почему по маркеру, а не по шаблону заголовка.**
Прежняя редакция искала секции §«Закрытие фазы N …» и называла три
носителя поимённо. Четвёртый якорь того же класса — `.claude/work/backlog.md` §«Снятие ограничения
`MARK`-only — по измеренному базису» — под шаблон заголовка не попадал и в
перечне назван не был: при ролляпе фазы его не проверяло ничто. Дефект
классовый, а не единичный — пятый якорь повторил бы его; поимённый
перечень, растущий вручную, и есть ровно то, против чего гейт заведён.

**Что гейт требует от найденного носителя** — зависит от того, чем задано
его условие, и это читается в самой секции:

- **условие по фазе** («до конца фазы N») — пункты обязаны быть
  **выполнены**: правило снято, миграции пересмотрены, флаг убран;
- **условие по данным или по событию после фазы** («по данным первого
  периода живой торговли», «по измеренному базису») — гейт **не** требует
  исполнения: он требует, чтобы пункт был **жив и передан вперёд** — секция
  на месте, её условие названо. Пункт с условием «после конца фазы», не
  проверяемый в момент закрытия фазы, теряется ровно так же, как правило с
  условием снятия внутри себя.

**Встречная проверка обязательна и при непустом выводе.** Маркеры
находят секции, которые кто-то **не забыл** пометить; правило, чьё
условие снятия называет конец фазы, а секции в `backlog.md` не получило,
маркером не находится по построению. Поэтому вторым ходом — **всегда**,
а не только при нуле маркеров:

```bash
grep -rln 'конц[ае] фазы\|конец фазы\|до конца фазы' .claude/rules/
```

По каждому попаданию: есть ли у правила секция в `backlog.md` с
маркером? Нет — завести её **до** простановки `DONE`; правило,
действовавшее «до конца фазы», после ролляпа продолжает разрешать
небезопасное. Проверка односторонняя (маркер → секция) оставляет ровно
тот класс, против которого гейт заведён, — и это его второй вход,
а не запасной.

Гейт **не пройден → фазе `DONE` не проставлять**; сигналить, какой пункт
закрытия не выполнен. Правило, действовавшее «до конца фазы», после ролляпа
в `DONE` продолжает разрешать то, что уже небезопасно, — и это не
обнаруживается ничем, кроме упавшей миграции.

## Граничные случаи

- **Шаг с указанным номером не найден.** Не угадывать; сигналить
  в чат, ждать уточнения.
- **Несогласованность ролляпа.** Если статус фазы в главном
  файле до пересчёта отличается от ожидаемого по правилам
  ролляпа (рассинхрон) — после обновления привести к корректному
  значению, отметить в отчёте про рассинхрон.
- **Архитектурный рубеж** в главной таблице — не основная фаза,
  ролляп для него не считается; статус ведётся вручную как для
  любой строки.

## Отчёт

После выполнения — короткое сообщение в чат:
- какой шаг и в какой фазе обновлён;
- предыдущее и новое значение статуса шага;
- какой статус получила фаза после ролляпа (с пометкой
  «без изменений», если ролляп не сдвинул статус фазы).

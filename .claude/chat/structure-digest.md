# Дайджест структуры знания (для PK чата)

## На какой вопрос отвечает этот файл

Какие типы знания есть в проекте (компактный перечень для чата
claude.ai).

Производный файл: источник правды — `.claude/rules/structure.md`
(полная таблица с правилами размещения). Этот дайджест кладётся
в Project Knowledge как ориентир дефолтного чтения чата: полные
`structure.md` / `naming.md` / `place-knowledge.md` тоже лежат в
PK, но чат открывает их точечно. При изменении структуры —
обновить дайджест и заменить его копию в PK. Размещением знания
занимается Claude Code, чату достаточно перечня типов.

## Типы знания (вопрос → место)

Пайплайн (`.claude/`):
- Базовые правила проекта → `CLAUDE.md`.
- Где мы сейчас → `snapshots/snapshot-vN.md` (в папке только
  актуальный; старые — в `work/history/snapshots/`).
- Дерево-индекс каталогов и файлов (вопрос каждого узла) →
  `knowledge-tree.md`; правило курации → `rules/curation.md`.
- Какое у нас правило → `rules/`. Как делать X → `skills/`.
  Роль Claude → `agents/`. Методологический процесс →
  `processes/`. Почему решили так (пайплайн) → `decisions/`.
- Наблюдения/разведка → `notes/`. Шаблоны кода и доков →
  `templates/`. Торговые первоисточники и дистиллят →
  `library/trading/`. Тест-планы API источников → `tests/`.
- Работа: план → `work/backlog.md`; дайджест автономных решений
  CC (на чтение пользователю, вето постфактум) →
  `work/decision-digest.md`; продуктовый роадмап →
  `work/roadmap/` (`roadmap.md` + `phase-N.md`); активная
  задача → `work/progress/`; нерешённое →
  `work/questions/open-questions.md` (+ `questions/tasks/` по
  задаче); сделанное → `work/history/`.
- Чат-артефакты (CI-исходник, этот дайджест) → `chat/`.

Продукт (`docs/`):
- Модели → `models/` (integrations — нативные модели источников;
  externalSnapshot — граничные объекты; domain
  core/aggregate/other; persistence; api; mapping — переходы
  между слоями).
- Состояния объекта → `lifecycles/`. Процессы → `processes/`.
  Исполнители → `components/` (runtime-объекты —
  `components/models/`). Правила системы → `rules/`. Термины →
  `dictionary/`. Контракты и правила источника →
  `integrations/{name}/`. Из каких сервисов состоит система и как
  они делят данные и контракты → `architecture/`. Почему решили
  так (продукт) → `concept.md` (каталога `decisions/` в `docs/`
  нет).

Фрагмент не ложится ни в один тип → открытый вопрос в
`work/questions/open-questions.md`, не угадываем.

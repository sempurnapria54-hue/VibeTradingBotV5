# Фокус `test` шага 12: проход по группам B7-B8 ящика `audit`

## На какой вопрос отвечает этот файл

Какие находки дал проход фокуса `test` по группам B7-B8 чёрного ящика `audit` 2026-09-24?

## Статус

Вход отчёту фокуса `test`, а не отчёт. Проход — субагент захода 147; вернулся
после конверта сессии. Находки проверены им чтением теста и продуктового кода
(`JournalCleanupJob`, `JobExecutionGuard`, `JournalReadService`,
`JournalReadApiQuery`, `application.yaml`, `V1__audit_baseline.sql`); заходом,
пишущим отчёт, перепроверяются. Пути — от
`services/audit/src/test/java/com/example/audit/box/`; `док:N` — строки
`.claude/tests/cases/audit.md`. Покрытие меток B7.1-B7.14, B8.1-B8.17 полное:
B7.14 объявлен непрогоняемым (док:2425), B8.10 — `debt` с ожиданием из дома.

## Находки

1. **B7.5 — невалидность.** `CleanupDisabledBoxTest.java:46-62`,
   `SilentCleanupBox.java:54` (док:918-922): «выключатель гасит проход раньше
   чтения оси» не различено — перенос проверки выключателя за `isApplicable()`
   (`JournalCleanupJob.java:91-111`) клетку не роняет. Правка: вход «выключатель
   снят, ось не доехала» (`UNSET`) либо сузить ожидание.
2. **B7.1, B7.2, B7.6-B7.8, B7.13 — детерминизм, пробел дока.**
   `AuditSubstrate.java:234-251`, `JournalCleanupBoxTest.java:71, 112-113`
   (док:878, 998, 1652): глубина берётся из умолчания
   `${JOB_JOURNAL_CLEANUP_DEPTH_DAYS:30}` (`application.yaml:116`), то есть из
   окружения машины, а клетки откалиброваны по нему (возраст 31 сутки). Тот же
   класс, спорно, — B7.4 (`${PLATFORM_JOURNAL_RETENTION_PROFILE:}`). Правка:
   `CLEANUP_DEPTH_DAYS` — ось субстрата, как `STATE_MAX_AGE` (док:1620-1627).
3. **Оснастка журнала приложения (B7.3-B7.5, B7.12) — детерминизм.**
   `AppLog.java:59-72`: чтение `APPENDER.list` без синхронизации с
   `AppenderBase.doAppend`; `List.copyOf` при записи потоков клиента Kafka
   падает либо сдвигает отметку. Тот же класс — у `market-data`
   (`…-market-data-box.md`, п. 24). Правка: чтение под `synchronized (APPENDER)`.
4. **B7.6 — пробел покрытия и дока.** `JournalCleanupBoxTest.java:222-241`
   (док:930, 932): «безлимитной правки одним запросом нет» ящиком не наблюдается.
   Правка: объявить «не мерится ящиком» либо счёт удалений `pg_stat_statements`.
5. **B7.13, B8.1 — невалидность, вхолостую.** `JournalCleanupBoxTest.java:130-137,
   432-438`, `JournalReadBoxTest.java:166-168`: отсутствие фасада и точки
   полноты — перебором угаданных путей. Правка: перечень `paths` из
   `/v3/api-docs` (образец — `ReceptionStateTickBoxTest.java:253`).
6. **B8.1 — невалидность.** `JournalReadBoxTest.java:154-165` (док:1022):
   `containsKeys` без значений и только у первой строки; класс, радиус, версия,
   содержимое и `continuityClaimable = TRUE` не сверены.
7. **B8.15, B8.7 — невалидность.** `JournalReadBoxTest.java:300-316, 520-534`
   (док:1082, 1162): `200` не проверен, `lowerBound` — `isNotNull`; у B8.7
   предикат полноты не проверен вовсе.
8. **B8.11 — невалидность.** `JournalReadBoxTest.java:419-443` (док:1122): ниже
   курсора соседа строк `T2` нет — утечка чужих строк в ветви курсора неразличима.
9. **B8.4 — пробел покрытия.** `JournalReadBoxTest.java:217-239`
   (док:1050-1052): строка одна, сужение окна ровно в предел незаметно.
10. **B7.2, B7.7 — форма, спорно.** `JournalCleanupBoxTest.java:214-216,
    260-262`: граница выдачи сравнивается с колонкой `recorded_at`, что документ
    (док:1606-1610) сам отвергает.
11. **B7.1 — невалидность, спорно.** `JournalCleanupBoxTest.java:167, 183-188`
    (док:880): след отказа доступа с моментом «сейчас» — отрицание холостое;
    настоящая проверка — B7.10.
12. **B8.16 — невалидность, спорно.** `JournalReadAxesBoxTest.java:109-122`
    (док:1172): «параметром не задаётся» — двумя угаданными именами.
13. **Кодстайл — форма.** `Objects.isNull` с именем класса — `AuditBox.java:564,
    852`, `Wire.java:125, 348`; ручные проверки коллекций — `Rows.java:68, 210,
    230`; магическое `2` — `JournalCleanupBoxTest.java:376`.

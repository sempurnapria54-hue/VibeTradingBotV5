# Аудит вопросов на делегируемость

## На какой вопрос отвечает этот файл

Кто из существующих агентов/скиллов может владеть каждым вопросом и
решением корпуса сейчас (разведка, не решение).

11 закрытых записей реестра) и `.claude/decisions/` (19 decisions).
История эскалаций `DOCS_CHECK` / `GAPS_CLOSE` в корпус не входит.

Бакеты: **Д** — делегируемо существующему агенту/скиллу; **Н** —
нужен новый агент/скилл; **П** — по существу пользовательское (цели,
приоритеты, риск-аппетит, продуктовые развилки).

Ретро-пометка (**ретро**): на момент постановки/решения вопроса
способного агента/скилла (в нынешнем наполнении) не было — способный
появился позже. Для закрытых элементов это значит: будущие вопросы
того же типа делегируемы; для открытых — вопрос завис как
пользовательский, хотя владелец уже существует.

## Сводка: кандидаты на делегирование

### Приоритет 1 — ретро-кандидаты, открытые сейчас (висят на пользователе, владелец уже есть)

К `trading-specialist` (появился 2026-06-04/05, вопросы старше):

1. **RISK-Q1** — структура `RiskSettings`.
2. **INSTR-Q2** — роль статического плеча при динамическом рабочем.
3. **OKX-Q1** — нужность persisted `TradeFill` (PnL source-of-truth).
4. **OKX-Q3** — bills как источник `DealCashFlow` (точность PnL).
5. **STRAT-Q4** — допустимые якоря percent-anchor.
6. **ENUM-Q1** — подтверждение `RISK_CONTROL` (+ `knowledge-curator`
   для закрытия по приоритету источников).

У всех остаётся пользовательский хвост — численные значения
риск-аппетита и сроки материализации; содержательное ядро снимается.

### Приоритет 2 — делегируемые без ретро (можно снять прямо сейчас)

7. **PROC-Q1** → `knowledge-curator` — закрыть по зафиксированному
   инварианту «одна `Deal` — одна `Position`».
8. **DEAL-Q3** → `knowledge-curator` — классификация по вшитым

   file-per-executor.
10. **RISK-Q2**, **IND-Q1** → `trading-specialist` — конструкция
    guard / роль объёма (пороги и интернет-добор — пользователь).

### Ретро-паттерны для процесса (закрытые элементы; урок на будущее)

- **Классификационные развилки** (первоисточник, новый тип,
  гранулярность, материализация процесса — Q1-Q3, NQ-F/H/G и 10
  decisions) решались в чате, критерии затем вшивались в скиллы.
  Сейчас вопросы этих типов не должны эскалироваться — владелец
  `knowledge-curator`.
- **Торговые развилки шага 2** (STRAT-Q1..Q3) прошли без торгового
  специалиста; теперь front-load специалистом обязателен до
  закрепления (так и зафиксировано в `trading-council`).

### Выявленный разрыв — профиль «нужен новый»

**Конструктивный проектировщик концепции (solution-designer):**
DEAL-Q1, INSTR-Q1, ORCH-Q1 и редизайны уровня
`model-layer-ontology`. Это архитектурные развилки, по существу не
пользовательские (не цели/приоритеты/риск-аппетит), но не покрытые
никем: `reviewer` критикует и не проектирует, `code-writer` пишет по
готовой концепции, `trading-specialist` — только торговый домен.
Сейчас эти развилки несёт чат/пользователь. 4 элемента корпуса — в
этом разрыве.

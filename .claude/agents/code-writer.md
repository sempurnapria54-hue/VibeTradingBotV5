# Code writer

## На какой вопрос отвечает этот файл

Что делает Claude в роли code-writer.

## Назначение роли

Автор кода. Пишет код шага по проработанной концепции (`docs/`):
опирается на `tech-radar` (выбор технологий), `codestyle` (стиль
написания) и код-шаблоны (абстрактные паттерны с плейсхолдерами) из
тира `.claude/templates/code/`. Подбор примеров из реального кода
(`find-code-examples`) — это пост-код-фаза для доков, не написание;
см. `.claude/decisions/code-templates-vs-examples.md`.

## Границы роли

### Что входит

- Написание кода в дереве кода (сейчас `donor/`; по мере порта —
  `services/<сервис>/`, `libs/<артефакт>/`) по утверждённой концепции шага.
- Следование `tech-radar` и `codestyle`.
- Опора на код-шаблоны `.claude/templates/code/` (абстрактные
  паттерны).

### Что не входит

- Ревью написанного — это роль `reviewer` (фокусы
  `conventions` / `security` / `performance` / `disaster`).
- Размещение / синхронизация знания в доках — это
  `knowledge-curator` (под-шаг `SYNC_DOCS_FROM_CODE`, docs←code).
- Содержательные продуктовые решения — это пользователь.

## Скелет

- **Вход:** утверждённая концепция шага (`docs/`), `tech-radar`,
  `codestyle`, код-шаблоны (`.claude/templates/code/`).
- **Выход:** код шага в дереве кода, выносимый на ревью-итерации и
  аппрув (под-шаг `CODE`).
- **Принцип:** код по концепции; отклонение от доков — сигнал,
  который снимается на `SYNC_DOCS_FROM_CODE` (docs←code), не молча.

## Связи

- Правила — `.claude/rules/tech-radar.md`, `.claude/rules/codestyle.md`.
- Код-шаблоны — `.claude/templates/code/`.
- Процесс шага — `.claude/processes/roadmap-step-execution.md`
  (под-шаг `CODE`).
- Ревьюер — `.claude/agents/reviewer.md`.

## Доработка

Процедура письма и форма опоры на код-шаблоны дорабатываются по
ходу. Спекулятивную процедуру здесь не фиксируем.

# Классификация знания: каркас и атомарные скиллы

## На какой вопрос отвечает этот файл

Почему процесс фиксации знания устроен через пятишаговую
классификацию и набор атомарных скиллов.

## Контекст

Изначально процедура размещения предполагала прямой переход
«фрагмент → вопрос → тип → файл». В обкатке выяснилось, что
между фрагментом и размещением больше шагов, и заранее
прописывать все правила фильтрации преждевременно. Потребовалось
оформить процесс как явную последовательность шагов с
постановкой вопроса на каждом, и закрепить, что скиллы
эволюционируют от каркасов к наполненным правилам через
накопление открытых вопросов.

## Принятое решение

Решение состоит из четырёх связанных частей.

### Часть 1. Каркас классификации — пять шагов

- **Шаг 1: фрагмент.** Источник любой (чат, файл, иное).
- **Шаг 2: область** (пайплайн / продукт / возможные другие).
- **Шаг 3: тип внутри области** (по перечню типов знания).
- **Шаг 4: тема внутри типа** (узкая формулировка под имя
  файла).
- **Шаг 5: размещение** (существующий файл или новый).

### Часть 2. Сквозные операции

На каждом шаге работают две сквозные операции:
- постановка вопроса (что определяю сейчас?);
- фильтр (стоит ли двигаться дальше? есть ли ответ?).

Если ответа на вопрос шага нет — фрагмент уходит в
`.claude/work/questions/open-questions.md`, движение по шагам
останавливается до накопления материала.

### Часть 3. Один скилл на шаг

Каждому шагу соответствует отдельный скилл:
- шаг 1: `recognize-knowledge.md`;
- шаг 2: `classify-area.md`;
- шаг 3: `classify-type.md`;
- шаг 4: `classify-theme.md`;
- шаг 5: `place-knowledge.md`.

Скиллы атомарны и самодостаточны: содержат внутри себя знание,
нужное для работы (перечни, признаки, критерии). Не ссылаются
на справочники и друг на друга. Логику последовательности
держит агент `knowledge-curator.md`.

### Часть 4. Эволюция скиллов через накопление

Скилл = набор вопросов с критериями, не свод правил. Открытые
вопросы копятся в `open-questions.md`. Когда видна
закономерность — оформляется отдельное decision; его содержание
встраивается в скилл как новое правило. Скилл растёт снизу
вверх: от каркаса к наполнению.

## Альтернативы

- **Один скилл с шагами внутри.** Отказались: теряется явность
  фильтров и постановки вопросов; навыки разных шагов
  смешиваются.
- **Прописать правила фильтрации заранее.** Отказались:
  преждевременная систематизация без материала. По нашему
  опыту такие правила быстро устаревают или не покрывают
  реальные случаи.
- **Не выделять «область» как отдельный шаг.** Отказались:
  область иногда нужна раньше типа, чтобы выбрать критерии
  фильтрации, специфичные для пайплайна или продукта.
- **Скиллы ссылаются друг на друга по последовательности.**
  Отказались: скиллы должны быть атомарными, последовательность —
  внешняя ответственность (агент или процесс).
- **Скиллы ссылаются на справочник `structure.md` за перечнем
  типов.** Отказались: скиллы самодостаточны, перечни и
  признаки — внутри скилла. Справочник о структуре каталогов —
  отдельная сущность для другого потребителя (агент при
  размещении).

## Следствия

- Каркас классификации описывается отдельной докой
  `.claude/processes/knowledge-classification.md`.
- В таблицу `.claude/rules/structure.md` добавляется строка для
  `.claude/processes/`.
- Принцип «один файл = одна сущность» в `structure.md`
  смягчается до «одна тема».
- В «Принципы» `structure.md` добавляется правило про
  самодостаточность скиллов и направление зависимостей.
- Существующий скилл `.claude/skills/formulate-question.md`
  переименовывается в `classify-type.md`. Содержание
  актуализируется: перечень типов с признаками — внутри
  скилла, без ссылок на `structure.md`.
- Создаются новые скиллы-каркасы `classify-area.md` и
  `classify-theme.md`.
- Существующий скилл `.claude/skills/place-knowledge.md`
  правится: ссылка на переименованный `classify-type.md`.
- Существующий скилл `.claude/skills/recognize-knowledge.md`
  правится по необходимости (если шаги пересекаются с новым
  каркасом).
- Создаётся агент `.claude/agents/knowledge-curator.md` —
  оркестратор процесса.
- Количество скиллов и их содержание будут уточняться по
  обкатке. Шаги 2 и 4 сейчас оформлены как каркасы; ожидается
  наполнение через накопление открытых вопросов.

# Переработка машины шага

## На какой вопрос отвечает этот файл

Почему машина шага роадмапа заменена с docs-first на
`CONCEPT → CONCEPT_REVIEW → CODE → DOCS → REVIEW → DONE`.

## Решение держателя (2026-09-15)

**Концепция — держателя, код и документация по факту — CC, апрув —
держателя.** Доковая петля до кода (`DOCS_CHECK_N` / `GAPS_CLOSE_N`) снята
вместе с машинерией под ней; концепция проверяется на **достаточность**,
а не на полноту по полю.

### Термин «концепция»

Живёт в `.claude/processes/roadmap-step-execution.md` §«Термин «концепция»»;
предмет ревью концепции — там же, §«`CONCEPT_REVIEW`».

### Машина шага

Живёт в `.claude/processes/roadmap-step-execution.md` §«Машина шага».

### Что снимается

`TOOLING` как статус — агенты и скиллы появляются от потребности внутри
любого статуса. `DOCS_CHECK_N`, `GAPS_CLOSE_N`, выходной гейт, пост-хок
концепт-гейт, `SYNC_DOCS_FROM_CODE` как отдельный статус — и машинерия под
них: сквозная проверка концепции «по полю», классификация пробелов,
популяции и глубина закрытия, потолки мини-петель.

Остаются: энфорсеры и свипы (теперь единственное, что держит доки от
дрейфа после факта), реактор, единица работы сессии, отчёты и снапшоты,
дайджест решений.

### Следствия, названные держателем

- Шаг 11 фазы 2 уже `DONE` — новая машина действует с шага 12 («Тесты»).
- Тесты — отдельный шаг в конце каждой фазы, той же машиной; его устройство
  живёт в `.claude/processes/roadmap-step-execution.md` §«Конец фазы».
- Оживители бэклога, привязанные к снятым статусам, переназначаются.
- Знание старой машины (процессы, скиллы, решения, роли) переписывается
  или снимается; снятое — в историю по правилам.
- Скиллы `test-design` / `test-review` / `test-code`, роль `tester` и
  фокус `test` переводятся с контура API источника на новый предмет под
  три под-шага; параллельный набор не заводится.

## Что было на развилке у CC

| Вариант | Почему не он |
|---|---|
| оставить реестр контакта с кодом как носитель парковок ревью | реестр гейтил компоненты по классу находки доковой петли; без петли остаётся секция бэклога с владельцем и условием — тот же исход меньшим следом (`.claude/rules/design-simplicity.md`) |
| оставить свипы в процессе исполнения шага | процесс стал описанием машины; норма, читаемая всяким корпусным заходом, а не только шагом, живёт в правиле (`.claude/rules/policy-home.md`) |
| завести отдельный набор тестовых скиллов под тестовый шаг | запрещено самим решением; общая форма кейса одна, различия контура — в его процессе |
| переписать снятые решения под новую машину | решение описывает прошлое; правка сделала бы его ложным (`.claude/rules/curation.md` §«Чек-лист свипа») |

# Триада принципов миграции

## На какой вопрос отвечает этот файл

По какому принципу мы фиксируем фрагменты при миграции из источника,
который после миграции станет недоступен.

## Контекст

Миграция 6 торговых сущностей и текущая миграция архивных процессов
показали повторяющийся вопрос: что делать с фрагментом, если для его
размещения нет однозначного ответа на одном из шагов классификации —
угадывать, искать промежуточные варианты, дробить решения. Нужен общий
принцип, единый для любой миграции из источника, который после работы
перестаёт быть источником истины (архив помечается deprecated, импорт
извне).

## Принятое решение — триада

При миграции из недоступного позднее источника действуют три правила.

1. **После прогона миграции к архивным источникам не возвращаемся.**
   Архив помечается deprecated и перестаёт быть источником истины. Всё,
   что нужно для последующих решений, должно быть зафиксировано в репо во
   время миграции.

2. **Если фрагмент не удаётся разместить однозначно** (противоречие,
   неполнота источника, неясный тип / тема / гранулярность) — заводим
   запись в `progress/<док>.md` или `tasks/<док>.md`, либо открытый вопрос
   в `open-questions.md`. Не угадываем.

3. **Если знаем, куда положить — кладём.** Не оставляем как tasks-заметку
   «решить позже», если решение уже понятно по существующим правилам.

## Связь с самодостаточностью open-questions

По правилу 1 источник станет недоступен, по правилу 2 часть решений
откладывается. Эти отложенные решения должны быть восстановимы без
возврата к архиву — поэтому open-questions и tasks-заметки фиксируются
самодостаточно: формулировка проблемы своими словами, цитаты источника с
локацией (док + раздел / параграф), варианты решения (если видны),
обратные ссылки на файлы `docs/`, ссылающиеся на вопрос.

Сквозное правило самодостаточности — в
`.claude/processes/knowledge-classification.md`, раздел «Сквозные
операции» → «Самодостаточность open-questions при недоступном источнике».
Триада — частный применимый случай для миграции.

## Альтернативы

- **Угадывать при сомнениях.** Отказались: рискуем зафиксировать ошибочное
  знание; восстановить будет тяжелее, чем оставить как open-question.
- **Возвращаться к архиву после миграции по необходимости.** Отказались:
  размывает границу «миграция завершена», архив живёт как теневой источник
  истины параллельно с репо.
- **Материализовать всё, в чём есть малейшие сомнения, как файл-заготовку.**
  Отказались: пустые скелеты в `docs/` размывают принцип «один файл = одно
  знание», создают шум.

## Следствия

- Применяется к текущей миграции архивных процессов (проход 2) и ко всем
  последующим миграциям из недоступного позднее источника.
- Не меняет работу с активным источником (история чата, текущий
  обсуждаемый файл) — там источник остаётся доступен, и правило 2 не
  требует самодостаточной фиксации (см.
  `knowledge-classification.md`, тот же раздел).

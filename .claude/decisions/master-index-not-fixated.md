# Master-index доки не фиксируются

## На какой вопрос отвечает этот файл

Почему мы не сохраняем как файл знания master-index /
навигационные доки поверх многих сущностей.

## Контекст

NQ-G третьей обкатки (отчёт
`.claude/work/progress/обкатка-классификации-процессы.md`, Ф30).
Документ `Deal management/Статусы торговых сущностей.md` объявляет
себя «основным источником истины по статусам», охватывая Deal,
Order, AlgoOrder, Position, BalanceContainer, DealActionState,
Strategy, Instrument и др.

Разбор фрагментов Ф24-Ф29 показал: всё содержание документа
распределяется по владельцам — словарь
(`docs/dictionary/`), lifecycle/модель каждой сущности, сквозные
правила (`docs/rules/`), компоненты (`docs/components/`), процессы
(`docs/processes/`). После распределения у документа-агрегатора
собственного содержания не остаётся — всё дубль владельцев. Это
противоречит one-owner-принципу из
`.claude/decisions/rule-source-of-truth.md`: у каждого правила
один владелец, единый «индекс статусов» владельца не имеет.

## Принятое решение

Master-index / навигационные доки поверх многих сущностей не
сохраняются как файлы знания.

Процедура при встрече такого документа:
- содержание распределяется по владельцам через
  `rule-source-of-truth.md`;
- сам файл-агрегатор после распределения не воспроизводится;
- навигация — забота читателя (древо `docs/`, поиск, IDE).

## Граница — master-index vs сквозное правило

Решение не запрещает сквозные правила про эффекты статусов на
другие сущности (например, «Exchange.HOLD ⇒ новые Deal не
создаются»). Такое правило — самостоятельная единица знания с
собственной формулировкой; владелец — само правило в
`docs/rules/` по критерию «сквозной слой» из
`rule-source-of-truth.md`.

Различение:
- **master-index** содержит только то, что уже сформулировано у
  владельцев (своего содержания нет) — не сохраняется;
- **сквозное правило** имеет собственную формулировку, которой у
  отдельных сущностей нет — сохраняется в `docs/rules/`.

## Альтернативы

- **B. Разрешить master-index как файл из одних ссылок без
  собственных формулировок** (отдельный навигационный тип в
  `structure.md`). Отказались: навигационный тип склонен
  отращивать собственное содержание; явный навигационный сценарий
  не сформулирован — древо `docs/` и поиск покрывают потребность.

## Следствия

- В `.claude/skills/recognize-knowledge.md` добавлен анти-признак
  про файлы-агрегаторы: документы вида «основной источник истины
  по X», «обзор всех Y», master-index сами по себе не кандидаты на
  фиксацию.
- При миграции из `.claude-archive/`: встретив документ-агрегатор,
  разбираем по фрагментам, распределяем по владельцам; сам
  файл-агрегатор не воспроизводим.
- Закрывает NQ-G третьей обкатки. Третья обкатка закрыта
  полностью (NQ-F, NQ-H, NQ-G).

# Торговый совет: специалист, фокус ревью, категория в петле

## На какой вопрос отвечает этот файл

Почему торговое знание введено в пайплайн именно так: один
специалист с единственным книжным домом, торговый фокус ревьюера и
торговая категория в существующей петле.

## Контекст

Шаг 2 Фазы 1 доведён до готовности к `CODE`; решено перед `CODE`
валидировать торговую модель торгово-компетентной стороной.
Согласовано в чате 2026-06-04.

## Решение

1. **«Торговый совет» — зонтичное имя** для торгово-компетентных
   помощников. Сейчас заведён один член — торговый специалист
   (`.claude/agents/trading-specialist.md`): валидирует всё
   торговое, предлагает торгово-обоснованные варианты, отвечает на
   любой торговый вопрос. Компетенция — весь торговый домен
   (фьючерсы и плечо, риск-менеджмент, структура рынка, типы
   ордеров, паттерны стратегий).
2. **Дом торгового знания — единственный:** корпус торговых книг
   `.claude/library/trading/raw/` (выкладывает пользователь). Интернет
   — не вторая база, а точечная свежесть, подаётся через чат; при
   конфликте по фундаменталиям книга главнее, интернет — флажок
   «возможно, устарело». Торговый фокус ревьюера грунтуется тем же
   корпусом и отдельной базы не держит (одно знание — один дом).
3. **Торговый фокус ревьюера**
   (`.claude/skills/trading-review.md`) — адверсариальный проход по
   торговой корректности в петле `DOCS_CHECK_N`; находки
   формулирует и возвращает, решений не предлагает.
4. **Торговая категория в петле** — та же машина
   `DOCS_CHECK_N` / `GAPS_CLOSE_N`, не отдельная петля. Приоритет —
   по тяжести, не по категории; внутри содержательного торговое
   ведёт (рябь: после торговой правки концептная проверка
   прогоняется заново). Содержательно-блокирующее гейтит `CODE`,
   включая жёсткий гейт «модель не выражает нужное торговое
   правило»; гигиена / name-level / заметки на будущие фазы — не
   гейтят. Два касания торговли: специалист конструктивом по ходу
   проектирования (front-load, чтобы не закреплять торгово-наивные
   решения), критик адверсариально в петле (независимость от
   автора). Оркестрация — в
   `.claude/processes/roadmap-step-execution.md`.

## Отвергнутые альтернативы

- **Отдельная торговая петля** рядом с
  `DOCS_CHECK_N` / `GAPS_CLOSE_N` — отвергнуто: торговые находки —
  категория в той же машине, отдельный процесс не нужен.
- **Интернет как вторая база знаний** — отвергнуто: только точечная
  свежесть через чат; конфликт по фундаменталиям решает книга.
  Своего веб-доступа агенту не заводим.
- **Отдельная торговая база у ревьюера** — отвергнуто: одно знание
  — один дом; фокус читает тот же корпус, что и специалист.
- **Приоритет находок по категории** («торговое всегда важнее») —
  отвергнуто: приоритет по тяжести; торговое ведёт только внутри
  содержательного.
- **Завести аналитика сейчас** (анализ данных БД, подбор
  инструмента/стратегии, живые рыночные данные) — отложено:
  будущая фаза, не заводится превентивно.

## Не определено намеренно

«Сбалансированность» специалиста (как именно взвешивает
риск/возможность, консерватизм/агрессию) — не доопределяется
превентивно; снимется с практики.

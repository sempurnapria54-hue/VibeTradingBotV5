# Корроборация закрытия позиции

## На какой вопрос отвечает этот файл

Почему пустой ответ живой ноги позиции не закрывает эпизод без записи
закрытия.

## Контекст

`RefreshPositionExecutor` закрывал живую строку эпизода одним чтением:
пустой ответ `positions` — `CLOSED + EXTERNAL_CLOSE`. Наблюдённого случая
транзиентной пустоты нет; вопрос поставлен как дизайн-вопрос. Разбор
последствий ложного закрытия по коду:

- `Deal` берёт нетто-размер из живого эпизода; на координированном выходе
  окно атрибуции открыто всегда, и нулевой нетто-размер приписывает
  закрытию всю экспозицию траншей — выход транша снимает встроенную защиту
  с живой позиции;
- следующее наблюдение той же позиции заводит вторую строку той же пары;
  ось эпизода на ногах write-once остаётся у закрытой, числа риска по
  живому эпизоду ноги теряют, а запись истории достаётся одной строке из
  двух — вторая ждёт вечно, и сделка уходит аварийным терминалом.

## Решение (solution-designer, 2026-09-30)

**Эпизод закрывается записью закрытия своей пары, добытой второй ногой той
же команды; пустой ответ живой ноги без записи оставляет строку живой, и
звено не завершается.** Смена пары на живой ноге закрывает прежний эпизод
без записи — она сама корроборация. Форма —
`docs/spec/external-status-resolution.json`, `positionCloseCorroborated`
(операнд `closeRecordFound`); исполнитель —
`docs/components/RefreshPositionExecutor.md`.

## Отвергнутые альтернативы

- **Одно чтение (как было).** Последствия выше разрешающие: защита снята с
  живой позиции.
- **Повторное чтение той же командой.** Снимает одиночный сбой, но не
  устойчивое расхождение источника: два ответа одного эндпоинта
  коррелированы.
- **Сверка с фактами исполнения (заявки, налив, счета).** Видит только
  закрытие нашими заявками; срабатывание защиты площадкой, ликвидация, ADL
  и закрытие вне системы не корроборировались бы никогда, а движения
  средств — окно линковки со своей задержкой.

## Цена

Задержка признания закрытия на время появления записи в истории (не
наблюдалась). Направление консервативное: риск завышен, защиты стоят.
Подтверждение снятия риска ждёт записи и тратит попытки своего предела;
запись, не появляющаяся вовсе, держит сделку живой до детектора
расхождения. Слот наблюдения задержки — первый прогон против источника.

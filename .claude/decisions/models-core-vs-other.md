# Разделение моделей: торговые (core) и прочие (other)

> **SUPERSEDED** by `.claude/decisions/model-layer-ontology.md`
> (2026-05-28). Слой `domain/` теперь дробится на `domain/core`
> (торговая модель с биржевым воплощением), `domain/aggregate`
> (сущность без биржевой привязки, нужная для торговли) и
> `domain/other` (прочая хранимая модель). Файл сохранён как
> историческая запись.

## На какой вопрос отвечает этот файл

Почему persisted-модели были разделены на торговые (core) и прочие (other).

## Контекст

В `docs/models/` попадают не только торговые сущности (`Deal`,
`Position`, `Order`, `AlgoOrder`, `Strategy`, `Balance`), но и
свечи, индикаторы, аудит и др. — persisted, но без торговой
бизнес-логики. Критерий «самостоятельная бизнес-сущность» из
`model-granularity.md` формально подходит обоим, но смысл разный:
агрегат с FSM и торговым жизненным циклом vs табличные данные.

## Принятое решение

Хранимые модели делились на торговые (`core/`) и прочие (`other/`).
Действующая раскладка, сменившая эту, живёт в `.claude/rules/structure.md`,
строки `docs/models/domain/core/`, `docs/models/domain/aggregate/`,
`docs/models/domain/other/`.

## Альтернативы

- **A. Не разделять, всё в `docs/models/`.** Отказались: смешение
  агрегатов с FSM и табличных данных теряет структуру.
- **B. Отдельный тип для timeseries / events вне `docs/models/`.**
  Отказались: преждевременно, пока непонятно, по каким осям
  расщеплять.
- **C. Эпитеты «вспомогательная» / «системная» / «не-торговая»
  для other.** Отказались: разнородное содержимое (свечи,
  индикаторы, аудит) ни один эпитет идеально не покрывает; общий
  «модель» работает как временная формулировка.

## Следствия

Живёт в `.claude/rules/structure.md`, строки `docs/models/domain/*`.

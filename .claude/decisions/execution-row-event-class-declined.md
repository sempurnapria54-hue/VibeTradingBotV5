# Класс события на переход строки исполнения не заводится

## На какой вопрос отвечает этот файл

Почему класс события на переход строки исполнения в фазе 2 не строится и
рефреш баланса сужен до уровня решений.

## Контекст

Правило об аудите держало два пункта, упиравшихся в этот класс: частичный
выход был сужен решением до уровня решений и терминала (класс дал бы
несколько событий на сделку **и** метрики под него нет), а исполнение рефреша
баланса стояло клеймом «верен и сегодня не обеспечен» — то есть читалось как
недостроенная фича. Метрики проскальзывания в доме агрегатов не объявлено;
разбора частичного выхода, не разрешимого решениями о заявках и терминалом,
не встречено.

## Решение (solution-designer, 2026-09-30)

**Класс не строится; пункт о рефреше баланса сужен тем же доводом, что и
частичный выход: объясняются решения, зависящие от средств, операндами их
событий, а сам остаток средств журнал не восстанавливает.** Условие возврата
— первая объявленная метрика проскальзывания в доме агрегатов либо разбор
частичного выхода, не разрешимый решениями и терминалом. Дом —
`docs/rules/audit-not-runtime-source.md`.

## Отвергнутые альтернативы

- **Построить класс на каждый переход статуса строки.** Строка исполнения
  двигается несколько раз на действие, действий на проходе несколько —
  объём без единого потребителя; механизм раньше предмета.
- **Узкий класс только на рефреш средств с остатком в содержимом.** Новый
  класс ради пункта, у которого нет читателя-метрики; остаток средств
  становится операндом отчёта только вместе с метрикой, которая его читает.
- **Оставить клейм «верен и не обеспечен».** Он читается как обязательство
  фазы 2 и держит секцию в работе без работы.

## Цена

Остаток средств на момент решения и уровень строк исполнения из журнала не
восстанавливаются; частичный выход объясним только решениями и терминалом.

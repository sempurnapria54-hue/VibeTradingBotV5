# Пустой плановый риск в агрегатах — знаменатель не посчитан, счётчик у него есть

## На какой вопрос отвечает этот файл

Почему сделка с пустым плановым риском выпадает из знаменателя R агрегатов
без своего нового счётчика и не читается нулём.

## Контекст

Дом агрегатов объявлял плановый риск величиной, которая никогда не пуста:
форма — сумма по входным ногам, на пустом множестве ноль
(`docs/spec/deal-risk-numbers.json`, `dealPlannedRisk`). Поле же у сделки
пишут только писатели четвёрки чисел риска и только на полном графе
(`DealRiskNumbersService#recompute`); пока ни один не завершился, колонка
ядра пуста, и терминальное событие везёт её пустой
(`CoreEventMessageMapper`, `plannedRisk ← deal.plannedRiskAmount`). У
статистики колонка nullable, предикат полноты входа её не спрашивает, запрос
пересчёта отбирает `planned_risk > 0` (знаменатель R) и `planned_risk = 0`
(`riskUnsizedDeals`): пустота выпадает из обоих молча.

Писатель признака доступности знаменателя у ядра
(`DealTerminalFeaturesWriter#benchmarkAvailability`) ставит принявшей риск
сделке `AVAILABLE` только при положительном плановом риске, иначе —
`MISSING`; признак пишут все три тропы терминала.

## Решение (solution-designer, 2026-09-30)

**Пустой плановый риск принявшей риск сделки — «знаменатель не посчитан»:
нулём он не читается, в `riskUnsizedDeals` не идёт, из знаменателя R
выпадает, а счётчик у него — уже существующий `riskBenchmarkMissingDeals`.**
Связь «`MISSING` ровно тогда, когда положительного планового риска нет»
держит охранный инвариант спеки агрегатов с контрпримером; число пустых
выводится разностью `riskBenchmarkMissingDeals − riskUnsizedDeals`. Дом —
`docs/rules/statistics-aggregates.md`, исполнимая форма —
`docs/spec/statistics-aggregates.json` (`rDenominatorPresent`,
`missingBenchmarkMarksAbsentDenominator`). Кода решение не требует: запрос
пересчёта трёхзначной логикой уже исключает пустоту из знаменателя.

## Отвергнутые альтернативы

- **Отвергать пустой плановый риск входом** (в предикат полноты). Пустота
  достижима у здорового производителя — сделка, на которой ни один писатель
  четвёрки не завершился, доходит до аварийного терминала штатно, — и
  отказ входа остановил бы приём всей темы на законном событии.
- **Читать пустоту нулём и назвать это в доме.** Второй смысл у пустоты:
  недобытое ушло бы в `riskUnsizedDeals` под ярлыком «сайзинга не было» —
  ровно тот «чужой ярлык», который `docs/rules/absent-value-semantics.md`
  запрещает.
- **Третий счётчик `plannedRiskEmptyDeals`.** Больший след — колонка, поле
  выдачи, миграция — ради числа, которое уже выводится из двух хранимых
  (`.claude/rules/design-simplicity.md`; `docs/concept.md` П4).

## Почему так

Популяция, выпавшая из суммы, обязана иметь счётчик (П1), и он у неё есть —
писатель признака производит его по той же строке сделки. Решение ничего не
заводит, а делает связь исполнимой и чинит примеры спеки, стоявшие на
недостижимом состоянии («знаменатель есть, а признак MISSING»; «ноль, а
признак AVAILABLE»).

## Цена

- **Число пустых — разность, а не своё поле:** читатель, не знающий связи,
  его не увидит. Связь названа в таблице величин дома.
- **Инвариант держится писателем ядра**, а не проверкой статистики: признак
  и плановый риск берутся с одной строки сделки, но пишутся в разные моменты
  (признак — на финализации либо терминале, число — последним писателем
  четвёрки). Класс значения (пусто / ноль / положителен) между этими
  моментами держится тем, что после налива плановый риск принявшей риск
  сделки не опускается ниже налитой доли, а пустым его не делает ни один
  писатель; прогоном это не мерено — связь читается по коду писателей ядра.

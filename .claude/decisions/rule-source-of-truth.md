# Первоисточник правила: кто им владеет

## На какой вопрос отвечает этот файл

Где первоисточник правила, когда оно естественно ложится сразу в
несколько мест.

## Контекст

Закрывает три открытых вопроса:

- **Q1** — куда класть инвариант объекта: в его doc или в `rules/`.
- **Q2** — где первоисточник дублированного правила.
- **Q3** — куда класть правило, неотделимое от процесса.

Вторая обкатка
(`.claude/notes/2026-05-26-обкатка-классификации-торговые-модели.md`)
дала богатый материал по дублям: partial-close запрещён (5
документов), `resultProfit` через `REFRESH_FILLS` (3 док.), формула
live risk (2 док. + внутридокументный дубль), ACK не runtime truth
(3 док.), `ServiceCommand` — runtime object (2 док.) и др.

## Принятое решение

Первоисточник правила = **тот, кто им владеет**. Возможные
владельцы:

- **сущность** (`docs/models/` / `docs/lifecycles/`) — формула,
  атрибут, поведение конкретного объекта;
- **сквозной слой** (`docs/rules/`) — правило применимо к нескольким
  сущностям, единственного владельца нет;
- **маппинг-слой** (`docs/client/<Биржа>/rules/`) — правило про
  преобразование внешнего ↔ доменное (см. `client-layer-docs.md`);
- **процесс** (`docs/processes/`) — правило имеет смысл только в
  контексте конкретного процесса;
- **компонент** (`docs/components/`) — правило про поведение
  конкретного исполнителя.

В местах, где правило задевает, но не является первоисточником, —
**короткое упоминание со ссылкой**, без повтора формулировки
(принцип «одна формулировка живёт в одном месте»).

### Прогон по материалу обкатки

- partial-close запрещён → `docs/rules/` (сквозное).
- `resultProfit` через `REFRESH_FILLS` → `Deal.md` (Deal владеет
  полем).
- ACK не runtime truth → `docs/rules/` (сквозное по командам).
- формула live risk → `Position.md` (Position владеет формулой).
- `ServiceCommand` — runtime object → `ServiceCommand.md`.
- external-status через resolver → компонент / процесс
  первоисточник; в `Order` / `AlgoOrder` — короткое упоминание.
- `positionReducingOnly` vs OKX `reduceOnly` →
  `docs/client/okx/rules/`.
- 12-пунктная валидация стратегии → процесс / компонент-валидатор.
- evidence-cycle refresh → процесс refresh.

## Альтернативы

- **A. Только «сущность vs `rules/`»** (исходная формулировка Q1).
  Отказались: B3 (`Strategy.INACTIVE`) дала тройную развилку с
  компонентом-решателем; покрытия двух категорий недостаточно.
- **B. Раздельные decisions для Q1, Q2, Q3.** Отказались: критерий
  один и тот же, разделение искусственное.

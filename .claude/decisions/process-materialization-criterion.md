# Критерий материализации процесса

## На какой вопрос отвечает этот файл

По какому критерию фрагмент-кандидат в процесс материализуется как файл
`docs/processes/<X>.md`, а в каких случаях — нет.

## Контекст

При подготовке миграции архивных процессов составлена карта артефактов
(`.claude/work/progress/progress-карта-артефактов.md`, проход 1). Из 5
кандидатов в процессы (`deal-lifecycle`, `market-data-calculation`,
`strategy-action-calculation`, `risk-evaluation`,
`audit-execution-history`) карта пометила три как «возможно сольётся с
компонентами» / «возможно только компоненты + правило» / «тонкий каркас».
Возник вопрос: когда процесс материализуется как файл, а когда нет.

Смежные решения:

- `.claude/decisions/component-vs-process.md` — различает «процесс» (как
  идёт поток) и «компонент» (кто выполняет), но не определяет, когда
  процесс материализуется как файл.
- `.claude/decisions/master-index-not-fixated.md` — файл-агрегатор не
  сохраняется, если после распределения содержания по владельцам
  собственного содержания не остаётся.

Из этих двух буквально следовало: если весь поток раскладывается по
компонентам, отдельный файл процесса не нужен. Но процессы могут
использовать другие процессы — композиция потоков (например,
`deal-management` использует данные от `market-data-calculation`,
вызывает `strategy-action-calculation` и `risk-evaluation`). Если процесс
не материализован — теряется устойчивая точка ссылки между кластерами
знаний.

## Принятое решение

Процесс материализуется как файл `docs/processes/<X>.md`, если выполнено
**хотя бы одно** из условий:

1. **Собственное содержание про оркестрацию** — связное описание потока
   (последовательность шагов, входы/выходы между компонентами, условия
   запуска), которое не дублируется ни в одном компоненте и не
   покрывается lifecycle какой-то одной модели.

2. **Точка композиции для других процессов** — процесс вызывается другим
   процессом как подпроцесс (композиция потоков), и нужна устойчивая точка
   ссылки между кластерами знаний.

Если не выполнено ни одно условие — содержание распределяется по
владельцам через `rule-source-of-truth.md`, отдельный
`docs/processes/<X>.md` не создаётся (по логике
`master-index-not-fixated.md`).

## Прогон по 5 кандидатам из текущей миграции

- **`market-data-calculation`** — материализуется. Условие 1 (собственное
  содержание: CandleJob → Indicator/Structure/Phase prep, jobs
  orchestration) и условие 2 (поставщик данных для `deal-management`).
- **`deal-management`** (переименован из `deal-lifecycle` для различения с
  `docs/lifecycles/Deal.md`) — материализуется. Композиционный корень:
  использует `market-data-calculation` как поставщика данных, вызывает
  `strategy-action-calculation` и `risk-evaluation`. Условие 1
  (последовательность jobs → EntryScanner → DealOpening → Orchestrator →
  FSM → Calculator → Command → Executor) и условие 2.
- **`strategy-action-calculation`** — материализуется. Условие 2
  (вызывается из `deal-management`), условие 1 (flow build
  CalculationContext → Price → Size).
- **`risk-evaluation`** — материализуется. Условие 2 (вызывается из
  `deal-management`), условие 1 (когда вызывается, как обрабатывается
  результат).
- **`audit-execution-history`** — не материализуется в текущей миграции.
  Архивный док — каркас, не финализирован, основное содержание —
  открытые вопросы. Полностью выведен из миграции в backlog п.6.

## Отношение к существующим decisions

- Уточняет `component-vs-process.md`: добавляет критерий материализации
  сверх различения «процесс vs компонент».
- Уточняет `master-index-not-fixated.md`: процесс не считается
  master-index'ом, если он точка композиции для других процессов
  (условие 2), даже если собственное содержание тонкое.

## Альтернативы

- **Жёсткий критерий «только собственное содержание»** (только условие 1,
  без условия 2). Отказались: процессы-точки композиции теряют устойчивую
  точку ссылки, асимметрия между кластерами.
- **Мягкий критерий «материализуем любой кандидат, если в архиве выделен
  как отдельный док»**. Отказались: тащим в `docs/` файлы-обзоры без
  собственного содержания, противоречит `master-index-not-fixated.md`.
- **Решать по каждому кандидату индивидуально без общего критерия.**
  Отказались: переоткроем тот же вопрос на каждой миграции.

## Следствия

- Текущая миграция процессов: материализуются 4 процесса
  (`market-data-calculation`, `deal-management`,
  `strategy-action-calculation`, `risk-evaluation`).
- `audit-execution-history` выведен из миграции (см. backlog п.6).
- Имя `deal-management` (не `deal-lifecycle`) — для различения с
  `docs/lifecycles/Deal.md`; совпадает с именем архивной папки
  `Deal management/`.
- **Критерий вшит в скиллы классификации** (2026-05-30, снято
  прежнее «скиллы пока не правим»): распознавание кандидата в
  процесс — `.claude/skills/recognize-knowledge.md` +
  `.claude/skills/classify-type.md` (§«Компонент vs процесс»);
  проверка двухусловного критерия при размещении —
  `.claude/skills/place-knowledge.md` (§«Кандидат в процесс»).

## Обновление прогона: вынос `candle-loading` (шаг 1 Фазы 1, 2026-05-30)

При проработке шага 1 Фазы 1 критерий применён повторно к
`market-data-calculation`: загрузка свечей удовлетворяет обоим
условиям и выделена в самостоятельный процесс.

- **`candle-loading`** (новый) — материализуется. Условие 1
  (собственное содержание: цикл `BACKFILL`/`SYNC`/`CHECK`/`REPAIR`,
  оркестрация `CandleJob`, density-политика, координация онбординга
  `Instrument` с несколькими `CandleGroup`) и условие 2 (поставщик
  свечей для `market-data-calculation`).
- **`market-data-calculation`** — сужен до **вычисления**
  (индикаторы / структура / фаза) поверх загруженных свечей;
  использует `candle-loading` как поставщика (условие 2). `CandleJob`
  и блок загрузки/целостности из него вынесены.
- Владелец оркестрации переходов `Instrument.Status` /
  `CandleGroup.Status` (отдельный orchestrator-компонент + handler'ы
  по образцу Deal, или иначе) пока не материализуется — открытый
  вопрос ORCH-Q1 (`.claude/work/questions/open-questions.md`).

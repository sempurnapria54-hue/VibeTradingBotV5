# Разделение знания по адресатам: чат vs Claude Code

## На какой вопрос отвечает этот файл

Почему знание в репозитории разделено по адресатам — чат и Claude
Code.

## Контекст

В обкатке выявилось, что у файлов знания есть два разных
адресата: чат (Claude в claude.ai, взаимодействует с
пользователем) и Claude Code (правит файлы в репозитории).
Формулировки в файлах для CC иногда писались так, как будто
адресат — чат («предлагает пользователю», «применяется в чате»,
«действует после подтверждения»). Это создавало путаницу: неясно,
кто исполнитель и как организовано взаимодействие с
пользователем.

## Принятое решение

- Файлы, адресованные чату, живут в `.claude/chat/`
  (`chat-project-instructions.md`, PK-дайджесты; изначально —
  единственный файл `chat-project-instructions.md` в `rules/`,
  переехал по `.claude/decisions/context-cost-diet.md`).
- Всё остальное в `.claude/` (скиллы, агенты, правила, процессы,
  решения, заметки, снапшоты) — адресовано Claude Code.
- Чат может читать файлы для CC как справку через Project
  Knowledge — чтобы знать, что CC будет делать. Но написаны они
  для CC.
- Формулировки файлов для CC живут в `.claude/rules/structure.md`
  §«Файлы для CC формулируются в терминах CC».

## Альтернативы

- **A. Не разделять явно, считать что все файлы читаются всеми
  участниками.** Отказались: формулировки становятся
  двусмысленными, неясно, кто исполнитель.
- **B. Два набора файлов — один для чата, один для CC, с
  дублированием содержания.** Отказались: дублирование
  содержательно, обслуживать его дорого; чату достаточно читать
  файлы CC как справку.

## Следствия

Итог ревизии формулировок держится состоянием корпуса: в
`.claude/rules/`, `.claude/skills/`, `.claude/agents/`, `.claude/processes/`
формулировок «применяется в чате» и «предлагает пользователю» нет.
Удаление закрытого вопроса из `open-questions.md` живёт в
`.claude/rules/closed-work-transfer.md` §«Правило».

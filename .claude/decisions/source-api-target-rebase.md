# Ре-база контура source-api: цель теста — сырьё

## На какой вопрос отвечает этот файл

Почему контур тестов API источника бьёт в сырьё (сырой клиент + сырые
DTO), а не в нашу границу, и какими вариантами решены сопутствующие
развилки.

## Решение

Цель контура тестов API источника (`.claude/processes/source-api-testing.md`)
переносится **с нашей границы на сырьё**:

- **было** — граница: `IntegrationService` / `*ExternalSnapshot` /
  `ExchangeAck` через mapped-прокси `OkxProxyController`;
- **стало** — сырой клиент `OkxRestClient` + сырые интеграционные DTO
  (`OkxApiResponse<T>`, типизированные `*OkxResponse`/`*OkxRequest`).

Тесты проверяют используемые поля сырого DTO + поведение/коды ошибок,
не каждое возможное поле биржи (интеграционные DTO — худые,
`codestyle` §«Неиспользуемый код» в силе, карваута на полное зеркало
нет).

## Почему

- **Снапшот/маппер — наш слой, не контракт биржи.** Проверка через
  mapped-границу смешивала «что отдала биржа» с «как мы это смапили»:
  поле, которое снапшот ронял, становилось ненаблюдаемым (прокси-
  surface-gap), а проверки кодировали ожидание на нашем DTO. Сырьё
  отделяет факт биржи от нашего маппинга.
- **Большинство прокси-surface-gap'ов растворяется.** Свечи (нет на
  прокси), сырой `getOrder` (ниже прокси), адаптер-инварианты на
  снапшоте (не выведены) — были артефактом mapped-границы. Против
  сырого клиента + сырого DTO наблюдаемы напрямую.
- **Источник истины об API — официальный док, а контур его проверяет.**
  Сырой ответ сверяется с апидоками (дистиллят офдока); расхождение —
  правка апидоков (через `integrator`), а не подгонка под наш маппинг.

## Сопутствующие развилки (варианты и выбор)

### A — подключение коллекции → **A2** (типизированный raw-passthrough)

Коллекция бьёт в новый контроллер app, который зовёт `OkxRestClient`
напрямую и отдаёт сырой `OkxApiResponse<T>` (без снапшот-маппинга). App
подписывает и сериализует request-DTO.

- **Почему A2:** прогоняет ровно новую цель (сырой клиент + сырые DTO),
  сохраняет два инвариант-свойства контура — **кредов в Postman нет**
  (подпись на стороне app), **demo/prod — профилем app**; прецедент —
  диагностический сырой `getAccountConfig()`.
- **Отклонены:** **A1** прямой вызов OKX из Postman — возвращает креды
  в Postman (регресс безопасности), дублирует подпись, не прогоняет
  наши DTO; **A3** универсальный signed-passthrough — мимо
  типизированного клиента/DTO (литеральный OKX-JSON).

### B — слой код-тестов → **B1 + passthrough**

`@SpringBootTest`-код-тесты в `src/test` (JUnit 5 + AssertJ —
существующий стек) бьют в **тот же** A2-passthrough, что и коллекция
(механика 1:1). Уточнения поверх варианта:

- **Профиль-гейт:** код-тесты активны на non-prod, на **prod не идут**
  (структурный no-prod на любом профиле, кроме prod; «пока» — интерим).
  Не «opt-in off by default».
- **Создание сущностей:** тесты создают реальные сущности на demo
  (ордера/позиции/algo) — иначе stateful-запросы (getOrder / cancel /
  close-position) не проверить. **Teardown обязателен в каждом кейсе.**
  Где сущность создать нельзя (архивные окна) — гейт достижимости:
  только негатив.
- **Почему B1:** переиспользует устоявшийся стек и расположение
  `src/test`; реальные подпись + сериализация request-DTO + биндинг
  response-DTO; teardown по жизненному циклу; единый с коллекцией
  passthrough держит коллекция↔код-тесты 1:1.
- **Отклонены:** **B2** Newman (исполнитель = коллекция) — противоречит
  «код-тесты — исполнитель»; **B3** отдельный раннер — переизобретает
  `@SpringBootTest` + профиль-гейт.

### C — сверка апидоков → **C3** (формализованная стыковка + рантайм-провенанс)

`integrator` остаётся владельцем апидоков; раздел «расхождения» отчёта
прогона — явный вход/триггер `api-docs-completion` («рантайм-
расхождение»); в легенду манифеста — провенанс `рантайм` /
`подтверждён-прогоном`; шапка `external-source-sync` несёт пометку
рантайм-расхождения рядом с датой офдок-сверки.

- **Почему C3:** честно фиксирует живой факт против офдока (канонический
  случай — `cancel-advance-algos` жив на demo вопреки офдоку
  2025-04-24); бинарный провенанс `офдок`/`сторонний` этого не мог.
  Разделение ролей сохранено.
- **Отклонены:** **C1** просто маршрутизировать находкой — оставляет
  противоречие офдок↔рантайм без честной пометки; **C2** `tester`
  правит апидоки сам — ломает разделение ролей.

## Prod — вне контура

Prod убран из контура целиком: **нет prod-кейсов, нет prod-read-only
блока**. Контур — demo/non-prod. Прод пользователь проверяет ад-хок
вручную коллекцией **вне контура** — контур его не описывает. (Снимает
прежний prod-read-only блок, требовавший read-only prod-ключа.)

## Следствия

- **Правки скиллов/процесса/шаблона/роли** контура — manifest-driven
  покрытие (периметр ∩ сырой клиент; client-coverage-gap), порождающая
  методология негатива, гейт достижимости, A2-passthrough, B1-код-тесты
  (новый скилл `test-code`), C3-сверка, prod вне контура, снятие
  прокси-surface-gap'ов.
- **Прокси-граничный пилот снят** (`.claude/tests/source-api/okx/`):
  дизайн-контент мигрирован, пилот регенерируется под сырьё; prod-блок
  (P1-P4) не переносится.
- **Судьба mapped-прокси и mapped `market-price` (§«Неиспользуемый
  код»).** `OkxProxyController` (отдаёт снапшоты/`ExchangeAck`) как
  поверхность контура **замещён** A2-passthrough. Mapped-цепочка
  `getMarketPriceData` → `MarketPriceDataExternalSnapshot` →
  `MarketPriceDataMapper` **не имеет доменного потребителя** (сборка
  `MarketPriceData` — шаг 5, `HOLD`); под сырьё live-цена цепочки идёт
  от сырого `getTicker`. **Диспозиция:** удаление неиспользуемого
  (mapped proxy-эндпоинты как старая поверхность контура + mapped
  market-price-цепочка) — **при приземлении A2-passthrough** (чтобы не
  снимать источник цены до его замены), с оговоркой forward-кода шага 5;
  исполняется на шаге реализации, не этой методологической правкой.
  Зафиксировано в `.claude/work/backlog.md`.
- **Doc-sync `OkxTickerResponse`** — инвентарь полей дока выровнен под
  худой код (decision 2): `instType` добавлен в таблицу полей DTO,
  `markPx`/`idxPx` (не в coded DTO) перенесены в «не входят».
- **Тип знания / расположение планов** (`test-knowledge-type.md`) — без
  изменений.

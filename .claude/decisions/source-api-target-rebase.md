# Ре-база контура source-api: цель теста — сырьё

## На какой вопрос отвечает этот файл

Почему контур тестов API источника бьёт в сырьё (сырой клиент + сырые
DTO), а не в нашу границу, и какими вариантами решены сопутствующие
развилки.

## Решение

Цель контура тестов API источника (`.claude/processes/source-api-testing.md`)
переносится **с нашей границы на сырьё**:

- **было** — граница: `IntegrationService` / `*ExternalSnapshot` /
  `ExchangeAck` через mapped-прокси `OkxProxyController`;
- **стало** — сырой клиент `OkxRestClient` + сырые интеграционные DTO
  (`OkxApiResponse<T>`, типизированные `*OkxResponse`/`*OkxRequest`).

Механизм контура — **единственный generic-эндпоинт `POST
/api/proxy/okx/raw`** поверх публичного `dispatch` в `OkxRestClient`
(раздел D): `/raw` подписывает под капотом (существующий signing-путь) и
возвращает `OkxApiResponse<JsonNode>`; тесты ассертят **сырые поля
ответа OKX**. Типизированных проксиметодов и `*OkxResponse`-DTO в контуре
**нет**. За счёт универсального метода цель — **весь in-perimeter
периметр манифеста** (кроме вне-периметра), независимо от того,
реализован ли сейчас типизированный метод клиента.

## Принцип: контур проверяет контракт биржи, не наш код

API-тесты контура проверяют **контракт API биржи (OKX)** — что сам
эндпоинт OKX рабочий и его можно подключить в любой момент. Мапперы,
DTO, наша сериализация — **наш код, вне scope этого контура** (нужна их
проверка — отдельные юнит-тесты мапперов, не здесь). Пройденный тест =
гарантия подключаемости метода OKX («проверено» ≠ «обязаны подключить»).
Отсюда **`/raw`-only + JsonNode**: контур смотрит на сырьё биржи, не на
наш типизированный слой. (`codestyle` §«Неиспользуемый код» в силе:
типизированные методы/параметры под доменно-неиспользуемые запросы за
счёт контура не заводятся.)

Цель контура — чтобы **`integrator` понимал и документировал реальное
поведение API OKX**: прямой/негативный прогон → наблюдение → находка C3
(правка апидоков). Детект регрессий API (периодический прогон, сверка
изменений) — **следствие** этого, явно как цель не фиксируется.

## Принцип: инвариант восстановления состояния кейса

Каждый **stateful-кейс возвращает стартовое состояние, и это
проверяется**: снимок старта → прогон → restore → ассерт «конец ==
старт» (через wait-until-condition, не фиксированный sleep). Реальное
исполнение и **реверсивные account-write** на demo допущены при
соблюдении инварианта (минимальный `sz`; восстановление настроек).

- **В охвате инварианта** (расхождение → фейл кейса): настройки
  (`leverage`, `posMode`, `acctLv`) и сущности (ордера / позиции / algo
  — ни одного открытого/живого по инструменту после кейса).
- **Вне инварианта** (наблюдаются, кейс не фейлят): append-only история
  (растёт), комиссионный / PnL-остаток баланса после реального fill.

**Модель sweep+halt (код-тесты).** Невозврат к старту — **жёсткий фейл
кейса** (и для сущностей, и для настроек `leverage`/`posMode`/`acctLv`),
не глушится. Дополнительно — **принудительный sweep**: снять/закрыть
утёкшие сущности; настройки — re-set к снапшот-значению старта. Если sweep
не вычистил (состояние всё ещё грязное) → **halt прогона** (дальше не
идём). Находка C3 (невосстановимое состояние) логируется **в любом
случае** — чтобы невосстановимая настройка наблюдалась, а не терялась. Это
уточняет прежнюю формулировку «невозврат настройки → находка, не тихий
мусор»: настройка теперь идёт через sweep+halt как сущность, но находка
по-прежнему пишется. Teardown-хелперы (`*Quietly`) — попытка sweep'а
(глушат ошибки); авторитет «вернулось ли» — Verify.end; halt — если после
sweep грязно. Применение — красной нитью по всем stateful-кейсам плана.

## Почему

- **Снапшот/маппер — наш слой, не контракт биржи.** Проверка через
  mapped-границу смешивала «что отдала биржа» с «как мы это смапили»:
  поле, которое снапшот ронял, становилось ненаблюдаемым (прокси-
  surface-gap), а проверки кодировали ожидание на нашем DTO. Сырьё
  отделяет факт биржи от нашего маппинга.
- **Большинство прокси-surface-gap'ов растворяется.** Свечи (нет на
  прокси), сырой `getOrder` (ниже прокси), адаптер-инварианты на
  снапшоте (не выведены) — были артефактом mapped-границы. Против
  сырого клиента + сырого DTO наблюдаемы напрямую.
- **Источник истины об API — официальный док, а контур его проверяет.**
  Сырой ответ сверяется с апидоками (дистиллят офдока); расхождение —
  правка апидоков (через `integrator`), а не подгонка под наш маппинг.

## Сопутствующие развилки (варианты и выбор)

### A — подключение коллекции → **A2** (raw-passthrough), под /raw-only сведён к generic-эндпоинту (раздел D)

Коллекция бьёт в контроллер app, который зовёт `OkxRestClient` напрямую и
отдаёт сырьё (без снапшот-маппинга). App подписывает под капотом.

- **Почему A2 (vs прямой вызов OKX из Postman):** сохраняет два
  инвариант-свойства контура — **кредов в Postman нет** (подпись на
  стороне app), **demo/prod — профилем app**; прецедент —
  диагностический сырой `getAccountConfig()`.
- **Отклонены:** **A1** прямой вызов OKX из Postman — возвращает креды
  в Postman (регресс безопасности), дублирует подпись.
- **Под /raw-only A2 сведён к generic-эндпоинту (раздел D).** Прежняя
  форма A2 — набор **типизированных** проксиметодов (`OkxApiResponse<T>`
  на каждый эндпоинт) — снята: контур ходит через **единственный**
  `POST /api/proxy/okx/raw` (форма A3, generic + JsonNode), но с
  сохранёнными свойствами A2 (креды/подпись в app). A3 отклонялся как
  «литеральный OKX-JSON мимо наших DTO» — под принципом «контур проверяет
  контракт биржи, не наш код» это ровно цель, а не недостаток.

### B — слой код-тестов → **B1 + passthrough**

`@SpringBootTest`-код-тесты в `src/test` (JUnit 5 + AssertJ —
существующий стек) бьют в **тот же** A2-passthrough, что и коллекция
(механика 1:1). Уточнения поверх варианта:

- **Профиль-гейт:** код-тесты активны на non-prod, на **prod не идут**
  (структурный no-prod на любом профиле, кроме prod; «пока» — интерим).
  Не «opt-in off by default».
- **Создание сущностей:** тесты создают реальные сущности на demo
  (ордера/позиции/algo) — иначе stateful-запросы (getOrder / cancel /
  close-position) не проверить. **Teardown обязателен в каждом кейсе.**
  Где сущность создать нельзя (архивные окна) — гейт достижимости:
  только негатив.
- **Почему B1:** переиспользует устоявшийся стек и расположение
  `src/test`; реальные подпись + сериализация request-DTO + биндинг
  response-DTO; teardown по жизненному циклу; единый с коллекцией
  passthrough держит коллекция↔код-тесты 1:1.
- **Отклонены:** **B2** Newman (исполнитель = коллекция) — противоречит
  «код-тесты — исполнитель»; **B3** отдельный раннер — переизобретает
  `@SpringBootTest` + профиль-гейт.

### C — сверка апидоков → **C3** (формализованная стыковка + рантайм-провенанс)

`integrator` остаётся владельцем апидоков; раздел «расхождения» отчёта
прогона — явный вход/триггер `api-docs-completion` («рантайм-
расхождение»); в легенду манифеста — провенанс `рантайм` /
`подтверждён-прогоном`; шапка `external-source-sync` несёт пометку
рантайм-расхождения рядом с датой офдок-сверки.

- **Почему C3:** честно фиксирует живой факт против офдока (канонический
  случай — `cancel-advance-algos` жив на demo вопреки офдоку
  2025-04-24); бинарный провенанс `офдок`/`сторонний` этого не мог.
  Разделение ролей сохранено.
- **Отклонены:** **C1** просто маршрутизировать находкой — оставляет
  противоречие офдок↔рантайм без честной пометки; **C2** `tester`
  правит апидоки сам — ломает разделение ролей.

### D — универсальный dispatch (полный in-perimeter)

Цель контура расширена с `in-perimeter ∩ клиент` на **полный
in-perimeter периметр манифеста** (кроме вне-периметра), независимо от
того, реализован ли сейчас типизированный метод клиента. Механизм —
**универсальный подписанный core-dispatch + generic-эндпоинт
passthrough** поверх него. Прежние A2/B1/C3 в силе; D их дополняет.

#### D1 — размещение → core-dispatch в `OkxRestClient` + generic-эндпоинт на `OkxProxyController`

Публичный обобщённый метод отправки произвольного запроса живёт в
`OkxRestClient` (форма: `<R> R dispatch(method, path, query, body,
signed, responseType)`):

- маршрутизирует public (`okxRestClientHttp`) / signed
  (`okxAuthRestClientHttp`) RestClient по флагу `signed`; подпись и
  креды — существующим `OkxSigningInterceptor` на стороне app;
- **общий core-dispatch с тремя потребителями:** (1) прод —
  типизированные методы клиента делегируют отправку в него (продукт
  передаёт typed `R`); (2) код-тесты и (3) Postman/коллекция — оба через
  **`/raw`** (контур передаёт `JsonNode`), 1:1 между собой;
- **не dead-код** (`codestyle` §«Неиспользуемый код»): используется
  продом через делегирование типизированных методов. За счёт него
  типизированные методы/параметры под доменно-неиспользуемые запросы
  **не** заводятся — вот это был бы dead-код;
- диагностический сырой `getAccountConfig()` — частный случай dispatch
  со String-токеном; bespoke-метод растворяется в общем core-dispatch.

Generic-эндпоинт `POST /api/proxy/okx/raw` на `OkxProxyController` —
**единственная поверхность контура** поверх dispatch. Принимает
конверт-запрос `{method, path, query, body, signed}` (JSON-тело) →
отдаёт `OkxApiResponse<JsonNode>`. Достаёт **любой** in-perimeter
эндпоинт OKX, включая client-coverage-gap'ы (batch orders, amend order,
order-history 3m, cancel-all-after, order-precheck, account-rate-limit,
amend-algos и прочие ⚪ gap манифеста), и негативы, ранее заблокированные
типизированным слоем (сырой битый `ordType`, `callbackSpread`, all-ccy
`getBalance`) — тело конверта строится руками по контракту OKX, типизация
прокси их больше не глушит.

**Типизированные проксиметоды `OkxProxyController` сняты** как unused
(`codestyle` §«Неиспользуемый код»): контуру при `/raw`-only они не нужны
(включая 7 read-эндпоинтов, добавленных под прежнее обоснование 1:1).
Типизированные методы **`OkxRestClient` остаются** — ими пользуется
продукт (делегируют в `dispatch`).

- **Отклонены:** отдельный конструкт-диспетчер — расщепляет владение
  двумя RestClient-бинами, которые уже живут в `OkxRestClient`, либо
  инвертирует текущее владение; **сохранить типизированные
  проксиметоды** — для контура это наш код (вне scope принципа) и
  unused-поверхность.

#### D2 — типизация ответа контура → `OkxApiResponse<JsonNode>` (контракт биржи, не наш DTO)

Core-dispatch обобщён по токену ответа `R`; потребитель выбирает биндинг:

- **контур (`/raw`)** — всегда `OkxApiResponse<JsonNode>`: конверт
  распарсен (`code`/`msg`/`data`), элементы `data` — JsonNode → ассерты
  по **сырым полям ответа OKX**. Под принципом «контракт биржи, не наш
  код» типизированный `*OkxResponse` контуру не нужен — его binding
  проверял бы наш DTO, а не API биржи;
- **продукт** — типизированные методы клиента передают свой
  `OkxApiResponse<*OkxResponse>`-токен в тот же dispatch (типизация —
  деталь продукта, не контура);
- **сырой String** — низший токен того же dispatch (`getAccountConfig`
  растворяется в нём); JsonNode его покрывает, отдельным контурным
  механизмом он не является.

- **Отклонены:** **типизированный биндинг в контуре** — проверяет наш
  DTO/сериализацию (наш код, вне scope принципа) и не даёт токена под
  gap-эндпоинты без DTO; **сырой String везде** — теряет структуру
  конверта (`code`/`data[].sCode`), ассерты руками по тексту.

#### Гейт no-prod — на тест-обращённой выдаче, не на core-dispatch

Core-dispatch **общий и нужен проду в проде** — гейта на нём нет.
Structural no-prod вешается на **generic-эндпоинт passthrough**
(тест-обращённый): он шлёт в т. ч. write'ы в произвольный path → демо/
non-prod обязателен **жёстче прежнего** (`@Profile("!prod")` —
структурный, на любом профиле, кроме prod). Согласуется с профиль-гейтом
B1 (код-тесты на non-prod, на prod не идут).

## Prod — вне контура

Prod убран из контура целиком: **нет prod-кейсов, нет prod-read-only
блока**. Контур — demo/non-prod. Прод пользователь проверяет ад-хок
вручную коллекцией **вне контура** — контур его не описывает. (Снимает
прежний prod-read-only блок, требовавший read-only prod-ключа.)

## Следствия

- **Охват расширен до полного in-perimeter** (раздел D) — с
  `in-perimeter ∩ клиент` на весь in-perimeter периметр манифеста: все
  эндпоинты (вкл. client-coverage-gap'ы и ранее заблокированные
  негативы) идут через `/raw`. Колонка покрытия манифеста
  (`⚪ gap` для строк без метода клиента) **переосмысляется**: gap
  больше не «покрыть нельзя», а «покрывается через `/raw`, не через
  типизированный метод клиента».
- **План + коллекция регенерированы под полный in-perimeter `/raw`**
  (`.claude/tests/source-api/okx/`) — этой правкой: 60 эндпоинтов, все
  кейсы через `/raw` + JsonNode-ассерты, структурный изоморфизм
  эндпоинт→раздел/папка/класс, write-тела руками по контракту OKX.
  **DESIGN аппрувнут** (два независимых адверсариальных ревью, оба
  APPROVE; §Нерешённое 1-4 закрыты). **Переразметка колонки покрытия манифеста**
  (`⚪ gap` → `🟡 в плане` для ныне покрытых через `/raw`) — отдельным
  проходом владельца колонки; план — её источник.
- **Реализация кода универсального механизма** (публичный обобщённый
  `dispatch` в `OkxRestClient` с делегированием туда типизированных
  методов; растворение `getAccountConfig` в нём; снос типизированных
  проксиметодов `OkxProxyController` до `/raw`; гейт `@Profile("!prod")`)
  — **отдельным шагом реализации**, не этой методологической правкой.
- **Скиллы/процесс/шаблон/роль контура отстают от `/raw`-only**
  (`test-design`/`test-collection`/`test-plan` ещё описывают
  типизированный A2-passthrough, `OkxApiResponse<T>`, «периметр ∩
  клиент»). Их выравнивание на `/raw`-only + JsonNode + полный
  in-perimeter — **follow-on**, вне текущей задачи (план/коллекция/
  решение).
- **Правки скиллов/процесса/шаблона/роли** контура — manifest-driven
  покрытие (периметр ∩ сырой клиент; client-coverage-gap), порождающая
  методология негатива, гейт достижимости, A2-passthrough, B1-код-тесты
  (новый скилл `test-code`), C3-сверка, prod вне контура, снятие
  прокси-surface-gap'ов.
- **Прокси-граничный пилот снят** (`.claude/tests/source-api/okx/`):
  дизайн-контент мигрирован, пилот регенерируется под сырьё; prod-блок
  (P1-P4) не переносится.
- **Судьба mapped-прокси и mapped `market-price` (§«Неиспользуемый
  код»).** `OkxProxyController` (отдаёт снапшоты/`ExchangeAck`) как
  поверхность контура **замещён** A2-passthrough. Mapped-цепочка
  `getMarketPriceData` → `MarketPriceDataExternalSnapshot` →
  `MarketPriceDataMapper` **не имеет доменного потребителя** (сборка
  `MarketPriceData` — шаг 5, `HOLD`); под сырьё live-цена цепочки идёт
  от сырого `getTicker`. **Диспозиция:** удаление неиспользуемого
  (mapped proxy-эндпоинты как старая поверхность контура + mapped
  market-price-цепочка) — **при приземлении A2-passthrough** (чтобы не
  снимать источник цены до его замены), с оговоркой forward-кода шага 5;
  исполняется на шаге реализации, не этой методологической правкой.
  Зафиксировано в `.claude/work/backlog.md`.
- **Doc-sync `OkxTickerResponse`** — инвентарь полей дока выровнен под
  худой код (decision 2): `instType` добавлен в таблицу полей DTO,
  `markPx`/`idxPx` (не в coded DTO) перенесены в «не входят».
- **Тип знания / расположение планов** (`test-knowledge-type.md`) — без
  изменений.

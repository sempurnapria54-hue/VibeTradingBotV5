# Обязанности полноты у правки

## На какой вопрос отвечает этот файл

Какое у нас правило обязанностей полноты у правки корпуса.

## Правило

**Обязанности полноты принадлежат правке и выводятся из РОДА того, что она
ввела; несёт их заход, который корпус меняет, — а не статус шага и не
отчёт.** После снятия доковой петли (решение держателя 2026-09-15,
`.claude/decisions/step-machine-rework.md`) свипы этого правила и
энфорсеры гейта инструментов — единственное, что держит доки от дрейфа
после факта; дом обязанностей каждого рода — этот файл.

Правило действует на всякий заход, меняющий носители корпуса: доки по
факту (`DOCS`), закрытие находки ревью (`REVIEW`), правку правила или
процесса, доработку по замечанию держателя. Заход, который корпус только
**читает** (фокус ревью, просмотр держателя), обязанностей не несёт.

## Предмет обязанностей — дельта захода

Перечень точек и производных носителей выводится из **собственной дельты**
захода командой, а не из перечня находок, на которые он отвечает: находка
называет, **что** чинить; чем правка обязана предъявиться, называют её род
и её дельта.

```bash
git write-tree                        # метка: до первой правки захода
git diff --name-only <метка>          # носители, которые правил ЭТОТ заход
git diff -U0 <метка> -- <носитель>    # его точки вставки в носителе
git diff -U0 <метка> | grep '^+[^+]'  # строки, которые заход добавил
```

Коммитов внутри шага нет, поэтому меткой служит дерево индекса
(`git write-tree` печатает его имя, не трогая ни рабочего дерева, ни
ссылок); дельта считается против рабочего дерева. Метка, не отбитая
вовремя, восстанавливается меткой предыдущего захода — перечень тогда шире
собственной дельты, и это объявляется; у́же дельты он не бывает.

## Обязанность кончается разбором выдачи, а не её предъявлением

У каждого члена добытой выдачи — свой записанный исход: таблица исходов
соразмерна выдаче, и единица клетки разбора равна единице, в которой выдача
напечатана: попадания — клетка на
попадание, файлы — клетка на файл (исход о файле утверждает о файле
**целиком**). Свёртка в класс законна, когда класс задаёт команда-фильтр и
счёты классов сходятся с полной выдачей (строка `Итого`, которую сверяет
`py tools/self-count-check.py`); свёртка прозой — сокращение предмета.
Пустая клетка — не разбор. Полный вывод грепа в отчёт не вклеивается —
адреса проверяемы повторным запуском команды, а команда стои́т блоком кода
(`.claude/rules/measurement-commands.md`).

## Словарь родов — закрытый

| Род | Признак: что правка сделала | Обязанность |
|---|---|---|
| `снятие` | сняла или заменила действующую редакцию | §«Свип снятой редакции» |
| `дом` | завела, перенесла или разделила дом истины | `.claude/rules/policy-home.md` §«Заведение и перенос дома — не дополнение»; §«Свип обоих концов переноса» |
| `величина` | ввела поле, колонку, операнд или тропу чтения | §«Свип по структурным носителям»; писатель — `docs/rules/writer-named-for-every-value.md` |
| `конструкция` | ввела или изменила формулу, предикат, инвариант, счётный клейм | §«Свип по конструкции» |
| `радиус` | изменила объём действия | §«Свип по перечню предикатов» |
| `кардинальность` | изменила кардинальность, предикат или инвариант | §«Свип по производным носителям» |
| `клейм` | изменила перечень, из которого выведен клейм полноты | §«Проход по носителям с клеймом полноты» |

Правка играет несколько родов сразу, и обязанности складываются. Род вне
словаря — дефект, а не расширение перечня; новый род вводится правкой этой
таблицы, и такая правка сама рода `клейм`.

## Свип снятой редакции

Правка, снимающая или заменяющая редакцию, завершается **свип-грепом по
терминам снимаемой формулировки** по всем живым носителям: `docs/**`,
`<дерево кода>/src/**`, `.claude/rules/**`, `.claude/processes/**`,
`.claude/skills/**`, `.claude/agents/**`, `.claude/tests/**`, рабочие файлы
(`backlog.md`, `open-questions.md`, roadmap, `progress/`). Термины берутся из
**снимаемой** формулировки, их обычно несколько; рабочие файлы опаснее
доков — они адресованы исполнителю следующего захода.

**Энфорсер — реестр снятых редакций `tools/retired-check.py`.** Запись
несёт опознавательный шаблон, шаблон **пришедшей** редакции, дату,
решение-источник, разрешённые места и **популяцию носителей** — перечень
мест, где снятая редакция стоя́ла и где пришедшая обязана появиться.
Команда падает на вхождении снятого термина вне разрешённых мест, на
носителе популяции без пришедшей редакции и на строке популяции, которой в
корпусе больше нет. Популяция ловит **встречную форму**: носитель,
выражающий снятое другими словами, шаблоном не берётся по построению.
Разрешённые места — только носители пайплайна: слой опровержения в
продуктовом корпусе запрещён (`docs/concept.md` §«Опровержение правит на
месте»).

**Форм предмета у свипа три:** имя величины, прозаическая тропа чтения и
**объём действия** («вся биржа», «по всему контуру») — правка, меняющая
радиус, свипается всеми тремя (`.claude/rules/measurement-commands.md`
§«Свип: две формы поиска и полный вывод»).

**Свип обоих концов переноса.** Когда правка переносит владение (перечень
команд — с обработчика на действие, метрику — с компонента на компонент),
свип покрывает **оба** конца: на принимающем уровне старых терминов может
не быть вовсе.

**Хвост — такое же закрытие.** Правка, пришедшая после свипов (ответ
держателя, доспроектированная механика, доработка по находке ревью),
получает свои свипы по **своей** дельте и свой независимый взгляд.

## Свип по конструкции

Греп по снимаемой формулировке находит носитель, где термин **звучит**, и
не находит конструкцию, пришедшую последней. Всякая формула, предикат,
инвариант или счётный клейм, которые правка **вводит или меняет**,
проверяются независимо — на арифметику, область определения операндов и
согласованность с соседями — кем-то, кроме автора, либо отдельным
проходом. *(Кейс: новая формула ошибалась арифметически и не свипалась
никем, потому что пришла хвостом.)*

## Свип по структурным носителям

Поле, которого нет, текстом не находится. Правка, вводящая поле, колонку,
операнд или тропу чтения, проходит по фиксированному перечню и отмечает
каждый носитель: §Структура доменной модели; §Персистентность; schema-дельта
шага; состав `*ExternalSnapshot` и used/unused нативного инвентаря;
mapping-таблицы; инвентарь читателей у владельца данных (если введена
тропа чтения); **контракт вызова у создателя сущности** — «что передаёт
вызывающий» и «чем заполняется каждое обязательное поле». Признак
применимости — правка называет новое имя либо фразу «резолвится через …».
Структурных правок не было — пишется явно.

## Свип по перечню предикатов

Радиус не имя: он выражается неограниченным числом прозаических форм, и
всякий шаблон берёт лишь те, которые автор вспомнил. Популяция такой правки
строится **от предмета**: выписываются предикаты и выборки, читающие радиус
— детекторы, гейты входа, предусловия снятия ступеней, исходы отбора, ключи
уникальности и индексы, — и каждый проверяется поимённо. Формы слова —
средство добыть носители найденного класса, а не способ найти класс.

## Свип по производным носителям

Правка кардинальности, предиката или инварианта имени не вводит, и текстовый
греп не находит ничего. Перечень: **сборщики контекста** (что и в каком
объёме загружается в проход); **исполнители-читатели** изменившейся
коллекции — предикаты под «ровно один» и клеймы «единственная строка»;
**предикаты-соседи того же поля** (write-once, единственное, непустое);
**schema-дельта** — ключи и индексы снятого инварианта; **клаузы «этого не
бывает»** — прежний инвариант мог быть доводом чужого решения. *(Кейс:
правка кардинальности `Position` дала восемь из десяти находок следующего
ревью — все непроведённые следствия.)*

## Проход по носителям с клеймом полноты

Клейм полноты («счёт цепочки N = N = N», «перечень закрытый») запрещает
читателю искать дальше, превращая пропуск в инструкцию. Клейм проверяется
**по объектам, а не по строкам**, и пересобирается из своего перечня: счёт
правится вместе с перечнем, из которого выведен. Проход идёт и по клеймам,
которых правка текстом не касалась, но чей предмет изменила: греп по
терминам правки их не находит. Форма счёта — порождённый блок либо
отсутствие клейма (`.claude/rules/self-description-form.md`).

## Прочие обязанности закрытия

- **Закрытие находки — по её собственному списку носителей.** Перечень
  берётся из находки, и каждый носитель получает исход: правлено / не
  требует правки — почему.
- **Правка политики идёт через её дом** (`.claude/rules/policy-home.md`):
  формулировка меняется в доме, указатели проверяются, пересказ вне дома
  сводится к ссылке той же правкой.
- **Отложенный хвост проверяется на сцепленность** с тем, что шаг
  поставляет: два хвоста, отложенных порознь, могут вместе обнулять
  вводимый сейчас guard.
- **Разведочный режим guard'а называет условие выхода и его носителя**;
  без него разведочный режим становится постоянным.
- **Ревизия used/unused инвентаря источника сверяется с правилом
  `Auditable`** (`docs/models/domain/other/Auditable.md`): поля времени
  создания и обновления в unused не выводятся.

## Чего правило НЕ означает

- **Не требует классификационной таблицы в отчёте.** Прежняя редакция
  требовала у каждого корпусного захода таблицу по всему словарю родов с
  маркером `(корпусный)` и мерила её энфорсером; форма снята вместе с
  доковой петлёй. Обязанности остались; предъявляются они свипами и их
  разбором в отчёте захода.
- **Не отменяет диспозиции находок.** Каждая находка ревью получает исход
  (`.claude/processes/roadmap-step-execution.md` §«`REVIEW`»); правило
  говорит, чем обязан заход, закрывающий её правкой корпуса.
- **Не ретро-размечает закрытое.** Отчёты закрытых шагов и `history/`
  описывают прошлое.

## Цена принята и названа

- **Род правки называет пишущий**, и прогона у этого нет: род, о котором
  заход не вспомнил, неотличим от рода, которого заход не играет. Компенсация
  — фокусы `REVIEW` читают дельту шага целиком.
- **Верность исхода в клетке не мерится** — только его наличие; верность
  читает критик.
- **«Указатель ведёт не к тому дому» механически не обнаруживается:** оба
  адреса разрешаются. Остаток держится дисциплиной пишущего.

## Что изменилось относительно v35

### `GAPS_CLOSE_3` — закрыты находки Н1, Н2, Н4, Н5, Н7

- **Н1 (идентичность хранения результатов).** Схема —
  **реестр конфигураций**: уникальная конфигурация (тип + `timeframe`
  + canonical-`params`) = строка реестра (`indicator_configs` /
  `market_structure_configs`) с `id`; результаты ссылаются на `config_id`;
  канонизация params — один раз при регистрации. Ключ результата
  `UNIQUE(instrument_id, config_id, candle_timestamp|window_end_at)`.
  Дополнен decision `market-data-result-identity-keying.md` (схема +
  отвергнутые inline/hash); поле `setting` → `config_id`, UNIQUE
  переписан в `IndicatorValue.md`, `MarketStructure.md`, `IndicatorJob.md`,
  `MarketStructureJob.md`, `market-data-calculation.md`. **`MarketPhase`
  не затронут** — ключуется контейнером-настройкой (у неё `id` есть).
- **Н2 (checkpoint).** Производный, не хранится: «докуда посчитано» =
  `max(timestamp)` по таблице результатов на инструмент + идентичность;
  «докуда считать» = время закрытия последней закрытой свечи в группе.
  Внесено в три job-дока + процесс.
- **Н4 (статусы для расчёта).** Считаем для **всех статусов кроме
  `DELETED`** (как в правиле свежести). Формулировки job-доков
  (`IndicatorJob`, `MarketStructureJob`, `MarketPhaseJob`) выровнены.
- **Н5 (история `MarketPhase`).** Хранится **история** — строка на
  свечу (`UNIQUE` по `candle_timestamp`), «актуальная фаза» = последняя
  по времени; не upsert. `MarketPhase.md` приведён.
- **Н7 (активационная проверка).** Не материализуется на шаге 3:
  владелец — по линии activate-валидации
  (`strategy-materialization-and-validation`), пункт про
  `InstrumentExternalRules` помечен отложенным. `market-data-calculation.md`
  §Активация.

### Калибровка принятия решений

- **«Второй взгляд» перед рестриктивным/узким закрытием находки**
  внесён в стойку обоих владельцев: (1) есть ли минимальное
  предусловие, при котором полная возможность корректна — ограничить,
  а не запрещать; (2) не прячет ли технический выбор продуктовую
  развилку — вынести пользователю, не решать молча.
- **Торговый рефлекс** (`trading-specialist`): «стабилизируй фиксацией
  системы отсчёта прежде чем запрещать». **Концепт-рефлекс**
  (`solution-designer`): «распознал скрытую продуктовую развилку → вынес
  scoped-вопросом пользователю».
- **Знание про OBV/шкало-старт-зависимые индикаторы** живёт как
  рассуждение роли в рефлексе `trading-specialist` (математическое
  свойство «предполагаю» + инженерная стабилизация), **не в дистилляте**:
  дистиллят — только дистилляция корпуса (тезисы с указателями
  книга+глава+страница), не-книжное туда не идёт. Книжный каталог
  объёмных индикаторов (Kaufman гл. 12) уже был в `strategy-patterns.md`
  §4 и не менялся. Сам запрет «дистиллят ← только корпус, не-книжное не
  идёт» закреплён явно в `.claude/rules/structure.md` (строка
  `distilled/`).

### Новая граница владения

- `docs/rules/trading-configuration-ownership.md`: стратегия владеет

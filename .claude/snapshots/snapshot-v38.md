## Главное решение (триггер переезда)

**Фаза рынка — авторские условия, не параметризованный алгоритм.**
Пользователь выбрал: автор стратегии пишет **правила определения**
`MarketPhase.Type` (как входные условия — операндами индикаторы /
структуры), параллельно тому, как устроен `StrategyCondition`. По
полученной фазе выбирается `StrategyDetail`; у детали — свои входные
условия создания сделки внутри этой фазы.

Это **замещает**:

- алгоритмическую часть проработки CC по Н3 (фаза/скоринг: двойной
  `trendScore`/`rangeScore`, классификация по порогам, `confidenceScore`
  как выигравший score);
- текущую модель `MarketPhaseParams` (`algorithmType` +
  `minTrendScore`/`minRangeScore`/`confirmationBars`).

Категория расхождения — **bucket-2** (по правилу «разбор сверки по трём
исходам»: исход 2 «Разошлось» — алгоритмический дизайн CC разошёлся с
условным замыслом пользователя; ответ пользователя не берётся как финал и
не адъюдицируется — диагностируем, чего не хватило CC, и проверяем
перепрогоном).

## Контекст разбора (для продолжения — `GAPS_CLOSE_4`)

**Где остановились:** на главной развилке по фазе (выше). Слепой проход
по находкам шёл, на фазе уперлись в фундаментальный пересмотр модели —
дальше нужен редизайн авторинга фазы, а не продолжение слепой сверки.

**Открыто на новый чат (первое, фундамент):** редизайн авторинга
`MarketPhase` под условия —

- как `StrategyMarketPhaseSetting` несёт правила определения фазы
  (параллельно `StrategyCondition`);
- судьба `MarketPhaseParams` (`algorithmType` / `minTrendScore` /
  `minRangeScore` / `confirmationBars` — вероятно убрать / переосмыслить);
- как `MarketPhaseJob` исполняет авторские правила (а не считает score
  по `algorithmType`);
- место `confidenceScore` при условной модели;
- как `MarketStructure` ссылается в правилах фазы (операнд структуры).

## Состояние находок `GAPS_CLOSE_4`

- **Н8** (retention результатов) — валидировано, вариант (A): не чистим
  до появления потребителя истории + якорь пересмотра. **На сейв.**
- **Н10** (ключевание `MarketPhase` контейнером) — валидировано, вариант
  (A): осознанное исключение из шаринга-по-идентичности (контейнер-ключ);
  основание — настройки фазы специфичны для стратегии и тянут меньше
  данных. **На сейв.**
- **Н6 точка отсчёта свежести** — валидировано: структура от
  `windowEndAt`, фаза от `candleTimestamp`; `confirmedAt` — гейт
  использования (без look-ahead), не точка отсчёта свежести. **На сейв.**
- **Н6 хвост `expiredAt`** — вывод CC (в основном из established):
  `expiredAt` — производная **на чтение**, не хранимая колонка, для всех
  трёх типов (`referencePoint + askingSetting.expirationDuration`);
  хранимое поле отвергнуто. Слепо не валидировалось (вывод установленный);
  **на сейв**. Fork D (материализовать для фазы, где конфликта нет) —
  крен «считать единообразно», малозначимо.
- **Н3 структура** — проработка CC (свинг-пивоты / кластеризация уровней
  по `minTouches` / тест диапазона-vs-тренда / пробой с буфером и
  подтверждением; ER как дискриминатор шума; `IndicatorValue` как
  шум-фильтр; `confirmedAt` no-look-ahead; доменный
  `MarketStructureAnalyzer`, job тонкий). Вероятно **выживает**
  (`MarketStructure` остаётся вычисляемым результатом, на который
  ссылаются правила фазы) — **проверить** против условной модели фазы.
- **Н3 фаза/скоринг** — **замещено** (см. главное решение). Forks **B**
  (модель score) и **C** (смысл `confirmationBars`) — **отпали** при
  условной фазе.
- **Fork A** (где живёт ER) — пользователь выбрал **вариант 2**: ER как
  индикатор каталога (максимум гибкости через стратегию). Расходится с
  креном CC (ER внутри аналитика) — **bucket-2**.

Проработка CC по Н3 + хвосту Н6 — в
`.claude/work/progress/phase-1-step-3-gaps-close-4-design.md` (staged):
полное торговое требование, арх-контракт job↔аналитик, развилки A-D с
кренами. Использовать как вход, с поправкой на замещение фазы.

## Решение-принцип на сейв

**Каталог индикаторов расширяем; новые индикаторы заводятся через
стратегию.** Подпирает fork A → вариант 2 (ER заводится как индикатор
каталога, а не прячется внутри аналитика).

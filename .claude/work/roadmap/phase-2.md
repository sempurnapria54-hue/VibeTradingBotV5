# Фаза 2. Торговля как сервисы одного тенанта

## На какой вопрос отвечает этот файл

В каком статусе каждый шаг Фазы 2.

## Назначение

Детальный роадмап Фазы 2. Главный роадмап —
`.claude/work/roadmap/roadmap.md`. Процесс исполнения шага —
`.claude/processes/roadmap-step-execution.md`. Скилл ведения прогресса —
`.claude/skills/update-roadmap-progress.md`. Целевая конструкция —
`docs/architecture/`.

Файл держит только таблицу статусов и живые примечания к будущим шагам.
Хроника текущего шага — `.claude/work/progress/phase-2-step-<M>-chronicle.md`.

## Цель фазы

Та же торговля одной стратегией, что умеет донор, — в форме продукта:
монорепозиторий, сервисы по целевым границам, один тенант-владелец,
кластер с GitOps и наблюдаемостью, ключи в Vault. Новой торговой
способности фаза не даёт; она даёт форму, из которой растут фазы 3-6.

## Шаги

| # | Шаг | Статус |
|---|---|---|
| 1 | Реструктуризация репозитория в монорепозиторий: донор в `donor/`, скелет сервисов, общих артефактов, фронта и манифестов, вторая ось размещения знания (`.claude/decisions/monorepo-restructuring-in-place.md`) | DONE |
| 2 | Платформа: Kubernetes, GitOps (CI хостинга репозитория на раннерах в кластере + Argo CD), операторы данных (Postgres+Timescale, Kafka, Vault, Elastic, Prometheus/Grafana, Jaeger), окружения `dev`/`stage`/`prod` как пространства имён | DONE |
| 3 | Общая доменная модель (`domain-model`): сущности, перечни, события и конверт; разведение площадки, тенанта и биржевого счёта | DONE |
| 4 | Авторизация: провайдер идентичности, `auth` (тенант, членства, реестр счетов, ключи в Vault), один тенант-владелец | DONE |
| 5 | Коннектор OKX: стейтлесс, ключи по идентификатору счёта, доменные запросы → общая модель, синхронная поверхность операций площадки (**публикации фактов в Kafka шаг не несёт: единственный её механизм у коннектора — WS-слушатель, а он припаркован по грунту**; опрос — механизм ЯДРА, шаг 7) | DONE |
| 6 | Рыночные данные: порт свечей/индикаторов/структуры/фазы, хранилище временных рядов, сбор невосполнимых срезов по листингу OKX, бэкфилл по требованию | DONE |
| 7 | Торговое ядро: порт сделок, FSM, команд, риск-гейта, холдов и аномалий; outbox; **наблюдение фактов исполнения опросом** (`REFRESH`-контур; потребитель `ExecutionObserved` приезжает со своим производителем — `.claude/work/backlog.md` §«WS-слушатель фактов исполнения»); торговое состояние счёта тенанта и риск-аппетит тенанта | DONE |
| 8 | Стратегии: определение как данные, валидация, жизненный цикл с активацией (до гейта фазы 4 активирует человек — гейт меняет актора, а не тропу), событие активации со снимком определения | DONE |
| 9 | BFF: проверка токена, контекст тенанта, агрегация, SSE живых данных | DONE |
| 10 | Аудит и статистика: один деплой, потребители событий, журнал по тенанту, агрегаты, read-only API | DONE |
| 11 | Раздел `audit-statistics` на `audit` и `statistics`: две единицы развёртывания с разной судьбой, каждая потребляет события сама | DONE |
| 12 | Тесты | CODE·3/3 |
| 13 | Фронт (простой, для прогонов) | HOLD |

Шаги 1-11 закрыты прежней машиной шага с доковой петлёй до кода (снята

## Примечания (будущие шаги)

- **Провайдер-специфичного в манифестах не пишется, пока провайдер не
  выбран** (`.claude/work/questions/open-questions.md` ARCH-Q1); форму
  развёртывания на стенде исполняет `tools/stand/deploy-services.sh`, а
  `Ingress` приезжает вместе с поверхностью
  (`docs/architecture/platform.md` §Безопасность).
- **Донор удалён 2026-09-16** вместе с контуром тестов API источника
  (`.claude/decisions/source-api-contour-retired.md`); пункт гейта закрытия фазы о его удалении снят досрочно. Инвентарь,
  по которому удаление проверено, — `.claude/work/history/2026-09-16-donor-inventory.md`.
- **Переякоренные условия** (`pre-launch-schema-changes`, автономия,
  второй субъект) — `.claude/decisions/roadmap-rebuild-for-service-platform.md`.
- **Шаг 12 («Тесты») — первый шаг новой машины.** Открыт 2026-09-15
  закрытием шага 11; концепция тестирования — держателя (чёрный ящик
  сервиса, юниты по критерию чистой логики, сквозные прогоны); её носитель
  — хроника шага `.claude/work/progress/phase-2-step-12-chronicle.md`
  §«Концепция», куда записан материал держателя от 2026-09-12. Ревью
  достаточности концепции дало **апрув** (2026-09-16,
  `.claude/work/progress/phase-2-step-12-concept-review.md`), и шаг вошёл в
  `CODE` — три фиксированных под-шага
  (`.claude/processes/roadmap-step-execution.md` §«Конец фазы»).
  Нагрузочные прогоны и генератор сбоев предметом шага не являются —
  парковка на конец фазы 6 (`.claude/work/backlog.md` §«Нагрузочные
  прогоны и генератор сбоев — конец фазы 6»).
- Под-шаги внутри `CODE` заранее не дробятся (кроме шага «Тесты»); они
  появляются в процессе исполнения.

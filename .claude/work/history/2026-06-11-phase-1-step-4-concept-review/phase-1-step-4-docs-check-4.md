## Находка К-1/Т-1 — amend trailing: концепция предлагает то, что биржа не исполняет

Единственная содержательная находка; обнажена новым биржевым фактом
**И-3** (прогон 3: `amend-algos` — только Stop/Trigger; standalone
`move_order_stop` **не амендится**).

- **Вопрос.** Несогласованность между доками: (1)
  `docs/models/mapping/AlgoOrder.md` §OKX request mapping —
  «для trailing биржевого amend нет (И-3): ремоделирование trailing —
  cancel + place, не amend»; но (2)
  `docs/components/AmendAlgoOrderExecutor.md` — payload
  `AmendAlgoOrderCommandPayload` несёт **`newTrailingPrice`**; (3)
  `docs/components/models/CalculatedPrice.md` — «`trailingPrice` ...
  если action создаёт/**меняет** trailing stop»; (4)
  `docs/models/domain/aggregate/Strategy.md` §StrategyAlgoOrderAction
  — `actionType=AMEND` допустим с `trailingSettings` (12 правил
  валидации типового ограничения не накладывают). Концепция
  предлагает амендный путь ремодела trailing-защиты, который для
  standalone algo на бирже неисполним. До И-3 несогласованности не
  было — её создал новый факт источника.
- **Ожидаемый владелец:** `solution-designer` (конструкция
  command/strategy-слоя); торговая грань — консультация
  `trading-specialist`.
- **Кто ответил + трассировка:** surface — `concept-review` (грепы
  trailing/amend по `docs/components/`, `docs/models/`); владелец —
  `solution-designer` (CC): открыл `AmendAlgoOrderExecutor.md`,
  `CreateAlgoOrderExecutor.md`, `CalculatedPrice.md`, `Strategy.md`
  §StrategyAlgoOrderAction/§валидация, `mapping/AlgoOrder.md` §Семья
  algo и §request mapping, `algo-order.md` §И-3 (owner-док биржевого
  факта); сверил: replace-flow в концепции уже есть
  («`AMEND_ALGO_ORDER` ≠ replace: replace-flow собирается отдельными
  атомарными командами вне executor'а»), т. е. модель **выражает**
  ремодел без аменда — несогласован только амендный аффорданс.
  Торговая грань — `trading-review` (дистиллят: риск позиции без
  защитного стопа).
- **Ответ (Предложение):** семантику `AMEND_ALGO_ORDER` для
  TRAILING_* надо явно закрыть в доках; варианты ниже.
- **Варианты:**
  - **(а) Запрет амендного пути для trailing на уровне концепции:**
    `AMEND_ALGO_ORDER` объявляется неприменимым к TRAILING_*
    (`newTrailingPrice` уходит из payload либо помечается
    неприменимым для standalone trailing); ремодел trailing —
    только replace-flow (cancel + place), который уже предусмотрен;
    Strategy-валидация дополняется правилом «AMEND-action не может
    целиться в TRAILING_*-CREATE» (или калькулятор транслирует).
  - **(б) Трансляция AMEND → replace-flow** в оркестрации (вне
    атомарного executor'а): авторский AMEND на trailing-цель
    разворачивается в cancel+place; требует проработки замены
    (владелец оркестрации — горизонт шага 6 FSM/handlers).
  - **(в) Оставить как есть** (executor шлёт amend, биржа отвечает
    `sCode != 0` → controlled error): торгово слепо — ремодел
    защиты молча не происходит; отвергается креном.
  - **Крен — (а) для шага 4** (дёшево, честно к биржевому факту,
    replace-flow уже есть в концепции) с дверью к (б) на шаге 6.
    Финализация — за пользователем на `GAPS_CLOSE_3`.
- **Торговая грань (Т-1, ведёт по тяжести):** ремодел trailing через
  cancel + place создаёт **окно без защиты** на плечевом перпе.
  Источник говорит: неограниченная ответственность без стопов →
  разорение при бесконечной игре с вероятностью → 1 [Vince,
  введение, с. 6 — дистиллят `risk-and-sizing.md` §7]; гэп может
  пройти все промежуточные уровни [там же]. Предполагаю (инженерное
  следствие): replace-последовательность должна минимизировать окно
  (порядок place-новой → cancel-старой против двойной защиты
  reduce-only — развилка реализации replace-flow, владелец — шаг
  своего внедрения; здесь не решается).
- **Целевой док:** `AmendAlgoOrderExecutor.md` (payload),
  `CalculatedPrice.md` (формулировка «меняет»), `Strategy.md`
  (§StrategyAlgoOrderAction / валидация), `mapping/AlgoOrder.md`

  `GAPS_CLOSE_3`.
- **Ярлык исхода:** `варианты-с-креном`.
- **Ярлык дефицита:** — (владелец ответ дал; финализация — ступень,
  не дефицит).

## Не-гейтящие заметки

1. **`partially_failed` — defensive-ветка при дрейфе офдока.**
   Текущий офдок больше не документирует это значение `state`
   (дрейф зафиксирован: `algo-order.md`, манифест), но
   resolver/lifecycle/DTO-доки (`AlgoOrderExternalStatusResolver`,
   `lifecycles/AlgoOrder.md`, `OkxAlgoOrderResponse.md`) держат его
   как обрабатываемое сырое состояние → `ExternalStatusException`.
   Не противоречие: дрейф документации ≠ удаление из рантайма;
   защитная ветка сознательно остаётся. Снять/подтвердить — при
   будущей сверке источника.
2. **Cancel-ответ advance-ветки** текущим офдоком не специфицирован
   (часть И-2; в контракте помечено «форма исторически та же») —
   подтверждается той же runtime-проверкой, что и И-2.
3. **Прежние CODE-level заметки** `DOCS_CHECK_2/3` без изменений:
   рёбра `SKIPPED` lifecycle `DealActionState`; `maxAttempts` на
   `Retryable` vs политика.

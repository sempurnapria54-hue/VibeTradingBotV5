## Среда

Против v132 не изменилась; полное описание — там. Ловушки среды из v156-v187
остаются в силе, включая: полный гейт инструментов в 120 с не укладывается —
прогонять фоновой командой (`tools/spec-mutation-check.sh` один держит
несколько минут); рабочий бинарь — `py`; в regex-шаблонах для
`tools/retired-check.py` пользоваться `\s+`; форма `py - <<'PYEOF'` рвётся на
длинном markdown с таблицами — большой раздел писать инструментом записи;
вывод `py` через пайп идёт в cp1251 и рвётся на кириллице (`export
PYTHONIOENCODING=utf-8`); перед всяким `-P`-прогоном ставить
`export LC_ALL=C.UTF-8`; файл журнала фоновой команды писать в `$TEMP`;
искать по слову со знаком ударения нельзя буквально; точная подстановка
проверяется счётом вхождений до записи.

**Ловушки этой сессии (новые):**

- **`io.open(p, 'w')` на Windows пишет CRLF, а репозиторий держит LF.**
  Файл, записанный так, уезжает в рабочее дерево с чужими концами строк:
  `git` печатает «CRLF will be replaced by LF», а IDEA показывает файл
  целиком изменённым. Записывать с `newline='\n'` либо нормализовать
  побайтно после правки.
- **Обратная косая в теле `py - <<'PYEOF'` до Python не доезжает целой.**
  Строка вида `'... \\'` внутри heredoc превращается в `'... \'` и роняет
  разбор. Собирать такие литералы через `chr(92)` либо писать скрипт
  файлом.
- **Ассерт `count == 1` до первой записи спасает не только от промаха, но и
  от частичной записи.** Приземление узла собирало все тринадцать целей и
  падало бы целиком, не тронув ни одного файла; две правки прошлых единиц
  ловились этим же ассертом на выпавшем слове внутри переноса.

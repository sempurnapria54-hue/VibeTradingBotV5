## Среда

Против v132 не изменилась; полное описание — там. Ловушки среды из v156-v190
остаются в силе, включая: полный гейт инструментов в 120 с не укладывается —
прогонять фоновой командой (`tools/spec-mutation-check.sh` один держит
несколько минут); рабочий бинарь — `py`; в regex-шаблонах для
`tools/retired-check.py` пользоваться `\s+` и делать их терпимыми к разметке;
вывод `py` через пайп идёт в cp1251 и рвётся на кириллице (`export
PYTHONIOENCODING=utf-8`); перед всяким `-P`-прогоном ставить
`export LC_ALL=C.UTF-8`; `\w` у `grep -P` кириллицы не берёт — классы писать
явно (`[а-яё]+`); файл журнала фоновой команды писать в `$TEMP`;
многострочная правка целится в текст **с его отступом**; точная подстановка
проверяется счётом вхождений до записи; спека, переписанная разбором-сборкой
JSON, теряет отступ корпуса — править точечной подстановкой.

**Ловушки этой сессии (новые):**

- **Heredoc `py - <<'PY'` рвётся, когда внутри тела есть строка `PY`** —
  а она там есть всегда, если тело цитирует другую команду с тем же
  разделителем. Внешний разделитель обязан отличаться (`PYEOF`), либо правку
  делать инструментом записи. Тот же класс, что уже записан про длинный
  markdown с таблицами.
- **Строка захода помечается `записан` ПОСЛЕДНЕЙ, после раздела, на который
  она указывает.** `edit-kind-check` спрашивает классификацию только у
  захода, чья строка уже записана, — значит дефект классификации (пустая
  клетка исхода) невидим ровно до того момента, как строку пометили. Гейт,
  прогнанный до простановки, зелен и ничего не удостоверяет.
- **§-адрес в клетке таблицы обязан называть файл в той же клетке.**
  `anchor-check` разрешает адрес по файлу, названному в том же абзаце, иначе
  по своему; строка дайджеста без имени носителя роняет прогон.

**Что форма захода уже включает** (не выводить заново):

- метка своей дельты отбивается **до первой правки** (`git write-tree`);
- механические оси мерятся разбором документа: четыре поля у каждого кейса,
  существование путей-носителей, **существование имён величин спек и имён
  секций бэклога** (разбор JSON и заголовков — обе оси добавлены этим заходом),
  разрешимость §-адресов (`py tools/anchor-check.py`);
- каждый перечень дома — операции поверхности, тики, ветви отказа, классы
  события, классы отказа, конъюнкты предикатов, компоненты содержимого —
  **перебирается поимённо**, и непокрытая единица уходит меткой `G` в раздел
  «Пробелы покрытия» документа;
- ожидание, у которого дом молчит либо код с домом разошёлся, помечается
  формой «по дому / сегодня», а разрыв уходит находкой `F` с секцией бэклога;
- **находка, уже припаркованная предыдущим предметом, новой секции не
  заводит** — существующая расширяется вторым носителем (`.claude/rules/policy-home.md`);
- отчёт несёт таблицу самопроверки автора по критерию
  (`.claude/skills/test-design.md`).

**Три класса, найденные у ВСЕХ СЕМИ предметов и стоящие проверки у каждого
следующего:**

1. **Пиньнутое HTTP-число, которого не фиксирует ни один дом.** Признак
   механический: число пишет **наш** код (ветвь обработчика либо место броска)
   — ожидание берёт класс, а где класс один на все поводы, то пару «класс плюс
   то, чем повод различается у самого сервиса». Число пишет контейнер, точка
   входа контура либо контракт успеха — остаётся числом. **`@ApiResponses`
   домом числа не является** — это второй носитель того же числа, уезжающий
   вместе с обработчиком.
2. **Элемент перечня без писателя либо без читателя.** Ловится перебором
   ветвей и значений поимённо против грепа по дереву сервиса.
3. **Ожидание, взятое из дома либо javadoc, которое код не несёт.** Ловится
   чтением исполнителя; javadoc — такой же носитель ожидания, и сверяется он с
   кодом, а не принимается на веру.

**Четвёртый класс добавлен этим заходом:** **ожидание, истинное лишь на части
описанного предусловия.** Признак — у исполнителя есть охрана либо ветвление,
которое на описанном состоянии может не сработать; тогда красный прогон не
различает предмет кейса и срабатывание охраны. Ловится чтением исполнителя
**вместе** с предусловием, а не по отдельности.

**Исходники читаются прямо из `services/**`** — распаковка нужна только для
библиотек; каталог распаковки заводится **внутри репозитория** и удаляется до
гейта (§Ловушки).

## Ловушки

**Ловушки** v206-v314 остаются в силе. Подтверждено этой сессией:

- **Длинные кириллические правки корпуса подаются Edit'ом либо
  скриптом-файлом** — с проверкой единственности каждой подстроки, — а не
  heredoc'ом через `bash`: heredoc с длинным кириллическим телом рвётся
  непредсказуемо. Короткий `py - <<'PY'`-скрипт с разбором файла (счёт кейсов,
  проверка путей, сверка имён величин спек) работает надёжно и следа не
  оставляет.
- **Сверка имён спек регуляркой по клетке таблицы даёт ложные срабатывания:**
  клетка называет два файла спек подряд, и имя из второго приписывается
  первому. Читать надо вхождение «файл → его величины» в пределах одного
  сегмента клетки, а неразрешённое — глазом.
- **`cd` внутрь дерева кода меняет рабочий каталог сессии** — следующая команда
  стартует уже оттуда; пути в командах гейта задаются от корня репозитория.
- Прочие ловушки — снапшоты v283, v285-v314 §Ловушки; они не переписываются.

Обязательное перед завершением любой единицы:

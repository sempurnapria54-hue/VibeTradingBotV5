## Путь к точке (от v51)

v51 оставил тщательный план + коллекцию **«на аппрув»** в модели
**типизированный A2-passthrough** (manifest ∩ клиент: 21 метод, 112
запросов, per-endpoint типизированные проксиметоды + `*OkxResponse`).
С тех пор (эта сессия) модель **переосмыслена** и доведена до аппрува:

1. **Универсальный `dispatch` + `/raw`-only.** Спроектирован публичный
   обобщённый `dispatch` в `OkxRestClient` (три потребителя: продукт
   через типизированные методы, код-тесты и Postman — через `/raw`).
   Контур сведён к **единственному** generic-эндпоинту
   `POST /api/proxy/okx/raw` + **JsonNode** (типизированных проксиметодов
   и `*OkxResponse` в контуре больше нет).
2. **Принцип «контур проверяет контракт биржи, не наш код».** Мапперы/
   DTO/сериализация — наш код, вне scope контура. Отсюда `/raw`-only +
   JsonNode.
3. **Охват расширен с `∩ клиент` на полный in-perimeter** (60
   эндпоинтов): client-coverage-gap'ы (нет метода клиента) и прежде
   заблокированные негативы (сырой битый `ordType`, `callbackSpread`,
   all-ccy `getBalance`) достижимы через `/raw` (тело руками по
   контракту). Прежних вариант-gap'ов из-за типизации прокси **нет**.
4. **Регенерация план+коллекция** под `/raw`-only (60 эндпоинтов: CORE
   M1-M21, TG1-9, AG1-12, MG1-10, PG1-8) — параллельной генерацией по
   группам + сборка, строгий изоморфизм.
5. **§Нерешённое 1-4 закрыты** и вшиты в план (см. ниже).
6. **Два независимых адверсариальных ревью** (свежий глаз каждый раз):
   1-е — REQUEST-CHANGES (MAJOR: необъявленные переменные коллекции →
   пустой `sz` на write; + TG7/precheck, изоморфизм M17.4, cross-chain
   зависимости) → исправлено; 2-е — APPROVE-with-fixes (3 MINOR + 2 NIT:
   утечка stray-id в teardown, выдуманный `51603` в плане, dup-цепочки
   не самодостаточны, имена teardown переобещали A0-close) → исправлено.

## Принципы, зафиксированные в сессии

- **Контур проверяет контракт биржи OKX, не наш код.** Мапперы/DTO/
  сериализация — вне scope (их проверка — отдельные юнит-тесты).
- **`/raw`-only универсальный dispatch.** Один подписанный эндпоинт-
  конверт; типизированные методы клиента — деталь продукта.
- **Инвариант восстановления состояния кейса.** Каждый stateful-кейс:
  Snapshot.start → restore → Verify.end (`конец == старт`, через
  wait-until-condition). **В охвате** (проверяется, фейлит кейс):
  настройки (`leverage`/`posMode`/`acctLv`) + сущности (ордера/позиции/
  algo). **Вне инварианта** (наблюдаются, не фейлят): append-only
  история (растёт), комиссионный/PnL-остаток баланса после реального
  fill. Невозврат настройки → находка.
- **Цель контура — интегратор понимает и документирует реальное
  поведение OKX** (наблюдение → находка C3). Регрессия-детект
  (периодический прогон) — следствие, **явно не фиксируется** как цель.
- **Структурный изоморфизм план ↔ коллекция ↔ тесты** (эндпоинт→раздел/
  папка/класс; кейс→подраздел+таблица/запрос-или-подпапка/метод;
  запрос→строка/request/шаг).

## Следующая фаза — CODE (задача нового чата)

1. **Универсальный `dispatch`** в `OkxRestClient` — публичный обобщённый
   `<R> R dispatch(method, path, query, body, signed, responseType)`;
   типизированные методы клиента делегируют в него (→ не dead-код);
   `getAccountConfig` растворяется (String-токен).
2. **Generic-эндпоинт `POST /api/proxy/okx/raw`** на `OkxProxyController`
   поверх dispatch (конверт → `OkxApiResponse<JsonNode>`); гейт
   `@Profile("!prod")` (тест-обращённая выдача шлёт write'ы).
3. **Снести unused типизированные проксиметоды** `OkxProxyController` до
   `/raw` (codestyle §«Неиспользуемый код»). **Типизированные методы
   `OkxRestClient` остаются** — ими пользуется продукт.
4. **Код-тесты** (`test-code`): бьют в тот же `/raw` (1:1 с коллекцией),
   класс на метод / тест на кейс, бланк отчёта = таблицы плана.
   **Строгий wait-until-condition (поллинг) и restore-verify живут
   здесь**; коллекция — best-effort (одношаговые ассерты). A0-фикстура
   (условный open/close при reduce-only без позиции) — тоже код-тесты.
5. **RUN** → наблюдения (точные коды негатива, поведение восстановления,
   И-2 `cancel-advance-algos`) → **C3 apidoc-sync** (`integrator`,
   владелец интеграции). Фаза 3 prod — вне контура (ад-хок пользователем).

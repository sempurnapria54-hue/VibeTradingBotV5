## Что изменилось относительно v33

### Разбор Э2: диагноз

- **Мисатрибуция в К1** (исправлена прошлым заходом): утверждение
  «для `DELETED` новые значения не считаются» было атрибутировано
  `market-data-freshness.md`, где его нет; реальные источники —
  `IndicatorJob.md` §Идемпотентность и `market-data-calculation.md`
  §Условия запуска (последний сам несёт битую ссылку на правило
  свежести). Единственный реальный дефект ревьюера — **верификация
  цитат**: внутридоковая кросс-ссылка перенесена как факт без
  открытия целевого дока.
- **Существо Э2** («по каким статусам jobs считают») оказалось
  выводимым из `lifecycles/Strategy.md` — контраст `DELETED`
  («Новые расчёты и сделки по ней не запускаются») vs `INACTIVE`
  («Блокирует **только** новые сделки»). Это **реконсиляция доков,
  не пользовательский выбор** — до пользователя дойти не должно
  было.
- **Корневой дефект — не в агенте, а в разводке процесса:**
  эскалации `concept-review` шли пользователю напрямую, минуя
  владельцев (модель делегирования существовала отдельно от
  ревью-петли); отчёт не нёс данных для трассировки — из него не
  было видно, что именно агент проверил (незаход ревьюера в
  `lifecycles/Strategy.md` по Э2 из отчёта не читался).

### Правки пайплайна (`.claude/skills/concept-review.md`)

1. **Верификация атрибуции источника** (новый раздел): цитируемый
   док открывается и клауза находится; кросс-ссылка не переносится
   как факт; битая кросс-ссылка — сама по себе находка.
2. **Эскалация — через владельцев** (first-cut, обкатка со
   следующего прогона): surface-вопрос со штатным владельцем по
   карте делегирования маршрутизируется владельцу
   (ревьюер↔владелец итерируют); открытый вопрос — только fallback,
   если владелец не разрешил; пользователю — product/policy-остаток
   по ступени автономии. Сшивка `concept-review` ↔
   `question-delegation.md`.
3. **Отчёт несёт трассировку эскалаций**: по каждой эскалации — кто
   surface-ил, что проверил (в т.ч. сверка с owner-доком),
   заключение; варианты; крен+обоснование либо «крена нет»; при
   маршрутизации — работа владельца и исход (разрешено / варианты /
   fallback в открытый вопрос).

### Три правила чата формализованы

`.claude/rules/chat-project-instructions.md`, раздел «Поведение»
(после «Делегирования развилок по владельцам»):

- **Разбор эскалаций/делегированного — с трассировкой агентов**;
- **Отладка решения — сначала дефицит, потом ответ**;
- **Эскалации — чинить агента, а не решать за него** (контур:
  диагностировать дефицит → дообучить агента/процесс →
  перезапустить; ручное решение — крайний случай).

Источник правды — Settings → Custom Instructions: после коммита
текст вставить туда (рассинхрон до вставки).

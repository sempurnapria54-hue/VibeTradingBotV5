## Ловушки

**Ловушки** v206-v284 остаются в силе. Подтверждённые этой сессией и новые:

- **Умолчания библиотеки читаются из её исходников, а не из описания
  среды.** Клиент хранилища при пустом `uri` собирает адрес из трёх свойств,
  и **схема** среди них несущая; адрес, взятый из файла о машине держателя,
  совпал по хосту и порту и разошёлся по схеме — то есть ожидание оказалось
  истинным по построению. Sources-jar'ы лежат в локальном репозитории
  (`~/.m2/repository/**/*-sources.jar`) и распаковываются `unzip`.
- **`py` не видит путей Git Bash.** `/tmp/файл`, записанный из bash, для
  `py` не существует — временный файл кладётся в рабочий каталог.
- **Отрицательное ожидание требует названного наблюдателя** — это
  воспроизводящийся класс: заход, снявший его в двух кейсах, завёл третий с
  тем же дефектом.
- **`grep -P` без `-z` через перенос строки не берёт** — и выдача читается
  как чистый свип. Форма свипа — `grep -rlUzP '(?s)…'`, и проверять её надо
  на заведомо существующем вхождении. (Условия `греп` в маркерах бэклога
  этой ловушки не имеют: `tools/backlog-check.py` читает файл целиком с
  `re.S`.)
- **У полей маркера бэклога альтернативы через `|` срабатывают ЛЮБАЯ**, и
  сам символ разбирается как разделитель условий: регулярного выражения с
  альтернацией в условии не бывает вовсе. Двум носителям — две секции.
- **§-адрес с вложенными кавычками «…» битый по построению** — заголовок
  секции, на которую будут ссылаться, кавычек внутри не несёт.
- **`python` в этой среде исполняет заглушку Windows Store**; зовётся `py`.
- **Ревью кейсов обязано читать КОД предмета, а не только его доки.**
- **Javadoc — такой же носитель снятой редакции, как док.**
- **`§«…»` в `docs/**` ни одним прогоном не мерится** — область
  `anchor-check.py` ограничена `.claude/**`.
- **Строка таблицы, начинающаяся словом `Итого`, попадает под сверку
  `self-count-check.py`** — в отчёте её пишут только там, где сумма
  действительно выводится по колонке.
- Прочие ловушки — снапшот v283 §Ловушки; они не переписываются.

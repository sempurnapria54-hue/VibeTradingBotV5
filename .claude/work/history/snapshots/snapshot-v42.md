## Костяная развилка R1 vs D (выбор за пользователем, НЕ финализирован)

Обе **полностью чинят STRUCT-Q2** (id-коллизия шаримого результата при
разных ER/ATR-ключах на одинаковых `timeframe+params`). Выбор — cost/benefit
+ ставка на будущее, не корректность.

- **R1 — ER/ATR в идентичность структуры.** Resolved ER/ATR config_id
  входит в `config_id` структуры; шаринг сохраняется, идентичность полна по
  построению. Блет-радиус **узкий** (~6-8 файлов, только структура).
  Стационарно **сложнее** (богаче идентичность; read тянет sibling-config_id).
  Сохраняет раскол ключевания «фаза по контейнеру vs индикатор/структура по
  config_id». Частичный откат fork-A (вход не свободная soft-ссылка).
- **D — перестать шарить.** Каждый результат ключуется
  настройкой-владельцем (контейнер+`key`), для **всех** видов; реестры
  конфигов и дедуп уходят. ≈ «сделать индикаторы и структуру такими же, как
  `MarketPhase`». Блет-радиус **широкий** (~25-30 файлов, удаление реестров +
  переписка ключевания). Стационарно **проще** (одна модель ключевания, нет
  канонизации). **Снимает раскол** ключевания — `MarketPhase` перестаёт быть
  осознанным исключением (когерентный плюс). Теряет compute-once шаринг
  (фаза-1 выгода ~ноль; фаза-3 окупалась бы — вернуть кэшом при нужде).

**Крен CC:** через линзу когерентности + YAGNI — **D** защитим (растворяет
корень повторяющейся путаницы про разное ключевание), при принятии трёх
цен: (1) D-ключ требует составного handle для id-less JSONB-листьев
(контейнер-строка + `setting_key`, либо вернуть листам стабильный id);
(2) это удаление работающего кода; (3) кэш-слой шаринга — отдельный заход
фазы-3. **R1** — если важнее минимум churn и сохранить фаза-3-оптимизацию
на месте. Пользователь клонит к **D**; R1 остаётся на столе (его более
ранний выбор).

Прежний интерим **B** (запрет на create-валидации) — субсумирован: и R1, и
D закрывают достижимость полностью, отдельный гард не нужен.

## Ответы на код-вопросы (проверено по коду)

1. **`StrategyMarketPhaseRule.level` — только сортировка в классификаторе**
   (`MarketPhaseClassifier.java:37` `.sorted(comparing(getLevel))`). Прочие
   `getLevel`/`setLevel` — другие сущности (`setLevels` структуры,
   `StrategyAction.getLevel`). Убрать `level` → правится один метод
   (итерировать List по позиции) + поле + api + валидатор + пример + доки.
2. **Контейнерный `timeframe` — нужен как якорь, не каденс.** Джоб тикает по
   CRON (`@Scheduled(cron=...)`); `timeframe` лишь выбирает группу свечей →
   `candleTimestamp` = ключ идемпотентности (`findCheckpoint`) +
   `referencePoint` свежести. Оставить; **переименовать** (омоним с листовым
   `timeframe`): `anchorTimeframe`/`classificationTimeframe`. У фазы своей
   расчётной серии нет — поле чисто «часы as-of».
3. **Срок на рул — резолвить при классификации, запекать на результат.**
   `MarketPhase` хранит `type+confirmed_at`, не клаузу; несколько клауз →
   один `Type` → на чтении неоднозначно. Фикс: классификатор знает
   сработавшую клаузу → возвращает её `expirationDuration`, джоб пишет на
   `MarketPhase` (новое поле/колонка `expiration_duration`); чтение берёт
   срок С результата (у фазы один спрашивающий). `UNKNOWN` (нет матча) →
   контейнерный `defaultExpirationDuration`.
4. **Цена D — большая (см. развилку).** Шаринг держится на реестрах
   (`config_id` на записи `IndicatorJob:95`/`MarketStructureJob:113` и
   чтении `IndicatorService:34`/`MarketStructureService:33`). D их сносит.
   **Контр-интуитивно:** для *lookup* самодостаточен текущий дизайн (лист →
   config_id сам); под D лист в одиночку результат не находит (нужен
   контейнер — но он всегда в области видимости на чтении). Гипотеза
   пользователя — про *владение результатом* (нет сцепленной строки), и его
   D даёт.

## Переработанная `StrategyMarketPhaseSetting` (целевая, под выбор)

- `anchorTimeframe: TimeFrame` (ренейм `timeframe`; якорь as-of, не каденс).
- `phaseRules: List<StrategyMarketPhaseRule>` (List сохраняется).
- `indicatorSettings` / `marketStructureSettings` — **key-ref списки, не
  inline** (объявить раз в контейнере; держится и при D — одна настройка →
  одна строка результата; на уровне детали key-ref обязателен — действия
  ссылаются на индикаторы/структуры по `key`).
- `defaultExpirationDuration: Duration` — только ветка `UNKNOWN`.
- `StrategyMarketPhaseRule`: **−`level`** (порядок = позиция),
  **+`expirationDuration`** (срок этой фазы), `type`, `condition`.
- `MarketPhase`: **+`expirationDuration`** (запекается классификатором;
  `referencePoint = candleTimestamp` как сейчас).

## Линза когерентности

Корень повторяющейся путаницы `StrategyMarketPhaseSetting` ↔
`StrategyMarketStructureSetting` — омонимы уровень×поле (`timeframe`,
`expirationDuration` значат разное на контейнере и листе) + раскол двух
моделей ключевания. Чистка п.2/3 снимает омонимы; **D** снимает раскол
ключевания (R1 — нет). Отдельную доку «идентичность/каденс/свежесть» писать
не обязались — линза как проверка связности.

## Что сделано после v336

Одна единица: **письмо документа кейсов `trading-core-calc`** — четвёртый из
шести новых предметов уровня 2. Отчёт передачи —
`.claude/work/progress/phase-2-step-12-hand-test-trading-core-calc.md`.
Здесь — только то, что меняет картину для следующей сессии.

- **Новая ось формы: кейс уровня 2 мерит РЕАЛИЗАЦИЮ формы, а не саму форму.**
  У четырёх единиц из шести дом ожидания — исполнимая спека со своими
  примерами, и прогон спеки исполняет **выражения спеки**, кода не открывая
  вовсе: расхождение реализации с формой ему невидимо по построению. Кейс,
  чьё ожидание уже сформулировано примером, называет пример поимённо и мерит
  класс; кейс на состоянии, которого у спеки нет, — собственный.
- **Ось оправдалась немедленно: три находки из пяти — прямые расхождения
  кода с исполнимой формой.** Различитель гранулярности комиссии считается
  по области, из которой уже вычтен список исключений площадки, а спека
  ставит его на непрореженные строки и держит ровно этот пример; пустая сумма
  движения читается нулём там, где спека **отказывает** арифметикой, и клейм
  исполняет обязательность колонки, а не код; охрана полноты графа читает
  пустое значение **противоположно** у двух писателей одного терминального
  ребра, хотя операнд спеки объявляет её симметричной.
- **Две прочие находки — о пустоте и о моменте.** Пустой статус родителя у
  публичного гейта цикла добычи охранён явно, а у резолва роняет
  разыменование — один класс, два входа, один вызывающий. Журнальные отчёты
  признаков пишутся транзакцией вызывающего, а клейм «терминал отчётом не
  блокируется» держится ловушкой, не покрывающей момент записи.
- **Популяция выведена двумя входами, и второй дал три единицы, которых
  реестр кандидатов не выделяет:** писателей трёх чисел допуска и признака
  режима (два разных класса свойств), писателя контроля валюты с его **тремя**
  исходами и момент журнального отчёта, у которого механизма в коде нет.

## Ловушки

**Ловушки** v206-v336 остаются в силе. Подтверждено и дополнено этой сессией:

- **Heredoc `bash` рвётся на обратных кавычках в теле.** Тело с блоками
  ```` ```bash ```` и `код в кавычках` даёт «unexpected EOF while looking for
  matching `'`» даже при закавыченном ограничителе. Рабочая форма для
  длинного русского markdown с кавычками — писать части файлом и склеивать
  `cat`, а точечную правку делать через `py -` с `assert s.count(a)==1`.
- **Якорь точечной правки берётся из файла, а не из памяти.** Подмена,
  собранная пересказом соседнего абзаца, не совпадает, и `assert` её
  отбивает — это и есть польза формы; экономия на чтении якоря стои́т одного
  лишнего прогона.
- **Счёт кейсов шаблоном `^| U<n>.<m> ` двои́т** — перекрёстные таблицы
  повторяют метку в первой колонке. Верное число даёт `| sort -u | wc -l`.
- Прочие ловушки — снапшоты v283, v285-v336 §Ловушки; они не переписываются.

## Среда

Против v132 не изменилась; полное описание — там. Ловушки среды из v156-v188
остаются в силе, включая: полный гейт инструментов в 120 с не укладывается —
прогонять фоновой командой (`tools/spec-mutation-check.sh` один держит
несколько минут); рабочий бинарь — `py`; в regex-шаблонах для
`tools/retired-check.py` пользоваться `\s+`; форма `py - <<'PYEOF'` рвётся на
длинном markdown с таблицами — большой раздел писать инструментом записи;
вывод `py` через пайп идёт в cp1251 и рвётся на кириллице (`export
PYTHONIOENCODING=utf-8`); перед всяким `-P`-прогоном ставить
`export LC_ALL=C.UTF-8`; файл журнала фоновой команды писать в `$TEMP`;
искать по слову со знаком ударения нельзя буквально; точная подстановка
проверяется счётом вхождений до записи; писать файлы с `newline='\n'`.

**Ловушки этой сессии (новые):**

- **Многострочная правка целится в текст С ЕГО ОТСТУПОМ.** Строки-продолжения
  буллета несут два ведущих пробела, и якорь, списанный «как читается», не
  находит цели ни разу. Глазами это неотличимо — ловится только ассертом
  `count == 1` до первой записи. Один якорь из восемнадцати промахнулся
  именно так.
- **Скрипт правки писать файлом в `tools/` и удалять после прогона.** Даже
  вариант «heredoc покороче» рвётся, когда в теле лежат кириллические
  markdown-блоки с обратными кавычками и кавычками-ёлочками.
- **Отчёт корпусного захода живёт РАЗДЕЛОМ отчёта единицы, а не соседним
  файлом.** `py tools/edit-kind-check.py` ищет таблицу классификации в
  разделе, который называет строка таблицы заходов, и ищет его **в том же
  файле**: вынесенное приземление даёт дефект «нет таблицы классификации»
  при полностью написанной классификации.
- **`grep -oUzP` с якорем `^` без флага `(?m)` не находит ничего:** при `-z`
  файл читается одной строкой, и `^` совпадает только с её началом. Для
  построчных шаблонов через перенос нужен `(?sm)`.

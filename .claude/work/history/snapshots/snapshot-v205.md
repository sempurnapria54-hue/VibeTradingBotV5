## Среда

Против v132 не изменилась; полное описание — там. Ловушки среды из v156-v204
остаются в силе, включая: полный гейт инструментов в 120 с не укладывается —
прогонять фоновой командой; рабочий бинарь — `py`; вывод `py` через пайп идёт в
cp1251 и рвётся на кириллице (`export PYTHONIOENCODING=utf-8`); перед всяким
`-P`-прогоном ставить `export LC_ALL=C.UTF-8`; длинный кириллический heredoc в
Bash рвётся — правки корпуса писать временным `.py`-файлом либо инструментом
записи файла; точечный прогон модуля идёт **из корня** (`-pl`), а не через `-f`;
`docker` под Git Bash требует `export MSYS_NO_PATHCONV=1`; `cd` внутри составной
команды Bash переносит рабочий каталог сессии.

**Ловушки этой сессии.**

- **`/tmp` у Git Bash и у `py` — РАЗНЫЕ каталоги.** `cp x /tmp/y` из Bash кладёт
  файл в `%LOCALAPPDATA%\\Temp`, а `open('/tmp/y')` из `py` ищет `C:\\tmp\\y` и не
  находит. Передавать между ними только windows-путь (`cygpath -w`).
- **`json.dump` в файл, открытый без `newline=''`, переписывает ВЕСЬ файл** на
  CRLF: диффом это 1255 строк вместо одной. Точечная правка JSON — заменой
  подстроки в тексте, а не пере-сериализацией.
- **Инструмент записи файла перезаписывает существующий молча.** Отчёт
  четвёртого захода был снесён отчётом десятого, потому что имена совпали
  (`code-pass-k4`); восстановлен из индекса (`git show :<путь>`). Перед записью
  нового отчёта — смотреть, занято ли имя.
- **`-Dtest=...` требует `-Dsurefire.failIfNoSpecifiedTests=false`**, а не
  `-DfailIfNoSpecifiedTests=false`: без первого прогон падает на модуле, у
  которого нет ни одного подходящего теста (`domain-model`).
- **Точечный прогон `audit-statistics` теперь требует `-am`:** модуль зависит от
  общего артефакта, а тот в локальном репозитории не установлен.

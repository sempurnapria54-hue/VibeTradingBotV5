## Контекст разбора (только у чата — НЕ свалидировано)

### Узел 1 (H1-H10) — реакция и тропа холда по несвежести. Разобран целиком

Сквозное решение: реакция на несвежесть ставки — **мягкая**,
kill-switch по несвежести **снят**.

- **(а) Реакция** — запрет новых входов по инструментам протухшей
  группы + `AnomalyReport`; живые сделки доживают под своим стопом.
- **(б) Блок-сет** — холд режет **создание нового риска**;
  сопровождение открытых сделок (защита, трейлинг, reduce-only выход,
  закрытие) разрешено. Граница «создание нового vs сопровождение
  существующего» сажается на `risk-validator-scope`
  (risk-creating/increasing блокируется, остальное по живой сделке
  проходит).
- **(в) Обнаружение и решение разведены по двум джобам:**
  `SyncJob` (бывшая `InstrumentExternalRulesSyncJob`) — **только
  синкает данные**, решений не принимает, режимов отказа не знает
  (упал вызов — просто не обновила метку). **Новая `AnomalyJob`** —
  смотрит возраст последнего обновления (и прочие аномалии биржи),
  инициирует холд **напрямую** статусом `Instrument.Status = HOLD`
  (deal-less, без kill-switch-аппарата и сделки-триггера) +
  `AnomalyReport`. Снятие холда — **вручную**; автоснятия по
  успешному синку **нет** — заявлено явно, чтобы следующий прогон не
  «оптимизировал». Блокировку входов обеспечивает gatekeeper на
  создании сделки, читающий статус → цепляет **H10** (проверка
  `Status == HOLD` в единственном создателе сделок должна
  существовать реально).
- **(г) `AnomalyJob` меряет возраст per-group**, холдит инструменты
  групп, чей возраст превысил порог. «Синк лёг целиком → все группы
  протухли → весь контур встал» — **истинный радиус** (данных нет ни
  по одной группе), не артефакт склейки, как было в H4.

Следствия: **H8 испаряется по построению** (оценщик возраста —
отдельная джоба, не глохнет с выключенным синком); **H7** (эскалация
L3→биржа) снимается вместе с kill-switch по несвежести.

### H6 + H13 — scope-енум (разобраны вместе)

- `HoldScope` = {`INSTRUMENT`, **`INSTRUMENT_GROUP`** (новый радиус
  между инструментом и биржей), `EXCHANGE`} — **чистые радиусы без
  ярлыков уровня**. Ярлыки «уровень 3/4» снять со **всего** енума и с
  API kill-switch'а; уровень серьёзности — отдельная ось, живёт в
  error-политике.
- `INSTRUMENT_GROUP` — **без** `fireGroup`: kill-switch остаётся с
  двумя исполнителями {инструмент, биржа}. Scope-енум (3 члена) и
  kill-switch-енум (2 цели) намеренно **не параллельны** — не каждый
  радиус тянет kill-switch.
- Носитель холда несвежести — сам `groupId` (scope
  `INSTRUMENT_GROUP`), инструменты выводятся при enforcement'е ⇒
  обратный резолв «группа → инструменты» не нужен ⇒ **H13 закрыт этим
  же ходом**.

## Среда

Против v132 не изменилась; полное описание — там. Ловушки среды из v156-v185
остаются в силе, включая: полный гейт инструментов в 120 с не укладывается —
прогонять фоновой командой; рабочий бинарь — `py` (`python3` и `python` из
PATH — заглушка, её код 49 читается как «не измерялось»); в regex-шаблонах
для `tools/retired-check.py` пользоваться `\s+`; импорт модуля из `tools/`
через `importlib` роняет `__pycache__` в корень репозитория; `cd` внутри
составной команды Bash сохраняется между вызовами; форма `py - <<'PYEOF'`
рвётся на длинном markdown с таблицами — большой раздел писать инструментом
записи; вывод `py` через пайп идёт в cp1251 и рвётся на кириллице (`export
PYTHONIOENCODING=utf-8`); `bash`-heredoc рвётся на многокилобайтном русском
тексте; перенос строки в шаблоне `grep -P` пишется escape-последовательностью;
имя в командном блоке связывается **внутри** блока; в §-адресе имя файла
пишется рядом с адресом; `\b` с кириллицей заменяется на `(?![а-яё])`;
извлечение шаблона из файла якорится различающим началом; в снапшоте снятое
**называется**, а не цитируется; раздел новой единицы называется с её
маркером; литерал `'\\'` внутри heredoc-скрипта приходит одиночным слешем;
слепая линза, идущая грепом, обязана исключать `.claude/work/progress/**` в
самой команде; временный файл писать через `tempfile.gettempdir()` — каталога
`/tmp` у Python в этой среде нет; однострочный греп по русскому термину не
видит вхождения, разорванного переносом строки, — форма замера
`grep -oUzP '(?s)…'`.

**Ловушка `grep -P` и локали** (новая, из этой сессии): `grep -P` в этой среде
отказывает сообщением «-P supports only unibyte and UTF-8 locales» — перед
всяким `-P`-прогоном ставится `export LC_ALL=C.UTF-8`. Без него команда
возвращает код 2, и отказ читается как «дефектов нет», если код не проверять.

## Среда

Против v132 не изменилась; полное описание — там. Ловушки среды из v156-v197
остаются в силе, включая: полный гейт инструментов в 120 с не укладывается —
прогонять фоновой командой (`tools/spec-mutation-check.sh` один держит несколько
минут); рабочий бинарь — `py`; в regex-шаблонах для `tools/retired-check.py`
пользоваться `\s+` и делать их терпимыми к разметке; вывод `py` через пайп идёт в
cp1251 и рвётся на кириллице (`export PYTHONIOENCODING=utf-8`); перед всяким
`-P`-прогоном ставить `export LC_ALL=C.UTF-8`; `\w` у `grep -P` кириллицы не
берёт — классы писать явно (`[а-яё]+`); файл журнала фоновой команды писать в
`$TEMP`; длинный кириллический heredoc в Bash рвётся — правки корпуса писать
временным `.py`-файлом либо инструментом записи файла; многострочная правка
целится в текст **с его отступом**; точная подстановка проверяется счётом
вхождений до записи; ждать фоновый гейт холостым циклом нельзя; точечный прогон
модуля идёт **из корня** (`-pl`), а не через `-f`; `docker` под Git Bash требует
`export MSYS_NO_PATHCONV=1`, а источник копирования — **относительным** путём;
`psql -c` с несколькими операторами шлёт их одной транзакцией.

**Ловушки этой сессии.**

- **Автоконфигурации Kafka в дереве зависимостей нет вовсе.** Boot 4 разнёс
  автоконфигурацию по модулям `spring-boot-<технология>`, и Kafka среди
  разрешаемых офлайн нет ни одного: свойства `spring.kafka.*` не читает никто,
  бина `KafkaTemplate` не существует, `@KafkaListener` не обрабатывается.
  Новый потребитель объявляет клиента целиком явно.
- **При трёх бинах `DataSource` автоконфигурация JPA отступает целиком** —
  `@ConditionalOnSingleCandidate`. Фабрика сущностей и менеджер транзакций
  объявляются руками; физические имена колонок пишутся `@Column(name = …)`,
  потому что стратегию именования Boot к своей фабрике не применяет.
- **`greatest` в Postgres пустые значения ИГНОРИРУЕТ** — на этом стои́т
  монотонность момента без отдельной охраны в `where`.
- **У `DefaultErrorHandler` публичного доступа к своему `BackOff` нет.**
  Число попыток мерится поведением — прогоном `handleOne` подряд, а не
  чтением настройки.

## Путь к точке (от v50)

v50 оставил: demo-пилот через mapped-границу пройден, методология
тест-коллекций внесена, price-gap подтверждён как предусловие
регенерации. Вместо точечного закрытия price-gap тема **переосмыслена**
— цель теста уведена с границы на сырьё (price-gap и большинство
прокси-surface-gap'ов при этом **растворились**: бьём в сырой клиент
напрямую). С тех пор (эта сессия):

1. **Ре-база цели — сырьё.** Решения зафиксированы (`progress` §Входные
   решения): тесты бьют в `OkxRestClient` + сырые DTO, не в нашу границу;

   §«Неиспользуемый код» в силе — карваута на полное зеркало биржи нет);
   источник набора запросов — **манифест** (`coverage-manifest.md`,
   периметр ∩ клиент); на каждый запрос прямой кейс + порождающий
   негатив; гейт достижимости; цепочки предусловий.
2. **Развилки A/B/C решены** (`tasks/source-api-rebase.md` — РЕШЕНО):
   **A2** (коллекция через passthrough `OkxProxyController`), **B1 +
   passthrough** (код-тесты + проходной слой, профиль-гейт structural
   no-prod), **C3** (сверка апидоков через `api-docs-completion`,
   рантайм-провенанс). Decision —
   `.claude/decisions/source-api-target-rebase.md`.
3. **Реализация (2026-06-18):** `OkxProxyController` переписан на сырьё
   (зовёт `OkxRestClient`, отдаёт `OkxApiResponse<T>`); mapped-поверхность

4. **Тщательное покрытие (2026-06-19):** пилотный субсет замещён **полным

## Наработано в сессии (всё staged, не коммичено)

**Методология (уточнения поверх v50):**
- **негатив на каждый запрос**, включая write/мутацию (не только read);
- **вариант-покрытие по типу-дискриминатору** (`ordType` limit/market;
  `conditionType` conditional/oco/move_order_stop; семья cancel
  ordinary/advance);
- **инвариант полноты:** in-perimeter ∩ клиент покрыт целиком; новый
  запрос клиента → либо покрытие, либо явный gap (не молча);
- **структура план/отчёт — метод → кейсы → таблица** (класс на метод,
  строка таблицы = запрос кейса с проверками и ожиданием);
- **колонка покрытия в манифесте** (`coverage-manifest.md`): метки
  🔴/🟡/🟢/⚪ по стадии; 21 строка клиента → 🟡 (в плане); gap'ы → ⚪;
  продвижение по стадиям зафиксировано в процессе.

**Артефакты:**
- **A2-passthrough расширен 7 read-эндпоинтами** (candles ×2,
  orders-pending/history, algo-pending/history, fills-history) — чтобы
  коллекция была 1:1 со всем периметром клиента; все read, write-риска
  нет (**на валидацию** — §Нерешённое 1);
- **тщательный план + коллекция** заместили пилот (21 метод, 112
  запросов): каждый запрос × негатив, варианты типов, цепочки Climit
  (неисполнимый) / Cmarket (исполняемый → fill/позиция, снимает пилотный
  отказ R5 по достижимости fills) / M19-варианты + teardown;
- **~40 client-coverage-gap + 3 вариант-gap** задокументированы (запрос
  не выдумывается): client-coverage-gap — строки периметра без метода
  клиента (batch, amend, archive-3м, mark-price, funding-rate и пр.);
  вариант-gap — `callbackSpread` trailing-value, partial SL/TP, битый
  сырой `ordType` (через типизированный прокси не достижимы).

## Ждёт валидации пользователя (gate — `plan.md` §Нерешённое)

Эти четыре — на валидацию пользователя при ревью/аппрусе; **не
финализированы** (крены даны, решение за пользователем):

1. **Расширение A2-passthrough 7 read-эндпоинтами** — оставить (для 1:1
   со всей поверхностью клиента; все read, passthrough — инструмент
   теста, не продуктовый API) **vs** вернуть в passthrough-exposure-gap
   (план покрывает, коллекция — нет). *Сделано; на валидацию.*
2. **Market-цепочка Cmarket ставит реальный исполняемый ордер на demo**
   (минимальный sz → fill → позиция → зависимые прямые кейсы fills/
   позиций → teardown closePosition) — допустимо ли реальное исполнение
   в контуре **vs** ограничиться неисполнимыми (тогда fills/позиции —
   отказ по достижимости, как в пилоте).
3. **Вариант-gap'ы** (trailing-value `callbackSpread`; битый сырой
   `ordType`-негатив; all-ccy `getBalance` без passthrough-параметра) —
   закрывать ли passthrough-параметрами под них (крен — **не** закрывать:
   расширение прокси под доменно-неиспользуемое против `codestyle`
   §«Неиспользуемый код»).
4. **Политика точных кодов ошибок негатива** — где контракт не
   документирует код, ожидание = «реджект (`code≠0`)», точный код —
   наблюдение прогона (находка интегратору на C3), не выдумка.

### Программа делегирования установлена

`.claude/processes/question-delegation.md` (модель) + правило
«Делегирование развилок по владельцам» в
`chat-project-instructions.md` (Custom Instructions). Суть:
развилки со штатным владельцем (классификация →
`knowledge-curator`, торговля → `trading-specialist`, детали кода →
`code-writer` на `CODE`, концепт → `solution-designer`) чат не
выносит пользователю «реши с нуля» — их прорабатывает владелец, до
пользователя доходит результат по ступени автономии (R1 — полная
валидация, R2 — выборочная, R3 — только исключения); пользователю
остаётся его хвост (цели, приоритеты, численный риск-аппетит,
продуктовый scope/интерфейс, сроки; для концепта — выбор из
вариантов). Размещение категорий: классификация **R3**, трейдинг
**R1**, концепт **R1 после создания владельца**. Гейт повышения —
**N=3** чистых валидации подряд (гибрид: прогон предлагает,
пользователь подтверждает), счёт ведёт CC. Трейл аддитивный, вне
канона: леджер гейта → данные по доверию в разрезе агентов; разбор
решения → неканон рабочее место. Канон (`decisions/`, файлы
знания) не меняется. Аудит-основание — заметка выше.

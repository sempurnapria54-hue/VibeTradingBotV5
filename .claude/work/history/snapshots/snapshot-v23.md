## Что изменилось относительно v22

### Э4 — персистентность `Strategy` закрыта и применена

Принято решение по схеме хранения дерева `Strategy` (главная
эскалация `DOCS_CHECK_2`):

- Каркас дерева — **реляционный** (узел = строка/таблица с `id`,
  связи через FK, загрузка целиком `@EntityGraph` / `JOIN FETCH`).
- Индикаторные `params` — **JSONB** на `StrategyIndicatorSetting`
  (сознательный отход от архива, где это отдельная сущность с
  наследованием).
- Действия (`StrategyAction`) — наследование **`JOINED`** (база
  `strategy_action` + подтаблицы по видам; у позиции своих полей нет;
  вложенные настройки действий — JSONB).
- `stepsByStatus` — плоские строки `strategy_step` (`strategy_detail_id`
  FK, `deal_status`, `step_index`); Map пересобирается группировкой +
  сортировкой.
- Ссылки: правило→settings = FK; ссылки изнутри JSON-листьев =
  «мягкие»; `targetActionKey` → self-FK `target_action_id`.
- Типы/nullability числовых полей дерева — **не решали** (проставятся
  при entity/миграции).

Размещено: новый decision
`docs/decisions/strategy-tree-persistence.md` (первое наполнение
`docs/decisions/`) + новый раздел «Персистентность» в
`docs/models/domain/aggregate/Strategy.md`.

### Э2 — зафиксировано только направление

Доки задают **контракт авторинга** условия; вычисление истинности —
деталь evaluator'а (downstream). Сам контракт по-полям не пишется:
открыта нестыковка представления (объектная ссылка `indicatorSetting`
vs строка-метка `leftOperand` + инлайновый `params`; дубли
`sourceType`/`valueType`). Заметка-направление добавлена в
`Strategy.md` (§Условия), со ссылкой на STRAT-Q1.

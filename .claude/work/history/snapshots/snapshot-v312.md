**Что форма захода уже включает** (не выводить заново):

- метка своей дельты отбивается **до первой правки** (`git write-tree`);
- механические оси мерятся разбором документа: четыре поля у каждого кейса,
  существование путей-носителей, разрешимость §-адресов (`py tools/anchor-check.py`);
- каждый перечень дома — операции поверхности, тики, рёбра жизненного цикла,
  классы события, классы отказа — **перебирается поимённо**, и непокрытая
  единица уходит меткой `G` в раздел «Пробелы покрытия» документа кейсов;
- ожидание, у которого дом молчит либо код с домом разошёлся, помечается
  формой «по дому / сегодня», а разрыв уходит находкой `F` с секцией бэклога;
- отчёт несёт таблицу самопроверки автора по критерию
  (`.claude/skills/test-design.md`).

**Три класса, найденные у всех четырёх предметов и стоящие проверки у каждого
следующего:**

1. **Пиньнутое HTTP-число, которого не фиксирует ни один дом.** Признак
   механический: число производит **наш** обработчик — ожидание берёт класс
   (`code`); число производит контейнер, точка входа контура либо контракт
   успеха — остаётся числом.
2. **Элемент жизненного цикла либо перечня без писателя.** Ловится перебором
   рёбер и значений поимённо против грепа по дереву сервиса.
3. **Ожидание, взятое из дома, которое код не несёт.** Ловится чтением
   исполнителя, а не дома: дом читается верно, расходится построенное (F-4 —
   первый случай, где код к тому же **сам объявляет** невыполненное поведение).

**Исходники читаются прямо из `services/**`** — распаковка нужна только для
библиотек; каталог распаковки заводится **внутри репозитория** и удаляется до
гейта (§Ловушки).

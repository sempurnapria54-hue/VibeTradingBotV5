## Среда

Против v132 не изменилась; полное описание — там, перечень ловушек — в v206
(`.claude/work/history/snapshots/snapshot-v206.md` §Среда) и он остаётся в
силе целиком. Ловушки v207-v210 тоже в силе: мутационная батарея держит
дерево мутированным; проба, чья фикстура совпадает с подменой, мутации не
ловит; `cd` внутри команды `Bash` переносит рабочий каталог сессии;
`-Dtest='A+B'` не выбирает ни одного класса; `grep -P` отказывает на
не-однобайтовой локали (формы исполняются с `LC_ALL=C.UTF-8`); heredoc с
длинным русским текстом рвётся; пути `/tmp` у `bash` и у `py` разные.

**Три ловушки этой сессии.**

1. **`python` в среде НЕТ — есть только `py`.** Вызов `python` не отказывает
   заметно: он печатает подсказку установщика Windows и возвращает **ноль**,
   то есть скрипт «отработал», ничего не сделав. Правки, отданные через
   `python`, теряются молча — проверять их приходится отдельным чтением файла.
2. **`-Dtest=<Класс>` в этом реакторе роняет сборку на СОСЕДНЕМ модуле**
   («No tests matching pattern»), потому что `-am` тянет `domain-model`.
   Точечный прогон делается без `-Dtest`, а нужный класс выбирается грепом по
   выдаче.
3. **`ThreadPoolTaskScheduler.getPoolSize()` возвращает НОЛЬ у поднятого
   планировщика:** потоки создаются лениво, и до первой задачи текущий размер
   пула равен нулю при любом назначенном. Назначенное число читается ядром
   пула — `getScheduledThreadPoolExecutor().getCorePoolSize()`.

## Среда

Против v132 не изменилась; полное описание — там. Ловушки среды из v156-v181
остаются в силе, включая: полный гейт инструментов в 120 с не укладывается —
прогонять фоновой командой; рабочий бинарь — `py` (`python3` и `python` из
PATH — заглушка, её код 49 читается как «не измерялось»); в regex-шаблонах для
`tools/retired-check.py` пользоваться `\s+`; импорт модуля из `tools/` через
`importlib` роняет `__pycache__` в корень репозитория, и `tools/retired-check.py`
отказывает кодом 2 на нём; `cd` внутри составной команды Bash сохраняется между
вызовами; форма `py - <<'PYEOF'` рвётся на длинном markdown с таблицами —
большой раздел писать инструментом записи во временный файл внутри репозитория
и вклеивать коротким скриптом (временный файл удаляется тем же ходом).

**Ловушка переноса строки в шаблоне `grep -P`** (из v179, в силе и мерится
машиной — ось 7 `tools/command-carrier-check.py`): длинный `-P`-шаблон
переносится **между** аргументами, внутри шаблона перенос пишется
escape-последовательностью. Оборотная сторона: команда, **ищущая** непарную
кавычку, не вправе нести непарную кавычку сама.

**Ловушка несвязанного имени в командном блоке** (из v181; **теперь мерится
машиной** — ось 9 того же инструмента): блок, читающий переменную, которую
связывает только проза рядом, исполняется, возвращает 0 и отвечает **не на свой
вопрос**. Имя связывается **внутри блока**; накопленное объявлено долгом
`tools/command-carrier-debt.txt`.

**Ловушка `\b` в шаблоне `grep -P` с кириллицей** (новая, из построения
популяции): граница слова определяется по байтовому классу `[A-Za-z0-9_]`, и
между кириллической буквой и концом строки её **нет** — шаблон
`(все)\s+(четыре)\b` не находит ничего при коде 0 у соседей. Рабочая форма
отрицательного просмотра — `(?![а-яё])`; она проверена пробой на двух строках,
где одна обязана совпасть, а вторая нет.

**Ловушка `-m1` при извлечении шаблона из файла** (новая, из закрытия Ш2):
извлечение якорится **различающим началом** шаблона, иначе `-m1` берёт первую
подходящую команду файла — и охрана `[ -n "$VAR" ]` этого не ловит, потому что
значение не пусто, оно чужое.

**Ловушка снапшота против реестра снятых редакций** (из v178, в силе): в
снапшоте снятое **называется**, а не цитируется, и рядом стои́т действующая
редакция с указателем на её дом.

**Ловушка одноимённых заголовков** (из v178, в силе): раздел новой единицы
называется с её маркером; §-адрес обязан разрешаться однозначно.

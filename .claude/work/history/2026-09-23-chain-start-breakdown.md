# Разбивка старта сессии цепочки

## На какой вопрос отвечает этот файл

Из чего складывается старт сессии цепочки на v412 и сколько в скиллах и
процессах старта дубля — по замеру задачи «разбивка старта» (только чтение).

## Итог

| Сводка | Значение |
|---|---|
| старт всего | 197,8K токенов |
| доля правил по маскам | 22,6% старта (44,7K) |
| доля дубля в скиллах и процессах | 4,1% их знаков (6 784 из 166 461; около 3,3K токенов, 1,7% старта); со спорными — 8,7% |

Старт вырос на 6,0K против замера `.claude/work/history/2026-09-23-trap-index.md`
(191,8K). Прирост дали два скилла, в которые проход «решение держит только
развилку» вписал пассажи решений: `test-code.md` — с 34 649 до 41 176 знаков,
`test-design.md` — с 19 796 до 28 831.

Крупнейшие доли старта — скиллы и процесс (81,0K, 41%), правила со scope
(44,7K, 23%) и ядро правил (33,7K, 17%). Из одиннадцати правил со scope до
начала работы сессии нужно одно — `session-work-unit` (3,5K). Дубль в скиллах
и процессе мал: почти весь текст — собственные нормы файлов.

Корпус не менялся; в рабочем дереве изменён только этот отчёт.

## Как мерилось

Перечень старта — тот же, что в замере «после» задачи
`.claude/work/history/2026-09-23-snapshot-without-tail.md`: `snapshot-v412.md`,
`phase-2.md`, `roadmap.md`, `roadmap-step-execution.md`, `test-code.md`,
`test-step-pace-measures.md`, `environment-commands.md`, `local-stand.md`,
`test-design.md`, `test-review.md`, `update-roadmap-progress.md`,
`session-chain.md`. Итог — `/context` сессии, прочитавшей перечень
инструментом `Read`; он совпал с суммой `usage` последнего хода (59 954 до
первого чтения плюс 137 870 после).

Разбивку по файлам дали ещё три сессии, в каждой чтения шли по одному вызову
на ход. Вклад вызова — прирост входных токенов следующего хода за вычетом
выходных токенов вызывающего хода: так вычитаются и сам вызов, и рассуждение
модели между вызовами.

- **Файлы перечня** — `Read` копий вне масок (временный каталог сессии), чтобы
  правила не приходили.
- **Правила со scope** — `cat` через Bash: чтение оболочкой масок не включает.
  `structure.md` больше предела выдачи Bash и мерился вычитанием: прирост
  чтения снапшота минус снапшот минус семь остальных правил, пришедших с ним.
- **Сверка вычитанием** на двух других чтениях: `phase-2.md` минус два его
  правила расходится с копией на −20 токенов, `test-step-pace-measures.md`
  минус `carrier-levels` — на −48.
- **Шум:** в одном из прогонов на ход чтения `test-design.md` пришли поздние
  инструкции MCP-коннектора (1 769 токенов); в разбивке они вычтены.

```bash
MSYS_NO_PATHCONV=1 claude -p "Прочитай инструментом Read каждый из этих файлов целиком: <перечень> . Ответь ok." --session-id <id> --permission-mode bypassPermissions < /dev/null
MSYS_NO_PATHCONV=1 claude -p "/context" --resume <id> < /dev/null
MSYS_NO_PATHCONV=1 claude -p "Прочитай инструментом Read каждый из этих файлов целиком, СТРОГО ПО ОДНОМУ: ровно один вызов инструмента в каждом сообщении, в указанном порядке: <перечень> . Затем ответь ok." --session-id <id> --permission-mode bypassPermissions < /dev/null
```

Вклад вызова — по журналу сессии `~/.claude/projects/<проект>/<id>.jsonl`;
ходы с одинаковым `usage` сливаются:

```python
import json, sys
turns = []
for line in open(sys.argv[1], encoding='utf-8'):
    o = json.loads(line)
    if o.get('type') != 'assistant':
        continue
    u = o['message']['usage']
    tot = u['input_tokens'] + u.get('cache_read_input_tokens', 0) + u.get('cache_creation_input_tokens', 0)
    if turns and turns[-1][0] == tot:
        turns[-1][1] = max(turns[-1][1], u.get('output_tokens', 0))
        continue
    turns.append([tot, u.get('output_tokens', 0)])
for a, b in zip(turns, turns[1:]):
    print(b[0] - a[0] - a[1])
```

единицу и начать её (на v412 — ящик `bff`, группа `B4`), до первой правки.

Восемь правил из одиннадцати пришли с первым же чтением — снапшота.

**Подтянулись бы и в работе.** Единица v412 читает документ кейсов
`.claude/tests/cases/bff.md` — это шесть корпусных правил и
`session-work-unit`; хронику шага (маска `.claude/work/**`) — это

`carrier-levels`. Только чтением снапшота приходит `snapshot-format`, а нужно
оно при записи нового снапшота. Запись нового файла по маске правило не
подтягивает (зонды `.claude/work/history/2026-09-23-rules-tiering.md`).

## Как читали реальные сессии цепочки

Восемь последних сессий цепочки (21-22.09, снапшоты v403-v410) шли до ярусов:
все правила тогда были ядром. Замер сделан по их журналам.

| Замер | Значение |
|---|---|
| вызовов Bash / `Read` за восемь сессий | 1 267 / 15 |
| вход до первого чтения | 113,2K-113,8K |
| вход на ходе первой правки | 220,9K-294,1K |
| из прироста до первой правки: снапшот, роадмап, хроника | 10K-20K |
| документы кейсов | 11K-31K |
| прочий корпус: скиллы, решения | 0-5K |
| код сервисов | 46K-106K |

Сессии читали оболочкой (`cat`, `sed -n`, `tail`). Цепочка идёт в режиме
`bypassPermissions` (`tools/session-loop.sh`, `PERMISSION_MODE`), и в нём
харнесс направляет чтение файлов в Bash. Чтение оболочкой масок не включает
(зонды того же отчёта ярусов), поэтому в такой сессии правила со scope пришли бы
только с редкими вызовами `Read`. Скиллы перечня целиком эти сессии почти не
читали: `test-code.md` прочла одна из восьми, `environment-commands.md` —
частями две.

Сессии v403-v410 были до снапшота без хвоста, поэтому прямого сравнения с
перечнем v412 этот замер не даёт.

## Дубль в скиллах и процессах

Дубль — пассаж, повторяющий норму, чей дом — правило, процесс, другой скилл,
`CLAUDE.md` или промпт цепочки. Пассаж можно снять, заменив указателем на дом
без потери смысла. Не считались:

- указатели без пересказа;
- строки оглавлений ловушек;
- нормы, чей дом — сам файл;
- применение нормы к предмету файла с собственным содержанием.

Пассаж, у которого дом между двумя файлами не определён, — «спорный» и в
основной счёт не входит. Разбор — четыре субагента по два файла; знаки,
не байты.

В токенах, пересчётом по отношению токенов к знакам каждого файла, основной
счёт — около 3,3K, со спорными — около 7,1K: 1,7% и 3,6% старта.

**Откуда дубль.**

- `update-roadmap-progress.md` пересказывает правила:
  `measurement-commands` (код 2, лаунчер `py`), `backlog-section-form`
  (исход сработавшего условия), `long-run-wait`, `codestyle` (точечная сборка
  `-am -pl`). Цепочку статусов он повторяет из процесса.
- `roadmap-step-execution.md` пересказывает `concept-review.md`,
  `question-delegation.md` (карта владельцев, дайджест) и
  `edit-kind-obligations`.
- `session-chain.md` пересказывает `session-work-unit`, `long-run-wait` и
  промпт цепочки.
- `test-design.md` пересказывает два абзаца `edit-kind-obligations` о
  популяции и радиусе рода.

**Вид дубля.** Дословных копий почти нет. Преобладает пересказ нормы рядом с
уже стоящим указателем на её дом.

**Спорное.** Спорное сосредоточено между тремя тест-скиллами и процессом шага.
Дом не определён, например, у критерия апрува и формы кейса
(`test-design`/`test-review`), у проверок кода тестов
(`test-review`/`test-code`) и у места хранилища Docker
(`local-stand`/`session-chain`).

**Замечено попутно, не разбиралось.**

- Домом гейта инструментов корпуса объявляют себя и
  `update-roadmap-progress.md`, и `roadmap-step-execution.md`.
- В `local-stand.md` одна строка говорит, что ингресс на стенде есть, другая —
  что его нет.
- Вводная формула оглавления ловушек повторена примерно в тринадцати файлах.

# Миграция API-кластера OKX

## На какой вопрос отвечает этот файл

Что мы сделали в миграции API-кластера OKX (backlog п.10) и какие
файлы созданы/дополнены.

## Итог

Завершена 2026-05-28. Мигрированы все REST endpoint-доки OKX из
`.claude-archive/2026-05-21/docs/api/okx/` в `docs/client/okx/`,
кроме `OKX — Сценарии применения операций (Playbooks v1).md` (не
скоуп).

Подход: один mapping-файл = одна доменная сущность; endpoint'ы
конкретных операций — раздел `## Endpoints` внутри mapping. Поля DTO
— отдельный файл в `models/`. Из-за нерешённых продуктовых вопросов
ни одну операцию не откладывали: мигрировали контракт endpoint'а
(endpoint, auth, rate limit, request/response поля), продуктовый
вопрос — open-question с обратной ссылкой.

## Создано в `docs/client/okx/`

**Новые mapping-файлы (`rules/`):**
- `okx-candle-mapping.md` — `market/candles` + `market/history-candles`
  (формат 9-элементного массива свечи, пагинация по `ts`, регистр-
  чувствительный `bar`).
- `okx-fills-mapping.md` — `trade/fills` + `trade/fills-history`
  (пагинация по `billId`, связь с `RefreshFillsExecutor`,
  persisted-сущность отложена → OKX-Q1).
- `okx-fills-archive-mapping.md` — async-флоу `POST/GET
  /trade/fills-archive` (генерация архива → polling → скачивание;
  лимит 10/day; материализация отложена → OKX-Q2).
- `okx-account-bills-mapping.md` — `account/bills` (7d) +
  `account/bills-archive` (3m); ввод в финализацию `Deal` отложен →
  OKX-Q3.
- `okx-ws-limits.md` — connection limit (3/s по IP), request limit
  (480/час на соединение), keep-alive (>30 с — risk reconnect),
  channel-conn-count (≤30 на канал).
- `okx-service-urls.md` — production EEA + глобальные REST/WS, demo
  trading URL, header `x-simulated-trading: 1`.

**Новые response DTO (`models/`):**
- `OkxFillResponse.md` — поля одного fill.
- `OkxFillsArchiveResponse.md` — generate response + file-link
  response.
- `OkxAccountBillResponse.md` — поля одного bill (включая funding
  `subType=173/174`).

**Дополнено в существующих файлах:**
- `okx-order-mapping.md` — endpoint'ы с rate-limit/permission, body
  amend (`cxlOnFail`, `pxAmendType`, `attachAlgoOrds`-mod), response
  ACK секции (create/amend/cancel), pagination, `tag`/`stpMode`/`ccy`
  policy.
- `okx-algo-order-mapping.md` — endpoint'ы с rate-limit, response
  ACK, ordType-specific body (`conditional`/`oco`/`trigger`/
  `move_order_stop`), history-3m + обязательный `ordType`.
- `okx-position-mapping.md` — endpoint'ы с permission/rate-limit,
  close-position body (`autoCxl`/`mgnMode`/`posSide`/`ccy`),
  подтверждение факта закрытия.
- `okx-instrument-mapping.md` — endpoint permission/rate-limit, WS
  альтернатива, таблица используемых полей response + sizing-формула.
- `okx-market-price-data-mapping.md` — endpoint, WS-канал `tickers`,
  таблица полей response, неиспользуемые 24h-агрегаты явно отброшены.
- `OkxOrderResponse.md` — добавлены `cTime`/`uTime` (snapshot
  `externalCreatedAt`/`externalModifiedAt`), секция validation/
  диагностика, расширенные attached protection поля.
- `OkxAlgoOrderResponse.md` — добавлены `cTime`/`uTime`, секция
  iceberg/TWAP/диагностики, attached в algo.
- `OkxPositionResponse.md` — close-position response details,
  `closeOrderAlgo[]` поля.

## Что не мигрировано

- Раздел «Реализация в коде (Stage 02)» в обзорном `okx_api_for_trading_bot_v5.md`
  (устаревшие пакеты `com.example.tradingbot.*`).
- Сводная таблица операций как отдельный файл (растворена в
  mapping-файлы).
- Сводные REST rate-limits (есть в индивидуальных mapping).
- WS-каналы детально (OKX-Q4).
- `Playbooks v1.md` — исходно вне скоупа.

## Решения по структурным развилкам

- **Q3 (свечи):** отдельный `okx-candle-mapping.md` (а не расширение
  `okx-market-price-data-mapping.md`) — по принципу «один mapping =
  одна доменная роль». Альтернатива пометкой в файле.
- **Q5 (request-DTO):** не заводим отдельные `Okx*Request.md`;
  request-структура остаётся в `Domain → request mapping` секциях
  существующих mapping (как сейчас).
- **Q6 (WS-лимиты + Service URLs):** два файла, а не один
  `okx-connectivity.md` — по «один файл = одна забота». Альтернатива
  пометкой в каждом файле.

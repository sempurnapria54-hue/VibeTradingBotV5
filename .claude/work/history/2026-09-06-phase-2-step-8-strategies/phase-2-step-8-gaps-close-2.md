# Популяция гейтящего узла

## Узел C1+C2. Носитель истины о тенанте у торговой строки

**Правило узла.** Тенант несётся строкой ровно там, где счёт локально не
резолвится; где резолвится — не дублируется.

**Ось 1 — строки, несущие либо резолвящие тенанта.** Перечень выведен
**из предмета** (фактических таблиц), командой:

```bash
LC_ALL=C.UTF-8 grep -rn 'tenant_id\|tenant_internal_id' services/*/src/main/resources/db/migration/*.sql \
  | grep 'varchar\|references\|index\|unique'
```

| Член (строка) | Исход |
|---|---|
| `auth.tenants.internal_id` | **правило выполняется**: тенант и есть предмет строки, дублем не является |
| `auth.memberships.tenant_id` | **правило выполняется**: предмет строки — связь пользователя с тенантом |
| `auth.exchange_accounts.tenant_id` | **правило выполняется**: реестр счёта и есть **источник** резолва |
| `trading_core.exchange_accounts.tenant_internal_id` | **правило выполняется**: проекция того же реестра, локальный источник резолва у ядра |
| `trading_core.tenant_risk_appetites.tenant_internal_id` | **правило выполняется**: предмет строки — риск-аппетит тенанта |
| `trading_core.outbox.tenant_id` | **правило выполняется**: первый названный случай — конверт события, он же ключ партиции |
| `trading_core.deals` (и подчинённые: транши, заявки, строки исполнения) | **правило выполняется**: тенанта не несут, резолв по счёту локален |
| `trading_core.strategies` (копия определения) | **правлено закрытием**: колонка тенанта **не заводится** — прежняя редакция §Персистентность объявляла её «у обеих сторон» |
| `trading_core` — отчёты аномалий, снимки средств, ставки комиссии | **правило выполняется**: тенанта не несут, счёт называют |
| `strategies.strategies` (строка определения у владельца) | **правлено закрытием**: колонка тенанта **заводится** — второй названный случай: строки счёта у сервиса нет вовсе |
| `strategies.outbox` (заводится шагом) | **правило выполняется**: первый названный случай, конверт |
| `market_data.*` | **недостижим**: рыночные данные не тенантные — инструмент принадлежит площадке, и ни одна строка `market-data` тенанта не адресует (`docs/architecture/data-ownership.md` §Раскладка) |
| `audit`, `statistics` | **недостижимы этим шагом**: базы приезжают шагом 10; их строки — проекции событий, и тенанта они возьмут из конверта, то есть по первому случаю |

**Ось 2 — носители правила.** Команда:

```bash
LC_ALL=C.UTF-8 grep -rlUP '(?s)Тенант\s+отдельным\s+полем|резолвится\s+по\s+счёту|Каждая\s+тенантная\s+таблица' docs/ .claude/rules/ .claude/processes/ --include=*.md
```

| Носитель | Исход |
|---|---|
| `docs/architecture/tenant-and-exchange.md` §«Торговая строка называет счёт, и радиусы читаются от него» | **правлен**: дом получил механический признак применимости и оба названных случая вместо одного |
| `docs/models/domain/aggregate/Strategy.md` | **правлен** дважды: строка `tenantId` корня и строка `tenant_internal_id` подраздела различий — обе сведены к ссылке на дом, пересказа нет |
| `docs/architecture/data-ownership.md` §«Разделение по тенанту» | **не требует правки**: «каждая тенантная таблица несёт `tenantId`» и признак дома не конфликтуют — у сервиса со строкой счёта тенант в таблице **есть**, он лежит в строке счёта, на которую таблица ссылается |
| `docs/models/domain/aggregate/Deal.md` | **не требует правки**: тенанта не несёт и объявляет резолв по счёту — ровно то, что признак предписывает сервису со строкой счёта |

**Исполнимая форма.** Ось не выразима спекой: предмет — наличие колонки,
а не вычислимая величина; счётных клеймов узел не вводит. Механический
якорь — запись реестра `tools/retired-check.py` «тенант строкой —
исключение ровно одно, конверт события»: шаблон снятой формулировки плюс
популяция из двух носителей с шаблонами пришедшей редакции. Прогон после
ввода — 0 дефектов, 50 записей реестра, 196 строк популяции.

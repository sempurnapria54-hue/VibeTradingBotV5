# Популяции гейтящих узлов

## Узел D1. Писатель значений контекста определения

**Правило узла.** У каждого поля контекста определения назван актор,
производящий значение, и момент; источник значения совпадает с тем, кто
вправе его назвать.

**Ось 1 — поля контекста корня.** Команда вывода:

```bash
sed -n '/^## Strategy (корень)/,/^`Status`/p' docs/models/domain/aggregate/Strategy.md
```

| Член | Исход |
|---|---|
| `internalId` | **правлено закрытием**: приёмник команды создания, фабрика `domain-model`, до первой записи |
| `tenantId` | **правлено закрытием**: приёмник создания **из контекста вызова**, транзакция создания; телом не принимается |
| `exchangeAccountInternalId` | **правлено закрытием**: приёмник создания **из тела**, та же транзакция |
| `instrumentInternalId` | **правлено закрытием**: то же |
| `id` | **правило выполняется**: суррогат базы, пишет persistence при вставке |
| `name` | **правило выполняется**: из тела, тот же приёмник и момент; правкой не затронуто |
| `status` | **правило выполняется**: писатель и моменты названы циклом (`docs/lifecycles/Strategy.md`); телом создания не передаётся (`docs/models/mapping/Strategy.md`) |
| те же поля **у копии ядра** | **правлено закрытием**: писатель другой — потребитель `StrategyActivated`, момент — транзакция приёма снимка; `tenantId` копия не хранит вовсе |

**Ось 2 — носители.** Команда:

```bash
LC_ALL=C.UTF-8 grep -rlUP '(?s)tenantId|exchangeAccountInternalId|instrumentInternalId' docs/ .claude/rules/ .claude/work/backlog.md --include=*.md --include=*.json
```

| Носитель | Исход |
|---|---|
| `docs/models/domain/aggregate/Strategy.md` | **правлен**: таблица «поле → писатель → момент» плюс довод, почему тенант не принимается телом |
| `docs/models/mapping/Strategy.md` | **правлен**: названо, чего в теле команды нет (тенант, статус) и почему |
| `docs/architecture/contracts.md` §«Контекст тенанта в вызове» | **не требует правки**: дом тропы контекста, и он уже говорит, что тенант едет заголовком и сверяется с кэшем членств |
| `docs/architecture/data-ownership.md` §Идентификаторы | **не требует правки**: уже называет писателя `internalId` (сервис-владелец, до первой записи) — правка узла на него ссылается |
| `docs/rules/writer-named-for-every-value.md` | **не требует правки**: дом требования; узел его исполняет, а не меняет |
| `donor/src/main/resources/strategy-examples/trend-following-ema.json` | **не требует правки доком**: тела тенанта не несёт и не должен — по пришедшей редакции это верно; счёта не несёт и должен (узел D3, `CODE`) |

**Исполнимая форма.** Ось не выразима спекой: предмет — актор и момент, а
не вычислимая величина. Заявлено явно: **клейм не счётный**.

## Узел D2. Порядок активации

**Правило узла.** Чужие операнды добываются **до** открытия транзакции
перехода; в транзакции остаются проверка на добытых числах, запись
статуса и запись строки outbox.

**Ось 1 — шаги активации.** Перечень выведен из предмета — из состава
предусловий и требования атомарности. Команда:

```bash
sed -n '/^## Что проверяется на активации/,/^## Материализация/p' docs/rules/strategy-validation.md
LC_ALL=C.UTF-8 grep -n 'одной транзакцией\|транзакция перехода' docs/architecture/contracts.md docs/architecture/data-ownership.md
```

| Член (шаг) | Исход |
|---|---|
| проверка допустимости перехода | **правило выполняется**: операнд локален (статус строки), место — транзакция |
| проверка единственности `ACTIVE` на паре | **правило выполняется**: операнд локален, плюс уникальный индекс — обе внутри транзакции |
| добыча чисел риск-аппетита | **правлено закрытием**: **до** транзакции |
| добыча подтверждения существования пары | **правлено закрытием**: **до** транзакции |
| проверка пяти неравенств | **правлено закрытием**: внутри транзакции, на **добытых** числах |
| запись статуса | **правило выполняется**: внутри транзакции |
| запись строки outbox | **правило выполняется**: та же транзакция — требование «решение и его событие одной транзакцией» |
| публикация в Kafka | **недостижима внутри транзакции по построению**: публикует реле, отдельным проходом (`docs/components/OutboxRelayJob.md`) |
| откат опубликованного | **недостижим**: компенсаций у саг проекта нет (`docs/architecture/contracts.md` §«Идемпотентность и повтор») — потому и отвергнута двухфазная сверка |

**Ось 2 — носители.** Команда:

```bash
LC_ALL=C.UTF-8 grep -rlUP '(?s)одной\s+транзакцией|транзакци[яю]\s+перехода|внешний\s+вызов\s+внутри\s+транзакции' docs/ .claude/work/backlog.md --include=*.md
```

| Носитель | Исход |
|---|---|
| `docs/rules/strategy-validation.md` §«Что проверяется на активации» | **правлен**: порядок, довод и названная цена окна |
| `docs/architecture/contracts.md` таблица привязки | **не требует правки**: «транзакция перехода статуса» верна и после правки — сеть из неё вынесена, транзакция осталась той же |
| `docs/architecture/data-ownership.md` §«Outbox и доставка» | **не требует правки**: требует атомарности записи, а не отсутствия предварительной добычи |
| `.claude/work/backlog.md` §«Перф-форвард» | **не требует правки**: перечень из двенадцати точек не растёт — закрытие ровно тем и занято, чтобы тринадцатой не появилось |
| `docs/rules/error-handling-policy.md` | **не требует правки**: отказ соседа до транзакции — обычный отказ внешней поверхности, единый error-DTO уже покрывает |

**Исполнимая форма.** Клейм не счётный: предмет — порядок шагов, а не
величина. Заявлено явно.

## Что изменилось с прошлого прогона (без деталей находок)

Между прошлым прогоном и этим прошли **дизайн-проход смены способа
доказательства** и закрытие двадцати узлов. Существенно для тебя:

- **мутационная проба стала условием приёмки спеки:** каждая объявленная
  величина обязана падать на замене константой; введено единственное
  исключение — «величина-теорема» с ключом `provenBy` и косвенной
  пробой;
- **четыре дома закрытой формы риска на стопе слиты в один**
  (`docs/spec/risk-at-stop.json`), потребители подключают его через
  `includes`; модуль дистанции заменён знаковой формой, `direction` стал
  операндом;
- у детектора областей видимости появилась **ось C** (одно выражение под
  разными именами), у неё — объявляемое исключение `independentFrom`;
- **охрана полнотой графа** введена симметрично всем читателям
  агрегатов по загружаемым коллекциям;
- **база риска следует за балансом в обе стороны** (концепт
  невозрастающей базы отменён вместе с энфорсерами);
- введено **пятое статическое неравенство** создания стратегии (запас
  нотинала под потолком);
- **точечные ручки вне scope фазы 1**: сняты `MANUAL_*`-значения причин;
- заведены носители: фаза рынка внутри сделки, `TrailingSettings`,
  запрет набора риска в окне сворачивания, тройной ключ эпизода
  (адресуемая единица — пара `externalId` + `externalCreatedAt`);
- **конвенция имён DTO источника сведена к суффиксной**
  (`{Сущность}{Биржа}Response`);
- заведены два новых энфорсера — указателей «спека (величина)» и
  разрешимости §-адресов `.claude/**`.

**Это не индульгенция:** правки проверяй как любой другой текст. Часть
из них вводилась быстро и уже давала расхождения с кодом.

## Инструменты, которыми нужно пользоваться

Одиннадцать команд корпуса (из корня репозитория):

```
bash tools/spec-run.sh                    # примеры исполняются и сходятся
bash tools/spec-mutation-check.sh         # величина что-то проверяет
bash tools/spec-mutation-probe.sh         # оси мутационного замера
<py> tools/spec-scope-check.py docs/spec  # области видимости спек
bash tools/spec-scope-probe.sh            # оси детектора областей
<py> tools/spec-pointer-check.py          # указатель ведёт в дом величины
bash tools/spec-pointer-probe.sh          # оси детектора указателей
bash tools/preconditions-check.sh         # реестр == план == фактика
<py> tools/anchor-check.py                # разрешимость §-адресов .claude/**
bash tools/anchor-probe.sh                # оси детектора адресов
mvn -o test-compile                       # дерево собирается
```

`mvn` — через wrapper из кэша, JDK 25 в `~/.jdks/corretto-25`
(`JAVA_HOME=~/.jdks/corretto-25 ./mvnw -o test-compile`).

**`<py>` — установи сам, каким лаунчером Python в этой среде запускаются
скрипты, и не доверяй ни одному написанному указанию, включая шапки самих
скриптов.** Несработавший лаунчер печатает пустой перечень и читается как
чистый прогон: ложно-зелёный результат. Проверь до прогона — «интерпретатор
действительно выполнил файл», а не «команда завершилась без ошибки».

**Ловушки среды, дающие ложно-зелёный результат:**

- `git diff` без `HEAD` не видит застейдженного и возвращает ноль на
  любом состоянии — верная форма `git diff HEAD -- docs/`;
- `grep -P` без `LC_ALL=C.UTF-8` падает с ошибкой в stderr и печатает
  **пустой** список, который читается как чистый свип;
- проба, привязанная к **форме записи** (текстовый якорь в файле), а не к
  смыслу, зеленеет от переформатировки цели, ничего об этом не сообщая.

**Мутационная проверка обязательна там, где ты утверждаешь, что
конструкция что-то ловит:** подмени величину константой во временной
копии (`SPEC_DIR=target/probe-<линза> bash tools/spec-run.sh`) и покажи,
падает ли прогон. Зелёный прогон на мутации — находка, а не
подтверждение. Каталог пробы за собой удаляй. То же для энфорсеров: если
ты утверждаешь, что скрипт ловит класс, — сломай носитель во временной
копии и покажи падение.

**Достижимость проверяй и по коду.** Валидация в `src/**` отсекает часть
состояний до всякой проверки корпуса: пример, предъявляющий такое
состояние законным, описывает вход, который система отвергает. Обратное
тоже находка — правило, которое код исполняет, а корпус не записывает.

## Формат находки — сокращённо

Вопрос → грунт (если торговый) → счётно/цитаты носителей (`файл:строки`)
→ почему гейтит → уровень пробела (предмет / носитель / доказательство)
→ целевой док → ожидаемый владелец → трассировка → варианты с ценой →
ярлык исхода → ярлык дефицита.

**Гейтит** = мешает писать корректный код по концепции. Форма,
именование, полнота перечней — прочее, если не меняют поведения.

## Выход

прочих), стадия остановки обхода, вердикт линзы, вынос пользователю (если
дефицит `подтверждение`).

гейтящих, сколько прочих, одной строкой каждый гейтящий узел, вердикт.

вход сигнала C2 детектора стагнации.

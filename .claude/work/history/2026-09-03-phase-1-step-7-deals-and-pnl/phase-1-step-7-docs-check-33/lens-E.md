## Находки

### E1. `spec-run.sh` на штатной среде проекта отказывает кодом 1 («есть расхождения») вместо 2 («прогон не состоялся»)

- **Вопрос.** Базовый гейт спек (`bash tools/spec-run.sh`) при системном
  отказе запуска JVM-раннера возвращает код 1 — код «измерено, дефекты
  есть», — нарушая собственный контракт трёх исходов.
- **Счётно.** Прогон из Git Bash на Windows со штатным `TMPDIR=/tmp`:
  `mktemp -d` в `tools/spec-runner-env.sh:48` возвращает POSIX-путь
  (`/tmp/tmp.XXXX`); `javac -d` его переваривает (MSYS-конвертация
  одиночного аргумента), а склейка `-cp "$SPEC_CLASSES;$CP"`
  (tools/spec-runner-env.sh:59-60) — нет: java печатает
  `Could not find or load main class com.example.tradingbot.spec.Spec`
  и возвращает **1**; `exec` в `tools/spec-run.sh:27` передаёт код
  наружу. Воспроизводимо дважды. С
  `TMPDIR="$(cygpath -m "$LOCALAPPDATA/Temp")"` тот же прогон зелен
  (0, 545 примеров).
- **Почему гейтит.** Контракт инструмента (шапка `tools/spec-run.sh:16-19`)
  обещает: 2 — «ПРОГОН НЕ СОСТОЯЛСЯ (… раннер не собрался)». Правило
  «Измерительная команда отказывается, когда мерить нечего»
  (`.claude/processes/roadmap-step-execution.md` §«Измерительная команда
  отказывается, когда мерить нечего») требует отделять системный отказ от
  расхождения. Здесь отказ не молчалив (stderr виден), но код возврата —
  ровно «измерено, дефекты есть»: потребитель кода возврата (гейт, CI,
  скрипт) прочитает «спеки разошлись» на здоровом корпусе. Обратная
  ловушка тоже жива: backlog §«Средовой дефицит…» клеймит «Переносимость
  инструментов — СНЯТА», фактикой это опровергается.
- **Уровень пробела:** доказательство (контракт кода возврата не
  доказан на оси «раннер собрался, но не запустился»; батарея осей у
  spec-runner-env отсутствует для этой ветви).
- **Класс:** `ИЗМЕРЕНИЕ`.
- **Целевой док:** `tools/spec-runner-env.sh` (нормализация
  `SPEC_CLASSES` через `cygpath -m` тем же ходом, что `SPEC_ROOT` и
  jar-пути) + строка backlog «Переносимость инструментов — СНЯТА»
  (клейм опровергнут фактикой).
- **Ожидаемый владелец:** `code-writer` (инструментальная правка).
- **Трассировка:** прогон spec-run → exit 1 при ClassNotFoundException →
  чтение spec-runner-env.sh → jar-пути и SPEC_ROOT конвертируются
  `cygpath -m`, `SPEC_CLASSES` — единственный неконвертированный →
  контрольный прогон с Windows-TMPDIR зелен.
- **Варианты:**

| Вариант | Что делает | Цена |
|---|---|---|
| конвертировать `SPEC_CLASSES` `cygpath -m` в env-скрипте (крен) | тот же ход, что для остальных путей той же оснастки | одна строка; контекстная связность 0 |
| ловить исход java и маппить незапуск в код 2 | честный контракт при любой причине незапуска | сложнее: парсинг stderr, хрупко |
| объявить среду Git Bash неподдерживаемой | ничего не чинит | опровергается домом фактов среды (контур гоняется из Git Bash) |

- **Ярлык исхода:** `выводимо` (крен — первый вариант; правка
  инструментальная, поведения спек не меняет).
- **Ярлык дефицита:** дефицита нет — закрыто прогоном (фактика
  предъявлена, правка механическая).

- **Вопрос.** Детектор указателей на дома величин (`py -3
  tools/spec-pointer-check.py`) на текущем корпусе возвращает 1 и
  печатает 42 дефекта — **все** в `.claude/work/progress/
  phase-1-step-7-docs-check-{26..32}/**` и `...gaps-close-{27,28}/**`
  (отчёты закрытых прогонов, поимённо: `lens-*.md`, `cc-verify.md`,
  `node-H*.md`, `critique-H*.md`); в `docs/**` дефектов 0.
- **Счётно.** Вывод прогона 2026-08-31: «указателей на величины
  проверено: 516; ВЕДУТ НЕ В ДОМ: 42», из них ~28 — «имени нет ни
  величиной, ни операндом — величина снята или переименована», ~14 —
  «дом величины — другая спека». Все 42 адреса — файлы прошлых
  итераций шага (архив по назначению; их адреса описывают корпус
  своего момента: `stateFrom`, `expectRefusal`-величины,
  переименованные при закрытиях).
- **Корень — в коде инструмента, и это средовой дефект класса, уже
  описанного у соседнего детектора.** Детектор **по построению**
  исключает архивные каталоги: `tools/spec-pointer-check.py:64`

  строки 161-162 применяют его как
  `if not any(skip in '/' + path for skip in SKIP)`. На Windows
  `glob.glob(..., recursive=True)` возвращает пути с `\`

  встречается — SKIP мёртв, архивные отчёты прогонов входят в область,
  детектор красный всегда. Тот же механизм разделителя путей, что у
  `anchor-check` (backlog §«Средовой дефицит автономного RUN тестов
  (контур source-api)»: «индекс путей `\` против `/`-адресов»), но у
  **другого** инструмента — в backlog он не назван, и батарея осей
  детектора (12 осей, все зелёные) эту ось не покрывает: фикстуры
  строятся `os.path.join` и на POSIX-разделителе дефект не
  воспроизводится, прогон на Windows «доказывает» оси и тут же даёт 42
  ложных дефекта на здоровом корпусе.
- **Почему гейтит.** Код возврата 1 детектора из мандатного набора
  прогона перестаёт быть сигналом: настоящий дефект указателя в

  §Ссылки «переименование величины ловится прогоном» на этой среде не

- **Уровень пробела:** доказательство (ось «SKIP отфильтровывает
  архив» не имеет пробы на Windows-форме пути; полнота письменных форм

- **Целевой док:** `tools/spec-pointer-check.py` (нормализация
  разделителя до `/` перед SKIP-сверкой + ось батареи на Windows-форму

- **Ожидаемый владелец:** `code-writer`.
- **Трассировка:** прогон → 42 дефекта, все в `progress/` → чтение

### E6. Команда вывода перечня фаз режет предмет позиционно (`head -4`) — рост перечня фаз не будет замечен ни командой, ни сверкой

- **Вопрос.** `tools/derive/phase-entry-policy-matrix.sh:13-14`:

  позиционно, а не признаком «значение перечня».
- **Счётно.** Прогон без `head -4` даёт BULL_TREND, BEAR_TREND, RANGE,
  UNKNOWN, UNKNOWN; `head -4` спасает сегодня — и молча ломается
  завтра: пятая фаза в перечне (или новый `A-Z_`-код в прозе секции
  до перечня) даёт неверный набор фаз **без отказа**; объявленный
  перечень популяции (16 пар) при этом совпадёт с искажённо-выведенным

  перечня, не предмет).

  предмет («значения енума `Type`»). Самоприменимость: требование
  процесса не применено к артефакту машины, введённому тем же
  дизайн-проходом.
- **Уровень пробела:** доказательство.
- **Класс:** `ИЗМЕРЕНИЕ`.
- **Целевой док:** `tools/derive/phase-entry-policy-matrix.sh`

  `\`X\`, \`Y\`, …` §«Енум `Type`» либо дедупликация с сохранением

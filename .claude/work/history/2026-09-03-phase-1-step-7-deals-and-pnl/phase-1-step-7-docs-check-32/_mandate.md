## Что изменилось с прошлого прогона (без деталей находок)

Между прошлым прогоном и этим прошёл **дизайн-проход смены концепции
полноты закрытия** и закрытие двенадцати узлов. Существенно для тебя:

- **у каждого гейтящего узла закрытие обязано предъявить популяцию** —
  перечень состояний и носителей, где правило обязано выполняться, —
  **до** правки; у каждого члена ровно один записанный исход
  (`.claude/skills/closure-population.md`);
- **в спеках появился ключ `populations`:** перечень членов по осям
  `keys`, фильтр участия `where`, недостижимый член предъявляет
  контрпример. Раннер даёт три вида расхождения: непокрытый член,
  недостижимость без контрпримера, пример вне перечня. Оси механизма
  доказаны батареей `spec-mutation-check.sh` (18-24);
- **базовый гейт спек ловит дубль ключа JSON** строгим разбором файла
  (ось 17a);
- **реестр снятых редакций** (`tools/retired-check.py`) получил у каждой
  записи **шаблон пришедшей редакции** и **популяцию носителей**; область
  свипа расширена до объявленной;
- **писатель причины закрытия сделки назван по ребру**, перечни причин
  сведены к достижимым значениям, `shutdownReason` получил второго
  писателя на ребре в `ERROR`;
- **судьба встроенной защиты** выводится из пары «терминален ли родитель»
  + «есть ли налив», а не из присутствия элемента в снапшоте; заведена
  вторая ступень исхода и per-source форма пятого источника цикла добычи;
- **заведено правило однократности шага стратегии на эпизод транша**;
- **порядок двух рубежей охраны знаменателя** переписан по порядку
  прохода, отказ сайзинга по стороне уровня объявлен отказом шага;
- **ступень инструментной лестницы** у триггера «исчерпание бюджета»
  выводится осью, а не назначается;
- **эталон стал операндом** спеки прохода; область предиката первичного
  уровня сужена;
- **дедуп `STATE`-отчёта** сведён к стоящему состоянию объекта, поглощённый
  ручной вызов заводит строку по паре операндов;
- **реестр предусловий** перестал держать сводные счёта; кейс п. 7 пишет
  исход и на ветви пропуска.

**Это не индульгенция:** правки проверяй как любой другой текст. Часть из
них вводилась быстро и уже давала расхождения с кодом.

## Инструменты, которыми нужно пользоваться

Восемь команд корпуса (из корня репозитория):

```
bash tools/spec-run.sh                        # примеры исполняются, сходятся, популяции покрыты
bash tools/spec-mutation-check.sh             # величина что-то проверяет
python3 tools/spec-scope-check.py docs/spec   # области видимости и копии формы
python3 tools/spec-pointer-check.py           # указатель ведёт в дом величины
python3 tools/anchor-check.py                 # §-адреса .claude/**
python3 tools/retired-check.py                # снятая редакция и популяция носителей
bash tools/preconditions-check.sh             # реестр == план == фактика
mvn -o test-compile                           # дерево собирается
```

`mvn` — из кэша wrapper'а, JDK 25 в `~/.jdks/corretto-25`; действующие
пути и лаунчер Python — дом фактов среды
(`.claude/tests/source-api/okx/code-preconditions.md` §«Среда контура —
проверено прогоном, не выведено»). **Лаунчер проверь прогоном, а не
шапкой.**

**Ловушки среды, дающие ложно-зелёный результат:**

- `git diff` без `HEAD` не видит застейдженного и возвращает ноль на
  любом состоянии — верная форма `git diff HEAD -- docs/`;
- `grep -P` без `LC_ALL=C.UTF-8` падает с ошибкой в stderr и печатает
  **пустой** список, который читается как чистый свип;
- проба, привязанная к **форме записи**, а не к смыслу, зеленеет от
  переформатировки цели, ничего об этом не сообщая.

**Мутационная проверка обязательна там, где ты утверждаешь, что
конструкция что-то ловит:** подмени величину константой во временной
копии (`SPEC_DIR=target/probe-<линза> bash tools/spec-run.sh`) и покажи,
падает ли прогон. Зелёный прогон на мутации — находка. Каталог пробы
удаляй. То же для энфорсеров и для **популяций**: сними пример,
покрывающий члена, и покажи, что прогон падает; добавь члена без примера
и покажи, ловится ли это.

**Инструмент проверяется встречной формой предмета.** Каждый детектор
объявляет в шапке письменные формы. Найди в корпусе форму, которой в
перечне нет, и покажи, что детектор её не видит.

**Достижимость проверяй и по коду.** Валидация в `src/**` отсекает часть
состояний до всякой проверки корпуса. Обратное тоже находка — правило,
которое код исполняет, а корпус не записывает.

## Формат находки — сокращённо

Вопрос → грунт (если торговый) → счётно/цитаты носителей (`файл:строки`)
→ почему гейтит → уровень пробела (предмет / носитель / доказательство)
→ целевой док → ожидаемый владелец → трассировка → варианты с ценой →
ярлык исхода → ярлык дефицита.

**Гейтит** = мешает писать корректный код по концепции. Форма,
именование, полнота перечней — прочее, если не меняют поведения.

дефицит `подтверждение`).

Отчёт пиши **в файл**, в терминал верни короткую сводку: сколько
гейтящих, сколько прочих, одной строкой каждый гейтящий узел, вердикт.

узлы, и **сколько гейтящих — следствия конструкций, введённых последним
закрытием** (перечислены в §«Что изменилось с прошлого прогона»). Это
вход сигнала C2 детектора стагнации.

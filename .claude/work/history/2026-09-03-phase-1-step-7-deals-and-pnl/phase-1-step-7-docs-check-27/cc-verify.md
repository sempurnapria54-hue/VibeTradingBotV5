### Уточнение к V3 — «поле доехало» и «механика доехала» суть разные глубины

V3 подтверждает, что `Exchange.consecutiveLossCount` и `Exchange.riskBase`
**существуют** в модели и что их писатель **назван** в правилах
(`docs/rules/loss-streak-halt.md:66-67`, `docs/rules/risk-policy.md:84-86`).
Он назван **ролью** — «финализация сделки той же транзакцией, что и
терминал». Проверка следующего слоя:
`grep -rn "consecutiveLossCount\|riskBase" docs/components/` → **ноль
вхождений** при пяти существующих исполнителях терминала
(`FinalizeDealEntryExecutor`, `FinalizeDealExitExecutor`,
`MarkDealClosedExecutor`, `MarkDealEmergencyClosedExecutor`,
`MarkDealErrorExecutor`), каждый из которых перечисляет свои побочные
эффекты явным списком.

**Это не опровергает V3, а показывает границу его глубины:** V-слой A
проверял «доехала ли правка до своего носителя», и по этому вопросу
ответ «да». Вопрос «доведена ли механика до компонента, который её
исполняет» — следующая глубина, и по нему ответ «нет» (находка G5 линзы
A, подтверждена независимо этим грепом). Ровно это различение введено в
процесс сегодня как критерий глубины закрытия
(`.claude/processes/roadmap-step-execution.md` §«Гейтящий узел
закрывается до исполнимой глубины, а не до формулировки»,
`.claude/decisions/gating-node-closure-depth.md`): пункт «носитель
назван и существует» выполнен, пункт «механика прописана: кто читает,
когда срабатывает, чем резолвится» — нет.

**Итог V-слоя A: одиннадцать из одиннадцати несущих правок закрытия
доехали до своих носителей** (глубина «носитель»; глубина «механика» —
см. уточнение выше и узлы прогона). Это существенно для детектора: класс
«непроведённые следствия закрытия», давший ⅔ гейтящих находок в прогонах
`_19`…`_25`, в этом прогоне **по проверенным правкам не воспроизводится**.

### N1. Клейм «27 битых входящих из `src/`» не сходится ни с одним счётом своего же объекта

- **Вопрос.** Сколько на самом деле ссылок из `src/` указывает в снятый
  каталог `docs/decisions/`, и почему рабочий файл называет число, которое
  не получается ни одним способом счёта?
- **Цитаты (носители).** `.claude/work/backlog.md:731-733` («**27 битых
  входящих ссылок из `src/`** на снятый каталог `docs/decisions/`
  (15 различных доков, 44 файла Java с упоминаниями)»).
- **Проверка (воспроизводимая).**
  `grep -rn "docs/decisions/" src/ | wc -l` → **51**;
  `grep -rl "docs/decisions/" src/ | wc -l` → **44**;
  `grep -rho "docs/decisions/[a-z0-9-]*\.md" src/ | sort -u | wc -l` → **15**;
  уникальных пар «файл + цель» → **51** (ни одна строка не несёт двух
  ссылок). Каталога `docs/decisions/` не существует.
- **Что ломается.** Два числа из трёх в той же скобке верны (15 доков,
  44 файла) — а несущее число неверно почти вдвое. Клейм адресован
  исполнителю `CODE` («правится при касании файла»), то есть занижает
  объём работы, который тот планирует. Это ровно класс «счёт правится
  вместе с перечнем, из которого выведен».
- **Целевой док.** `.claude/work/backlog.md` §«Гигиена, заведённая
  прогоном `_26`» — заменить счёт на воспроизводимый («51 ссылка в 44
  файлах на 15 несуществующих доков») либо на перечень.
- **Ожидаемый владелец.** `knowledge-curator`.
- **Трассировка.** CC: проверка «доехала ли гигиена `_26`» → греп по
  `src/` → три счёта, ни один не даёт 27.
- **Варианты.** Развилки нет — дефект записи, чинится курационно.
- **Ярлык исхода.** `выводимо`.
- **Ярлык дефицита.** Дефицита нет — закрыто прогоном.
- **Гейтит?** Нет (гигиена).

### N2. Предикат полноты контекста не отличает «всё загружено» от «коллекция пуста» — и его собственная нота о консервативном направлении ошибки ложна

**Происхождение — верификация G1 линзы A.** Линза нашла расхождение
объёмов (транши грузятся «все нетерминальные», ноги — «все по всем
траншам»; к штатному терминалу нетерминальных траншей нет). Механизм она
назвала как «`legsComplete` ложен ⇒ расчёт запрещён». Проверка механизма
**опровергла именно эту половину** и вскрыла дефект **шире**, чем
заявленный.

- **Вопрос.** Что даёт предикат полноты контекста, когда коллекция
  загружена **пустой** — отказ расчёта или молчаливое «полно»?
- **Проверка (воспроизводимая).**
  `src/test/java/com/example/tradingbot/spec/Spec.java:204-205,213` —
  агрегат `all` инициализируется `true` и над пустой коллекцией цикл не
  исполняется ⇒ возвращает **`true`**, не `false`.
- **Цитаты (носители).**
  - `docs/spec/deal-context-load.json:27-53` — **все пять** конъюнктов
    (`episodesComplete`, `tranchesComplete`, `legsComplete`,
    `attachedComplete`, `algoComplete`) построены на `op: "all"`;
  - `:55-57` — `contextComplete` = их конъюнкция;
  - `:58-62` — `computationAllowed` = `contextComplete` с нотой
    «**Неполный контекст не даёт заниженного числа: он даёт отказ.
    Направление ошибки — консервативное**»;
  - `docs/components/DealContextService.md:26-27` — «Всё, по чему
    считаются персистируемые числа сделки, грузится целиком, иначе
    **число выходит заниженным молча**».
- **Что ломается.** Нота гарантирует ровно то, чего конструкция не
  даёт. Пустая коллекция проходит предикат как полная, `computationAllowed`
  истинен, а числа, считаемые суммой по этой коллекции (числа риска,
  экспозиция транша, омиссионный член допуска, покрытие защиты),
  выходят **нулями**. Направление ошибки не консервативное, а
  **разрешающее**: занижённый риск и заниженный допуск — в сторону
  «всё в порядке». Дефект **общий для всех пяти конъюнктов**, а не
  только для ног, то есть шире расхождения объёмов, найденного линзой.
- **Почему прогон примеров это не ловит.** Семь примеров спеки покрывают
  «одна из N не загружена» (`:116,133,150,165,183,198,210`); примера с
  **пустой** коллекцией нет ни одного. Зелёный прогон здесь ничего не
  доказывает — случай не предъявлен.
- **Целевой док.** `docs/spec/deal-context-load.json` (каждый конъюнкт
  дополняется требованием непустоты — `exists`-операция в раннере уже
  есть, `Spec.java:214`) + `docs/components/DealContextService.md`
  §«Объёмы загрузки» (нота о направлении ошибки).
- **Ожидаемый владелец.** `solution-designer`.
- **Трассировка.** CC: верификация несущего механизма G1 → чтение
  реализации агрегата `all` в раннере → проверка, распространяется ли
  на остальные конъюнкты → проверка, есть ли пример на пустоту.
- **Варианты.**

| Вариант | Что делает | Названная цена |
|---|---|---|
| (а) каждый конъюнкт = `all(loaded) && exists(коллекция)` | предикат перестаёт быть истинным на пустоте | цена — коллекция, законно пустая (сделка без отдельных условных заявок), потребует явного разрешения пустоты; то есть непустота требуется не у всех пяти, а у названных |
| (б) отдельный предикат «объём предъявлен» рядом с «всё загруженное загружено» | разводит два разных вопроса | больший след: вторая величина на каждый конъюнкт |
| (в) снять ноту о консервативном направлении | запись приводится к фактике | **не проходит**: чинит запись, а не дефект; число по-прежнему считается на пустоте |

- **Крен.** (а), с явным перечнем коллекций, чья пустота законна.
- **Ярлык исхода.** `варианты-с-креном`.
- **Ярлык дефицита.** дефицита нет — закрыто прогоном.
- **Гейтит?** **Да.** Числа сделки — предмет шага 7, и предикат,
  который их охраняет, охраняет не в ту сторону.

**Следствие для G1.** Находка линзы остаётся верной по существу
(расхождение объёмов реально), но её механизм переписывается: не «расчёт
запрещён», а «расчёт разрешён на пустом множестве». Узел один, механизм
общий — закрывать их вместе.

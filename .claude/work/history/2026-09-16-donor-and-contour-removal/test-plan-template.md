# Шаблон: документ тест-кейсов

## На какой вопрос отвечает этот файл

Каков формат докового файла тест-кейсов (план и бланк отчёта прогона).

## Назначение

Универсальный шаблон документа кейсов, **один на все предметы и
уровни**: чёрный ящик сервиса, юнит чистой логики, сквозной прогон,
контур API источника. Вход для `tester` на под-шаге описания кейсов
(`.claude/skills/test-design.md`). Готовый документ кладётся в
`.claude/tests/{testType}/{subject}/plan.md`.

## Структура: предмет → кейсы → таблица

Документ построен **по предметам**, прямой маппинг на код (**класс на
предмет, тест на кейс**):

- **предмет — заголовок** (`## S3. <операция или событие сервиса>`,
  `## U1. <класс чистой логики>`, `## E2. <тропа>`; у контура источника —
  `## Mn. <метод сырого клиента>`);
- **кейс — подзаголовок** (`### S3.2 …`): прямой кейс / **каждый**
  негатив / **каждый** вариант дискриминатора / цепочка — отдельным
  подзаголовком;
- **в каждом кейсе — своя таблица**.

Эти же таблицы — **бланк отчёта прогона**: на прогоне заполняется колонка
«Факт», структура не пересобирается.

## Форма документа (скелет)

- **На какой вопрос отвечает этот файл** — «Как проверяем `{subject}` на
  уровне `{testType}`?».
- **Скоуп** — что покрывает документ: уровень концепции тестирования,
  поверхность предмета (перечень операций, событий, методов), триггер
  (шаг «Тесты» фазы / новая биржа / новый эндпоинт / изменение контракта).
- **Граница** — чего предмет не делает намеренно (по доку сервиса), и
  потому кейсов не имеет.
- **Инвариант полноты** — перечень единиц поверхности с отметкой «покрыт
  кейсами такими-то»; у контура источника сверяется с колонкой покрытия
  манифеста.
- **Среда прогона** — что нужно (база, брокер, соседи-заглушки, внешний
  источник demo); у живых контуров — non-prod, prod вне контура.
- **Недостижимое** — кейсы, описанные и не прогоняемые: причина и условие
  возврата.

## Форма кейса (скелет)

**Кейс — подзаголовок `###` предмета, тело — одна таблица.** Кейс
самодостаточен: ставит своё предусловие, проверяет своё, убирает за собой.

- **Шапка кейса** — уровень, предмет, предусловие-состояние, среда,
  пометка достижимости; для варианта — какой именно.
- **Тело — таблица, строка = вход кейса.** Колонки: **предусловия** |
  **вход** (запрос, событие, тик, вызов) | **ожидаемые выходы — все,
  включая отсутствие** (ответ, запись, событие, лог, метрика, вызов
  наружу; «события нет», «строка не меняется») | **чем подтверждается**
  (док, спека, решение; незадокументированное — находка, не ожидание) |
  **Факт** (пусто до прогона — это и есть бланк отчёта).
- **Негатив — на каждую единицу поверхности** по порождающим категориям
  (`test-design`): битый вход, отсутствие обязательного, значение вне
  домена, несуществующий идентификатор, дубль, повтор терминальной
  операции, состояние-конфликт, отказ соседа, отказ доступа.
- **Вариант дискриминатора — отдельным кейсом:** прямой кейс варианта +
  применимый негатив.
- **Уборка кейса** — завершающие строки той же таблицы: что снимает
  поставленное состояние (у живого контура — teardown на бирже).

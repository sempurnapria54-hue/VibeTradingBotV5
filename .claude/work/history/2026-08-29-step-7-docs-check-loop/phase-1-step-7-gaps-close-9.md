## 4. Проверка H8 — тропы в терминал в обход подсчёта

Инвариант пользователя: одна живая сделка на инструмент; новая не
открывается до терминала предыдущей; терминал требует подсчёта.
Проверено по носителям (`lifecycles/Deal.md`, `SystemActionExecutor.md`,
`ErrorHandler.md`, `pnl-finalization-mechanics.md` §5a) и коду
(контроллеров сделки в `src/` нет — ручного перевода статуса не
существует; `ERROR → CLOSED` запрещён).

**Тропы в обход подсчёта существуют — обе ратифицированные:**

1. **`EMERGENCY_CLOSED` с «неисчислимо»** (провенанс (b) отказа расчёта):
   жёсткий отказ чтения приравнен к «недоступно», терминал ставится без
   числа — ратифицированная асимметрия троп (реш.3/§5a; kill-switch-тропа
   ведёт сюда же через `ERROR`).
2. **No-entry `CLOSED`** из `PRECHECK` (`ENTRY_CONDITION_EXPIRED` /
   `RISK_CONTROL`) — терминал без подсчёта, но и без движений (позиции и
   bills нет; окно не открыто).

**Следствие для ветки «персистит, но не линкует»:** на no-entry-тропе
bills не собираются вовсе; на штатной тропе гейт держит сделку живой до
конца подсчёта. Единственный потенциальный производитель незалинкованных
строк — эмиссия `REFRESH_BILLS_COMMAND` **при пустом `billsWindowEnd`**:
(а) на аварийной тропе — `ErrorHandler.md` держит «опц.
`REFRESH_BILLS_COMMAND`» в best-effort добыче, эмиссия при пустом `end`
носителями не запрещена; (б) на штатной — порядок звеньев внутри цикла
добычи (`SystemActionExecutor.md` §`REFRESH_DEAL_CONTEXT_ACTION`) не
специфицирован. **Предложение (крен (3) отчёта, к валидации):** предикат
эмиссии bills-звена — только при непустом `billsWindowEnd`; тогда ветка
исчезает на обеих тропах, клейм модели верен как есть (цена на аварийной
тропе — разбивка при недобытом факте закрытия не собирается; это уже
названная цена узла 1). До валидации носители (ветка в
`RefreshBillsExecutor.md`, клейм в `DealCashFlow.md`) не правились.

## 5. Проверка H16 — покрытие `CloseReason` троп без входа

Дискриминатор членства R-выборки — `CloseReason` (решение пользователя:
на no-entry-`CLOSED` пишется `0`, членство ключуется причиной). Проверка
покрытия каждой тропы без входа (`Deal.md` §Енумы, `lifecycles/Deal.md`,
`PrecheckHandler.md`, `EntrySubmittedHandler.md`):

| Тропа без входа | Причина | Покрытие |
|---|---|---|
| Истечение условия в `PRECHECK` | `ENTRY_CONDITION_EXPIRED` | ✅ покрыта |
| Риск-блок в `PRECHECK` | `RISK_CONTROL` | ⚠️ **смешивает**: то же значение — штатное risk-control-завершение сделки **с входом** (в R-выборке). Причина не разделяет «вход был / не был» — дискриминатор членства на ней не работает |
| Неисполненный ордер из `ENTRY_SUBMITTED` (условие истекло, fills нет; `plannedRisk` уже записан) | — | ❌ **своей причины нет**: `ENTRY_CONDITION_EXPIRED` заявлен «в PRECHECK до live risk»; сама тропа `ENTRY_SUBMITTED → CLOSED` без входа в lifecycle не описана (описан только recovery в `EXIT_PENDING` при закрывшейся позиции) — без причины сделка попадёт в выборку нулём |

**Предложения (к решению пользователя/владельцев, не финализировано):**
(а) для риск-блока без входа — активировать `ENTRY_RISK_BLOCKED` (в
енуме уже есть, помечен «не используется») либо развести `RISK_CONTROL`
пер-статусно; (б) для `ENTRY_SUBMITTED`-экспирации — расширить
`ENTRY_CONDITION_EXPIRED` на «вход не состоялся» (снять PRECHECK-скоуп)
либо своя причина; тропу `ENTRY_SUBMITTED → CLOSED` (отмена
неисполненного ордера) описать в lifecycle. Правки вводят/разводят
семантику enum — по новому правилу шаблона не `выводимо` при ступени
ниже `Автономии`.

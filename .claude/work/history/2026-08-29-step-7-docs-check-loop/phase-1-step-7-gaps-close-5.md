## Закрыто (по спискам цитат — правка A)

### H2 — реакция на несвежесть: мягкая, kill-switch снят

Решение (свалидировано): запрет новых входов по инструментам протухшей
группы + `AnomalyReport`; живые сделки доживают под своим стопом;
kill-switch по несвежести **не применяется**. Довод — радиус ущерба
ограничивает и реакцию: ставка участвует только в сайзинге нового входа,
`R` живой сделки задан стопом, `resultProfit` считается из фактов.

Цитаты находки:

- `error-handling-policy.md:71-73` (критерий радиуса) — **не требует
  правки**: опора решения; рядом добавлен §«Радиус ущерба ограничивает и
  реакцию» + kill-switch-снятие в кейсе.
- `per-trade-risk-policy.md:89-90`, `:136-138` (ставка — прогноз сайзинга)
  — **не требуют правки**: опора (задают радиус). *Сверх списка:*
  §Null-политика того же дока нёс старую реакцию (kill-switch + ручное
  снятие) — **правлен**.
- `risk-creating-entry-protection.md:32-36` (`R` задан стопом на бирже) —
  **не требует правки**: опора.
- `instrument-hold.md:68` («Реакция и снятие — общие для этого файла») —
  **правлено**: реакции разведены по классу триггера; для несвежести —
  §«Реакция — мягкая», для риск-триггеров уровня 3 — прежний состав.
- `KillSwitchExecutor.md:45-47` (закрытие по рынку) — **не требует
  правки**: kill-switch остаётся исполнителем реакции риск-триггеров;
  к несвежести по политике не вызывается.

Прочие носители реакции (найдены грепом, вне списка цитат):

## Инспекция `src/` (задача 3, вход для H5 — не финализирован)

Чтением кода: `Instrument.java:89-120` — енум `Instrument.Status` содержит
**8 членов**, среди них **и `HOLD`, и `TRADE_BLOCKED`**:

- `HOLD` — «Инструмент придержан (не вовлекается в онбординг)» —
  **онбординговый** статус;
- `TRADE_BLOCKED` — safety-холд; javadoc прямо: «Отдельный смысл от
  онбординг-`HOLD`», «снятие — вручную в `ACTIVE`».

⇒ по развилке задачи: **расходятся доки** — `Instrument.md:51` перечисляет
7 членов без `TRADE_BLOCKED`, доковый инвентарь енума неполон. Аппарат
шага 6 пишет `TRADE_BLOCKED` согласно коду; клауза `instrument-hold.md`
«`Instrument.Status = HOLD`, енум уже есть» опиралась на **другой**
(онбординговый) статус — «HOLD есть в енуме» верно буквально, но это не
safety-статус. Дефект смещается в **доковый инвентарь**, не в аппарат.
Попутно: код (`EntryScannerJob.java:38-39`, `DealOrchestratorJob.java:94`)
несёт enforcement по `TRADE_BLOCKED` (инструмент исключён выборкой
`ACTIVE`; каскад биржи) — материал для финализации H5/H10-enforcement
следующим прогоном.

## Закрытие по пробелам

### H1 (N9 fee-wiring) — ЗАКРЫТ. Гейт `CODE` снят

**Гейт закрылся без новой фактуры от биржи:** `groupId` **уже приходит**
`/public/instruments` («instType and groupId should be used together to
determine a trading fee group» — офдок, Get instruments). Дыры в фактуре не
было — был **отброшенный ключ**: отброс сделан до changelog OKX 2025-11-21,
который ввёл `groupId` в Get instruments и `feeGroup` в Get fee rates,
задепрекейтив флэт `maker`/`taker` для SWAP. Отброс снят.

**Аспект 1 — дом ставки: (a) native `OkxTradeFeeResponse` + маппинг.** Ось
резолва — **пара (`instType`, `groupId`)**, не голый `groupId` (одно число
значит разное при разном instType). Перечень групп **не хардкодится** — офдок
сам предписывает «actual return values shall prevail» (его enum-список неполон
относительно его же примера).

**Хранение — ставка в своём масштабе (уточнение пользователя; ревизует
хранение, не seam).** Фактура подтвердила, что ставка **group × tier-level**, а
не инструмент-level — то есть (c) был прав по факту, но его правильный объём —
**место хранения**, не поверхность чтения:

- новая модель **`TradeFeeRate`** — **одна строка на группу**, таблица
  `trade_fee_rates` с историей; **не копия на каждом инструменте** (копия —
  заготовка под расхождение: при смене тира N копий, N шансов отстать);
- на навесе инструмента — **только ключ** `externalFeeGroupId`; поля
  `externalTakerFeeRate`/`externalMakerFeeRate` с навеса **сняты**;
- **seam не двинулся** — `SizeCalculator`/`RiskValidator` читают ставку там же,
  через `CalculationContext.instrumentExternalRules`; аксессоры гидрируются по
  ключу группы;
- **запись:** значение изменилось → новая строка; совпало → `modifiedAt`
  последней. Даёт **историю** (сколько строк — столько раз скакал тир) +
  **прямой измеритель свежести** (`modifiedAt` двигается при каждом успешном
  чтении ⇒ его возраст = время с последнего успеха). Рост — единицы строк в год;
- пишутся `level` и `ts` из ответа — **датчик такта пересчёта тира**: офдок его
  **не специфицирует** (а страница комиссий — JS-рендер, не читается), поэтому
  на вопрос отвечают собственные данные, а не догадка о поведении OKX.

**Аспект 2 — такт: (A′) чтение раз-на-тик.** Один вызов
`trade-fee(instType=SWAP)` до цикла → карта групп → per-instrument матч. Ось
запроса — группа, поэтому лимит (5 req/2 s по User ID) неощутим; **один
писатель** навеса. Отвергнуты: (B) отдельная джоба — два писателя в один навес,
гонка RMW (`JobExecutionGuard` per-job); (C) чтение на входе — точка отказа в
момент входа ради свежести ценой ~5 bp против стопа 1-2%.

**Снятая посылка (важно).** Тезис «съехавшая ставка вылезет на сверке bills↔net
аномалией неизвестной природы» **не подтвердился**: сверка (реш.5) сравнивает
Σ`balChg` из bills с net из positions-history — **оба факта биржи**; прогнозная
ставка в ней **не участвует** (верифицировано грепом). Устаревшая ставка бьёт
только в точность сайзинга ⇒ **Аспект 2 `CODE` не гейтил** — это инженерная
чистота, не корректность числа.

**Холд по несвежести.** Возраст `modifiedAt` > порога (конфиг, стартово **24
ч**) → холд биржи, сделки доживают. Довод: при часовом такте 24 ч = **24
неудачи подряд** — поломка интеграции (права/эндпоинт/подпись), не сетевая
икота. Отдельный счётчик отказов не нужен — таблица его уже выражает.

**Аспект 3 — null-политика (пробел, найденный интегратором; в задании его не
было).** Реш.4 не задал поведение при нерезолвящейся ставке → `takerFeeRate()`
= null → прогноз комиссии **молча выпадал** (ровно тот отказ, ради которого H1
гейтил `CODE`). Принято: (i) `updateFromSnapshot` с **IGNORE-null** (не
затирать последнюю известную); (ii) ставки не было никогда → **реджект
`FEE_RATE_UNAVAILABLE`**. Fallback из конфига отвергнут: подставленное число
выглядит фактом, не будучи им; заниженная ставка → позиция больше положенной —
та же болезнь, что H6/H2. Цена реджекта — пропуск одной сделки с громкой
причиной; цена fallback'а — тихо превышенный риск на каждой.

**Инвариант organic-base-rates (записан как условие, не примечание).** Запрос
без `instId`/`instFamily` возвращает organic base rates — ставок market-maker
incentive не видно, ответ **валидный, но не тот**. Мы не участники ⇒ base rates
корректны. **Вход в MM-программу требует пересмотра оси запроса `trade-fee`.**
Молчаливое условие — ровно то, на чём горел H1.

### H2-докочасть — native `fee` возвращён в used — ЗАКРЫТ

**Решение:** `fee` → used; `TRADE_FEE`/`REBATE` резолвятся **по нему**, не по
знаку `balChg`; `balChg` остаётся под `amount` и контроль суммы. **Безопасный
суперсет** — корректен при любой гранулярности bills, поэтому не ждёт
рантайм-ответа §AG1.5.

**Разделение ролей зафиксировано явно** — два поля отвечают на разные вопросы:

| Поле | Вопрос | Роль |
|---|---|---|
| `balChg` → `amount` | «сходится ли сумма» | Σ`amount` ↔ net из positions-history |
| `fee` → `externalFee` | «сколько комиссии» | комиссия сделки = Σ`externalFee` |

**Носитель — компонента на строке, не вторая строка** (выведено из
`UNIQUE(external_bill_id)`): разложение комбинированной записи на две
`DealCashFlow` задвоило бы движение в Σ`amount` (сломав сверку) и не имело бы
второго `billId` под ключ. Следствие: при комбинированной записи
realized-pnl-слагаемое = `amount` − `externalFee`; native `pnl` отдельным
носителем не требуется (остаётся unused).

**Правки:** `OkxAccountBillResponse` (`fee` в used + довод), `mapping/DealCashFlow`
(поле, §«Разделение ролей», резолв категории, validation), `domain/other/DealCashFlow`
(поле `externalFee`, enum-пояснения, §Персистентность «одна строка на bill»).

### H5 — `Instant` → `OffsetDateTime` — ЗАКРЫТ

`PositionCloseResult.externalUpdatedAt` выровнен на `OffsetDateTime` по конвенции
типов проекта (`Balance` mapping, `Auditable`, `DealCashFlow.externalTs`).
**Сверх находки:** тот же `Instant` в `OkxPositionsHistoryResponse` §Конвертация
(native-док того же пути) — выровнен, иначе рассинхрон воспроизводился бы с
другой стороны.

### H6 — «пометки достаточно» исправлено на добор числа — ЗАКРЫТ (направление)

Утверждение в реш.3 ревизовано: пометка (`AnomalyReport`/лог) фиксирует **факт**
дыры, но не устраняет **смещение** — null outcome-коррелирован (кучкуется на
аварийной тропе, где крупные убытки), поэтому drop воспроизводит смещение
омиссией и завышает ожидаемость [Vince гл.5 с.63; Tharp формула 6-2, гл.6
с.158-159]. Решение «не ноль» — **верно, не тронуто**.

**Принятое направление:** добор недостающего числа до истечения окна
positions-history (~3 мес; недоступность обычно временна) — null не финальный
вердикт, а отложенный долг. Отвергнуты как основной путь: worst-case импутация,
метрика счёта дыр (годится как дополнение). **Материализация — форвард шага
ожидаемости / фазы 2**; здесь только направление.

### H7 — якорь epsilon переставлен на оборот — ЗАКРЫТ

`max(0.01 settle-ccy, 0.5% от Σ`|amount|`)` — относительный член якорится на
**валовой оборот**, не на `|net|`. Довод: охраняемая ошибка — ошибка
**композиции разбивки**, её масштаб задают валовые потоки, а не их итог.
Привязка к `|net|` ломалась с обоих концов (большой net — глотает дыру; net ≈ 0
при больших потоках — вырождается в ложные аномалии на округлении).
**Провизорность величины сохранена** (калибровка — пользователь/бэктест);
сменился якорь, не калибровка.

### H8 — инвариант settle-ccy принят — ЗАКРЫТ

**Комиссии платятся только в валюте расчёта (settle-ccy, USDT)**; оплата
сторонней валютой (на OKX — скидка за OKB) запрещена конфигурацией, нарушение —
аномалия, а не рабочий режим.

**Дом — `docs/rules/trading-constraints.md`** §Валюта комиссии (реестр
инвариантов контура, куда указывает `trading-configuration-ownership.md`), не
OKX-док: инвариант **source-agnostic**. Формулировка нейтральна к источнику,
довод — **переносимость**: заголовочное число берётся net'ом в settle-ccy,
поэтому издержка вне settle-ccy в него не входит и молча завышает результат —
это свойство **схемы «net в одной валюте»**, а не особенность OKX. Режим
отключается на всех источниках, не патчится per-source.

Cross-ccy guard сохранён — он ловит **нарушение** (конфигурацию сбили / площадка
сменила поведение), а не штатный режим. Формулировки «например комиссия в OKB»,
подававшие режим как ожидаемый, выровнены в 4 доках.

**Детект — только постфактум по `ccy`; проактивного рычага нет** (зафиксировано
прямо в H8, иначе следующий заход пойдёт искать несуществующую настройку).
Проверено против офдока: в OKX API v5 **нет** поля/настройки «платить комиссию
в OKB» (скидка конфигурируется вне API), а `feeType` из `account-config` —
**Spot-only**, на SWAP не применим и рычагом OKB **не является**. Спросить у
источника «в какой валюте будут комиссии» нечем ⇒ инвариант наблюдаем **только**
уже заложенным cross-ccy guard'ом. Это **граница источника, не пробел
проектирования**. Рантайм-наблюдатель — AG3.4/RQ-4.

### Часть 4 — `elpMaker` → `rpiMaker`: проверено, механику не строим

**Проверка дала `unused` — но не по той причине, что предполагалась.**
Исходная посылка: «`elpMaker` — из плоской deprecated-шестёрки, которую мы
обходим». Факт: `elpMaker` лежит **внутри `feeGroup[]`**
(`contracts/trade-fee.md:46`) — то есть в структуре, которую мы **читаем**. Не
потребляем мы его потому, что берём из группы только `taker`/`maker`, а
`elpMaker` — ставка ELP/RPI-программы, в которой мы не состоим (инвариант
organic-base-rates). **Вывод тот же:** unused → **защитную механику не строить**
(«не строить инфраструктуру на пустом месте»), поле корректно названо в
unused-перечне native-дока с пометкой о переименовании и датами.

⚠ **Прод 2026-07-28 — внутри горизонта шага 7** (13 дней), отмечено в
native-доке и `trade-fee.md` как ближний факт, не отдалённый форвард.

**Общее правило записано отдельным решением** —
`docs/decisions/source-model-change-absorption.md`: известное заранее изменение
модели источника **поглощается native-слоем**; домен видит одно стабильное имя;
резолв — **по заполненности, не по дате** (заполненность — наблюдаемый факт и
самокорректируется при сдвиге сроков; дата — утверждение о будущем внешней
системы, которое мы не контролируем, и годится максимум как страховка, если оба
поля придут разом). Ветка `unused` → механику не строить вовсе. Отвергнуты:
переключение по дате, реакция постфактум, протаскивание обоих имён в домен.

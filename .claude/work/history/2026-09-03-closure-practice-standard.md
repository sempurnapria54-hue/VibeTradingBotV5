# Штатная практика закрытия шага

## На какой вопрос отвечает этот файл

Чем закрыта задача «сделать ход закрытия шага 7 штатной практикой».

## Задача

Закрытие шага 7 прошло верно, но верным его сделал **промпт**, а не
процесс: итерации до чистого гейта в одном заходе, парковка
незакрываемого с причиной, вынос держателю только класса
`подтверждение` — всё это было предписано текстом задачи. Требовалось
внести практику в процесс так, чтобы прогон вёл себя так же без
специального промпта. Шаг 8 задачей не затрагивался.

Вход диагностики — три вопроса, вынесенные держателю при открытии шага 8
(радиус жёсткой реакции детекторов; поведение при неполном снапшоте
биржи; гистерезис жёсткой реакции в тиках).

## Диагноз: чего не хватило процессу

| Вынесенный вопрос | Дефицит |
|---|---|
| Радиус жёсткой реакции | Права и критерия хватало — **не было гейта самопроверки выноса**. Текст варианта сам называл концепцию основанием выбора, то есть перебор был свёрнут до выноса |
| Поведение при неполном снапшоте | То же плюс **составная развилка не расщеплена**: концепция снимала один вариант как ослабление П1, оставался только числовой параметр |
| Гистерезис в тиках | **Конфликт двух правил**: концепция запрещает провизорное число риск-аппетита, а корпус и практика назначали провизорные калибровочные числа. Границы класса не существовало — всякое число с порогом читалось как величина держателя |

Сверх того — общий дефицит: **вынос читался как пауза**, и три вопроса
остановили шаг целиком, хотя ни один не гейтил ни обхода корпуса, ни
сверки припаркованного.

## Что правлено

| Носитель | Правка |
|---|---|
| `.claude/processes/roadmap-step-execution.md` §4 | Закрывающий прогон идёт до гейта одним заходом; условий остановки три (третье — «блокер не работа»); шаг закрывается с парковками; срок — величина держателя, объём захода — нет |
| `.claude/rules/parking-address.md` | **Заведён.** Дом практики Д422: адресат парковки — носитель, который позицию оживит; три обязательные величины парковки; признак верного дома |
| `.claude/processes/question-delegation.md` | Три секции: самопроверка выноса и её запись (с механическим признаком невыводимости); граница «риск-аппетит против калибровки наблюдения»; вопрос держателю не останавливает прогон. Правлены две прежние формулировки, читавшиеся как «всякое число — держателя» |
| `.claude/skills/update-roadmap-progress.md` | Шестой предмет гейта выхода из `GAPS_CLOSE_N` — записи выноса держателю; в диспозицию находок добавлена проверка трёх величин парковки |
| `.claude/agents/solution-designer.md` | Встречный рефлекс к «распознал → вынес»: выводимое из концепции к держателю не едет |
| `.claude/templates/docs/gap-report.md` | Ярлык `подтверждение` без записи самопроверки не принимается; калибровочное число ярлыка не получает |

Решения — Д433-Д438 в дайджесте.

## Проверки

Все девять проверочных команд корпуса (в их числе мутационная проба) —
зелены; `src/` не трогался, гейт сборки не применяется. `anchor-check` —
607 адресов, новых неразрешимых 0 (все §-адреса правки разрешились);
`retired-check` — 0 дефектов на 986 живых носителях;
`spec-mutation-check` — 388 величин, переживают нейтрализацию 0.

## Что осталось держателю

Три вопроса шага 8 по новому процессу перераспределяются: два —
владельцу (`solution-designer`), выводимы из концепции; третий —
калибровочное число, назначает владелец с якорем калибровки. Держателю
как `подтверждение` не остаётся ни одного. Разбор — в отчёте задачи;
исполнение — отдельным прогоном шага 8, эта задача его не открывала.

## Правило узла одной фразой

**`statistics` получает данные сама, и у неё названы четыре вещи: подписка
(темы, группа, позиция чтения), признак несомого класса, форма факта и
отметка обработанного; следствие приёма у неё ОДНО — строка факта.**

Уровень пробела — **концепция-стык**
(`.claude/skills/classify-gap-level.md`): предмет связывает больше одного
узла (производитель, брокер, два потребителя, пересчёт) и больше одного
носителя, и ни один дом сегодня на него не отвечает. Ниже уровнем пробел
не закрывается: правка одного носителя оставила бы механику получения
данных невыведенной, и следующий прогон вернул бы узел.

Решение держателя переоткрытию не подлежит: «каждая сторона потребляет
события сама, журнал аудита источником статистики не служит»
(`.claude/decisions/audit-statistics-split.md`). Узел выбирает **форму**,
отданную дизайн-проходу тем же решением, а не предмет.

### Ось предметная — классы событий и их отношение к признаку

Правило стои́т на признаке «класс несом статистикой», и его популяция —
**значения перечня классов событий**: каждый класс обязан получить исход.
Перечень выводится из предмета двумя сторонами — объявлением перечней в
общем артефакте и таблицей `contracts.md` §События, — потому что
расхождение между ними и есть частый дефект:

```bash
export LC_ALL=C.UTF-8
# сторона 1 — построенные классы (перечни общего артефакта)
grep -hoP '^\s{4}\K[A-Z][A-Z_]+(?=,?$)' \
  services/common/model/domain/src/main/java/com/example/tradingbot/domain/event/CoreEventType.java \
  services/common/model/domain/src/main/java/com/example/tradingbot/domain/event/StrategyEventType.java | sort -u | wc -l
# сторона 2 — все классы, объявленные таблицей §События
sed -n '/^## События/,/^Перечень открыт/p' docs/architecture/contracts.md \
  | grep -oP '^\| `\K[^|]+' | grep -oP '`?[A-Z][A-Za-z]+`?' | tr -d '`' | sort -u | wc -l
```

Выдача: сторона 1 — 9, сторона 2 — 21. Членом перечня взята **сторона 2**:
она шире и включает первую; расхождение объяснено тем, что часть
объявленных классов производителя не имеет, и это состояние корпус уже
называет (`contracts.md` §«Что значит «класс построен»»).

Второй командой выведен **сам признак** — какие классы являются операндами
объявленных зёрен. Перечень читается у владельца зёрен и у построенных
выборок, а не у дока, который проверяется:

```bash
export LC_ALL=C.UTF-8
grep -oP '(ORDER_DECIDED|DEAL_OPENED|DEAL_CLOSED|HOLD_RAISED|ANOMALY_REPORTED|DEAL_SHUTDOWN_INITIATED|STRATEGY_[A-Z]+)' \
  docs/spec/statistics-aggregates.json | sort -u
grep -rhoP '(ORDER_DECIDED|DEAL_OPENED|DEAL_CLOSED|HOLD_RAISED|ANOMALY_REPORTED|DEAL_SHUTDOWN_INITIATED|STRATEGY_[A-Z]+)' \
  services/audit-statistics/src/main --include='*.java' --include='*.sql' | sort -u
```

Обе стороны дали одно и то же множество; `STRATEGY_INTERNAL` во второй
выдаче — фрагмент имени колонки, а не класс события, и в множество не
входит.

| Класс | Исход |
|---|---|
| `DealClosed` | **правило правлено этим закрытием**: несом, операнды сделочного зерна, раскладывается в **сделочный факт** |
| `DealOpened` | **правлено**: несом (`openedDeals`), раскладывается в **факт происшествия** |

на том, «несёт ли содержимое класса операнд зерна», а содержимое класса —
не операнд состояния, а форма носителя; величины, которая это считает,
исполнимая спецификация не производит. Ось закрывается перечнем в отчёте
(`.claude/skills/closure-population.md` §«Что перечень не обязан делать»).

### Ось окрестностная — утверждения файлов-целей у точек вставки

**Перечень точек выведен из дельты захода по метке, а не вспомнен.**
Команда и её выдача:

```bash
git diff -U0 042024ead4f8ae52b8af9d6e5af6c2dfb99fc931 | grep -cE '^@@'
git diff --name-only 042024ead4f8ae52b8af9d6e5af6c2dfb99fc931 | wc -l
```

**Пробы этого раздела пересчитаны ПОСЛЕ доработки 1**, и перечень их членов
поэтому объединяет обе правки узла: доработка правит те же носители, и
перечень, собранный до неё, её точек по построению не видел. Перечень по
**собственной** дельте доработки предъявлен отдельно —
§«Популяция доработки 1»; ошибка здесь допущена только в сторону избытка.

## Правка

### Заведён дом формы факта — `docs/models/domain/other/StatisticsFact.md`

Отвечает на четыре вопроса, которые ставили A1-A3, и держит их один раз:

- **что такое факт** — строка-предшественник строки агрегата: те же ключи и
  операнды, зерном служит одно принятое событие, а не сутки. Отсюда
  механическое отношение: **строка агрегата есть свёртка фактов своего
  зерна по суткам**;
- **чем он не второй журнал** — двумя проверяемыми половинами: факт не
  хранит содержимого как доставлено (у журнала `content` есть предмет) и не
  имеет поверхности чтения строк. Снятие любой делает факт журналом;
- **подписка, группа, позиция** — тема каждого производителя несомых
  классов (правило общее, дом `contracts.md`), своя durable-группа,
  `earliest`;
- **признак несомого класса** — содержимое несёт операнд объявленного
  зерна; перечень выводится из зёрен и второй записи не получает;
- **структура** — две таблицы по зерну, инвариант «класс раскладывается
  ровно в одну таблицу», колонки производны от зёрен и от состава
  терминального события;
- **отметка обработанного** — ключ строки факта по `eventId`; отдельной
  таблицы inbox нет.

### Проведены указатели на дом

`contracts.md` (колонка потребителей + клауза признака + durable-группы +
перечень форм отметки), `data-ownership.md` (строка базы + буллет дедупа +
«Место истины схемы»), `OutboxRelayJob.md` (перечень форм),
`statistics-aggregates.md` (определение агрегата, §«Чего агрегаты не
считают», указатель на дом и отношение свёртки).

### Снята редакция радиуса

Требование единственности следствия адресовалось потребителю, у которого
баз несколько; после раздела такое условие пусто по построению.
Радиус расширен на всякого потребителя, запись реестра заведена.

### Снятая запись реестра

`tools/retired-check.py` нёс запись «статистика — потребитель событий
ядра», снятую `GAPS_CLOSE_4` шага 10. Она была верна ровно до решения
держателя о разделе: пока процесс был один, события потреблял журнал, а
статистика была проекцией журнала. После решения запись стала бы **охраной
против действующей редакции** — прогон падал бы на носителе, который
корпус теперь и обязан предъявлять. Шапка реестра называет это состояние
прямо: запись живёт, пока живо знание о снятии. Запись снята;
её строки в `tools/retired-prose-debt.txt` не было — проверено прогоном
(долг остался прежним, строк без записи нет).

**Найдено не чтением, а прогоном:** первая правка сделала
`py tools/retired-check.py` красным на двух дефектах, и оба указывали в
одну запись.

## Диспозиция ориентиров держателя

Секция `.claude/work/backlog.md` §«Ориентиры к дизайн-проходу по
`statistics`» требует исхода по каждому ориентиру. Ориентиры даны
**материалом, а не решениями**.

| Ориентир | Исход |
|---|---|
| две сущности — неизменяемые факты (строка на событие, идемпотентно по ключу события) и агрегаты над ними; пересчёт из фактов, а не из Kafka | **принят целиком** — и принят по названному в самом ориентире доводу: срок хранения тем не должен становиться скрытым условием восстановления |
| хранилище — Postgres + Timescale, гипертаблица фактов по времени | **принят** — форма хранения объявлена в §Персистентность нового дома; ось времени выбрана по читателю (сутки зерна считаются по ней же) |
| агрегаты по периодам и инструментам — continuous aggregates | **отклонён** — агрегат объявлен проекцией, отдающей **момент своей сборки**, а окно пересчёта объявлено калибруемой величиной с названной ценой; у continuous aggregate момента сборки строки нет, а политика обновления есть второй носитель окна. Инструмент, сверх того, в зерно не входит ни у одного из двух зёрен, и агрегата «по инструментам» не существует. **Следствия для корпуса разбирает своя находка (B7/B8), и узел у неё свой** — здесь ориентир получает исход, а не находка |
| прочие срезы — SQL по фактам с индексами по измерениям | **принят как направление, состава не получает** — состав выборок статистики в фазе 2 не растёт (границы шага), и индекс без названного читателя был бы формой раньше предмета |
| колоночное хранилище не сейчас; условие возврата названо | **принят** — условие возврата уже стои́т записью радара (`.claude/rules/tech-radar.md`, TimescaleDB), и второго носителя ему не заводится |
| потребители — Spring Kafka, как у соседей | **принят** — форма подписки та же, что у журнальной группы; своя группа и своя позиция чтения объявлены домом |
| аналитические запросы — `JdbcClient` либо jOOQ, не JPA | **принят как ориентир уровня кода, исхода в корпусе не получает** — выбор библиотеки есть деталь уровня кода, её владелец `code-writer` (`.claude/rules/tech-radar.md` §Политика), и решается он ходом `CODE` по предъявленной потребности |
| Kafka Streams / Flink / ksqlDB — нет | **принят** — довод ориентира (state store есть второй носитель истины рядом с фактами) совпадает с `.claude/rules/carrier-levels.md`; записи радара не заводится, потому что запись на **отвергнутое, не встреченное** есть спекулятивная запись (`.claude/rules/tech-radar.md` §Наполнение) |
| read-only API с ограниченной моделью запроса, а не произвольный SQL наружу | **принят, и он уже исполнен** — поверхность сервиса объявлена только читающей, ограничения отбора агрегатной выборки имеют дом (`docs/rules/statistics-aggregates.md` §«Что это за числа и кто их читает»), а произвольного SQL наружу нет ни в одной точке |

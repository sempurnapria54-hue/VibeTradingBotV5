# Первая постановка локального стенда

## На какой вопрос отвечает этот файл

Что мы уже сделали: чем закончилась первая живая постановка платформы и
сервисов на машине держателя.

## Что поставлено

**Кластер:** kind v0.33.0, узел Kubernetes v1.37.0, один узел поверх
Docker Desktop 4.88.1. **GitOps:** Argo CD v3.5.2 держит кластерный слой
(семь приложений, все `Synced/Healthy`).

| Пространство имён | Что живёт |
|---|---|
| `argocd` | Argo CD |
| `cert-manager`, `cnpg-system`, `kafka-system`, `elastic-system`, `keycloak-operator`, `vault-system`, `monitoring` | операторы и стек метрик |
| `dev` | Postgres 17.10 + TimescaleDB 2.29.2, Kafka (KRaft, узловой пул), Elasticsearch 9.5.3 + Kibana + сборщик логов, Jaeger 2.20, провайдер идентичности 26.7.3 с реалмом, `auth`, `connector-okx`, `market-data` |

**Миграции применены впервые:** `auth` `V1` (три таблицы), `market-data`
`V1` (гипертаблицы TimescaleDB созданы, расширение поднялось).

**Живой прогон дошёл до площадки:** синк каталога прошёл цепочку
`market-data` → токен провайдера идентичности → `connector-okx` → OKX и
записал **473 инструмента**. Доступность API площадки с адреса стенда
проверена **прогоном**, а не документацией: `GET /api/v5/public/time` →
`200` за 0.9 с; чтение листинга → `code=0`.

Команды и доступ к интерфейсам — `.claude/skills/local-stand.md`;
сценарии — `tools/stand/`.

## Что первое развёртывание нашло

Каждая находка закрыта тем же заходом; носитель правки назван.

| # | Находка | Чем закрыта |
|---|---|---|
| 1 | Оверлей окружения уводил `Application` и `AppProject` из `argocd` в пространство окружения — Argo CD их не видел | раскол манифестов на кластерный слой и слой окружения (`deploy/base/platform/kustomization.yaml`) |
| 2 | Клиентская форма применения **молча теряла** крупные CRD: у CNPG не встал `clusters`, у стека метрик — `prometheuses` и `alertmanagers` | `ServerSideApply=true` патчем на все `Application` кластерного слоя |
| 3 | Оператор стека метрик не создал `Prometheus` и `Alertmanager`: его информеры поднялись раньше собственных CRD и не перечитались | перезапуск оператора; причина названа в хронике — при исправном порядке (находка 2) она не воспроизводится |
| 4 | Оператор Kafka не видел кластер: по умолчанию он смотрит только своё пространство имён | `watchAnyNamespace: true` |
| 5 | Схема CRD Kafka 1.x не имеет ни `spec.kafka.replicas`, ни `storage`, ни версии `v1beta2` | манифест переписан на `KafkaNodePool` + `kafka.strimzi.io/v1`; патчи оверлеев переведены на пул; избыточный патч `prod` снят |
| 6 | Оператор провайдера идентичности ставился чартом, который его CRD не несёт; namespace-вариант не видел инстанса в окружении | источник заменён на официальные манифесты, вариант cluster-wide |
| 7 | Оператор Jaeger требует cert-manager и падает на CRD Kafka версии `v1beta2` при согласовании любого инстанса | оператор снят, трейсинг развёрнут прямым `Deployment` (Jaeger 2.x); cert-manager введён отдельно — у него есть второй потребитель |
| 8 | Прямое имя образа TimescaleDB отвергается вебхуком CNPG («invalid version tag»); запуск падает на правах тома | `ImageCatalog` с явным мажором плюс `postgresUID/GID: 1000` |
| 9 | **Запрет по умолчанию исполняется CNI** — кластер Postgres не поднялся: агент экземпляра не доходил до API-сервера | заведены разрешения платформенного трафика (`deploy/base/network-platform-allowances.yaml`) |
| 10 | Правило только на исходящей стороне не открывает тропу: запрет двусторонний | у каждой пары «сервис → база», «провайдер → база», «сборщик → приёмник» правило написано с обеих сторон |
| 11 | Под импорта реалма ходит в базу под другой меткой, чем сам сервер провайдера | селектор политики взят по владельцу (`managed-by: keycloak-operator`) |
| 12 | Тропа логов существовала только в доке: из четырёх звеньев в манифестах стояло одно (приёмник) | заведены Kibana и сборщик на узле, права сборщика — в кластерном слое |
| 13 | Ни один сервис не собирался в исполняемый артефакт: `spring-boot-maven-plugin` не подключён | плагин подключён в pom всех трёх сервисов |
| 14 | **Проба живости, объявленная единственной открытой точкой поверхности, не существовала**: стартера актуатора нет ни у одного сервиса, всякий запрос к `/actuator/health` отвечал `401`, под не становился готовым никогда | стартер добавлен всем трём |
| 15 | **Миграции молча не применялись**: в Boot 4 автоконфиг Flyway живёт в модуле стартера, а в зависимостях стоя́л только `flyway-core`; сервис падал на валидации схемы | `spring-boot-starter-flyway` вместо `flyway-core` у обоих сервисов с базой |
| 16 | **Падала каждая запись в базу**: умолчание JPA-аудита отдаёт `LocalDateTime`, а audit-поля объявлены `OffsetDateTime` | явный поставщик момента (UTC) в `auth` и `market-data` |
| 17 | Команда стенда собирала проект JDK 11: в среде уже стои́т `JAVA_HOME` | JDK и Maven назначаются, а не наследуются (`STAND_JDK`/`STAND_MAVEN`) |

**Находки 13-16 — кодовые, и все четыре означали одно:** ни один сервис,
построенный шагами 4-6, до первого развёртывания **не запускался вообще**.
Компиляция и модульные тесты этот класс не ловят по построению.

## Наблюдённое потребление

Снято на стенде в покое и на синке листинга (5-минутное среднее), не под
нагрузкой.

| Пространство имён | CPU, ядер | Память, МиБ |
|---|---|---|
| `dev` (данные + три сервиса) | 0.098 | 5760 |
| `kube-system` | 0.062 | 1696 |
| `monitoring` | 0.016 | 807 |
| `argocd` | 0.017 | 651 |
| прочие операторы | 0.015 | 472 |
| **всего** | **0.21** | **9644** |

Крупнейшие потребители памяти в `dev`: Elasticsearch 1756 МиБ, Kibana
1053, провайдер идентичности 737, Kafka 512 + 483 у оператора сущностей,
`market-data` 400, `auth` 315, `connector-okx` 296, Postgres 153,
сборщик логов 43, трейсинг 12.

**Диск.** Тома данных заняты мало (Postgres 207 МиБ, Elasticsearch 11
МиБ, Kafka и Vault — сотни КиБ), а вот **образы стоят дорого**: 16 ГиБ в
хранилище узла. Виртуальный диск Docker вырос с 2.9 до 27.9 ГиБ, и на
системном диске держателя осталось **8.2 ГиБ свободного места** — это
первое, что упрётся при следующей постановке. Освобождено 4.6 ГиБ внутри
диска (неиспользуемые образы и кэш сборки), но сам файл не сжимается.

**Что из этого следует для проработки облака** (`.claude/work/backlog.md`
§«Проработка облака, хостинга кода и CI», критерии 1-2): холостой ход
всей платформы одного окружения — около **10 ГиБ памяти и четверти ядра**;
торговой нагрузки в этих числах нет, как и второго-третьего окружения.

## Что не сделано и почему

| Что | Почему |
|---|---|
| `stage` и `prod` не поднимались | те же манифесты, отдельный ход; на одной машине смысла в трёх копиях платформы нет |
| экспорт трейсов из сервисов | приёмник стои́т, кода отправки в сервисах нет — это отдельная работа шага, а не развёртывания |
| ингресс и сертификаты | приезжают вместе с `bff` и `web` |
| **срезы стакана не собираются** | сборщик выбирает инструменты в статусе `ACTIVE`, а инструмент доходит до него только с заказанной группой свечей; заказчика на стенде нет. Расхождение с правилом «невосполнимое собирается по всему листингу без потребителя» — позиция в бэклоге |
| Vault-хардненинг | политики и роли ставит команда, а не манифест; ротации и approle нет (`.claude/work/backlog.md` §S1) |

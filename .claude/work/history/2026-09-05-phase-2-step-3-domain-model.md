# Шаг 3 фазы 2 — закрытые позиции бэклога

## На какой вопрос отвечает этот файл

Какие позиции бэклога закрылись на шаге 3 фазы 2.

## Сторона заявки — доменный перечень вместо литерала источника

**Закрыто** `GAPS_CLOSE_1` шага 3 фазы 2, находка H3.

**Условие возврата сработало по своей же формулировке** — «ближайший ход,
трогающий модель заявки»: шаг 3 переносит `Order` в общую библиотеку
`domain-model`. Вдобавок обнаружилось встречное основание, которого при
записи долга ещё не существовало: объявленный критерий устойчивости
библиотеки («вторая площадка проходит добавлением, а не правкой
существующих полей», `docs/architecture/services.md`) поле с литералом
одной площадки нарушает по построению.

**Чем закрыто.** `docs/models/domain/core/Order.md` — поле `side` типа
`Side`, закрытый доменный перечень `BUY`/`SELL`, поле обязательное
(прежде было nullable вместе с типом `String` — оба свойства сняты одним
ходом). `docs/models/mapping/Order.md` — перевод словаря площадки назван
на границе коннектора. `.claude/rules/codestyle.md` §«Слои» — запись об
объявленном долге снята.

**Что обнаружилось по пути.** `docs/models/mapping/Order.md:20` **уже**
объявлял `side → Order.side` как `BUY`/`SELL`: доковое расхождение с
кодом существовало и до этого шага, просто не было названо. Закрытие
свело три носителя (модель, mapping, конвенция) к одной редакции.

**Кодовая часть** — на `CODE` шага 3: тип поля, миграция колонки
`orders.side`, снятие `CreateOrderActionExecutor.toSide`, обход
читателей.

(«шаг 4 фазы 2, заводящий `auth` и модель `ExchangeAccount`») сработало.

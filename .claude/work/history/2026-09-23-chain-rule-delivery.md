# Правила со scope доходят до цепочки

## На какой вопрос отвечает этот файл

Что сделано задачей «правила со scope должны доходить до цепочки» и какими
пробами это подтверждено.

## Итог

Цепочка идёт в `bypassPermissions`, и харнесс в этом режиме направляет чтение
файлов в Bash, а чтение оболочкой масок `paths:` не включает
(`.claude/work/history/2026-09-23-chain-start-breakdown.md`). Теперь в
`.claude/settings.json` стоит хук `PreToolUse` на Bash и `Read` —
`tools/rule-touch-guard.py`.

- **Отказ до первого касания.** Команда, касающаяся корпусного `*.md` или
  `*.txt`, получает отказ, пока правило области этого файла не пришло в
  контекст.
- **Что делать, называет сам отказ:** прочитать файл инструментом `Read`
  (хватит `limit: 1`) и повторить команду. После этого оболочка по той же
  области работает как прежде.
- **Код и поиск хук не трогает:** `grep`, `git`, `ls`, `wc` и прочие команды
  поиска проходят без отказа.
- **Маски не копируются:** хук читает их из шапок правил при каждом вызове.

Маски, состав ядра и содержимое правил не менялись. Попутно у гейтов шага
остался один дом — скилл статуса, — а противоречие об ингрессе в
`local-stand.md` снято. Развилки — Д2044-Д2050 в
`.claude/work/decision-digest.md`.

## Почему не конвенция

Направление чтения в Bash задаёт эксперимент харнесса. У сессий v403-v410 он
стоял в варианте `strict`, сегодня — в `relaxed`; вариант приходит вложением
`auto_mode` в журнале сессии и меняется без нашего участия. Пробы без хука, в
режиме цепочки:

| Касание | Инструмент | Правил пришло |
|---|---|---|
| «покажи 20 строк бэклога» | `Read` | 11 |
| «прочитай снапшот» | `Read` | 8 |
| «прочитай `Order.md`» | `Read` | 9 |
| строки 418-470 документа кейсов `bff` | `Read` | 7 |
| пункт 1 промпта цепочки: снапшот, статусы, хвост хроники | Bash: `ls`, `cat` | 0 |
| последние 40 строк хроники | Bash: `wc`, `tail` | 0 |
| два файла роадмапа одним махом | Bash: цикл `cat` | 0 |

Короткая просьба идёт через `Read`. Старт по промпту цепочки, хвост и чтение
нескольких файлов разом идут через оболочку. Конвенция в промпте держалась бы
дисциплиной против системной подсказки харнесса, и на практике старт цепочки
её не соблюдает.

## Хук

- **Касание** — путь к `*.md` или `*.txt` в тексте команды, в любой форме:
  относительной, абсолютной Windows- или POSIX-формы, маской с `*`.
  Исключены сегменты, чья команда только ищет или перечисляет; сегмент —
  часть между `|`, `&&`, `;` и переводом строки. Поэтому видно и касание
  скриптом в heredoc.
- **«Пришло»** засчитывается по трём источникам:
  - в журнале сессии есть вложение `nested_memory` с файлом правила;
  - в журнале есть вызов `Read` файла по маске правила;
  - хук сам видел `Read` этого файла и записал его в файл сессии во
    временном каталоге.

  Третий источник нужен из-за гонки: харнесс дописывает журнал с
  запаздыванием (§«Матрица касаний»).
- **Сбой хука пропускает команду:** исправность хука мерит его батарея в
  гейте инструментов корпуса, а не остановка работы.
- **Батарея** — `py tools/rule-touch-guard.py --self-test`: тринадцать осей и
  семь контролей на действующих масках правил. Команда добавлена в перечень
  `.claude/skills/update-roadmap-progress.md` §«Гейт инструментов корпуса».
- **Норма для сессии** записана строкой «Чтение корпуса оболочкой» в таблице
  фактов среды `.claude/skills/environment-commands.md`.

## Проба в режиме цепочки

Пробы запускались флагами цикла: `--permission-mode bypassPermissions
--permission-prompts none`. Просьба в каждой нейтральна: показать строки
файла командой `head`. Какие правила пришли, читалось по вложениям
`nested_memory` в журнале. Ожидаемый набор выводился из масок шапок.

### Промпт цепочки и субагент

- **Пункт 1 промпта цепочки.** Сессия взялась за `cat` снапшота и получила
  отказ. Дальше она читала снапшот, таблицу статусов и хронику через `Read`,
  а `wc -l` по хронике прошёл без отказа. Пришло десять правил, среди них
  `snapshot-format` и `session-work-unit`; без хука — ни одного.
- **Хвост хроники:** один отказ, затем `Read`, затем тот же `tail` прошёл.
  Пришло девять правил.
- **Два файла роадмапа разом** сессия прочла через `Read` сама, без отказа.
  Пришло девять правил.
- **Код:** `cat services/bff/pom.xml` прошёл без отказа, правил не пришло.
- **Субагент:** `head` бэклога получил отказ, субагент прочёл файл `Read`,
  получил одиннадцать правил, и повторный `head` прошёл.

```bash
py tools/rule-touch-guard.py --self-test
MSYS_NO_PATHCONV=1 claude -p "Покажи первые 3 строки файла .claude/work/backlog.md командой head в Bash и ответь первой строкой файла." --session-id <id> --permission-mode bypassPermissions --permission-prompts none < /dev/null
grep -o '"type":"nested_memory","path":"[^"]*"' ~/.claude/projects/<проект>/<id>.jsonl
```

## Попутные дефекты

- **Дом гейтов.** Домом объявляли себя скилл
  `.claude/skills/update-roadmap-progress.md` («Гейты живут здесь, в
  скилле») и процесс `.claude/processes/roadmap-step-execution.md` («Канон
  гейтов процесса»). Дом — скилл: он гейты исполняет, держит перечень команд,
  и на него ведут все прочие указатели. §«Гейты» процесса сведён к указателю
  на дом; пассаж «Фиксация статуса» остался в процессе — это норма
  оркестрации. Снятая фраза заведена записью `tools/retired-check.py`.
- **Ингресс.** Верна строка «ингресса нет»: объект `Ingress` приехал с
  периметром, а контроллера, который его исполнит, нет. Снаружи стенд не
  отвечает ни по какому имени хоста — `.claude/work/backlog.md` §«Ингресс
  окружения исполнять некому: контроллера нет ни в манифестах, ни на стенде».
  Сделано:
  - ложная строка «ингресс на стенде теперь есть» снята;
  - верная уточнена и получила указатель на секцию бэклога;
  - абзац §«Доступ к интерфейсам» больше не говорит, что ингресс
    маршрутизирует;
  - свипом правлены комментарий `tools/stand/kind-cluster.yaml` («пока ни
    одного Ingress-ресурса нет») и абзац секции бэклога, цитировавший снятую
    фразу;
  - снятая фраза заведена записью реестра.

Шаблоны обеих записей реестра проверены на двух состояниях: на `HEAD`
находят по одному вхождению в своём носителе, в рабочем дереве — ни одного.

## Остаток

- **Запись нового файла** инструментом `Write` правило не подгружает, и хук
  её не ловит — так же, как у сессий с `Read`.
- **Путь, собранный из частей** (`"$D/$F"`) без литерала файла, хук не видит.
- **Субагент после родителя:** случай, когда область уже прочёл родитель, не
  мерился.
- **Упоминание как касание.** Текст, лишь называющий корпусный файл (промпт
  в аргументе команды, `echo`), считается касанием; цена — один `Read` на
  область.
- **`.claude/rules/structure.md` не правлен** по границе задачи:
  - строка `.claude/settings.json` говорит, что файл держит «сегодня — предел
    таймаута вызова инструмента и его умолчание», а хука не называет;
  - строка `.claude/rules/` называет Bash среди действий, правило не
    подгружающих, — это по-прежнему верно о харнессе, но о хуке не говорит.

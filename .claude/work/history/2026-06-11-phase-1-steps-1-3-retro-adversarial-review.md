# Ретро-достройка адверсариального ревью шагов 1-3

## На какой вопрос отвечает этот файл

Каков зафиксированный исход независимого адверсариального code-review,
ретроспективно прогнанного по шагам 1-3 фазы 1 (достройка пропущенного
гейта), и как закрыты находки.

## Контекст

При закрытии шага 4 вскрылся дефект: переход в `DONE` проскакивал мимо
предписанного **независимого** агентского адверсариального ревью. Гейт
ужесточён (`roadmap-step-execution.md` §7). По требованию — проверить
шаги 1-3 и достроить пропущенное.

### Что показала проверка записей

- **Шаг 1** — code-review был **self-review** (отчёт `phase-1-step-1-code.md`
  §Self-review прямо: «self-review conventions/performance/disaster»). Тот же
  дефект. `divergence` на синке — прогнан (`phase-1-step-1-sync-docs.md`).
- **Шаг 2** — ревьюер-фокусы с зафиксированными находками
  (`phase-1-step-2-code.md` §Находки ревью); независимость субагентом —
  не подтверждена. `divergence` — прогнан.
- **Шаг 3** — code-review-фокусы не зафиксированы (нет `-code.md`-отчёта).
  `divergence` — прогнан; пост-хок концепт-гейт §6a — прогнан
  (post-revision-D).

Разрыв: **независимый** адверсариальный code-review на 1 (self-review),
3 (не зафиксирован), под вопросом 2. `divergence` — везде есть.

## Прогон (независимые general-purpose субагенты, не авторы)

Консолидированные фокусы `conventions` + `performance` + `disaster` по

|---|---|---|---|
| 1 (рыночные данные) | 0 | 1 | 4 |
| 2 (стратегия) | 0 | 3 | 3 |

**Блокеров нет ни в одном шаге.** Старый код подтверждён крепким:

контрастирует с шагом 4, где независимый disaster нашёл 4 деньги-блокера
— разница объяснима: шаг 4 — свежий торговый write-путь к бирже.

## Находки и закрытие (все неблокирующие → форвард-долг)

Статусы шагов 1-3 **остаются `DONE`**: гейт удовлетворён (независимое
ревью прогнано, зафиксировано, блокеров нет). Major/minor — не блокеры,
вынесены в `backlog.md` §Ретро-ревью шагов 1-3.

### Шаг 1

- **[MAJOR] SYNC-overlap не реализован.** `CandleLoadingProperties.syncOverlapBars`
  объявлен + в `application.yaml`, но `CandleLoader.sync()` его не зовёт —
  overlap получается «бесплатно» от `pageSize=100`. Мислид-конфиг.
  → реализовать SYNC через `getLatestCandles(.., syncOverlapBars)` либо
  удалить свойство.
- **[MINOR]** `repairAttempts` in-memory (теряется при рестарте — гарантия
  «N попыток → ERROR» не переживает рестарт; кандидат — поле на
  `CandleGroup`); отброшенный return `saveCandles`; двойной
  `findByStatusIn` за тик; SYNC-gap heal через REPAIR (наблюдение, не
  дефект).

### Шаг 2

- **[MAJOR][PERF] Декартов join-fetch дерева.** `StrategyRepository.findByInternalIdWithTree`
  fetch'ит несколько независимых *ToMany-ветвей разом (indicatorSettings ×
  marketStructureSettings × steps × actions) → произведение строк
  материализуется в памяти. → разнести на 2 fetch-запроса /
  `@EntityGraph`+`@BatchSize` / `default_batch_fetch_size` (+ `distinct`).
  Should-fix (бьёт с ростом дерева).
- **[MAJOR][DISASTER, error-convention] Неатомарная «одна ACTIVE» → 500.**
  `StrategyService.updateStatus` не `@Transactional`; exists-проверка и
  write в разных tx; гонка двух активаций → partial-UNIQUE кидает
  `DataIntegrityViolationException` → необработанный 500 вместо 422. БД
  инвариант держит. → ловить нарушение констрейнта → 422.
- **[MAJOR][DISASTER, error-convention] Повторный POST → 500.** `internalId`
  клиентский; ретрай → `uk_strategy_internal_id` → 500 вместо 409 /
  идемпотентного возврата. Развилка 409-vs-идемпотентность — продуктовая.
- **[MINOR]** неиндексированные FK `strategy_actions.strategy_step_id` /
  `target_action_id`; `toResponse` вне tx создания (create вернул ошибку,
  хотя создал).

### Шаг 3

- **[MINOR]** провизорные пороги-дефолты резолвера применяются молча (нет
  сигнала «дефолт применён» → маскирует пропущенную калибровку);
  двойная простановка owner-полей на UNKNOWN-ветке `MarketStructureJob`;
  `lookbackBars`→`PageRequest.of` без нижней границы (0/отриц. → общий
  catch, смазанная диагностика).
- **[NIT]** N+1 по таймфреймам (несколько настроек одного инструмента →
  повторная загрузка окна); полный пересчёт окна каждый тик (осознанно).

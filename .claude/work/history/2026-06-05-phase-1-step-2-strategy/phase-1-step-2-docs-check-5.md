## Контекст

- Шаг роадмапа: Фаза 1, шаг 2 — «Стратегия (абстракция: объявляет
  нужные индикаторы и условие сигнала; одна реализация)».
- Под-шаг: `DOCS_CHECK_5` (пятая итерация), после `GAPS_CLOSE_4`.
- Тулинг: роль `reviewer`, фокус `concept-review`. Граница охвата —
  **только доки**, код не читается.
- **Scope** (зафиксирован на `GAPS_CLOSE_1`, Э1): шаг 2 строит,
  **персистит** и читает полное монолитное immutable-дерево `Strategy`

- **Фокус итерации:** `GAPS_CLOSE_4` ввёл общее правило

## Пробелы по типам

### 1. Несогласованности между доками (мелкие, гигиена)

**М1. `strategy-condition-authoring-contract.md` несёт устаревшую
формулировку «настройки — реляционно с JSONB-листьями» как «уже
принятое».** §Принятое решение → отвергнутая альтернатива
«`type`-строкой» (стр. ~62-64): «бьётся с уже принятым (операнды —
структурой, настройки — **реляционно** с JSONB-листьями)». После
ревизии `GAPS_CLOSE_3` настройки — JSONB внутри контейнера, не
реляционные узлы. На момент закрытия STRAT-Q1 фраза была верна;
ревизионной врезки (как в `strategy-tree-persistence.md`) этот
decision не получил. Читатель получает противоречащее текущей схеме
утверждение о «принятом». Миграцию/entity шага 2 не затрагивает.

**М2. Мёртвые ссылки на `.claude/work/questions/tasks/strategy.md`.**
`Strategy.md` (стр. 83, 513) и `docs/lifecycles/Strategy.md` (стр. 17)
ссылаются на файл форвард-заметок по старому пути; файл архивирован в
`.claude/work/history/2026-05-27-миграция-торговых-сущностей/tasks-strategy.md`
(указатели по конвенции живут в `backlog.md`). Ссылки ведут в
несуществующий файл.

**М3. STRAT-Q5 в `open-questions.md` неточно описывает текущее
состояние доков.** Формулировка «§Внутридеревные ссылки **обоих
доков** пишет „операнды — JSONB на строке `strategy_condition_rule`“»
— фраза есть только в `Strategy.md` (стр. 463-464);
в `strategy-tree-persistence.md` §Внутридеревные ссылки её нет
(проверено и на коммите `DOCS_CHECK_4` — не было и там; неточность
унаследована из формулировки Н1). При закрытии STRAT-Q5 исполнитель
будет искать фантомную фразу во втором доке.

### 2. Name-level без структуры (где структура нужна шагу 2)

Единственный структурный дефицит — **схема персистентности условия**
(`StrategyCondition`/`StrategyConditionRule`): таблицы/колонки либо
JSONB-форма на `strategy_step` не заданы. Это содержание STRAT-Q5
(тип 3 ниже), отдельным пунктом не дублируется. Прочая
под-определённость (типы/nullability числовых полей) — осознанный
отложенный порог (§Не зафиксировано), не пробел.

### 3. Неотвеченные вопросы (open-questions)

Проход по `open-questions.md` (16 открытых):

  условие каждого `StrategyStep`; без выбора представления
  (JSONB-дефолт правила на `strategy_step` vs реляционное исключение
  decision'ом) entity/миграция условия не пишутся. Механику шага не
  гейтит (стадия 0 чиста) — недостающая деталь структуры внутри
  понятной механики; фиксируется здесь, обход не остановлен.
  Известный вопрос, сознательно оставленный `GAPS_CLOSE_4`.
- **STRAT-Q4** (percent-anchor) — непгейтящий бизнес-инкремент, без

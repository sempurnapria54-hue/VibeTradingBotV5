## Торговые находки (фокус `trading-review`)

Категория торговой корректности; каждая находка — с указателем на
источник (пересчёт страниц — `corpus-map.md`). «Источник говорит»
отделено от «предполагаю».

### Содержательные находки

- **ТР1 (cross-cutting → шаг 5). После снятия наших потолков нет
  worst-case guard'а на позицию/плечо.** Источник говорит: для
  автоматики обязательны позиционные лимиты — guard rails против
  ошибок расчёта и jump-риска (минимум из «позиция при максимальном
  форкасте ×1.5», лимита плеча на инструмент, доли открытого
  интереса) [Carver AFTS, тактика 4, PDF с. 651-655]; ни одна
  позиция не должна обнулять счёт при максимальном мыслимом движении
  [Carver ST, гл. 9, с. 180-181]; кэп экспозиции — «единственный
  форвардный риск-контроль» [Kaufman, гл. 24, PDF с. 2188,
  2192-2193]; будущий крупнейший убыток больше исторического [Vince,
  гл. 2, с. 30-31]. Текущее правило
  (`docs/rules/trading-constraints.md`) после решения «плечо
  динамическое» (2026-06-04) оставляет единственным жёстким пределом
  биржевой `externalMaxLeverage` — предполагаю (крипто-специфика — ∅
  пробел корпуса): на перпах биржевой максимум порядка 50-100× ролью
  guard rail не обладает. Находка **не против** решения о
  динамическом плече (вывод плеча из риска и стопа корпусу
  соответствует: риском управляет сайзинг/плечо [Kaufman, гл. 23,
  PDF с. 2036-2037; Tharp, гл. 9, с. 238]) — она про **отдельный
  страховочный кэп** поверх вычисленного значения: формула даёт
  корректное плечо при корректных входах; guard ловит некорректные
  (ошибка данных/расчёта, гэп, jump-риск). Шаг 2 не гейтит
  (риск-движок — шаг 5). Рекомендация: на `GAPS_CLOSE_8` завести
  открытый вопрос с владельцем «шаг 5» (рядом с RISK-Q1/INSTR-Q2,
  не внутри них — у них другой предмет).

- **ТР2 (шаг 2, эскалация). Create-валидация не задаёт
  sanity-диапазоны торговых полей.** Линия реза
  (`strategy-materialization-and-validation.md`) на create включает
  sanity только для `warmup`-override; числовые торговые поля
  (`riskPerTradePercent`, `targetRiskRewardRatio`,
  `allocationPercents`, `distancePercents`, …) диапазонов не имеют —
  стратегия с `riskPerTradePercent = 50` структурно валидна.
  Источник говорит: для тренд-фоллоинга со стопами риск >3% на
  сделку — «ганслингер», ориентир ≤3% на своих средствах [Tharp,
  гл. 12, с. 292-296]; «скромный» процент на коротком удержании
  скрывает сверхагрессивный implied vol target [Carver ST, гл. 9,
  с. 189-190, табл. 27]; превышение оптимума риска гибельно и хуже
  недобора [Vince, гл. 1, с. 9, 18]. Эскалация (решает чат на
  `GAPS_CLOSE_8`): вводить ли числовой sanity и **где** — create
  (400) / activate (422) / risk-движок шага 5; и каков характер
  границ (жёсткие vs предупреждение). Шаг 2 не гейтит: «одну
  реализацию» авторим сами, но решение влияет на контракт
  валидатора, который пишется на `CODE` шага 2 — потому поднято
  сейчас.

### Торговые заметки (не гейтят; материал авторингу/downstream)

- **ТР3 (авторинг «одной реализации», `CODE` шага 2).** Модель
  допускает торгово-наивные комбинации, не требуя защит структурно
  (они выразимы условиями, но опциональны): `CONTRARIAN` в трендовой
  фазе без тренд/волатильностного guard'а — источник говорит:
  mean-reversion против тренда без фильтра — «ловля ножей», тяжёлый
  негативный скос; safer-вариант гасит сигнал против тренда и режет
  позиции при высокой волатильности [Carver AFTS, стратегия 27, PDF
  с. 492-494]; `TrailingSettings.activationProfitPercents = null`
  (активация сразу) — ранний перевод в безубыток выбивается шумом
  [Kaufman, гл. 23, PDF с. 2037-2040]. Для шага 2 структурных правок
  не требует — это чек-лист конструктивного касания
  `trading-specialist` при авторинге реализации.

- **ТР4 (шаг 3 — расчёт индикаторов; авторинг).** `VOLUME_FILTER_PASSED`
  и OBV опираются на биржевой объём; источник говорит: wash trades —
  стандартный приём блефа («paint the tape») [Harris, гл. 12,
  с. 259-260, 273-274]; крипто-специфика фейкового объёма — ∅ пробел
  корпуса (`microstructure.md` §9). Предполагаю: объём как
  единственное основание ENTRY-условия на крипто ненадёжен; как
  вспомогательный фильтр — приемлем. Заметка владельцу шага 3 и
  авторингу.

- **ТР5 (Фаза 2 — бэктест-гейт).** В Фазе 1 стратегия торгует без
  проверки ожидаемости: источник говорит — при ME ≤ 0 никакой money
  management не спасает [Vince, гл. 1, с. 13]; «реальная торговля =
  тестированная торговля» [Kaufman, гл. 21, PDF с. 1913-1914].
  Роадмап это уже покрывает: Фаза 2 — «бэктест-гейт: без прохождения
  бэктеста стратегия не активируется и не торгует» — находка
  **снимается роадмапом**, фиксируется как осознанный риск live-прогонов
  Фазы 1 (размер/режим прогонов — продуктовое решение вне доков
  шага 2). Новых артефактов не требует.

### Положительная сверка (модель соответствует корпусу)

- Режимность через фазы рынка + `UNKNOWN → NO_TRADE` — выбор стиля
  по характеру рынка, консервативность вне определённости [Kaufman,
  гл. 1, PDF с. 98-107; Carver AFTS, стратегия 13, PDF с. 293-295].
- `GRID` только в `RANGE`, направленные политики — в трендах
  [Carver AFTS, стратегии 26-27, PDF с. 469-471, 492-494].
- Волатильностные стопы `ATR_PERCENT` — «среди лучших» типов стопа
  [Tharp, гл. 9, с. 245]; structure-buffer
  (`MARKET_STRUCTURE_BUFFER_PERCENT`) — анти-stampede: не ставить
  стоп ровно на очевидном уровне [Tharp, гл. 9, с. 246; Harris,
  гл. 11, с. 255-257 — gunning the market].
- Инвариант «ликвидация за стопом»
  (`STOP_LOSS_TOO_CLOSE_TO_LIQUIDATION`) — worst-case как отправная
  точка; стоп не гарантирует цену при гэпе [Vince, введение, с. 6;
  Harris, гл. 4, с. 78].
- `riskPerTradePercent` (percent-risk модель) — основная модель
  сайзинга для систем со стопами [Tharp, гл. 12, с. 292-296];
  формула вывода — корректно отложена в шаг 5.
- Immutability стратегии — анти-meddling: правка параметров на лету
  = источник скрытого оборота и порчи системы [Carver ST, гл. 12,
  с. 231-233; гл. 7, с. 149-150].
- Бинарная сигнальная архитектура (condition → пакет действий) —
  легитимная stop-driven философия (Tharp); корпус расходится с
  size-driven каркасом непрерывных форкастов (Carver) — ⚠
  зафиксированное расхождение источников (`risk-and-sizing.md` §13,
  `system-design.md` §8), выбор модели осознан, дефектом не
  является.

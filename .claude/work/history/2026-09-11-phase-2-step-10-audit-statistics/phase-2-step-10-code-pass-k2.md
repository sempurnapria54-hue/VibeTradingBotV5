# Кодовый заход K2 шага 10 фазы 2 — схемы журнала и статистики, роли и гранты

## На какой вопрос отвечает этот файл

Чем предъявлен кодовый заход по компоненту K2 шага 10 фазы 2.

## Единица работы и её заходы

Единица — **один кодовый заход** по одному компоненту реестра
(`.claude/rules/session-work-unit.md`). Компонент — K2
(`audit-statistics: схемы журнала и статистики, роли и гранты`), позиции
6, 7, 7а, 7б, 9а, 17, 18 (таблица) и 25 дельты `CODE`.

**Почему K2.** Порядок заходов реестром не назначен, и естественный
следующий назван обоими предыдущими носителями: персистентность — то, на
чём стоя́т K3-K8, а без неё ни слушателю приёма, ни выборкам чтения не во
что писать и не из чего читать. K10 по-прежнему не берётся одной единицей
(Д1215): его составы меняют канонические конструкторы семи записей, чьи
писатели лежат в трёх сервисах.

| Заход | Состояние |
|---|---|
| кодовый заход K2 (корпусный) | `записан` — §«Классификация правки по родам» |

Раунда критики и доработки у единицы этого рода нет: корпус она меняет
одной партией, а исход её правок мерит не чтение, а прогон — реактор,

### Чего заход НЕ строил, и почему это названо

- **Сущностей и репозиториев нет ни одного.** Схема заведена миграциями, а
  отображать её на классы — предмет тех компонентов, которым это нужно:
  слушателя приёма (K3) и двух выборок чтения (K7, K8). Отсюда и стартер
  взят `jdbc`, а не `data-jpa`: конфигурации JPA при трёх источниках
  данных нечего настраивать, пока нет ни одной сущности.
- **Писателя строки `access_denials` у сервиса нет.** Таблица есть, точка
  входа отказа есть (заход K1), а строку она не заводит: писать её нечем
  без персистентного слоя. Припарковано с домом, оживителем и причиной —
  `.claude/work/backlog.md` §«Таблица отказов доступа у сервисов со своей
  базой».
- **Пробы выбора подключения у ЧИТАТЕЛЯ нет.** Дом раскладки называет
  остаток охраны: грант отвергает запись через подключение роли
  статистики, но какое подключение внедрено в читателя — выбор автора
  кода. Читатели (джоба пересчёта, агрегатная выборка) приезжают своими
  компонентами; проба припаркована строками K6 и K8 реестра.
- **Стенд не поднят и образ не собран.** Живой прогон схемы сделан на
  одноразовом Postgres, а не на стенде: стенд от дерева кода отстаёт с
  захода K1.

## Чем предъявлено, а не прочитано

**Живой прогон обеих цепочек и инварианта «один пишущий».** Одноразовый
Postgres, роли и базы заводит не миграция, а кластер; тело цепочки журнала
подставляется так же, как это делает Flyway:

```bash
export MSYS_NO_PATHCONV=1
CT=k2probe
CHAIN_AUDIT=services/audit-statistics/src/main/resources/db/migration/audit/V1__audit_baseline.sql
CHAIN_STATS=services/audit-statistics/src/main/resources/db/migration/statistics/V1__statistics_baseline.sql
docker rm -f "$CT" >/dev/null 2>&1
docker run -d --name "$CT" -e POSTGRES_PASSWORD=probe postgres:16 >/dev/null
until docker exec "$CT" pg_isready -U postgres >/dev/null 2>&1; do sleep 1; done
docker exec -i "$CT" psql -U postgres -v ON_ERROR_STOP=1 -q <<'SQL'
create role audit login password 'probe-audit';
create role statistics login password 'probe-statistics';
create database audit owner audit;
create database statistics owner statistics;
SQL
sed 's/[$]{statisticsRole}/statistics/g' "$CHAIN_AUDIT" > tmp-audit.sql
docker cp tmp-audit.sql "$CT":/tmp/audit.sql >/dev/null
docker cp "$CHAIN_STATS" "$CT":/tmp/statistics.sql >/dev/null
docker exec "$CT" psql -U audit -d audit -v ON_ERROR_STOP=1 -q -f /tmp/audit.sql
docker exec "$CT" psql -U statistics -d statistics -v ON_ERROR_STOP=1 -q -f /tmp/statistics.sql
docker exec "$CT" psql -U statistics -d audit -At -c "select count(*) from audit_records"
docker exec "$CT" psql -U statistics -d audit -v ON_ERROR_STOP=1 -q -c "insert into audit_records (event_id, tenant_id, event_type, occurred_at, recorded_at, version, content) values ('e-1','tn-1','DealClosed', now(), now(), 1, '{}'::jsonb)"
docker exec "$CT" psql -U audit -d audit -q -c "create table future_journal_table (id bigserial primary key)"
docker exec "$CT" psql -U statistics -d audit -At -c "select count(*) from future_journal_table"
docker exec "$CT" psql -U statistics -d statistics -At -c "select c.relname, i.indnullsnotdistinct from pg_index i join pg_class c on c.oid = i.indexrelid where c.relname like 'uk_%' order by 1"
docker rm -f "$CT" >/dev/null
rm -f tmp-audit.sql
```

## Решения захода

| # | Решение | Отвергнуто | Довод |
|---|---|---|---|
| 1 | цепочек миграций две — по владельцу данных, и каждая идёт **своим** подключением | одна цепочка на оба владельца; цепочка кросс-подключением | права по умолчанию действуют на объекты, создаваемые **текущей** ролью: пройди цепочка журнала чужим подключением, будущие таблицы завёл бы не владелец, и грант достался бы не тем объектам. Одна цепочка на две базы невыразима вовсе — у Flyway на один прогон одна база |
| 2 | `flyway-core`, а не `spring-boot-starter-flyway`, как у соседей | стартер ради единообразия | автоконфиг, **запускающий** миграции, отказывает при собственном бине `Flyway` (`@ConditionalOnMissingBean`), а он здесь обязателен: цепочек две. Стартер добавил бы автоконфиг, который не может сработать, — то есть видимость механизма |
| 3 | третье подключение **собирается** из двух настроенных, своей настройки не имеет | третий комплект `url`/`username`/`password` в конфигурации и манифесте | заданный отдельно адрес той же базы расходится с первым молча, и клейм «читаем журнал» держался бы совпадением двух настроек. Собранное держится построением, и это то, что мерит проба уровня контекста |
| 4 | `@Primary` нет ни у одного подключения | пометить основным подключение журнала — «чаще нужное» | выбор подключения и есть предмет инварианта; умолчание отдавало бы чужую тропу молча. Без него неквалифицированное внедрение **роняет контекст** — то есть остаток охраны, названный домом, закрыт настолько, насколько это выразимо сборкой |
| 5 | имя роли-читателя приезжает в миграцию **подстановкой** из настроенного подключения | литерал `statistics` в теле миграции | литерал разошёлся бы с настройкой молча: миграция осталась бы зелёной, а пересчёт — без чтения. Цена названа: подстановка обязана иметь значение, иначе отказ приходит от базы |
| 6 | грант выдан **на базу целиком** (`all tables` + права по умолчанию), а не поимённо | перечень таблиц журнала в гранте | операнд исполнимой формы — пара «роль × база» (`docs/spec/owner-role-grants.json`), и поимённый перечень был бы у́же собственной спеки; сверх того он умолчал бы о таблице, которой на момент выдачи нет, — против чего и стои́т вторая половина хода |
| 7 | суррогатный `id` у трёх таблиц, доки правлены тем же ходом | ключ по зерну без суррогата | в ключе сделочного зерна две законно пустые колонки, а первичный ключ пустых не допускает. Расхождение схемы с доком запрещено симметричным требованием (`docs/rules/persistence-representation.md` §«Место истины схемы — модель»), поэтому правится **док**, а не умалчивается код |
| 8 | секреты обеих ролей заводит цикл `tools/stand/up.sh` | оставить их ручным пунктом постановки, как у `strategies` | роль без секрета оператор не сводит вовсе, то есть стенд встал бы на первой же постановке. Чужой пункт (`strategies`) при этом **не** закрывается: у него свой дом и свой владелец |
| 9 | таблица состояния приёма переименована в `journal_reception_states` — во множественное число, как требует конвенция | оставить объявленное доками имя в единственном числе; объявить исключение из конвенции с доводом | конвенция общая для **всех** таблиц проекта (`.claude/rules/codestyle.md` §«Схема БД»), и в дереве ей следует ближайший аналог — `account_instrument_states`, таблица состояния той же формы «строка на пару». Довода для исключения нет ни одного; имена ограничений при этом остаются в единственном числе — это та же конвенция, а не отступление от неё. Момент выбран потому, что применённая миграция неизменяема: после первой постановки переименование стоило бы второй миграции и свипа по коду читателей |

## Что осталось у компонента и что дальше

- **K2 закрыт**: статус кодирования в `.claude/work/code-gate-ledger.json`
  — `закодирован`.
- **Аппрув `CODE` компонентом не выдаётся.** Фокусы
  (`conventions` / `performance` / `disaster` / `security`) прогоняются на
  под-шаге целиком, когда компоненты шага закодированы
  (`.claude/processes/roadmap-step-execution.md` §Гейты).
- **Вход следующей единицы — следующий кодовый заход.** Естественный
  порядок дальше: **K3** (слушатель приёма и обработчик ошибок) — он
  первый, кому нужна сущность, и он же приводит стартер JPA и брокера;
  вместе с ним закрываются две парковки этого захода — писатель строки
  отказа доступа и первая проба выбора подключения у читателя.
- **Стенд от дерева кода отстаёт по-прежнему**: образ не собран, роли и
  базы на стенде не заводились — их заведёт ближайшая постановка
  (`.claude/skills/local-stand.md`).

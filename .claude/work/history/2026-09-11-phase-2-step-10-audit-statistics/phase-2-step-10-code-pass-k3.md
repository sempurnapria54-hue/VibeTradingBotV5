# Кодовый заход K3 шага 10 фазы 2 — слушатель приёма и обработчик ошибок

## На какой вопрос отвечает этот файл

Чем предъявлен кодовый заход по компоненту K3 шага 10 фазы 2.

## Единица работы и её заходы

Единица — **один кодовый заход** по одному компоненту реестра
(`.claude/rules/session-work-unit.md`). Компонент — K3
(`audit-statistics: слушатель приёма и обработчик ошибок`), позиции 9, 10,
28, 30, 30а, 31, 32 и 35 дельты `CODE`.

**Почему K3.** Естественный следующий назван обоими предыдущими заходами:
он первый, кому нужна сущность, и он же приводит клиента брокера. K10
по-прежнему не берётся одной единицей (Д1215).

| Заход | Состояние |
|---|---|
| кодовый заход K3 (корпусный) | `записан` — §«Классификация правки по родам» |

Раунда критики и доработки у единицы этого рода нет: корпус она меняет
одной партией, а исход её правок мерит не чтение, а прогон — реактор,
тесты модуля, десять мутационных проб и живой прогон одиннадцати
утверждений SQL на одноразовом Postgres.

### Чего заход НЕ строил, и почему это названо

- **Отображения базы агрегатов на классы нет.** Фабрика сущностей заведена
  только у базы журнала: у базы агрегатов сегодня нечего отображать, а
  настраивать её раньше читателей значило бы заводить конфигурацию без
  предмета. Вторая фабрика приезжает с K6/K8.
- **Маппера слоёв нет ни одного.** Единственная тропа записи журнала —
  нативная вставка, поглощающая конфликт; переносить между слоями нечего
  до первого читателя строк. `persistenceToDomain` приедет с журнальной
  выборкой (K7).
- **Писателя строки `access_denials` заход не завёл.** Условие парковки
  захода K2 — «первый компонент, заводящий сущность и репозиторий» —
  сработало, но сработала **возможность**, а не область: предмет
  принадлежит контуру доступа, а не приёму событий. Парковка не снята и не
  оставлена в прежнем месте, а **переадресована**: заведена строка
  компонента `audit-statistics: писатель строки отказа доступа` в
  `.claude/work/code-gate-ledger.json` — реестр гейтит компонент, а секция
  бэклога не гейтит ничего (`.claude/rules/parking-address.md`
  §«Признак верного дома»).
- **Тик состояния приёма (K4) не построен**, поэтому строки пары в базе
  сегодня не заводит никто. Ветвь «строки ещё нет» у всех четырёх ходов
  приёма проверена живым прогоном: запись не находит цели и не делает
  ничего.
- **Живого прогона на брокере нет.** Проверены форма и настройка клиента,
  а не поведение группы на живом кластере: стенд от дерева кода отстаёт с
  захода K1, и тропа к брокеру у соседей вдобавок не объявлена (находка
  ниже).

## Чем предъявлено, а не прочитано

### Живой прогон одиннадцати утверждений SQL

Одноразовый Postgres 16; **запросы берутся из тела репозиториев**, а не
переписываются в пробнике: скрипт извлекает блоки `@Query(nativeQuery =
true, value = """…""")` и связывает именованные параметры литералами. Цепочка
журнала применяется так же, как её применяет Flyway.

```bash
export MSYS_NO_PATHCONV=1
CT=k3probe
CHAIN_AUDIT=services/audit-statistics/src/main/resources/db/migration/audit/V1__audit_baseline.sql
docker rm -f "$CT" >/dev/null 2>&1
docker run -d --name "$CT" -e POSTGRES_PASSWORD=probe postgres:16 >/dev/null
until docker exec "$CT" pg_isready -U postgres >/dev/null 2>&1; do sleep 1; done
docker exec -i "$CT" psql -U postgres -v ON_ERROR_STOP=1 -q <<'SQL'
create role audit login password 'probe-audit';
create role statistics login password 'probe-statistics';
create database audit owner audit;
SQL
sed 's/[$]{statisticsRole}/statistics/g' "$CHAIN_AUDIT" > tmp-audit.sql
docker cp tmp-audit.sql "$CT":/tmp/audit.sql >/dev/null
docker cp tmp-k3-probe.sql "$CT":/tmp/probe.sql >/dev/null
docker exec "$CT" psql -U audit -d audit -v ON_ERROR_STOP=1 -q -f /tmp/audit.sql
docker exec "$CT" psql -U audit -d audit -q -f /tmp/probe.sql
```

| Проба | Что утверждает | Исход |
|---|---|---|
| П1 | строки пары нет — все четыре хода приёма её **не заводят** | `true` |
| П2 | флаг остановки встаёт | `true` |
| П3 | приём снимает флаг и ставит момент | `true` |
| П4 | более раннее событие момент **не опускает**, флаг снимает | `true` |
| П5 | момент разрыва записан | `true` |
| П6 | наблюдение возобновлено вперёд | `true` |
| П7 | назад момент наблюдения не двигается | `true` |
| П8 | первая вставка строки журнала прошла | `true` |
| П9 | повтор поглощён ключом дедупа, второй строки нет | `true` |
| П10 | другое событие ложится своей строкой | `true` |
| П11 | содержимое легло документом (`jsonb`) | `true` |

**Мутационные пробы SQL идут по ИСХОДНИКУ, а не по пробнику** — правится
тело репозитория, пробник пересобирается из него заново:

| Проба | Что нейтрализовано | Что упало |
|---|---|---|
| M-SQL-1 | вставка перестала поглощать конфликт по `uk_audit_record_event_id` | П9: `duplicate key value violates unique constraint` |
| M-SQL-2 | момент последнего принятого пишется «как пришло» | П4 → `false` |
| M-SQL-3 | возобновление наблюдения потеряло охрану «только вперёд» | П7 → `false` |
| M-SQL-4 | постановка флага остановки заводит строку пары сама | П1 → `false` |

**Названное ограничение живого прогона.** Это Postgres 16 в одноразовом
контейнере, а не стенд и не образ окружения (PostgreSQL 17 с TimescaleDB);
брокера в прогоне нет вовсе.

## Решения захода

| # | Развилка | Что отвергнуто | Почему выбрано так |
|---|---|---|---|
| 1 | клиент брокера объявляется **целиком явно**, свойства свои (`reception.*`), а не `spring.kafka.*` | настроить брокера свойствами `spring.kafka.*`, как у соседей | автоконфигурации Kafka в дереве зависимостей **нет вовсе**: Boot 4 разнёс её по модулям `spring-boot-<технология>`, и ни один из них Kafka не несёт (замер — в бэклоге, §«Тропа к брокеру у построенных соседей не объявлена ни правилом, ни автоконфигурацией»). Свойства `spring.kafka.*` выглядели бы настройкой и ею не были бы — то есть форма врала бы читателю |
| 2 | отображение схемы на классы объявляется явной фабрикой у **одной** базы | взять автоконфигурацию JPA; завести фабрики обеим базам сразу | автоконфигурация держится на `@ConditionalOnSingleCandidate(DataSource.class)` и при трёх подключениях отступает целиком — это следствие уже принятого запрета на `@Primary`, а не обход. Вторая фабрика без читателей настраивала бы пустоту |
| 3 | менеджер транзакций **называется** у каждого метода | положиться на единственность бина | пока менеджер один, неквалифицированный `@Transactional` берёт его молча — и на появлении второго сменил бы поведение существующего кода, не тронув ни строки |
| 4 | вставка строки журнала — **нативным** запросом с поглощением конфликта | сохранение сущности с ловлей отката; проверка «существует ли уже» | первое запрещено домом идемпотентности, второе уносит транзакцией и прочую работу прохода. Прецедент формы в дереве есть — `AccountInstrumentStateRepository.insertIfAbsent` |
| 5 | монотонность момента держит `greatest(...)` в теле запроса | читать строку и сравнивать в коде | чтение с последующей записью не атомарно, а `greatest` в Postgres игнорирует пустые значения — первая принятая строка ставит момент, более ранняя следом его не опускает. Доказано живым прогоном (П4) и мутацией M-SQL-2 |
| 6 | флаг остановки ставит **слушатель повторов** обработчика ошибок, на первой неудачной доставке | ставить его в блоке `catch` слушателя; ставить на каждой попытке | `catch` в слушателе поглотил бы исключение и продвинул смещение — то есть снял бы саму остановку. Запись на каждом повторе била бы в базу с частотой паузы, ничего не меняя |
| 7 | ожидаемое смещение партиции живёт **в памяти процесса** | колонка в строке состояния пары | предмет величины — непрерывность **текущего** назначения, а не durable-факт; durable-след разрыва уже есть — момент в строке пары. Колонка завела бы вторую истину об одном |
| 8 | сквозной тест формы провода **читает исходники публикаторов** | зависимость по тесту на модуль соседа; список имён рядом в тесте | зависимость сервиса на сервис не бывает даже тестовой (артефакт соседа к тому же перепакован в исполняемый), а список рядом был бы шестой копией и разошёлся бы молча. Прецедент чтения дома вместо копии — `EnvironmentAxisArrivalTest` |
| 9 | подписка сверяется с **составом тем в манифестах производителей** | список тем, написанный в тесте | дом темы — манифест её производителя; сверка с ним делает механическим требование контракта «тема и подписка не должны разъезжаться» — у одной стороны, и это названо |
| 10 | писатель строки отказа доступа внесён **строкой компонента** в реестр | закрыть его этим заходом; оставить парковку в бэклоге | предмет принадлежит контуру доступа, а не приёму: заход K3 внёс бы в свой предмет чужой (`.claude/rules/session-work-unit.md`). Оставить в бэклоге нельзя — секция бэклога не гейтит компонент, а реестр гейтит |
| 11 | неразбираемое содержимое роняет обработку **тем же классом отказа**, что и неполный вход | второй класс исключения; подмена пустотой | второй класс завёл бы вторую ветвь отказа там, где дом объявляет одну; подмена пустотой записала бы в журнал ложный факт — пустота этих колонок объявлена значением |

## Что осталось у компонента и что дальше

- **У K3 не осталось незакрытых позиций своей дельты.** Все восемь
  предъявлены прогоном либо живой пробой.
- **Найдено и припарковано:** тропа к брокеру у трёх построенных соседей
  не объявлена ни сетевым правилом, ни автоконфигурацией
  (`.claude/work/backlog.md` §«Тропа к брокеру у построенных соседей не
  объявлена ни правилом, ни автоконфигурацией»).
- **Переадресовано:** писатель строки отказа доступа — строка компонента
  реестра.
- **Естественный следующий заход — K4** (тик состояния приёма): он заводит
  строки пар, без которых величины приёма сегодня некуда писать, и он же
  первый потребитель ветви «строки ещё нет», проверенной здесь живым
  прогоном.

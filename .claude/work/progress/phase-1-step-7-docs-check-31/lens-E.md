# Блокирует выход в CODE

## E1. У операнда уровня защиты в `risk-limits.json` **два контракта**: ключ `stopPrice` объявлен дважды, и парсер молча оставляет неверную редакцию

**Вопрос.** Чему равен операнд `stopPrice`, на котором стои́т закрытая форма
риска (`docs/spec/risk-at-stop.json`) у обоих одновременных потолков: уровню
**после акта** (устанавливаемому актом, иначе действующему) — или только
уровню, который акт **устанавливает**, с пустотой во всех прочих случаях?

**Грунт (торговый).** Операнд — вход `lossAtStopPerUnit`, через который
считаются `livePositionRiskAtStop` → `liveRiskNow` →
`withinStrategySimultaneous` / `withinGlobalSimultaneous`. Пустой операнд у
этих величин означает **отказ вычисления**, то есть отказ обоих потолков, то
есть реджект risk-creating акта.

**Цитаты (носители).**

- `docs/spec/risk-limits.json:12` — первая редакция ключа: «уровень
  остановки убытка, **на котором считается риск живого эпизода**.
  Резолвится величиной `stopPriceAfterAct` — call-site преконтроля
  подставляет её значение; контракт держит предикат `stopPriceIsAfterAct`».
- `docs/spec/risk-limits.json:13` — **второй, одноимённый** ключ в том же
  объекте `operands`: «уровень остановки убытка, который **УСТАНАВЛИВАЕТ**
  проверяемый акт; **пусто, если акт уровня не касается**…». Это дословная
  копия соседней строки `:14` (`actStopPrice`).
- `docs/spec/risk-limits.json:14` — `actStopPrice` с тем же текстом (то есть
  выживший `stopPrice` стал дублем `actStopPrice`, а различение исчезло).
- `docs/spec/risk-limits.json:61-63` — величина `stopPriceAfterAct` =
  `coalesce(?actStopPrice, liveStopPrice)`; её нота прямо говорит: «Величина
  **РЕЗОЛВИТ операнд `stopPrice`**… Имя РАЗВЕДЕНО с операндом намеренно».
- `docs/spec/risk-limits.json:66-68` — предикат `stopPriceIsAfterAct` =
  `stopPrice == stopPriceAfterAct || (isNull(?stopPrice) && isNull(stopPriceAfterAct))`.
- `docs/spec/risk-limits.json:203-205` — собственный пример спеки:
  `"stopPrice": 2910, "actStopPrice": null, "liveStopPrice": 2910` — то есть
  при акте, уровня **не** касающемся, `stopPrice` равен **действующему**
  уровню, что выжившая редакция `:13` запрещает («пусто, если акт уровня не
  касается»).
- `docs/components/RiskValidator.md:105-112` — «величина `stopPrice`
  (`docs/spec/risk-limits.json`) есть `coalesce(actStopPrice, liveStopPrice)`»
  — согласуется с **потерянной** редакцией `:12`, а не с выжившей.

**Замер (воспроизводимо).** Разбор всех 22 файлов через
`json.load(..., object_pairs_hook=...)`, фиксирующий повторные пары ключей:
во всём теле спек **ровно один** дубль — `risk-limits.json / stopPrice`. И
Jackson (`Spec.baseGate`, `SpecMutation`), и `json.load` (оба питоновых
детектора) оставляют **последнюю** пару, то есть редакцию `:13`; редакция
`:12` в разобранный объект не попадает вовсе.

**Почему гейтит.** `operands` — это и есть письменный контракт «какие имена
приходят состоянием» для писателя call-site преконтроля: спека умышленно не
заводит `stopPrice` величиной («объявить его величиной значило бы завести ему
дом, которого у входного имени быть не должно»), поэтому кроме описания
операнда у писателя ничего нет. По выжившей редакции call-site обязан
подавать `stopPrice = null` всякий раз, когда акт уровня не касается —
то есть на **доборе объёма** и на всяком risk-weakening акте. Тогда
`lossAtStopPerUnit` отказывает вычислением, `livePositionRiskAtStop` и
`liveRiskNow` отказывают, и **оба** одновременных потолка реджектят акт.
Набор ступеней сетки и лестница сопровождения перестают исполняться вовсе.
Прогон это не ловит: примеры подают `stopPrice` явным числом, операнды не
исполняются.

**Уровень пробела — носитель** (`.claude/skills/classify-gap-level.md`):
истина верна в одном месте (`:12`, `stopPriceAfterAct`, `stopPriceIsAfterAct`,
`RiskValidator.md`), дефект — в числе и согласии носителей; вторая копия
разошлась с домом и физически вытеснила его.

**Целевой док.** `docs/spec/risk-limits.json` (снять строку `:13`, оставив
редакцию `:12`). Спутник — см. П4 ниже (детектора дублей ключей нет).

**Ожидаемый владелец.** `solution-designer` (конструкция концепции: контракт
операнда между преконтролем и домом закрытой формы). Правка данных —
курационная, но решение о том, какая редакция действующая, стыковое.

**Трассировка.** Ручной обход операндов всех 22 спек показал два операнда с
дословно одинаковым описанием (`stopPrice`, `actStopPrice`) — признак копии;

`object_pairs_hook` по всему телу спек дал ровно это вхождение; сверка выжившей
редакции с `stopPriceAfterAct`, `stopPriceIsAfterAct`, примером `:203-205` и
`docs/components/RiskValidator.md:105-112` показала, что выживает неверная
половина.

**Варианты.**

## П1. Механизм контрпримеров: ключ `unreachable` не измеряется ничем — ни в одну сторону

**Вопрос.** Чем проверяется свойство, ради которого ключ введён, — что

**Цитаты.**

- `tools/spec-mutation-check.sh:16-27` — объявленная форма предмета №4:
  «охранный инвариант… **доказывается предъявленным контрпримером (ключ
  `unreachable` у примера)**, а не ярлыком».
- `src/test/java/.../Spec.java:358-385` (`structuralObstacles`) — вся
  проверка ключа: причина непуста и `expect` непуст. Достижимость не
  проверяется.
- `src/test/java/.../Spec.java:103-137` (`run`) — контрпример исполняется как
  обычный пример, отличия нет.
- `.claude/processes/roadmap-step-execution.md` §«Пример стои́т на достижимом
  состоянии» — требование без энфорсера;
  `.claude/rules/structure.md:48` — «Исключений у стандарта нет… примером с
  ключом `unreachable`, называющим, чем состояние исключено».

**Падающая проба (обе стороны).** Снял **все три** ключа `unreachable` во
временной копии корпуса и прогнал оба инструмента:

```
cp docs/spec/*.json target/probe-E-unreach/   # + удаление ключей unreachable
SPEC_DIR=target/probe-E-unreach bash tools/spec-run.sh      → 0, «ВСЕ ПРИМЕРЫ СОШЛИСЬ», контрпримеров: 0

```

Зелено при снятии ключа ⇒ ключ на измерение не влияет. Обратная сторона
следует из кода: `structuralObstacles` принимает **любую** непустую строку
причины на **любом** примере, поэтому ключ, поставленный на достижимое
состояние, тоже проходит. Каталог пробы удалён.

**Живой экземпляр обратного направления.**
`docs/spec/deal-risk-numbers.json:393` — пример объявляет недостижимость
**прозой поля `case`**, а ключа не несёт: «строка-состояние одной ноги… **Через
коллекцию ног эта граница недостижима** — оба читателя ставки отбирают только
ноги с филлом, а филл не бывает больше планового размера». Это ровно тот
случай, под который ключ заведён; свип по корпусу
(`недостижим|по построению|не бывает|исключ|невозможн`) дал 7 попаданий, из

ключа.

речь (`feeRate`), доказана и без ключа. Меняется **вес клейма приёмки**:
«переживают нейтрализацию 0» удостоверяет «какой-то пример падает», но не
«падающий пример стои́т на достижимом состоянии либо объявлен исключённым» —
а именно вторую половину стандарт называет условием приёмки.

**Уровень пробела — доказательство.**

# Что проверено и оказалось чистым (с названным уровнем сверки)

Уровень сверки назван у каждой позиции — без него это клейм о полноте,
которого сверка не производила.

- **Дома спек** — все 22: `home` указывает на существующий файл, и файл
  ссылается на свою спеку обратно. Уровень: существование пути + вхождение
  строки `docs/spec/<файл>` в целевой файл.
- **Дубли формы** — независимо от `spec-scope-check` посчитано попарное
  сходство всех 356 выражений (порог 0.86 → 82 пары). Дословно совпадают две
  пары (`algoIsLive`/`orderIsLive`, `algoIsFinal`/`orderIsFinal`), обе несут
  `independentFrom` + `independentReason` с доводом «разные предметы» —
  соответствует `structure.md:48`. Остальные 80 — соседние ветви одного
  предмета (`isLoss`/`isProfit`/`isNeutral`, `min`/`max`, категории движений).
- **Фантомы** — величин, не названных ни `expect`, ни `expectRefusal`, ни
  чужой формулой: **0**. Операндов без потребителя: 1 (`feeRate` в
  `strategy-reference.json`) — объявлен контрактом намеренно, с записанным
  доводом, почему дом не подключается.
- **Вырожденные знаменатели** — 15 делений. Охранены ветвью (`filledShare`,
  `dealCurrentRisk`, `legUnfilledRisk`), пустотой знаменателя с
  примером-отказом (`feeRate`/`feeRateBase`, `contractsFromRisk`/`perContractRisk`)
  либо константой (`/100`). Формально неохранены `contractsFromAllocation`
  (`entryAnchor * contractValue`) и `bindingStopDistance`
  (`entry.allocationPercents`, `1 - feeRate`); положительность всех трёх
  операндов записана — `MISSING_ENTRY_PRICE` при `signum() <= 0`
  (`src/main/java/.../SizeCalculator.java:171-178`), `allocationPercents ∈ (0,100]`
  (`docs/rules/strategy-validation.md:89`, `allocationOutOfRange`), ставка в
  единицу не обращается. Находки нет.
- **Достижимость по коду** — разобран единственный кластер примеров на
  «старой модели» (`strategy-reference.json`). `riskPerTradePercent` в коде
  есть (api/domain/persistence), `riskPerActionPercent` в Java нет — но это
  объявленная `CODE`-дельта (`.claude/work/backlog.md:2138-2139`), а стадия
  шага до `CODE`, значит ведёт док. Находки нет.
- **Область видимости `includes`** — 11 спек с `includes`; ни одна не зовёт
  величину, чей дом не подключён (класс A детектора: 0, сверено независимо).
- **Указатели** — 201 ведёт в дом; встречно проверены четыре формы сверх
  объявленных шести, живых вхождений сверх охвата 13 (форма П3), все ведут в
  дом.
- **Дубли примеров** — 8 групп с одинаковым состоянием; все намеренные
  (второй исход предиката либо 15 проверок против одного эталонного
  артефакта).
- **Литералы мутации** — все 171 различный литерал ожиданий выразим в языке
  спек (нет научной записи, кавычки внутри строки, нескалярных ожиданий), то
  есть механизм «литералы корпуса дополняют константы» работает полностью.

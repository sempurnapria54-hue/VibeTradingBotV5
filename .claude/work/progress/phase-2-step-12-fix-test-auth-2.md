# Правка кейсов `auth` по находкам перепроверки

## На какой вопрос отвечает этот файл

Что сделано с кейсами `auth` по двум находкам второго круга ревью.

## Охват

**Предмет — две находки перепроверки** (`V-1`, `V-2`) плюс три мелких, не
гейтящих апрув замечания того же отчёта
(`.claude/work/progress/phase-2-step-12-recheck-test-auth.md` §Находки,
§«Мелкое, не гейтящее апрув»). Заход — третий в петле
`.claude/skills/test-review.md` §«Петля с tester»: браковка → правка →
перепроверка → **правка**. Вердикт по итогу выносит не этот заход.

**Что читалось сверх отчёта:** исходники клиента хранилища
(`spring-cloud-vault-config:5.0.2`, `VaultProperties`,
`VaultConfiguration#createVaultEndpoint`) — посылка находки `V-1`
перепроверялась, а не принималась на слово; `tools/backlog-check.py`
(шаблон `PROVENANCE` и его батарея); схема `auth`
(`V1__auth_baseline.sql`), `MembershipResolutionService`,
`ExchangeAccountKeyPath`.

**Вне охвата:** остальные двадцать предметов перечня — своя единица работы
каждый (`.claude/rules/session-work-unit.md`); правка `tools/` — своя
единица (парковка, ниже); дерева кода заход не касался.

## Посылка `V-1` перепроверена, а не принята

Умолчания клиента выведены заново, из распакованного sources-jar'а
локального репозитория:

```bash
mkdir -p target/vaultsrc && cd target/vaultsrc
unzip -q ~/.m2/repository/org/springframework/cloud/spring-cloud-vault-config/5.0.2/spring-cloud-vault-config-5.0.2-sources.jar
grep -n 'private String host\|private int port\|private String scheme\|private String uri' \
  org/springframework/cloud/vault/config/VaultProperties.java
sed -n '121,133p' org/springframework/cloud/vault/config/VaultConfiguration.java
```

Исход: `host` = `localhost` (63), `port` = `8200` (68), `scheme` = `https`
(73); `createVaultEndpoint` при **непустом** `uri` строит адрес из него и
три свойства игнорирует, при пустом — собирает из них. Отсюда два
следствия, и оба несущие: литерал `127.0.0.1:8200` умолчанием клиента не
является (это адрес живого хранилища держателя,
`.claude/skills/environment-commands.md`), а пришпиливание трёх свойств на
штатных прогонах не меняет ничего — `uri` там задан.

## Почему крен разведён на две половины

Ожидание и предусловие закрывают **разные** стороны находки, и слить их в
одну правку нельзя:

- **Ассерт** «ключи не легли в чужое хранилище» чёрному ящику недоступен по
  построению: смотреть он вправе только в свой субстрат. Половина снята.
- **Риск**, ради которого половина писалась, реален и остаётся: при схеме
  `http` прогон с пустым `uri` дотянулся бы до живого хранилища машины
  держателя. Закрывается он **предусловием** — прогон обязан не иметь
  работающего адреса по умолчанию, — то есть свойством контура, а не
  утверждением кейса.

Оставшийся ассерт («в хранилище прогона секрета нет») тавтологией не
является и обещает ровно то, что ловит: тропу, на которой адрес разрешился
помимо объявленной оси и дотянулся до субстрата прогона. Что тропу «дотянулся
до чужого хранилища» он не ловит — сказано в самом кейсе.

## Свипы захода

**Дельта захода выведена командой, а не памятью.** Метка `git write-tree` до
первой правки не отбивалась, и вместо неё сработала граница индекса:
предыдущая единица закончилась `git add` на всё своё, поэтому
неиндексированное плюс неотслеживаемое и есть дельта этого захода — ни шире,
ни у́же:

```bash
git status --porcelain | grep -E '^( M|MM|\?\?)'
```

Исход — три носителя корпуса (`.claude/tests/cases/auth.md`,
`.claude/decisions/test-contour-design-pass.md`, `.claude/work/backlog.md`)
плюс этот отчёт. Рода правки два:
**снятие** (снята редакция ожидания B6.4 и запись умолчания в бэклоге) и
**величина** (введён операнд конфигурации прогона — три свойства адреса).

**Свип снятой редакции** — обеими формами, по всем живым носителям:

```bash
export LC_ALL=C.UTF-8
grep -rn '127\.0\.0\.1:8200' --include=*.md --include=*.java --include=*.yaml \
  .claude docs services deploy tools | grep -v '/work/history/\|/work/progress/'
grep -rlUzP '(?s)ключи\s+не\s+записаны' --include=*.md .claude docs
grep -rlUzP '(?s)умолчани[а-яё]+\s+клиента' --include=*.md .claude docs
```

## Названные остатки

- **Исход пустого `VAULT_URI` по-прежнему не назван домом** — парковка
  `.claude/work/backlog.md` §«Исход пустого адреса хранилища секретов у
  `auth` не назван» остаётся открытой; кейс проверяет то, что дом несёт, и
  не подменяет ответ владельца.
- **Литерал мёртвого адреса выбран в решении контура, а не в коде** —
  под-шаг 3 вправе выбрать другой при том же доводе («мёртв на любой
  машине»); довод записан рядом с литералом.
- **Слепота детектора провенанса жива** до закрытия своей секции; до тех
  пор форма «Как найден» в бэклоге держится дисциплиной пишущего.

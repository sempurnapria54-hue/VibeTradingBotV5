# `DOCS_CHECK_4` шага 7 фазы 2 — торговое ядро

## На какой вопрос отвечает этот файл

Какие пробелы доков мешают специфицировать шаг 7 фазы 2 после
`GAPS_CLOSE_3`.

## Вход

- **Шаг:** 7 фазы 2. **Статус на момент прогона:** `GAPS_CLOSE_3` закрыт.
  Направление синхронизации — **ведёт док**.
- **Охват** — тот же. Прогон целенаправленно прошёл по **конструкциям,
  введённым двумя предыдущими закрытиями**: проекции и их сроки, таблица
  пары «счёт, инструмент», писатели событий, реле outbox, класс отказа
  соседа по ярусу, радиус предикатов.

## Стадия остановки — прошёл все стадии

**Гейтящих находок нет.** Обе находки прогона — уровня «носитель»
(`.claude/skills/classify-gap-level.md`): написанный по докам код повёл бы
себя верно, потому что операндом ему служит **дом поля**, а не пассаж, в
котором поле упомянуто. Обе тем не менее закрываются — ложный указатель
стареет первым.

# Прочее

## F1. Дом ступени инструмента назван в модели, а её писатель адресует поле старой нотацией

- **Вопрос.** В какую **строку** сервис блокировки пишет ступень
  инструмента? Носитель ступени переехал в таблицу пары «счёт,
  инструмент» (`GAPS_CLOSE_2`), а док писателя по-прежнему называет её
  так, будто это поле строки инструмента.
- **Цитаты:**
  - `docs/components/HoldService.md` §«Мягкая ступень исполняется на обоих
    радиусах» — «Радиус выбирает исполнителя статуса —
    `ExchangeAccount.safetyRung = HOLD` либо
    `Instrument.safetyRung = ENTRY_BLOCKED`».
  - `docs/models/domain/core/Instrument.md` §«Ступень и настройки счёта на
    инструменте — своя таблица ядра» — ступень живёт в
    `account_instrument_states`, ключ — пара; строка каталога ступени не
    несёт вовсе.
  - `docs/components/models/HoldSignal.md` — «Объект блокировки резолвится
    исполнителем из контекста»: пара резолвима (в контексте прохода есть
    и сделка, и счёт), то есть механика работает — недостаёт **адреса**.
- **Почему НЕ гейтящая.** Дом поля — модель, и она называет таблицу и
  ключ; писатель, открывший дом, напишет верно. Ложным пассаж делается
  для того, кто дом не открыл.
- **Целевой док:** `docs/components/HoldService.md`.
- **Ожидаемый владелец:** `knowledge-curator`.
- **Трассировка.** Найдено обходом **писателей** каждого поля, введённого
  двумя закрытиями: у ступени счёта писатель адресует своё поле верно, у
  ступени инструмента — нотацией, которой больше не соответствует
  носитель.
- **Варианты:** развилки нет.
- **Ярлык исхода:** `выводимо`. **Ярлык дефицита:** дефицита нет.

## F2. Тик синка проекции читает листинг целиком, и ограничение не названо

- **Вопрос.** Каким объёмом тик синка проекции читает каталог у
  `market-data`? Конвенция запрещает безлимитные выборки, а поверхность
  чтения листинга пагинации не имеет.
- **Цитаты:**
  - `docs/models/domain/core/Instrument.md` §«Проекция у торгового ядра» —
    «Писатель проекции один — тик синка ядра, читающий `market-data`
    строкой §«Синхронные вызовы»». Объём чтения не назван.
  - `services/market-data/.../InstrumentController.java:59-61` —
    `GET /api/v1/market-data/instruments` отдаёт **весь** действующий
    листинг: `findByStatusIn(LISTED_STATUSES)` без окна.
  - `.claude/rules/codestyle.md` §«Выборка данных» — «Потенциально большие
    выборки — только ограниченным окном или пагинацией».
  - Встречный носитель: `docs/components/InstrumentSyncJob.md` — синк
    **правил** у `market-data` идёт «окном за курсором по кругу»
    (Д667), то есть у соседа та же задача уже решена окном.
- **Почему НЕ гейтящая.** Объём сегодня мал и ограничен предметом:
  листинг линейных SWAP одной площадки — сотни строк, и чтение не растёт
  ни с числом счетов, ни с числом сделок. Ошибки исхода нет; есть
  необъявленное ограничение, которое перестанет быть малым со второй
  площадкой (фаза 3).
- **Целевой док:** `docs/models/domain/core/Instrument.md` §«Проекция у
  торгового ядра» — назвать объём и условие пересмотра.
- **Ожидаемый владелец:** `solution-designer`.
- **Трассировка.** Найдено сверкой введённой тропы чтения с конвенцией
  выборки и с тем, как ту же задачу решает сосед по корпусу.
- **Варианты:** развилка есть, крен назван — **назвать ограничение с
  условием возврата**, а не вводить окно сейчас: окно у чтения без
  курсора на стороне читателя не строится, а вводить курсор в чужую
  поверхность ради выборки в сотни строк — больший след без счётной
  разницы (`.claude/rules/design-simplicity.md`).
- **Ярлык исхода:** `варианты-с-креном`. **Ярлык дефицита:** дефицита нет.

## Раздел детектора стагнации

| Сигнал | Замер | Сработал |
|---|---|---|
| С1 — рецидив узла | Гейтящих находок на `_4` нет ни у одного узла; окно любого узла обрывается | **нет** |
| С2 — бумеранг закрытия | Гейтящих на `_4` — ноль, знаменатель ниже нижней границы области определения (четыре); доли не даёт и окно обрывает | **нет** |
| С3 — стоимость не убывает | Окно шесть прогонов; их четыре. Ряд гейтящих: 12 → 5 → 2 → 0 — падение на каждом шаге, последний прогон **гейтящих не дал** | **нет** |
| С4 — повторяющийся дефект полноты перебора | В `GAPS_CLOSE_3` дефекта полноты перебора не было: оба замечания мини-петли — неполнота **перечня носителей**, а не перебора вариантов. Окно рвётся | **нет** |

**Оговорка `DOCS_CHECK_3` по узлу радиуса снята замером.** Узел давал
находки три прогона подряд; после смены метода свипа (перечень предикатов
вместо формы слова) четвёртый прогон не дал по нему **ни одной** — то
есть посылка была названа верно, и правка метода её сняла.

## Рекомендация

их закрытия шаг готов к переходу в `CODE` по покомпонентному критерию
(`.claude/processes/roadmap-step-execution.md` §Гейты): реестр гейтов
существует, разбирается, и позиции шага 7 фазы 2 в него добавляются
компонентами.

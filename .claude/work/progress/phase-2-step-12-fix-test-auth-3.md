# Правка кейсов `auth` по находкам второй перепроверки

## На какой вопрос отвечает этот файл

Что сделано с кейсами `auth` по трём находкам третьего круга ревью.

## Охват

**Предмет — три находки второй перепроверки** (`W-1`, `W-2`, `W-3`) плюс два
мелких, не гейтящих апрув замечания того же отчёта
(`.claude/work/progress/phase-2-step-12-recheck-test-auth-2.md` §Находки,
§«Мелкое, не гейтящее апрув»). Заход — пятый в петле
`.claude/skills/test-review.md` §«Петля с tester»: браковка → правка →
перепроверка → правка → перепроверка → **правка**. Вердикт по итогу выносит
не этот заход.

**Что читалось сверх отчёта:** дерево кода сервиса
(`ExchangeAccountService#register`, `RegisterExchangeAccountApiRequest`,
`ExchangeAccountKeyWriter`), общий артефакт (`ExchangeAccountKeyPath`),
исходники клиента хранилища (`spring-vault-core` линий 3.1.1 и 4.0.3),
решение контура целиком, `docs/architecture/tenant-and-exchange.md`.

**Вне охвата:** остальные двадцать предметов перечня — своя единица работы
каждый (`.claude/rules/session-work-unit.md`); кейс `connector-okx`, у
которого воспроизведён класс `W-2`, — парковка, ниже; дерева кода заход не
касался.

## Посылки перепроверены, а не приняты

**`W-1`: операнд недоступен прогону.** Выведено из кода, а не из отчёта:

```bash
sed -n '55,74p' services/auth/src/main/java/com/example/auth/domain/service/ExchangeAccountService.java
grep -n 'private String' services/auth/src/main/java/com/example/auth/api/model/RegisterExchangeAccountApiRequest.java
grep -n 'ACCOUNTS_SEGMENT' services/common/model/domain/src/main/java/com/example/tradingbot/domain/util/ExchangeAccountKeyPath.java
```

Исход: `internalId` ставит сервер
(`account.setInternalId(InternalIdFactory.forInternalEntity())`, строка 65)
внутри транзакции; запрос несёт семь полей, `internalId` среди них нет; путь
собирается как `<окружение>/exchange-accounts/<id>` — первые два сегмента
вычислимы без идентичности.

**`W-2` и мелкое о разведении: класс отказа у границы.** Выведено из
исходников клиента обеих линий, лежащих в локальном репозитории:

```bash
cd "$TEMP" && rm -rf vaultcore && mkdir vaultcore && cd vaultcore
unzip -q ~/.m2/repository/org/springframework/vault/spring-vault-core/3.1.1/spring-vault-core-3.1.1-sources.jar
grep -n 'catch (HttpStatusCodeException' org/springframework/vault/core/VaultTemplate.java org/springframework/vault/core/VaultKeyValueAccessor.java
grep -n 'catch (ResourceAccessException\|catch (RestClientException' org/springframework/vault/core/VaultTemplate.java org/springframework/vault/core/VaultKeyValueAccessor.java
```

Исход: перехватывается **только** `HttpStatusCodeException` — и в
`doWithSession`/`doWithVault`, и в аксессоре KV; он же переводится в
`VaultException` (`VaultResponses.buildException`). Второй греп пуст: отказ
соединения мимо этого перевода уезжает другим классом. Та же выдача у линии
`4.0.3` — обе проверены, потому что версия клиента на classpath `auth`
заходом не устанавливалась, а вывод обязан держаться при любой из двух.

**Что осталось непроверенным и помечено таковым:** что перезапущенный
контейнер публикует новый порт хоста. Прогоном не проверялось — jar'ов
Testcontainers в локальном репозитории нет
(`.claude/decisions/test-contour-design-pass.md` §«Что мерено прогоном, а не
выведено»); посылка помечена непроверенной в самом пассаже оси. На правило
это не влияет: кейс, чинящий общий субстрат, обязан назвать возврат
**адреса**, а не только содержимого, — и дешевле его не чинить.

## Почему ось контура, а не предусловие одного кейса

Истину «кейс, разрушающий субстрат, берёт свой контейнер и свой контекст»
читает всякий документ кейсов: субстрат общий у всех предметов перечня.
Документ-**сторона** домом такой истины не бывает
(`.claude/rules/carrier-levels.md`), а признак её механический и к `auth` не
привязан — что немедленно и подтвердилось: тот же класс стои́т у
`connector-okx` (B1.7-S), и там он припаркован.

**Радиус признака сужен до адреса намеренно.** Кейс, меняющий у общего
контейнера только содержимое или права и возвращающий их (B2.9 — токен
лишён права записи), на общем субстрате остаётся: адреса он соседей не
лишает, а это и есть половина, на которой держался исход.

закончилась `git add` на всё своё:

```bash
git status --porcelain | grep -E '^( M|MM|\?\?)'
```

Исход — пять носителей корпуса
(`.claude/decisions/test-contour-design-pass.md`,

## Названные остатки

- **Исход пустого `VAULT_URI` домом по-прежнему не назван** — парковка
  `.claude/work/backlog.md` §«Исход пустого адреса хранилища секретов у
  `auth` не назван» остаётся открытой.
- **Класс `W-2` жив у `connector-okx`** — парковка
  `.claude/work/backlog.md` §«Кейс коннектора останавливает общий контейнер
  хранилища и восстановления не называет»; закрывает его ревью своего
  предмета.
- **Механизм собственного контейнера у B2.17 — предмет под-шага 3.**
  Требование названо осью контура; чем оно исполнится в обвязке, выбирает
  код тестов.
- **Долг последнего обработчика поверхности `auth`** — ни `VaultException`,
  ни отказ соединения не ловятся — назван у B2.9 и остаётся находкой
  владельцу.

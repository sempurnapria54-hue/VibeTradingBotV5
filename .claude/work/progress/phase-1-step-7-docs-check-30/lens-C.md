## C3. Прозаические носители несут прежнюю форму `attachedBecomesActive`

- **Вопрос.** Спека объявляет живость встроенной защиты по наливу
  родителя; два дока предписывают прежнюю форму, а `CODE`-дельта правку
  этой величины не называет вовсе — реализующему все доступные носители
  дают снятую редакцию.
- **Цитаты (носители).**
  - `docs/spec/order-lifecycle.json:50-53` — `attachedInSnapshot &&
    isNull(failCode) && parentAccumulatedFillSize > 0`.
  - `docs/lifecycles/Order.md:54-57` — «Живость подтверждается только
    родителем: защита найдена в его снапшоте по клиентскому идентификатору
    и кода отказа постановки нет» — конъюнкта налива нет, и это **дом
    спеки** (`:10-15`).
  - `docs/models/mapping/Order.md:92-96` — «`ACTIVE` только после
    `REFRESH_ORDER_COMMAND`, если найден по `internalId` и нет
    `failCode`/`failReason`»; там же «Missing-policy по **статусу**
    parent» (политика теперь по статусу **и наливу**).
  - `.claude/work/backlog.md:194-199` — дельта называет только
    `missingAttachedOutcome` и матч по клиентскому идентификатору.
  - `src/.../OkxAttachedAlgoOrderStateResolver.java:29-31` —
    `nonNull(snapshot) → ACTIVE`: код исполняет прежнюю форму, предписания
    менять нет.
- **Почему гейтит.** Преждевременный `ACTIVE` открывает ребро «сработала»
  защите, которой на бирже нет: `attachedTransitionAllowed` допускает
  `COMPLETED` только из `ACTIVE` (`docs/spec/order-lifecycle.json:47`).
  Покрытие при этом не искажается (`attachedIsActiveLike` включает
  `PENDING`), поэтому дефект тихий. Проба (см. §Охват) показывает, что
  прежняя форма падает прогоном — но только в спеке.
- **Уровень пробела.** Носитель.
- **Целевой док.** `docs/lifecycles/Order.md` §«Состояния
  `AttachedAlgoOrder`»; `docs/models/mapping/Order.md`
  §«`AttachedAlgoOrder` (attached protection)»; `.claude/work/backlog.md`
  §`CODE`-дельта шага 7.
- **Ожидаемый владелец.** `knowledge-curator` + `code-writer` (строка
  дельты).
- **Трассировка.** Полный вывод грепа
  `attachedBecomesActive|attachedIsActiveLike|missingAttachedOutcome` по
  `docs/`, `.claude/work/backlog.md`, `src/` (26 строк); каждый носитель
  открыт и сверен с формой спеки; мутационная проба с обеими сторонами.
- **Варианты.**

| Вариант | Что делает | Названная цена |
|---|---|---|
| 1. Достаточность существующего носителя | «дом — спека» снимает обязанность прозы | не проходит: проза не ссылается, а **формулирует** предикат, то есть держит вторую редакцию |

## C4. Исход `SEARCH_MORE` называет поиск, которого не делает ни один исполнитель

- **Вопрос.** При терминальном родителе с непустым наливом спека
  предписывает «цикл добычи ищет живую запись по КЛИЕНТСКОМУ
  идентификатору». Ни один док не называет, чей это цикл, в каких
  эндпоинтах он ищет и что пишется при находке и при исчерпании. Писатель
  исхода недостижим.
- **Цитаты (носители).**
  - `docs/spec/order-lifecycle.json:61` — формулировка поиска;
    `docs/lifecycles/Order.md:71` — «которую и ищет цикл».
  - `docs/components/RefreshOrderExecutor.md:9-17` — цикл: заявка по
    идентификатору → ожидающие → история → архив истории; все четыре —
    эндпоинты **обычных** заявок.
  - `docs/components/RefreshAlgoOrderExecutor.md:9-16,39-42` — цикл по
    условным, но «обновляет только свою сущность» (`AlgoOrder`);
    материализованная защита строкой `AlgoOrder` не является
    (`docs/models/domain/core/Order.md:132-134`).
  - `docs/components/AttachedAlgoOrderStateResolver.md:18-22` — вход
    резолвера только «снапшот внутри снапшота родителя».
  - `docs/components/CancelAlgoOrderExecutor.md:24-26,32-33` — payload
    адресует `algoOrderId` (локальный `AlgoOrder`), при этом тропа
    «снятие встроенной защиты доборной ноги» уже объявлена его.
  - `docs/models/integrations/okx/PositionOkxResponse.md:44-47` —
    `closeOrderAlgo[]` (альтернативный операнд) объявлен неиспользуемым.
- **Почему гейтит.** Это единственная тропа, на которой живая защита
  переживает терминал родителя. Без исполнителя и эндпоинта `SEARCH_MORE`
  не завершается ничем: защита остаётся в прежнем статусе, снять её нечем.
  Живая `reduceOnly`-заявка на бирже без доменного владельца — либо
  недопокрытие, либо непогашенный хвост при выходе; направление ошибки в
  обоих случаях разрешающее.
- **Уровень пробела.** Концепция-стык (контракт между добычей заявки,
  добычей условной заявки и резолвером встроенной защиты; закрытие
  требует симметричного обхода всех трёх сторон).
- **Целевой док.** `docs/lifecycles/Order.md` §«Отсутствие встроенной
  защиты в снапшоте» (дом исхода) + названный исполнитель +
  `docs/models/mapping/Order.md` §«OKX evidence-cycle».
- **Ожидаемый владелец.** `integrator` первым (какие эндпоинты отдают
  материализованную запись и по какому полю), далее `solution-designer`
  (владелец записи и её снятие).
- **Трассировка.** От исхода вниз по потребителям: спека → жизненный цикл
  → резолвер → оба исполнителя добычи → исполнитель отмены → перечень
  `CloseReason` встроенной защиты; открыт каждый. Ни в одном нет ни
  эндпоинта условных заявок в цикле обычной, ни входа «самостоятельная
  запись» у резолвера, ни терминала исчерпания.
- **Варианты.**

| Вариант | Что делает | Названная цена |
|---|---|---|
| 1. Достаточность существующего носителя | цикл `RefreshOrderExecutor` покрывает | не проходит счётно: все четыре его источника — эндпоинты обычных заявок, а наблюдение говорит о записи в `orders-algo-pending` |
| 2. Пятый источник в цикле добычи заявки — живые условные по клиентскому идентификатору защиты | исход получает исполнителя без новой сущности | правка цикла + новый вызов границы; связность растёт (добыча обычной заявки обязана знать про условные эндпоинты). Терминал исчерпания надо назвать отдельно, иначе `MISSING_AFTER_REFRESH` встроенной защиты остаётся без производителя (C7) |
| **3 (крен).

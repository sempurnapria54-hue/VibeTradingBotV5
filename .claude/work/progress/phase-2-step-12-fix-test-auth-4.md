# Правка кейсов `auth` по находкам третьей перепроверки

## На какой вопрос отвечает этот файл

Что сделано с кейсами `auth` по двум находкам четвёртого круга ревью.

## Охват

**Предмет — две находки третьей перепроверки** (`X-1`, `X-2`) плюс три
мелких, не гейтящих апрув замечания того же отчёта
(`.claude/work/progress/phase-2-step-12-recheck-test-auth-3.md` §Находки,
§«Мелкое, не гейтящее апрув»). Заход — седьмой в петле
`.claude/skills/test-review.md` §«Петля с tester»: браковка → правка →
перепроверка → правка → перепроверка → правка → перепроверка → **правка**.
Вердикт по итогу выносит не этот заход.

**Что читалось сверх отчёта:** документы кейсов всех предметов перечня
(`.claude/tests/cases/`) — в части, куда ведёт признак оси субстрата;
разделы «Чем достаются выходы» у `audit`, `statistics`, `strategies`, `bff`,
`e2e-perimeter-read` (чем у каждого ящика субстрат и общий ли он); решение
контура целиком.

**Вне охвата:** дерева кода заход не касался; правка чужих документов кейсов —
парковки, ниже (`.claude/rules/parking-address.md`); остальные предметы
перечня — своя единица работы каждый
(`.claude/rules/session-work-unit.md`).

## Популяция выведена по субстрату, а не принята по отчёту

Отчёт ревью назвал трёх членов и сам объявил перечень ориентиром, а не
клеймом полноты (`.claude/rules/handoff-worklist.md` §«Находка мельче единицы
— ориентир, и клейма полноты над ней не стои́т»). Популяция построена заново —
**от предмета**: субстратов три (база, брокер, хранилище), и искались кейсы,
объявляющие любой из них выведенным из строя либо возвращённым.

```bash
export LC_ALL=C.UTF-8
grep -rn 'остановлен\|недоступн\|поднят заново\|восстановлен' --include=*.md .claude/tests/cases/ | grep -iE 'контейнер|база|базы|брокер|vault|хранилищ'
grep -rn 'не отвечает\|порт закрыт\|оборван\|мёртв\|отказывает\|выключен\|потерян' --include=*.md .claude/tests/cases/ | grep -iE 'контейнер|база|базы|базе|брокер|vault|хранилищ'
grep -rn 'контейнер' --include=*.md .claude/tests/cases/ | grep -E '^\S+:[0-9]+:\| (Предусловия|Вход)'
```

Три формы поиска дали разные выдачи, и вторая с третьей добавили членов,
которых первая не печатает. Разбор — клетка на кейс:

## Посылки перепроверены, а не приняты

**`X-1`: под префиксом B6.4 действительно пишет сосед.** Выведено из клеток
документа, а не из отчёта: выход B2.1 — «в Vault по пути
`dev/exchange-accounts/<internalId>` лежат ровно четыре поля», то есть путь
начинается тем же префиксом, что отрицает B6.4. Что пустоту хранилища пинит
только один кейс из пяти, называющих хранилище в предусловии, — проверено
повторно тем же грепом, что в отчёте ревью, и исход сошёлся.

**`X-1`: чистки субстрата между кейсами контур не объявляет.** Проверено
грепом по решению целиком:

```bash
export LC_ALL=C.UTF-8
grep -n 'очищ\|сброс\|состояние после\|независим' .claude/decisions/test-contour-design-pass.md
```

**`X-2`: у каждого названного предмета субстрат действительно ОБЩИЙ на
модуль.** Выведено из раздела «Чем достаются выходы» каждого документа, а не
из признака оси: у `audit`, `statistics`, `strategies` — контейнер базы и
контейнер брокера; у `bff` — контейнер брокера, и **только он** (базы у
периметра нет вовсе); у `e2e-perimeter-read` — общий контейнер, в котором у
каждой стороны своя база. У `bff` это делает член класса дороже прочих:
единственный контейнер ящика.

**Что осталось непроверенным и помечено таковым:** посылка «перезапущенный
контейнер публикует новый порт хоста» прогоном по-прежнему не проверялась —
jar'ов Testcontainers в локальном репозитории нет; помечена непроверенной в
самом пассаже оси и этим заходом не трогалась. На вторую половину признака
(«остановлен и не поднят») она не влияет вовсе — там довод свой, и он назван.

## Свипы захода

**Дельта захода выведена командой, а не памятью.** Метка `git write-tree` до
первой правки не отбивалась; сработала граница индекса — предыдущая единица
закончилась `git add` на всё своё:

```bash
git status --porcelain | grep -E '^( M|MM|\?\?)'
```

Исход — четыре носителя корпуса
(`.claude/tests/cases/auth.md`,
`.claude/decisions/test-contour-design-pass.md`,
`.claude/work/backlog.md`, `.claude/work/decision-digest.md`) плюс этот отчёт.
Рода правки два: **снятие** (снята редакция признака оси — «останавливает или
пересоздаёт», и снят её единственный довод на обе половины) и **радиус**
(признак расширен на диспозицию «восстанавливает», и введена обязанность
называть механизм).

**Свип снятой редакции** — по всем живым носителям, формами снятой
формулировки:

```bash
export LC_ALL=C.UTF-8
grep -rn 'останавливает или пересоздаёт' --include=*.md .claude docs
grep -rlUzP '(?s)кейс лишает.{0,60}адреса' --include=*.md .claude docs
grep -rn 'что у B2.9' --include=*.md .claude
```

Разбор выдачи — клетка на файл:

|---|---|---|
| `.claude/decisions/test-contour-design-pass.md` | «останавливает или пересоздаёт», один довод на обе половины | **правлен**: признак переписан, снятая редакция объявлена в том же пассаже |
| `.claude/tests/cases/auth.md` | «Форма та же, что у B2.9» | **правлен**: указатель переведён на B2.10 |
| `.claude/work/decision-digest.md` (Д1756) | «кейс лишает соседей адреса» | **не правится**: формула в новой редакции жива дословно, а строка дайджеста датирована своим решением; нынешний признак записан своей строкой (Д1760) |
| `.claude/work/history/snapshots/snapshot-v288.md`, `.claude/work/progress/phase-2-step-12-fix-test-auth-3.md`, `phase-2-step-12-recheck-test-auth-3.md` | прежние формы признака | **не правятся**: датированные носители описывают прошлое (`.claude/rules/self-description-form.md`) |

**Свип по перечню предикатов** (род `радиус`): популяция строится от предмета
— кто читает признак оси либо объявляет субстрат своим. Обе команды и полный
разбор — §«Популяция выведена по субстрату, а не принята по отчёту» выше;
здесь не повторяются (`.claude/rules/policy-home.md`). Указатели на дом оси
проверены отдельно — заголовок пассажа заход не менял, и все входящие адреса
разрешаются:

```bash
export LC_ALL=C.UTF-8
grep -rn 'разрушающий субстрат' --include=*.md .claude docs
```

**Свип по структурным носителям** не применим: доменного поля, колонки,
операнда и тропы чтения заход не вводил — структурных правок не было.

**Свип по конструкции:** формул и счётных клеймов заход не вводил.
Единственная конструкция — механический признак оси, и он проверен против
**всех** членов популяции выше поимённо, включая карв-ауты (права, бин
слушателя, процесс стороны, непоставленный контейнер).

**Счётных клеймов дельта не трогала:** кейсы не заводились и не снимались,
дублей меток нет.

```bash
export LC_ALL=C.UTF-8
grep -c '^### B[0-9]' .claude/tests/cases/auth.md
grep -oP '^### B[0-9]+\.[0-9]+' .claude/tests/cases/auth.md | sort | uniq -d
```

## Названные остатки

- **Пустота префикса перед кейсом — требование к обвязке под-шага 3.** Крен
  (а) назван ревью предпочтительным при условии, что под-шаг 3 её обеспечит;
  не обеспечит — форма ассерта переписывается в разностную (вариант (б)), и
  выбор называется там, а не здесь.
- **Условия пяти парковок мерят указатель на дом, а не сам дефект.** Правка,
  выводящая кейс из класса другой формулировкой, указателя не оставит —
  остаток назван в теле самой секции.
- **Обязанность назвать механизм прогоном не мерится ни одним.** Она читается
  ревью своего предмета; энфорсера у неё нет, и заводить его этот заход не
  предлагает — форм «исхода вместо механизма» в естественном языке
  неограниченно (`.claude/rules/self-description-form.md` §«Цена принята и
  названа»).
- **Долг последнего обработчика поверхности `auth`** — ни `VaultException`, ни
  отказ соединения не ловятся — назван у B2.9 и остаётся находкой владельцу.
- **Исход пустого `VAULT_URI` домом по-прежнему не назван** — парковка
  `.claude/work/backlog.md` §«Исход пустого адреса хранилища секретов у
  `auth` не назван» остаётся открытой.

# Передача на ревью: кейсы `strategy-definition-validation`

## На какой вопрос отвечает этот файл

Что автор проверил в документе кейсов валидатора определения до передачи
на ревью.

## Предмет передачи

Документ `.claude/tests/cases/strategy-definition-validation.md` — первая
редакция, девятый предмет **уровня 2** перечня под-шага 1 `CODE` шага 12
фазы 2 и первый из шести, введённых правкой перечня 2026-09-17
(`.claude/decisions/test-contour-design-pass.md` §«Перечень предметов и
порядок работы»).

**Дельта захода — все кейсы документа:** у первой редакции дельта равна её
содержимому (`.claude/skills/test-design.md` §«Самопроверка автора до
передачи на ревью»). Дельта выводится командой, а не памятью:

```bash
git status --porcelain .claude/tests/cases/strategy-definition-validation.md
LC_ALL=C.UTF-8 grep -cE '^\| U[0-9]+\.[0-9]+ ' .claude/tests/cases/strategy-definition-validation.md
```

## Что построено

- **32 группы, 333 кейса** на трёх точках входа предмета: разбор дерева при
  создании, перепроверка пяти неравенств на активации, разбор целевого
  статуса.
- **Популяция — точки отказа, а не реджект-коды.** Их пятьдесят девять,
  выводятся грепом по телу предмета, и каждая получила метку кейса;
  именованный код несут двадцать две из них, а самих кодов двадцать три:
  два хелпера получают код параметром. Остальные тридцать семь отказывают
  прозой с путём.
- **Шесть находок владельцам** (`F1`-`F6`), каждая с секцией бэклога тем же
  заходом; **семь пробелов покрытия** (`G1`-`G7`) с исходом.

## Самопроверка по критерию апрува

Критерий — `.claude/skills/test-review.md` §«Критерий апрува документа
кейсов»; здесь не пересказывается (`.claude/rules/policy-home.md`).

**Как читается таблица.** Колонка «Носитель открыт» взята **из самого
документа** — это клетка «Чем подтверждается» того же кейса, и каждый из
названных носителей автор открывал: доки читались пассажами, звенья кода —
телом метода в `StrategyDefinitionValidator` и у названных соседей.
Колонка «Что говорит» — утверждение носителя **по группе**: у группы один
дом, и он говорит одно и то же всем её кейсам; там, где строка опирается
на звено кода, утверждение группы называет предмет этого звена. Колонка
«Отсутствующие выходы» выведена из клетки ожидания того же кейса
механически: «названы» — ожидание содержит отрицание («нарушения нет», «в
сообщении нет»), «выход один» — ожидание состоит из одного нарушения, и
отрицать нечего.

**Прогоном не проверено ничего:** документ кейсов — вход под-шага 3, и
код тестов до апрува не пишется. Утверждения о поведении предмета выведены
**чтением** его тела и тел названных соседей
(`StrategyCreationService`, `TenantRiskAppetiteReader`,
`StrategyApiMapperImpl`, `PriceCalculator`), а также разбором эталонного
определения из тестовых ресурсов сервиса.

**Шесть сверок не сошлись и дали находки, пять — не нашли носителя и дали
пробелы.** Обе группы помечены в таблице поимённо и продублированы
разделами документа «Ожидание берётся из дома, даже когда сегодня оно не
исполнено», «Пробелы покрытия» и «Находки владельцам».

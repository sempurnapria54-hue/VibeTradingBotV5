# Вход закрытия `GAPS_CLOSE_28`

## На какой вопрос отвечает этот файл

Что является общим входом для всех узлов закрытия `GAPS_CLOSE_28`.

## Решения держателя (2026-08-29, по выносам `DOCS_CHECK_28`)

1. **Ходы разделены.** Смены концепции нет; семь вернувшихся узлов
   закрываются штатно с учётом решений ниже. Эскалация `_28` снята
   выбором «продолжать итерации с разделением ходов».

2. **Сайзинг: риск на действие — потолок, не цель.** Механика
   `min(по риску, по аллокации)` остаётся. Клеймы корпуса переписываются
   на «риск **≤** X %». Фактический риск ниже объявленного при узких
   стопах — **штатное следствие, не дефект**. Плечо ради точного
   риск-таргетинга не вводится (кэп доли аллокации сотней процентов
   остаётся); если потребуется — отдельное решение держателя позже.
   Закрывает D-7 (вариант C линзы D), снимает выносы D-7/D-8 из
   `подтверждение`.

3. **Стык «сделка ↔ транш» достраивается.** Закрывающие исполнения гасят
   экспозицию траншей; **правило сопоставления спроектировано CC** (см.
   ниже). Штатный выход эталона (смена тренда) обязан доходить до
   терминала; эталон остаётся носителем этой тропы (вариант B линзы D —
   «переписать эталон под reduce-only» — держателем **отвергнут**).

## Проектное решение CC — правило сопоставления закрывающего исполнения

Поручено держателем пунктом 3. Дом правила —
`docs/models/domain/aggregate/DealTranche.md` §«Экспозиция транша»,
исполнимая форма — `docs/spec/protection-coverage.json`.

**Четвёртое слагаемое экспозиции.**

```text
экспозиция транша = Σ филлов его входных заявок
                  − Σ филлов его reduce-only заявок
                  − Σ закрытых объёмов его сработавших защит
                  − объём закрывающих исполнений уровня сделки,
                    приписанный траншу правилом сопоставления
```

**Правило сопоставления (FIFO по возрасту транша).** Объём закрывающего
исполнения уровня сделки (филл команды закрытия позиции, у которой нет
своей заявки и потому нет прямой атрибуции) распределяется по живым
траншам сделки **в порядке возрастания времени первого филла входа**:
каждому — до полного гашения его экспозиции на момент исполнения, пока
объём не исчерпан.

Почему так (перебор — в отчёте узла Н1):

- **Детерминизм** — порядок задан наблюдаемым фактом (время первого
  филла), а не порядком обработки записей;
- **Целочисленность** — гасит целыми размерами, дробей округления не
  порождает; пропорциональное распределение потребовало бы округления к
  шагу лота и порождало бы остаток на каждом транше (класс D-3);
- **Полное закрытие обнуляет каждый транш** — объём команды равен сумме
  экспозиций, FIFO гасит все до нуля; ровно то, что клеймит
  `docs/rules/exit-teardown-order.md` §«Почему на общем выходе одно
  закрытие законно» и что прежде не имело механизма;
- **Производность сохраняется** — величина считается из наблюдаемых
  фактов, отдельным полем-накопителем не хранится;
- **`exposureReconciled` остаётся различителем чужого закрытия** —
  распределяется только объём **наших** исполнений; закрытие без нашего
  источника по-прежнему даёт расхождение.

**Инварианты правила — проверяемые спекой** (алгоритм живёт в доме,
спека проверяет его следствия):

- полнота атрибуции: сумма приписанного по траншам равна закрытому
  объёму наших команд;
- неотрицательность: приписанное траншу не больше его экспозиции до
  атрибуции.

## Требования к отчёту узла

Файл — `.claude/work/progress/phase-1-step-7-gaps-close-28/node-<Н>.md`.
Обязательные разделы:

1. **Проход по спискам цитат** каждой находки — таблица «цитата → исход»
   (правлено что именно / не требует правки — почему).
2. **Чек-лист глубины** по каждому гейтящему узлу — четыре пункта
   поимённо, включая **обход потребителей** (механический поиск, пофайлово).
3. **Свипы обоих предметов** — команда дословно + пофайловая таблица.
4. **Счётные клеймы** — пересобраны из своих перечней.
5. **Диспозиция находок узла** — каждая (гейтящая, прочая, гигиена):
   закрыта чем либо припаркована с адресатом и местом.
6. **Хвост закрытия** — если правки пришли после свипов.
7. **Незакрытое** — с основанием.

**Прогон спек обязателен** после правки любого `docs/spec/*.json`:
`bash tools/spec-run.sh`. Правка счётного клейма засчитывается, только
если **падает на прежней форме** (откат во временную копию,
`SPEC_DIR=target/probe-<узел> bash tools/spec-run.sh`, обе стороны — в
отчёт).

# Кодовый заход шага 9 — контур доступа (`ApiAccessPolicy`)

## На какой вопрос отвечает этот файл

Чем закодирован контур доступа к поверхности на шаге 9 фазы 1.

## Что построено

| Артефакт | Роль |
|---|---|
| `config/ApiAccessSecurityConfig` | `SecurityFilterChain`: умолчание закрыто, открыта одна точка — проба живости; stateless, Basic; реестр принципалов |
| `config/ApiAccessProperties` | имя и секрет принципала из Vault per-profile; умолчаний нет |
| `api/security/AccessDenialHandler` | обе точки входа отказа: `PRINCIPAL_ABSENT` (401) и `OPERATION_FORBIDDEN` (403); пишет строку **до** ответа |
| `api/ErrorApiResponseFactory` | единственный сборщик error-DTO; его же зовёт глобальный обработчик |
| `domain/security/AccessDenial` | доменная модель со своим инвариантом согласованности |
| `domain/security/AccessDenialService` | писатель строки; сбой записи не превращает отказ в доступ |
| `persistence/.../AccessDenialEntity`, репозиторий, маппер, `AccessDenialDataService` | граница domain ↔ persistence, своя транзакция |
| `V26__create_access_denials.sql` | таблица журнальных строк |

**Секрет принципала лежит в Vault**, как datasource и OKX-креды:
`secret/tradingbot/api-access` (prod) и `…-test` (test), ключи
`API_ACCESS_PRINCIPAL` / `API_ACCESS_SECRET`. Значение для профиля `test`
заведено этим заходом; в коммит не попадает.

## Решения захода

| Решение | Альтернативы | Почему так |
|---|---|---|
| **Арность принципала выражена в одном бине** (`apiAccessPrincipal`) | завести реестр из N принципалов сразу; зашить имя константой | реестр из N без модели прав молча разрешил бы состояние, которое доки объявляют требующим проектирования; константа в коде сделала бы посылку неснимаемой правкой конфига. Остальной код работает с «текущим принципалом» и имени не знает |
| **Пустой секрет — отказ подъёма** | поднять с открытой поверхностью и предупреждением в логе | контур, поднявшийся с поверхностью, закрытой ничем, — ошибка в разрешающую сторону (П1 следствие 3); предупреждение в логе её не отменяет |
| **`@PreAuthorize` на операциях не ставится, и плейсхолдер снят из код-шаблона** | оставить плейсхолдер; проставить authority на точках снятия ступеней | пер-операционная аннотация выражает **модель прав**, которой при одном принципале различать некого. Плейсхолдер приглашал бы достроить её догадкой |
| **Сессий нет (`STATELESS`)** | завести сессию после Basic-логина | сессия — второй носитель факта «кто вызывает», и первый, кто разошёлся бы с актором записи |
| **Строка отказа пишется своей транзакцией (`REQUIRES_NEW`)** | подхватывать окружающую | отказ возникает в фильтр-цепочке, вне прикладной транзакции; подхваченная чужая унесла бы след отказа своим откатом |
| **Отказ записи не поднимает исключение** | пробросить наружу | иначе вызывающий получил бы 500 вместо отказа: поведение контура зависело бы от доступности журнала |

## Что вскрылось попутно

### Закрытие поверхности сломало контур тестов источника — починено тем же ходом

Коллекция кейсов бьёт в `POST /api/proxy/okx/raw` напрямую, и после
закрытия поверхности каждый её вызов получал бы `401`. База живых кейсов
теперь **предъявляет принципал** — креды берутся из конфигурации поднятого
app, вторым носителем в тесте не заводятся. Проверено прогоном
`Ag12TradeFeeLiveTest`: 3 теста, 0 падений.

Это ровно та позиция, что стояла в `backlog.md` §S2 «креды контура тестов
источника»; она закрыта, а не перенесена.

### Парковки в javadoc сняты

Три контроллера несли `Авторизация — шаг 9` в javadoc — то есть парковку в
месте, которое домом не является. Заменены указателем на дом политики.

## Пробы — каждая падает без своего кода

| Проба | Что охраняет | Предъявлено падение |
|---|---|---|
| `ApiAccessSurfaceTest` (6) | умолчание закрыто; проба живости открыта; строка заводится; наружу ничего сверх класса; принятый принципал проходит; неверный секрет отвергается | **да**: при замене `anyRequest().authenticated()` на `permitAll()` — 3 падения из 6; конфиг восстановлен |
| `AccessDenialRowTest` (4) | инвариант «пустота принципала ⟺ `PRINCIPAL_ABSENT`»; писатель заводит идентификатор; сбой записи не роняет тропу отказа | да: инвариант проверяется на всех четырёх комбинациях, включая обе несогласованные |

**Контекст проб поднимается без БД и Vault** — на `spring-test`, а не
`@SpringBootTest`: предмет проб поверхность, и авто-конфигурация тянула бы
за собой Flyway и datasource, которых предмету не требуется.

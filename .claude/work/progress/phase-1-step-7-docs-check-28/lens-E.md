**Метод, помимо чтения.** Зелёный прогон (`19 спецификаций, 315 примеров`)
не доказывает, что примеры **различают** объявленную форму и её

удалением после и проверкой, что базовый прогон остался зелёным:

1. **Мутационный прогон по `expr`** — каждая скалярная величина (225 шт.)
   поочерёдно заменялась на `true` / `false` / `0` / `'ZZZ'`; выживание
   мутанта означает, что ни один пример величину не утверждает по существу.
2. **Мутационный прогон по `where` и по `of`** агрегатов — то же для
   предиката популяции и подынтегрального выражения.
3. **Статический граф величин** — построена область видимости каждого
   файла (свои значения + значения по `includes`, **нетранзитивно**, как в
   `src/test/java/com/example/tradingbot/spec/Spec.java` §`addValues`),
   затем проверено, какие величины достижимы от утверждений примеров.
4. **Точечные пробы** — 6 добавленных примеров, доказывающих конкретные
   находки (E1, E5, E7, E8, E11, P8).

**Вне охвата:** корректность исходников `src/main` (граница
`concept-review` §«Граница охвата — только доки»; исключение — раннер
`src/test/.../spec/`, читанный как носитель семантики языка спецификаций);
торговая обоснованность формул (линза торгового совета).

## E1. Терминал транша не читает условные заявки: живой стоп переживает закрытие своего транша

- **Вопрос.** `docs/lifecycles/DealTranche.md` требует у терминала транша
  трёх условий (экспозиция ноль, живых заявок нет, **условных заявок
  нет**), а `terminalContract` спеки проверяет два и только по **входным**
  заявкам. Транш с живой отдельной защитой доходит до `CLOSED`.
- **Цитаты (носители).**
  - `docs/lifecycles/DealTranche.md:94-95` — «`CLOSED` применяется, когда
    у транша нет живого риска: экспозиция ноль, живых заявок и условных
    заявок нет.»
  - `docs/lifecycles/DealTranche.md:87` — «живой риск транша ⟺ экспозиция
    > 0 либо есть живая входная заявка» (дизъюнкция **двухместная**);
    `docs/lifecycles/DealTranche.md:90` — «Из этой дизъюнкции читаются оба
    агрегатных предиката» — то есть док противоречит сам себе на строке 95.
  - `docs/spec/deal-tranche-lifecycle.json:40-42` — `terminalContract` =
    `!trancheRiskBearing`.
  - `docs/spec/protection-coverage.json:69-71` — `trancheRiskBearing` =
    `trancheExposure > 0 || trancheHasLiveEntryOrder`;
    `docs/spec/protection-coverage.json:63-67` — `trancheHasLiveEntryOrder`
    берёт только `isEntryOrder && orderIsLive`.
  - Контраст на уровне агрегата: `docs/spec/deal-lifecycle.json:69-71` —
    `riskProvenAbsent` **включает** `!anyLiveProtection`. Уровни
    асимметричны.
- **Проба.** Пример «`EXIT_PENDING → CLOSED`, экспозиция 0, входных ног
  нет, живая `STANDALONE`-защита `ACTIVE`» даёт `terminalContract: true`,
  `transitionAllowed: true` — прогон остаётся зелёным. Примера на это
  состояние в спеке нет (все 13 — без живых защит).
- **Целевой док.** `docs/lifecycles/DealTranche.md` §«Терминал транша» —
  привести к дизъюнкции строки 87 либо расширить `trancheRiskBearing`
  третьим дизъюнктом; правка формы — `docs/spec/protection-coverage.json`
  и `docs/spec/deal-tranche-lifecycle.json` + пример на пробное состояние.
- **Ожидаемый владелец.** `solution-designer` (конструкция концепции:
  чем именно определяется живой риск транша).
- **Трассировка.** Расхождение поднято чтением пары док↔спека; открыты
  `DealTranche.md:80-100`, `deal-tranche-lifecycle.json:30-50`,
  `protection-coverage.json:60-77`, `deal-lifecycle.json:65-92`; затем
  доказано пробой в `target/probe-tr`.
- **Варианты.**

| Вариант | Что делает | Названная цена |
|---|---|---|
| A. Док:95 верен — расширить `trancheRiskBearing` дизъюнктом «живая защита транша» | терминал транша симметричен терминалу сделки | форма уже есть — `trancheHasLiveProtection` (`deal-lifecycle.json:53-56`), но объявлена **там**, а не в `protection-coverage`; правка затрагивает 2 спеки. Контекстная связность: `protection-coverage` уже везде подключён, потребителям знать ничего не нужно |
| B. Док:87/90 верен — снять третий пункт со строки 95 | док приводится к своей же дизъюнкции | правка одной клаузы; цена — живая защита переживает `CLOSED` своего транша, и уборка её ложится на другой носитель, который надо назвать |

## E2. `hasLiveEpisode` объявлена в двух спеках, и обе реализуют один конъюнкт из двух

- **Вопрос.** Величина `hasLiveEpisode` объявлена дважды — в

  цитируют определение живого риска из **двух** конъюнктов, обе формы

- **Цитаты (носители).**
  - `docs/spec/stop-distance.json:4` и `docs/spec/risk-limits.json:4` —
    `"home": "docs/rules/risk-policy.md"` (один дом у обеих).
  - `docs/spec/stop-distance.json:35-37` — `hasLiveEpisode` =

    `coalesce(?position.externalSize, 0) > 0`; нота строки `:52` цитирует:
    «живой риск есть тогда и только тогда, когда status = ACTIVE **и**
    externalSize > 0».
  - `docs/models/domain/core/Position.md:99-102` — «живой риск ⟺
    status = ACTIVE и externalSize > 0»; `:104-105` — «Нулевой размер при
    активном статусе означает, что биржевая запись есть, а живого риска

  - `docs/rules/risk-policy.md` — определения предиката нет; ближайшее

  - Существующий, но неиспользуемый носитель:

    не читает (проверено грепом по всему блоку `values`).
- **Целевой док.** `docs/rules/risk-policy.md` — назвать дом предиката;
  форма — одна спека, вторая получает операнд с указателем
  (`.claude/rules/structure.md:47`).
- **Ожидаемый владелец.** `solution-designer`.
- **Трассировка.** Кросс-файловый скан одноимённых величин по всем 19

| Вариант | Что делает | Названная цена |
|---|---|---|
| A. Контекстная связность падает: потребителю не надо знать, какое поле означает живость |

  **Крен — A.** Счётная разница: `externalSize > 0` при статусе не

## E5. `exitOutcome`: полный выход по объявленной доле ниже `minSize` получает ложный отчёт об округлении

- **Вопрос.** Док разводит два полных выхода признаком «округление ни при
  чём»; спека ставит внешнюю развилку по `exitSize >= minSize`, из-за чего
  выход долей `1.0` при экспозиции ниже минимума попадает в `FULL` и
  заводит `PARTIAL_EXIT_ROUNDED_TO_FULL`, хотя ничего не округлялось.
- **Цитаты (носители).**
  - `docs/components/SizeCalculator.md:76` — «`FULL_BY_FRACTION` |
    объявленная доля забрала экспозицию целиком; **округление ни при чём**
    | ничего»; `:77` — «`FULL` | … | журнальный отчёт
    `PARTIAL_EXIT_ROUNDED_TO_FULL`».
  - `docs/spec/order-sizing.json:75-77` — `exitOutcome` =
    `if(exitSize >= instrument.minSize, if(exitRemainder == 0,
    'FULL_BY_FRACTION', 'PARTIAL'), if(exitRemainder < instrument.minSize,
    'FULL', 'SKIPPED'))`.
  - Нота строки `:76` объявляет ровно тот довод, который форма нарушает:
    «Одно значение на оба исхода заставляло бы потребителя перевыводить
    `exitSize >= minSize`» — разведение сделано **по тому самому
    признаку**, от которого док его отвязал.
- **Проба.** `externalSize = 3`, `fraction = 1`, `lotSize = 1`,
  `minSize = 5` → `exitSize = 3`, `exitRemainder = 0`; ожидалось
  `FULL_BY_FRACTION`, получено `FULL`. Достижимость ветви подтверждена
  существующим примером `docs/spec/order-sizing.json:148-151`
  (`fraction = 1` через этот расчёт проходит; там `minSize = 1`, поэтому
  исход правильный).
- **Целевой док.** `docs/spec/order-sizing.json` §`exitOutcome` — вынести
  проверку `exitRemainder == 0` наружу; примера на пробное состояние нет.
- **Ожидаемый владелец.** `solution-designer`.
- **Трассировка.** Расхождение поднято чтением `SizeCalculator.md:68-80`
  против `order-sizing.json:62-82`; доказано пробой в `target/probe-x`.
- **Варианты.**

| Вариант | Что делает | Названная цена |
|---|---|---|
| A. `if(exitRemainder == 0, 'FULL_BY_FRACTION', if(exitSize >= minSize, 'PARTIAL', if(exitRemainder < minSize, 'FULL', 'SKIPPED')))` | признак дока («округление ни при чём») становится внешним | правка одной строки спеки + 1 пример; потребитель отчёта не меняется |
| B. Признать спеку верной, переписать док: `FULL_BY_FRACTION` — «доля забрала целиком **и размер выразим**» | док приводится к форме | ложный отчёт `PARTIAL_EXIT_ROUNDED_TO_FULL` остаётся штатным: шум в журнале там, где округления не было |

  **Крен — A.** Счётная разница: при B журнальный отчёт об округлении
  заводится на выходе, который округлению не подвергался, — наблюдаемая

- **Ярлык исхода.** `варианты-с-креном`.

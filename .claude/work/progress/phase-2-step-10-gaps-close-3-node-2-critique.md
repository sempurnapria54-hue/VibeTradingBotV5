## K3 — `continuityClaimable` на пустой коллекции пар даёт ИСТИНУ: тот самый механизм, против которого узел заведён

**Предмет 1** (конструкция). **Несущий. БЛОКИРУЕТ.**

`continuityClaimable` объявлен как `op: all, over: pairs`. Свёртка «все» по
**пустой** коллекции в языке спеки истинна. Значит в состоянии «у группы нет ни
одной строки состояния приёма» поверхность отдаёт «дыры нет» — ошибка **в
разрешающую сторону**, прямо запрещённая `docs/concept.md` П1 следствие 3, и
неразличение «не проверяли» / «проверили, всё в порядке» (следствие 4).

Проверено пробой на обеих версиях спеки (добавлен пример, прогон принял
ожидание):

    $ SPEC_DIR=".../probe-spec"  bash tools/spec-run.sh
      # sim-spec + пример {"pairs": []} → continuityClaimable: true
      Спецификаций: 27, примеров: 668 … ВСЕ ПРИМЕРЫ СОШЛИСЬ
    $ SPEC_DIR=".../probe3-spec" bash tools/spec-run.sh
      # sim-spec-2 + тот же пример
      Спецификаций: 27, примеров: 669 … ВСЕ ПРИМЕРЫ СОШЛИСЬ

Довод закрытия эту ветвь не покрывает: правка 2 говорит «Окно, в котором строки
может не быть, ограничено **одним проходом опроса** у живого потребителя; у
неживого его ловит третий конъюнкт предиката **на остальных парах**» — то есть
предполагает, что остальные пары есть. Состояние «пар ноль» достижимо: первый
запуск потребителя до первого прохода опроса; выключенная джоба опроса
(`enabled = false` — обязательный выключатель по `.claude/rules/codestyle.md`
§Джобы) при живой поверхности чтения; очистка таблицы состояния в
непроизводственном окружении.

В `sim-spec-2` дефект становится **внутренним противоречием формы**: там на
ровно этом состоянии `journalLowerBound` объявлен **отказывающим** —
«подписки нет ни на одну тему: величина ОТКАЗЫВАЕТ… группа, не наблюдающая ни
одной темы, полноты не обещает вовсе», — тогда как `continuityClaimable`,
отдаваемый **той же выдачей**, в том же состоянии говорит «дыры нет». Две
величины полноты, обязанные ехать вместе, высказываются об одном состоянии
противоположно, и ни одна нота этого не называет.

Ни в одной из двух версий спеки примера на `continuityClaimable` с пустыми
`pairs` нет, и ни один док ветвь не называет — при том что
`docs/rules/writer-named-for-every-value.md` §«Как проверять» п.4 требует либо
писателя, либо явной записи «состояние недостижимо, и чем именно».

# Интегратор, прогон 2: полное покрытие OKX + скан с манифеста

## На какой вопрос отвечает этот файл

Каков результат полного перепрогона `integrator` по обновлённому
процессу: манифест покрытия OKX, фиксация И-1, скан возможностей с
полного манифеста и эскалация источникового дефицита (на валидацию).

## Контекст

Перепрогон после правки процесса `api-docs-completion` (вариант A):
докачка = **полное покрытие периметра** (не скоуп шага), **манифест
покрытия** с провенансом per-row, скан **только после полного
корпуса**. Сменяет скан прогона 1 (`...-run-1.md`) на скан с полной
поверхности. Ступень — **Предложение**: ничего не финализируется.

Поправка пользователя учтена: сторонний список эндпоинтов — только
**скелет + кросс-чек**; источник правды — **официальный док OKX**;
каждая строка манифеста несёт провенанс (`офдок` / `сторонний`);
расхождения — находкой.

(batch/safety/account-config/market-public read'ы), не дыры в
command-layer шага 4.

## Источниковый дефицит — эскалация (главное прогона)

**Официальный док OKX — JS-SPA.** Доступными веб-инструментами
надёжно подтверждается **существование/путь** эндпоинта (через
okx.com-поиск), но **не поле-уровневый инвентарь**: поиск возвращает
способности раздела, не таблицы полей; SPA-`WebFetch` корня
конфабулирует (прогон 1: выдумал `amend-order-algo`/`cancel-order-algo`).

Следствие: строки `пробел` доведены до манифеста (существование/путь,
провенанс `офдок` где подтверждено), но **полные доки полей для них в
этом прогоне не заведены** — писать инвентарь полей «из памяти» и
штамповать его офдок-указателем запрещено дисциплиной роли (источник
правды — официальный док; не выдумывать).

**Эскалация (развилка для пользователя/чата).** Чтобы довести корпус
до офдок-grade, нужен надёжный канал чтения официального дока. Это —
**новая фактура**, частично подрывающая прежнее отвержение «библиотеки
выгрузок» (`.claude/decisions/integrator-agent.md`): то отвержение
держалось на посылке «офиц. веб-док читается»; посылка не
подтвердилась. Варианты:

- **(1) пользователь выкладывает офиц. страницы** нужных разделов
  (HTML/PDF/выгрузка) — целевой канал чтения офдока под докачку полей;
  стареющее перевыкачивается под потребность, не держится корпусом
  (мягче отвергнутой «библиотеки»);
- **(2) официальный машинный контракт OKX** (OpenAPI/Postman), если
  публикуется, — разовый надёжный вход;
- **(3) интерим:** факты с провенансом `сторонний` (SDK-кросс-чек:
  tiagosiebler/ccxt/nautilus) пишутся в доки **помеченными**
  «требует офдок-подтверждения», доводятся при появлении канала.

**Крен — (1)** под текущую потребность + **(3)** как интерим для
скоупных пробелов: целевой источник правды остаётся офдок, но
читается через выкладку, а не через нечитаемый SPA. Решение — за
пользователем (это разблокирует докачку полей по всему периметру).

## И-1 — зафиксировано фактом + развилка перевыдана

**Факт (офдок, okx.com):** trailing `move_order_stop` (и iceberg /
twap) отменяется через `cancel-advance-algos`, не `cancel-algos`.
Зафиксировано в `contracts/algo-order.md` («Cancel — две семьи algo»);
`cancel-advance-algos` добавлен в манифест (`обновлён`).

**Развилка реализации `CANCEL_ALGO_ORDER` — на валидации (не финал):**
(а) ветвить cancel-путь по типу algo; (б) сузить используемые типы до
ordinary (trigger/oco/conditional), `move_order_stop` — форвард.
**Крен — (б)** (фаза 1 защищается TP/SL, trailing не нужен).

## Скан возможностей с полного манифеста (Предложение)

Командный костяк шага 4 vs полная поверхность: **новых внутри-скоупных
(шаг 4) возможностей к добавлению нет** — командный слой полон против
поверхности. Всё содержательное — форвард к владельцам будущих шагов.
С уважением к принятым решениям (отвергнутое по вкусу/scope не
перевыношу без новой фактуры).

## Итог — на валидацию в чат

1. **Источниковый дефицит** (главное): выбрать канал чтения офдока
   (1)/(2)/(3) для разблокировки докачки полей по периметру. Крен —
   (1)+(3). До решения строки `пробел` остаются в манифесте без
   поле-уровневых доков.
2. **И-1:** подтвердить выбор (а)/(б). Крен — (б).
3. **В-1/В-2/В-3/В-6/В-7/В-8/В-9** — форвард-кандидаты; подтвердить
   передачу владельцам шагов 8 / 5 / 7 (как заметки, не действия
   сейчас).
4. **В-4/В-5** — к действию не предлагаю; зафиксировать «рассмотрено,
   отложено/не берём».

Правки этого прогона: процесс (полное покрытие + манифест +
провенанс + статус `пробел`), скилл (провенанс/скелет-дисциплина),
манифест (новый), `algo-order.md` (И-1 факт + развилка). Поле-уровневые
доки `пробел`-строк **не заводились** (источниковый дефицит).

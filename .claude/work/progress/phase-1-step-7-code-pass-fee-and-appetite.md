# Кодовый заход по ставке комиссии и читателю чисел риска

## На какой вопрос отвечает этот файл

Что сделано заходом по ставке комиссии и читателю чисел риск-аппетита.

## Состав и вход

Три задачи держателя одним заходом: полное имя параметра в примерах спек,
операнд ставки комиссии (поле, писатель, источник) и читатель трёх чисел
риск-аппетита. Гейта на них нет; `py -3 tools/code-gate-check.py` перед
заходом — **ПРОЙДЕН**. Живых заявок в demo не подавалось: прогонялся
только read-only кейс `AG12` (ставки комиссий), заявок он не создаёт.

## 1. Полное имя параметра в примерах спек

Усечённые имена операндов заменены каноническими — «одна строка поиска»
теперь находит число и в примерах:

| Было | Стало |
|---|---|
| `limits.globalSimultaneousPercent` | `limits.globalSimultaneousRiskPerDealPercent` |
| `limits.strategySimultaneousPercent` | `limits.strategySimultaneousRiskPerDealPercent` |
| `limits.catastrophicMultiplier` | `limits.strategyCatastrophicRiskPerDealMultiplier` |
| `limits.cumulativeMultiplier` | `limits.cumulativeRiskPerDealMultiplier` |
| `lossLimit` (спека серии убытков) | `globalConsecutiveLossLimit` |

**Проверка обеих пар `strategyX`/`globalX` дала тот же класс усечения** —
обе стороны в `risk-limits.json` были усечены одинаково, поэтому
переименованы обе: иначе «одна строка поиска» нашла бы конфигурационное
число и не нашла бы его стратегическую пару, стоящую в том же
неравенстве. Величины (`withinGlobalSimultaneous` и прочие) не
переименовывались: усечения у них не было.

**Значения примеров остались литералами** — это состояние кейса, а не
значение системы; ссылок из примеров на конфиг не заведено.

## 2. Ставка комиссии: поле, писатель, источник

**Наблюдение прежде кода.** Прогон `AG12.1` расширен до персистентного
наблюдения (`.claude/tests/source-api/okx/observations/AG12_1.md`):
источник вернул одну группу `groupId=4`, `taker=-0.0005`,
`maker=-0.0002`, `level=Lv1`, а **плоские** `taker`/`maker` верхнего
уровня у SWAP пришли **пустыми**. Отсюда две вещи в коде стоя́т на
факте, а не на чтении офдока: знак снимается маппингом (`× −1`), и DTO
плоской шестёрки не несёт вовсе.

| Носитель | Что |
|---|---|
| `TradeFeeOkxResponse` (новый) | DTO ответа: `instType`, `level`, `ts`, `feeGroup[]` |
| `OkxRestClient.getTradeFee` | подписанный `GET /api/v5/account/trade-fee`, ось запроса — тип |
| `TradeFeeRateExternalSnapshot` (новый) | граничный снапшот на группу, знак уже снят |
| `TradeFeeRateMapper` (новый) | DTO+группа → снапшот → домен; `× −1`, эпоха → момент, проекция типа |
| `TradeFeeRate` (новый) | доменная модель: пара сырых осей, ставки строкой, предикат сравнения, подтверждение |
| `TradeFeeRateEntity`, репозиторий, `TradeFeeRateDataService` (новые) | правило истории: значение изменилось — новая строка, совпало — подтверждение последней |
| `V14__create_trade_fee_rates.sql` | таблица группы с индексом резолва |
| `InstrumentExternalRulesSyncJob` | **один** вызов на тик по паре «биржа × тип», не по инструменту |
| `InstrumentExternalRules` | ключ группы (`externalFeeGroupId`) плюс ГИДРИРУЕМАЯ ставка; в JSONB-навес она не попадает |
| `InstrumentExternalRulesDataService` | гидрация ставки на чтении — обе тропы чтения навеса проходят через эту границу |
| `PriceCalculator` | `BREAKEVEN` считается точной формой `P·(1±f)/(1∓f)`; ставки нет — контролируемый отказ |

**Сторона округления защитного уровня выведена из положения уровня, а не
из стороны сделки.** Прежнее `isLong ? DOWN : UP` верно для стопа на
убыточной стороне и **неверно** для безубытка: у LONG он лежит выше
якоря, и округление вниз опустило бы уровень ниже истинного безубытка,
то есть в убыток. Консервативная сторона — **прочь от якоря**, и на
loss-side стопах это то же самое, что было.

## 3. Читатель трёх чисел риск-аппетита

| Число | Кто читает | Отказ, пока пусто |
|---|---|---|
| `globalConsecutiveLossLimit` | `RiskValidator`, fail-fast | `LOSS_LIMIT_NOT_CONFIGURED` |
| `globalSimultaneousRiskPerDealPercent` | `RiskValidator` fail-fast + неравенство создания | `RISK_APPETITE_NOT_CONFIGURED` |
| `globalCatastrophicRiskPerDealMultiplier` | неравенство создания стратегии | `RISK_APPETITE_NOT_CONFIGURED` на создании |

Плюс — **боевой профиль без чисел не поднимается**
(`RiskAppetiteStartupCheck`, `@Profile("prod")`): «пустое место — отказ»
переехало из дока в код. Адресные отказы прохода это не заменяет — у них
другой момент и другой адресат, и в профилях, где число может законно
отсутствовать, развязка прежняя.

**Заведён один новый код — `RISK_APPETITE_NOT_CONFIGURED`.** Дом кодов
его не называл, а П3 требует различать два разных пустых операнда:
пустой порог серии и пустой максимум риска — разные факты. Оба кода
временны́е и оба попали в карв-аут исчерпанного бюджета по доводу, уже
записанному там для первого.

**Четвёрка риск-чисел детали приземлена** (`V15`): `risk_per_trade_percent`
переименована в `risk_per_action_percent` — прежнее имя обещало потолок
сделки, а несло поактный, — и добавлены три объявления автора. Создание
торгуемой детали без любого из четырёх отвергается.

## Что заход оставил названным

- **Эталон репозитория не десериализуется api-моделью целиком:** его шаг
  несёт действие `actionKind: POSITION`, а перечень подтипов
  `StrategyActionApiModel` знает только `ORDER` и `ALGO_ORDER`. Это
  предсуществующий пробел выходной тропы, не этого захода; тест эталона
  читает артефакт деревом и потому от пробела не зависит. Позиция —
  `.claude/work/backlog.md`.
- **Уникальность строки группы БД не держит** — правило истории требует
  нескольких строк, а признака актуальности у модели нет; инвариант
  «одна актуальная» держит писатель, резолв идёт порядком. Названо в
  доке модели.
- **Синк ставок гоняется раз в час** вместе со справочником инструмента:
  своей частоты у ставки нет, и заводить её без потребности — больший
  след.

# Обкатка классификации: процессы (архив)

## На какой вопрос отвечает этот файл

Что показал прогон скилла классификации на архивных процессах.

## Источник

`.claude-archive/2026-05-21/docs/domain/processes/`

- `Calculation/Расчёт индикаторов и рыночных данных.md`
- `Calculation/Калькуляторы действий стратегии.md`

## Установки прогона

- Прогон сухой: реальные файлы знания и архив не правятся, всё — в
  отчёт. Открытые вопросы перечисляю, в `open-questions.md` не вношу.
- Применяю **обновлённый** каркас: решения `model-granularity`,
  `rule-source-of-truth`, `client-layer-docs` и активный тип
  `docs/components/`. Прогон проверяет, держатся ли они на
  процессном материале.
- **Шаг 2 (область)** для всего материала — **продукт**, без
  развилок. Ниже не повторяю.
- `Жизненный цикл сделки.md` уже разобран первой обкаткой
  (`.claude/notes/2026-05-23-обкатка-классификации-deal-lifecycle.md`);
  здесь — только дельта от новых решений.
- Сквозной анти-паттерн (встречается во всех Calculation/Audit
  доках): раздел «после Q2–Q8 / после Q3..Q8» ссылается на **старый
  decision-log** прежнего пайплайна (не наши вопросы). Это меташум,
  при миграции растворяется (как L1 первой обкатки). Дальше помечаю
  как «legacy-Q-addenda», отдельным фрагментом не дроблю.

- **Отбросил:** legacy-Q-addenda «после Q2–Q8» (во всех Calc/Audit доках), retry-policy yaml (Ф38, конфиг), navigation/«основной источник истины»-индекс (Ф30, растворяется), негативные «не делает/не храним» списки (по `negative-statements-not-fixated`).
- **Гипотез на decisions / новые открытые вопросы:**
  - **NQ-F** (Ф9, Ф14, Ф20): где живут runtime value objects / context-объекты (MarketPriceData, CalculationContext, DealContext, Calculated*, RiskValidationResult) — не persisted сущности; `model-granularity` («модель = бизнес-сущность») их не покрывает. *Главный новый скрип процессного материала.*
  - **NQ-G** (Ф30): что делать с master-index / навигационными legacy-доками («Статусы торговых сущностей» объявляет себя источником истины по статусам) — против `rule-source-of-truth` (один владелец на правило). Нужно правило миграции: растворять в распределённое владение.
  - **NQ-H** (Ф40): FSM-handler — компонент (`docs/components/`) или раздел lifecycle Deal. Уточняет NQ-D на handler-per-status.

### Что сработало (валидация новых решений)
- **`docs/components/` (активирован)** снял главный скрип первой обкатки «модель vs процесс/компонент»: jobs, services, calculators, validators, resolvers, executors, factories, handlers — однозначно компоненты. Старые открытые B11/K1/D3 закрыты.
- **`rule-source-of-truth`** разрулил массовое дублирование процессных доков (partial-close, ACK-not-truth, live-risk, RiskValidator-применимость, balance-freshness повторяются в 3-6 доках): первоисточник = владелец, остальное — ссылки. Q2 проверен на процессах — критерий держится.
- **`client-layer-docs`** принял весь OKX-слой (TimeFrameMapper, статус-маппинги, endpoint'ы, tdMode/posSide, autoCxl) без новых развилок.
- **`model-granularity`** уверенно разложил модели данных (IndicatorValue+подтипы, MarketStructure+MarketPriceLevel, settings/params как разделы Strategy) — кроме класса runtime/context-VO (NQ-F).

### Где скрипит
- **NQ-F (VO/context vs модель)** — единственный системный новый скрип; процессные доки полны не-persisted result/context объектов, для которых критерий «модель = бизнес-сущность» не даёт ответа.
- **NQ-G (master-index доки)** и **NQ-H (handler vs lifecycle-раздел)** — точечные.
- **Шаг 4 на «процесс vs правило-владелец»**: для правил, неотделимых от конкретного процесса (формулы цен, идемпотентность, one-command-at-a-time, three-checks), `rule-source-of-truth` корректно указывает владельцем процесс/компонент — старый Q3 на процессном материале снят.

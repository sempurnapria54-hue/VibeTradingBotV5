## Узел E — торговые находки

### H16 — тропы `PRECHECK`/`ENTRY_SUBMITTED` → `CLOSED` без входа не имеют источника числа; инвариант непустоты на `CLOSED` сформулирован безусловно [F-C1]. **Гейтит мягко.**
После снятия placeholder ZERO число на `CLOSED` пишет только финализация
из фактов позиции — у закрытий без входа (условие истекло, risk-block)
источника числа нет и быть не может; обе тихие развязки плохи (`null`
делает инвариант ложным; `0` — запрещённый fallback, 0R-псевдотрейды
занижают ожидаемость [Tharp гл.6 с.144-146]). As-built прецедент ZERO уже
в коде шага 6. Ключевание R-выборки по `plannedRiskAmount ≠ null`
недостаточно — экспирации из `ENTRY_SUBMITTED` несут plannedRisk без
входа. **Крен: карв-аут в инварианте** (непустота — только для сделок с
состоявшимся входом; no-entry-`CLOSED` — `null` + явный признак «не
сделка»); критерий членства R-выборки («вход был») назвать сейчас.
*Владелец:* `trading-specialist` + `solution-designer`. *Исход:*
`варианты-с-креном`.
*Сверка пользователя (2026-08-02, вход для диагностики — не финал):*
выбран **`0`** при **`CloseReason` как дискриминаторе членства
R-выборки** (0R-псевдотрейды исключаются причиной, не значением); крен
линз (null + карв-аут) разошёлся — диагноз: ключ членства искали среди
значений результата, а не по всем дискриминаторам (правка —
`design-fork.md` эвристика 7). Проверка покрытия enum выполнена
`GAPS_CLOSE_9`: покрытие **неполно** — экспирация из `ENTRY_SUBMITTED`
без своей причины, `RISK_CONTROL` смешивает «вход был/не был»
(детали и предложения — `phase-1-step-7-gaps-close-9.md` §H16). *Флаг
действия CC:* предложил (доукомплектование enum — пользователю/владельцам;
семантика `0` в носители не финализировалась).

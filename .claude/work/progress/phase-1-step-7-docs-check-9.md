# DOCS_CHECK_9 — шаг 7 фазы 1 «Сделки и P&L»

## На какой вопрос отвечает этот файл

Каков исход подтверждающего прогона концепции после `GAPS_CLOSE_8` —
чисто ли материал шага специфицирован под `CODE` после материализации
развилки «команда ↔ действие».

## Контекст

- **Под-шаг:** `DOCS_CHECK_9`, подтверждающий прогон после `GAPS_CLOSE_8`
  (материализация развилки: атомарные команды + 4 системных действия,
  строка = исполнение, окно линковки на `Deal`, суффиксы
  `_COMMAND`/`_ACTION`).
- **Прогон:** три независимых ревьюер-субагента — линза A (механика /
  оркестрация / командный слой / компоненты / правила / решения /
  контракты), линза B (модели / mapping / native / персистентность,
  field-level + миграции `V1-V10`), линза C (торговая корректность,
  грунт — дистиллят корпуса).
- **Ограничение каталога поиска — применено** (правка после дисклозуры
  `DOCS_CHECK_8`): линзам явно запрещены `.claude/work/**`, снапшоты,
  заметки, чат, архивы; разрешены только `docs/**`, `src/**`, дистиллят
  (линза C) и codestyle/tech-radar. По отчётам «Что открывал» — запрет
  соблюдён, утечек рабочего материала нет.
- **Верификация CC (V1-V5):** несущие атрибуции перепроверены чтением
  целей; **одна находка отвергнута** (V1).
- Нумерация `H#` — локальная; ссылки на находки линз — `F-A#`/`F-B#`/`F-C#`.

## Стадия остановки

**НЕ чист — но класс дефектов сместился.** **Ядро развилки подтверждено
всеми тремя линзами независимо**: критерий атомарности, состав четырёх
системных действий, единый retry-анкер, частичные ключи живых исполнений,
транзакционная клауза §5, матрица SYSTEM, асимметрия троп, окно линковки
в канонических носителях, торговое ядро (источник числа, «неисчислимо» ≠

§Подтверждено-ОК). Гейтят: **два переоткрытых узла** `DOCS_CHECK_8`

## Узел C — дисциплина ключей и статусов SYSTEM-вида

### H9 — target-дисциплина SYSTEM-строк не закреплена; nullable-операнд в ключе 1; `BALANCE`/`NONE` без производителя/с пересечением [F-B4]. **Гейтит мягко.**
Модель говорит «цель в ключе ⇒ одно живое» (ключ 1), исполнители — ключ 2
(`deal_id`, `system_action_type`); смешанная дисциплина не запрещена ни
одним; `target_entity_type` — nullable-операнд ключа 1 без предиката
непустоты (нарушение собственного правила NULL-семантики);
`TargetEntityType.BALANCE` без писателя, `NONE` пересекается с
SYSTEM-DEAL. **Крен линзы B: закрепить** — SYSTEM-строки всегда
`(DEAL, NULL)`, инвариант несёт ключ 2, в ключ 1 добавить `and
target_entity_type is not null` (или CHECK), судьбу `BALANCE`/`NONE`
решить явно (мёртвые значения протекут в миграцию). *Владелец:*
`solution-designer` → `code-writer`. *Исход:* `варианты-с-креном`.

### H10 — `CLOSE_POSITION_COMMAND` в статусной матрице при анкер-less cleanup [F-A5]. **Гейтит мягко.**
`DealActionState.md:103-104` + lifecycle держат close в переходах
`SUBMITTED`, но все эмиссии close — cleanup без `dealActionStateId`;

refresh» сформулировано внутри anchored-retry-механики. **Крен: вычистить
из матрицы + развести в `RetryPolicyService.md` два режима повтора

`fsm-execution-layering` отдаёт market-close `ExitPendingHandler`, а его
реестр команд close не несёт (при живой позиции в `EXIT_PENDING`
единственная тропа — `ERROR`); крен — добавить в реестр (симметрия с

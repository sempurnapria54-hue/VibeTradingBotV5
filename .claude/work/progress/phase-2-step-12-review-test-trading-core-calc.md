# Ревью кейсов `trading-core-calc` по критерию валидности

## На какой вопрос отвечает этот файл

Каков исход адверсариального ревью документа кейсов
`.claude/tests/cases/trading-core-calc.md`.

## Охват

**Предмет** — расчётный и резолверный слой ядра: шесть классов одного
дерева (`services/trading-core`) — итог сделки, сверка движений, признаки
терминального ребра, два резолвера состояния и техническая политика
повтора. **Двенадцатый предмет уровня 2** перечня под-шага 1 `CODE` и
**четвёртый из шести**, введённых правкой перечня 2026-09-17
(`.claude/decisions/test-contour-design-pass.md` §«Перечень предметов и
порядок работы»), **первый круг документа**.

Критерий апрува — `.claude/skills/test-review.md` §«Критерий апрува документа
кейсов»; потолок петли — три круга. Передача пришла с таблицей самопроверки
автора
(`.claude/work/progress/phase-2-step-12-hand-test-trading-core-calc.md`) —
по строке на кейс всех четырнадцати групп; без неё круг не открывался бы.

**Метка своей дельты отбита до первой правки** (`git write-tree` →
`bdc7676825…`, `.claude/rules/edit-kind-obligations.md` §«Предмет
обязанностей — дельта захода»). Дельта круга: этот отчёт, хроника шага и
снапшот. **Документ кейсов круг НЕ правит** — ревьюер не чинит
(`.claude/skills/test-review.md` §«Назначение и границы»); дерево кода круг
**читал**.

**Новое против одиннадцати апрувленных документов уровня: документ вводит
ось «кейс уровня 2 мерит РЕАЛИЗАЦИЮ формы, а не саму форму», и ревью
обязано применить эту ось к его собственным клеткам.** Ось объявлена
буквально: «прогон спеки исполняет выражения спеки; кода он не открывает
вовсе, и расхождение реализации с формой ему невидимо по построению».
Отсюда предмет круга: у каждой клетки, чей носитель — пример спеки,
спрошено не «сходится ли клетка с примером» (это и делает `spec-run.sh`), а
**«что на этом состоянии делает написанный класс»**.

Ось оправдалась и в обратную сторону: **единственный гейтящий дефект круга
пришёл ровно оттуда** — клетка сверена с примером спеки и не сверена с
кодом, а код на этом состоянии не даёт объявленного исхода и не даёт вообще

## Механические оси критерия — команды и их исход

Разбор документа и предмета командами, не глазами.

**Цитаты примеров спеки разрешаются в существующие примеры.** Ось введена
этим кругом: клетка, чей носитель — «пример спеки», проверяема механически,
и выдуманное имя примера было бы невидимо глазу.

```bash
export LC_ALL=C.UTF-8
py - <<'PY'
import re, glob, io
doc = io.open('.claude/tests/cases/trading-core-calc.md', encoding='utf-8').read()
specs = ''.join(io.open(p, encoding='utf-8').read() for p in glob.glob('docs/spec/*.json'))
found = {f.split('…')[0].strip().rstrip('.,:') for f in re.findall(r'пример[ыа]?\s+«([^»]+)»', doc)}
miss = [k for k in sorted(found) if k not in specs]
print('цитат:', len(found), '| не найдено:', len(miss))
for k in miss:
    print('  MISS:', k)
PY
```

Исход — **ноль ненайденных**: все процитированные примеры существуют в
`docs/spec/*.json`. Ни одного выдуманного носителя у клеток нет.

**Поведение библиотеки на пустом операнде проверено прогоном, а не
чтением.** Автор пометил такие утверждения «прогоном не проверено» и был
прав, что пометил: одно из двух не подтвердилось.

```bash
export LC_ALL=C.UTF-8
mkdir -p target/probe-review && cat > target/probe-review/Probe.java <<'EOF'
import java.util.EnumMap;
import java.util.Map;
import java.util.Set;
public class Probe {
    enum T { A, B }
    static final Set<String> NORMAL = Set.of("1", "2");
    public static void main(String[] a) {
        try {
            System.out.println("Set.of.contains(null) = " + NORMAL.contains(null));
        } catch (RuntimeException e) {
            System.out.println("Set.of.contains(null) THROWS " + e.getClass().getName());
        }
        System.out.println("Set.of.contains(empty) = " + NORMAL.contains(""));
        Map<T, String> m = new EnumMap<>(T.class);
        try {
            System.out.println("EnumMap.getOrDefault(null) = " + m.getOrDefault(null, "def"));
        } catch (RuntimeException e) {
            System.out.println("EnumMap.getOrDefault(null) THROWS " + e.getClass().getName());
        }
    }
}
EOF
"$HOME/.jdks/corretto-25.0.3/bin/java" target/probe-review/Probe.java
```

Исход на `corretto-25.0.3`:

- `Set.of("1","2").contains(null)` — **`NullPointerException`**;
- `Set.of("1","2").contains("")` — `false`;
- `new EnumMap<>(T.class).getOrDefault(null, def)` — `def`, отказа нет.

Первая строка гейтит `U6.7` (находка `N-1`), третья подтверждает `U12.12`.

### `N-1` (`невалидность`, `U6.7`, звено `Z17`) — на пустом типе закрытия класс не даёт объявленного исхода, а роняет проход

**Что говорит клетка.** `U6.7`: «запись добыта, тип **пуст**» → «та же
корзина и тот же отчёт: обе формы непригодности идут одной ветвью».
Носитель — два примера `docs/spec/position-close-outcome.json`: «добытая
запись с пустым типом закрытия» (`externalCloseType: null`) и «добытая
запись с типом-пустой-строкой» (`externalCloseType: ""`), оба с
`closeOutcome: UNDETERMINED`, `unrecognizedCloseTypeReported: true`.

**Что делает класс.** `DealTerminalFeaturesWriter#resolve` вычисляет
торговый исход **первым** аргументом конструктора четвёрки;
`#episodeOutcome` на добытой записи доходит до
`NORMAL_EXIT_TYPES.contains(closeType)`, а `NORMAL_EXIT_TYPES` —
`Set.of("1", "2")`. На пустом значении этот вызов **бросает
`NullPointerException`** (прогон выше), и `apply` умирает до единого
сеттера, до `report` и до контроля валюты. Ни корзины, ни отчёта — ни
одного из двух объявленных выходов.

**Соседняя ветвь того же класса охрану имеет, и это делает расхождение
адресным:** `#closeTypeRecognized` начинается с `isFalse(isBlank(closeType))`
и пустое значение до перечней не доносит — поэтому предикат отчёта
пустотой не роняется, а исход роняется. Один класс, два читателя одного
поля, две разные трактовки пустого — ровно тот механизм, который документ
сам предъявил находками `F3` и `F4`, и здесь он не назван.

**Почему это невалидность, а не пробел дока.** Носитель у ожидания есть, и
он не молчит: спека держит **пример** ровно на этом состоянии. Расходится
с ним реализация — то есть сработала та самая ось, которую документ
объявил своей («расхождение реализации с формой прогону спеки невидимо по
построению»). Ось предписывает исход: расхождение объявляется находкой
владельцу, а ожидание берётся из дома (§«Ожидание берётся из дома, даже
когда сегодня оно не исполнено»). Клетка вместо этого утверждает согласие
и в самопроверке помечена «сходится: да» — то есть кейс, попав в код,
покажет `NullPointerException` там, где обещал корзину, и автор прочтёт
это как дефект своего теста.

**Вторая половина клетки при этом верна:** на пустой строке
(`externalCloseType: ""`) `contains("")` отвечает ложью, исход — корзина,
отчёт заводится. Клетка **склеивает два состояния в одно ожидание**, и
одно из двух неверно.

**Что правит автор** (ревьюер не чинит):

- разнести `U6.7` на два кейса — пустое значение и пустая строка: у них
  разный факт, и общая клетка это скрывает;
- у кейса пустого значения ожидание оставить домовым (корзина плюс отчёт),
  пометить его находкой владельцу и **завести секцию бэклога** по
  `.claude/rules/parking-address.md` — сторона закрытия здесь **кода**:
  спека держит пример с `null` и правится не она;
- поправить звено `Z17`: «всё прочее, **включая пустое**, садится в
  корзину» — для пустого значения ложно, и звено сегодня врёт ровно тем
  же местом, что и клетка;
- проверить, не задевает ли та же охрана строку `U6.8`: там пустой тип
  приходит на **недобытой** записи, ранний возврат по непустоте числа
  стои́т выше, и отказа нет — клетка верна, но её верность держится
  порядком охран, а не пометкой.

**Дефект предъявлен не только тесту.** Состояние достижимо: площадка может
не вернуть тип закрытия у добытого положения, спека держит его примером и
называет нормальной популяцией, а цена отказа — не «признак не посчитан», а
**весь терминал сделки**, включая четыре сеттера и контроль валюты. Это
находка владельцу ядра сверх пяти, уже названных документом.

### `Ф-1` (`форма`) — заголовок колонки инвертирован относительно её содержимого

Таблица §«Ожидание берётся из дома, даже когда сегодня оно не исполнено»
имеет колонку **«Чью сторону берёт ожидание»**, а значения в ней называют
**чью сторону правят**. Видно по самим клеткам: строка `U4.13` несёт
значение «**дома**» и тут же поясняет — «ожидание берётся **по коду**»;
строка `U6.18` несёт «**кода**» и поясняет, что ожидание берёт спеку.
Читатель, взявший заголовок буквально, прочтёт все пять строк наоборот —
включая три, где красный прогон означает дефект кода.

Правка — переименовать колонку в «Чью сторону правит закрытие» (или
инвертировать значения; первое дешевле — пояснения останутся верны).

### `Ф-2` (`форма`) — популяция недостижимого раздельной гранулярности названа двумя способами, и они расходятся

§«Состояния, недостижимые обычной тропой» называет строкой «`U4.4`, `U4.6`,
`U4.11`», а пробел `G4` — «`U4.5`, `U4.6`, `U4.11`». Права вторая:
`U4.4` — **комбинированная** запись, то есть ровно то, что отгруженное
отображение категорий и производит, и собственной пометки «недостижимо» её
строка не несёт; недостижима **раздельная** запись `U4.5`, и её строка
пометку несёт. Расхождение двух записей одной популяции — тот класс, против
которого заведена единственность дома
(`.claude/rules/carrier-levels.md`).

### `Ф-3` (`форма`) — в группах сверки клетка выхода называет непубличную величину вместо наблюдаемого исхода

Документ сам объявил точку наблюдения: «выход наблюдается пятью точками:
возвращённое значение (результат, **исход сверки**, четвёрка признаков,
резолюция, политика, момент)» (§«Чем достаются выходы»). У
`DealReconciliationCalculator` наружу выходят ровно два значения — исход
сверки и признак запроса ступени; левые стороны пар, слагаемые, область и
общее расхождение считаются **приватными** методами и наблюдаемы только
через исход.

Клетки, называющие вместо исхода приватную величину: `U3.6` («правые
стороны всех четырёх пар нулевые»), `U4.3`, `U4.4`, `U4.5` («тот же исход,
что у `U4.4`» — а у `U4.4` исхода не названо), `U4.6`, `U4.7`, `U4.8`,
`U4.9`, `U4.10`, `U4.12`, `U4.13`, `U4.14` («расхождение равно модулю
правых»), `U4.15`, `U4.16`.

**Ожидание при этом выведено, а не выдумано** — и потому это форма, а не
невалидность: названный носитель несёт исход в своём `expect` (у примера
«комбинированная запись источника» стои́т `matched: true` рядом с
`leftRealizedPnl` и `leftTradeFee`). Но клетка в таком виде не переводится
в утверждение теста без повторного открытия спеки, а под-шаг 3 читает
именно клетку.

Правка — дописать в каждую названную клетку наблюдаемый исход («сошлась» /
«разошлась»), оставив приватную величину пояснением, **чем именно** исход
достигается. Соседние группы это уже делают: `U1`, `U2`, `U6`-`U13` называют
возвращаемое значение в каждой клетке.

### `Ф-4` (`форма`, `U1.16`) — у тройного выхода названа одна треть

У группы `U1` выход тройной — доступность, число, валюта, — и клетки
`U1.15` и `U1.17` называют все три. `U1.16` называет доступность и состав
слагаемого; числа и валюты в клетке нет. Обе величины из той же клетки
выводятся (слагаемое пусто ⇒ число равно сумме по эпизодам; валюта пуста по
входу), поэтому класс — форма; не будь вывода в самой клетке, строка
гейтила бы.

### `П-1` (`пробел покрытия`, `U13`) — верхняя граница задержки предъявлена одной стороной

`#computeDelay` связывает рост строгим сравнением
(`scaled.compareTo(maxDelay) > 0`), то есть равенство отдаёт **посчитанную**
задержку, а не потолок. `U13.9` берёт счётчик `10` (задержка кратно выше
потолка), `U13.11` — `1000`; входа, на котором `scaled` равен потолку, у
группы нет, и строгость сравнения не пинится ничем. Соседний предикат того
же класса автором предъявлен обеими сторонами (`U7.5` — «окно ровно равно
глубине»), поэтому пробел читается как пропуск, а не как решение.

Исход — **под-шаг 3**: добирается кейсом с начальной `5s`, потолком `20s` и
счётчиком `3` (`scaled` = `20s` = потолок ⇒ ожидание `20s` по обеим
ветвям — различает их мутация сравнения).

### `П-2` (`пробел покрытия`, `U8`) — популяция контроля валюты не предъявлена смешанным эпизодным составом

`#verifyCloseRecordCurrency` отбирает **добытые** записи и уже по ним ищет
расхождение. `U8.1` берёт состав без добытых вовсе, `U8.5` и `U8.6` — состав
из двух добытых. Состава «одна добытая с совпавшей валютой плюс одна
**недобытая** с разошедшейся» нет, а именно он различает отбор по
добытости: сними фильтр — и отчёт заведётся там, где дом предписывает
молчание.

Исход — **под-шаг 3**.

## Находки владельцам: проверены, не приняты на слово

Пять находок документа (`F1`-`F5`) круг проверил по носителям, а не по
изложению автора.

| Находка | Проверено | Исход |
|---|---|---|

## Вердикт

**Апрува нет: круг первый, гейтящий остаток — один (`N-1`).**

Проверка по четырём осям критерия: четыре поля стоя́т у всех кейсов
документа, колонка «Факт» пуста; достижимость помечена честно — каждая
пометка «недостижимо» проверена по своему носителю (фабрика контекста,
миграция `V4`, отгруженное отображение категорий, умолчание конфигурации,
контракт границы), и ни одна не оказалась выдуманной; отсутствующие выходы
названы там, где носитель предписывает молчание. Гейтит третья ось —
соответствие ожидания носителю: `U6.7` объявляет согласие с домом на
состоянии, где класс не даёт ни одного из двух объявленных выходов.

нового круга не требуют: форму автор правит той же единицей, пробелы

секции бэклога.

## Что этот круг добавляет к форме захода

Две оси сверх тех, что перечисляли заходы 37-56:

- **ось, которую документ объявил своей, ревью прогоняет первой и по всем
  её клеткам.** Документ объявил, что кейс уровня 2 мерит реализацию, а не
  форму, — и единственный гейтящий дефект оказался ровно там, где эта ось
  не была применена к собственной клетке. Класс воспроизводится вторым
  кругом подряд (у предыдущего документа собственная ось была применена к
  семи клеткам из девяти): автор вводит ось, разбирая тот класс входов, на
  котором её встретил, и не проходит ею по остальным;
- **утверждение о поведении библиотеки на пустом операнде проверяется
  прогоном, и прогон этот дёшев.** Автор честно пометил три таких
  утверждения «прогоном не проверено»; одно из них оказалось ложным, и
  установил это однофайловый запуск через `java Probe.java` — без сборки,
  контекста и базы. Пометка «не проверено» на утверждении, которое
  проверяется за минуту, есть отложенный красный прогон, а не диспозиция.

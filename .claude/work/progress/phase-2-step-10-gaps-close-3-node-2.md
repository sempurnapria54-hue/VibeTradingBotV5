# Узел 2 закрытия `GAPS_CLOSE_3` — полнота журнала: область величин и квантор предиката (A1, A5, B3)

## На какой вопрос отвечает этот файл

Как закрыт узел 2 прогона `DOCS_CHECK_3` шага 10 фазы 2.

Рамка — `.claude/decisions/per-node-closure-frame.md` в редакции поправки
держателя по `PROC-Q5`: чистота меряется **по носителю** (по правкам,
идущим в корпус), рационал — проверяемый минимум, хроники хода мини-петли
здесь нет. Метод узлов — четыре конвенции в
`.claude/work/progress/phase-2-step-10-chronicle.md` §«Четыре конвенции,
введённые узлом 1 и обязательные для узлов 2-6».

## Правило узла

**Полнота журнала меряется по паре «группа × тема», а наружу едет
консервативная свёртка по парам.**

Правило одно на три находки: A1 (нижняя граница и перечень ветвей мерены
по группе, а источник дыры потемной), A5 (величина, отдаваемая при каждой
выдаче, считается сканом нечистимой таблицы), B3 (предикат объявлен прозой
«по всем парам», а исполнимая форма — скаляр без квантора).

## Уровень пробела и род закрывающего действия

Уровень — **концепция-стык** (`.claude/skills/classify-gap-level.md`), и
он взят по верхней из трёх находок: закрытие A1 требует решения,
связывающего больше одного носителя — контракт между строкой состояния
приёма, величиной, которую отдаёт поверхность, и порядком двух чужих
ходов. Верхний уровень поглощает нижние: A5 своей второй половиной
(индексы прозой) и B3 (проза говорит «по всем парам», исполнимая форма —
скаляр) сами по себе легли бы в **носитель**, но закрываются тем же
решением и потому идут с ним.

Признак сработал так: дело не в том, что истина разошлась с домом, а в
том, что **потемной оси у величин полноты нет вовсе**. Корпус уже решил,
что источник разрыва потемной — строка состояния приёма ключуется парой,
операнды алерта объявлены потемными, — и тот же довод к величинам полноты
**не применён** ни к одной.

Род действия — тот, что скилл предписывает уровню: решение на уровне
истины плюс **симметричный обход всех сторон стыка**. Дом истины — владелец
журнала и его исполнимая форма (правки 1-5, 9, 12, 13, 15); стороны стыка —
порядок ходов (правка 6), потребитель клейма (правка 7), чужой ход, который
обязанность исполнит (правка 14). Точечная правка одного носителя пробел
этого уровня не закрывает, и потому носителей у узла восемь, а не один.

**Признак пробела снят прогоном по исполнимой форме, а не чтением прозы.**
Команда печатает форму каждой величины спеки и помечает операнды, чьё
описание объявляет их потемными:

```bash
python - <<'PY'
import json, io
d = json.load(io.open('docs/spec/audit-journal.json', encoding='utf-8'))
for v in d['values']:
    form = 'over=%s op=%s of=%s' % (v.get('over'), v.get('op'), v.get('of')) if 'over' in v else 'expr'
    print('%-24s %s' % (v['name'], form))
print()
for k, t in d['operands'].items():
    print('%-26s %s' % (k, 'ПОТЕМНОЙ' if 'ПОТЕМН' in t.upper() else '—'))
PY
```

До правки:

```
journalLowerBound        over=rows op=min of=recordedAt
receptionStateFresh      expr
continuityClaimable      expr
lagAlertThreshold        expr
lagAlertFires            expr

rows                       —
recordedAt                 —
receptionHalted            —
lagExceededRetention       —
lastEventAgeMs             ПОТЕМНОЙ
topicRetentionMs           —
unconsumedRecords          ПОТЕМНОЙ
receptionStateAgeMs        —
receptionStateMaxAgeMs     —
```

**Ни одна из пяти величин квантора по парам не несёт** — притом что два
операнда объявлены потемными **дословно**, а ещё два потемные **по
существу**: `topicRetentionMs` назван «сроком хранения ТЕМЫ пары» и по нему
считается порог, `receptionStateAgeMs` есть возраст строки состояния,
которых у группы столько же, сколько пар. Метка команды буквальная и
потому занижает: она ловит слово, а не область, — и именно поэтому клейм
здесь строится на **величинах** (ноль из пяти), а не на счёте помеченных
операндов. Это и есть пробел B3 в машинной форме; A1 добавляет к нему
нижнюю границу, у которой потемного операнда нет вовсе — ни по слову, ни по
существу.

## Популяция правила

Собрана до первой правки. Три оси: величины, обязанные иметь потемную
форму; операнды, из которых они считаются; носители, где та и другая
объявлены.

### Ось A — величины полноты, отдаваемые читателю

Члены выведены из дома обязательства, а не из спеки:

```bash

```

```

journalLowerBound receptionStateFresh continuityClaimable lagAlertThreshold lagAlertFires
```

Обязательство дома называет **две** величины, спека объявляет **пять**:
третья читателю не отдаётся (`lagAlertThreshold` — операнд алерта), а
пятая (`lagAlertFires`) обязана быть потемной по своему дому
(`docs/architecture/data-ownership.md`). Члены оси — все пять: правило узла
адресует **форму** величины полноты, а не только то, что едет наружу.

| Величина | Что с ней было | Исход |
|---|---|---|
| нижняя граница полноты (`journalLowerBound`) | одно `min(recorded_at)` по всему журналу; потемного операнда нет | **правлена**: свёртка двух операндов, второй — потемной |
| предикат непрерывности (`continuityClaimable`) | проза говорит «по ВСЕМ парам», исполнимая форма — скаляр | **правлен**: попарная величина плюс свёртка `все` |
| срабатывание алерта на лаг (`lagAlertFires`) | операнды объявлены потемными, квантора нет | **правлен**: попарная величина плюс свёртка `любая` |
| порог алерта (`lagAlertThreshold`) | считается по сроку **своей** темы — операнд уже потемной | выполняется; попарность названа явно |
| свежесть строки состояния (`receptionStateFresh`) | строк состояния столько же, сколько пар; какая из них — скаляр не говорит | **правлена**: величина объявлена попарной |

**Правка 2** — там же, после пассажа «Предикат непрерывности утверждается
по ВСЕМ парам группы» (строки 237-238) добавляется абзац. Было:

> **Предикат непрерывности утверждается по ВСЕМ парам группы:** дыра хоть на
> одной теме есть дыра в журнале, потому что журнал один.

Стало:

> **Предикат непрерывности утверждается по ВСЕМ парам группы:** дыра хоть на
> одной теме есть дыра в журнале, потому что журнал один. Квантор несёт и
> **исполнимая форма** (`docs/spec/audit-journal.json`): попарная величина,
> свёртка «все» по парам и конъюнкт **непустоты** области — а не скаляр.
> Третий нужен потому, что свёртка «все» по пустой коллекции истинна:
> группа, у которой нет ни одной строки состояния, о непрерывности не
> высказывается и отвечает «не утверждаема», а не «дыры нет».
>
> **Подписку группы держит тот же проход опроса, который пишет
> `updated_at`:** он заводит строку каждой темы, что есть в подписке, и
> ставит `subscribed = false` теме, которой в подписке больше нет. **Строка
> при этом не удаляется**, и это несущее в обе стороны. Без заведения пара,
> чьей строки ещё нет, конъюнкцию по существующим строкам не роняет, и
> молчание читается как здоровье — ровно тот механизм, против которого ключ
> и сделан потемным. Без флага снятая тема оставляла бы строку, которую
> никто не обновляет, и предикат непрерывности становился бы ложен
> **навсегда**; а удаление строки **опустило бы нижнюю границу**, потому что
> её второй операнд есть максимум по моментам наблюдения, — при том что
> строки журнала снятой темы из журнала не исчезают. Отсюда разные области:

- **величины.** `journalMinRecordedAt` (`over: rows, op: min`) и

  включение её в предикат сделало бы непрерывность ложной **навсегда**.

  «все» по **пустой** коллекции истинна, значит при нуле подписанных пар
  поверхность отдавала бы «дыры нет» — ошибка **в разрешающую сторону**
  (`docs/concept.md` П1 следствие 3) и неразличение «не проверяли» с
  «проверили, всё в порядке» (следствие 4). Состояние достижимо: первый
  запуск потребителя до первого прохода опроса, выключенная джоба опроса при
  живой поверхности чтения, очищенная таблица состояния в непроизводственном
  окружении. Тем же стражем снабжена и **граница**: на том же состоянии она
  даёт **отсутствие** — одинаково при пустом и при непустом журнале, — и обе
  величины, едущие одной выдачей, говорят об одном состоянии одно и то же.
  Прежняя редакция давала здесь два разных исхода (пустоту при пустом
  журнале, отказ вычисления при непустом) и в двух нотах утверждала один —
  L2 второго раунда критики. Конъюнкт счётным клеймом о числе пар не
  является: он сравнивается только с нулём.
- **примеры.** Прежние девятнадцать сохраняются по предмету: три
  переезжают на `journalMinRecordedAt`, восемь ветвей разрыва — на
  `pairContinuityClaimable`, **восемь** алертных — на `pairLagAlertFires`
  (3 + 8 + 8 = 19, разбивка снята разбором ключей `expect`, а не памятью).
  Добавляются примеры свёртки: расходящиеся пары у `continuityClaimable`
  (одна здорова, вторая нет) и у `lagAlertFires`, четыре примера границы,
  разводящие оба её операнда, две ветви пустого операнда (пустой журнал —
  границей служит момент наблюдения; в подписке нет ни одной темы — границы
  **нет**), пустая область квантора и **снятая с подписки тема** (граница не
  изменилась, непрерывность утверждаема).
- **популяция.** Ось «ветвь разрыва непрерывности» остаётся с теми же
  восемью членами и той же командой вывода; правило популяции —
  `pairContinuityClaimable`: перечень ветвей **попарен по существу**, и
  указание его на групповую свёртку было бы третьим прочтением того же
  предмета.

**Второй популяции — «как попарные исходы складываются» — не заводится, и
это решение, а не пропуск.** Её перечень был бы двухчленным («все истинны» /
«хоть одна ложна») и выводился бы из формы самой свёртки, то есть из того же
текста, который проверяет, — самореферентный перечень, против которого и
заведено требование `derive` (`.claude/skills/closure-population.md`). Зажата
свёртка иначе: тремя примерами расходящихся пар и мутационной пробой, которая
ловит подмену `all` на `any` и обратно.

раннера, а не предположено.** `Spec.aggregate` собирает коллекцию из

**Каждая свёртка предъявлена ПАДАЮЩЕЙ пробой поимённо, а не только общим
мутационным замером.** Подмена операции в симуляции роняет ровно те примеры,

```

pairsAllContinuous   where снят фильтр подписки          : РАСХОЖДЕНИЙ 1
pairsObservedSince   where добавлен фильтр подписки      : РАСХОЖДЕНИЙ 2
```

Проба именно падающая: без неё клейм «квантор мерится» стоял бы на общем
счёте выживших, который у здоровой спеки нулевой при любой её форме.
Последние три строки — охраны, заведённые критикой: непустота области
квантора у предиката и у границы (K3, L2) и **разные области** у границы и у
непрерывности (L4). Седьмая строка читается так: попытка считать границу
только по подписанным парам роняет **два ожидания одного примера** — того,
где тема снята с подписки: и `pairsObservedSince`, и `journalLowerBound`
уезжают с 5000 на 1000.

**Шесть новых величин прибавились к мутационному замеру и его прошли**
(453 → 459): ни одна не переживает нейтрализации, то есть каждая чем-то
проверяется. Четырнадцать новых примеров (656 → 670) — четыре границы, три
свёртки предиката, три свёртки алерта, две ветви пустого операнда, пустая
область квантора и снятая с подписки тема.

**Пустой операнд свёртки — разобранная ветвь, а не край, и разобрана она
потому, что арифметика языка спеки на пустоте ОТКАЗЫВАЕТ** («подстановка
нуля запрещена», `SpecExpression.number`). Ветвей две, и они несимметричны:

- **журнал пуст** (свежее развёртывание, принято ещё ничего) — состояние
  штатное, и границей служит второй операнд: обещать раньше момента
  наблюдения тем нечего. Форма — `if(isNull(journalMinRecordedAt), …)`;
  без разбора поверхность отказывала бы ровно в первый день работы;
- **в подписке нет ни одной темы** — величина даёт **отсутствие**, и это
  верный исход: группа, не наблюдающая ни одной темы, полноты не обещает
  вовсе. Отсутствие зажато примером с `expect: {journalLowerBound: null}` и
  падающей пробой (снятие стража непустоты роняет ровно его), то есть
  проверяется, а не подразумевается. Отказа вычисления у этой ветви нет: он
  был прежней редакцией, при которой один предмет выражался двояко.

**Ключи популяции разрешаются на верхнем уровне состояния**
(покрытие популяций в `Spec` вычисляет каждый ключ с **пустой строкой**:
`resolve(id, state, Map.of(), …)`), поэтому восемь примеров ветвей
остаются со **скалярным** состоянием, а коллекцию `pairs` несут только
примеры свёртки. Обратный порядок — переложить ветви внутрь `pairs` —
вывел бы популяцию из-под измерения: её оси перестали бы разрешаться, и
прогон объявил бы её неизмеренной.

## Исполнимая форма — чем клейм обеспечен и чем НЕ обеспечен

**Спекой обеспечен полностью — в этом и состоит правка 9.** Свёрток по
парам три (`pairsAllContinuous`, `lagAlertFires`, `pairsObservedSince`), и
каждая предъявлена **падающей** пробой; сверх них падающими пробами
предъявлены оба стража непустоты области квантора — у предиката и у
границы. Перечень проб с их исходами — в §«Проект правки», подраздел
правки 9.

**Схемой обеспечена только половина.** `not null` у `observed_since`
гарантирует, что у **существующей** строки момент есть; что строка есть у
**каждой** темы подписки, схема не знает — состав подписки живёт в
конфигурации сервиса, а не в базе. Отсюда охрана — тест потребителя
(позиция 23 дельты `CODE`), и её область названа: она мерит проход опроса,
а не конфигурацию.

**Индекс охраной клейма не является и на неё не выдаётся.** Он снимает
стоимость, а не проверяет верность: `min(recorded_at)` без индекса вернул
бы то же число. Клейм A5 — «величина, отдаваемая при каждой выдаче,
считается сканом нечистимой таблицы» — закрывается **наличием индекса в
объявленной схеме**, и проверяется он тем же способом, что и остальные
индексы дока: сверкой перечня с миграцией на `CODE`
(`docs/rules/persistence-representation.md` §«Место истины схемы — модель»).

**Крен линзы у A5 взят наполовину, и половина названа.** Линза кренила к
варианту 3 («хранить границу величиной строки состояния и не считать её
запросом») **при условии**, что A1 разрешится потемной границей; иначе — к
варианту 2 (индекс). Узел берёт потемную границу, но вариант 3 **в чистом
виде отвергает**: хранимая целиком граница теряет ветвь чистки. В `dev` и
`stage` журнал чистится по профилю, а `observed_since` чисткой не двигается —
хранимая граница обещала бы там полноту, которой нет. Вернуть верность можно
было бы, сделав чистку **писателем** `observed_since`; тогда правда о
`prod`-клейме зависела бы от джобы, работающей только вне `prod`, и у
непостроенного компонента появилась бы обязанность, которой никто не
предъявит. Взятая половина: второй операнд — хранимый и потемной (закрывает
A1), первый остаётся выводимым из журнала и получает индекс (закрывает A5).
У каждого операнда при этом свой уже существующий писатель, а нового
компонента не заводится ни одного.

**Чего узел НЕ обеспечивает и почему.** Порядка «подписка не позже темы»
(правка 6) не мерит ничто, и это названо в самом тексте правки: энфорсер
потребовал бы реестра тем с их durable-потребителями, то есть счётного
перечня, от которого корпус отказался сознательно
(`docs/architecture/data-ownership.md`). Клейм полноты при нарушенном
порядке остаётся верным — это и есть причина, по которой отсутствие
энфорсера здесь терпимо: нарушение стоит событий, а не правды о них.

## Исход мини-петли — строкой

**Два раунда критики плюс верификация финальной правки.** Раунд 1 — **14**
дефектов, 9 несущих, **5 блокирующих**; раунд 2 — **12** дефектов, 7
несущих, **4 блокирующих**, регресс раунда 1 снят на 12 из 14 (K11 и K12 —
доработаны вторым заходом). Диспозиция обоих перечней поимённо —
§«Ответ критике раунда 1» и §«Ответ критике раунда 2»; ни один дефект не
оставлен без исхода. Верификация финальной правки: вердикт «приземление не разрешено» из-за одной находки (нота одной величины утверждала отказ там, где спека даёт отсутствие); находка снята, прочие десять — рационал. Диспозиция всех одиннадцати — §«Ответ верификации финальной правки».

**Что поймала петля, чего не поймал свип закрытия.** Два раза подряд —
ошибку **в разрешающую сторону**, невидимую читателю. Раунд 1: свёртка «все»
по **пустой** коллекции пар давала «дыры нет» при нуле строк состояния
приёма. Раунд 2: писатель снятия строки, заведённый доработкой раунда 1,
делал нижнюю границу **немонотонной** — снятие темы опускало максимум, а
строки журнала снятой темы из журнала не исчезают. Оба состояния достижимы,
и ни одно не ловилось ни спекой, ни схемой.

**Что поймал СВОЙ свип, чего не предъявляла критика:** «границы нет»
выражалось двумя разными исходами на одном состоянии; контракт чтения
обязывал отдавать границу с **каждой** выдачей, не называя ветви её
отсутствия; перечень ветвей разрыва стоя́л копией в доке деталей и стал
неполон тем же ходом, которым заведён конъюнкт непустоты.

**Механизм, который стои́т унести в следующий узел.** Правка, снимающая
дефект, обязана быть проверена **на соседа**: три снятия раунда 1 дали
побочные дефекты, и два из них были блокирующими. Самый дорогой —
удаление литерала, который оказался `arrived`-шаблоном **чужой** живой
записи реестра: приземление уронило бы зелёный энфорсер на чужом предмете.

Отчёты заходов — `…-node-2-critique.md`, `…-node-2-critique-round2.md`,
`…-node-2-verification.md`.

# Шаблон: тест-план интеграции

## На какой вопрос отвечает этот файл

Каков формат докового файла тест-плана контура тестов API источника.

## Назначение

Универсальный шаблон тест-плана и кейсов контура тестов API
источника, **один на все источники**. Вход для `tester` на этапе
DESIGN (`.claude/skills/test-design.md`). Готовый план кладётся в
`.claude/tests/{testType}/{source}/`.

**Стаб.** Известен скелет (форма плана + форма кейса). Детальные
поля **не фиксируются** — форма снимается с первого пилотного плана
(`.claude/tests/source-api/okx/`). Спекулятивные поля не вносим.

## Форма плана (скелет)

- **На какой вопрос отвечает этот файл** — «Как проверяем интеграцию
  с источником `{name}` (такой-то скоуп)?».
- **Скоуп** — что покрывает план. Для новой биржи — **вся
  интеграционная поверхность источника**: каждый запрос клиентского
  слоя к источнику, с осмысленным кейсом на каждый (не подмножество).
  Плюс триггер (новая биржа / новый эндпоинт / изменение контракта /
  разовый).
- **Среда** — demo (test-профиль, demo-креды) для write; prod
  read-only — для чтений; явно, что без write-эффектов на prod.
- **Негативный слой (без состояния)** — дешёвые кейсы, гоняются
  первыми.
- **Цепочки (по графу предусловий)** — связные последовательности;
  выход кейса = предусловие следующего.
- **Чистота биржи** — после прогона ни висящих ордеров, ни позиций,
  ни иных сущностей. Достигается teardown'ом **в каждом кейсе** (см.
  форму кейса), а не одним общим финальным шагом.

## Форма кейса (скелет)

**Один кейс = одна отдельная таблица.** Кейс самодостаточен: ставит
своё предусловие, проверяет своё и **оставляет биржу чистой**.

- **Шапка кейса** — объект (эндпоинт или цепочка),
  предусловие-состояние (исполненный ордер / живой неисполненный /
  отсутствие ордера / —), среда (demo / prod read-only).
- **Тело — таблица, строка = запрос кейса.** Колонки: запрос
  (операция клиентского слоя + параметры) | проверки | ожидаемый
  результат (из контракта источника — ACK-семантика, код ошибки,
  факт состояния; незадокументированное не выдумывается, помечается
  пробелом) | фактический результат + наблюдения (заполняется на RUN
  `.claude/skills/test-run.md`; до прогона пусто).
- **Teardown кейса** — завершающие строки той же таблицы: что
  снимает поставленное кейсом состояние (отмена / закрытие), чтобы
  после кейса биржа была чистой.
- **Цена ордера — с биржи, минимальный риск.** Кейс, ставящий ордер,
  не берёт цену «из воздуха»: live-цена тянется с биржи (ticker /
  mark — отдельной строкой кейса), и ордер ставится от неё **заведомо
  неисполнимым, с минимальным риском** (цель — проверить интеграцию,
  не потерять деньги; критично на prod). **Предусловие:** интеграция
  отдаёт live-цену через прокси. Нет такого эндпоинта — surface-gap:
  помечается (запрос цены не выдумывается), закрывается при
  регенерации.

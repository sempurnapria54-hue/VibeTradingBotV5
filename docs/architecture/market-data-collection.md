# Сбор рыночных данных

## На какой вопрос отвечает этот файл

Какие рыночные данные собираются и по какому правилу.

## Правило — по невосполнимости

Ось одна: **можно ли добыть это потом**.

| Класс | Примеры | Как собираем | Область |
|---|---|---|---|
| невосполнимое | срезы стакана, ликвидации, тикер-снимки | непрерывно, грубой частотой, с первого дня работы сервиса | весь листинг каждой подключённой площадки |
| восполнимое | свечи, открытый интерес, funding, история сделок площадки | по требованию потребителя плюс бэкфилл за глубину, которую площадка отдаёт | инструменты, которые кто-то запросил, и весь листинг для советника |

Довод: невосполнимое стоит дёшево сегодня и бесконечно дорого завтра;
восполнимое стоит одинаково в любой день, и собирать его впрок незачем.

## Невосполнимые срезы

- **Стакан** — верхние уровни обеих сторон с фиксированной глубиной,
  снимок раз в интервал по каждому инструменту; интервал — калибровочная
  величина сервиса, направление ошибки — реже, чем чаще: пропущенный срез
  не ломает потолок, перегруженный сбор ломает всё остальное.
- **Ликвидации** — поток, как отдаёт площадка; хранится как есть.
- **Тикер** — цена, объём, mark и index на момент среза.

Срезы пишутся с биржевой меткой времени; своя метка — рядом, для разбора
задержки (`docs/rules/time-utc.md`).

## Восполнимое

- **Свечи** — как сегодня (`docs/processes/candle-loading.md`), по
  таймфреймам, объявленным потребителями, с бэкфиллом на запрошенную
  глубину.
- **Открытый интерес, funding** — тем же механизмом по требованию.
- Бэкфилл идёт в бюджете лимитов площадки после потока: срез важнее
  истории.

## Производные

Индикаторы, структура и фаза рынка считаются как сегодня
(`docs/processes/market-data-calculation.md`) и хранятся историей строк:
у истории появился потребитель — бэктест и детекторы. Глубина хранения
производных следует за глубиной свечей, на которых они посчитаны.

## Пригодность для детекторов

Собранное обязано быть пригодным для детекторов советника
(`reserved-extension-points.md`): срезы по всему листингу, а не только по
торгуемым инструментам; единая шкала времени; фичи, вычислимые на любой
момент прошлого без обращения к площадке. Это требование к сбору сегодня,
а не к детекторам потом.

## Хранение

Временные ряды — `data-ownership.md`. Глубина по классам: невосполнимое
не удаляется; восполнимое чистится по политике хранения с возможностью
повторного бэкфилла; производные — за свечами.

# Платформа: развёртывание, наблюдаемость, безопасность

## На какой вопрос отвечает этот файл

На чём система развёрнута и как наблюдается.

## Развёртывание

- **Kubernetes** — всё: сервисы, данные, наблюдаемость, раннеры сборки.
- **GitOps.** GitHub Actions на self-hosted раннерах в кластере собирает
  образы сервисов по путям монорепозитория и меняет тег образа в
  манифестах окружения; Argo CD приводит кластер к состоянию манифестов.
  Ручных `kubectl apply` в поставке нет.
- **Окружения** — `dev`, `stage`, `prod` как отдельные наборы манифестов;
  до выбора облака все три — пространства имён одного кластера, после —
  `prod` отдельным кластером.
- **Данные операторами до выбора облака:** CloudNativePG для Postgres
  (с TimescaleDB), Strimzi для Kafka, оператор Vault, ECK для Elastic,
  kube-prometheus-stack, оператор Jaeger, оператор провайдера
  идентичности. Управляемые сервисы облака — после выбора, по одному,
  с сохранением контрактов сервисов.
- **Монорепозиторий:** общие артефакты, сервисы, фронт, манифесты и корпус
  знания рядом; сборка сервиса перезапускается только по изменению его
  путей и общих артефактов.

## Наблюдаемость

- **Логи** — структурированный JSON из каждого сервиса → сборщик на
  узле → Elasticsearch → Kibana. Секреты в логах не появляются
  (`.claude/rules/codestyle.md` у автора кода).
- **Трейсы** — OpenTelemetry SDK в каждом сервисе → Jaeger. Контекст
  трейса проходит через REST и через конверт события; `tenantId` и
  `strategyId` — атрибуты каждого спана с первого дня.
- **Метрики** — Prometheus + Grafana. Технические (задержки, ошибки,
  лаг потребителей, глубина outbox) и бизнес (сигналы по исходам,
  сделки по терминалам, холды по ступеням, серия убытков, доля
  бюджета) с метками `tenantId` и `strategyId`; кардинальность связана
  числом активных стратегий и пересматривается, когда оно перестаёт
  быть малым.
- **Алерты** — Alertmanager: технические от метрик, бизнес — от событий
  `HoldRaised`, `AnomalyReported`, остановки по серии убытков.
  Носитель факта при этом — запись, не алерт
  (`docs/concept.md`, П3).

## Безопасность

- **Секреты — Vault:** ключи площадок по счетам тенантов
  (`tenant-and-exchange.md`), учётные данные баз и брокера — динамические
  или короткоживущие; сервисы входят в Vault методом Kubernetes с ролью
  на свой префикс.
- **Доступ пользователей** — провайдер идентичности, bearer-токены,
  проверка подписи локально в каждом сервисе, права по роли на каждом
  вызове (`contracts.md`). Basic-аутентификации и CSRF-оговорок больше
  нет: тропа к поверхности — токен.
- **Между сервисами** — сетевые политики по ярусам (`services.md`):
  периметр видит домен, домен видит интеграцию, обратных путей нет;
  наружу из кластера ходят только коннекторы и `bff`.
- **Поставка** — образы подписываются в сборке и проверяются
  политикой допуска кластера; зависимости сканируются в той же сборке.
- **Данные** — базы не доступны снаружи кластера; бэкапы шифруются;
  тенантные данные разделены `tenantId` и проверкой контекста на каждом
  вызове.

# CandleGroup lifecycle

## На какой вопрос отвечает этот файл

Через какие состояния проходит загрузка свечей группы (`CandleGroup`).

Структура модели — `docs/models/domain/other/CandleGroup.md`.

## Кто управляет

Статусы ведёт `docs/components/CandleJob.md` в рамках процесса
`docs/processes/candle-loading.md`. Группа движется по
статусам загрузки/докачки/проверки целостности свечной истории;
фактические границы загруженной истории фиксируются в
`actualFirstUtcMillis`/`actualLastUtcMillis`, объём — в `count`
(чтобы рестарт `BACKFILL`/`REPAIR` не был дорогим). Плановый
горизонт загрузки — `plannedFirstUtcMillis` **самой группы**; дом
величины — `docs/models/domain/other/CandleGroup.md`.

## `CandleGroup.Status`

| Статус | В расчётах | Final | Смысл |
|---|---|---|---|
| `CREATED` | нет | нет | Группа создана; данных нет или покрытие не подтверждено. |
| `BACKFILL` | нет | нет | Историческая загрузка «в глубину» до планового горизонта группы (`plannedFirstUtcMillis`) либо до пустого ответа биржи. Фиксирует `actualFirstUtcMillis`/`actualLastUtcMillis`/`count`. |
| `SYNC` | да | нет | Регулярная докачка хвоста (overlap последних N баров) по расписанию. |
| `CHECK` | да | нет | Быстрая проверка целостности по count; при необходимости инициирует `REPAIR`. |
| `REPAIR` | да* | нет | Найдены дыры → бинарный поиск по count + докачка окон. |
| `ACTIVE` | да | нет | Покрытие подтверждено, дыры отсутствуют. |
| `ERROR` | нет | problem-final | Попытки докачки дыр исчерпаны. Цикл группу не ведёт, требование не оживляет, и ни одна операция сервиса из статуса не выводит: разбор — ручной, мимо поверхности. |
| `DELETED` | нет | да | Значение перечня без писателя — недостижимо (см. ниже). |

\* в `REPAIR` группа уже имеет покрытие, но целостность ещё
восстанавливается.

## Общий поток

```text
CREATED
  -> BACKFILL        (первый тик цикла; чтения площадки на нём нет)
BACKFILL
  -> CHECK           (достигнут plannedFirstUtcMillis либо площадка отдала пусто)
CHECK
  -> ACTIVE          (ряд плотен)
  -> REPAIR          (дефицит по count)
REPAIR
  -> CHECK           (окно дыры докачано либо дыра не локализована)
  -> ERROR           (попытки докачки исчерпаны: столько проходов подряд не продвинули ряд)
ACTIVE
  -> SYNC            (подошёл новый закрытый бар)
SYNC
  -> ACTIVE          (хвост докачан, и проверка тем же шагом нашла ряд плотным)
  -> REPAIR          (хвост докачан, и проверка тем же шагом нашла дефицит)
BACKFILL <- из любого живого статуса, когда требование потребителя УГЛУБИЛО горизонт
```

Все рёбра, кроме возврата к `BACKFILL`, пишет тик загрузки свечей
(`docs/components/CandleJob.md`): ребро `ACTIVE → SYNC` — его триггер
хвоста, остальные — ведение рабочих групп, по одному шагу группы за тик.
Возврат к `BACKFILL` пишет приём требования потребителя
(`docs/architecture/market-data-collection.md`).

**Завершённый бэкфилл идёт прямо в проверку, а не в докачку хвоста.**
Плотность меряется на фактических границах `[actualFirst, actualLast]`, и
выкачанный ряд проверяется сразу. Хвост, отросший за время бэкфилла,
догоняется штатным ребром: после проверки группа в `ACTIVE`, и первый же
новый закрытый бар уводит её в `SYNC`; не уложившееся в одну страницу
докачки проверка видит дефицитом и латает через `REPAIR` — постранично, и
ширина хвоста группу в `ERROR` не уводит (§«Докачка дыр (`REPAIR`)»).

**Докачка хвоста проверяет целостность тем же шагом.** `SYNC` докачивает
хвост, сводит границы и `count` с рядом в базе и тут же решает `ACTIVE` либо
`REPAIR`; статуса `CHECK` между ними нет. Довод — готовность инструмента: её
пересчитывает тот же тик **после** ведения групп
(`docs/lifecycles/Instrument.md`), и проверка отдельным шагом оставляла бы
догнанную группу на пересчёте вне `ACTIVE`. Инструмент тогда терял бы
готовность на каждом тике с новым баром — при минутной группе и ежеминутном
тике через тик, — а торговое ядро отбирает торгуемые инструменты по
`ACTIVE`. Статус `CHECK` при этом не лишний: в него ведут завершённый
`BACKFILL` и проход `REPAIR`, и `CHECK` после `BACKFILL` есть первое
подтверждение плотности — до него группа готовой не считается.

**Рядовой отказ чтения группу в `ERROR` не уводит.** Отказ стоит группе
текущего тика, и следующий тик берёт её тем же шагом цикла
(`docs/components/CandleJob.md`); `ERROR` пишет только исчерпание попыток
докачки дыр.

**`DELETED` недостижим, и это названо.** Значение в перечне есть, писателя
у него нет: операции удаления единицы сбора поверхность не несёт, а отзыва
требования нет намеренно (`docs/architecture/market-data-collection.md`).
Цикл статус только **исключает** — как терминальный он не ведётся и
требованием не оживляется.

### Возврат к `BACKFILL` по углублённому требованию

**Ребро несущее, и оно шире, чем «из `ACTIVE`».** Дотягивать нижнюю
границу до горизонта умеет только `BACKFILL`; остальные статусы цикла
сами к нему не возвращаются. Группа, которую требование застало в
`SYNC`/`CHECK`/`REPAIR`, дошла бы по циклу до `ACTIVE` с непокрытым
горизонтом — и требование потерялось бы молча. Окно не редкое: докачка
хвоста уводит группу из `ACTIVE` на каждом новом закрытом баре — на время
тика, а хвост шире страницы держит её в `REPAIR` несколько тиков.

**Терминальные статусы требованием не оживляются.** Из `ERROR` и
`DELETED` возврата нет: иначе чужая команда обнуляла бы исчерпанные
попытки докачки. Горизонт при этом всё равно расширяется — он величина
группы, а не её статуса.

Проверка целостности — по count: число свечей от первой до
последней по таймфрейму должно совпадать с ожидаемым по
density-инварианту на `[actualFirst, actualLast]`
(`docs/models/domain/other/CandleGroup.md`). Все расчёты — только по закрытым свечам, без look-ahead
(`docs/components/CandleJob.md`).

## Политика загрузки и целостности

Детали, ранее отложенные на, зафиксированы здесь.
Конкретные числа и тайминги (CRON-период, шаг деления при бинарном
поиске, лимит окна докачки, число попыток до `ERROR`, дефолт
горизонта) — конфигурируемы, проставляются на под-шаге `CODE`.

### Глубина и покрытие (`BACKFILL`)

- Плановый горизонт — `plannedFirstUtcMillis` **группы**; его называет
  требование потребителя, дом величины —
  `docs/models/domain/other/CandleGroup.md`.
- `BACKFILL` пагинирует историю назад (по `history-candles`, см.
  `docs/integrations/okx/contracts/candle.md`) до достижения
  горизонта **либо** до пустого ответа биржи (начало истории биржи по
  инструменту → фиксируется в `actualFirstUtcMillis`).
- **Горизонт не назван** — глубина не заказана, и выкачка идёт до конца
  истории площадки: требование без глубины есть требование всей
  доступной истории, а не отсутствие требования.
- Фактические границы загруженного — `actualFirstUtcMillis`/
  `actualLastUtcMillis` на группе (per-ТФ).

### Регулярная докачка хвоста (`SYNC`)

- Включается по группе, когда подошёл новый закрытый бар; когда он
  подходит — дом величины `docs/models/domain/other/CandleGroup.md`.
  Докачка — forward-fill от `actualLast` к `now`.
- Запускается из общего тика `CandleJob` (CRON, см.
  `docs/components/CandleJob.md`).

### Проверка целостности (`CHECK`)

- Выполняется **после завершённого `BACKFILL`** и **после каждой
  записи** в группу (`SYNC`/`REPAIR`); после `SYNC` — тем же шагом, без
  отдельного статуса (§«Общий поток»).
- `count` и `actualFirst`/`actualLast` не накапливаются, а берутся из ряда
  в базе (`COUNT(*)` и крайние моменты открытия) на каждом шаге цикла,
  который пишет в группу или проверяет её: рассинхрон после рестарта в
  середине пачки гасит первый же шаг группы, и отдельного стартового прохода
  нет. Сама проверка — сравнение `count` с ожидаемым на
  `[actualFirst, actualLast]` (density-инвариант).
- Плотно (`docs/spec/candle-group-integrity.json` (`candleGroupDense`)) →
  `ACTIVE`; дефицит → `REPAIR`.

### Докачка дыр (`REPAIR`)

- Дыра локализуется **бинарным поиском по count** (делим интервал,
  сравниваем фактический count подынтервала с ожидаемым).
- Локализованное окно докачивается точечно (`history-candles`).
- Петля `REPAIR` ↔ `CHECK`, пока ряд не станет плотным.
- Постоянная внутренняя дыра (биржа реально отдаёт пусто) после
  исчерпания попыток → `ERROR`. Реестра известных пропусков нет.
- **Проход, продвинувший ряд к плотности, бюджет попыток возвращает.**
  Предел попыток отличает дыру **неустранимую**, а не широкую: проход
  докачивает не больше страницы, и хвост, отросший за долгий бэкфилл, латается
  постранично. Бюджет, не возвращаемый прогрессом, исчерпывался бы на заведомо
  устранимой дыре шире `1 + max-repair-attempts` страниц — у минутной группы
  при умолчаниях это бэкфилл дольше примерно 600 тиков, — и терминальный
  `ERROR` такую группу уже не отпустил бы. Поэтому предел считает проходы
  **подряд**, не сократившие недостачу до плотности. Недостача — ожидаемое по
  density-инварианту минус `count`, а не число вставленных свечей: бары ниже
  нижней границы ряда её не сокращают. Завершение сохраняется: недостача
  конечна, каждый продвинувший проход сокращает её хотя бы на бар, а верхняя
  граница ряда в петле не растёт.
- **Широкий хвост латается здесь, а не докачкой вперёд от `actualLast`.**
  Курсор площадки — «строго старше» (`docs/integrations/okx/contracts/candle.md`),
  и шаг вперёд он даёт только окном; окно, целиком попавшее в настоящий
  пропуск площадки, возвращало бы уже загруженное, и группа стояла бы в
  догонке без исхода. Починка же такой пропуск находит и после исчерпания
  попыток уводит в `ERROR`.

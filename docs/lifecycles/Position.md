# Position lifecycle

## На какой вопрос отвечает этот файл

Через какие состояния проходит `Position`.

Структура модели — `docs/models/domain/core/Position.md`.

## Кто управляет

Статусы меняет **только тропа добычи позиции**: граница интеграции отдаёт
снапшот либо пустоту, резолвер возвращает статус и кандидата причины
закрытия, исполнитель применяет результат. FSM позицию не создаёт и полей
не заполняет.

Команда **двуногая**: живая позиция, затем — при её отсутствии либо смене
эпизода — история закрытых позиций. **Вторая нога статус не меняет** — его
определила первая; она наполняет положения закрытия на строках эпизодов и
двигает верхнюю границу окна линковки **монотонно вперёд**, по времени
последней записи.

## Статусы

| Статус | Что означает |
|---|---|
| `ACTIVE` | позиция существует на бирже и сопровождается; живого риска сам по себе не гарантирует |
| `CLOSED` | позиции на бирже нет |
| `ERROR` | факты биржи нельзя безопасно интерпретировать либо нарушен инвариант её контракта |

**Промежуточных статусов нет:** позиция не создаётся локально до биржи,
появляется как результат исполнения заявки, а частичное уменьшение — это
активная позиция с обновлённым размером.

## Статус и живой риск

```text
ACTIVE                     → позиция есть и сопровождается
ACTIVE, размер > 0         → есть живой риск
ACTIVE, размер = 0         → биржа ещё возвращает позицию, живого риска нет
CLOSED                     → позиции на бирже нет
```

## Смена эпизода

Наблюдение **другого** идентификатора позиции означает новый эпизод:
живая строка закрывается, заводится строка нового эпизода.

**Дискриминатор гейта переоткрытия — размер, а не идентификатор:** он
срабатывает **до** появления новой позиции, а ждать смены идентификатора
значило бы ловить уже случившееся переоткрытие. **Размер берётся
траншевый, а не нетто-размер позиции** — на сетке нетто-позиция в ноль
почти не приходит (`docs/lifecycles/DealTranche.md`).

**Позиция, впервые увиденная уже закрытой**, заводится второй ногой сразу
закрытой — из записи истории.

## Матрица переходов

```text
(нет)   -> ACTIVE | CLOSED
ACTIVE  -> CLOSED | ERROR
CLOSED  -> (терминальный для эпизода)
ERROR   -> CLOSED
```

**Закрытые эпизоды остаются строками** той же таблицы: по ним считается
результат сделки и правые операнды пар сверки.

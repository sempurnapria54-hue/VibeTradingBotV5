# PositionsHistoryOkxResponse (OKX positions-history)

## На какой вопрос отвечает этот файл

Какие поля у нативной модели истории позиций источника.

## Инвентарь полей

### Используемые

Used-минимум для числа `resultProfit`: готовый net берётся одним полем
`realizedPnl`; своих слагаемых не складываем. Сверх числа used-набор несёт
операнды **create-тропы** (позиция впервые увидена уже закрытой) и
готовый funding.

| OKX field | Тип | Семантика |
|---|---|---|
| `realizedPnl` | string-decimal | готовый net realized P&L = `pnl` + `fee` + `fundingFee` + `liqPenalty` (посчитан биржей) → `Position.externalRealizedProfit` → `Deal.resultProfit` |
| `ccy` | string | валюта, в которой посчитан `realizedPnl` → `Position.externalResultCurrency`. В `Deal.resultProfitCurrency` **не переходит** — авторитет валюты результата — расчётная валюта инструмента, а это поле **проверяемый признак**; кто, когда и с чем его сравнивает — правило проверки валюты чисел записей закрытия (`docs/rules/pnl-reconciliation.md`) |
| `closeAvgPx` | string-decimal | средняя цена фактического выхода → `Position.externalCloseAveragePrice`; потребитель — калибровка запаса на проскок на тропе attached-SL |
| `pnl` | string-decimal | реализованный P&L **до** издержек → `Position.externalRealizedProfitGross`; потребитель — **первая пара** раздельной сверки разбивки по категориям |
| `fee` | string-decimal | знаковая комиссионная компонента (минус — комиссия, плюс — ребейт; **сырой знак**) → `Position.externalFee`; потребитель — **вторая пара** раздельной сверки |
| `fundingFee` | string-decimal | накопленный funding закрытой позиции → `Position.externalFundingCost`, **со снятием знака при маппинге**. Потребители — ценовой результат сделки, на котором стои́т счётчик серии убытков (`docs/rules/loss-streak-halt.md`), и **третья пара** сверки. `FUNDING`-строки `DealCashFlow` — **сверка** этого числа, не источник |
| `liqPenalty` | string-decimal | ликвидационный штраф (**сырой знак**) → `Position.externalLiquidationPenalty`; потребитель — **четвёртая пара** раздельной сверки против категории `LIQ_PENALTY` |
| `type` | string | тип последнего закрытия (`1` частичное / `2` полное / `3` ликвидация / `4` частичная ликвидация / `5` ADL не полностью / `6` ADL полностью) → `Position.externalCloseType`; провенанс аварийного терминала **и** операнд `Deal.closeOutcome`. Во что резолвится — `docs/models/mapping/PositionCloseResult.md`, дом отображения, старшинства по эпизодам и ветки непригодного операнда; перечень **офдоковый, наблюдением не подтверждён** |
| `instId` | string | биржевой идентификатор инструмента записи → `externalInstrumentId` снапшота; **операнд структурной валидации** «запись относится к запрошенному инструменту». Без него корректность чтения держалась бы только фильтром запроса — знанием вызывающего, а не фактом ответа, и при снятии ограничения «один инструмент в контуре» молча давала бы чужую запись |
| `posId` | string | биржевой id позиции (**половина** ключа адресации записи — вторая половина `cTime`; истекает ~30 дней после полного закрытия). Источником **переиспользуется** у переоткрытой позиции, и фильтр `posId` в запросе записи не сужает (наблюдено 2026-08-30, провенанс `рантайм`). На **update**-тропе сверяется с `Position.externalId` **в паре** с `externalCreatedAt`; на **create**-тропе — **пишется** в `Position.externalId`. Дом единицы — `docs/models/domain/core/Position.md` |
| `direction` | string | направление закрытой позиции → `Position.direction` **только на create-тропе** (на update-тропе поле уже заполнено live-ногой). Без него create-тропа материализует `Position` без направления, а `positions.direction` nullable ⇒ отказ был бы тихим. **Резолв сырого значения в доменный `Position.Direction` — в слое интеграции**, снапшот несёт уже доменное значение; незнакомое либо пустое — `ExternalInvariantViolationException`. Перечень сырых значений (`long` / `short`) — `docs/integrations/okx/contracts/position.md`, дом перечней значений полей элемента записи; он **офдоковый и наблюдением не подтверждён** |
| `cTime` | string-ms | время создания записи → `Position.externalCreatedAt` (наследуется от `Auditable`). Роль «нижняя граница окна линковки `Deal.billsWindowBegin` на create-тропе» **снята** — границу ставит единственный писатель `SubmitOrderExecutor`. В used остаётся: потребитель структурный (audit-поле), критерий «прикладного потребителя нет» к таким полям неприменим (`docs/models/domain/other/Auditable.md`) |
| `uTime` | string-ms | время обновления записи → `Position.externalModifiedAt` (сортировка/пагинация positions-history — тоже по `uTime`) |

### Не используются (отбрасываются на маппинге)

Поле без названного потребителя не заводится.

| Поле | Почему не заводится |
|---|---|
| `settledPnl`, `pnlRatio` | слагаемые и производные net'а; net берётся готовым `realizedPnl` |
| `openMaxPos`, `closeTotalPos`, `nonSettleAvgPx` | объёмы и цены без потребителя |
| `triggerPx` | цена триггера ликвидации/ADL — кандидат в носители провенанса аварийного закрытия; вопрос открыт, пока не маппится. Расхождение доков источника о его применимости ничего не нагружает |
| `openAvgPx` | средняя цена входа за жизнь позиции. Её маппинг сделал бы колонку двуписьменной: при доборах текущая средняя и средняя за жизнь расходятся, и провенанс значения становится неоднозначным. `Position.externalAverageEntryPrice` пишет только живая нога (`docs/models/mapping/PositionCloseResult.md`) |

Категорийная разбивка (комиссия / funding / ребейт / штраф) идёт из
bill-записей (`docs/models/mapping/DealCashFlow.md`), а не из этих полей:
четыре числа биржи здесь — правые операнды четырёх пар сверки
(`docs/rules/pnl-reconciliation.md`), а не её источник.

## Конвертация

`numeric string → BigDecimal`; timestamp string → epoch millis →
`OffsetDateTime` (конвенция типов времени проекта;
`docs/models/mapping/PositionCloseResult.md`).

**Пустое значение конвертируется по природе поля**:

| Природа поля | Поля | Пустое значение (пустая строка / отсутствие ключа) |
|---|---|---|
| **несобытийное** — величина существует всегда, «не было события» означает нулевую величину | `pnl`, `fee`, `fundingFee`, `liqPenalty` | **`ZERO`** |
| **событийное** — факт мог не наступить, и его отсутствие есть значение | остальные поля записи | `null` |

**Конвенция применяется до проверки обязательности контракта записи.**
Иначе валидация границы реджектила бы **каждую** сделку без фондирования
или без ликвидационного штрафа: контракт требует, чтобы эти четыре поля
были заполнены и парсились, а нарушение выражается
`ExternalInvariantViolationException` ⇒ биржевая ступень 2
(`Exchange.TRADE_BLOCKED` + flatten) с ручным
снятием (`docs/models/mapping/PositionCloseResult.md`).

**Какую форму источник отдаёт фактически — открытый факт**, добываемый
прогоном. Правило записано для всех трёх форм (пустая строка, `"0"`,
отсутствие ключа), поэтому ответ прогона меняет срабатывающую ветку, а не
конструкцию.

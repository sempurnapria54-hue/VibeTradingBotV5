# Position

## На какой вопрос отвечает этот файл

Что это за сущность `Position`.

## Назначение

`Position` — **строка одного эпизода** позиции сделки: одна биржевая
позиция — одна строка. Отвечает на вопрос «есть ли живой риск по сделке
прямо сейчас», а после закрытия несёт **положение закрытия** —
реализованные факты, добытые из истории позиций.

**Сделка многоэпизодна:** позиция может схлопнуться в ноль и открыться
заново новой входной заявкой, получив новый биржевой идентификатор. Живой
эпизод может быть только один; закрытые остаются строками той же таблицы.

**Эпизод принадлежит сделке, а не траншу.** В нетто-режиме биржевая
позиция одна на инструмент, поэтому потраншевого эпизода не существует:
экспозиция транша — производная его собственных заявок
(`docs/models/domain/aggregate/DealTranche.md`), а сумма этих экспозиций
сверяется с размером эпизода.

`Position` **не отвечает** за итоговый результат сделки (число живёт на
сделке, здесь — биржевой факт, из которого оно считается), историю
команд и действий, сырые ответы биржи.

## Структура

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `Long` | Внутренний идентификатор. |
| `dealId` | `Long` | Сделка. |
| `externalId` | `String` | Биржевой идентификатор позиции. Не стабильный клиентский идентификатор и не вечен: биржа может очистить его после закрытия. |
| `status` | `Status` | Доменный статус. |
| `closeReason` | `CloseReason` | Причина закрытия либо проблемного состояния. |
| `direction` | `Direction` | Доменное направление. |
| `externalSize` | `BigDecimal` | Размер по данным биржи, нормализованный абсолют, **в контрактах** — та же единица, что у заявок: предикат покрытия сравнивает их напрямую. |
| `externalAverageEntryPrice` | `BigDecimal` | Средняя цена входа. Пишет только live-нога рефреша. |
| `externalMarkPrice` | `BigDecimal` | Марк-цена. |
| `externalLiquidationPrice` | `BigDecimal` | Расчётная цена ликвидации. |
| `externalMargin` | `BigDecimal` | Маржа позиции. |
| `externalUnrealizedProfit` | `BigDecimal` | Нереализованный результат. |
| `externalRealizedProfit` | `BigDecimal` | **Положение закрытия:** готовый net закрытой позиции, посчитанный биржей. Пусто, пока позиция жива или запись не добыта. |
| `externalResultCurrency` | `String` | **Положение закрытия:** валюта этого числа. **Проверяемый признак, не источник** валюты результата сделки. |
| `externalCloseAveragePrice` | `BigDecimal` | **Положение закрытия:** средняя цена фактического выхода. Потребитель — калибровка запаса на проскок на тропе встроенной защиты. |
| `externalCloseType` | `String` | **Положение закрытия:** сырой тип последнего закрытия источника. Операнд торгового исхода сделки. |
| `externalRealizedProfitGross` | `BigDecimal` | **Положение закрытия:** результат до издержек. Потребитель — первая пара сверки разбивки. |
| `externalFee` | `BigDecimal` | **Положение закрытия:** знаковая комиссионная компонента, **сырой знак**. Потребитель — вторая пара сверки разбивки. |
| `externalFundingCost` | `BigDecimal` | **Положение закрытия:** накопленное финансирование эпизода, **знак нормализован** — издержка положительна. Потребители — третья пара сверки и де-микширование R-мультипликатора. |
| `externalLiquidationPenalty` | `BigDecimal` | **Положение закрытия:** штраф ликвидации, **сырой знак**. Потребитель — четвёртая пара сверки разбивки. |

Поля положения закрытия пишет **вторая нога рефреша позиции**, не
финализация; наследуемое время изменения принимает время записи
закрытия, и той же транзакцией нога двигает верхнюю границу окна
линковки движений.

Состав ограничен полями с **названным потребителем**.

## Инварианты

- Позиция принадлежит сделке; **живая — максимум одна**, закрытые
  эпизоды остаются.
- **Эпизоды различаются биржевым идентификатором.** Пара «сделка,
  биржевой идентификатор» уникальна: наблюдение того же идентификатора
  обновляет свою строку, нового — заводит новую и закрывает предыдущую.
- Позиция **не хранит** инструмент, биржу, внутренний идентификатор и
  ссылок на действие стратегии: это приходит контекстом прохода.
- Позиция создаётся и обновляется **только рефрешем позиции** (обеими
  ногами); FSM её не создаёт и полей не заполняет.

**Адресация записи истории не ключуется биржевым идентификатором.**
Когда он не наблюдался — позиция открылась и закрылась между тиками —
запись адресуется инструментом и **временным окном от времени создания
первой отправленной входной заявки**; однозначность держит инвариант
«одна активная сделка на инструмент».

**Несколько записей в окне — это несколько эпизодов одной сделки**, а не
неразобранная развилка: каждая материализуется своей строкой.

**Известное ограничение:** у позиции, возникшей вокруг чужого риска,
отправленной входной заявки нет, значит нет и операнда нижней границы —
адресация на этой подтропе не определена. Второго механизма не вводится.

## Енумы

**`Direction`** — `LONG` / `SHORT`. Нетто-режим направлением не
является: это режим позиции на бирже, а не направление рыночного риска;
для нетто-режима направление выводится из знака размера.

**`Status`** — `ACTIVE`, `CLOSED`, `ERROR`. Промежуточных состояний нет:
позиция не создаётся локально до биржи, а частичное уменьшение — это
активная позиция с обновлённым размером.

**`CloseReason`** — `CLOSED_BY_STRATEGY`, `KILL_SWITCH`, `MANUAL_CLOSE`,
`EXTERNAL_CLOSE` (закрылась на стороне биржи без нашего действия),
`UNKNOWN_EXTERNAL_STATUS`, `EXCHANGE_INVARIANT_VIOLATION`, `UNKNOWN`.

## Живой риск

```text
живой риск ⟺ status = ACTIVE и externalSize > 0
```

Нулевой размер при активном статусе означает, что биржевая запись есть, а
живого риска нет.

## Персистентность

Таблица `positions`, наследует поля аудита. `NOT NULL`: `deal_id`,
`status`, `direction`. Уникальна пара «сделка, биржевой идентификатор».
Прежнего ключа «одна позиция на сделку» нет — он запрещал бы второй
эпизод.

**Четыре колонки положения закрытия** — `external_realized_profit_gross`,
`external_fee`, `external_funding_cost`,
`external_liquidation_penalty` — nullable: они пусты, пока эпизод жив
либо запись закрытия не добыта. Пустота здесь **значащая**: она делает
результат сделки недоступным, а не заниженным
(`docs/rules/pnl-reconciliation.md`).

**Носитель предиката «запись закрытия эпизода добыта» — непустота
`externalRealizedProfit`.** Предикат один на весь корпус и зовётся везде
`closeRecordFetched` (`docs/spec/deal-result.json`); отдельной
колонки-признака под него нет — валидация границы записи закрытия
принимает комплект целиком (`docs/models/mapping/PositionCloseResult.md`
§«Структурная валидация — до маппинга»), поэтому непустота любого поля
комплекта равносильна непустоте всех. **Зависимость названа именно
поэтому:** если хоть одно поле комплекта станет опциональным, предикат
обязан переехать на явный признак, а не разъехаться молча. Писатель — вторая нога рефреша позиции
(§Структура выше).

Денежные величины — `numeric(36,18)`, строковые и енум-колонки —
`varchar(64)`.

# ExchangeAccount

## На какой вопрос отвечает этот файл

Что это за сущность `ExchangeAccount`.

## Назначение

`ExchangeAccount` — **биржевой счёт тенанта**: тенант × площадка × метка.
На нём живёт всё, что сегодняшняя модель `Exchange` совмещала со
площадкой, — база риска, серия убытков, ступень холда
(`docs/architecture/tenant-and-exchange.md` §«Что переезжает на счёт
тенанта»).

Форму несёт `domain-model`. **Писателей два, и они пишут разные наборы
полей:** реестр, контур и ключи — `auth`; торговое состояние —
`trading-core`. Физически это две таблицы в двух базах с общим
`internalId`, поэтому правило «у таблицы один писатель» соблюдено
(`docs/architecture/data-ownership.md`).

## Структура — реестровая часть (писатель `auth`)

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `Long` | Внутренний идентификатор. Границу сервиса не пересекает. |
| `internalId` | `String` | Идентичность счёта наружу и между сервисами. **Из неё выводится путь ключей в Vault** (`docs/architecture/platform.md` §Безопасность). Присваивается при регистрации, неизменяема. |
| `tenantId` | `String` | `internalId` тенанта-владельца. |
| `exchangeCode` | `String` | Код площадки (`Exchange.code`). |
| `label` | `String` | Метка счёта, видимая человеку: у тенанта на одной площадке счетов может быть несколько. |
| `contour` | `Contour` | **Контур площадки — боевой или демо.** Лежит рядом с ключами, потому что ключ и контур суть одна истина. Допустимость проверяется при регистрации по величине `contourAdmitted` (`docs/spec/environment-contour.json`, дом правила — `docs/architecture/platform.md` §«Чем различаются окружения»). |
| `status` | `Status` | Состояние счёта. |

Ключей в этой таблице нет ни в каком виде: они в Vault по пути,
выводимому из `internalId` (`tenant-and-exchange.md` §Ключи).

## Структура — торговое состояние (писатель `trading-core`)

| Поле | Тип | Назначение |
|---|---|---|
| `riskBase` | `BigDecimal` | База риска счёта. Операнд всех четырёх потолков через снимок на сделке. Пусто ⇒ risk-creating действие отвергается (`docs/rules/risk-policy.md`). |
| `riskBaseCurrency` | `String` | Валюта базы; источник — расчётная валюта инструмента. |
| `consecutiveLossCount` | `Integer` | Длина текущей серии подряд убыточных закрытых сделок; операнд остановки (`docs/rules/loss-streak-halt.md`). |
| `blindPassCount` | `Integer` | Подряд идущие ненаблюдённые проходы проактивной детекции; операнд предела слепоты. |
| `holdRung` | `Status` | Ступень биржевой лестницы, поднятая на **этом счёте** (`docs/rules/exchange-hold.md`). |

Плюс поля аудита у обеих частей
(`docs/models/domain/other/Auditable.md`).

**Радиус реакции стал радиусом счёта.** Ступень лестницы, поднятая у
одного тенанта, других не трогает — это и есть смысл переезда состояния
с площадки на счёт (`tenant-and-exchange.md`).

## Енум `Contour`

| Значение | Что означает |
|---|---|
| `LIVE` | Боевая площадка: сделки двигают капитал владельца. |
| `DEMO` | Демо-контур площадки: сделки капитала не двигают. |

Перечень закрыт: третьего контура у площадки не бывает — либо деньги
настоящие, либо нет. Значение неизменяемо после регистрации: сменить
контур означает завести другой счёт, потому что и ключи у него другие
(`tenant-and-exchange.md` §Ключи).

## Енум `Status`

| Значение | Что означает |
|---|---|
| `ACTIVE` | Счёт торгует. |
| `HOLD` | Мягкий холд: счёт выпадает из выборки сканера входа, новые сделки не создаются; живые сопровождаются полностью. |
| `TRADE_BLOCKED` | Сворачивание: снятие живого риска по счёту, каскад активных сделок в ошибку, блок торговых команд. |
| `CLOSED` | Счёт отключён владельцем; ключи отозваны. |

`HOLD` и `TRADE_BLOCKED` — ступени лестницы реакций; их семантика,
условия входа и снятия живут в `docs/rules/exchange-hold.md`, здесь не
пересказываются.

## Персистентность

Две таблицы, по одной у каждого писателя
(`docs/architecture/data-ownership.md`):

- `auth`, таблица `exchange_accounts` — реестровая часть. `internal_id`
  `NOT NULL` `UNIQUE`; `tenant_id`, `exchange_code`, `contour`, `status`
  — `NOT NULL`; уникальность `(tenant_id, exchange_code, label)`;
- `trading_core`, таблица `exchange_account_states` — торговое состояние.
  Ключ — `internal_id` счёта (`NOT NULL` `UNIQUE`), поля счётчиков
  `NOT NULL` со стартовым значением, назначаемым писателем заведения;
  `risk_base` и `risk_base_currency` — nullable, и пустота означает отказ
  risk-creating действия, а не ноль.

Схемы заводятся шагами 4 (`auth`) и 7 (`trading-core`) фазы 2; здесь —
форма.

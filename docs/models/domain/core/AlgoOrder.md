# AlgoOrder

## На какой вопрос отвечает этот файл

Что это за сущность `AlgoOrder` — отдельная условная заявка транша.

## Назначение

`AlgoOrder` — условная заявка, связанная с траншем сделки: отдельный
стоп, тейк, их комбинация, трейлинг, частичный выход.

**Входа среди применений нет:** все типы условия — защитные либо
закрывающие. Появление входного типа условия переоткрыло бы состав
таблиц планового риска: сегодня они живут только у обычных заявок.

`AlgoOrder` **не является действием стратегии**: связь «действие —
runtime-сущность» вместе с ролью и уровнем живёт в строке исполнения
(`docs/models/domain/other/DealActionState.md`), а доля закрытия,
объявленная стратегией, — на самом действии
(`docs/models/domain/aggregate/Strategy.md`).

**Ссылки на ногу входа у неё нет — связь только со сделкой.** Отсюда
отдельная условная заявка **не может** быть носителем уровня стопа
конкретной ноги: «защита той же ноги» ею не адресуема. Поэтому форма
защиты доборной ноги сужена до её собственной встроенной защиты.

## Структура

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `Long` | Внутренний идентификатор. |
| `dealId` | `Long` | Сделка-агрегат. |
| `dealTrancheId` | `Long` | **Транш, которому принадлежит условная заявка.** Защита транша — его собственная: покрытие считается по своим, а не по всем защитам сделки. Пишет создатель условной заявки — из действия, чьё исполнение её породило (`docs/components/CreateAlgoOrderExecutor.md`), симметрично обычной заявке. |
| `internalId` | `String` | Стабильный клиентский идентификатор. |
| `externalId` | `String` | Биржевой идентификатор. |
| `status` | `Status` | Доменный статус. |
| `closeReason` | `CloseReason` | Причина финализации. |
| `conditionType` | `ConditionType` | Денормализованная проекция типа условия; обязана совпадать с условием. |
| `condition` | `Condition` | Условие срабатывания (JSONB): триггер либо трейлинг. |
| `size` | `BigDecimal` | Рассчитанный размер в контрактах. |
| `direction` | `Direction` | Сторона заявки. |
| `positionReducingOnly` | `Boolean` | Доменное намерение «только уменьшать позицию». |
| `replacesInternalId` | `String` | Предшественник в цепочке замещений. |
| `externalStatus` | `String` | Сырой статус биржи — диагностика. |
| `externalLive` | `Boolean` | **Наблюдённая живость на площадке** — что показала последняя добыча: живой статус — истина; терминальный статус, в том числе известное слово отказа, либо полный цикл без записи — ложь; статус не разобран либо наблюдения не было — пусто; добыча, чьё эхо разошлось с нашей строкой, его не пишет (`docs/lifecycles/AlgoOrder.md`). Читается только у заявки в `ERROR`: у прочих живость несёт статус (`docs/lifecycles/AlgoOrder.md`). Писатель — добыча условной заявки (`docs/components/RefreshAlgoOrderExecutor.md`). |
| `failCode` | `String` | Код отказа биржи. |
| `externalSize` | `BigDecimal` | **Фактический размер срабатывания**, не исходный размер. |
| `externalPrice` | `BigDecimal` | **Фактическая цена срабатывания.** У живой трейлинговой защиты пусто; после срабатывания несёт цену исполнения, а не уровень стопа. |
| `externalTriggerTime` | `Instant` | Время срабатывания. |
| `linkedOrderExternalIds` | `List<String>` | Связанные идентификаторы обычных заявок — внешний факт, runtime на него не опирается. |

**Доменные методы:** `isLive`; **`mayBeLive`** — живость на площадке не исключена: живые по статусу, включая `CREATED`, плюс заявка в `ERROR` без наблюдённой нежилости, читают только аварийные тропы (`docs/lifecycles/AlgoOrder.md`; форма — `docs/spec/algo-order-lifecycle.json` §`algoMayBeLive`); **`isExchangeLive`** — `PENDING`,
`ACTIVE`, `PARTIALLY_COMPLETED`: предикат «заявка стоит на бирже», по нему
считается покрытие. `CREATED` исключён — подтверждения нет; частично
сработавшая включена — она жива и покрывает остаток. Смысл тот же, что у
предиката встроенной защиты `isActiveLike`, но **набор статусов другой**:
у встроенной их два, состояния «частично сработала» у неё нет.

Писателей наблюдённой живости у модели два, и зовёт их добыча условной
заявки: **`observeOnVenue(found)`** — по итогу полного цикла (найдена
живой — истина; терминальной либо не найдена — ложь) и
**`observeRefusedStatus(reason)`** — по отказу разбора статуса (известное
слово отказа — ложь; слово, которого словарь не знает, либо отказ без
причины — пусто).

Плюс переходы состояний через строгую матрицу и проверка совпадения
проекции типа условия с самим условием.

## Енумы

**`Direction`** — `BUY`, `SELL`.

**`Status`** — `CREATED`, `PENDING`, `ACTIVE`, `PARTIALLY_COMPLETED`,
`COMPLETED`, `CANCELED`, `ERROR`.

**`CloseReason`** — у каждого значения назван производитель
(`docs/rules/writer-named-for-every-value.md`):

| Значение | Кто производит |
|---|---|
| `TRIGGERED` | резолвер внешнего статуса на сработавшей условной заявке (`docs/rules/external-status-resolution.md`) |
| `CANCELED_BY_STRATEGY` | исполнитель отмены условной заявки по объявленному действию |
| `REPLACED_BY_STRATEGY` | исполнитель замещения — на снимаемом звене цепочки (`docs/rules/replace-not-amend.md`) |
| `KILL_SWITCH` | исполнитель снятия живого риска (`docs/components/KillSwitchExecutor.md`) |
| `MISSING_AFTER_REFRESH` | исполнитель добычи условной заявки, исчерпавший цикл источников у **отправленной** заявки |
| `NOT_PLACED` | он же у **неотправленной**: до площадки она не дошла — терминал штатный, без биржевой ступени (`docs/lifecycles/AlgoOrder.md`) |
| `ORDER_FAILED` | резолвер внешнего статуса: биржа отвергла постановку целиком |
| `PARTIALLY_FAILED` | он же: часть пакета встала, часть отвергнута |
| `UNKNOWN_EXTERNAL_STATUS` | резолвер внешнего статуса, ветвь `REFUSED` в `docs/spec/external-status-resolution.json` |
| `UNKNOWN` | умолчание разбора |

`MANUAL_CANCEL` снят — `docs/rules/manual-halt.md`.

**`ConditionType`** — `STOP_LOSS`, `PARTIAL_STOP_LOSS`, `TAKE_PROFIT`,
`PARTIAL_TAKE_PROFIT`, `OCO_FULL`, `TRAILING_PERCENTS`,
`TRAILING_VALUE`.

**`TRAILING_VALUE` сегодня не производится:** настройки трейлинга
стратегии несут только процентный откат, и тип «трейлинг абсолютным
значением» создание стратегии отвергает (`docs/rules/strategy-validation.md`).

Какие из них считаются защитой — не свойство типа, а свойство заявки:
`docs/rules/live-risk-protection.md`.

**`TriggerPriceType`** — `LAST`, `INDEX`, `MARK`. Ценовая база триггера
объявляется стратегией и доезжает до биржи.

**Защита срабатывает только по `MARK`.** Условная заявка, которую
стратегия объявила защитой, и встроенная защита входа обязаны нести
`MARK`; `LAST` и `INDEX` у них отвергаются на создании стратегии реджектом
`STRATEGY_TRIGGER_PRICE_TYPE_NOT_MARK`
(`docs/rules/strategy-validation.md`). Базу, которую площадка применила,
подтверждает эхо чтения: сверка у отдельной условной заявки —
`docs/models/mapping/AlgoOrder.md`, у встроенной защиты —
`docs/models/mapping/Order.md`.

**Пустая база защиты — `MARK`, а не молчание.** Умолчание к безопасной
стороне, названное (`docs/rules/absent-value-semantics.md`): пустое поле
доехало бы до площадки молчанием, которое та читает последней ценой.
Писатель — создатель определения, до первой записи
(`Strategy#applyProtectiveTriggerDefaults`), поэтому база явна на всех
носителях: в строке определения, в снимке события активации и в копии
ядра. Отказ создания на пустой базе отвергнут — он ломал бы определения,
где база не названа по незнанию, а не по выбору.

**Трейлинг ограничение не исполняет, и это ограничение площадки.** У
постановки трейлинга (`move_order_stop`,
`docs/integrations/okx/contracts/algo-order.md`) поля базы нет:
активация и откат считаются по `last`. Объявленная у трейлинга база до
площадки не доезжает, умолчания `MARK` он не получает — записанное в
определение, оно объявляло бы срабатывание, которого нет. Реджект `LAST`
и `INDEX` у трейлинга остаётся: объявление, противоречащее правилу
защиты, отвергается независимо от того, исполнила бы его площадка.

Довод: ликвидацию биржа считает по марк-цене, а last-цену на тонком
рынке двигают единичной сделкой. Стоп по `LAST` можно снять
манипуляцией, не сдвинув марк, — и тогда защита срабатывает там, где
ликвидационный контур ещё не считает движение состоявшимся; обратный
случай хуже: марк уходит к ликвидации, а `LAST`-триггер молчит.
Ограничение — консервативная сторона: оно сужает объявимое, а не
расширяет.

**Ограничение снимается по измеренному базису**, не по умозрению: пока
расхождение `mark` и `last` не измерено на живых данных, запас на базис
назначить нечем, и сужение остаётся.

**Цена входа и уровень защиты этим не ограничены:** свобода источника
цены для входного расчёта и для объявленного уровня остаётся — правило
касается **базы срабатывания** триггера, а не того, откуда взято число
уровня.

## Условие срабатывания

`Condition` — JSONB на строке: тип плюс параметры триггера либо
трейлинга.

- **триггерная ветка** несёт уровни стопа и тейка;
- **трейлинговая ветка** несёт цену активации, отступ и **наблюдаемый
  уровень** — он появляется **при наблюдении**, после активации. Писатель
  — добыча условной заявки; это единственное поле условия, которое эхо
  переносит на строку (`docs/models/mapping/AlgoOrder.md`).

Отсюда трейлинг с непройденной ценой активации уровня остановки убытка
не несёт и защитой не считается.

## Плановый риск здесь не живёт

Плановый риск и его операнды — атрибуты **ноги входа**, а входной тропы
условной заявкой не существует. Соответствующих колонок у таблицы нет:
это была бы мёртвая четвёрка с живым именем, читающаяся как «тропа
есть».

Уровень стопа ноги финализация резолвит с persisted-числа самой ноги, а
не через её встроенную защиту: число write-once, поэтому уровень
остаётся резолвимым и после снятия защиты.

## Персистентность

Таблица `algo_orders`, наследует поля аудита.

**`NOT NULL`:** `deal_id` (FK), `deal_tranche_id` (FK), `internal_id`
(уникален), `status`, `condition_type`.

**Nullable:** `external_id`, `close_reason`, `size`, `direction`,
`position_reducing_only`, `replaces_internal_id`, `external_status`,
`external_live` (`boolean`; пусто значаще — «не наблюдалась»), `fail_code`, `external_size`, `external_price`,
`external_trigger_time`.

`condition` — JSONB-навес на строке; поля аудита навеса — колонки
строки-владельца (`docs/models/domain/other/Auditable.md`).
`linked_order_external_ids` — тоже навес: внешний факт, на который
runtime не опирается, отдельной таблицы связей под него не заводится.

Денежные величины — `numeric(36,18)`, строковые и енум-колонки —
`varchar(64)`. Енумы хранятся именем значения.

**Транш обязателен наравне со сделкой:** покрытие считается потраншево
(`docs/rules/live-risk-protection.md`), и защита без транша не
атрибутируема — то есть не участвует в инварианте покрытия, оставаясь
при этом живым риском.


## Биржевое имя инструмента — атрибут границы, не поле строки

Счёт-широкие чтения площадки возвращают строки по **разным**
инструментам, и без биржевого имени читатель не может отнести строку к
инструменту вовсе. Поэтому модель несёт `externalInstrumentId` —
**атрибут границы**: его заполняет коннектор при маппинге **каждого**
ответа площадки, на любой тропе чтения, а не только на счёт-широкой.
Нужен он счёт-широкой; у строки, приехавшей чтением одного инструмента,
он повторяет имя из запроса. Пусто поле у строки, которая границы не
пересекала, — у нашей, прочитанной из базы.

**Колонки под него нет и не заводится.** У наших собственных строк связь с
инструментом идёт через сделку; поле, приземлённое в схему, стало бы
вторым носителем той же связи и разошлось бы с первым.

**Резолв имени в наш числовой идентификатор на границе запрещён:** он
погасил бы детектор чужого риска, чей признак — отсутствие локальной
строки (`docs/components/AnomalyJob.md`).

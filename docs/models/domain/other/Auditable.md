# Auditable

## На какой вопрос отвечает этот файл

Какие общие поля аудита несут доменные сущности.

## Назначение

`Auditable` — базовый класс полей аудита. Наследуют его доменные модели
**со своей строкой**. У модели, хранимой JSONB-навесом, своей строки нет,
и поля аудита у неё — колонки строки-владельца; наследником она не
является.

## Структура

| Поле | Тип | Назначение |
|---|---|---|
| `createdAt` | `OffsetDateTime` | Время создания записи в системе. |
| `createdBy` | `String` | Кто создал запись. |
| `modifiedAt` | `OffsetDateTime` | Время последнего изменения в системе. |
| `modifiedBy` | `String` | Кто изменил последним. |
| `externalCreatedAt` | `OffsetDateTime` | Время создания записи на стороне биржи. |
| `externalModifiedAt` | `OffsetDateTime` | Время последнего обновления на бирже. |

**Системные поля проставляет persistence-слой; биржевые заполняет код,
производящий данные, из таймстампов источника.** Это разделение двух
временных доменов; правило их сравнения — `docs/rules/time-utc.md`.

## У локального события биржевой момент тоже существует

Когда у события нет метки источника, потому что событие **наше**,
биржевое поле принимает **серверное время источника**, а не системные
часы.

Поле означает «момент в биржевом домене», а не «момент, о котором
сообщила биржа». Подставить сюда системные часы запрещено классом.

Экземпляр — момент создания сделки: он служит нижней границей окна
линковки движений, когда собственной границы у сделки ещё нет.

## Правило состава колонок

**Набор бинарен: либо все шесть колонок, либо ни одной.** Частичных
наборов не вводится.

Названная цена: у наследника без события источника два биржевых поля
останутся пустыми навсегда. Это дешевле, чем исключение из бинарного
правила.

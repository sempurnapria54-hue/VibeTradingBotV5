# AnomalyReport

## На какой вопрос отвечает этот файл

Что это за модель `AnomalyReport`.

## Назначение

`AnomalyReport` — журналируемый объект расследования: фиксация,
сопровождение и аудит аномалии, обнаруженной при сравнении локального
состояния с фактическим состоянием на бирже.

Это **носитель наблюдаемости** (`docs/concept.md`, П3): персистентная
запись, по которой восстанавливается причина сработавшей защиты.

Отчёт не валидатор и не команда.

## Структура

| Поле | Тип | Обязательно | Назначение |
|---|---|---|---|
| `id` | `Long` | да | Внутренний идентификатор. |
| `internalId` | `String` | да | Внешний идентификатор отчёта. |
| `exchangeId` | `Long` | да | Биржа. |
| `instrumentId` | `Long` | нет | Инструмент; пусто, если однозначно не определён. |
| `subjectExternalId` | `String` | нет | **Сущность-предмет** — четвёртая величина ключа дедупа у отчёта БЕЗ блокировки. Пусто у отчёта с блокировкой: его состояние есть стоящая ступень объекта радиуса. |
| `scope` | `HoldScope` | да | **Радиус** инцидента: инструмент либо биржа. Снимает неоднозначность пустого инструмента. |
| `status` | `Status` | да | Статус обработки. |
| `severity` | `Severity` | да | Критичность. |
| `kind` | `Kind` | да | **Природа факта**: состояние либо событие. Дискриминатор идемпотентности. |
| `code` | `String` | да | Машинно-читаемый код аномалии. Значение приходит от тропы-производителя; закрытого реестра кодов нет, дом каждого значения — дом его тропы (`docs/components/models/HoldSignal.md`, дом конвенции о домах значений). |
| `message` | `String` | нет | Текст непредвиденной ошибки обработки. |
| `internalBefore`, `externalBefore` | JSONB | нет | Снимки локального и внешнего состояния до обработки. |
| `internalAfter`, `externalAfter` | JSONB | нет | Снимки после обработки. |

## Енумы

**`Status`** — `CREATED`, `IN_PROGRESS`, `KILL_SWITCH_EXECUTED`,
`COMPLETED`, `ERROR`.

**`Severity`** отвечает ровно на один вопрос — **критична аномалия или
нет**. Силу реакции холда она не выражает: это отдельная ось на стороне
холда.

| Значение | Что означает |
|---|---|
| `CRITICAL` | гоняется kill-switch; отчёт терминализуется только по подтверждённому снятию риска |
| `NON_CRITICAL` | kill-switch не гоняется, процесс завершается штатно |

**«Холд до ручного разбора» не тождественен kill-switch:** мягкий запрет
входов — тоже холд с ручным снятием, но его отчёт некритичен, потому что
kill-switch в составе реакции нет. Блокировку задаёт **состав реакции**, а
не критичность. То же на биржевом радиусе: мягкая ступень некритична,
ступень со сворачиванием — критична.

**`Kind` — природа факта, отдельная ось от критичности.** Критичность
отвечает на «гоняется ли kill-switch», природа — на «один отчёт **на
что**».

| Значение | Что означает | Дедуп |
|---|---|---|
| `STATE` | факт есть **состояние scope**, держащееся во времени | применяется: пока состояние **держится на объекте радиуса**, второй отчёт по тому же ключу не заводится (ключ — ниже) |
| `EVENT` | факт есть **отдельное происшествие**, привязанное к своему моменту | не применяется: каждое событие — своя строка |

**Операнд дедупа `STATE` — стоящее состояние объекта, а не статус
отчёта.** Спрашивать «есть ли **незавершённый** отчёт» нельзя: журнальная
тропа создаёт отчёт сразу завершённым
(`docs/lifecycles/AnomalyReport.md`), поэтому
множество незавершённых пусто **по построению** и такой дедуп не
срабатывал бы никогда. Тем же доводом ниже объяснено, почему не годится
общий анкер, — и прежняя редакция не применяла его к собственному ключу.
Дом правила — `docs/rules/error-handling-policy.md`.

**Привязка к сделке — типичный признак `EVENT`, а не обязательный.**
Несущий признак один — **свой момент** против держащегося состояния.
Происшествия без сделки существуют штатно: снятие safety-ступени
держателем привязано к моменту, а не к сделке
(`docs/rules/manual-halt.md`), и `EVENT` для него — не натяжка.

**Ключ дедупа у `STATE`** — тройка «**объект радиуса** + `code` +
`severity`»:

- **объект радиуса**, а не радиус вообще: групповых значений у радиуса
  нет, состояние держится на конкретной бирже или
  инструменте;
- **`code`** — иначе ручная остановка схлопнулась бы с автоматической,
  стоящей на том же объекте, и различимость, ради которой коды заведены,
  пропала бы ровно в том случае, ради которого нужна;
- **`severity`** — она несёт **состав реакции** (критична аномалия или
  нет, а состав задаёт блокировку), поэтому
  эскалация мягкой ступени в полную — **другое состояние**, а не повтор
  того же: её строка заводится, и запуск kill-switch виден в журнале.

Это не противоречит «ключ по коду тоже не спасает» ниже: там речь о
`EVENT`-отчётах **по разным сделкам** одного инструмента, у которых
дискриминатором служит сделка; у `STATE`-факта сделки нет по природе, и
дедуп ведётся по состоянию объекта.

**У отчёта без блокировки в ключ входит четвёртая величина — сущность,
о которой он.** Тройка выше предполагает, что состояние держится **на
объекте радиуса**; у отчёта, за которым блокировки нет вовсе
(журнальная тропа, `HoldSignal` фабрик `instrumentJournal` /
`exchangeJournal`), состояние держится на **сущности-предмете** — заявке,
позиции, algo-заявке, — а инструмент в этот момент ни в какой ступени не
стои́т. Ключ поэтому четвёрка: «объект радиуса + сущность-предмет +
`code` + `severity`». Без сущности в ключе два разных расхождения учёта
по одному инструменту схлопнулись бы в одну строку — тот же дефект, ради
которого в ключ введён `code`, только уровнем ниже.

**Тропа-производитель этого класса названа:** проактивная детекция,
детектор `A8` — локально терминальная сущность, живая на бирже
(`docs/components/AnomalyJob.md` §«Что ищет»). Отчёт с блокировкой
четвёртой величины не несёт: у него состояние и есть стоящая ступень
объекта радиуса.

**Почему природа, а не код, служит дискриминатором.** «Один на факт» у
холда означает «один на состояние», у журнала — «один на событие»; одним
механизмом это не выражается. Общий анкер по радиусу и критичности
сталкивался бы с жизненным циклом: журнальная тропа завершается сразу,
поэтому охраняемое множество незакрытых пусто, и анкер не срабатывал бы
никогда. Ключ по коду тоже не спасает: отчёты по разным сделкам одного
инструмента с одинаковым кодом схлопнулись бы.

**Торговое следствие — счётность неизвестных исходов.** Невключение
неисчислимого результата в расчёт ожидаемости корректно **только если
число таких случаев известно**. При схлопывании маркеров оно
систематически занижено, причём тем сильнее, чем чаще отказ, — дефект
скрывал бы сам себя.

## Инварианты

- **Групповой радиус выражается набором строк** — по отчёту на каждый
  затронутый инструмент: группового значения у радиуса нет. **Биржевой
  радиус сюда не относится** — у него своё значение `scope = EXCHANGE` и
  одна строка по объекту-бирже (`docs/rules/error-handling-policy.md`
  §«Радиус ущерба задаёт scope»).
- **Отчёт принадлежит тропе, а не классу реакции**
  (`docs/rules/error-handling-policy.md`): производителем может быть и
  детектор, и сама тропа — у ручного вызова детектора нет по
  построению, — и не всякая мягкая реакция отчёт производит.

## Персистентность

Таблица `anomaly_reports`, наследует поля аудита. Снимки состояния —
JSONB-колонки. Строковые и енум-колонки — `varchar(64)`.

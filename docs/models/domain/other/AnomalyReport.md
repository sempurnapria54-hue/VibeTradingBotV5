# AnomalyReport

## На какой вопрос отвечает этот файл

Что это за модель `AnomalyReport`.

## Назначение

`AnomalyReport` — журналируемый объект расследования: фиксация,
сопровождение и аудит аномалии, обнаруженной при сравнении локального
состояния с фактическим состоянием на бирже.

Это **носитель наблюдаемости** (`docs/concept.md`, П3): персистентная
запись, по которой восстанавливается причина сработавшей защиты.

Отчёт не валидатор и не команда.

## Структура

| Поле | Тип | Обязательно | Назначение |
|---|---|---|---|
| `id` | `Long` | да | Внутренний идентификатор. |
| `internalId` | `String` | да | Внешний идентификатор отчёта. |
| `exchangeId` | `Long` | да | Биржа. |
| `instrumentId` | `Long` | нет | Инструмент; пусто, если однозначно не определён. |
| `scope` | `HoldScope` | да | **Радиус** инцидента: инструмент либо биржа. Снимает неоднозначность пустого инструмента. |
| `status` | `Status` | да | Статус обработки. |
| `severity` | `Severity` | да | Критичность. |
| `kind` | `Kind` | да | **Природа факта**: состояние либо событие. Дискриминатор идемпотентности. |
| `code` | `String` | да | Машинно-читаемый код аномалии. |
| `message` | `String` | нет | Текст непредвиденной ошибки обработки. |
| `internalBefore`, `externalBefore` | JSONB | нет | Снимки локального и внешнего состояния до обработки. |
| `internalAfter`, `externalAfter` | JSONB | нет | Снимки после обработки. |

## Енумы

**`Status`** — `CREATED`, `IN_PROGRESS`, `KILL_SWITCH_EXECUTED`,
`COMPLETED`, `ERROR`.

**`Severity`** отвечает ровно на один вопрос — **критична аномалия или
нет**. Силу реакции холда она не выражает: это отдельная ось на стороне
холда.

| Значение | Что означает |
|---|---|
| `CRITICAL` | гоняется kill-switch; отчёт терминализуется только по подтверждённому снятию риска |
| `NON_CRITICAL` | kill-switch не гоняется, процесс завершается штатно |

**«Холд до ручного разбора» не тождественен kill-switch:** мягкий запрет
входов — тоже холд с ручным снятием, но его отчёт некритичен, потому что
kill-switch в составе реакции нет. Блокировку задаёт **состав реакции**, а
не критичность. То же на биржевом радиусе: мягкая ступень некритична,
ступень со сворачиванием — критична.

**`Kind` — природа факта, отдельная ось от критичности.** Критичность
отвечает на «гоняется ли kill-switch», природа — на «один отчёт **на
что**».

| Значение | Что означает | Поиск незавершённого |
|---|---|---|
| `STATE` | факт есть **состояние scope**, держащееся во времени | применяется: пока состояние держится, второй отчёт по тому же ключу не заводится |
| `EVENT` | факт есть **отдельное происшествие**, привязанное к своему моменту и своей сделке | не применяется: каждое событие — своя строка |

**Почему природа, а не код, служит дискриминатором.** «Один на факт» у
холда означает «один на состояние», у журнала — «один на событие»; одним
механизмом это не выражается. Общий анкер по радиусу и критичности
сталкивался бы с жизненным циклом: журнальная тропа завершается сразу,
поэтому охраняемое множество незакрытых пусто, и анкер не срабатывал бы
никогда. Ключ по коду тоже не спасает: отчёты по разным сделкам одного
инструмента с одинаковым кодом схлопнулись бы.

**Торговое следствие — счётность неизвестных исходов.** Невключение
неисчислимого результата в расчёт ожидаемости корректно **только если
число таких случаев известно**. При схлопывании маркеров оно
систематически занижено, причём тем сильнее, чем чаще отказ, — дефект
скрывал бы сам себя.

## Инварианты

- **Радиус шире инструмента выражается набором строк** — по отчёту на
  каждый затронутый инструмент, — а не отдельным значением радиуса.
  Группового значения у радиуса нет.
- **Отчёт принадлежит тропе, а не классу реакции**
  (`docs/rules/error-handling-policy.md`): его заводит детектор, и не
  всякая мягкая реакция отчёт производит.

## Персистентность

Таблица `anomaly_reports`, наследует поля аудита. Снимки состояния —
JSONB-колонки. Строковые и енум-колонки — `varchar(64)`.

# DealCashFlow

## На какой вопрос отвечает этот файл

Что это за модель `DealCashFlow`: структура, енум `CashFlowCategory`,
персистентность, линковка к `Deal`.

## Назначение

`DealCashFlow` — **persisted** доменная модель `other`: журнал одного
денежного движения по аккаунту, отнесённого к сделке. Носитель
**категорийной разбивки** результата сделки (торговая комиссия / funding /
rebate / ликвидационный штраф / реализованный pnl / прочее) — из bills
(`GET /api/v5/account/bills[-archive]`, доменно наполняется командой
`REFRESH_BILLS_COMMAND`).

Число `resultProfit` — **не отсюда**: заголовочное число берётся готовым
**net'ом** из positions-history (`realizedPnl`), не из `sum(bills)`
(`docs/decisions/result-profit-source.md`). Роль `DealCashFlow` —
**разбивка** (категорийная атрибуция: сколько комиссии vs funding vs штраф)
плюс **независимая сверка** суммы flows с net из positions-history (контроль
целостности). Механика финализации, сверка и cross-ccy —
`docs/decisions/pnl-finalization-mechanics.md` (реш.1 `REFRESH_BILLS_COMMAND`, реш.5
сверка/cross-ccy, «Носители»).

Не торговая бизнес-сущность (бизнес-циклом сделки владеет `Deal`), а
журналируемый факт денежного движения для аудита/разбивки — поэтому
`docs/models/domain/other/`, по аналогии с `AnomalyReport` /
`DealActionState` (`.claude/decisions/models-core-vs-other.md`).

## Структура

Java-модель, наследует поля аудита от `Auditable`.

| Поле | Тип | Обязательно | Назначение |
|---|---|---|---|
| `id` | `Long` | да | Внутренний идентификатор в БД. |
| `dealId` | `Long` | нет | Сделка-владелец движения. Проставляется `RefreshBillsExecutor` **при сохранении** — предикатом «биржа + инструмент + `ts ≥ Deal.billsWindowBegin` при нетерминальном `Deal`» (bills не несут `dealId`, см. «Линковка к `Deal`»). Отложенной линковки нет: ждать закрытия окна линковке не нужно (C1 `DOCS_CHECK_19`). **`null` у строки сделки в фазе 1 не наблюдаем:** движение, попавшее в окно живой сделки, линкуется тем же проходом, что его сохранил. Cross-ccy-запись тоже линкуется (H5, `GAPS_CLOSE_6`). Долгоживущий `null` — форвард-слот под производителя движений аккаунта **вне** периода жизни сделок (аккаунт-широкий скан `AnomalyJob`, шаг 8). |
| `category` | `CashFlowCategory` | да | Категория движения (доменный enum). Резолвится **из `type`/`subType`** bill-записи — по типу операции, не по знаку `externalFee` (`docs/models/mapping/DealCashFlow.md` §«Резолв категории»). |
| `amount` | `BigDecimal` | да | Знаковая сумма движения (минус — списание, плюс — начисление). Отвечает на вопрос «**сходится ли сумма**»: Σ`amount` сверяется с net из positions-history. |
| `externalFee` | `BigDecimal` | нет | Знаковая **комиссионная компонента** записи (минус — комиссия, плюс — ребейт; сырой `fee` bill-записи, **без нормализации знака** — в отличие от прогнозной ставки `TradeFeeRate`: `docs/models/mapping/DealCashFlow.md` §«Знак `externalFee` — сырой»). Отвечает на вопрос «**сколько комиссии**»: комиссия сделки = Σ`externalFee` по торговым движениям. `null` — у события комиссионной компоненты не бывает (например funding); `0` — бывает и нулевая. Взята явно, а не выведена из знака `amount` — иначе комбинированная запись (`amount` = pnl + комиссия) исказит разбивку. **Вторая природа пустоты не разобрана — названное ограничение** (B14 `DOCS_CHECK_21`), см. ниже. |
| `ccy` | `String` | да | Валюта движения (штатно — `USDT`). **Обязательно** — без валюты cross-ccy движение теряется молча при сверке (`pnl-finalization-mechanics.md` реш.5). Сравнивается с **расчётной валютой инструмента**, не с `Deal.resultProfitCurrency` (на момент записи оно пусто — H4, `GAPS_CLOSE_7`). Чужая `ccy` — нарушение инварианта «комиссии только в settle-ccy» (`docs/rules/trading-constraints.md`), а не рабочий режим: строка **персистится, линкуется, пересчитывается сразу** и помечается `AnomalyReport`. **Критерием матчинга к сделке не является** — только проверяемым атрибутом. |
| `appliedRate` | `BigDecimal` | нет | Курс пересчёта движения в расчётную валюту, взятый **из свечи на момент операции** (H25 `DOCS_CHECK_11`). Заполнен только при `rateStatus = APPLIED`. Делает cross-ccy-слагаемое `amount × appliedRate` **воспроизводимым**: число, полученное по внешней котировке, обязано быть проверяемым постфактум (H4, `GAPS_CLOSE_7`; тот же принцип, по которому отвергнут fallback-ставки). Момент курса — `externalCreatedAt` строки (момент **операции**, не обработки), отдельным полем не дублируется. |
| `rateStatus` | `RateStatus` | да | **Состояние курса** на строке: `NOT_REQUIRED` / `APPLIED` / `RATE_UNAVAILABLE` / `SETTLE_CURRENCY_UNAVAILABLE` (см. §Енум `RateStatus`). Явный признак, а не вывод из пустоты `appliedRate`: пустым он бывает по трём разным причинам, и различение по `ccy` верно только для одной из них (H9 `DOCS_CHECK_11`). На нём ключуются область суммирования и множество должников догона курса. |
| `appliedRateCandleInstrument` | `String` | нет | **Ссылка на свечу курса, координата 1:** сырой инструмент пары котировки (`instId`), по свече которого взят `appliedRate`. Заполнена только при `rateStatus = APPLIED` (H11 `DOCS_CHECK_14`). |
| `appliedRateCandleTimeframe` | `TimeFrame` | нет | **Координата 2:** таймфрейм взятой свечи — фиксирует и **разрешение** (секундное или огрублённое деградацией): признак разрешения в `rateStatus` не кодируется, его несёт ссылка. Заполнена только при `APPLIED`. **Енум расширен `ONE_SECOND`** (H10 `DOCS_CHECK_15`): без секундного значения носитель не мог выразить именно то различение, ради которого заведён; легальность значения в группах свечей и в дереве стратегии ограничена явно (`docs/models/domain/other/CandleGroup.md` §«Енум `TimeFrame`»). |
| `appliedRateCandleOpenTime` | `OffsetDateTime` | нет | **Координата 3:** время открытия интервала свечи. Вместе с двумя предыдущими однозначно идентифицирует свечу (та же схема идентичности, что у локальной `Candle`: группа-пара + таймфрейм + `openTimestamp`). Заполнена только при `APPLIED`. |
| `exchangeId` | `Long` | да | Биржа-владелец движения. Входит в **ключ уникальности** вместе с `externalBillId`: `billId` — идентификатор в номенклатуре одной площадки, и при втором источнике столкновение значений дало бы не логическую ошибку, а отказ вставки на `UNIQUE`, то есть тихую потерю движения (H13 `DOCS_CHECK_11`). Разрешить биржу через `deal_id → instrument → exchange` нельзя: `deal_id` на момент вставки может быть `null`. |
| `externalInstrumentId` | `String` | нет | **Сырой** биржевой идентификатор инструмента (`instId` bill-записи). **Ось предиката линковки** (H11 `DOCS_CHECK_11`; переобосновано B4b `DOCS_CHECK_20`): ответ `/account/bills` аккаунт-широкий, поэтому без инструментной оси предикат подобрал бы движение чужого инструмента, попавшее в то же временное окно. `null` — у движений без инструментной привязки. Сырой, а не FK: резолв в наш `Instrument.id` на границе не гарантирован; побочно даёт ось разбора форвард-слоту шага 8. |
| `externalBillId` | `String` | да | `billId` bill-записи. Вместе с `exchangeId` — ключ идемпотентности/дедупа `REFRESH_BILLS_COMMAND` (см. «Персистентность»). |
| `externalType` | `String` | да | Сырой `type` bill-записи (интерпретируется в `category`). |
| `externalSubType` | `String` | нет | Сырой `subType` bill-записи (для funding: `173` expense / `174` income). |
| `externalOrderId` | `String` | нет | `ordId`, если bill связан с ордером. `null` для движений без ордера (например funding). |
| `externalCreatedAt` | `OffsetDateTime` | да | Время bill-события (Unix ms источника → доменное время). Поле **из `Auditable`**, не собственное: событие источника называется конвенционным именем, отдельного `externalTs` не заводим (H25, `GAPS_CLOSE_7` — иначе рядом встают две вечно пустые audit-колонки, а окно линковки считается по разным именам одного факта). Обязательность **обеспечивается на границе разбора**, не колонкой — см. §Персистентность. |

**Природа пустого `externalFee` разобрана в одну сторону** (B14
`DOCS_CHECK_21`). Записано «`null` = комиссионной компоненты у события
не бывает»; вторая природа — «**источник поля не отдал**» — не названа, и
конвенции пустоты у bills-записи, в отличие от positions-history
(`docs/models/integrations/okx/OkxPositionsHistoryResponse.md`
§Конвертация, «пусто = 0 для несобытийного поля»), не существует вовсе.

- **Цена ложного прочтения направленная.** При омиссии `fee` у торгового
  движения комиссия сделки (`Σ externalFee`) **недосчитывается**, и
  вторая пара сверки расходится в одну и ту же сторону на всей
  популяции — то есть выглядит как систематический дефект целостности,
  а не как неполнота данных.
- **Что делается сейчас:** ограничение записано, и **пустота не
  подменяется нулём** — правило `docs/rules/absent-value-semantics.md`
  запрещает благоприятное умолчание, а «0» здесь именно оно (нулевая
  комиссия — благоприятнее неизвестной).
  - **Названное исключение — арифметика разности** (B3 `DOCS_CHECK_22`,
    решение держателя). В `Σ(amount − externalFee)` пустое вычитаемое
    трактуется нулём: там оно означает «вычитать нечего», а не «комиссия
    равна нулю». В `Σ externalFee` пустота по-прежнему **пропускается**,
    и различение двух природ живёт именно там. Исключение записано в
    правиле (`docs/rules/absent-value-semantics.md` §«Названное
    исключение: пустой `DealCashFlow.externalFee` в разности»), а не
    практикой маппинга; клауза выше им не отменяется.
- **Что делается после грунта:** фактический состав полей bill-записи
  снимается кейсом `AG3.5`/`AG3.6`
  (`.claude/tests/source-api/okx/plan.md`); по его итогу конвенция
  пустоты для bills заводится там же, где живёт конвертация границы, и
  выравнивается с positions-history. До прогона вторая природа остаётся
  **ненаблюдаемой**, а не отсутствующей.

## Енум `RateStatus`

Состояние курса пересчёта на строке (H9 `DOCS_CHECK_11`, решение
пользователя). Заведён потому, что `appliedRate = null` нёс **три** разных
смысла, а модель утверждала один; различитель «`ccy` = расчётной валюте»
верен только для первого:

- `NOT_REQUIRED` — движение в расчётной валюте, пересчёт ему не нужен.
  `appliedRate` пуст **по природе**.
- `APPLIED` — курс получен из свечи на момент операции и зафиксирован.
  Единственное состояние, при котором строка входит в
  cross-ccy-слагаемое. **Разрешение свечи признак не несёт** (H11
  `DOCS_CHECK_14`: у енума нет второго `APPLIED`, и «взят по секундной» /
  «взят по минутной за неимением секундной» значением не различались —
  носителя не существовало). Носитель — **ссылка на свечу** тремя
  координатными полями строки (`appliedRateCandle*`, §Структура): она
  фиксирует и разрешение (таймфрейм), и сам интервал, масштабируясь на
  любую лестницу деградации без новых констант статуса.
- `RATE_UNAVAILABLE` — котировка не получена. `appliedRate` пуст **по
  отказу**; строка образует **долг догона** (там же, §«Политика отказа
  котировки и догон»), сопровождается `AnomalyReport`
  `CROSS_CCY_RATE_UNAVAILABLE`.
- `SETTLE_CURRENCY_UNAVAILABLE` — расчётная валюта инструмента не
  резолвится, guard сравнения не выполнялся вовсе. Сопровождается
  одноимённым `AnomalyReport`
  (`docs/models/domain/aggregate/Deal.md` §«Ветка "операнд пуст"»).
  **Тоже должник догона** (B3 `DOCS_CHECK_18`): валюта инструмента
  резолвится ближайшим тиком синка, после чего guard исполним —
  строка уходит в `NOT_REQUIRED` / `APPLIED` / `RATE_UNAVAILABLE`
  (`docs/components/RefreshBillsExecutor.md` §«Политика отказа котировки
  и догон»).

**Оба «пусто по отказу» входят в предикат неполноты числа.** Область
суммирования ключуется `APPLIED`, а предикат неполноты — **перечнем
значений** `{RATE_UNAVAILABLE, SETTLE_CURRENCY_UNAVAILABLE}`, а не
формулировкой «cross-ccy-строка без `APPLIED`»: у строки со
`SETTLE_CURRENCY_UNAVAILABLE` cross-ccy-ность **неопределима по
построению** (расчётной валюты, с которой сравнивать `ccy`, нет), а вывод
из `ccy` в этом кластере запрещён явно
(`docs/models/mapping/DealCashFlow.md` §«Cross-ccy-область ключуется
признаком состояния курса, а не `ccy`»). Дом предиката —
`docs/components/FinalizeDealExitExecutor.md` §«Неполное число — не
чистый терминал».

Тот же довод, по которому `AnomalyReport` получил `kind`: «пусто по
природе» и «пусто по отказу» не делят одно значение. Побочно признак
делает возможным **догон** (H24): множество должников адресуемо запросом,
чего предикат заполненности не давал.

## Енум `CashFlowCategory`

Категория = **тип события источника** (`type`/`subType`), не знак числа
(`docs/models/mapping/DealCashFlow.md` §«Резолв категории»):

- `TRADE_FEE` — торговая комиссия **отдельной записью** (источник эмитит
  списание комиссии самостоятельным bill'ом).
- `FUNDING` — funding-платёж по SWAP (списание/начисление; `subType` `173`
  expense / `174` income).
- `REBATE` — ребейт отдельной записью (возврат/скидка комиссии).
- `LIQ_PENALTY` — ликвидационный штраф (издержка принудительного закрытия
  позиции биржей).
- `REALIZED_PNL` — торговое движение по факту закрытия/частичного закрытия
  позиции. **Сюда же — комбинированная запись** (`amount` = pnl + комиссия):
  событие торговое, комиссия едет компонентой `externalFee` на той же строке.
- `OTHER` — прочее cashflow, не отнесённое к перечисленным категориям.
  **Корзина наблюдаемая, не молчаливая** (H14 `DOCS_CHECK_10`): непустой
  `OTHER` у сделки сам по себе даёт `AnomalyReport`
  (`UNCLASSIFIED_CASH_FLOW`). Так новый `type` от источника, попавший в
  окно, обнаруживается вместо того, чтобы молча раздувать сумму-сверку —
  а если он посторонний, его вносят в список исключений биржи
  (`docs/models/mapping/DealCashFlow.md` §«Область сверки задаётся списком
  исключений по бирже»).

`TRADE_FEE`/`REBATE` против `REALIZED_PNL` — вопрос **гранулярности
источника** (отдельная fee-запись или комбинированная), а не знака: комиссия
как **число** достаётся из `externalFee` при любой гранулярности. Фактическая
гранулярность — рантайм-вопрос (`.claude/tests/source-api/okx/plan.md`
**§AG3.5**; фикстура общая с §AG1.5, но вопрос гранулярности — в AG3.5,
H11 `GAPS_CLOSE_6`); категорийная ось от ответа не зависит.

Состав audit-колонок — все шесть, по `docs/models/domain/other/Auditable.md`
§«Состав audit-колонок»; **имена — по фактическому `AuditableEntity`**
(`modified_at`/`modified_by`, не `updated_at`/`updated_by`, — H12
`DOCS_CHECK_14`: прежние имена расходились с маппингом базового типа и со
всеми существующими миграциями, Hibernate генерировал бы SQL по
`modified_*`, а падение всплыло бы только на первом
insert внутри транзакции звена — `ddl-auto: none` схему на старте не
валидирует). **Nullability audit-колонок выровнена с конвенцией
существующих таблиц** (все nullable): довода для отступления
(`not null` у `created_at`/`modified_at` только в новых таблицах) названо
не было — отступление снято той же правкой. **Вывод «Обязательно: да ⇒
`NOT NULL`» общим не
является** — `external_created_at` тому контрпример (§ниже), поэтому
nullability названа здесь по каждой колонке, а не выводится из §Структуры.

**Ссылка на свечу курса — координатная запись, не FK** (H11
`DOCS_CHECK_14`). Свеча котировки добывается у **источника** (пара
котировки в контур не входит, её свечи локально не персистятся —
`docs/components/RefreshBillsExecutor.md` §«Носитель курса»), поэтому
ссылаться на строку `candles` не на что; идентификация — той же схемой,
что у локальной `Candle` (пара + таймфрейм + открытие интервала).
Следствия: чистка локальных свечей по ретеншену ссылку **не затрагивает**
(каскадов нет, битой FK не бывает); протухание свечи **у источника**
(глубина хранения) ожидаемо и ссылку не обесценивает — воспроизводимость
самого числа держит записанный `applied_rate`, ссылка отвечает за разбор
**качества** котировки (какое разрешение, какой интервал), а не за
повторную добычу.

Прочие ограничения и доводы:

- FK-колонка `deal_id` (`null` до матчинга; проставляется при сохранении).
- FK-колонка `exchange_id` — `NOT NULL` (ось ключа уникальности, см. ниже).
- Колонка `applied_rate` — nullable (заполняется только при `rate_status =
  APPLIED`), точность денежной конвенции `numeric(36,18)`.
- Колонка `rate_status` — `NOT NULL`, хранится **строкой** (имя enum).
- Колонка `external_instrument_id` — nullable (сырой `instId`); входит в
  предикат линковки и в индекс отбора несвязанных строк.
- **`UNIQUE(exchange_id, external_bill_id)`** — идемпотентность/дедуп
  `REFRESH_BILLS_COMMAND`: повторный проход команды не задваивает движение
  (модель — место истины ключа уникальности,
  `docs/rules/idempotency-via-unique.md`; upsert по паре). **Ось биржи в
  ключе с самого начала** (H13 `DOCS_CHECK_11`, решение пользователя):
  `billId` уникален в номенклатуре одной площадки, и ключ без биржи при
  втором источнике теряет движение молча — тем же устройством, каким
  соседняя новая сущность шага (`TradeFeeRate`) несёт `exchangeId` в
  ключе-тройке. Таблица новая ⇒ ни `ALTER`, ни бэкфилла, ни дедупа.
- Колонка `external_created_at` — **nullable**, как все audit-колонки
  проекта; обязательность поля обеспечивается **валидацией на границе
  разбора**, а не схемой (H12 `DOCS_CHECK_11`, решение пользователя).
  Довод: `external_created_at`/`external_modified_at` приходят из
  `AuditableEntity` и общи для всех наследников, часть которых
  БД-first, — `NOT NULL` на этой колонке невозможен в принципе, и
  требовать его у одной таблицы значило бы разойтись с базовым типом.
  Пункт валидации — `docs/models/mapping/DealCashFlow.md` §Validation
  («`ts` присутствует и парсится»); пустой `ts` делает строку
  невыбираемой оконным предикатом, то есть молча выпадающей из
  суммы-сверки, поэтому запись с непарсимым `ts` до персиста не доходит.
- **Одна строка на bill-запись.** Следствие ключа выше: комбинированная
  запись источника (`amount` = pnl + комиссия) **не разбирается** на две
  строки — комиссия едет компонентой `external_fee` на той же строке. Две
  строки задвоили бы движение в Σ`amount` (сломав сверку) и не имели бы
  второго `billId` под `UNIQUE`.
**Имена ключей и индексов названы здесь** (B7 `DOCS_CHECK_19`) — место
истины схемы сущности называет их поимённо, как это уже сделано для
объектов на существующих таблицах; выводить основу имени из конвенции
префиксов нельзя, она задаёт только `uk_`/`fk_`/`ix_`
(`docs/rules/writer-named-for-every-value.md` — тот же класс «объявлено,
но не названо»):

- **`fk_deal_cash_flow_deal`** — FK `deal_id` → `deals(id)`;
  **`fk_deal_cash_flow_exchange`** — FK `exchange_id` → `exchanges(id)`.
- **`uk_deal_cash_flow_exchange_bill`** — `UNIQUE(exchange_id,
  external_bill_id)`, ключ дедупа (§выше).
- **`ix_deal_cash_flow_deal`** по `deal_id` — выборка разбивки сделки и
  сверка.
- **`ix_deal_cash_flow_unlinked`** — отбор несвязанных строк окна по
  (**`exchange_id`**, `external_instrument_id`, `external_created_at`) с
  предикатом `deal_id is null`.
  - **Потребитель индекса назван, и это не отложенная линковка** (B4b
    `DOCS_CHECK_20`). Отложенной линковки после C1 `DOCS_CHECK_19` не
    существует — `deal_id` проставляется при сохранении. Индекс
    обслуживает **форвард-слот шага 8**: аккаунт-широкий скан
    `AnomalyJob` по движениям **вне** периода жизни сделок, для
    которого `deal_id is null` — целевая, а не транзиторная популяция
    (§Структура, строка `dealId`).
  - **Почему заводится сейчас, а не на шаге 8.** Таблицы пусты
    (`.claude/rules/pre-launch-schema-changes.md`), заведение
    бесплатно; ретроспективное — миграция на непустой таблице. Цена
    ошибки в другую сторону названа: индекс на непрунимой таблице
    платится стоимостью записи, и это принято.
  - **Ось биржи внесена и в индекс, и в предикат** (H16 `DOCS_CHECK_15`,
    решение пользователя). Прежний состав — «окно + `instId` +
    `deal_id is null`» — молча опирался на «сейчас площадка одна»:
    строковый `instId` между площадками **не уникален**
    (`ETH-USDT-SWAP` существует у нескольких), поэтому строки второго
    источника попадали бы под предикат чужой сделки, получали `deal_id`
    и входили в суммы разбивки. Отказ **тихий**:
    `UNIQUE(exchange_id, external_bill_id)` его не ловит (разные
    `billId`), а сверка поймает только при превышении единого epsilon и
    финализацию не блокирует.
  - **Довод — тот же, которым отвергнут матч ставки по голому
    `groupId`**: «сейчас сущность одна» основанием предиката не является
    (`docs/components/InstrumentExternalRulesSyncJob.md` §«Матч по паре,
    не по голому `groupId`»). Здесь он симметрично применим, а прежде не был
    выставлен. Достижимость в фазе 1 — ноль (одна биржа); цена правки —
    одна колонка в `CREATE INDEX` и один конъюнкт в предикате, операнд
    **уже есть на строке** (`exchange_id`, `NOT NULL`), связность не
    растёт.
  - Первым операндом индекса стоит `exchange_id` — самая селективная и
    всегда известная координата отбора.
- `category` хранится **строкой** (значение = `name()` доменного enum),
  persistence-поле — `String` без `@Enumerated` (codestyle §Слои моделей и
  enum'ы).

**Реляционно, а не JSONB-навес.** По `docs/rules/persistence-representation.md`
представление определяет характер связей, не число полей. Здесь на строку
завязаны: дедуп по адресуемому `external_bill_id` (`UNIQUE`), сверка суммы
flows и запросы категорийной разбивки по `deal_id`. Каждое движение —
адресуемая строка с собственным ключом уникальности и индексом выборки; у
JSONB-навеса нет цели для `UNIQUE(exchange_id, external_bill_id)` и индекса `deal_id`.
Поэтому `DealCashFlow` — собственная таблица, а не JSONB-коллекция на строке
`Deal`.

### Политика перезаписи при повторной записи (H12 `DOCS_CHECK_16`)

Строки персистятся **до** закрытия окна и перечитываются на каждом повторе
звена, а идемпотентность описана как «дедуп по паре + upsert, приводит их к
состоянию биржи». Формулировка верна только для половины колонок: вторая
половина — **производные вызывающего**, фактами источника не являющиеся, и
буквальное `ON CONFLICT DO UPDATE SET` по всем колонкам их обнуляет.
Различитель состояния курса (`rateStatus`) уже существует — не хватало
**правила перехода** при повторной записи. Оно записано здесь:

| Класс колонок | Колонки | На конфликте |
|---|---|---|
| **Снапшот источника** | `amount`, `external_fee`, `ccy`, `external_type`, `external_sub_type`, `external_order_id`, `external_instrument_id`, `external_created_at`, `external_modified_at` | **обновляются** — это и есть «привести к состоянию биржи» |
| **Производные вызывающего** | `deal_id`, `category`, `applied_rate`, `rate_status`, `applied_rate_candle_instrument` / `_timeframe` / `_open_time` | **монотонно**: пустое заполняется, заполненное не обнуляется; порядок состояний курса `SETTLE_CURRENCY_UNAVAILABLE → RATE_UNAVAILABLE → {NOT_REQUIRED, APPLIED}`, переходы **только вперёд** (B3 `DOCS_CHECK_18`; прежняя редакция знала один переход `RATE_UNAVAILABLE → APPLIED`) |
| **Ключ и audit** | `exchange_id`, `external_bill_id`; `created_at` / `created_by` | не трогаются (`modified_*` ведёт JPA auditing) |

**Почему монотонность, а не «последний писатель выигрывает».** Отказ добычи
котировки — штатная ветка (`RATE_UNAVAILABLE`, догон —
`docs/components/RefreshBillsExecutor.md` §«Политика отказа котировки и
догон»). При симметричном upsert проход, на котором котировка не добылась,
**стирал** бы уже вычисленный `applied_rate`: cross-ccy-слагаемое тихо
выпадало бы из `resultProfit`, число завышалось бы **направленно**, и это
ровно тот отказ, ради устранения которого слагаемое вводилось. Регресс не
ловится ни одной из четырёх пар сверки — cross-ccy-строки в settle-ccy-суммы
не входят по построению, — то есть был бы тихим. Механизм догона без запрета
обратного перехода соревнуется сам с собой.

**Что политика не вводит.** Ни колонки, ни признака: `rateStatus` —
единственный операнд перехода, и он уже `not null`. Вариант «вынести
производные курса в отдельную строку/таблицу» **переоткрывает** «одна строка
на bill-запись»; вариант «не персистить до закрытия окна» рассмотрен и
отвергнут ранее.

## Линковка к `Deal`

Bills **не несут** `dealId` — только `instId`, `ccy`, `ts`, `ordId`.
`RefreshBillsExecutor` матчит движение к сделке по **бирже + окну сделки +
`instId`** и **проставляет `deal_id`** при сохранении
(`docs/integrations/okx/contracts/account-bills.md` §Использование).
**Ось биржи — обязательный конъюнкт предиката** (H16 `DOCS_CHECK_15`):
`instId` между площадками не уникален, и без неё строки второго источника
попадали бы под предикат чужой сделки (разбор и довод — §Персистентность,
индекс отбора несвязанных строк). Операнд уже на строке — `exchange_id`
`NOT NULL`.
`instId` — это `Instrument.externalId`, и он резолвится **через
`DealContext`**: пути `Deal.instrument.externalId` на модели нет — `Deal`
хранит `instrumentId`, а сам `Instrument` в runtime graph не входит
(`docs/models/domain/aggregate/Deal.md` §«Runtime graph»; H27,
`GAPS_CLOSE_7`).

**Границы окна — собственные поля `Deal`** (узел 1 `DOCS_CHECK_8`;
`docs/decisions/command-action-boundary.md` §7): `Deal.billsWindowBegin`
(write-once) / `Deal.billsWindowEnd` (монотонно вперёд), заполняет
наблюдатель факта
(`docs/models/domain/aggregate/Deal.md` §«Окно линковки bills»). Из чужих
колонок окно **не реконструируется**: прежний операнд
`Position.externalModifiedAt` писали **обе** ноги
`REFRESH_POSITION_COMMAND`, и предикат «запись закрытия добыта» по нему был
невыразим — прочитанное значение могло быть до-закрытийным, закрывающие
движения выпадали из окна необратимо.

- `begin` = `Deal.billsWindowBegin`, а при его пустоте —
  `Deal.externalCreatedAt` (биржевой момент создания сделки, П7-B;
  разбор — `docs/models/domain/aggregate/Deal.md` §«Почему у нижней
  границы один писатель»). `Deal.billsWindowBegin` — `Order.externalCreatedAt` первой
  отправленной ноги; писатель **один**, `SubmitOrderExecutor` (H9
  `DOCS_CHECK_16`; прежняя AG1.5-развилка снята вместе с двумя другими
  писателями — разбор у модели `Deal`).
- `end` **запроса и линковки** = **серверное время источника** прохода
  (`t_source`, `GET /api/v5/public/time`; подвижная граница, Р7
  `GAPS_CLOSE_16` + C1 `DOCS_CHECK_19`, операнд — A8 `DOCS_CHECK_20`):
  добыча не ждёт записи закрытия, и линковка тоже — `deal_id`
  проставляется при сохранении, предикатом `ts ≥ begin` при
  нетерминальном `Deal`. **Системные часы здесь не участвуют** (B12
  `DOCS_CHECK_21`: прежняя формулировка «текущее время прохода» их
  допускала, а этот же файл ниже их прямо запрещает —
  `docs/rules/time-utc.md` §«Два временных домена, и смешивать их
  запрещено»).
- `end` **контроля полноты и обязанности сверки** =
  `Deal.billsWindowEnd` — `uTime` записи закрытия **позднейшего
  закрывшегося эпизода**, пишет вторая нога
  `REFRESH_POSITION_COMMAND` транзакционно с полями положения закрытия,
  **монотонно вперёд**. Разбор двух величин —
  `docs/models/domain/aggregate/Deal.md` §«Верхних границ две» и
  §«Верхняя граница монотонна, а не write-once».
- **`billsWindowEnd` пуст → окно не закрыто**: сверка не обязана, звено
  добычи не завершено (`docs/models/domain/aggregate/Deal.md` §«Добыча
  движений — durable-факт»), поэтому оно повторяется каждым проходом;
  **линковка при этом идёт** — ждать нечего. Исчерпание бюджета уводит
  сделку ошибочной тропой + холд инструмента. Фолбэка `Deal.modifiedAt`
  больше нет — системное время в биржевом окне было смешением часовых
  доменов.
- **Почему линковка не ждёт неподвижную границу** (C1 `DOCS_CHECK_19`):
  движения закрытия приходят в конвейер **позже** `uTime` записи
  закрытия, поэтому предикат `ts ≤ billsWindowEnd` отсекал бы ровно тот
  хвост, ради которого окно и открывалось; а пока эпизоды продолжают
  закрываться, состояние «окно закрыто» не наступает вовсе. Довод,
  разрешающий открытость сверху, записан ниже и был ратифицирован
  раньше находки.

Границы **включительные**; искусственного зазора не вводим.

**Точность окна сверху обеспечивает не сама граница, а инвариант «одна
активная сделка на инструмент»** (`docs/rules/trading-constraints.md`;
DB-уровень — `uk_deal_active_instrument`,
`docs/models/domain/aggregate/Deal.md` §Персистентность). Пока сделка
удерживает слот по инструменту, второй сделки по нему не существует ⇒ любое
движение по `instId` позже `begin` принадлежит **этой** сделке, и открытость
границы сверху безвредна. `end` нужен, чтобы запрос не тянул лишнего, а не
чтобы разделять сделки. **Это несущий довод, не подразумеваемое свойство:**
без него верхняя граница обязана была бы быть точной, и любая её неточность
означала бы чужие движения в разбивке.

**Условие исполнимости линковки — сделка удерживает слот.**
`REFRESH_BILLS_COMMAND` линкует движения **только пока `Deal` не терминализован**
(статус вне `CLOSED`/`EMERGENCY_CLOSED` — то же множество, по которому
построен `uk_deal_active_instrument`). После терминала слот освобождён,
по инструменту может открыться новая сделка, и матчинг по окну + `instId`
однозначным быть перестаёт ⇒ повторная добыча bills после
терминала **не выполняется**. Без этого условия аварийная тропа снова
открывала бы окно вверх. Добор недостающего числа за терминалом
(реш.3, форвард шага ожидаемости) обязан нести **собственную** адресацию, а
не переиспользовать это окно.

**Названная цена запрета линковки за терминалом** (узел 1
`DOCS_CHECK_8`): ожидание факта закрытия ограничено бюджетом
добычи, а исчерпание ведёт к терминалу — после которого движения, не
пришедшие в конвейер, **не подберутся никогда**. Разбивка такой сделки остаётся
неполной, сверка даёт `AnomalyReport` сверх epsilon при, возможно, верном
числе; сделка попадает в `EMERGENCY_CLOSED`-корзину (смещение R-выборки —
торговый хвост узла 2). Это принятая цена, не дефект.

Остаточный риск «движение с `ts` на границе окна» ловится сверкой:
недобранное движение даёт расхождение сверх epsilon → `AnomalyReport`
(§Сверка в `docs/models/mapping/DealCashFlow.md`); рантайм-наблюдение —
фикстура §AG1.5.

**Нижняя граница под наблюдением: entry-fee — постоянный житель границы**
(H24, `GAPS_CLOSE_7`). Комиссия входа — не случайное движение у края окна:
она возникает ровно в момент открытия позиции. Если источник штампует её
временем **раньше** `cTime` позиции, входная нога комиссии выпадает из окна
на **каждой** сделке — то есть аномалия на каждой сделке при **верном**
`resultProfit` и заниженной комиссии в разбивке.

**Этот режим отказа — омиссионный, и именно он потребовал второго члена
допуска** (H15 `DOCS_CHECK_10`). Прежняя оценка («fee ≈ 5.0 против допуска
≈ 2.5 на крупной сделке, 0.05 против 0.025 на мелкой») считалась при
одночастном допуске и **без учёта того, что realized-движения входят в
Σ`|amount|` того же оборота** — с их учётом относительный член на крупной
сделке перерастает целую комиссионную ногу, и систематическая омиссия
перестаёт быть видимой ровно там, где она дороже. Двухчастный тест
(`min(композиционный, омиссионный)`,
`docs/rules/pnl-reconciliation.md` §«Допуск (epsilon)») якорит
второй член на **ожидаемую комиссию сделки**, которая от оборота не
растёт.

- **Развилка снята: писатель один, безусловно** (H9 `DOCS_CHECK_16`,
  решение пользователя). `Deal.billsWindowBegin` пишет наблюдатель
  **первого отправленного `Order`** (его `externalCreatedAt`) — **всегда**
  при постановке, а не только при отсутствии позиции; ни live-нога, ни нога
  2 `REFRESH_POSITION_COMMAND` поля не касаются. Окно шире, но лишних
  движений не захватывает: активная сделка на инструмент одна (тот же
  инвариант слота, что держит верхнюю границу).
- **Наблюдение §AG1.5 (сравнение `ts(entry-fee)` с `cTime(position)`) для
  этой границы больше не гейт.** Оно закрыто конструкцией:
  `externalCreatedAt` ордера не позже комиссии его же исполнения, значит
  окно накрывает entry-fee при любом ответе источника. Разбор и цена —
  `docs/models/domain/aggregate/Deal.md` §«Почему у нижней границы один
  писатель»; механизм write-once (условный `UPDATE`) — там же,
  §Персистентность.

**Валюта критерием матчинга не является** (H5, `GAPS_CLOSE_6`). Прежняя
редакция включала `ccy == Deal.resultProfitCurrency` в предикат линковки —
вместе с фильтром `ccy` в самом запросе это делало cross-ccy guard мёртвым.
Теперь `ccy` — **проверяемый атрибут**: не совпала с **расчётной валютой
инструмента** → строка всё равно персистится, линкуется, пересчитывается по
`appliedRate` и помечается `AnomalyReport`
(`docs/models/mapping/DealCashFlow.md` §«Guard оживлён», §«Операнд сравнения»).
Операнд — именно инструмент, а не `Deal.resultProfitCurrency`: последнее на
момент записи пусто (H4, `GAPS_CLOSE_7`).

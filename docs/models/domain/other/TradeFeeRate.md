# TradeFeeRate

## На какой вопрос отвечает этот файл

Что это за модель `TradeFeeRate`: структура, персистентность, история,
свежесть.

## Назначение

`TradeFeeRate` — **persisted** доменная модель `other`: актуальная ставка
торговой комиссии (taker/maker) **комиссионной группы** аккаунта на бирже.
Источник прогнозной комиссии в риск-сайзинге (N9, шаг 7 —
`docs/decisions/pnl-finalization-mechanics.md` реш.4).

Не про бизнес-цикл сделки, а хранимые справочные данные аккаунта → модель
`other` (`.claude/decisions/models-core-vs-other.md`), как
`InstrumentExternalRules`.

## Масштаб модели — группа, не инструмент

**Ставка живёт в своём масштабе: одна строка на группу.** Ключ ставки —
пара (**тип инструмента**, **id комиссионной группы**), а не инструмент:
ставка — атрибут **комиссионного уровня аккаунта** (объём/VIP-тир), а не
справочника инструмента. Инструмент несёт только **ключ группы**
(`InstrumentExternalRules.externalFeeGroupId`), по которому ставка
резолвится.

**Ось группы — биржевые значения, не доменные проекции** (H7,
`GAPS_CLOSE_4`). Ключ группы — пара сырых полей источника
(`externalInstrumentType`, `externalFeeGroupId`), а **не** доменный
`instrumentType`. Довод — коллизия `UNKNOWN`: доменная проекция схлопывает
все нераспознанные сырые типы в одно значение (`mapping/TradeFeeRate.md`
§«snapshot → `TradeFeeRate`»), поэтому две разные группы источника
столкнулись бы в одном ключе, и правило истории «значение изменилось →
новая строка» выродилось бы во флип-флоп между ставками двух групп.
Группа — **ось источника**, и ключевать её надо тем, чем её задаёт
источник. `instrumentType` на модели остаётся доменной проекцией для
runtime-логики, но осью резолва **не является**.

**Почему не копией на каждый инструмент.** Копия ставки на инструменте —
заготовка под расхождение: тир аккаунта меняется **по своей оси и на своём
такте**, и при смене тира N копий обновляются N операциями, каждая из
которых может отстать или упасть → часть инструментов торгует по старой
ставке, часть по новой, и расхождение ничем не выражено. Одна строка на
группу делает смену тира **одной записью**: расходиться нечему.

Ревизует хранение (не seam) относительно первой редакции реш.4: поля
`externalTakerFeeRate`/`externalMakerFeeRate` на навесе инструмента
**сняты**, ставка уехала сюда. **Поверхность чтения не двинулась** —
`SizeCalculator`/`RiskValidator` по-прежнему читают ставку аксессором
`InstrumentExternalRules.takerFeeRate()`
(`docs/models/domain/other/InstrumentExternalRules.md` §«Ставка комиссии»).
Гидрирует аксессор **хранилищный слой** —
`docs/components/InstrumentExternalRulesDataService.md`, единственная граница
domain ↔ persistence навеса; обе тропы чтения навеса получают гидрированный
инстанс, читатели о `TradeFeeRate` не знают (H1, `GAPS_CLOSE_4`).

## Структура

Java-модель, наследует поля аудита от `Auditable`.

| Поле | Тип | Обязательно | Назначение |
|---|---|---|---|
| `id` | `Long` | да | Внутренний идентификатор в БД. |
| `exchangeId` | `Long` | да | Биржа-владелец ставки (ставка — атрибут аккаунта на бирже, не инструмента). |
| `externalInstrumentType` | `String` | да | **Ось группы:** сырой тип инструмента источника (`instType`). |
| `externalFeeGroupId` | `String` | да | **Ось группы:** сырой id комиссионной группы источника (`groupId`). Пара (`externalInstrumentType`, `externalFeeGroupId`) — ключ группы. |
| `instrumentType` | `InstrumentType` | да | Нормализованный тип инструмента (`SWAP`) — доменная проекция `externalInstrumentType` для runtime-логики. **Осью группы не является** (см. §«Масштаб модели»: `UNKNOWN`-коллизия). |
| `externalTakerFeeRate` | `String` | да | Ставка taker-комиссии как **издержка**: знак биржевой конвенции снят при маппинге, комиссия — положительная величина (см. §«Знак ставки»). |
| `externalMakerFeeRate` | `String` | да | Ставка maker-комиссии, та же знаковая конвенция. Хранится; в фазе 1 прогноз сайзинга берёт taker (worst-case). |
| `externalFeeLevel` | `String` | нет | Комиссионный уровень аккаунта на момент чтения (`level`, например `Lv1`) — **датчик оси тира**. |
| `externalModifiedAt` | `OffsetDateTime` | нет | Время данных источника (`ts` ответа) на момент последнего подтверждения строки. Метка ответа, **не** значение группы: обновляется на месте и новую строку не порождает (см. §Запись). Поле **из `Auditable`**, а не собственное `externalTs`: время события источника носит конвенционное имя (H25, `GAPS_CLOSE_7` — иначе рядом стоят две вечно пустые audit-колонки). |
| `refreshCount` | `Long` | да | **Счётчик подтверждений строки:** сколько успешных чтений группы подтвердили это значение. Строка создаётся с `1`, каждое последующее успешное чтение с тем же значением — инкремент. Несущее назначение — сделать движение `modifiedAt` **записанным**, а не побочным (см. §«Свежесть измеряется, а не предполагается»). |

`createdAt` / `modifiedAt` — из `Auditable`; несут историю и свежесть (см.
ниже), поэтому не декоративны.

## Знак ставки: снимается при маппинге, одним местом

Источник несёт **свою** знаковую конвенцию (на OKX — «отрицательное значение
= комиссия, положительное = ребейт»,
`docs/integrations/okx/contracts/trade-fee.md` §«Знаковая конвенция»). Она
**не выходит за маппинг**: конвертация в проектную нормаль — умножением на
−1 — делается **при маппинге**, в per-source-секции
(`docs/models/mapping/TradeFeeRate.md` §OKX), как конвенция конкретной биржи.

**Проектная нормаль — «издержка»:** комиссия положительна, ребейт
отрицателен. Отсюда формула риска
(`docs/decisions/per-trade-risk-policy.md` §«Учёт комиссий»)
`|entry − stop| × contracts × ctVal + commissions` верна **в обе стороны**
без `abs`: положительная издержка увеличивает убыток на стопе, отрицательная
(ребейт) уменьшает — ровно то, что происходит в деньгах. То же для бюджета:
`бюджет − прогнозная_комиссия`.

**Почему при маппинге, а не в аксессоре/формуле.** Снятие знака — перевод
внешней конвенции во внутреннюю, то есть **граница**; маппинг — её штатное
место (прецедент в проекте: `docs/models/mapping/Position.md` — `abs(pos)` →
`externalSize`, знак → `direction`). Разложи это по формулам через `abs` —
получится N мест, каждое из которых можно забыть, и `abs` вдобавок
**потерял** бы ребейт (превратил его в издержку). Одно место, ниже него
знак — свойство величины, а не источника.

> **Не путать со знаком `DealCashFlow.externalFee`.** Там нормализации
> **нет** и быть не должно: `externalFee` — не ставка-прогноз, а **факт**
> движения, участвующий в арифметике композиции
> (`amount − externalFee = realized pnl` при комбинированной bill-записи,
> `docs/models/mapping/DealCashFlow.md`). Снятие знака сломало бы эту
> арифметику. Асимметрия сознательная: нормализуется **прогнозная ставка**,
> не **фактическое движение**.

**Отказ, который это закрывает (H2, `DOCS_CHECK_4`).** До `GAPS_CLOSE_4`
аксессор отдавал сырую знаковую ставку, а формулы складывали её через
`+ commissions` без `abs` — композиция как написано **уменьшала** убыток на
стопе и **увеличивала** бюджет, оба члена в одну сторону ⇒ **позиция больше
положенной**. Это дословно тот отказ, ради недопущения которого отвергнут
fallback-ставки (`docs/components/RiskValidator.md` §«Null-политика ставки
комиссии»): тихое оптимистичное смещение, не видное ни в одном логе.
Валидация его не ловила — отрицательное число парсится, а
`FEE_RATE_UNAVAILABLE` срабатывает только на `null`.

## Запись: история значением, свежесть счётчиком

Синк ставки (`docs/components/InstrumentExternalRulesSyncJob.md`) на каждое
успешное чтение группы пишет по правилу:

- **Значение группы изменилось** → **новая строка** (`refreshCount = 1`).
- **Значение группы совпало** → строка **не плодится**; у последней строки
  группы **инкрементится `refreshCount`** и **обновляется `externalModifiedAt`**.

**Что считается «значением группы»** (то, изменение чего рождает строку):
`externalTakerFeeRate`, `externalMakerFeeRate`, `externalFeeLevel`. Тир —
**часть значения**, а не примечание к нему: иначе смена тира без смены ставки
переписала бы `level` на месте, и `level` не ответил бы на вопрос, ради
которого заведён — «когда пересчитался тир» (H11, `DOCS_CHECK_4`).

**Что значением группы не является:** `externalModifiedAt` — метка **ответа**, а не
факт о группе; она меняется каждый тик, и попади она в триггер — история
росла бы строкой в час. Обновляется на месте.

Отсюда два свойства:

- **История** — сколько строк у группы, столько раз менялась **ставка или
  тир** (аудит: когда, на что и при каком `level`). Формулировка точная:
  триггер строки — изменение значения группы целиком, а не одного лишь тира.
- **Свежесть** — возраст `modifiedAt` актуальной строки (см. ниже).

**Рост** — единицы строк в год (ставка и тир скачут редко), поэтому история
хранится без ретеншена.

**Актуальная ставка группы** = последняя строка по `createdAt` для ключа
(`exchangeId`, `externalInstrumentType`, `externalFeeGroupId`). Читается
ограниченным запросом (`…OrderByCreatedAtDesc(…, Pageable)` limit 1), не
выборкой всей истории (codestyle §Выборка данных).

## Свежесть измеряется, а не предполагается

> **Измеритель самоизлечим — холд нет.** Возраст падает сам при первом
> успешном чтении; статус инструмента остаётся до ручного снятия
> (§«Свежесть → холд инструментов группы»). Это не напряжение, а разделение
> вопросов: измеритель отвечает «свеж ли факт», холд — «возобновлять ли
> входы» (H2, `GAPS_CLOSE_6`).

**Измеритель — возраст `modifiedAt` актуальной строки.** Работает он потому,
что **`refreshCount` инкрементится на каждом успешном чтении** — и на пути
новой строки, и на пути совпадения. Инкремент — реальное изменение сущности ⇒
строка dirty ⇒ JPA auditing (`docs/models/domain/other/Auditable.md`
§Структура: системные `createdAt`/`modifiedAt` проставляет persistence-слой)
выпускает UPDATE и двигает `modifiedAt`. Возраст `modifiedAt` = **время с
последнего успешного чтения**.

**Зачем счётчик, если `externalModifiedAt` и так обновляется.** Обновление
`externalModifiedAt` действительно сделало бы строку dirty само по себе — но тогда
несущее свойство измерителя держалось бы на **побочном эффекте** соседнего
поля: убери или закешируй `externalModifiedAt` — и измеритель молча перестанет
измерять. `refreshCount` заведён **ради** этого свойства и потому делает его
**записанным**, а не выведенным. Он же — прямой ответ на «сколько раз это
значение подтверждалось» (полезно при разборе: одна строка с `refreshCount`
= 700 против семи строк по сотне — разные истории).

**Отказ, который это закрывает (H5, `DOCS_CHECK_4`).** До `GAPS_CLOSE_4` на
пути совпадения предписывалось «обновить `modifiedAt`» — а JPA auditing метку
сам не двигает: он реагирует на изменение сущности, которого на этом пути по
определению нет. Ставка меняется редко ⇒ «значение совпало» — практически
**единственный** путь ⇒ `modifiedAt` замирал на времени создания, и через 24 ч
**полностью здоровой** работы возраст превышал порог. Дефект давал не «тихо
сломанный измеритель», а **ложноположительную остановку торговли**.

**Отдельный счётчик отказов не нужен — довод перепроверен против этого
механизма (H5, `GAPS_CLOSE_4`).** Он держится: возраст `modifiedAt` — это и
есть время с последнего успеха, а при фиксированном такте синка время
однозначно переводится в число неудач подряд (часовой такт, порог 24 ч → 24
неудачи). Счётчик отказов отвечал бы на **тот же** вопрос второй записью,
которую надо согласованно сбрасывать. Разница с прежней редакцией — в опоре:
раньше довод стоял на незаписанном побочном эффекте (и потому был ложен),
теперь — на `refreshCount`.

**Измеритель не различает, почему возраст растёт** — упало чтение, группа
выпала из ответа или синк молчит: в любом случае возраст ставки неизвестен.
Различение — на уровне политики радиуса (H4, `GAPS_CLOSE_5`): «вызов не
прошёл» и «группа отсутствует в ответе» — источники холда с разным
радиусом, а «синк выключен» (`enabled = false`) источником холда **не
является** — это штатная эксплуатационная операция, а не отказ интеграции
(`docs/rules/error-handling-policy.md` §«Перечень scope и реакций»).

## Свежесть → холд инструментов группы

Возраст `modifiedAt` актуальной строки группы > **порога свежести** (конфиг,
стартовое значение **24 ч**) → **запрет новых входов по инструментам этой
группы** (`docs/rules/instrument-hold.md` §«Несвежесть ставки комиссии») —
тех, чья пара (`externalInstrumentType`, `externalFeeGroupId`) навеса
резолвится в эту строку.

**Реакция — мягкая, kill-switch не применяется** (H2, `GAPS_CLOSE_5`):
запрет новых входов + `AnomalyReport`; живые сделки доживают под своим
стопом и сопровождаются штатно. Радиус ущерба несвежести — **сайзинг новых
входов**: в `R` живой сделки (задан стопом на бирже) и в её `resultProfit`
(считается из фактов) ставка не участвует.

**Снятие — вручную** (H2, `GAPS_CLOSE_6`). Отсюда несущее следствие:
**измеритель самоизлечим, холд — нет.** Возраст `modifiedAt` падает сам при
первом успешном чтении (§выше), но статус инструмента — **sticky-запись**,
которую снимает оператор (`docs/rules/instrument-hold.md` §Снятие).
Противоречия нет: измеритель отвечает на «свеж ли факт», холд — на
«возобновлять ли входы». Авто-снятие по предикату `isFresh()` — форвард на
установившийся режим, отложено, не отвергнуто.

**Меряется не только значение — ещё и ключ резолва** (H9, `GAPS_CLOSE_6`).
Возраст этой строки отвечает лишь за половину факта, питающего сайзинг;
вторая половина — ключ группы на навесе инструмента, у него свой источник и
свой измеритель (`docs/models/domain/other/InstrumentExternalRules.md`
§«Свежесть ключа группы»). Протухший ключ при живом чтении ставок резолвится
в **чужую свежую строку** — свежесть значения этого не ловит.

**Радиус — по режиму отказа** (H4, `GAPS_CLOSE_5`). «Группа отсутствует в
ответе» → затронута одна группа (остальные подтверждены тем же ответом);
«вызов не прошёл» → все группы одного вызова разделяют судьбу — радиус
**аккаунт**, входы стоят по всему контуру; «синк выключен» — не источник
холда. Сводная таблица — `docs/rules/error-handling-policy.md` §«Перечень
scope и реакций».

**Почему реакция вообще нужна, а не тихий прогноз по старой ставке.**
`modifiedAt` двигается при каждом успешном чтении (см. выше), поэтому при
часовом такте синка возраст 24 ч = **24 неудачи подряд**. Это не сетевая
икота, а поломка интеграции (права / эндпоинт / подпись) — сайзить новые
входы по ставке неизвестной давности нельзя. Отсутствие ставки **вовсе** —
другой случай: это реджект `FEE_RATE_UNAVAILABLE` на `RiskValidator`, не
холд (`docs/components/models/RiskCheckResult.md`).

## Rich-модель (методы)

- `takerFeeRate()` / `makerFeeRate()` — `BigDecimal`, числовые аксессоры строк
  (пусто/нечисловое → `null`). Отдают **издержку** (знак источника снят при
  маппинге, §«Знак ставки») — `abs` вызывающему не нужен;
- `isFresh(OffsetDateTime staleBefore)` — `Boolean`, ставка свежа
  (`modifiedAt` после порога). Предикат собственных данных модели
  (codestyle §Вложенность и rich-модели); порог считает вызывающий по конфигу.

Состав audit-колонок — все шесть
(`docs/models/domain/other/Auditable.md` §«Состав audit-колонок»);
**имена — по фактическому `AuditableEntity`** (`modified_at`/`modified_by`,
не `updated_at`/`updated_by` — H12 `DOCS_CHECK_14`: прежние имена
расходились и с маппингом базового типа, и со всеми миграциями проекта, и
с §«Свежесть» **этого же файла**, который меряет свежесть по
`modified_at`; писатель миграции, идущий по месту истины схемы, создал бы
таблицу, на которой синк падал бы каждым тиком, а дефект маскировался бы
штатной реакцией на несвежесть). **Nullability audit-колонок выровнена с
конвенцией существующих таблиц** (все nullable) — довода для отступления
названо не было, отступление снято той же правкой.
`exchange_id` — **FK и `NOT NULL`**, симметрично одноимённой колонке
`deal_cash_flows`: прежде перечень его не называл вовсе.

Прочие ограничения и доводы:

- **`UNIQUE` по ключу группы НЕТ** — история означает несколько строк на ключ.
  Уникальность здесь была бы прямым запретом истории.
- Индекс по (`exchange_id`, `external_instrument_type`,
  `external_fee_group_id`, `created_at DESC`) — резолв актуальной строки
  группы одним ограниченным запросом. Колонки индекса совпадают с ключом
  группы (§«Масштаб модели»): ось резолва — **сырая**, поэтому индекс
  обслуживает заявленный запрос (H7, `GAPS_CLOSE_4` — до него запрос шёл по
  доменному enum, а индекс лежал на сырой колонке).
- `refresh_count` — `BIGINT NOT NULL`; пишется синком, инкрементом на строке
  (§Запись).
- **Колонки ставок — `varchar`, и это записанное исключение из конвенции**
  (H23 `DOCS_CHECK_10`): `external_taker_fee_rate`,
  `external_maker_fee_rate`, `external_fee_level` — `varchar(32)`, а не
  `numeric(36,18)`, которого требует сквозная конвенция схемы для
  денежных/процентных величин (`docs/rules/persistence-representation.md`
  §«Численные колонки»).
  - **Довод.** Доменные поля — `String` (сырые ставки приходят строками,
    `× −1` при снятии знака сериализуется обратно в строку носителя), а
    аксессор `takerFeeRate()` определён как «числовой аксессор сырых строк
    (пусто/нечисловое → `null`)», то есть модель **сознательно допускает
    непарсящееся значение**. `numeric` это допущение уничтожает и
    переносит отказ парсинга с аксессора на **запись**: одна
    неожиданная строка от источника обрушила бы синк вместо того, чтобы
    дать `null` и штатный реджект `FEE_RATE_UNAVAILABLE`.
  - **Почему не «привести домен к `BigDecimal`»** — это ревизия решения о
    сыром хранении ставки, принятого вместе с осью группы (§«Масштаб
    модели»); здесь закрывается **тип колонки**, а не оно.
  - **Прецедент `InstrumentExternalRules` не переносится:** там
    JSONB-навес, где типа колонки нет вовсе, здесь — реляционная колонка.
    Без явной записи `code-writer` разошёлся бы с доменным типом: по
    конвенции создал бы `numeric`, по модели — `varchar`.
- `instrument_type` хранится **строкой** (значение = `name()` доменного enum),
  persistence-поле — `String` без `@Enumerated` (codestyle §Слои моделей и
  enum'ы). В индекс резолва **не входит** — это проекция, не ось.

**Реляционно, а не JSONB-навес.** По `docs/rules/persistence-representation.md`
представление определяет характер связей. Здесь на строку завязаны: история
(строка = событие смены ставки), резолв актуальной по `created_at`, аудит
скачков тира и измерение свежести по `modified_at`. У JSONB-навеса нет ни
цели для этого индекса, ни носителя истории. Навесом эта модель быть **не
может** ещё и по масштабу: владельца-строки у неё нет — группа не сущность
нашей схемы, а ось источника.

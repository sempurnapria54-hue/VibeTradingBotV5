# TradeFeeRate

## На какой вопрос отвечает этот файл

Что это за модель `TradeFeeRate` — ставка торговой комиссии.

## Назначение

`TradeFeeRate` — актуальная ставка комиссии **комиссионной группы** счёта
на бирже. Источник прогнозной комиссии в риск-сайзинге.

## Масштаб — группа, а не инструмент

**Одна строка на группу.** Ключ — пара «тип инструмента, идентификатор
комиссионной группы»: ставка есть атрибут комиссионного уровня счёта, а
не справочника инструмента. Инструмент несёт только **ключ группы**, по
которому ставка резолвится.

**Ось группы — сырые значения источника, а не доменные проекции.**
Доменная проекция схлопывает все нераспознанные типы в одно значение,
поэтому две разные группы источника столкнулись бы в одном ключе, и
правило истории «значение изменилось — новая строка» выродилось бы в
переключение между ставками двух групп. Доменный тип на модели остаётся,
но осью резолва не является.

**Почему не копией на каждый инструмент.** Тир счёта меняется по своей
оси и на своём такте; при копиях смена тира обновляла бы N строк, каждая
из которых может отстать, и часть инструментов торговала бы по старой
ставке без всякого выражения расхождения. Одна строка на группу делает
смену тира одной записью.

**Поверхность чтения не меняется:** потребители читают ставку аксессором
справочного навеса инструмента, гидрирует его хранилищный слой навеса, и
о существовании этой модели читатели не знают.

## Структура

| Поле | Тип | Обязательно | Назначение |
|---|---|---|---|
| `id` | `Long` | да | Внутренний идентификатор. |
| `exchangeAccountId` | `Long` | да | **Биржевой счёт-владелец ставки.** Ставка есть атрибут комиссионного уровня счёта, а не свойство площадки, и читается его ключами (`docs/architecture/tenant-and-exchange.md`). |
| `externalInstrumentType` | `String` | да | **Ось группы:** сырой тип инструмента источника. |
| `externalFeeGroupId` | `String` | да | **Ось группы:** сырой идентификатор комиссионной группы. |
| `instrumentType` | `InstrumentType` | да | Доменная проекция типа для runtime-логики. Осью группы не является. |
| `externalTakerFeeRate` | `String` | да | Ставка taker как **издержка**: знак биржевой конвенции снят при маппинге, комиссия положительна. |
| `externalMakerFeeRate` | `String` | да | Ставка maker, та же конвенция. Хранится; прогноз сайзинга берёт taker как худший случай. |
| `externalFeeLevel` | `String` | нет | Комиссионный уровень счёта на момент чтения — датчик оси тира. |
| `externalModifiedAt` | `OffsetDateTime` | нет | Время данных источника на момент последнего подтверждения строки. Метка ответа, а не значение группы: обновляется на месте и новой строки не порождает. |
| `refreshCount` | `Long` | да | **Счётчик подтверждений строки.** Делает движение времени изменения записанным, а не побочным. |

**Ставки хранятся строкой, а не числом** — это названное исключение из
численной конвенции: значение хранится в форме источника, и эта форма —
часть факта. Предикат сравнения строковых операндов задан в модели; без
него сырое хранение дало бы тихий отказ.

## Запись и история

**Значение изменилось — новая строка**; значение то же — инкремент
счётчика подтверждений на месте.

**Свежесть измеряется, а не предполагается:** время последнего
подтверждения плюс счётчик дают ответ на вопрос «когда мы в последний раз
видели эту ставку и сколько раз её подтверждали».

**Несвежесть ставки — мягкая реакция инструментного радиуса**
(`docs/rules/instrument-hold.md`): устаревшее справочное число
обесценивает сайзинг новых входов, но не риск живой сделки.

## Персистентность

**Таблица `trade_fee_rates` базы `trading_core`**, наследует поля аудита.
Уникальность — тройка «**биржевой счёт**, сырой тип инструмента, сырой
идентификатор группы» среди актуальных строк.

**Реестр живёт у владельца счёта, а не у владельца каталога, и довод
счётный:** чтение ставок — **приватная** операция площадки
(`docs/components/IntegrationService.md` §«Приватные операции — добыча
факта»), то есть требует ключей счёта, а `market-data` ходит к площадке
только публичными чтениями (`docs/architecture/contracts.md`
§«Синхронные вызовы»). У `market-data` остаётся **ключ** комиссионной
группы на навесе правил инструмента — он приходит публичным чтением
спецификации; сама ставка приходит приватным и потому принадлежит ядру.
Единственный потребитель прогнозной комиссии — сайзинг, и он тоже в
ядре.

**Ограничением БД эта уникальность не выражена, и это названо.** Правило
истории требует нескольких строк на группу (значение изменилось — новая
строка), а признака актуальности у модели нет ни одного: уникальный
индекс по тройке запретил бы историю, а частичный — стоял бы на поле,
которого не существует. Актуальная строка группы резолвится **порядком**
(последняя по идентификатору), и держит инвариант «одна актуальная»
писатель: запись идёт одним ходом — подтвердить последнюю либо завести
новую. Индекс по тройке заведён ради резолва, не ради запрета.

Ставки — `varchar` по названному исключению; прочие строковые колонки —
`varchar(64)`.

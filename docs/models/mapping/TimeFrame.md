# TimeFrame — mapping между слоями

## На какой вопрос отвечает этот файл

Как таймфрейм переходит между слоями.

## OKX

Доменный `TimeFrame` ↔ строка таймфрейма OKX, например:

```text
TimeFrame.ONE_HOUR <-> "1H"
```

Полный набор доменных значений: **`ONE_SECOND`**, `ONE_MINUTE`,
`THREE_MINUTES`, `FIVE_MINUTES`, `FIFTEEN_MINUTES`, `ONE_HOUR`,
`TWO_HOURS`, `FOUR_HOURS`, `ONE_DAY`.

### Правила

- Маппинг строгий: без `lowerCase` / `upperCase`, точное соответствие
  строк.
- `TimeFrameMapper` предоставляет `domainToOkx` (домен → строка OKX).
  Обратное направление в коде шага 1 не используется и не заведено
  (по потребности). Строки баров живут в `util.OkxConstants` коннектора.
- Отдельный `TimeFrameResolver` на первом этапе не нужен.

### `ONE_SECOND` — ветка маппера и её условие

Значение введено шагом 7 (канон — `docs/models/domain/other/CandleGroup.md`), поэтому **исчерпывающий `switch` `TimeFrameMapper`
получает девятую ветку**: без неё маппер перестаёт компилироваться либо
падает на новом значении.

- **Строка источника взята из его контракта, а не угадана:** `1s`, и
  контракт называет у неё два ограничения — бар отдаёт только эндпоинт
  истории и только за последние три месяца
  (`docs/integrations/okx/contracts/candle.md` §«Query (одинаковые для
  обоих)»). Ветка маппера отдаёт эту строку. Эндпоинту последних свечей
  контракт секундного бара не объявляет, и что он отвечает на такой
  запрос, прогоном не добыто: соблюсти оба ограничения — забота
  вызывающего, выбирающего эндпоинт и окно.
- **Молчаливой подмены на минутную быть не должно** — именно её различает
  ссылка на свечу курса. Ветка отдаёт секундную строку, а не соседний бар.
- **Обратное направление по-прежнему не заводится** — потребителя нет.

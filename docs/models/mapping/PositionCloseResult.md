# PositionCloseResult

## На какой вопрос отвечает этот файл

Как положение закрытой позиции источника переходит в `Position`.

## Цепочка

```text
ответ истории позиций источника
  → PositionCloseResultExternalSnapshot   (граница интеграции)
  → Position                              (вторая нога рефреша позиции)
  → Deal                                  (финализация)
```

Отдельного файла снапшот не требует: самостоятельного хранимого
содержания у него нет, состав фиксируется здесь.

## Граничный снапшот

| Поле | Тип | Семантика |
|---|---|---|
| `externalRealizedPnl` | `BigDecimal` | готовый net, посчитанный биржей |
| `externalResultCurrency` | `String` | валюта этого числа — **проверяемый признак**, не источник валюты результата сделки; дом контроля — правило проверки валюты чисел записей закрытия (`docs/rules/pnl-reconciliation.md`) |
| `externalCloseAveragePrice` | `BigDecimal` | средняя цена фактического выхода |
| `externalCloseType` | `String` | тип последнего закрытия, **сырое значение источника**; во что оно резолвится — правило резолва торгового исхода закрытия ниже |
| `externalRealizedPnlGross` | `BigDecimal` | результат **до** издержек — правый операнд первой пары сверки |
| `externalFee` | `BigDecimal` | знаковая комиссионная компонента, **сырой знак** — правый операнд второй пары |
| `externalFundingCost` | `BigDecimal` | накопленное финансирование, **знак нормализован**: издержка положительна — правый операнд третьей пары |
| `externalLiquidationPenalty` | `BigDecimal` | штраф ликвидации, **сырой знак** — правый операнд четвёртой пары |
| `externalPosId` | `String` | идентификатор позиции: **половина** оси адресации записи (вторая — `externalCreatedAt`), а на тропе материализации — данные |
| `externalInstrumentId` | `String` | сырой идентификатор инструмента — операнд **структурной проверки** принадлежности записи; на позицию не приземляется |
| `direction` | `Direction` | направление закрытой позиции — **доменное значение, нормализованное в слое интеграции** |
| `externalCreatedAt`, `externalModifiedAt` | `OffsetDateTime` | время создания и обновления записи |

Числовые и временные поля нормализуются при построении снапшота; пустая
строка становится пустотой, а не нулём.

## Знак финансирования нормализуется здесь, и только здесь

В тождестве источника слагаемые знаковые, и финансирование приходит со
знаком «сколько прибавилось к результату». Домен же хранит его
**издержкой**: положительная величина означает уплаченное фондирование.

Нормализация делается **при построении снапшота** — одним местом. Иначе
каждый потребитель нормализовал бы сам, и знак разошёлся бы между
потребителями молча.

**У комиссии и штрафа ликвидации знак остаётся сырым** — они уходят
правыми операндами пар сверки, где сравниваются с сырыми же суммами
разбивки. Смешение конвенций дало бы расхождение на всей популяции.

## Снапшот → `Position`: две тропы

- **обновление** — позиция уже существует, статус в закрытый перевела
  первая нога;
- **материализация** — позиция **впервые увидена уже закрытой**
  (открылась и закрылась между тиками, быстрый стоп, ликвидация), и
  вторая нога заводит её из записи истории.

| Поле снапшота | Куда | Тропа |
|---|---|---|
| `externalRealizedPnl` | `externalRealizedProfit` | обе |
| `externalResultCurrency` | `externalResultCurrency` | обе |
| `externalCloseAveragePrice` | `externalCloseAveragePrice` | обе |
| `externalCloseType` | `externalCloseType` | обе |
| `externalRealizedPnlGross` | `externalRealizedProfitGross` | обе |
| `externalFee`, `externalFundingCost`, `externalLiquidationPenalty` | одноимённые поля | обе |
| `externalModifiedAt` | `externalModifiedAt` **и верхняя граница окна линковки на сделке** — той же транзакцией | обе |
| `externalPosId` + `externalCreatedAt` | сверка **парой** со строкой эпизода (дом единицы — `docs/models/domain/core/Position.md`): одинокого идентификатора мало, `posId` переиспользуется | обновление |
| `externalInstrumentId` | сверка с инструментом запроса | обе |
| `externalPosId` | `externalId` — **запись** | материализация |
| `direction` | `direction` — перенос доменного значения, без резолва здесь | материализация |
| `externalCreatedAt` | `externalCreatedAt` позиции | материализация |

**Статус и размер на тропе материализации.** Позиция создаётся сразу
закрытой, размер пишется нулём.

Предикат живого риска этим не подделывается: он требует активного статуса,
а он здесь другой при любом размере. Значащее состояние «активна и размер
ноль» на этой тропе недостижимо.

**Цена названа:** теряется различение «наблюдали ноль» и «не наблюдали
вовсе»; различить их можно только по тропе материализации.

## `Position` → `Deal`

Финализация читает положения закрытия **со строк эпизодов** и складывает:
результат сделки — по составу из дома
(`docs/models/domain/aggregate/Deal.md`).

Правые операнды четырёх пар сверки берутся суммами по тем же строкам
(`docs/spec/pnl-reconciliation.json`).

Оттуда же берутся операнды двух признаков положения закрытия: торговый
исход и валюта результата; правила обоих — резолв торгового исхода ниже
и правило проверки валюты чисел записей закрытия (`docs/rules/pnl-reconciliation.md`).

## Структурная валидация — до маппинга

Проверяется на границе интеграции, **там, где ответ впервые
разбирается**:

- запись относится к запрошенному инструменту;
- обязательные поля непусты: net, валюта, четыре правых операнда пар,
  резолвимое направление;
- числовые и временные поля разбираемы.

**Нарушение даёт контролируемое исключение здесь, а не у финализации.**
Радиус поражения при нарушении контракта неизвестен по построению,
поэтому реакция соразмеряется с неизвестностью
(`docs/rules/error-handling-policy.md`).

**Пустота из-за отсутствия самой записи нарушением не является:** это
недобытый факт, и звено просто не завершается.

**Тип закрытия в контракт границы не входит вовсе — ни непустотой, ни
принадлежностью перечню.** Обе проверки сняты с границы одним доводом:
признак **отчётный**, он ничего не гейтит, а нарушение контракта здесь
сворачивает площадку — реакция, адресующая сущности вне радиуса ущерба
(`docs/concept.md` §П1, лестница реакций). Пустое и незнакомое значение
обрабатывает резолв торгового исхода — одинаково и громко, отчётом.

Симметрии с направлением здесь нет намеренно: без направления
материализация эпизода отказывает **тихо**, поэтому направление остаётся
контрактным; непригодный тип закрытия громок собственным отчётом.

## Резолв торгового исхода закрытия

**Это дом правила резолва** `Deal.closeOutcome`: перечень значений енума
живёт у модели (`docs/models/domain/aggregate/Deal.md`),
**отображение и порядок разрешения — здесь**, исполнимая форма —
`docs/spec/position-close-outcome.json`. Прочие носители ссылаются сюда и
правила не пересказывают.

**Ключ отображения — сырой тип закрытия** `Position.externalCloseType`,
персистируемый **всегда**, независимо от исхода резолва: иначе перечень
нераспознанного нельзя было бы собрать постфактум, и калибровка
отображения опиралась бы на память, а не на данные (та же конвенция, что
у категории движения — `docs/models/mapping/DealCashFlow.md`, дом резолва
категории).

**Резолвер — писатель признака**, той же транзакцией, что и запись самого
признака. Кто им является на каждой тропе, здесь не перечисляется: дом
разведения писателей по тропам — таблица признаков отбора терминального
ребра (`docs/lifecycles/Deal.md`), и смена писателя правит её одну.

Слой доменный: сырое значение к этому моменту уже приземлено на строку
эпизода **второй ногой рефреша позиции**, границы интеграции резолв не
требует.

**Почему не в слое интеграции, как у направления.** У направления
нерезолвимое значение — нарушение контракта со ступенью 2, потому что
без него материализация эпизода отказывает тихо. Торговый исход —
**отчётный** признак: он ничего не гейтит, и реакция такой силы
адресовала бы площадку по поводу вне радиуса ущерба (`docs/concept.md`,
лестница реакций).

### Отображение — OKX

| Сырое значение | Доменный исход |
|---|---|
| `1` (частичное закрытие), `2` (полное закрытие) | `NORMAL_EXIT` |
| `3` (ликвидация), `4` (частичная ликвидация) | `LIQUIDATION` |
| `5` (ADL не полностью), `6` (ADL полностью) | `FORCED_REDUCTION` |

Перечень взят из офдока источника
(`docs/integrations/okx/contracts/position.md`, дом перечней значений полей
элемента записи) и **наблюдением не подтверждён**: какие значения источник
фактически отдаёт на закрытых позициях контура, устанавливает прогон
против источника. Наблюдение меняет **срабатывающую ветку**, а не
конструкцию: незнакомое значение уже имеет свою.

### Непригодный операнд — `UNDETERMINED` плюс отчёт

**Операнд непригоден, когда запись закрытия добыта, а исход из её типа не
выводится** — поле пусто либо значение перечню не принадлежит. Обе формы
дают `UNDETERMINED` **и** `AnomalyReport` с машинным кодом
`UNRECOGNIZED_CLOSE_TYPE`; состав отчёта — радиус инструмента, природа
события, некритичность, момент после коммита — тот же, что у отчёта о
доступности знаменателя (`docs/models/domain/aggregate/Deal.md`, дом
состава). Терминал этим не блокируется.

**Пустое и незнакомое значение разведены не реакцией, а данными.**
Различать их отдельным кодом незачем: разбор у них один — сверить
перечень с источником, — а сама форма непригодности читается сырым
значением на строке эпизода, которое персистится всегда.

**Отчёт — различитель непригодности и недобытости.** У `UNDETERMINED` на
уровне эпизода два производителя, и по данным они обязаны различаться
(`docs/concept.md` следствие 4):

| Производитель | Исход | Чем наблюдаем |
|---|---|---|
| **запись закрытия не добыта** | `UNDETERMINED` | отчёта нет: недобытость наблюдаема тропой добычи и признаком доступности итога |
| **запись добыта, операнд непригоден** — тип пуст либо вне перечня | `UNDETERMINED` | отчёт `UNRECOGNIZED_CLOSE_TYPE` плюс сырое значение (пустое либо незнакомое) на строке эпизода |

Пятого значения енума при этом не заводится: различение несёт отчёт, а не
корзина, и меньший след предпочтителен, пока он выражает то же самое.

### Исход сделки собирается из исходов эпизодов по старшинству

Сделка многоэпизодна (позиция внутри неё может схлопнуться и открыться
заново), а признак на сделке один. Порядок старшинства:

```text
LIQUIDATION > FORCED_REDUCTION > UNDETERMINED > NORMAL_EXIT
```

- **Принудительное выше неизвестного:** наблюдённый факт ликвидации или
  сокращения не отменяется неизвестностью соседнего эпизода — признак
  отвечает на «был ли принудительный выход», и наблюдённое «да» сильнее
  «неизвестно».
- **Неизвестное выше штатного:** недобытый или нераспознанный операнд
  хотя бы одного эпизода не даёт права утверждать штатный выход по
  сделке. Обратный порядок был бы благоприятным умолчанием — ровно тем,
  что скрывает ликвидацию за `NORMAL_EXIT` и загрязняет `R`-выборку
  (`docs/processes/risk-evaluation.md`).
- **Вошедшая сделка без единого эпизода** даёт `UNDETERMINED` по тому же
  доводу: утверждать штатный выход не из чего.
- **Сделка, не входившая,** признака не получает вовсе — пусто означает
  «признак неприменим» (`docs/lifecycles/Deal.md`, дом разведения
  признаков отбора по тропам).

**Производителей `UNDETERMINED` на сделке три, и это полный перечень** —
дом значения (`docs/models/domain/aggregate/Deal.md`) отсылает за ним
сюда:

| Производитель | Отчёт | Чем наблюдаем |
|---|---|---|
| хотя бы у одного эпизода запись закрытия не добыта | нет | тропа добычи и признак доступности итога |
| хотя бы у одного эпизода операнд непригоден (пуст либо вне перечня) | `UNRECOGNIZED_CLOSE_TYPE` | сырое значение на строке эпизода |
| у вошедшей сделки нет ни одного эпизода | нет | само отсутствие строк эпизодов у сделки с состоявшимся входом; популяция достижима на аварийной тропе, где эпизод не материализовался |

## Резолв направления

Направление закрытой позиции резолвится **в слое интеграции**, из полей
записи, и в домен приходит уже доменным значением — симметрично живой
ноге. Нерезолвимое направление — нарушение контракта, а не пустота:
пустое направление на тропе материализации сделало бы отказ тихим.

# persistence — модели хранимого слоя

## На какой вопрос отвечает этот файл

Что это за слой `docs/models/persistence/` и когда здесь появляются
файлы.

## Назначение

Тир `persistence` хранит модели хранимого слоя: entity-классы,
jsonb-снимки, persistence-проекции. Сюда уходит знание о том, **как
domain-модель ложится в БД** (структура таблицы, маппинг полей,
особые правила сериализации, если они не очевидны из domain).

## Статус

**Скаффолд.** На момент введения слой пуст. Наполняется по мере
появления отдельных persistence-проекций, отличных от
domain-структуры. Стандартные ORM-маппинги, очевидные из аннотаций
кода, документировать здесь обычно не нужно.

## Когда заводить файл

- Появилась jsonb-сериализация с собственной схемой и
  версионированием (например, `AnomalyReport.internalBefore/After` —
  см. backlog-пункт «Стандарт описания персистентности доменных
  моделей»; идентификатор открытого вопроса здесь не указывается —
  прежняя приписка `ANOM-Q5` атрибутировала пункту чужой вопрос, а имя
  переживает перенумерацию, H25 `DOCS_CHECK_14`).
- Persistence-проекция отличается от domain (например, отдельная
  read-model или write-model).
- Применяются нетривиальные техники: partitioning, retention policy,
  archiving.

## Что не место здесь

- Сама доменная модель (`docs/models/domain/...`).
- Структура миграций Flyway (это в SQL-файлах + `docs/processes/...`
  при необходимости).

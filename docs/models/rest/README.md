# rest — модели API нашего сервиса

## На какой вопрос отвечает этот файл

Что это за слой `docs/models/rest/` и когда здесь появляются файлы.

## Назначение

Тир `rest` хранит модели API нашего сервиса: request / response DTO
наших REST endpoint'ов. Сюда уходит знание о том, **что наружу отдаёт
наш API** — в отличие от `integrations/{name}` (что приходит снаружи
от внешних источников).

## Статус

**Скаффолд.** На момент введения слой пуст — внешний API сервиса
ещё не вводится. Наполняется при появлении первых REST-endpoint'ов
наружу.

## Когда заводить файл

- Появился request/response DTO REST-операции, у которого
  нетривиальная структура / документация полей / валидации.
- Структура отличается от domain (например, наружу выходит
  read-model без чувствительных полей).

## Что не место здесь

- Доменные модели (`docs/models/domain/...`).
- Native-модели внешних источников (`docs/models/integrations/{name}/`).
- Mapping между REST DTO и domain (это `docs/models/mapping/<Сущность>.md`
  — раздел про rest, по аналогии с integration-разделами).

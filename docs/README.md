# Карта документации

## Где что лежит

### Источники правды о системе

- **`spec/`** — **целевая спецификация**. Сюда переезжает вся актуальная документация. Главный приоритет.
- **`domain/`** — **текущая живая спецификация** (legacy). Используется по темам, ещё не перенесённым в `spec/`. Постепенно мигрирует.
- **`api/`** — документация по API (OKX и внутренний API сервиса).

### Архитектурные решения и конвенции

- **`../.claude/adr/`** — Architecture Decision Records. Все ADR проекта (продуктовые и пайплайновые), append-only. Индекс — `../.claude/adr/README.md`. Обоснование расположения — ADR-0003.
- **`conventions/`** — `code-style.md`, `tech-radar.md`. Правила написания кода и состояние стека.

### Планирование

- **`planning/`** — roadmap, milestones, execution log. Долгосрочные планы развития.

### Операционная документация

- **`ops/`** — операционные заметки (vault-local и т.д.).

### Работа с Claude

Документация по работе с Claude — в `../.claude/` (см. CLAUDE.md раздел Repository layout). Обоснование разделения `docs/` vs `.claude/` — ADR-0003.

- **`../.claude/working-with-claude.md`** — концепция работы.
- **`../.claude/flow/playbook.md`** — операционные сценарии.
- **`../.claude/pipeline-evolution-log.md`** — история изменений пайплайна.
- **`../.claude/strategy-summary/`** — версионированные снимки стратегии (v1 — стартовый этап 2026-05-14, v2 — после ADR-0003).

### Реестры и навигация

- **`spec/MODELS.md`** — (создаётся в начале фазы 1 миграции) реестр канонических имён бизнес-моделей. Навигационная точка входа в `docs/spec/`.
- **`conventions/terminology.md`** — (создаётся в Этапе 4 подготовки) терминологические соглашения проекта.
- **`README.md`** — этот файл.

## Иерархия источников правды

См. `../CLAUDE.md`, раздел "Source of truth hierarchy".

Кратко: `spec/` побеждает `domain/`, `domain/` побеждает legacy/archive. При конфликте уровней с близкими приоритетами — фиксируется в ADR.

## Архивные и устаревшие материалы

Никакие старые документы не удалены. Они остаются на месте до тех пор, пока тема не будет полностью перенесена в `spec/`. После переноса — старый документ помечается `[MIGRATED → ...]` и теряет статус источника правды.

Папки, содержащие исключительно устаревшее (`context/`, `deprecated/`, фрагменты `planning/`) — приоритет 5, используются только как историческая справка.

## Получить сделки (fills, последние 3 дня) (REST)

**Зачем нужно (простыми словами):**

* Это список **фактически совершённых сделок** (fills) за последние **3 дня**.
* Используется для **восстановления после даунтайма**: понять, какие ордера реально исполнялись (в т.ч. частично), какая была цена/объём/комиссия.

> Важно: **fills ≠ ордера**.
>
> * Ордер = «заявка» (может исполниться частично / несколько раз).
> * Fill = «конкретная сделка» (каждое исполнение ордера порождает 1 или несколько fills).

---

### Endpoint

`GET /api/v5/trade/fills`

---

### Query параметры

* `instType` *(опционально)* — тип инструмента: `SPOT | MARGIN | SWAP | FUTURES | OPTION`.
* `instId` *(опционально)* — конкретный инструмент, например `ETH-USDT-SWAP`.
* `ordId` *(опционально)* — ID ордера на бирже (OKX ordId). Удобно, если хочешь увидеть fills только по одному ордеру.
* `after` *(опционально)* — пагинация «старее, чем `billId`» (вернёт записи **раньше** указанного `billId`).
* `before` *(опционально)* — пагинация «новее, чем `billId`» (вернёт записи **позже** указанного `billId`).
* `begin` *(опционально)* — фильтр по времени начала (Unix ms).
* `end` *(опционально)* — фильтр по времени конца (Unix ms).
* `limit` *(опционально)* — сколько записей вернуть за раз. Максимум `100`, по умолчанию `100`.

**Ключевой момент:** `after/before` — это якорь по **billId**, а не по времени и не по ordId.

---

### Доступ / лимиты / аутентификация

* Permission: Read
* Rate limit: **60 requests / 2 seconds**, правило — User ID
* Это приватный REST → нужны стандартные auth headers:

    * `OK-ACCESS-KEY`
    * `OK-ACCESS-SIGN`
    * `OK-ACCESS-TIMESTAMP` (UTC ISO строка)
    * `OK-ACCESS-PASSPHRASE`
    * `Content-Type: application/json`
* Demo trading: `x-simulated-trading: 1` (если используешь demo ключи)

---

### Пример запроса

> Пример для твоего кейса (SWAP, конкретный инструмент). Если begin/end не указывать — вернёт то, что биржа считает «последними 3 днями».

```bash
curl -X GET 'https://www.okx.com/api/v5/trade/fills?instType=SWAP&instId=ETH-USDT-SWAP&limit=100' \
  -H 'Content-Type: application/json' \
  -H 'OK-ACCESS-KEY: <api_key>' \
  -H 'OK-ACCESS-SIGN: <base64_hmac_sha256_signature>' \
  -H 'OK-ACCESS-TIMESTAMP: 2026-01-24T12:34:56.789Z' \
  -H 'OK-ACCESS-PASSPHRASE: <passphrase>'
  # -H 'x-simulated-trading: 1'   # только для demo
```

**Пример запроса с временем (begin/end в ms):**

```bash
curl -X GET 'https://www.okx.com/api/v5/trade/fills?instType=SWAP&instId=ETH-USDT-SWAP&begin=1768992000000&end=1769251200000&limit=100' \
  -H 'Content-Type: application/json' \
  -H 'OK-ACCESS-KEY: <api_key>' \
  -H 'OK-ACCESS-SIGN: <base64_hmac_sha256_signature>' \
  -H 'OK-ACCESS-TIMESTAMP: 2026-01-24T12:34:56.789Z' \
  -H 'OK-ACCESS-PASSPHRASE: <passphrase>'
```

## Описание полей ответа (простыми словами)

### Верхний уровень

* `code` — "0" значит успех.
* `msg` — текст ошибки/сообщение.
* `data[]` — список сделок (fills).

### Один fill (data[i])

* `instType` — тип инструмента (`SWAP` для perpetual).
* `instId` — инструмент на бирже (например `ETH-USDT-SWAP`).
* `tradeId` — ID сделки (trade) на стороне биржи.
* `ordId` — ID ордера, который породил эту сделку.
* `clOrdId` — наш `client order id` (если мы его задавали при создании ордера).
* `billId` — внутренний ID записи (используется как **якорь для пагинации** через `after/before`).
* `tag` — метка/тэг (если передавали).
* `fillPx` — цена, по которой исполнилась именно эта сделка.
* `fillSz` — объём именно этой сделки (для SWAP это обычно **контракты**).
* `side` — сторона сделки: `buy` или `sell`.
* `posSide` — сторона позиции: `net | long | short` (зависит от режима позиций).
* `execType` — как исполнилось по ликвидности:

    * `T` = taker (забрал ликвидность, обычно комиссия выше)
    * `M` = maker (дал ликвидность, может быть ниже комиссия/ребейт)
* `feeCcy` — валюта комиссии.
* `fee` — комиссия за эту сделку (часто отрицательное число).
* `ts` — время сделки (Unix ms).

---

## Как правильно делать пагинацию (важно)

Обычно `data` приходит отсортированным «свежие сверху», но полагаться на это лучше аккуратно.

**Чтобы идти в прошлое:**

1. запрос без `after`
2. берёшь **минимальный `billId`** из ответа
3. следующий запрос делаешь с `after=<minBillId>`
4. повторяешь, пока не вернулось пусто

**Чтобы идти в будущее (редко нужно):** используешь `before`.

---

### Практическая подсказка для даунтайма

* `fills` (3 дня) — быстро и часто достаточно для «упал на час/день».
* Если даунтайм был дольше 3 дней — используешь `GET /api/v5/trade/fills-history` (до 3 месяцев).

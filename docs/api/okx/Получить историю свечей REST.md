### Получить свечи (история) (REST)

**Endpoint:** `GET /api/v5/market/history-candles`

**Что делает простыми словами:**

* Возвращает **исторические** свечи по инструменту (публичный REST, без авторизации).
* Используется, когда тебе нужно **глубже**, чем «последние свечи» (`/market/candles`).

**Доступ / лимиты / аутентификация:**

* Permission: Public
* Rate limit: **20 запросов / 2 секунды**, правило — **IP**
* Auth headers: **не нужны**

---

## Query-параметры

* `instId` (**обязательный**) — имя инструмента на бирже, например `ETH-USDT-SWAP`.
* `bar` (опционально) — размер свечи. По умолчанию `1m`.

    * Примеры: `1m/3m/5m/15m/30m/1H/2H/4H`
    * Поддерживается `1s`, но есть ограничения:

        * **1s поддерживается только за последние 3 месяца**
        * **1s не поддерживается для OPTION**, но поддерживается для SPOT/MARGIN/FUTURES/SWAP
    * Дневные/недельные/месячные:

        * Открытие по UTC+8: `6H/12H/1D/2D/3D/1W/1M/3M`
        * Открытие по UTC+0: `6Hutc/12Hutc/1Dutc/2Dutc/3Dutc/1Wutc/1Mutc/3Mutc`
    * ⚠️ **Регистр важен**: `1H` ≠ `1h`, `1Dutc` ≠ `1DUTC`.
* `after` (опционально) — пагинация: вернуть свечи **строго старше (раньше)** указанного `ts` (ms).

    * Это основной параметр для выкачки истории «назад во времени».
* `before` (опционально) — пагинация: вернуть свечи **строго новее** указанного `ts` (ms).

    * Если передать **только `before`**, биржа вернёт **самые последние** данные.
* `limit` (опционально) — количество свечей в ответе.

    * Максимум: `100`
    * По умолчанию: `100`

---

## Важные особенности

1. **Порядок свечей** в `data` обычно идёт **от новых к старым** (самая свежая первая).

2. **confirm**:

* Обычно в history-эндпоинте свечи уже **закрыты** (`confirm=1`), но поле всё равно приходит.

3. **Формат массива свечи:**

* На практике он совпадает с `/market/candles`:
  `[ts, o, h, l, c, vol, volCcy, volCcyQuote, confirm]`
* В некоторых описаниях встречается укороченный формат, но **в реальных ответах для v5** обычно приходит **9 элементов**.
* Для надёжности: валидируй, что размер массива == **9** (как у тебя в `CandleDataParser`).

---

## Пример 1: просто взять 100 свечей истории

```bash
curl -X GET 'https://www.okx.com/api/v5/market/history-candles?instId=ETH-USDT-SWAP&bar=1m&limit=100' \
  -H 'Content-Type: application/json'
```

## Пример 2: пагинация назад во времени (как качать историю батчами)

### Шаг 1: стартуем «от сейчас»

```bash
curl -X GET 'https://www.okx.com/api/v5/market/history-candles?instId=ETH-USDT-SWAP&bar=1m&after=1769253296789&limit=100'
```

* `after` — это **timestamp**, “раньше которого” ты хочешь получить данные.
* То есть биржа вернёт свечи **строго старше** этого времени.

### Шаг 2: берём самую старую свечу из ответа и повторяем

* В ответе находишь `min(ts)` среди полученных свечей.
* Следующий запрос делаешь с `after=min(ts)`.

**Стоп-условия (простые и рабочие):**

* Пришёл пустой `data` → истории больше нет.
* Или `min(ts)` стал меньше твоей `coverage_start_utc` → дальше не нужно.

## Описание полей ответа

**Верхний уровень:**

* `code` — код результата. `"0"` = успех.
* `msg` — сообщение об ошибке (обычно пустое при успехе).
* `data` — массив свечей.

**`data[i]` — одна свеча (массив из 9 элементов):**
Формат: `[ts, o, h, l, c, vol, volCcy, volCcyQuote, confirm]`

* `ts` — время **открытия** свечи (Unix ms).
* `o` — Open (цена открытия).
* `h` — High (максимум за свечу).
* `l` — Low (минимум за свечу).
* `c` — Close (цена закрытия).
* `vol` — торговый объём.

    * Для **SPOT**: количество в **базовой валюте**.
    * Для **SWAP/FUTURES**: обычно объём в **контрактах**.
* `volCcy` — торговый объём (для **SPOT** обычно в **котируемой валюте**).
* `volCcyQuote` — торговый объём в **котируемой валюте** (например в USDT).
* `confirm` — закрыта ли свеча:

    * `0` — не закрыта
    * `1` — закрыта

## WS-заметка (когда лучше WS, а когда REST)

* REST `history-candles` — для **докачки истории**.
* WS `candle<bar>` — для **реалтайма**, чтобы получать новые свечи без polling.

Пример канала: `candle1m`, `candle5m`, `candle1H`, `candle1Dutc`.

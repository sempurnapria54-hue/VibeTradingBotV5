# CalculationContext

## На какой вопрос отвечает этот файл

Что это за контекст расчёта одного действия.

## Назначение

Рабочий контекст калькуляторов. Неизменяемый runtime-объект, не хранится.

Строится из контекста прохода, действия и свежих рыночных данных, и
должен быть собран максимально близко ко времени создания команды.

Контекст прохода он не заменяет.

## Структура

| Поле | Назначение |
|---|---|
| `deal` | Сделка, для которой идёт расчёт. |
| `instrument` | Инструмент сделки. |
| `strategyDetail` | Закреплённая деталь стратегии. |
| `action` | Действие, для которого считаются параметры. |
| `instrumentExternalRules` | Справочные правила инструмента с **гидрированной** ставкой комиссии. |
| `marketPriceData` | Runtime-цены. |
| `indicatorValues` | Готовые значения индикаторов — раскладка **по авторскому имени операнда**. |
| `marketStructures` | Готовые структуры рынка — та же раскладка, тот же ключ. |
| `marketPhase` | Актуальная фаза. Потребители названы — условия шагов `MARKET_PHASE_IS` и `TREND_CHANGED` внутри сделки (`docs/models/domain/other/MarketPhase.md`); заполняется тем же `MarketPhaseService`, что раздаёт фазу сканеру входа. Прежняя редакция объявляла её незаполняемой «за отсутствием потребителя» — потребитель был, и им была эталонная стратегия. |
| `riskBase` | **База риска** — делитель поактного потолка при сайзинге (`docs/components/SizeCalculator.md`). Приезжает **разрешённым числом**: развилка «снимок сделки, а при его отсутствии живая база счёта» живёт в доме-спеке `docs/spec/risk-limits.json` (величина `base`), и второй её копии здесь нет. |
| `dealTranche` | Транш, которому принадлежит действие, — носитель **экспозиции**, от которой берётся доля выхода и размер защитной ступени (`docs/spec/order-sizing.json`, операнд `tranche.exposure`). |
| `ladderPreviousStepsTotal` | Сумма размеров уже поставленных ступеней защитного набора шага (`docs/spec/order-sizing.json`, операнд `ladder.previousStepsTotal`); селектор набора и источник суммы — `docs/rules/live-risk-protection.md`. |
| `activePosition` | Живой эпизод, если открыт. |
| `entryOrder` | Входная заявка, если создана. |
| `strategyDirection` | Направление стратегии. |

**Ключ раскладок — авторское имя операнда, а не идентичность
вычисления.** Идентичность есть номенклатура владельца рыночных данных, и
связать её с объявлением стратегии может только тот, кто это соответствие
держит, — читатель
(`docs/models/domain/other/IndicatorValue.md` §«Ключевание — идентичностью
вычисления»). Снятая редакция резолвила ключ равенством «идентичность
значения = идентификатор строки объявления»: в монолите оно держалось,
потому что одна настройка и была одним вычислением, а в сервисной
конструкции это **две разные номенклатуры** — резолв возвращал бы пустоту
ВСЕГДА, и цена по уровню индикатора считалась бы на недоступном операнде.

**Каталогов настроек стратегии в контексте нет, и это следствие ключа.**
Поля `indicatorSettings` / `marketStructureSettings` были нужны прежнему
резолву; при ключе-имени резолв — обращение к раскладке, и второй носитель
соответствия оказался бы лишним.

## Операнды, которых у контекста прежде не было

**Снимок средств базой риска не является, и сайзинг на нём считал бы не
тот потолок.** Прежняя редакция называла операндом сайзинга
`balanceContainer` — «снимок баланса»; доступный остаток расчётной валюты
есть операнд **движения** базы, а не сама база
(`docs/models/domain/core/BalanceContainer.md`,
`docs/rules/risk-policy.md`). Поле заменено на `riskBase`.

**Экспозиция берётся у транша, а не у эпизода.** Доля выхода и размер
защитной ступени считаются от экспозиции **транша** действия
(`docs/spec/order-sizing.json`); нетто-размер эпизода на сетке относится к
нескольким траншам сразу, и доля, взятая от него, уводила бы экспозицию
транша в минус — при том, что сумма по сделке сходится и сверка такого
класса этого не ловит. Носителя экспозиции в контексте не было вовсе:
поле `dealTranche` введено.

**Сумма уже поставленных ступеней приезжает операндом.** Её источник —
строки исполнения действий шага, то есть персистентность ядра, а
библиотека к базе не ходит (`docs/architecture/services.md` §«Что в
библиотеку НЕ уезжает»). Пустота операнда законна только у набора из
одной ступени; у лестницы из нескольких она отдала бы последней ступени
всю экспозицию — благоприятное умолчание, запрещённое
`docs/rules/absent-value-semantics.md`, — поэтому калькулятор на ней
отказывает.

## Scope сборки

**Один рассчитываемый `StrategyAction` — один свежий контекст.** Общий
контекст на весь шаг, обработчик или проход не собирается: параметры
действия считаются по данным своего момента.

**Исключение — защитный класс действий:** расчёт размера ступени лестницы
читает уже поставленные ступени этого набора из графа сделки
(`docs/rules/live-risk-protection.md`). Расширение поверхности чтения
названо явно и на прочие классы не распространяется.

# DealTransition

## На какой вопрос отвечает этот файл

Что это за runtime-объект.

## Назначение

Исход одного прохода FSM **сделки**: команды к диспетчеризации и, если он
разрешён, новый статус сделки. RVO, не persisted
(`.claude/decisions/runtime-value-object.md`).

## Структура

| Поле | Тип | Назначение |
|---|---|---|
| `commands` | `List<ServiceCommand>` | Команды прохода — свои и поднятые каскадом траншей. |
| `nextStatus` | `Deal.Status` | Целевой статус; пусто — ребра нет. |
| `shutdownReason` | `Deal.ShutdownReason` | Причина выхода из штатного ведения; едет с ребром в координированный выход. |
| `closeReason` | `Deal.CloseReason` | Причина закрытия; едет с терминальным ребром. |
| `trancheEdges` | `List<TrancheEdge>` | Одобренные рёбра траншей — они доезжают до применения ЭТИМ носителем. |
| `holdSignal` | `HoldSignal` | Затребованная ступень; намерение, а не право. |

## Статусные рёбра системных действий здесь не едут

Терминалы и подтверждение входа пишет **звено** в транзакции своего
завершения, а обработчик гейтит эмиссию: переход несёт тогда **команду**,
а не статус (`docs/processes/fsm-execution-layering.md` §«Ребро в `ERROR`:
два механизма по природе тропы»).

## Причины едут вместе со своим ребром

Писатель обоих полей — обработчик, и пишет он их той же транзакцией,
которой гейтит ребро (`docs/lifecycles/Deal.md`). Отдельная запись
причины пережила бы отказ своего ребра.

## Рёбра траншей — часть перехода СДЕЛКИ

Каскад траншей их только **одобряет**; применяет проход, и после
диспетчеризации (`docs/components/DealOrchestratorJob.md` §«Цикл
прохода»). Записанный до диспетчера, статус транша пережил бы отказ
собственной команды.

## Границы

Живёт только в памяти прохода: читателя за сериализацией нет, поэтому
неизменяемая форма здесь дефолт
(`.claude/rules/codestyle.md` §«Неизменяемое значение, пересекающее
сериализацию»).

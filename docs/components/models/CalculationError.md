# CalculationError

## На какой вопрос отвечает этот файл

Что это за контролируемая ошибка расчёта.

## Назначение

Контролируемая ошибка расчёта параметров действия. Неизменяемый
runtime-объект, не хранится.

**Только для контролируемых случаев** — тех, что названы перечнем кодов
ниже. **Неожиданные исключения в неё не превращаются** — у них своя
классификация (`docs/rules/runtime-error-classification.md`).

## Перечень кодов

**Перечень кодов живёт здесь, у модели ошибки, одним списком на обе
половины расчёта**, а не у каждого калькулятора своей половиной. Код —
наблюдаемое значение: он уезжает в последнюю ошибку строки исполнения
(`docs/models/domain/other/DealActionState.md`; отказ по стороне уровня в
учёт строки не попадает — `docs/processes/risk-evaluation.md`) и в лог
оркестратора расчёта, и читается человеком при
разборе отказа, а читатель отказа не знает заранее, какая половина его
произвела. Поведение, породившее отказ, по-прежнему описывает дом своего
калькулятора; здесь — словарь: код, кто отказывает и на каком операнде.

**Где лежит константа кода — отдельный признак, и он о ветвлении, а не о
наблюдаемости.** Код, нужный вне одного калькулятора, — его **сравнивает**
вызывающий либо производят обе половины расчёта, — объявлен в общем доме
кодов расчётного слоя (`CalculationErrorCodes`); прочие — константами
своего калькулятора. На перечень это не влияет. Сравнивает коды сегодня
звено прохода ядра, отличая отказ шага от аварии сделки
(`docs/processes/risk-evaluation.md`).

**Расчёт цены** (`docs/components/PriceCalculator.md`):

| Код | Тип | Повод |
|---|---|---|
| `NO_REFERENCE_PRICE` | временная | рыночной цены нет: снапшота цен нет либо нужная цена в нём пуста — последняя у рыночного ориентира, объявленный источник у базы «рыночная цена»; когда пуста середина спреда — `docs/components/models/MarketPriceData.md` |
| `PRICE_SOURCE_UNAVAILABLE` | постоянная | объявленный источник рыночной цены снапшотом не несётся — марк- и индексная цена |
| `MISSING_STRUCTURE` | временная | структуры по объявленному ключу нет либо в ней нет нужного уровня (либо у уровня нет цены). У базы размещения соседний уровень не подставляется; у стопа по структуре вместо отсутствующего свинга берётся граница диапазона, и отказ — когда нет обоих |
| `MISSING_ATR` | временная | значения волатильности по ключу нет, оно другого индикатора либо само число пусто |
| `MISSING_STOP_LOSS_SETTINGS` | постоянная | действию нужен уровень остановки убытка, а настроек стопа у него нет |
| `MISSING_DISTANCE` | постоянная | доля дистанции не объявлена там, где способ её требует (стоп долей от входа, от волатильности, от структуры; тейк), либо у трейлинга нет блока настроек |
| `ENTRY_ANCHOR_UNAVAILABLE` | временная | живой эпизод есть, а средняя цена входа не наблюдена: якорь уровня пуст |
| `FEE_RATE_UNAVAILABLE` | временная | ставка комиссии не резолвится, и безубыток считать не из чего; тот же код даёт расчёт размера входа |
| `BREAKEVEN_LEVEL_UNAVAILABLE` | постоянная | ставка вырождает знаменатель точной формы безубытка |
| `MISSING_TICK_SIZE` | постоянная | правил инструмента либо шага цены в них нет, либо шаг неположителен — там, где цена округляется |
| `INVALID_PRICE_AFTER_ROUNDING` | постоянная | цена после округления неположительна |

**Расчёт размера** (`docs/components/SizeCalculator.md`):

| Код | Тип | Повод |
|---|---|---|
| `MISSING_SIZE_SPECS` | постоянная | правил инструмента нет либо набор полей сайзинга неполон: размер нельзя привести к торговой единице |
| `MISSING_RISK_BASE` | постоянная | база риска не резолвлена либо неположительна |
| `MISSING_RISK_LIMIT` | постоянная | детали стратегии нет либо поактный потолок риска в ней не объявлен |
| `MISSING_ENTRY_PRICE` | постоянная | цена входа в результате расчёта цены пуста либо неположительна |
| `MISSING_STOP_PRICE_FOR_SIZING` | постоянная | вход не объявляет уровня остановки убытка: worst-case выхода не существует, и размер по доле аллокации на его месте был бы благоприятным умолчанием |
| `FEE_RATE_UNAVAILABLE` | временная | ставка комиссии не резолвится: обе ноги издержки неизвестны |
| `STOP_LEVEL_NOT_ON_LOSS_SIDE_FOR_SIZING` | постоянная | убыток на контракте с round-trip комиссией неположителен, то есть уровень остановки лежит **за безубытком**, и размера по риску не существует (форма — `docs/spec/order-sizing.json`, величина `perContractRisk`). «Убыточная сторона» в имени — в смысле сайзинга, с комиссией: полоса между якорем и безубытком сюда не попадает, её держит преконтроль (`docs/components/SizeCalculator.md`) |
| `MISSING_ALLOCATION` | постоянная | доля аллокации входа не объявлена |
| `MISSING_CLOSE_FRACTION` | постоянная | доля закрытия не объявлена — у reduce-only заявки либо у частичного типа условной заявки |
| `MISSING_TRANCHE_EXPOSURE` | постоянная | транша в контексте нет: у экспозиции нет владельца |
| `LADDER_PREVIOUS_STEPS_UNKNOWN` | постоянная | сумма уже поставленных ступеней защитного набора не предъявлена при лестнице из нескольких ступеней: прочитанная нулём, она отдала бы последней ступени всю экспозицию (`docs/rules/live-risk-protection.md`) |
| `PROTECTION_LADDER_STEP_BELOW_MIN_SIZE` | постоянная | ступень защитной лестницы меньше минимального торгового размера |

## Механизм сигнализации

Субкалькуляторы бросают внутреннее исключение, несущее эту ошибку;
оркестратор расчёта его перехватывает и возвращает результат с ошибкой.
Внешний контракт слоя расчёта **возвратный**, а не бросковый.

## Структура

Код ошибки, тип и признак повторяемости, короткое пояснение.

**Тип** разделяет временную нехватку наблюдения и постоянную
невыразимость: первая повторяется бюджетом действия, вторая исполнения не
получает.

**Тип выводится из повода.** Отказ **временный**, когда недостающая
величина — наблюдение рынка либо площадки, которое производит чужой
писатель своим тактом, и следующий проход может его застать: цена,
значение индикатора, структура рынка, средняя цена входа живого эпизода,
ставка комиссии. Отказ **постоянный**, когда недостаёт объявления
стратегии, справочного правила инструмента либо сборки контекста, или
когда величина наблюдена и вырождена: повтор без правки стратегии дал бы
тот же отказ. Тип — функция кода, и колонка «Тип» перечня выше называет
его у каждого; повод, который отвергается созданием стратегии (ключ
операнда не объявлен, под ключом волатильности лежит другой индикатор),
получает тип своего кода — до расчёта он не доезжает.

**Временный отказ, исчерпавший бюджет повтора, ведёт туда же, куда
постоянный.** Исчерпание бюджета — самостоятельный исход, уводящий
действие штатной ошибочной тропой, как и у исчерпания бюджета команды
(дом исходов исполнения — `docs/components/ServiceCommandExecutor.md`):
иначе строка исполнения отказывала бы, а сделка оставалась бы в
своём статусе без исполненного шага — у защитного действия это позиция
без обещанной защиты.

**Что делает `PERMANENT` со сделкой — решает не тип, а код.** По общему
разбору строка исполнения уходит в отказ, и сделка — в ошибочное
состояние; временный отказ до исчерпания бюджета ставит строку в ожидание
повтора, а сделку оставляет в её статусе
(`docs/processes/strategy-action-calculation.md`). Названные исключения
перечисляет схема реакции
(`docs/processes/risk-evaluation.md`): у них шаг не исполняется, а сделка
остаётся в своём статусе. `STOP_LEVEL_NOT_ON_LOSS_SIDE_FOR_SIZING` —
`PERMANENT` и такое исключение: уровень, выведенный из живой рыночной
структуры, ушёл за безубыток, а живой риск при этом под контролем.

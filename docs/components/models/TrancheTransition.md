# TrancheTransition

## На какой вопрос отвечает этот файл

Что это за runtime-объект.

## Назначение

Исход одного прохода FSM **транша**: команды и, если он разрешён, новый
статус транша. RVO, не persisted.

## Структура

| Поле | Тип | Назначение |
|---|---|---|
| `commands` | `List<ServiceCommand>` | Команды прохода этого транша. |
| `nextStatus` | `DealTranche.Status` | Целевой статус; пусто — ребра нет. |
| `closeReason` | `DealTranche.CloseReason` | Причина закрытия; едет с терминальным ребром. |
| `dealErrorRequested` | `Boolean` | Просьба увести СДЕЛКУ в ошибку. |
| `shutdownRequested` | `Deal.ShutdownReason` | Причина, с которой просят увести сделку. |
| `holdSignal` | `HoldSignal` | Затребованная ступень. |

## Ребра в ошибочный статус здесь нет и быть не может

У транша такого статуса не существует. Отказ, который нельзя разобрать на
месте, поднимается обработчику сделки **признаком**, и ошибочное состояние
ставится на СДЕЛКЕ (`docs/lifecycles/DealTranche.md`).

## Затребованная ступень — намерение, а не право

Переход её только несёт; поднимает ступень петля прохода, одной точкой на
оба уровня (`docs/components/DealOrchestratorJob.md`). Прямой вызов службы
ступеней из транша замкнул бы зависимость в цикл.

## Причина закрытия едет вместе с терминалом

Писатель причины — обработчик терминального ребра, и пишет он её той же
транзакцией, которой ставит статус
(`docs/lifecycles/DealTranche.md` §«Писатель причины закрытия транша —
обработчик терминального ребра»).

## Границы

Живёт только в памяти прохода — читателя за сериализацией нет.

# InstrumentExternalRulesSyncJob

## На какой вопрос отвечает этот файл

Кто обновляет внешние справочные данные инструмента (компонент-job): что
делает, источники, частота.

## Назначение

`InstrumentExternalRulesSyncJob` обновляет из REST биржи:

- `InstrumentExternalRules` — навес правил инструмента (см.
  `docs/models/domain/other/InstrumentExternalRules.md`);
- `TradeFeeRate` — ставку комиссии комиссионной группы аккаунта (см.
  `docs/models/domain/other/TradeFeeRate.md`), источник прогнозной комиссии в
  риск-сайзинге (N9, шаг 7).

> **Материализуется на шаге 5** (риск-преконтроль — потребитель
> ограничений инструмента; решение
> `docs/decisions/instrument-external-rules-materialization.md`). В
> активную оркестрацию шага 1 (`docs/processes/candle-loading.md`,
> `docs/processes/market-data-calculation.md`) **не входит**:
> идентичность инструмента в шаге 1 синхронизируется отдельно
> (онбординг — `docs/lifecycles/Instrument.md`, граница —
> `docs/models/mapping/Instrument.md`), через тот же endpoint
> спецификации; rules-навес обновляется этой джобой.

На первом этапе обновление только через REST; WebSocket для instruments
можно добавить позже. `InstrumentExternalRules` меняется редко, поэтому
хранится в БД как актуальный snapshot правил инструмента.

## Источники: два, разной природы

| Источник | Операция | Природа | Лимит |
|---|---|---|---|
| Правила инструмента | `GET /api/v5/public/instruments` | **публичный** — auth не нужен | по **IP** + Instrument Type |
| Ставка комиссии | `GET /api/v5/account/trade-fee` | **приватный** — permission `Read`, подпись | 5 req / 2 s по **User ID** |

Разная природа — не декоративная деталь: у приватного источника лимит
считается по **аккаунту**, поэтому число его вызовов за тик не должно расти
вместе с числом инструментов (см. §Такт). Контракт операции ставки —
`docs/integrations/okx/contracts/trade-fee.md`.

## Такт: ставка читается раз на тик, не на инструмент

**Один** вызов `trade-fee(instType=SWAP)` **до** цикла по инструментам → карта
(`instType`, `groupId`) → ставки; далее per-instrument матч **по паре**
(`InstrumentExternalRules.externalInstrumentType`,
`InstrumentExternalRules.externalFeeGroupId`). **Не** N вызовов на N
инструментов.

**Матч по паре, не по голому `groupId`** (H8, `GAPS_CLOSE_4`): одно и то же
число `groupId` значит разное при разном `instType`
(`docs/decisions/pnl-finalization-mechanics.md` реш.4). Обе половины ключа —
**сырые** поля навеса, теми же значениями, что и ключ строки `TradeFeeRate`
(`docs/models/domain/other/TradeFeeRate.md` §«Масштаб модели»), без доменных
проекций. Прежняя редакция матчила по одному `groupId` — на контуре из
нескольких `instType` это дало бы **молча неверную ставку**.

**Группа не нашлась** (пары нет в карте ответа) — строка не пишется, ставка
группы стареет штатным путём (§«Свежесть ставки → холд инструментов группы»).
Подставлять ставку соседнего `instType` нельзя — это и есть тот молчаливый
отказ.

**Почему.** Ось ставки — **комиссионная группа**, а не инструмент
(`docs/models/domain/other/TradeFeeRate.md` §«Масштаб модели — группа, не
инструмент»): N вызовов на N инструментов вернули бы одни и те же строки
группы N раз. При этом лимит приватного источника — по **User ID**, поэтому
per-instrument чтение упирается в него на росте числа инструментов: расход
квоты растёт с N, а новых фактов не приносит.

## Делает

- читает правила инструмента из REST;
- маппит client-модель в `InstrumentExternalRulesExternalSnapshot`,
  затем в `InstrumentExternalRules` (OKX-маппинг —
  `docs/models/mapping/InstrumentExternalRules.md`);
- сохраняет/обновляет актуальный snapshot правил и **подтверждает навес**:
  на каждом успешном чтении `instruments` **явно проставляет
  `Instrument.externalModifiedAt` = момент подтверждения** — это и есть
  измеритель свежести **ключа группы**
  (`docs/models/domain/other/InstrumentExternalRules.md` §«Свежесть ключа
  группы», H11 `GAPS_CLOSE_7`). Собственных `refreshCount`/`confirmedAt` у
  навеса **нет** — они сняты: метка живёт колонкой строки-владельца и
  переживает перезапись JSONB. Запись метки **явная** (биржевые `external*`
  пишет код, производящий данные, а не JPA auditing), поэтому
  dirty-проблема, из-за которой понадобился `TradeFeeRate.refreshCount`,
  здесь не возникает. **Этот синк — единственный писатель метки** (H21
  `DOCS_CHECK_10`): онбординговый `SYNC` спецификации её не пишет и
  писать не может — граничный снапшот шага 1 поля времени не несёт, и в
  коде присваиваний `Instrument.externalModifiedAt` ноль. Прежняя
  формулировка «писателей ровно два, оба читают тот же эндпоинт» снята;
  требование «эндпоинт один» держится и при одном писателе;
- читает ставки комиссии одним вызовом `trade-fee` на тик и **пишет
  `TradeFeeRate`** по правилу
  `docs/models/domain/other/TradeFeeRate.md` §«Запись: история значением,
  свежесть счётчиком»: значение группы (taker/maker/`level`) изменилось →
  новая строка; совпало → инкремент `refreshCount` + обновление `externalModifiedAt`
  последней строки. Механику записи здесь не дублируем — дом правила там
  (mapping — `docs/models/mapping/TradeFeeRate.md`);
- при исчерпании **порога свежести** — ставки группы **или** ключа группы на
  навесе — **выставляет** мягкий холд затронутых инструментов (см.
  §«Свежесть ставки → холд инструментов группы»). **Снимает не он:** снятие
  ручное, оператором (`docs/rules/instrument-hold.md` §Снятие). Синк —
  односторонний писатель холда: восстановившееся чтение статус не
  возвращает.

**Валют инструмента этот синк не пишет** (H10 `DOCS_CHECK_12`).
`Instrument.externalSettlementCurrency` / `externalBaseCurrency` /
`externalQuoteCurrency` заполняет **тропа заведения инструмента** (переход
`CREATED → SYNC`, `docs/lifecycles/Instrument.md`) — значения считаются
неизменными и периодического подтверждения не требуют, поэтому второго
писателя у них нет (`docs/decisions/instrument-currencies-home.md`
§«Писатель — тропа заведения»). Перечень §Делает выше — полный: валюты в
него не входят намеренно. Формулировка «валюты приходят тем же синком» в
проекте была двузначной и снята: «тот же синк» писателя не определяет — тот
же вывод, что уже сделан для метки свежести (H21 `DOCS_CHECK_10`, выше).

## Операционные детали

- **Scope:** синхронизирует инструменты в статусах `SYNC`,
  `CANDLES_LOADING`, `ACTIVE`. Контур фазы 1 — **SWAP-only**
  (`docs/rules/trading-constraints.md` §Контур), поэтому чтение ставок одним
  вызовом `trade-fee(instType=SWAP)` покрывает scope целиком: инструментов
  других `instType` в контуре нет. Появись такой инструмент — пара
  (`instType`, `groupId`) не найдётся в карте ответа, ставка не запишется, и
  инструмент штатно уйдёт в реджект `FEE_RATE_UNAVAILABLE` (ставки не было
  никогда), а не получит чужую ставку молча (H8, `GAPS_CLOSE_4`).
- **Расписание:** guarded `@Scheduled`-джоба, CRON из конфигурации
  (по умолчанию раз в час, `0 0 * * * *`), выключатель `enabled`
  (`@ConfigurationProperties`) — при `false` запланированный и ручной
  тик ничего не делают.
- **Защита от конкурентного запуска:**
  `JobExecutionGuard.runExclusively` (in-memory на инстанс).
- **Вне расписания:** асинхронно через фасад
  `InstrumentExternalRulesSyncJobFacade`.
- **Изоляция по инструменту:** per-instrument try/catch — сбой одного
  инструмента не прерывает батч (логируется error); `null`-снапшот
  (инструмента нет на бирже) → warn + skip.
- **Изоляция по источнику:** отказ чтения `trade-fee` не роняет тик
  инструментов, отказ `instruments` не роняет чтение ставки. Источники разной
  природы (публичный / приватный) отказывают по разным причинам — общий тик не
  делает их общей судьбой.
  - **Изоляция — про тик, не про доверие к факту** (H9, `GAPS_CLOSE_6`).
    Отказ **каждого** из двух источников имеет свою реакцию по свежести:
    не подтвердилась строка ставки — стареет значение; не подтвердился навес
    — стареет **ключ группы**, и при исчерпании порога затронутые инструменты
    уходят под мягкий холд так же. Прежняя редакция описывала изоляцию без
    реакции на отказ `instruments` — из-за чего протухший ключ молча
    резолвился в чужую свежую строку.
- **Порог свежести ставки** — из конфигурации (`@ConfigurationProperties`),
  стартовое значение **24 ч**; не хардкод (codestyle §Джобы: пороги и флаги —
  из конфига).

## Свежесть ставки → холд инструментов группы

Возраст **любой из двух половин резолва** > порога свежести → **запрет
новых входов по затронутым инструментам** + `AnomalyReport`:

- `modifiedAt` актуальной строки `TradeFeeRate` группы (значение) —
  затронуты инструменты, чей ключ (`exchangeId` + пара
  (`externalInstrumentType`, `externalFeeGroupId`) навеса) резолвится в
  устаревшую строку;
- `externalModifiedAt` строки инструмента (ключ группы, H11
  `GAPS_CLOSE_7`) — затронут сам инструмент. **Холд ставится только по
  протуханию подтверждённой метки** (была свежей → устарела). Пустая
  метка (`NULL` — синк по этому инструменту ещё не отработал) холдом
  **не является**: инструмент просто не попадает в entry-скан по
  невыполненному предусловию, и это снимается первым же успешным тиком
  (H21 `DOCS_CHECK_10`;
  `docs/models/domain/other/InstrumentExternalRules.md` §«Начальное
  состояние измерителя», `docs/components/EntryScannerJob.md`). Разница
  несущая: холд sticky и снимается оператором, предусловие —
  самоизлечимо.

**Писатель холда на этой тропе — сам синк, и это ратифицировано** (H12
`GAPS_CLOSE_13`, решение пользователя). Перечень зовущих `HoldService`
**открыт**, инвариант «единственный исполнитель блокировки» снят: синк
проставляет `ENTRY_BLOCKED` инструментам радиуса напрямую, через
`InstrumentDataService`. Цена названа: идемпотентность по статусу scope
(повтор по инструменту, уже находящемуся в `ENTRY_BLOCKED`/`TRADE_BLOCKED`
— no-op; обратной эскалации нет) синк держит **у себя**, поскольку не
проходит через общего исполнителя
(`docs/components/HoldService.md` §«Кто зовёт»). Журнальный
`AnomalyReport` на этой тропе производит **тоже синк** — как детектор
факта, а не как следствие класса реакции (H14 `GAPS_CLOSE_13`).

**Реакция мягкая: kill-switch не применяется, живые сделки доживают под
своим стопом** и сопровождаются штатно (H2, `GAPS_CLOSE_5`;
`docs/rules/instrument-hold.md` §«Несвежесть ставки комиссии»,
`docs/models/domain/other/TradeFeeRate.md` §«Свежесть → холд инструментов
группы»). Точка enforcement — `Instrument.Status.ENTRY_BLOCKED`, **не**
`TRADE_BLOCKED` (H3, `GAPS_CLOSE_6`: последний уводит активные сделки в
`ERROR`). **Снятие — вручную** (H2, `GAPS_CLOSE_6`): синк холд ставит, но
не снимает.

**Радиус — по режиму отказа** (H4, `GAPS_CLOSE_5`): «вызов не прошёл» —
все группы одного вызова разделяют судьбу ⇒ радиус **аккаунт**, входы
стоят по всем инструментам контура; «группа отсутствует в ответе» ⇒ радиус
— **только эта группа** (остальные подтверждены тем же ответом); «синк
выключен» (`enabled = false`) — **не источник холда** (штатная
эксплуатационная операция). Перечень и сводная таблица —
`docs/rules/error-handling-policy.md` §«Перечень scope и реакций».

**Как отказ доезжает до холда без счётчика отказов.** Чтение упало → строка
группы не подтверждается → `refreshCount` не инкрементится → `modifiedAt` не
двигается → возраст растёт сам; при исчерпании порога срабатывает холд.
Последняя известная ставка при этом **не затирается** — потому что на отказе
**не пишется ничего** (история append-only: актуальная = последняя строка,
она просто остаётся последней и стареет). Отдельный счётчик неудач не нужен:
`modifiedAt` двигается при каждом **успешном** чтении — за счёт инкремента
`refreshCount`, который делает строку dirty, — поэтому его возраст уже и есть
время с последнего успеха. Полный довод и закрытые на нём отказы —
`docs/models/domain/other/TradeFeeRate.md` §«Свежесть измеряется, а не
предполагается»; про снятую атрибуцию IGNORE-null —
`docs/models/mapping/TradeFeeRate.md` §«Error policy».

## Почему такт такой (отвергнутые варианты)

- **(B) Отдельная `TradeFeeSyncJob` на своём такте** — отвергнут: **два
  писателя в один JSONB-навес** дают read-modify-write гонку / lost update.
  `JobExecutionGuard` — per-job (in-memory на инстанс), джобы друг друга не
  видят, поэтому от гонки двух разных джоб он не защищает. Один писатель навеса
  — один такт. **Вернуться к (B)**, если приватный контур потребует своего
  такта (свой лимит, своя частота, свои права).
- **(C) Читать ставку на входе в сделку** — отвергнут: exchange-вызов на
  горячем пути входа — точка отказа **в момент входа**, и покупается этим
  устранение **дрейфа ставки между тиками**, а не всей комиссии. Ставка и
  тир меняются редко (единицы раз в год,
  `docs/models/domain/other/TradeFeeRate.md` §Запись), поэтому за час между
  тиками ставка почти всегда та же: (C) убирает величину, близкую к нулю, а
  вносит отказ входа в момент входа. Цена отказа несопоставима с ценой
  устаревания **на такте**.
  - **Довод уточнён (H12, `GAPS_CLOSE_4`)** — вывод не изменился, изменилась
    его опора. Прежняя формулировка («свежесть величины ~5 bp против стопа
    1-2%») стояла на двух неверных посылках: (1) «стоп 1-2%» — **не свойство
    системы**, конкретные расстояния стопа нигде не зафиксированы и
    сознательно оставлены отдельной осью
    (`docs/rules/risk-creating-entry-protection.md`); (2) сравнивалась не та
    величина — раз-на-тик рискует **дрейфом** ставки между тиками, а не её
    **уровнем** (~5 bp). Обе поправки вывод переживает: комиссия при узком
    стопе от риск-бюджета вовсе не мала (при стопе 1% round-trip taker ≈ 9%
    бюджета), но за час она не меняется — а именно это и покупала бы (C).
  - **Чем перевывести.** Если геометрия сдвинется так, что ставка начнёт
    меняться внутри такта (смена тира внутри дня на большом обороте) —
    довод перестаёт держать, и ответ даёт **история `TradeFeeRate`**: сколько
    строк в год у группы. Датчик для этого уже стоит (`externalFeeLevel` +
    `refreshCount`) — пусть отвечают собственные данные, а не догадка.

## Связи

Правила инструмента используются для округления цены/размера, расчёта размера
в контрактах, проверки min/max limits, биржевого max leverage и торгуемости
инструмента (`status`). Ставка комиссии — прогноз комиссии в риск-сайзинге
(`docs/decisions/per-trade-risk-policy.md` §«Учёт комиссий»,
`docs/components/SizeCalculator.md`); недоступность ставки — реджект
`FEE_RATE_UNAVAILABLE` (`docs/components/RiskValidator.md`).

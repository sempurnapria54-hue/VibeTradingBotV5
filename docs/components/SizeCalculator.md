# SizeCalculator

## На какой вопрос отвечает этот файл

Кто рассчитывает размер действия.

## Что делает

Считает размер заявки или условной заявки и возвращает результат расчёта
размера. Цену не считает, но принимает рассчитанную цену входом.

```java
CalculatedSize calculate(CalculationContext context, CalculatedPrice price);
```

## Размер в контрактах

```text
baseQty          = нотинал / цена
contracts        = baseQty / размер контракта
contractsRounded = округление вниз по шагу лота
```

Размер контракта, шаг лота и минимальный размер — из справочных правил
инструмента.

## Вход: сайзинг под поактный потолок

Размер ограничен поактным потолком риска: убыток на стопе не превышает
`riskPerActionPercent × база риска`.

**Считается закрытой формой, не подбором** — комиссия пропорциональна
размеру, поэтому размер решается из неравенства. Форма и примеры —
`docs/spec/risk-limits.json` (`perContractRisk`).

Каждая нога комиссии — **по своей цене**: вход по цене входа, выход по
цене стопа. Оценка обеих по цене входа занижала бы комиссию выхода для
коротких позиций и давала бы им систематически больший размер.

Ставка читается аксессором справочных правил — без вызова биржи из
калькулятора и без отдельного поля контекста; ставка не резолвится —
вход блокирует преконтроль, калькулятор её не выдумывает.

- размер округляется по шагу лота и **снизу ограничен** минимальным
  торговым размером;
- если даже на минимуме убыток на стопе выше потолка — калькулятор
  возвращает минимум, а преконтроль блокирует вход;
- **сделочные потолки калькулятор не считает** — их проверяет преконтроль
  над готовым размером: подбирать размер под остаток бюджета значило бы
  выпускать ногу заведомо меньше объявленного, не сообщая об этом;
- **пола дистанции стопа нет**, и запас на проскок не закладывается —
  названные ограничения.

Потолок аллокации — желаемая доля; потолок риска — связывающий предел над
ней.

## Reduce-only выход: пола минимального размера нет

Размер закрытия — доля живой экспозиции, округлённая вниз.

**Подъём размера до минимума менял бы объявленное действие:** частичный
выход стал бы бо́льшим, вплоть до полного, — система сняла бы риск,
который стратегия снимать не объявляла. Ошибка односторонняя и тихая: ни
одна из минимальных проверок «закрыли больше объявленного» не выражает.

Вместо пола — три исхода округления:

| Округлённый размер | Исход |
|---|---|
| ≥ минимума и < живой экспозиции | штатный частичный выход объявленной доли |
| < минимума, и остаток после выхода тоже был бы < минимума | **выход целиком**: «частично» на этом размере невыразимо. Исход **объявляется** журнальным отчётом `PARTIAL_EXIT_ROUNDED_TO_FULL` |
| < минимума, остаток ≥ минимума | действие **не исполняется**; журнальный отчёт `PARTIAL_EXIT_BELOW_MIN_SIZE` |

## Защитная ступень — другой класс

**Последняя ступень набора получает остаток:**
`size_last = живая экспозиция − Σ размеров предыдущих ступеней`.
Округление вниз применяется к предыдущим ступеням, поэтому суммарное
покрытие получается ровно равным экспозиции.

Селектор «последней» и операнд суммы — `docs/rules/live-risk-protection.md`.

**Ступень меньше минимального размера — контролируемая ошибка расчёта**
(`PROTECTION_LADDER_STEP_BELOW_MIN_SIZE`), а не пропуск: шаг не
исполняется явно, с видимым отказом.

**Почему класс разведён.** У выхода «не исполнили» значит «ничего не
произошло»; у защиты то же «не исполнили» значит **«стоп не поставлен»**
— благоприятное умолчание, запрещённое
`docs/rules/absent-value-semantics.md`. Достижимость не краевая: вход
снизу упирается в минимальный размер, поэтому позиция меньше `N`
минимумов делает лестницу из `N` ступеней невыразимой.

## Границы

- Прямое частичное закрытие позиции не считает: полный выход идёт своей
  командой.
- Размер нельзя безопасно посчитать (нет размера контракта, шага лота или
  минимума) — контролируемая ошибка расчёта, а не приближение.

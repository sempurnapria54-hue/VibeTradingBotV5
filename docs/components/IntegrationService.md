# IntegrationService

## На какой вопрос отвечает этот файл

Кто является границей с биржей.

## Что делает

Единственная точка выхода на биржу: исполнители и добыча ходят наружу
только через неё.

**Сырой ответ источника за границу не выходит** — он разбирается в
проверенный граничный снапшот (`docs/rules/raw-exchange-dto-boundary.md`),
а наружу отдаётся **общая модель**: снапшот форму источника несёт, и у
второй площадки она своя.

## Входной контракт

**Дом перечня операций коннектора — здесь.** `contracts.md` называет пары
вызовов, этот раздел — что именно вызывается и в каких типах.

**Перечень полон против границы донора и проверяется компилятором.**
Исполнимая форма — интерфейс `ExchangeGateway` коннектора; каждая строка
таблиц ниже имеет в нём метод, и у каждого публичного метода читателя
источника есть выход наружу. Первая редакция раздела перечень **сузила**:
шесть операций донорской границы (живые и исторические algo инструмента,
история защит по ноге, закрытые эпизоды позиции, исторические свечи,
правила инструмента) остались без выхода, хотя их зовут `RefreshAlgoOrderExecutor`,
`RefreshOrderExecutor`, `RefreshPositionExecutor`, `CandleLoader` и
`InstrumentSyncJob` — то есть `trading-core` и
`market-data`. Сужение обнаружено контактом с кодом: методы читателя
остались без вызывающего.

### Два свойства, из которых выведён весь перечень

- **На входе доменные запросы, на выходе общая модель**
  (`docs/architecture/services.md`). Граничный снапшот наружу не выходит:
  он форма источника, и у второй площадки она своя. Перевод
  снапшот → домен делает сам коннектор, на своей стороне.
- **Коннектор стейтлесс и обслуживает любой счёт любого тенанта.**
  Отсюда: **всякий приватный вызов несёт идентификатор биржевого счёта**,
  по нему коннектор берёт ключи из Vault
  (`docs/architecture/tenant-and-exchange.md` §Ключи). Публичный вызов
  счёта не несёт — ключи ему не нужны, и требовать их значило бы связать
  чтение листинга с наличием счёта.

### Приватные операции — команды площадке

Вызывает `trading-core`. Все несут идентификатор счёта; все возвращают
`ExchangeAck` — подтверждение приёма, которое **истиной не является**
(`docs/rules/ack-not-runtime-truth.md`).

| Операция | Аргументы сверх счёта | Что делает |
|---|---|---|
| выставить заявку | `Order`, инструмент | ставит обычную заявку, с встроенной защитой либо без |
| отменить заявку | `Order`, инструмент | снимает выставленную |
| выставить algo-заявку | `AlgoOrder`, инструмент | ставит условную заявку |
| отменить algo-заявку | `AlgoOrder`, инструмент | снимает условную |
| отменить встроенную защиту | `AttachedAlgoOrder`, инструмент | снимает защиту, привязанную к заявке |
| закрыть позицию | инструмент, расчётная валюта | рыночное закрытие |
| установить плечо | инструмент, плечо | настройка счёта на инструменте |

**Замещения здесь нет:** оно доменное и собирается ядром из «выставить»
плюс «отменить» (`docs/architecture/contracts.md` §«Синхронные вызовы»).

### Приватные операции — добыча факта

Вызывает `trading-core`. Все несут идентификатор счёта; все возвращают
**доменные модели**, не снапшоты.

| Операция | Аргументы сверх счёта | Возвращает |
|---|---|---|
| заявка по идентификатору | инструмент, биржевой **либо** наш идентификатор | `Order` |
| живые заявки инструмента | инструмент | `List<Order>` |
| все живые заявки счёта | — | `List<Order>` |
| история заявок инструмента | инструмент | `List<Order>` |
| algo-заявка по идентификатору | инструмент, биржевой либо наш идентификатор | `AlgoOrder` |
| все живые algo счёта | — | `List<AlgoOrder>` |
| живые algo инструмента | инструмент, **род условия** | `List<AlgoOrder>` |
| история algo инструмента | инструмент, род условия, идентификатор | `List<AlgoOrder>` |
| живые материализованные защиты | инструмент | `List<AttachedAlgoOrder>` |
| история защит по ноге | инструмент, нога | `List<AttachedAlgoOrder>` |
| позиция инструмента | инструмент | `Position` |
| все позиции счёта | — | `List<Position>` |
| закрытые эпизоды позиции в окне | инструмент, начало окна | `List<Position>` |
| баланс расчётной валюты | расчётная валюта | `BalanceContainer` |
| движения средств за окно; их архив | окно | `List<DealCashFlow>` |
| ставки комиссии | тип инструмента | `List<TradeFeeRate>` |

**Род условия — операнд, а не удобство:** у площадки условные заявки
разных родов лежат в разных перечнях, и запрос без рода вернул бы не
«все», а один произвольный.

**Закрытый эпизод возвращается как `Position`** и несёт лишь то, что
сообщает запись закрытия (`docs/models/mapping/PositionCloseResult.md`).
Отдельной модели для записи закрытия нет: это та же позиция, в прошлом.

**Ставки комиссии — приватное чтение, и это не мелочь:** ставка есть
атрибут комиссионного уровня **счёта**
(`docs/models/domain/other/TradeFeeRate.md`), а не свойство площадки;
публичным её чтение сделало бы ставку общей для всех тенантов.

### Публичные операции — рыночные данные

Вызывает `market-data`. Счёта не несут.

| Операция | Аргументы | Возвращает |
|---|---|---|
| инструмент; листинг инструментов площадки | инструмент и/или тип инструмента | `Instrument` / `List<Instrument>` |
| **правила торговли инструментом** | инструмент, тип инструмента | `InstrumentExternalRules` |
| **тикеры всего листинга** | тип инструмента | `List<MarketTicker>` |
| **книга заявок инструмента** | инструмент, глубина на сторону | `MarketOrderBook` |
| **марк-цены листинга** | тип инструмента | инструмент → цена |
| **цены индексов** | расчётная валюта | индекс → цена |
| последние свечи инструмента | инструмент, таймфрейм, предел | `List<Candle>` |
| исторические свечи окном | инструмент, таймфрейм, верхняя граница, предел | `List<Candle>` |
| свеча индекса на момент | индекс, таймфрейм, момент | `Candle` |
| цены момента (last, mark, index) | инструмент | `MarketPriceData` |
| время площадки | — | момент |

**Правила торговли — отдельная операция, а не часть чтения
инструмента.** Площадка меняет их независимо от листинга, и читатель
синхронизирует их своим тиком; сложи их в одно чтение — и обновление
правил стоило бы обхода всего листинга.

**Чтение истории — окном, а не «всё, что есть»:** минутные свечи за годы
кладут и площадку, и базу читателя (`.claude/rules/codestyle.md`
§«Выборка данных»).

**Марк-цены и индексы отдаются картой, а не моделью:** это одна величина
на инструмент, и модель с единственным полем была бы носителем ради формы
(`.claude/rules/design-simplicity.md`). Срез цен собирает **вызывающий**
из трёх чтений — тикер площадки марк-цену и индекс не отдаёт
(`docs/models/domain/other/MarketTicker.md`).

**Открытый интерес, funding и ликвидации в перечне отсутствуют, и это не
пропуск.** Первые два собираются по требованию и приезжают с шагом, у
которого требование появится
(`docs/architecture/market-data-collection.md` §Восполнимое); у
ликвидаций нет канала, пока не добыт контракт WS (там же,
§«Невосполнимые срезы»).

## Контракт чтения

```text
найдено                          → доменная модель
успешно, но не найдено           → пусто
ошибка API, разбора, инварианта  → исключение
```

Пустой ответ означает «не найдено в этом источнике», а не ошибку;
трактовка зависит от сущности.

**Граничный снапшот из контракта ушёл, но не из коннектора.** Он
по-прежнему существует внутри — как форма, в которой ответ площадки
впервые разобран и проверен, — и именно на нём стоя́т проверки
инвариантов ниже. Наружу он не выходит: перевод снапшот → домен делает
сам коннектор, последним шагом чтения.

**Исключение — баланс:** успешное чтение обязано вернуть валидный снапшот
с расчётной валютой; иначе контролируемая ошибка, а не пустота.

### Классы отказа на границе — дом здесь

**По границе переезжает КЛАСС отказа, а не одно лишь «не получилось».**
Реакция на отказ — перевод сущности в ошибку, холд инструмента, холд
биржи — живёт у ядра (`docs/rules/controlled-exchange-exceptions.md`,
`docs/rules/exchange-hold.md`), а не у коннектора. Значит коннектор
обязан сказать, ЧТО именно случилось; свернув разные отказы в общий
статус, он решил бы за ядро.

Классы объявлены здесь, потому что владелец поверхности — коннектор;
обе стороны на этот перечень ссылаются, а не повторяют его.

| Класс | Что означает | Повтор помогает |
|---|---|---|
| `CREDENTIALS_UNAVAILABLE` | ключей счёта в хранилище нет | нет |
| `SECRET_STORE_UNAVAILABLE` | хранилище не ответило | да |
| `EXCHANGE_CREDENTIALS_REJECTED` | площадка отвергла ключи | нет — ступень биржи |
| `EXCHANGE_UNREACHABLE` | площадка не ответила либо ответ не разобран | да |
| `EXCHANGE_ERROR` | площадка ответила и объяснила отказ | по коду площадки |
| `EXTERNAL_STATUS` | статус получен, но неизвестен либо проблемный | нет |
| `EXTERNAL_INVARIANT_VIOLATION` | ответ нарушает инвариант торговли | нет |

**«Ключей нет» и «хранилище не ответило» — разные классы, и различие
несущее:** в первом случае повтор бесполезен (ключи не заводили), во
втором — единственно верен. Слитые в один класс, они дали бы одну
реакцию на две противоположные причины.

**`EXTERNAL_STATUS` несёт ещё и ПРИЧИНУ** — отдельным полем, а не внутри
текста: ядро ставит её причиной закрытия сущности
(`docs/rules/controlled-exchange-exceptions.md`, `closeReason =
reasonCode`), и оставь её только в сообщении для человека — ядру
пришлось бы разбирать текст, чтобы назначить исход сделке. Перечень
причин потому и общий (`libs/domain-model`
`domain/resolve/ExternalStatusReason`): производит их коннектор,
потребляет ядро.

**«Не найдено» в этот перечень не входит по двум разным причинам.**
Пустой ответ отказом не является (см. выше) — это первая. Вторая:
`ExternalNotFoundException` объявлен броском **ядра** после полного цикла
добычи улик, а не броском границы («нельзя бросать после одного пустого
ответа», `docs/rules/controlled-exchange-exceptions.md`). Коннектор его
не производит, и класса с таким именем на границе нет: класс без
производителя — механизм без предмета.

**Конкретные HTTP-коды провизорны** — их выравнивание по платформе идёт
одним ходом (`.claude/rules/codestyle.md` §«Обработка ошибок»); классы
выше от этого выравнивания не зависят.

## Проверка инвариантов контракта

Граница проверяет структуру ответа, обязательные поля и инварианты
источника — режим маржи, сторону позиции, тип и признаки заявки,
обязательные поля добытой записи закрытия.

Нарушение даёт контролируемое исключение **здесь**, где ответ впервые
разбирается, а не у потребителя.

## Отказ источника в наших кредах опознаётся здесь же

**Граница — единственный слой, который видит ответ источника**, поэтому
признак «креды отвергнуты» производит она, на любом приватном вызове.
Контролируемым исключением этот класс не является — он не о сущности, а о
праве контура обращаться к источнику, — и граница бросает собственное
исключение, не назначая сущности никакого исхода. Класс и его
ретраибельность — `docs/rules/runtime-error-classification.md`;
последствие — `docs/rules/exchange-hold.md`; перечень кодов, по которым
признак опознаётся, — `docs/integrations/okx/rules/auth-rejection-codes.md`.

**Опознание идёт по коду, а не по HTTP-статусу.** Статус у всего семейства
один, и по нему наш собственный дефект сборки запроса неотличим от
отвергнутых кредов, а реакции у них противоположные: первое лечится нашей
стороной, второе повтором не лечится вовсе.

## Границы

- Доменных решений не принимает и сущностей не сохраняет.
- Константы интеграции (режим маржи, сторона позиции) ставит сама и в
  домен не выносит.

# CreateOrderExecutor

## На какой вопрос отвечает этот файл

Кто исполняет создание обычной заявки.

## Что делает

Создаёт локальную заявку, генерирует стабильный клиентский
идентификатор, сохраняет рассчитанные параметры, создаёт встроенную
защиту внутри заявки, заполняет цель строки исполнения и двигает её
статус — **всё одной транзакцией**.

На биржу не ходит, цену не пересчитывает, условия не проверяет.

## Что пишет для входного действия

Той же транзакцией:

| Что | Куда | Свойство |
|---|---|---|
| база риска первого сайзинга | сделка | write-once — первым сайзингом любого транша |
| валюта риска | сделка | из расчётной валюты инструмента |
| шесть чисел планового риска ноги | создаваемая заявка | write-once, «шесть или ни одного» |
| два измерителя — запас до ликвидации и ёмкость стакана | создаваемая заявка | write-once, пусты, когда операнд не наблюдался |
| пересчёт четвёрки чисел риска сделки | сделка | производные проекции по заявкам всех траншей, пересчитываются целиком |
| принадлежность траншу | создаваемая заявка | `dealTrancheId`, из действия, чьё исполнение её породило |

**Пересчёт гейтится признаком полноты графа.** Признак `graphComplete`
читается готовым с контекста прохода (`docs/components/models/DealContext.md`);
ложен — числа не пишутся и звено не завершается. Правило, перечень
писателей и их триггеры — дом четырёх чисел риска
(`docs/models/domain/aggregate/Deal.md`); здесь оно не пересказывается.

**Числа ноги живут на ноге, а не на сделке:** write-once поле на сделке
при многоногом входе сохраняло бы число **первой** ноги и молча выдавало
его за сделку. То же верно для транша: своих чисел риска он не хранит.

**Величина риска приходит из преконтроля этого же действия.** Валидация и
создание идут одним проходом, поэтому durable-слота между проходами не
нужно; внутри прохода число доезжает полем payload команды. Пересчёт
формулы в исполнителе отвергнут: он завёл бы второй экземпляр той же
формулы.

## Встроенная защита

Создаётся внутри заявки и уходит на биржу **вместе с ней**. Ценовая база
триггера — объявленная стратегией; без неё вход не выпускается.

Размер встроенной защиты — из payload действия: защита **может** быть
поставлена на часть ноги, и покрытие считает это
(`docs/spec/protection-coverage.json`).

## Идемпотентность

Анкер — строка исполнения действия. Повтор до завершения пересоздаёт
локальную сущность по тому же клиентскому идентификатору; после
завершения — пустая операция.

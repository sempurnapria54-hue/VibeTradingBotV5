# MarketStructureJob

## На какой вопрос отвечает этот файл

Кто готовит структуру рынка.

## Что делает

Заранее считает уровни рынка и сохраняет результат под идентичностью
вычисления. Вычисление делегирует резолверу — джоба **тонкая**.

Источник — закрытые свечи окна; дополнительно готовые значения
индикаторов, адресуемые **идентичностями своих входов**.

## Шаги

- читает заказанные идентичности структуры из реестра;
- по таймфрейму идентичности берёт группы, готовые отдать историю;
- читает закрытые свечи окна (`lookbackBars` параметров идентичности);
- по объявленным идентичностям входов извлекает готовые скаляры из
  значений индикаторов и подаёт их резолверу;
- зовёт резолвер;
- сохраняет структуру и её ценовые уровни.

## Обходятся идентичности, а инструменты приносит сбор

Тот же довод, что у джобы индикаторов
(`docs/components/IndicatorJob.md`): настройки стратегий живут в базе
другого сервиса, а идентичности входов входят в идентичность результата
(`docs/models/domain/other/MarketStructure.md`).

Ни настроек стратегий, ни их владельцев джоба не знает: вход
адресуется идентичностью, и одна заказанная идентичность обслуживает всех,
кому её результат нужен.

## Объявленный вход не готов — консервативный исход

Идентичность входа объявлена, а готового значения нет — джоба **не зовёт
резолвер**: пишет результат окна со значением «неизвестно», чтобы
потребитель не торговал по недосчитанной структуре. Пропущенная строка
была бы неотличима от «ещё не считали», а подставленное значение
выглядело бы наблюдением, не будучи им.

Вход не объявлен — резолвер идёт своей веткой без этого входа.

**Различие держит джоба**, а не резолвер: она знает, что было объявлено.

## Свежесть входа здесь не гейтится

Правило и довод — `docs/rules/market-data-freshness.md`, дом политики
свежести. Точка отсчёта результата — `windowEndAt`.

## Границы

- Свечи не добывает.
- Семантику классификации не определяет.
- Идентичностей не заводит: их заводит команда требования.

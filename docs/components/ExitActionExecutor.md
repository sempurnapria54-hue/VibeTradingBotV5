# ExitActionExecutor

## На какой вопрос отвечает этот файл

Кто исполняет действие выхода из сделки.

## Что делает

Исполнитель действия выхода, объявленного шагом стратегии, — по одной
команде за проход.

**Действие выхода — не одна команда.** Команда закрытия закрывает позицию,
и всё; в стратегии закрытие одной позиции самостоятельного смысла не
имеет. Осмысленное действие — **выход**, и отмена живых входных заявок
входит в его состав, а не является внешней дочисткой: у действия транша —
его собственной, у действия сделки — всех траншей.

## Состав и порядок

Порядок задан инвариантом `docs/rules/exit-teardown-order.md`:

```text
живые входные (не reduce-only) заявки есть → отмена этих заявок
живых входных заявок нет → закрытие экспозиции
команда закрытия отправлена → дальше ведёт статус выхода
```

Область «этих заявок» задана уровнем действия: у выхода транша — его
собственные, у выхода сделки — заявки всех траншей. Закрытие
нетто-экспозиции одной командой законно только на втором
(`docs/rules/exit-teardown-order.md`).

**Закрытый объём команды исполнитель никуда не записывает:** он
приписывается траншам правилом сопоставления и считается производной
(правило сопоставления, `docs/models/domain/aggregate/DealTranche.md`).
Это и есть тропа выхода
эталонной стратегии (`actionKind = POSITION`), доведённая до терминала
транша в `docs/spec/strategy-walkthrough.json`.

**На этой форме обработчик координированного выхода своей команды
закрытия не эмитит** — иначе по одной позиции ушли бы две, и вторая
получила бы биржевой отказ на штатной тропе. Различитель форм — дом
`docs/rules/no-partial-close.md`;
встречный указатель — `docs/components/DealExitPendingHandler.md`, шаг 2.

Стадия выводится из **подтверждённых фактов**, а не из счётчика проходов.

**Reduce-only ноги под отмену этим действием не идут:** они риск снимают,
а не создают, и их дочищает обработчик выхода уже после подтверждённого
закрытия.

## Границы

- Преконтроль риска не вызывается.
- Статус сделки не двигает: переход — исход условий обработчика.

# RetryPolicyService

## На какой вопрос отвечает этот файл

Кто управляет повтором команд строки исполнения.

## Что делает

Отдаёт политику повтора по типу команды, отвечает, можно ли повторять, и
считает момент следующей попытки.

Политика хранится в конфигурации приложения — общая плюс переопределения
по типу команды.

## Модель политики

Тип команды, предел попыток, начальная задержка, максимальная задержка,
вид отката: фиксированный либо экспоненциальный.

## Авторитет предела — политика, читается живьём

**Предел определён только в политике** и читается каждый тик: предел
повторов — операционная крутилка, и правка должна браться сразу везде. На
строке исполнения предела нет — она несёт только счётчик.

Альтернатива «авторитет — поле сущности, фиксируется при создании»
отвергнута: тогда правка предела не бралась бы вживую.

## Предел — по команде, счётчик — по исполнению

**Предел** резолвится по типу **текущей** команды; **счётчик** — сквозной
бюджет отказов **одного исполнения действия**, без обнуления при
продвижении стадии.

У многозвенного системного действия применимый предел меняется со звеном
— это намеренно: звенья однородны по цене отказа, а бюджет у действия
один.

## Последняя ошибка хранится одним объектом

Состояние повтора на строке исполнения — три поля: счётчик попыток, момент
следующей допустимой попытки и **последняя ошибка** операции. Форма последней
ошибки — `RetryError`, и компонентов у неё три:

| Компонент | Что несёт |
|---|---|
| `code` | исходный код ошибки — например, код ответа площадки; пусто, когда исходного кода у отказа нет |
| `message` | сообщение для человека |
| `type` | классификация ошибки, задающая повторяемость (`docs/rules/runtime-error-classification.md`); пусто — исход «звено не завершено» (`docs/components/ServiceCommandExecutor.md`) |

**Хранится объектом в навесе, а не тремя колонками.** Код, сообщение и
классификация описывают один факт отказа, и три скалярные колонки завели бы
три носителя одной истины. Колонка навеса — `last_error` (`jsonb`), одна и та
же у обеих таблиц строк исполнения: `deal_strategy_action_states` и
`deal_system_action_states`. Объект переводится в навес и обратно
конвертером навеса ядра; пустая ошибка лежит пустой колонкой, а не объектом с
пустыми полями.

**Форма значения — запись, а не неизменяемый класс без пустого
конструктора.** У значения есть читатель: навес перечитывается при каждом
чтении строки, в том числе на тропе повтора — то есть тогда, когда что-то
уже пошло не так, и отказ разбора пришёл бы ровно туда. Запись сериализатор
собирает по канонической форме, ничего сверх неё не требуя; общее правило
формы — `.claude/rules/codestyle.md` §«Неизменяемое значение, пересекающее
сериализацию».

**Писатели ошибки — исполнители звена, а не этот компонент.** Исполнитель
служебной команды (`docs/components/ServiceCommandExecutor.md`) пишет её на
каждом отказе звена — и повторяемом, до решения о повторе, и закрывающем
строку без повтора; исходного кода у такого отказа нет, поле пусто.
Исполнитель прохода стратегии пишет её на отказе расчёта действия — с кодом и
сообщением отказа расчёта и классификацией `VALIDATION_ERROR`. Каждый отказ
перезаписывает предыдущий: истории ошибок строка не держит, только последнюю.

## Опасные команды

Команда, повтор которой может создать вторую внешнюю сущность,
повторяется только через поиск по стабильному клиентскому идентификатору:
сперва проверить, не встала ли она уже, и лишь затем слать снова.

## Границы

- Строки исполнения сам не двигает.
- Исход повтора не интерпретирует: классификация ошибок — не его предмет.

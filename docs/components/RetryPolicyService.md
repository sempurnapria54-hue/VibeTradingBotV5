# RetryPolicyService

## На какой вопрос отвечает этот файл

Кто управляет политикой повтора команд.

## Что делает

Отдаёт политику повтора по типу команды, отвечает, можно ли повторять, и
считает момент следующей попытки.

Политика хранится в конфигурации приложения — общая плюс переопределения
по типу команды.

## Модель политики

Тип команды, предел попыток, начальная задержка, максимальная задержка,
вид отката: фиксированный либо экспоненциальный.

## Авторитет предела — политика, читается живьём

Предел определён в двух местах: в политике и снимком на строке
исполнения.

**Авторитет — политика**, читается каждый тик: предел повторов —
операционная крутилка, и правка должна браться сразу везде. Поле на
строке исполнения — **снимок для истории**, а не операторное значение.

Альтернатива «авторитет — поле сущности, фиксируется при создании»
отвергнута: тогда правка предела не бралась бы вживую.

## Предел — по команде, счётчик — по исполнению

**Предел** резолвится по типу **текущей** команды; **счётчик** — сквозной
бюджет отказов **одного исполнения действия**, без обнуления при
продвижении стадии.

У многозвенного системного действия применимый предел меняется со звеном
— это намеренно: звенья однородны по цене отказа, а бюджет у действия
один.

## Опасные команды

Команда, повтор которой может создать вторую внешнюю сущность,
повторяется только через поиск по стабильному клиентскому идентификатору:
сперва проверить, не встала ли она уже, и лишь затем слать снова.

## Границы

- Строки исполнения сам не двигает.
- Исход повтора не интерпретирует: классификация ошибок — не его предмет.

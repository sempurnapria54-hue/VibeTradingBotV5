# StrategyActionOrchestrator

## На какой вопрос отвечает этот файл

Кто выбирает следующее действие стратегии за проход.

## Что делает

Для пакета шага выбирает следующее действие, гейтит повтор и
маршрутизирует действие в исполнитель своего типа.

```java
Optional<ServiceCommand> next(StrategyStep step, DealContext dealContext);
```

## Порядок выбора действия

**Пакет шага исполняется целиком; за проход — одно действие.**

**Ключ порядка — риск-класс действия: устанавливающие защиту раньше
снимающих** (`docs/rules/live-risk-protection.md`). Риск-класс
оркестратор резолвит и так — он определяет ветку преконтроля и порядок
ног замещения. Порядок вставки ключом порядка не служит; уровень действия
остаётся уровнем грид-сетки.

**Действие, чьё предусловие не выполнено, исполнения не начинает:** строка
исполнения не заводится, бюджет попыток не расходуется, шаг остаётся
неисполненным до следующего прохода. Верхней границы ожидания нет — всё
это время позицию держит прежняя защита.

## Гейт повтора

Исполнение, ожидающее повтора, отдаёт команду только по наступлении
времени следующей попытки. Завершённые и отказавшие строки терминальны:
новая надобность — новая строка.

**«Новая надобность» — не повтор того же шага на том же эпизоде.** Шаг
стратегии применяется на эпизоде транша однократно, и его строки
исполнения служат носителем этого признака
(`docs/rules/strategy-step-once-per-episode.md`). Гейт повтора считает
**попытки исполнить** надобность; сколько раз надобность возникает —
предмет того правила, не этого.

## Границы

- Статус исполнения сам не пишет — его двигают исполнители команд и учёт
  повторов.
- Состав команд действия не знает: это собственность исполнителя типа.
- Системные действия не ведёт.

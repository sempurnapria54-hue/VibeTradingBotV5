# FinalizeDealExitExecutor

## На какой вопрос отвечает этот файл

Кто исполняет `FINALIZE_DEAL_EXIT_COMMAND` (компонент-executor): что читает/пишет,
терминальное ребро, идемпотентность, retry-anchor, граница 6 ↔ 7.

## Назначение

Получает `FINALIZE_DEAL_EXIT_COMMAND` — консолидацию фактов штатного выхода после
того, как live risk снят, **и расчёт итогового `resultProfit`** (шаг 7).
**Читает** подтверждённые факты выхода (живого эпизода `Position` нет по
`REFRESH_POSITION_COMMAND`; нет live orders/algo; `Deal.CloseReason` определён) плюс
P&L-факты: `DealCashFlow` (категорийная разбивка, добыта **до него**
командой `REFRESH_BILLS_COMMAND`) и **положения закрытия на строках
эпизодов** (готовый net `realizedPnl` в поле
`Position.externalRealizedProfit` каждой строки) — см.
§«Положение закрытия — читается со строки».

**Число сделки — Σ по эпизодам** (`docs/decisions/multi-episode-deal.md`):
сделка многоэпизодна, и финализатор складывает готовые net'ы её строк, а
правые операнды четырёх пар сверки берёт суммами по тем же строкам.
Эпизод без добытого положения закрытия делает число **недоступным**
(звено не завершается), а не заниженным: подстановка нуля запрещена
(`docs/rules/absent-value-semantics.md`). Для **допуска сверки**
дочитывает операнды планового риска **по каждой ноге входа**
(`Order.plannedRiskAmount` / `plannedEntryPrice` / `plannedSizeContracts` /
`plannedContractValue` / `plannedStopPrice` — все пять write-once на самой
ноге; attached-защита операндом быть перестала, Р3 `GAPS_CLOSE_16`) — §«Сверка
bills ↔ net». **Навес `InstrumentExternalRules` не читает** (H5
`DOCS_CHECK_16`): все операнды тождества — persisted-факты ноги.
**Вычисляет** net-число +
сверяет сумму `DealCashFlow` с net
(`docs/decisions/result-profit-source.md`); **пишет
`resultProfit`/`resultProfitCurrency` прямо на `Deal`** (persisted) в
**одной транзакции** с durable-продвижением своего звена в исполнении
`FINALIZE_DEAL_EXIT_ACTION` (N7 — durable-носитель числа = поле `Deal`,
рестарт-safe; транзакционная клауза —
`docs/decisions/command-action-boundary.md` §5). На биржу **сам не ходит**
— интеграционное чтение остаётся за `REFRESH_*`-командами; `RiskValidator`
не вызывается (`docs/rules/risk-validator-scope.md`).

## Положение закрытия — читается со строки

Биржевой факт закрытия **персистится на `Position`** второй ногой
`REFRESH_POSITION_COMMAND` (H1/H3, `GAPS_CLOSE_7`;
`docs/models/domain/core/Position.md` §«Положение закрытия»). Для
финализатора это значит:

- **никакой вложенной команды.** Прежняя редакция (H13, `GAPS_CLOSE_6`)
  исполняла `REFRESH_POSITIONS_HISTORY` **вложенным шагом внутри**
  `FINALIZE_DEAL_EXIT_COMMAND`, потому что считала снапшот транзитным и не
  пересекающим границу прохода. Посылка снята: факт durable, и
  «команда внутри команды» — конструкция, которой канон не знает
  (`docs/rules/command-lifecycle.md`). Аналогия «как REPLACE композирует
  свои ноги» была ложной: ноги REPLACE секвенсит **петля по проходам**
  (`docs/decisions/action-orchestration-vs-command.md`);
- **финализатор читает `Position` как обычные входные факты** — тем же
  чтением, которым берёт `Position.status` и `DealCashFlow`;
- **идемпотентность — на уровне действия**, анкер — строка исполнения
  **`FINALIZE_DEAL_EXIT_ACTION`** (вид SYSTEM,
  `docs/models/domain/other/DealActionState.md`). Рестарт до завершения
  перезапускает звено: число пересчитывается из тех же persisted-полей и
  пишется в той же транзакции. Рестарт после завершения — no-op.
- **поля пусты хотя бы у одного эпизода (запись закрытия не добыта) →
  звено не эмитится и не завершается** (узел 4 `DOCS_CHECK_8`, вариант (а)):
  `FINALIZE_DEAL_EXIT_COMMAND` эмитится `SystemActionExecutor` только по
  **терминальному исходу добычи** (`REFRESH_DEAL_CONTEXT_ACTION` довёл
  цикл), а без числа не завершается. Исчерпание бюджета добычи →
  ошибочная тропа + холд инструмента. Тропа «неисчислимо» — только
  аварийный контур (`docs/decisions/pnl-finalization-mechanics.md`
  §«Асимметрия троп отказа добычи»).

**Что это не меняет.** Отвергнутый в реш.1 вариант «fetch внутри
`FinalizeDealExitExecutor`» остаётся отвергнутым: на биржу ходит
**refresh-команда** со своим retry и своей идемпотентностью, финализатор
читает уже приземлённый факт. Паттерн «refresh populates → finalize
consolidates» сохранён и стал буквальным: populate пишет в свою строку,
consolidate её читает. `REFRESH_BILLS_COMMAND` — тоже **отдельная** эмитируемая
команда: её факт durable (`DealCashFlow` в БД).

## Расчёт прибыли (шаг 7) и сверка

**Расчёт `Deal.resultProfit` — здесь.** Шаг 6 поставил *механику* финализации
(retry-state, терминальное ребро, триггер, идемпотентность) и
интерим-placeholder ZERO; шаг 7 наделяет `FINALIZE_DEAL_EXIT_COMMAND` **расчётом и
записью числа** на `Deal`: Σ `Position.externalRealizedProfit` по эпизодам +
разбивка из `DealCashFlow` + сверка. `MARK_DEAL_CLOSED_COMMAND`
(`MarkDealClosedExecutor`) число **не пишет** — читает готовое `Deal.resultProfit`,
ассертит непустоту и ставит терминал `CLOSED` (N7). Placeholder ZERO снят.
- **Сверка bills ↔ net (N10) — раздельная по категориям** (H19
  `DOCS_CHECK_12`, решение пользователя, вариант 3; четвёртая пара — H7
  `GAPS_CLOSE_13`). Число **всегда** =
  positions-history net (bills его не подменяют). Сверяются **четыре
  пары**, все по строкам settle-ccy вне списка исключений биржи:

  | Слагаемое разбивки | Против числа биржи |
  |---|---|
  | Σ(`amount` − `externalFee`) по `REALIZED_PNL` | `pnl` |
  | Σ`externalFee` по торговым категориям (`REALIZED_PNL`/`TRADE_FEE`/`REBATE`) | `fee` |
  | Σ`amount` по `FUNDING` | `−externalFundingCost` |
  | Σ`amount` по `LIQ_PENALTY` | `externalLiquidationPenalty` |

  **Общее расхождение сверх epsilon** (`Σ|Δᵢ|` по четырём парам; отчёт
  называет разошедшиеся пары поимённо) → **`AnomalyReport`**
  `PNL_RECONCILIATION_MISMATCH` (аудит-аномалия, `scope = INSTRUMENT`,
  `severity = NON_CRITICAL` — тропа без kill-switch,
  `docs/lifecycles/AnomalyReport.md`), `Deal.reconciliationStatus =
  MISMATCHED`; сошлось — `MATCHED`. **Не блокирует** финализацию, сделка
  идёт в `CLOSED` (`docs/decisions/pnl-finalization-mechanics.md` реш.5).
  - **Почему раздельно, а не отдельным детектором funding.** Заявленный в
    доводе H20 `GAPS_CLOSE_11` «независимый детектор омиссии funding» не был
    материализован ни в одном доке: ни производителя, ни кода, ни допуска,
    ни области. Развилка не в допуске, а в форме: **одна сверка по
    категориям против двух сверок по числам**. Раздельные слагаемые дают ту
    же адресную проверку funding-омиссии (у длинной SWAP-сделки
    funding-поток — основная масса строк, и его омиссия и есть самый
    вероятный вид дыры), но **не заводят ни второго контроля, ни четвёртой
    провизорной величины**.
  - **Прямая цена варианта, входит в закрытие:** два поля positions-history
    (`pnl`, `fee`), прежде выведенные из снапшота, **возвращаются** в
    used-набор и в `PositionCloseResultExternalSnapshot`
    (`docs/models/mapping/PositionCloseResult.md`,
    `docs/models/integrations/okx/OkxPositionsHistoryResponse.md`). Без них
    правых операндов двух пар не существует.
  - **Знак funding приведён до сверки** (H20 `DOCS_CHECK_12`):
    `Position.externalFundingCost` нормализован **при маппинге в доменный
    снапшот** и является **издержкой** (положителен, когда фондирование
    уплачено), тогда как `DealCashFlow.amount` — сырой знаковый. Поэтому
    третья пара сравнивает Σ`amount` по `FUNDING` с **`−externalFundingCost`**;
    приведение выполняется **в одном названном месте** — в маппинге, не
    здесь (`docs/models/mapping/PositionCloseResult.md` §«Знак
    `fundingFee`»).
  - **Тождество, на котором стоит разложение:** `realizedPnl = pnl + fee +
    fundingFee + liqPenalty` (`docs/decisions/result-profit-source.md`).
    **Четыре пары исчерпывают его состав** — по одной на каждое
    слагаемое (H7 `GAPS_CLOSE_13`).
  - **Суммарной сверки Σ`amount` ↔ net больше нет.** Прежний довод,
    выводивший `LIQ_PENALTY` из-под контроля («отдельного числа биржи под
    неё в записи нет; вклад остаётся внутри суммарной сверки»), **ложен
    в обеих половинах**: поле `liqPenalty` у источника есть
    (`docs/integrations/okx/contracts/position.md` §История,
    `docs/models/integrations/okx/OkxPositionsHistoryResponse.md`), а
    суммарная сверка была заменена раздельными парами тем же решением,
    которое их вводило. Второго контроля с собственным допуском не
    заводится: свойство «число сверено целиком» даёт **исчерпание
    состава** четырьмя парами, а не пятое сравнение, чья область
    (Σ`amount` по всей разбивке) шире net'а на строки, которых в net'е
    нет по построению.
  - **Ликвидационный штраф — единственная категория левого хвоста.**
    `LIQ_PENALTY` возникает только на форсированных исходах и крупен на
    событие; без пары его омиссия оставалась бы ненаблюдаемой ровно в
    самой дорогой корзине распределения.

  Аномалию **по валюте** финализатор не ставит: она ставится раньше, на
  записи движения (`RefreshBillsExecutor`, H4 `GAPS_CLOSE_7`) — там же, где
  доступен операнд сравнения (расчётная валюта инструмента) и где движение
  пересчитывается.
- **Структурная неполнота разбивки — признак, а не молчание** (H23
  `DOCS_CHECK_12`; операнд и третье состояние — H27 и H4
  `GAPS_CLOSE_13`). Если сделка прожила дольше окна доступности движений
  **выбранного конвейера добычи**, часть строк недобываема ⇒ Σ`amount`
  заведомо не сойдётся с net, и сверка звенела бы **детерминированно**, а
  не по дефекту — то есть контроль, срабатывающий на каждом объекте своей
  популяции, был бы эквивалентен погашенному. Финализатор сравнивает
  **возраст нижней границы окна на момент добычи** с **глубиной архивной
  выдачи** и пишет `Deal.breakdownIncomplete`:

  | Условие | Значение |
  |---|---|
  | `max(t_добычи, billsWindowEnd) − billsWindowBegin` ≤ глубины | `COMPLETE` |
  | `max(t_добычи, billsWindowEnd) − billsWindowBegin` > глубины | `INCOMPLETE_BY_WINDOW` |
  | **операнд не добыт**: `billsWindowBegin` пуст **либо** добыча движений не выполнялась (окно не закрыто — `billsWindowEnd` пуст) | `NOT_ASSESSED` + журнальный `AnomalyReport` |

  - **Верхняя отметка — позднейший из двух моментов** (решение держателя П4
    валидации `GAPS_CLOSE_17`, вариант C): так операнд **монотонен** и не
    зависит от тропы — какой бы из двух моментов ни оказался старше,
    отметка не уезжает назад. Цена — один конъюнкт. Одноместный
    `t_добычи − billsWindowBegin` (предложение владельца) ошибался
    консервативно, но оставался тропа-зависимым.
  - **Операнд — возраст нижней границы, а не длительность окна** (H20
    `DOCS_CHECK_15`, решение пользователя). Недобываемость строки
    определяется тем, насколько **давно** она произошла к моменту
    обращения к источнику, а не тем, сколько окно длилось. Прежняя
    редакция сравнивала `billsWindowEnd − billsWindowBegin`, то есть
    теряла **лаг между закрытием окна и его добычей**, и ошибка была
    **односторонней в благоприятную сторону**: сделка с окном чуть короче
    глубины и ненулевым лагом получала `COMPLETE`, хотя часть строк уже
    недобываема, — и её `MISMATCHED` читался как дефект целостности вместо
    «звенит по построению». На штатной тропе лаг мал; на тропе через
    `ERROR` он не ограничен ничем записанным.
  - **`t_добычи` — момент исполнения финализирующего звена.** Звено идёт в
    том же действии сразу за добычей, лаг между ними ограничен одним
    проходом. Остаточная погрешность **односторонняя и консервативная**:
    она может пометить `INCOMPLETE_BY_WINDOW` сделку, чьи строки на момент
    фактической добычи ещё были доступны, — то есть в сторону «звенит по
    построению», а не в благоприятную. Новых полей и чтений операнд не
    требует: `billsWindowBegin` persisted, момент исполнения у звена свой.
  - **`billsWindowEnd` остаётся операндом обязанности сверки**
    (`docs/models/domain/aggregate/Deal.md` §«Признаки отбора для
    отчёта») и, с решением П4, входит **вторым** операндом признака
    полноты — под `max`. Ветка «добыча не выполнялась» сохраняется: там его
    пустота означает отсутствие разбивки, которую можно было бы мерить.

  - **Операнд — глубина `bills-archive`** (не первичного 7-дневного
    эндпоинта): конвейер команды добычи идёт `bills` → `bills-archive`
    (`docs/components/RefreshBillsExecutor.md`), и признак обязан
    сравниваться с концом **этого** конвейера, иначе он становится
    константой у любой сделки старше недели. Величина живёт **в
    конфиге** — не хардкодом в финализаторе и не в
    `adapter-constants` (H27 `GAPS_CLOSE_13`).
  - **«Недобываема выбранным конвейером», а не «в принципе».** Источник
    держит deep-архив глубже 3 месяцев (асинхронный двухшаговый флоу,
    `docs/integrations/okx/contracts/account-bills.md`), в конвейер
    финализации он не встаёт (12 запросов в сутки, ссылка через ~2 ч) —
    это **задел**, а не отсутствующая возможность.
  - **`NOT_ASSESSED` ≠ `COMPLETE`.** Благоприятное значение по умолчанию
    там, где сравнение не выполнялось, запрещено
    (`docs/rules/absent-value-semantics.md`): «не проверяли» и
    «проверили, всё в порядке» обязаны различаться, иначе сделка с
    недобытыми границами окна молча попадает в выборку «разбивка полна».

  Сделка из популяции **не выводится** — признак отделяет «звенит по
  дефекту» от «звенит по построению», и фильтрует по нему потребитель
  отчёта.
- **Epsilon — форма, область применения и операнды.**
  `epsilon = max( 0.01 settle-ccy, min( 0.5% × Σ|amount|, k × ожидаемая
  комиссия сделки ) )` (H15 `DOCS_CHECK_10`; пол вынесен наружу — H8
  `DOCS_CHECK_11`).
  - **Допуск один на сделку, не на пару** (H9 `GAPS_CLOSE_13`). Пары
    дают **состав** расхождения (какая категория разошлась — это
    попадает в отчёт), но порог применяется **однажды**, к **общему
    расхождению по сделке**: `Δ = Σ|Δᵢ|` по четырём парам против
    `epsilon`. Пер-парных якорей не вводится: они потребовали бы трёх-
    четырёх калибруемых величин вместо одной, а для funding-пары —
    операнда (ставка фондирования), которого в модели шага нет.
    Расхождения разных знаков берутся по модулю и **не гасят друг
    друга**: омиссия строки в одной категории не должна компенсироваться
    избытком в другой.
  - **Ожидаемая комиссия считается из persisted-операндов, ставка не
    перечитывается** (H7 `DOCS_CHECK_11`), и считается **поногово** (H6
    `DOCS_CHECK_15`, решение пользователя):

    ```text
    ожидаемая комиссия сделки =
      Σ по ногам входа i:
        plannedRiskAmount_i − |plannedEntryPrice_i − stop_i|
                              × plannedSizeContracts_i
                              × plannedContractValue_i
    ```

    **Все операнды слагаемого — persisted-поля одной и той же ноги**,
    включая уровень стопа `plannedStopPrice` (`docs/models/domain/core/Order.md`
    §«Плановый риск и его операнды»; attached-защита операндом быть
    перестала — Р3 `GAPS_CLOSE_16`). **Финализатор навес `InstrumentExternalRules`
    не читает вовсе** (H5 `DOCS_CHECK_16`, решение пользователя): прежняя
    редакция дочитывала оттуда `ctVal` — единственную величину тождества,
    не привязанную темпорально ко входу, — и тем ставила допуск в
    зависимость от синка справочника, переписывающего навес каждым тиком.
    Теперь `ctVal` момента постановки персистится на ноге пятым числом
    (`planned_contract_value`, write-once), и тождество целиком
    воспроизводимо из persisted-фактов — тем же доводом, каким проект
    отверг пере-чтение ставки комиссии
    (`docs/decisions/pnl-finalization-mechanics.md` реш.4).
    - **Почему поногово.** Тождество `plannedRiskAmount = ценовая часть +
      ожидаемая комиссия` верно ровно в одной точке — там, где риск и его
      операнды принадлежат одной ноге. Прежняя редакция брала
      `plannedRiskAmount` с `Deal`, а ценовую часть — с ноги; при
      многоногом входе это давало односторонний перекос в обе стороны
      (агрегат ⇒ вычитаемое ≈ N × ценовой части ⇒ **отрицательная**
      ожидаемая комиссия ⇒ `max(0.01, …)` схлопывает допуск до шум-флора
      на самых крупных сделках; первая нога ⇒ комиссия ~1/N реальной ⇒
      допуск систематически уже режима отказа). Переезд риска на ногу
      восстанавливает тождество, сумма разностей и есть ожидаемая комиссия
      сделки.
    - **Слагаемые отбирает бизнес-тип, страхует непустота числа** (решение
      держателя `GAPS_CLOSE_16`). Берутся ноги
      `Type ∈ {ENTRY, ENTRY_ATTACHED_STOP_LOSS}` с непустым
      `Order.plannedRiskAmount` — тот же предикат, что у суммы `R`
      (`docs/models/domain/aggregate/Deal.md` §«Предикат отбора
      слагаемых»); смешанного случая
      не бывает — либо вход наш (и риск-преконтроль записал риск каждой
      ноге), либо входных ног у сделки нет вовсе (популяция «позиция
      создана вне приложения», H23). Сумма по пустому множеству — **пусто,
      не ноль**: омиссионный член не участвует, `epsilon` вырождается в
      композиционный, факт помечается `AnomalyReport`
      (`PLANNED_RISK_MISSING`). Разбор —
      `docs/decisions/pnl-finalization-mechanics.md` реш.5 §epsilon.
  - **Уровень стопа `stop_i` — persisted-число ноги** (H10 `GAPS_CLOSE_13`;
    операнд переопределён Р3 `GAPS_CLOSE_16`, решение держателя). Операнд —
    `Order.plannedStopPrice` **этой ноги**: уровень, под который считался
    `plannedRiskAmount_i`, записанный write-once в момент постановки
    (`docs/models/domain/core/Order.md` §«`plannedStopPrice` — шестое
    число»). Тождество вычитания верно только с ним.
    - **Почему не из `Order.attachedAlgoOrders`.** Прежняя редакция брала
      уровень из встроенной защиты ноги. Решение Р3 сделало эту защиту
      **временной** — она снимается после пересчёта основной под
      увеличенную позицию (`docs/rules/risk-creating-entry-protection.md`
      §«Защита доборной ноги снимается…»), — а операнд тождества обязан
      быть воспроизводимым из фактов **постановки**, а не из состояния,
      которое стратегия вправе менять. Тот же довод, каким персистятся
      `ctVal` и reference-цена (`docs/decisions/pnl-finalization-mechanics.md`
      реш.4).
    - **Standalone-защита операндом не была и не становится:** `AlgoOrder`
      связан с `Deal` и ссылки на ногу не несёт, то есть «защита **этой**
      ноги» standalone-сущностью не адресуема. Дизъюнкт «либо
      `AlgoOrder…stopLoss.value` защиты той же ноги» остаётся снятым.
    - **Операнд резолвим у всякой ноги входа по одному основанию** —
      инварианту «шесть или ни одного»: непустой `plannedRiskAmount_i` при
      пустом `plannedStopPrice_i` недостижим, потому что оба числа
      производит один преконтроль и пишет одна транзакция.
    - **Ветка при трейлинге не достижима — проверено**: трейлинг и перенос
      стопа в безубыток живут на **основной standalone-защите**
      (`MANAGING`, `docs/lifecycles/Deal.md` §Статусы), которая защитой
      входной ноги не является; штатное правило «резолвить актуальную
      сущность как последнее звено цепочки замещений»
      (`docs/decisions/replace-not-amend.md`) к этому операнду поэтому не
      применяется. Persisted-число тем более неподвижно.
  - **Предикат селекции защиты операндом епсилона быть перестал** (Р3
    `GAPS_CLOSE_16`, решение держателя). Уровень стопа читается из
    persisted-числа ноги, поэтому выбирать элемент коллекции
    `attachedAlgoOrders` финализатору больше не требуется. Сам предикат
    (H12 `DOCS_CHECK_15`) сохраняется как описание того, какой элемент
    коллекции считается «той защитой, что стояла», — он нужен там, где
    коллекцию читают по другому поводу, — но **тождество епсилона на нём
    больше не стоит**. Берётся элемент `type = ATTACHED_STOP_LOSS` той же
    ноги, для которого истинно **одно из**:

    | Ветка | Условие |
    |---|---|
    | защита стоит на бирже | `status ∈ {PENDING, ACTIVE}` (`isActiveLike()`) |
    | защита стояла и была снята либо сработала | `status` терминален **и** `closeReason ∈ {TRIGGERED, SWITCHED_BY_STRATEGY, PARENT_ORDER_CANCELED, KILL_SWITCH, MANUAL_CANCEL}` |

    **Исключаются** элементы, которые уровня не несут: `status = ERROR`
    (заявка не встала — `failCode`/`failReason`) и `closeReason ∈
    {MISSING_AFTER_REFRESH, PROTECTION_LOST, UNKNOWN_EXTERNAL_STATUS,
    UNKNOWN}` (защита не подтверждена).
    - **Персист уровня стопа отдельным числом теперь требуется** — прежняя
      клауза «не требуется, операнды уже есть» **снята** решением держателя
      вместе с постоянством встроенной защиты доборной ноги. Довод
      «операнды уже есть» держался ровно на том, что защита ноги не
      снимается; решение Р3 её снимает.
    - **Ветка «операнд обязанной сверки не резолвится» снята** (решение
      держателя, позиция С3 валидации `GAPS_CLOSE_16`, вариант a). После H5
      её единственным производителем было вырождение предиката селекции («не
      ровно один элемент»); теперь предикат в резолве епсилона не участвует,
      а инвариант «шесть или ни одного» делает пустое `plannedStopPrice_i`
      при непустом `plannedRiskAmount_i` недостижимым. Ветка и журнальный
      код `RECONCILIATION_OPERAND_MISSING` **удалены**: реестр кодов не
      держит значений без производителя, а нарушенный инвариант данных
      ловит **детектирующий контур отказом операции** (§ниже).
  `TradeFeeRate` финализатор **не читает** — от её свежести и доступности
  epsilon не зависит.
  - **Ветки «операнд допуска не резолвится» у финализатора нет** (решение
    держателя, позиция С3 валидации `GAPS_CLOSE_16`, вариант a; прежние
    редакции — «`NOT_RUN` + успешный терминал» H25 `DOCS_CHECK_12` и
    «ошибочная тропа + журнальный код» H2 `DOCS_CHECK_15` — **обе сняты**).

    | Обязанность сверки | Операнд допуска | Исход |
    |---|---|---|
    | наступила | резолвится | сверка гоняется: `MATCHED` / `MISMATCHED`, успешный терминал |
    | не наступила | — | `NOT_RUN`, успешный терминал |

    Обязанность выражена тем же составным предикатом, что у правых операндов
    пар: записи закрытия добыты у **всех** эпизодов (`Position.externalRealizedProfit` непуст на каждой строке)
    **и** окно движений закрыто (`Deal.billsWindowEnd` непуст)
    (`docs/models/domain/aggregate/Deal.md` §«Признаки отбора для отчёта»).

    **Различение несёт терминальный статус, не значение признака** (H10
    `DOCS_CHECK_14`; третье значение `ReconciliationStatus` рассмотрено H6
    `DOCS_CHECK_16` и **не заводится** — решение держателя `GAPS_CLOSE_16`).

    - **Третьей строки в таблице нет, потому что у неё не осталось
      производителя** (Р3 `GAPS_CLOSE_16`). `ctVal` вышел из этой роли H5
      (персистится write-once на ноге), `stop_i` — Р3 (персистится шестым
      числом), и оба резолвятся всегда по инварианту «шесть или ни одного».
      Предикат селекции защиты, бывший последним производителем, в резолве
      епсилона больше не участвует.
    - **Нарушенный инвариант ловит детектирующий контур, а не финализатор**
      (позиция С3, в паре с Р1). Пустой операнд при непустом риске — тот же
      класс, что рассогласование пары носителей, и реакция у него уже
      назначена: **отказ операции**
      (`docs/models/domain/aggregate/Deal.md` §«Обнаружение рассогласования
      пары носителей»). До расчёта епсилона такой операнд не доезжает, и
      отдельная ветка внутри финализатора не нужна.
    - **Цена решения названа:** если инвариант «шесть или ни одного» нарушен
      **вне приложения** (правка данных в обход контура), детектирующий
      контур — единственное, что стоит между этим и молчаливым расчётом
      епсилона с пустым операндом. Собственной страховки у финализатора
      больше нет.
    - **Почему не «вырождать epsilon до композиционного члена».** При
      защитном приведении невырезолвившегося операнда к нулю омиссионный
      член выродился бы в `plannedRiskAmount` целиком — допуск раздулся бы
      до величины планового риска, и контроль целостности **погас бы
      молча** на этой сделке. Отказ операции называет недостачу, вместо того
      чтобы её маскировать.
- **Область сверки — за вычетом исключённых типов (H14 `DOCS_CHECK_10`):**
  суммы **каждой из четырёх пар** идут по строкам settle-ccy **вне списка
  исключений биржи** (типы, не принадлежащие экономике сделки); отдельной
  Σ`amount` по всей разбивке сверка больше не содержит (H7
  `GAPS_CLOSE_13`). Плюс отдельная проверка:
  **непустая корзина `OTHER`** у сделки → `AnomalyReport`
  `UNCLASSIFIED_CASH_FLOW` — так новый тип источника обнаруживается сам,
  а не раздувает сумму молча
  (`docs/models/mapping/DealCashFlow.md` §«Область сверки задаётся списком
  исключений по бирже»).
- **Валюта результата — пишется по авторитету, биржевая сверяется
  (H10 `DOCS_CHECK_10`):** `Deal.resultProfitCurrency` берётся из
  **расчётной валюты инструмента** — поля
  `Instrument.externalSettlementCurrency`, читаемого с
  `DealContext.instrument` (H6 `DOCS_CHECK_11`,
  `docs/decisions/instrument-currencies-home.md`; тот же резолв, что у
  `RefreshBillsExecutor`, навес `InstrumentExternalRules` не
  задействуется), а `Position.externalResultCurrency`
  **сверяется** с ней; не совпало → `AnomalyReport`
  `RESULT_CURRENCY_MISMATCH` (`severity = NON_CRITICAL`), **расчёт не
  блокируется и терминал проходит**. Операнд пуст → валюта берётся с
  `Position` + `AnomalyReport` `SETTLE_CURRENCY_UNAVAILABLE` (явная
  деградация с пометкой, `docs/models/domain/aggregate/Deal.md` §«Валюта
  результата: один авторитет»).
- **Число — в settle-ccy целиком (H5, `GAPS_CLOSE_6`):**
  `resultProfit` = net из положения закрытия **+ Σ(`amount` × `appliedRate`)**
  по строкам, у которых **`rateStatus = APPLIED`** **и** тип **вне списка
  исключений биржи** **и** категория — экономическая (не `OTHER`)
  (предикат — H9 `DOCS_CHECK_11`, выровнен H11 `GAPS_CLOSE_13`;
  «по строкам чужой `ccy`» **снято**: такой предикат затягивает в
  произведение строки с пустым `appliedRate` и обнуляет число на чистой
  тропе `CLOSED`, где оно обязано быть непустым).
  - **Почему конъюнкция, а не один `rateStatus`** (H11 `GAPS_CLOSE_13`):
    это единственная сумма, которая **прибавляется** к числу, а не
    проверяет его; ключевать её слабее, чем три проверяющие, значит
    пускать в числитель `R` любое прилинкованное движение в чужой валюте,
    не принадлежащее экономике сделки (перевод, движение маржи, новый тип
    источника). Операнды конъюнкции финализатор уже читает для четырёх
    пар — ни нового поля, ни нового чтения.
  Биржевой net считается в settle-ccy и издержку,
  уплаченную вне неё, не содержит — без слагаемого число завышало бы
  результат молча. Курс уже зафиксирован на записи, поэтому финализатор
  котировку **не запрашивает** — контракт «на биржу сам не ходит» держится
  (CCY-Q1 закрыт, H4 `GAPS_CLOSE_7`).
- **Признаки отбора для отчёта пишет он же** (узел F `DOCS_CHECK_12`), той
  же транзакцией, что и число:

  | Признак | Предикат |
  |---|---|
  | `Deal.closeOutcome` | `Position.externalCloseType`: `1,2` ⇒ `NORMAL_EXIT`; `3,4` ⇒ `LIQUIDATION`; `5,6` ⇒ `FORCED_REDUCTION`; **пусто ⇒ `UNDETERMINED`** + журнальный `AnomalyReport` (значение «вне `1..6`» до финализатора не доезжает — контракт записи проверяется на границе, H5 `DOCS_CHECK_15`) |
  | `Deal.reconciliationStatus` | исход сверки выше (`MATCHED`/`MISMATCHED`/`NOT_RUN`) |
  | `Deal.breakdownIncomplete` | таблица §«Структурная неполнота» выше (`COMPLETE`/`INCOMPLETE_BY_WINDOW`/`NOT_ASSESSED`) |
  | `Deal.riskBenchmarkAvailability` | `plannedRiskAmount` непуст ⇒ `AVAILABLE`; пуст при состоявшихся операциях ⇒ `MISSING` + журнальный `AnomalyReport` `PLANNED_RISK_MISSING` (H13 `DOCS_CHECK_16`). **Ветки `NOT_APPLICABLE` здесь нет** — она недостижима и снята (решение держателя П9 валидации `GAPS_CLOSE_17`): тропы закрытия без входа до этого финализатора не доходят, значение пишет `MarkDealClosedExecutor` своей транзакцией |

  - **Ветки «иначе `NORMAL_EXIT`» больше нет** (H2 `GAPS_CLOSE_13`).
    Пустой или неизвестный операнд закрытия — не штатный выход: значение
    `UNDETERMINED` оставляет сделку в популяции и делает недобытость
    счётной тем же `group by`, что остальные исходы. Разбивка `3..6` на
    две константы зафиксирована здесь по-значенчески, а не выводится
    из легенды типа.
  - **Нарушение контракта в добытой записи финализатор больше не
    обнаруживает** (H5 `DOCS_CHECK_15`, решение пользователя). Обязательные
    поля записи закрытия — `type` внутри перечня `1..6`, правые операнды
    четырёх пар, `realizedPnl`, `ccy`, резолвимый `direction` — проверяются
    **в слое интеграции**, там, где ответ впервые разбирается, и нарушение
    выражается броском `ExternalInvariantViolationException`
    (`docs/models/mapping/PositionCloseResult.md` §«Контракт записи
    проверяется здесь»). Дальше реакция идёт общим путём: строка исполнения
    → `FAILED` → бросок → перехват оркестратором → **полный биржевой
    холд** (`docs/rules/exchange-hold.md` §«Что переводит в HOLD»), сделка
    уходит ошибочной тропой к `EMERGENCY_CLOSED`. Вызова `HoldService`
    здесь **нет**, и финализатор из реестра детекторов убран
    (`docs/components/HoldService.md` §«Кто зовёт»): так `FULL`-реакция не
    поднимается из середины цикла команд, поверх сделки, чей переход ещё
    не применён, — конфликт снят по построению, а не оговоркой.
  - **Что это оставляет финализатору.** Один случай, чей операнд не
    приходит записью источника: сверка `ccy` с расчётной валютой
    инструмента (признак `RESULT_CURRENCY_MISMATCH`, расчёт не
    блокируется). Второй — «обязанная сверка с нерезолвимым операндом
    допуска» — **снят вместе с веткой** (позиция С3 `GAPS_CLOSE_16`;
    `ctVal` вышел из перечня операндов резолва H5 `DOCS_CHECK_16`,
    уровень стопа персистится шестым числом).
    Пустота `closeType` из-за отсутствия самой записи (позиция не
    заводилась) — не нарушение контракта: она даёт `UNDETERMINED` +
    журнальный отчёт, холда не вызывает.
  - **Неполное число — не чистый терминал** (H11 `DOCS_CHECK_17`, решение
    держателя П11, вариант 3). `resultProfit` содержит cross-ccy-слагаемое,
    суммируемое по строкам `DealCashFlow`, а строки усекаемы двумя
    названными способами — **глубиной конвейера добычи** и **нерезолвившимся
    курсом**, — и оба усечения уменьшают вычитаемую издержку, то есть
    **завышают** число направленно. Отсюда:
    - **предикат неполноты — из уже существующих фактов**, новой колонки
      нет; **оба дизъюнкта записаны перечнем значений, без неявного
      «иначе»** (Г1 + B3 `DOCS_CHECK_18`):

      ```text
      неполное число ⇔
        Deal.breakdownIncomplete ∈ {INCOMPLETE_BY_WINDOW, NOT_ASSESSED}
        ИЛИ ∃ прилинкованная строка DealCashFlow с
              rateStatus ∈ {RATE_UNAVAILABLE, SETTLE_CURRENCY_UNAVAILABLE}
      ```

      - **`NOT_ASSESSED` в перечне** — «не проверяли» не то же, что
        «проверили, всё в порядке» (`docs/rules/absent-value-semantics.md`
        §«Благоприятное значение по умолчанию запрещено»: признак
        нарушения — предикат вида «перечень ⇒ значения, **иначе** —
        благоприятное»). Прежняя редакция называла только
        `INCOMPLETE_BY_WINDOW`, и третье значение уходило в неявное
        `иначе` ⇒ чистый `CLOSED`. Ветка достижима штатно
        (`docs/lifecycles/Deal.md` §«Признаки отбора на рёбрах в
        терминал» прямо допускает `NOT_ASSESSED` на ребре
        `EXIT_PENDING → CLOSED`), и на популяции без отправленной ноги
        входа она **постоянна**;
      - **cross-ccy-дизъюнкт — по значениям `rateStatus`, а не по
        «cross-ccy-строке без `APPLIED`»**. У строки со
        `SETTLE_CURRENCY_UNAVAILABLE` cross-ccy-ность **неопределима по
        построению** (расчётная валюта не резолвилась), а вывод из `ccy`
        в этом кластере запрещён явно
        (`docs/models/mapping/DealCashFlow.md` §«Cross-ccy-область
        ключуется признаком состояния курса, а не `ccy`»). Перечень
        значений выразим колонкой и решает обе неопределённости разом;
        `NOT_REQUIRED` и `APPLIED` в него не входят — это и есть полнота;
    - **исход — ошибочная тропа** к `EMERGENCY_CLOSED`, а не успешный
      `CLOSED`. Число пишется и остаётся наблюдаемым; терминал говорит, что
      доверять ему как чистому нельзя;
    - **актор маршрутизации — `ExitPendingHandler`, выходной проверкой**
      (Г2 `DOCS_CHECK_18`). Финализатор предикат **не исполняет**: он
      пишет число и признаки своей транзакцией, а развилкой
      «`CLOSED` vs `ERROR`» на этой тропе уже владеет handler
      (`docs/components/ExitPendingHandler.md` §«Выходные проверки»).
      Так решение получает и точку вычисления, и актора, не заводя ни
      пятого ребра у `MarkDealClosedExecutor`, ни конструкции «звено с
      двумя статусными исходами», которой канон не знает;
    - **отдельного признака полноты числа не заводится** — ни третьего
      значения `breakdownIncomplete`, ни `resultProfitCompleteness`
      (вариант 2 предложения владельца отвергнут держателем).
    - **Названная цена принята:** аварийный терминал за событие, радиус
      которого локализован сделкой. Довод несоразмерности держателем
      взвешен и отклонён — систематическое завышение центрального числа
      сдвигает ожидаемость вверх у **подмножества**, коррелированного со
      сроком удержания, то есть делает выборку не из одного распределения.
  - **Пустого правого операнда пары при обязанной сверке у финализатора
    больше не бывает** (H10 `DOCS_CHECK_14` — перенесено H5
    `DOCS_CHECK_15`): либо запись прошла границу целиком, либо её не
    существует. Ветка «пара не участвует» и значение «оценено N из 4» не
    вводятся намеренно (`docs/models/domain/aggregate/Deal.md` §«Признаки
    отбора для отчёта»). Защитный `coalesce(…, ZERO)` запрещён — он
    превращал бы «не проверяли» в «проверили, всё в порядке» ровно в
    корзине ликвидаций.
  - Ни один из трёх не вычисляется «на лету» потребителем: фильтр
    эндпоинта отчёта обязан быть выразим запросом
    (`docs/models/domain/aggregate/Deal.md` §«Признаки отбора для
    отчёта»).
  - **Тропы закрытия без входа этот executor не проходят вовсе**, и
    признаки на них остаются **пустыми** — это их значение, а не пропуск
    (H3 `GAPS_CLOSE_13`; `docs/components/MarkDealClosedExecutor.md`
    §«Вторая ветка»).
- Внутренняя декомпозиция расчёта (выделять ли отдельный калькулятор) — деталь
  CODE шага 7. Структуры носителей —
  `docs/models/mapping/PositionCloseResult.md`,
  `docs/models/domain/other/DealCashFlow.md`.

## Терминальное ребро

Не терминал сделки. Поддерживает выходную проверку `EXIT_PENDING → CLOSED`
(`docs/components/ExitPendingHandler.md`), готовя факты к `MARK_DEAL_CLOSED_COMMAND`.

## Идемпотентность и retry

- **Retry-anchor** — строка исполнения `FINALIZE_DEAL_EXIT_ACTION`
  (вид SYSTEM, база `Retryable`;
  `docs/models/domain/other/DealActionState.md`,
  `docs/decisions/command-action-boundary.md`).
- **Идемпотентность** — частичный ключ живого исполнения (`deal_id`,
  `system_action_type`) + факты: повтор на уже консолидированном выходе —
  no-op.
- Падение → `RETRY_PENDING`/`FAILED` (`docs/components/RetryPolicyService.md`,
  `docs/rules/runtime-error-classification.md`).

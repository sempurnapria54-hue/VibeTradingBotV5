# FinalizeDealExitExecutor

## На какой вопрос отвечает этот файл

Кто исполняет команду финализации штатного выхода.

## Что делает

Консолидирует факты выхода после снятия живого риска, **считает итоговое
число сделки и сверяет разбивку**.

**Читает:** подтверждённые факты выхода (живого эпизода нет, живых заявок
нет, причина закрытия определена), строки разбивки движений и **положения
закрытия на строках эпизодов**.

**Пишет:** число и его валюту прямо на сделку — **в одной транзакции** с
продвижением своего звена. Отсюда durable-носитель числа есть само поле
сделки, и рестарт безопасен.

**На биржу не ходит:** интеграционное чтение остаётся за командами
добычи. Преконтроль риска не вызывается.

## Число — сумма по эпизодам

Сделка многоэпизодна: финализация складывает готовые net закрытых
эпизодов, а правые операнды пар сверки берёт суммами по тем же строкам.

**Эпизод без добытого положения закрытия делает число недоступным, а не
заниженным:** звено не завершается, подстановка нуля запрещена.

Плюс слагаемое чужой валюты — движения, оплаченные вне расчётной валюты,
по применённому курсу.

## Положение закрытия читается со строки

Биржевой факт закрытия персистит **вторая нога рефреша позиции**.
Финализация читает его как обычные входные факты.

**Идемпотентность — на уровне действия:** анкер — строка исполнения
финализации выхода. Рестарт до завершения перезапускает звено: число
пересчитывается из тех же persisted-полей. Рестарт после завершения —
пустая операция.

**Паттерн «добыча наполняет — финализация консолидирует» буквален:**
добыча пишет в свою строку, финализация её читает. Ходить на биржу из
финализации отвергнуто: у команды добычи свои повторы и своя
идемпотентность.

## Сверка

Сверяются **четыре пары по категориям**: реализованный результат,
комиссии, финансирование, штраф ликвидации — слагаемые разбивки против
чисел записей закрытия, просуммированных по эпизодам.

**Обязанность сверки — предикат из трёх конъюнктов** (записи закрытия
добыты у всех эпизодов, окно закрыто, движения добывались). Формула
допуска и область суммирования — `docs/spec/pnl-reconciliation.json`; дом
правила — `docs/rules/pnl-reconciliation.md`.

**Число суммой движений не подменяется:** расхождение — сигнал
целостности разбивки, а не ошибка числа.

Для допуска дочитываются операнды планового риска **по каждой ноге
входа**; справочный навес инструмента не читается — все операнды
тождества persisted на ноге.

## Признаки отбора для отчёта

Финализация пишет торговый исход закрытия, статус сверки, полноту
разбивки и доступность знаменателя.

**Структурная неполнота** определяется сравнением возраста нижней границы
окна на момент добычи с глубиной конвейера. Добыча не выполнялась —
значение «не оценивалось», а не «полна».

## Терминальное ребро

Ребро в терминал пишет следующее звено действия, а не этот исполнитель:
здесь считается и пишется число, там ставится терминал с проверкой его
непустоты.

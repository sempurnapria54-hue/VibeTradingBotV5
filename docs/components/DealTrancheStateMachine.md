# DealTrancheStateMachine

## На какой вопрос отвечает этот файл

Кто управляет статусами транша.

## Что делает

Выбирает обработчик по текущему статусу транша, запускает его проверки и
логику и возвращает переход: команды и, если он разрешён, новый статус
транша.

Зовётся обработчиком активной сделки — по одному проходу на каждый
нетерминальный транш. Порядок между траншами значения не имеет: их
операнды независимы по построению.

Терминальный статус обработчика не имеет.

## Конструкция обработчика — та же, что у сделки

Три блока: входные проверки, рабочая логика этапа, условия перехода
(`docs/components/DealStateMachine.md`). Отличается только область:
операнды — заявки, защиты и экспозиция **своего** транша.

## Чего эта машина не делает

- **Ребра в ошибочный статус не выдаёт** — его у транша нет. Отказ,
  который нельзя разобрать на месте, поднимается обработчику сделки, и
  ошибочное состояние ставится на **ней**
  (`docs/lifecycles/DealTranche.md`).
- **Терминал сделки не ставит:** закрытие транша сделку не закрывает.
- **Потолки риска не считает** — их считает преконтроль, и считает по
  всей сделке (`docs/rules/risk-policy.md`).

## Границы

- Команд сам не строит и на биржу не ходит.
- Статусную механику не определяет: значения и инварианты переходов —
  предмет жизненного цикла транша.

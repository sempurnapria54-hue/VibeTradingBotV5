# RiskBlockResolver

## На какой вопрос отвечает этот файл

Кто превращает результат risk-проверки в действие handler'а.

## Назначение

`RiskBlockResolver` нужен, чтобы handler не содержал большой `switch` по
всем risk-кодам. Получает результат проверки риска и возвращает
`RiskBlockAction` (см. `docs/components/models/RiskBlockAction.md`):
`RiskValidationResult → RiskBlockAction`.

## Контракт

```java
RiskBlockAction resolve(
    DealContext dealContext,
    DealTranche.Status currentStatus,
    RiskValidationResult riskValidationResult
);
```

- `dealContext` — фактическое состояние сделки (позиция, live orders/algo,
  `DealActionState`, active risk);
- `currentStatus` — статус **транша**: различить `PRECHECK` и этапы, где
  live risk уже есть или мог появиться;
- `riskValidationResult` — итоговое решение и конкретные `RiskCheckCode`.

Параметры `strategyStep` / `strategyAction` / `calculatedAction` **не**
передаются: маппинг кода риска в действие опирается только на
`riskValidationResult`, `dealContext` и `currentStatus`. Reduce-only intent
и направление, если нужны, доступны из `dealContext` (`deal.direction`,
runtime graph) — отдельных параметров под них нет.

`boolean liveRiskExists` отдельным параметром не передаётся — это
производное состояние, выводится из `DealContext + currentStatus + runtime
graph`.

## Карта «вердикт → действие»

**Дом карты — здесь.** Владелец маппинга объявлен этим файлом, и сама
карта живёт здесь же: диспозиция отвергнутого входа, разложенная по
носителям, читается несовместимыми способами.

**Первый операнд — стадия объекта действия, второй — код.** Стадия решает
**род** реакции, код — только **причину**; порядок именно такой, потому
что цена ошибки задаётся стадией: до живого риска рвать нечего, после —
есть.

| Стадия транша | Живой риск | Действие (`RiskBlockAction.Type`) | Причина |
|---|---|---|---|
| `PRECHECK` | нет | `CLOSE_CANDIDATE_DEAL` — терминал транша, если отказ **бессрочен**; иначе `SKIP_ACTION` | `RISK_CONTROL` пишется **только** с `CLOSE_CANDIDATE_DEAL` |
| `PRECHECK` | нет, но операнд не добыт | `REQUEST_REFRESH` | причины нет: вердикт отложен |
| любая прочая | есть | `MOVE_DEAL_TO_ERROR` | код вердикта в `errorCode` |

**Бессрочность отказа — свойство КОДА, и вот его определение.** Отказ
**бессрочен**, когда повторная проверка того же действия не может дать
иного исхода без изменения самой стратегии: конфигурация невалидна,
сторона уровня противоречит направлению, инструмент не торгуется.
Отказ **временный**, когда исход зависит от состояния, которое меняется
само: занятый бюджет освободится выходом соседнего транша, баланс
пополнится, свежесть вернётся.

Различение денежное, а не редакционное: уровень сеточной детали,
отвергнутый **временно** занятым бюджетом, при прочтении «терминал»
теряется навсегда — бюджет освободится, а транша, который должен был
войти, уже нет, и объявленный автором веер вырождается по уровню за
проход, молча. Обратное прочтение тоже названо: сделка с единственным
траншем на бессрочном отказе крутилась бы в `PRECHECK` бесконечно.

**Перечень кодов по признаку бессрочности живёт у дома кодов**
(`docs/components/models/RiskCheckResult.md`): признак объявляется рядом
со значением, а не переписывается здесь вторым носителем.

## Свёртка многокодового вердикта

Вердикт преконтроля несёт **перечень** отказов (`RiskValidator` копит их:
любой отказ даёт отказ итога), а `RiskBlockAction` односоставен. Свёртка:

- **род действия берёт стадия** — она одна на вердикт, и смешение кодов
  на неё не влияет;
- **причину берёт старший код перечня**; старшинство — тот же порядок,
  что у причин закрытия транша (`docs/spec/deal-lifecycle.json`
  §`trancheCloseReasonRank`), а среди кодов одного ранга — первый по
  порядку проверок `RiskValidator`;
- **бессрочность вердикта — конъюнкция**: вердикт бессрочен, только если
  бессрочны **все** его коды. Один временный код делает вердикт
  временным: повтор может пройти.

**Почему свёртка не покодовая.** Покодовый карв-аут на смешанном вердикте
неразрешим, и обе однородные свёртки ошибочны в названную сторону:
«строгая» (хоть один код вне карв-аута ⇒ `ERROR`) уводит в аварийный
контур сделку без живого риска — ровно то, против чего карв-аут заведён;
«мягкая» (хоть один в карв-ауте ⇒ не `ERROR`) маскирует настоящее
рассогласование учёта соседним ожидаемым отказом, то есть ошибается в
**разрешающую** сторону (`docs/concept.md` П1 §3). Стадия свободна от
обеих: она не зависит от состава перечня.

## Границы

Сам команды не исполняет; политику маппинга кодов риска в действие держит
здесь, исполнение `RiskBlockAction` — у FSM handler (см.
`docs/processes/risk-evaluation.md`).

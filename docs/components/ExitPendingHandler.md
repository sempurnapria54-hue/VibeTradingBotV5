# ExitPendingHandler

## На какой вопрос отвечает этот файл

Что делает обработчик статуса выхода.

## Что делает

Дочищает сделку после инициированного выхода: подтверждает закрытие
позиции, снимает живые сущности, финализирует факты.

## Входные проверки

Статус выхода; закреплённая деталь стратегии; есть факты инициированного
выхода; не более одной живой позиции; живой риск можно безопасно
проверить; локальные заявки доступны для очистки.

## Рабочая логика

**Добыча — через системное действие:** подтверждение отсутствия живого
риска, положение закрытия эпизодов, состояние заявок, баланс после снятия
риска, движения средств. Звено движений — звено **выходной тропы**: на
аварийной оно не эмитится вовсе.

**Дочистка — напрямую, без анкера**, в порядке инварианта
`docs/rules/exit-teardown-order.md`: сперва живые **входные** ноги, затем
позиция, затем остальные живые сущности.

Учёта серии неудач у дочистки нет — у неё нет исполнения-действия, а
значит и бюджета отказов; неснятую сущность подберёт следующий проход.

**Завершение — через действие финализации выхода:** подтвердить причину
закрытия, посчитать и записать число, затем поставить терминал.

Дочистка и safety преконтроль риска не проходят.

## Выходные проверки

Живого риска нет и он подтверждён; заявки сняты; число посчитано —
терминал штатного закрытия.

Число посчитать нельзя после исчерпания бюджета добычи — ошибочная тропа.

## Допустимые шаги

`EXIT`, `FAIL_SAFE`.

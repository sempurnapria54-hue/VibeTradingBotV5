# ActionRiskGate

## На какой вопрос отвечает этот файл

Кто связывает преконтроль риска с планом действия за проход.

## Назначение

`ActionRiskGate` — тонкий узел между `RiskValidator` и
`RiskBlockResolver` для per-type исполнителей действий: прогоняет
вердикт и, если реакция блокирующая, отдаёт её планом действия
(`ActionPlan.blocked`). Разрешающая реакция (`CONTINUE`) плана не
порождает (форма — пустой `Optional`) — действие продолжает свой ход;
следа в журнале, статусов, строк в базе и событий она не оставляет.

Две ветви входа, обе из `docs/rules/risk-validator-scope.md`:

| Ветвь | Операнд | Кто зовёт |
|---|---|---|
| рассчитанное действие, создающее либо ослабляющее контроль риска | `CalculatedStrategyAction` + транш действия (операнд блок-сета ступени) | `CreateOrderActionExecutor`, `CreateAlgoOrderActionExecutor` |
| снятие отдельной защиты при живой экспозиции | транш + id снимаемой защиты | `CancelAlgoOrderActionExecutor` |

## Почему узел отдельный

Связка «валидатор → резолвер → план» одна и та же у всех валидируемых
действий, а её копия у каждого исполнителя расходилась бы первой же
правкой карты реакции: какие реакции разрешающие, решает карта, а не
исполнитель.

## Границы

- Решений не принимает: состав проверок держит `RiskValidator`, род
  реакции — `RiskBlockResolver`.
- Статусы не пишет и команд не создаёт.
- Условие шага и стадию действия не смотрит — это работа обработчика и
  исполнителя типа.

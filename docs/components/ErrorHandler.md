# ErrorHandler

## На какой вопрос отвечает этот файл

Что делает обработчик ошибочного состояния сделки.

## Что делает

Ошибочное состояние означает: авария обнаружена, обычная логика
заблокирована, риск может быть ещё живым. Разрешены только safety,
восстановление и проверка фактов.

**Состояние сделочное, а не траншевое.** Отказ одного транша уводит в
него всю сделку: транши делят одну нетто-позицию и одну арифметику
экспозиции, поэтому набор риска останавливается по всем сразу
(`docs/lifecycles/Deal.md`). FSM траншей в этом статусе не гоняется —
единственный из трёх обработчиков сделки, который её не гоняет; дом
ответа и цена обоих неверных прочтений —
`docs/processes/fsm-execution-layering.md`.

Статус **нетерминален**: переход в штатный терминал запрещён, допустим
только аварийный.

## Входные проверки

Ошибочный статус; есть ли активный риск; позиция без покрытия; живые
заявки без связи со сделкой; расхождение локального состояния и биржи;
нужна ли аварийная очистка риска.

## Рабочая логика

Добыть факты о живом риске; при необходимости снять риск аварийным
путём; дождаться подтверждения снятия.

## Выходные проверки

Аварийный терминал — только если **подтверждено**: позиция закрыта либо
отсутствует; живых заявок и условных заявок нет ни у одного транша;
встроенная защита отсутствует либо на риск не влияет; нет ожидающих
сущностей, способных создать риск; сделка не требует сопровождения.

**Терминальность строк траншей аварийный терминал не гейтит:** требование
одно — доказанное отсутствие живого риска. Строка транша стала бы второй
точкой отказа аварийного контура (`docs/spec/deal-lifecycle.json`).

Иначе остаётся в ошибочном состоянии.

**Затребователь аварийного терминала — этот обработчик**; ребро пишет
звено в одной транзакции со своим завершением.

# Базовый тип `ServiceCommandPayload`: маркер-база + дискриминатор `ServiceCommandType`

## На какой вопрос отвечает этот файл

Почему у payload'ов команд есть общий маркер-базовый тип
`ServiceCommandPayload` (без поведения), дискриминатор — `ServiceCommandType`
на команде, а файл `ServiceCommandPayload.md` остаётся домом базового типа.

## Контекст

Решение `executor-payload-file-granularity.md` (CMD-Q1) перенесло
payload-разделы к своим executor'ам, оставив открытым (CMD-Q2): есть ли у
payload'ов общий базовый тип/дискриминатор и какова судьба
`ServiceCommandPayload.md`. `DOCS_CHECK_1` шага 4 поднял CMD-Q2 как
гейтящий чистоту payload-детали (находка Э3/N4).

Первый проход (`DOCS_CHECK_1`, крен Э3) отверг общую базу по одному
критерию — «база без поведения ценности не несёт». На валидации крен
**разошёлся** как неполный; концепт-проектирование дообучено
(`.claude/agents/solution-designer.md`, эвристика 5: маркер/базовый тип
взвешивать по эргономике сигнатур и расширяемости, не только по поведению).
Переоценка под полным критерием выполнена на `GAPS_CLOSE_1` и
**валидирована в чате**.

## Решение

- **Маркер-база `ServiceCommandPayload`** (без поведения): подтипы
  (`CreateOrderCommandPayload`, `SubmitOrderCommandPayload`, … — по одному
  на команду, документированы при своих executor'ах) наследуют/реализуют
  её.
- **Дискриминатор — `ServiceCommandType`** на команде (`ServiceCommand.type`),
  не отдельное поле в payload'е.
- **`docs/components/models/ServiceCommandPayload.md` — дом базового типа**
  (не упраздняется): несёт назначение RVO, базовый тип и карту
  «payload → executor».

## Обоснование (полный критерий)

- **Эргономика сигнатур (решающее):** поле `ServiceCommand.payload` уже
  типизировано `ServiceCommandPayload`; без общей базы его тип выродился бы
  в `Object`. Generic-диспетч `ServiceCommandExecutor.execute(P payload,
  DealContext)` получает осмысленную границу `P extends
  ServiceCommandPayload`.
- **Запас на расширение:** новые команды/биржевые модели добавляют
  payload-подтипы под общей базой без правки контракта диспетча.
- **Поведение:** у базы его нет — но «нет поведения» перевешивается
  контрактом и расширяемостью; пустой маркер окупается сигнатурами.

## Альтернативы (отвергнуты)

- **Без общей базы** (`ServiceCommand.payload : Object`, диспетч по
  instanceof/касту). Отвергнуто: теряет типобезопасность поля и границы
  диспетча — исходный крен `DOCS_CHECK_1`, признан неполным.
- **Отдельное поле-дискриминатор в payload'е.** Отвергнуто: дублирует
  `ServiceCommandType`, уже несущий дискриминацию на команде.

# Механика финализации P&L (шаг 7)

## На какой вопрос отвечает этот файл

Как механически добываются P&L-факты, кто считает и пишет число
`resultProfit` (штатно и аварийно), где durable-живёт посчитанное число,
откуда берётся ставка комиссии для сайзинга, как реагирует сверка bills↔net —
и почему именно так.

## Контекст

`GAPS_CLOSE_1` выбрал **источник** числа (net из positions-history + разбивка
из bills, `docs/decisions/result-profit-source.md`), но сознательно отложил
стадия-1/2 механику. `DOCS_CHECK_2` (`phase-1-step-7-docs-check-2.md`) вскрыл 11
гейтящих пробелов механики: добыча фактов не назначена (N6); носитель
staged-числа между двумя финализационными командами (N7); аварийный терминал без
владельца + неисполнимый контракт (N8); seam ставки комиссии в сайзинг (N9);
реакция сверки (N10); носители пути только name-level (N1-N5); непроверенный
инвариант агрегации (N11). Это решение закрывает **механику**; структуры-носители
материализуются отдельными доками (native / mapping / model), ссылаясь сюда.

## Решения

### 1. Добыча P&L-фактов — новые refresh-команды, замена `REFRESH_FILLS` (N6, N12)

- Вводятся `REFRESH_POSITIONS_HISTORY` (наполняет positions-history-снапшот —
  число) и `REFRESH_BILLS` (наполняет `DealCashFlow` — разбивка), **по одной на
  новую сущность** (паритет CMD-Q3 «refresh — по одной команде на сущность»).
- `REFRESH_FILLS` **снимается** (N12): его единственная функция (пересчёт
  order-fill-метрик `accumulatedFillSize`/`averagePrice`/`fee` ordinary `Order`)
  покрыта `REFRESH_ORDER` (`OkxOrderResponse.accFillSz`/`avgPx`). Чистый swap
  1-out-2-in в refresh-вокабуляре.
- Эмитятся handler'ами: `ExitPendingHandler` (штатный выход) и `ErrorHandler`
  (аварийная тропа) **до** финализации/терминала; идемпотентны, retryable через
  командную машинерию. `REFRESH_BILLS` внутри команды проходит пагинацию bills
  (7d→3m archive) — паритет evidence-cycle (`refresh-evidence-cycle-ownership.md`).
- `FinalizeDealExitExecutor` **остаётся off-exchange** — читает готовые
  снапшот + `DealCashFlow`, добытые командами. Латентное противоречие снято
  (executor «на биржу не ходит» ⟷ факты некому добывать → теперь их добывают
  refresh-команды).
- **Альтернативы отвергнуты:** (2) integration read вне command-layer
  (CMD-Q4-образец) — размывает «финализация не ходит на биржу», теряет командный
  retry/идемпотентность на гранулярности факта; (3) fetch внутри
  `FinalizeDealExitExecutor` — концентрирует fetch+compute, ломает паттерн
  «refresh populates → finalize consolidates».

### 2. Носитель staged-числа = поле `Deal`, пишет `FINALIZE_EXIT` (N7)

- **Разрыв GAPS_CLOSE_1:** число считалось в `FINALIZE_EXIT`, писалось
  `MARK_CLOSED` — durable-слот между двумя командами (разные проходы FSM, разные
  строки `DealFinalizationState`) не назначен; ломалось об идемпотентность/рестарт.
- **Решение:** `FINALIZE_DEAL_EXIT` **пишет `resultProfit`/`resultProfitCurrency`
  прямо на `Deal`** (persisted) в **одной транзакции** с
  `DealFinalizationState(FINALIZE_EXIT) = COMPLETED` (+ персистит `DealCashFlow`).
  `MARK_DEAL_CLOSED` **читает `Deal.resultProfit`, ассертит непустоту** (инвариант
  чистого `CLOSED`), ставит `status = CLOSED`.
- **Durable-носитель = сами поля `Deal.resultProfit`** (nullable; заполнены на
  `FINALIZE_EXIT`, ассертятся на терминале). Рестарт-safe: после `COMPLETED` число
  уже на `Deal`; повторный `FINALIZE_EXIT` — no-op, `MARK_CLOSED` читает готовое.
  Транзакционная связка: `COMPLETED` ⟺ `resultProfit` persisted.
- **Ревизует framing GAPS_CLOSE_1** «`MARK_CLOSED` пишет число»: число пишет
  `FINALIZE_EXIT`, `MARK_CLOSED` терминализует + ассертит. Побочно: `resultProfit`
  может быть непустым на `EXIT_PENDING` до терминала — доброкачественно (транзитное
  финализационное состояние; §Персистентность `Deal` — nullable).

### 3. Аварийный терминал: владелец + провенанс-контракт (N8)

- **Владелец (part 1):** step-6 не назначил **запись** `EMERGENCY_CLOSED` —
  команды-терминала нет (`MarkDealErrorExecutor` пишет только `ERROR`;
  `MARK_DEAL_EMERGENCY_CLOSED` в enum отсутствовал). Вводится
  **`MARK_DEAL_EMERGENCY_CLOSED`** (команда + `MarkDealEmergencyClosedExecutor` +
  `DealFinalizationType.MARK_EMERGENCY_CLOSED`), терминальное ребро
  `ERROR → EMERGENCY_CLOSED`, **симметрично `MARK_DEAL_CLOSED`**. Эмитит
  `ErrorHandler` после подтверждённого снятия live risk. Best-effort число —
  из positions-history-снапшота (добыт `REFRESH_POSITIONS_HISTORY` перед терминалом).
- **Провенанс-контракт (part 2) — best-effort, два провенанса разведены:**
  - **(a) реальная ликвидация/ADL** (позицию закрыла биржа): `realizedPnl` +
    `liqPenalty` доступны (`type` 3-6) → пишем **фактический realized net**.
  - **(b) отказ расчёта после исчерпания retry** (чистая тропа не смогла
    посчитать → ушла в `ERROR`): `ErrorHandler` перед терминалом ещё раз пробует
    добыть (`REFRESH_POSITIONS_HISTORY`); net доступен → пишем его; **genuinely
    недоступен** → `resultProfit = null` с семантикой **«неисчислимо»** (НЕ ноль),
    сделка терминализуется **всё равно**, факт помечается (лог + `AnomalyReport`).
  - **Маркер (без нового поля):** на `EMERGENCY_CLOSED` `resultProfit != null` =
    фактический net; `resultProfit == null` = «неисчислимо» — **отличимо от нуля**
    (ноль = посчитанный нулевой P&L). Nullability несёт маркер.
  - **Торговое обоснование (F-T1):** число **не зануляется** — недоступность
    помечается, не подменяется нулём; null-случай **исключается из R-выборки как
    unknown** (не считается нулём) → левый хвост не усекается молча [Vince гл.1
    с.15; Tharp гл.6 с.158-159].
  - **Пометки недостаточно — нужен добор числа (H6, `GAPS_CLOSE_3`).** Ревизует
    прежнее «пометки (`AnomalyReport` / лог) достаточно»: пометка фиксирует
    **факт** дыры, но не устраняет её **смещение**. Пропуск null'ов
    **outcome-коррелирован** — null возникает на аварийной тропе, а она
    кучкуется там же, где крупные убытки. Значит выборка «вычислимых» сделок
    смещена к благоприятным исходам, и простой drop не устраняет смещение, а
    **воспроизводит его омиссией**: ожидаемость завышается [Vince гл.5 с.63;
    Tharp формула 6-2, гл.6 с.158-159]. Само решение «не ноль» — **верно**
    (ноль был бы прямой ложью о числе); неверно было утверждение о
    достаточности пометки.
  - **Принятое направление — добор недостающего числа** до истечения окна
    positions-history (~3 мес; тот же эндпоинт, недоступность обычно
    **временна**). То есть null на `EMERGENCY_CLOSED` — не финальный вердикт, а
    **отложенный долг**: число дочитывается, пока окно источника живо.
    **Материализация добора** (кто дочитывает, на каком такте, что с
    просроченным окном) — **форвард шага ожидаемости / фазы 2**; здесь
    фиксируется **направление**, не механика. Отвергнуты как основной путь:
    worst-case импутация (искажает число ради метрики) и метрика счёта дыр
    рядом с ожидаемостью (честно раскрывает дыру, но не закрывает её — годится
    как дополнение, не как замена добора).
- Контракт становится **исполнимым**: «на `EMERGENCY_CLOSED` — фактический realized
  net если доступен; иначе `null` с маркером «неисчислимо»; **никогда не ноль**».

### 4. Ставка комиссии для сайзинга — seam на `InstrumentExternalRules`, дом на `TradeFeeRate` (N9)

**Доспецифицировано на `GAPS_CLOSE_3` (H1).** Первая редакция назвала ставку
«инструмент-level внешние данные» и положила её полями на навес инструмента.
Фактура офдока (прогон `integrator`, 2026-07-14) показала, что это неверно: ставка
— **group × tier-level**, и слой её добычи не был заведён вовсе (нет native, нет
маппинга, `groupId` отброшен) → `takerFeeRate()` оставался null, прогноз комиссии
молча выпадал. Ниже — итог.

- **Поверхность чтения не изменилась:** `SizeCalculator`/`RiskValidator` читают
  taker-ставку тем же аксессором `InstrumentExternalRules.takerFeeRate()` —
  **нового поля контекста не нужно**, **exchange-вызова из калькуляторов не
  нужно**. Дефект был в **наполнении**, не в поверхности.
  - **Уточнено на `GAPS_CLOSE_4` (H1).** Прежняя редакция формулировала это
    как «оба читают из **уже присутствующего**
    `CalculationContext.instrumentExternalRules`» — для `RiskValidator`
    **ложно**: его сигнатура `validate(CalculatedStrategyAction, DealContext)`,
    `CalculationContext` у него нет, навес он читает **напрямую** через
    `InstrumentExternalRulesDataService.findByInstrumentId`
    (`docs/components/RiskValidator.md` §Входы). Верно так: **аксессор** у обоих
    один и не двигался, а **троп чтения навеса две** — через фабрику контекста
    и прямая. Довод `DOCS_CHECK_3` «обе линзы признали seam валидным» покрывал
    только первую тропу; на `DOCS_CHECK_4` это стоило гейта.
- **Дом значения — `TradeFeeRate`** (`docs/models/domain/other/TradeFeeRate.md`):
  одна строка на комиссионную группу, отдельная таблица с историей. На навесе
  инструмента — **только ключ группы** `externalFeeGroupId`.
- **Гидрация — на хранилищном слое** (H1, `GAPS_CLOSE_4`). Аксессоры
  `takerFeeRate()`/`makerFeeRate()` наливает
  `docs/components/InstrumentExternalRulesDataService.md` — граница
  domain ↔ persistence, **единственная точка, через которую проходят обе
  тропы**. Гидрируй фабрика контекста — прямая тропа `RiskValidator` отдавала
  бы негидрированный навес, `takerFeeRate()` = `null`, и
  `FEE_RATE_UNAVAILABLE` блокировал бы **каждый** risk-creating вход. Читатели
  о `TradeFeeRate` не знают.
  **Почему не полем навеса:** ставка — атрибут комиссионного уровня аккаунта
  (объём/VIP), а не справочника инструмента; копия на каждом инструменте —
  заготовка под расхождение при смене тира (N копий, N шансов отстать). Это
  ревизует **место хранения**, а не seam: (c) «дом ставки не на инструменте»
  был прав по факту, но правильный его объём — хранение, не поверхность чтения.
- **Ось резолва — пара (`instType`, `groupId`)**, не голый `groupId`: одно число
  значит разное при разном `instType`. Ключ группы приходит
  `/public/instruments` (офдок: «instType and groupId should be used together to
  determine a trading fee group»); отброс `groupId` снят
  (`docs/models/mapping/InstrumentExternalRules.md`). Перечень групп **не
  хардкодится** — офдок сам предписывает «actual return values shall prevail».
  - **Обе половины ключа — сырые биржевые значения** (H7, `GAPS_CLOSE_4`), не
    доменная проекция `instrumentType`. Довод — **коллизия `UNKNOWN`**:
    проекция схлопывает все нераспознанные сырые типы в одно значение, поэтому
    две разные группы источника столкнулись бы в одном ключе и правило истории
    «значение изменилось → новая строка» выродилось бы во флип-флоп между их
    ставками. Группа — ось **источника**, ключуется тем, чем её задаёт
    источник. Ратифицировано пользователем; заявка на доменную ось в
    `TradeFeeRate`/`InstrumentExternalRules` снята.
  - **Матч в синке — тоже по паре** (H8, `GAPS_CLOSE_4`): per-instrument матч
    идёт по (`externalInstrumentType`, `externalFeeGroupId`) навеса, а не по
    голому `groupId` (`docs/components/InstrumentExternalRulesSyncJob.md`
    §Такт). Голый `groupId` на контуре из нескольких `instType` дал бы **молча
    неверную ставку** — ровно тот отказ, от которого предостерегает абзац выше.
- **Такт (A′) — чтение раз-на-тик:** **один** вызов `trade-fee(instType=SWAP)`
  **до** цикла по инструментам → карта групп → per-instrument матч. Ось запроса —
  группа, а не инструмент, поэтому лимит (5 req / 2 s по User ID) неощутим.
  Синк — тем же `InstrumentExternalRulesSyncJob`: **один писатель**.
  - *(B) отдельная `TradeFeeSyncJob`* — отвергнута: её единственный настоящий
    довод (разные природы контуров — публичный/IP vs приватный/User ID) не
    окупает внесённую гонку двух писателей в один навес (`JobExecutionGuard` —
    per-job, джобы друг друга не видят). Вернуться, если приватный контур
    потребует своего такта.
  - *(C) читать на входе в сделку* — отвергнута: точка отказа в момент входа
    ради свежести, чья цена ~5 bp против стопа 1-2%; ломает seam.
- **Свежесть — измеряется, не предполагается.** Возраст `modifiedAt` строки =
  время с последнего успешного чтения; возраст > порога (конфиг, стартово
  **24 ч**) → **холд инструментов группы**
  (`docs/rules/instrument-hold.md` §«Несвежесть ставки комиссии»).
  - **Измеритель держится на `refreshCount`** (H5, `GAPS_CLOSE_4`).
    Прежняя редакция утверждала, что `modifiedAt` двигается при каждом успешном
    чтении, — из механизма это **не следовало**: JPA auditing двигает метку на
    **изменении** сущности, а путь «значение совпало» (практически
    единственный: ставка меняется единицы раз в год) ничего не менял ⇒ UPDATE не
    выпускался, метка замирала на времени создания, и через 24 ч **здоровой**
    работы срабатывал холд. Введён **счётчик подтверждений `refreshCount`**:
    инкремент на каждом успешном чтении делает строку dirty ⇒ метка двигается.
    Свойство стало **записанным**, а не побочным.
  - **«Счётчик отказов не нужен» — довод перепроверен и держится** (H5,
    `GAPS_CLOSE_4`): возраст `modifiedAt` и есть время с последнего успеха, а
    при фиксированном такте оно однозначно переводится в число неудач подряд
    (часовой такт, порог 24 ч → 24 неудачи). Разница с прежней редакцией — в
    опоре: раньше довод стоял на незаписанном побочном эффекте (и потому был
    ложен), теперь — на `refreshCount`. Полный разбор —
    `docs/models/domain/other/TradeFeeRate.md` §«Свежесть измеряется, а не
    предполагается».
  - **Scope холда — инструмент, не биржа** (H3/H4, `GAPS_CLOSE_4`). Ратифицировано
    пользователем. Чтение `trade-fee` ломается на **исправной** бирже и
    обесценивает справочное число **одной группы** ⇒ радиус ущерба —
    инструменты этой группы (`docs/rules/error-handling-policy.md` §«Радиус
    ущерба задаёт scope»). Реакция — полная, уровня 4: запрет новых сделок по
    инструменту + **kill-switch** по нему + `AnomalyReport`, снятие
    **вручную**; восстановившееся чтение холд не снимает. Формулировка
    «холд биржи, сделки доживают» **снята**: она была вдобавок внутренне
    противоречива — exchange-блок-сет рубит `SUBMIT_ALGO_ORDER`, то есть
    `MAIN_PROTECTION`, ремодел трейлинга и reduce-only partial exit, так что
    «доживающие» сделки лишались управления. Более слабого класса холда
    («гейт входа» без kill-switch, с авто-снятием) **не заводим**.
  - Такт пересчёта тира офдок **не специфицирует** (а страница комиссий —
    JS-рендер, не читается), поэтому `level`/`ts` пишутся в строку как
    **датчик**: пусть на вопрос ответят собственные данные, а не догадка о
    поведении биржи. `level` при этом — **часть значения группы** (его смена
    рождает строку), иначе датчик не зафиксировал бы смену тира без смены
    ставки (H11, `GAPS_CLOSE_4`).
- **Null-политика:** ставка не резолвится → **реджект `FEE_RATE_UNAVAILABLE`**
  (`RiskValidator`); последняя известная ставка не затирается — на отказе синк
  **не пишет ничего** (история append-only; атрибуция «IGNORE-null» снята как
  рудимент редакции «ставка на навесе» — H10, `GAPS_CLOSE_4`,
  `docs/models/mapping/TradeFeeRate.md` §«Error policy»).
  Fallback из конфига **отвергнут**: подставленное число выглядит фактом, не
  будучи им; заниженная ставка → позиция больше положенной — та же болезнь, что
  H6/H2 (тихое оптимистичное смещение). Цена реджекта — пропуск одной сделки с
  громкой причиной; цена fallback'а — тихо превышенный риск на каждой.
  - **Оговорка о цене (H15, `DOCS_CHECK_4`).** Асимметрия «пропуск одной сделки
    vs риск на каждой» защитима для **реджекта**, но ею же прежде обосновывался
    **холд** — а холд не «одна сделка». С переездом холда на scope=инструмент
    цена стала конечной и адресной (инструменты одной группы, не вся биржа), но
    **нулевой она не является**: пропуск входов — цена по оси **возможностей**
    [Tharp гл.6 с.158-159; гл.11 с.279]. Форвард — §«Форвард-фокус» ниже.
- **Инвариант organic-base-rates.** Запрос **без** `instId`/`instFamily`
  возвращает organic base rates — ставок market-maker incentive не видно, ответ
  приходит **валидный, но не тот**. Мы не участники программы ⇒ base rates для
  нас корректны. **Вход в MM-программу требует пересмотра оси запроса
  `trade-fee`.** Записано именно как условие, а не примечание: молчаливое
  допущение — ровно то, на чём горел H1.
- Прогноз по **taker** (worst-case: вход-маркет = taker, выход-по-стопу = taker →
  консервативно).
  - **Оговорка (H13, `DOCS_CHECK_4`, cross-cutting → шаг ожидаемости / фаза 2):**
    taker-консерватизм подан здесь как **бесплатный**, а корпус этого не
    поддерживает — «издержки: равный вред от занижения и завышения» [Kaufman
    гл.1, PDF с.114-119]. При **maker**-входе (лимитные входы в модели есть —
    `docs/components/RiskValidator.md`, `PriceMode.EXPLICIT`; `makerFeeRate()`
    хранится и не используется) прогноз по taker систематически
    **недосайзит**. В фазе 1 не чиним — это ось ожидаемости, а не механики
    финализации; помечено, чтобы не закрепилось как «выбора не было».
- **Знак ставки — снимается при маппинге** (H2, `GAPS_CLOSE_4`). Биржевая
  конвенция «минус = комиссия» (`docs/integrations/okx/contracts/trade-fee.md`)
  **не выходит за маппинг**: `× −1` в per-source-секции
  (`docs/models/mapping/TradeFeeRate.md` §«Знак ставки — снимается здесь») →
  ниже маппинга ставка есть **издержка** (комиссия положительна, ребейт
  отрицателен). Отсюда `+ commissions` в формуле риска верно **в обе стороны**,
  и `abs` на пути не появляется — **одним местом**, без дубля по формулам.
  - **Что это закрывало.** До `GAPS_CLOSE_4` аксессор отдавал сырую знаковую
    ставку, а `RiskValidator`/`SizeCalculator`/`per-trade-risk-policy` складывали
    её через `+ commissions` без `abs`: убыток на стопе **уменьшался**, бюджет
    риска **увеличивался** — оба члена в одну сторону ⇒ **позиция больше
    положенной**. Дословно тот отказ, ради которого отвергнут fallback (выше):
    тихое оптимистичное смещение, не видное ни в одном логе. Валидация его не
    ловила (отрицательное парсится), `FEE_RATE_UNAVAILABLE` — тоже (только на
    `null`).

### 5. Реакция сверки bills ↔ net (N10)

- **Число всегда авторитетно = positions-history net** (bills-sum его **не
  подменяет**). Расхождение — **сигнал целостности, не ошибка числа**.
- **Не блокирует финализацию:** сделка идёт в `CLOSED` с net-числом. Расхождение
  **сверх epsilon** → **`AnomalyReport`** (audit-аномалия для разбора; `scope =
  INSTRUMENT`, `severity` умеренная) — **не** холд, **не** runtime-error уровней 1-2,
  **не** блок терминала.
- **Epsilon — якорь = оборот, не итог (H7, `GAPS_CLOSE_3`).** Допуск на
  округление между эндпоинтами: **max(абсолютный 0.01 settle-ccy, относительный
  0.5% от Σ`|amount|`)**. Якорь относительного члена — **валовой оборот сделки**
  (Σ модулей движений), **не `|net|`.** Довод: сверка охраняет **ошибку
  композиции разбивки**, а такая ошибка масштабируется **валовыми потоками**
  (сколько движений сложили), а не их **итогом**. Привязка к `|net|` ломается с
  обоих концов: при большом net `0.5%·|net|` глотает реальную дыру, а при
  net ≈ 0 с большими валовыми потоками (типично: прибыльные и убыточные
  ноги гасят друг друга) относительный член вырождается в ноль и сверка
  срывается в ложные аномалии на голом округлении.
- **Величина — по-прежнему провизорна** (`0.01` / `0.5%` — паттерн «провизорное
  значение»): калибровка — пользователь / бэктест. `GAPS_CLOSE_3` меняет
  **якорь** (то, к чему привязан относительный член), не калибровку.
- **Инвариант валюты комиссии (H8, `GAPS_CLOSE_3`) — принят, не допущение.**
  **Комиссии платятся только в валюте расчёта (settle-ccy, USDT).** Оплата
  комиссии сторонней валютой (на OKX — скидка за оплату в OKB) **запрещена
  конфигурацией**; движение с `ccy ≠ resultProfitCurrency` — **нарушение
  инварианта**, то есть аномалия, а не ожидаемый режим работы.
  - **Довод — переносимость, не деталь OKX.** Инвариант формулируется
    **нейтрально к источнику**: заголовочное число берётся net'ом в settle-ccy,
    поэтому издержка, уплаченная **вне** settle-ccy, в это число не входит — и
    `resultProfit` **завышает** реальный net на её величину. Это свойство
    **схемы «net в одной валюте»**, а не особенность OKX: любая площадка с
    оплатой комиссии сторонним токеном ломает число одинаково. Поэтому режим
    отключается на всех источниках, а не патчится per-source.
  - **Дом инварианта — `docs/rules/trading-constraints.md`** (реестр
    инвариантов контура, куда указывает
    `docs/rules/trading-configuration-ownership.md`): инвариант
    source-agnostic, стратегия его не переопределяет. Здесь — только довод.
  - **Детект — только постфактум по `ccy`; проактивного рычага нет.**
    Проверено против офдока (прогон `integrator`, 2026-07-14): в OKX API v5
    **нет поля/настройки «платить комиссию в OKB»** — скидка конфигурируется
    вне API; `feeType` (`account-config`) — **Spot-only** и на SWAP не
    применим, то есть **не рычаг OKB**. Спросить у источника «в какой валюте
    будут комиссии» **нечем** ⇒ инвариант наблюдаем **только** по факту, уже
    заложенным cross-ccy guard'ом на сверке. Это **граница источника, не
    пробел проектирования** — зафиксировано явно, чтобы следующий заход не
    искал несуществующую настройку. Рантайм-наблюдатель — AG3.4/RQ-4
    (`.claude/tests/source-api/okx/plan.md`).
  - **Механика (OKX):** `DealCashFlow` с `ccy ≠ resultProfitCurrency` **не
    отбрасывается молча** фильтром — помечается `AnomalyReport` (guard). Поле
    `DealCashFlow.ccy` **обязательно** — без валюты cross-ccy движение теряется
    молча. Guard остаётся при принятом инварианте: он ловит **нарушение**
    (конфигурацию сбили / площадка сменила поведение), а не штатный режим.

### 6. Инвариант агрегации positions-history — рантайм-верификация (N11)

- **Инвариант:** одна сделка ↔ один `posId` ↔ **одна финализированная** запись
  positions-history, чей `realizedPnl` **кумулятивен по ВСЕМ** partial-закрытиям и
  доборам за жизнь позиции; читается **финализированной** (позиция полностью
  закрыта — `REFRESH_POSITION` показал flat/отсутствие).
- **Требует рантайм-верификации** (контур source-api, demo,
  `.claude/tests/source-api/okx/plan.md`): агрегирует ли OKX partial-выходы
  (partial TP `type` 1 → SL `type` 2) в **одну** запись на `posId`, и в какой
  момент запись финализирована (риск чтения слайса/нефинализированной записи →
  систематический недосчёт realized). До верификации инвариант — **предположение**,
  помеченное в контракт-доке и test-плане. **Гейтит корректность числа** →
  верификация до `CODE`.

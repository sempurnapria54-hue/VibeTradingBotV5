# Агрегаты статистики

## На какой вопрос отвечает этот файл

Какое правило задаёт состав и способ счёта агрегатов статистики.

## Что это за числа и кто их читает

Агрегаты — **персистентная проекция журнала событий**, по которой
держатель видит, как торговала система. Их читает человек и принимает по
ним решения руками; runtime-логика их не читает вовсе
(`docs/rules/audit-not-runtime-source.md`).

Отсюда требование, из которого выведено всё остальное: **число, показанное
человеку, обязано совпадать с числом, которым система действует.** Если
статистика показывает серию убытков, это должна быть та же серия, что
поднимает ступень; иначе человек видит одну картину, а система исполняет
другую, и разбор упирается в вопрос, какому числу верить.

## Зерно строки

**Зёрен два, и различает их предмет.** Сделочная строка —
«тенант × биржевой счёт × определение стратегии × сутки UTC × расчётная
валюта»; строка происшествий — «тенант × биржевой счёт × сутки UTC»
(§«Счётчики происшествий — своё зерно…» ниже). Ключи сделочной строки:

- **тенант** — радиус владения; чужие строки читатель не видит;
- **счёт** — радиус, по которому работают остановки
  (`docs/rules/loss-streak-halt.md`): агрегат по тенанту, склеивающий два
  счёта, показывал бы серию, которой энфорсер не считает;
- **определение стратегии** — то, ради чего агрегат заведён: сравнение
  определений между собой. Пусто законно и означает «сделка стратегии не
  имеет» — восстановительная тропа входа заводит сделку вокруг живого
  риска без определения;
- **сутки UTC** — наименьшее зерно времени, при котором сравнение
  периодов не зависит от часового пояса читателя (`docs/rules/time-utc.md`);
- **расчётная валюта** — в зерне, а не в поле: суммировать результаты
  сделок разных расчётных валют нельзя, а сумма без ключа валюты
  выглядит осмысленной и таковой не является. Читатель, которому нужен
  один итог, выбирает валюту; система курса не подставляет
  (`docs/rules/pnl-reconciliation.md` §«Ожидание курса чужой валюты» —
  курс приезжает наблюдением, а не допущением). **Пусто законно** и
  означает «расчётная валюта результата не резолвилась»: такое состояние
  достижимо (`docs/spec/deal-result.json` — курс применён, а расчётной
  валюты инструмента нет).

**Строка нерезолвленной валюты денежных сумм не несёт.** Сделки с пустой
валютой собираются в собственную строку зерна, и в ней денежные суммы
**нулевые по построению** — все до одной, включая выведенный из знаменателя
плановый риск: складывать числа без единицы измерения нельзя, а группировка
их вместе единицу не создаёт. Исключения плановому риску нет, и довод его —
не тождество двух валют, а **ключ зерна**: единицу строке даёт он, несёт он
валюту результата, второй валютной колонки у строки нет, а сделки в такую
строку попадают разных инструментов. Видна эта популяция счётчиком
`currencyUnresolvedDeals` — то есть не выпадает молча; величины у неё нет по
той же причине, по которой её нет у результата. Охранный инвариант
строки (`rowCurrencyUniform`) при этом мерит **обе** законные формы: либо
вся строка одной известной валюты, либо вся — пустой. Инвариант, мерящий
только равенство, на паре пустот истинен по совпадению и не охраняет
ничего — потому обе формы названы в нём явно.

## Что хранится

**Хранятся только слагаемые; всё, что из них выводится, выводится при
чтении.** Доля выигрышных, профит-фактор, ожидаемость и средний
R-мультипликатор — частные уже хранимых величин, и вторым носителем не
заводятся (`docs/concept.md` П4). Клейм этот **счётный**, и потому состав
хранимого подобран так, чтобы он был верен: без сумм выигрышей и убытков по
отдельности профит-фактор и ожидаемость не вычислимы никак, а без `rSum`
средний R-мультипликатор подменяется отношением сумм — числом с
направленным смещением (ниже).

**Операнд агрегата — поле СОДЕРЖИМОГО события, а не поле чужой базы.**
Указатели на доменные поля (`Deal.resultProfit`, `Deal.plannedRiskAmount`,
`Deal.resultProfitCurrency`) называют **дом формы** — где живёт определение
величины, — а не тропу чтения: строки на чтение базы ядра у аудита нет
(`docs/architecture/contracts.md`), и всё, что агрегату нужно, приезжает
содержимым терминального события. Величина, которой в содержимом нет,
агрегатом не становится (перечень несчитаемого — ниже).

| Величина | Что считает |
|---|---|
| `closedDeals` | закрытых сделок за сутки — оба терминала |
| `riskBearingDeals` | из них **принявших риск**: сделка, закрытая без входа, сюда не входит |
| `winningDeals` / `losingDeals` / `neutralDeals` | из принявших риск — с положительным, отрицательным и нулевым результатом **до финансирования** |
| `resultUnavailableDeals` | из принявших риск — те, у кого результат недоступен |
| `currencyUnresolvedDeals` | из принявших риск — те, у кого расчётная валюта результата не резолвилась |
| `riskUnsizedDeals` | из принявших риск — те, у кого плановый риск **нулевой**: знаменатель отношения к риску их не покрывает |
| `liquidatedDeals` | из принявших риск — закрытые биржей **по марже** |
| `forcedReductionDeals` | из принявших риск — **принудительно сокращённые** биржей |
| `outcomeUndeterminedDeals` | из принявших риск — с **неустановленным** торговым исходом |
| `reconciliationMismatchedDeals` | из принявших риск — с несошедшейся сверкой |
| `reconciliationNotRunDeals` | из принявших риск — с **непроверенной** сверкой |
| `breakdownIncompleteDeals` | из принявших риск — с неполной разбивкой движений |
| `breakdownNotAssessedDeals` | из принявших риск — с **неоценённой** полнотой разбивки |
| `riskBenchmarkMissingDeals` | из принявших риск — с потерянной базой риска |
| `resultBeforeFundingSum` | сумма результатов **до накопленного финансирования** |
| `netResultSum` | сумма итогов — net по всем издержкам, включая финансирование |
| `feeSum` | комиссии обеих ног, издержкой положительные |
| `fundingSum` | накопленное финансирование, издержкой положительное |
| `liquidationPenaltySum` | штрафы принудительного закрытия, издержкой положительные |
| `winResultSum` / `lossResultSum` | суммы выигрышей и убытков по отдельности |
| `plannedRiskSum` | плановый риск сделок, вошедших в денежные суммы, — знаменатель отношения к риску |
| `plannedRiskExcludedSum` | плановый риск сделок, **выведенных** из этих сумм; считается на строке известной валюты |
| `rSum` | сумма R-мультипликаторов сделок |
| `rDenominatorDeals` | сколько сделок в неё вошло — вторая половина среднего R |

**Счётчик рядом с суммой — не украшение, а требование П1.** Всякая
популяция, выпавшая из суммы, обязана иметь свой счётчик: без него она
выпадает **молча**, и число читается как полное. Так стоя́т
`resultUnavailableDeals` (недоступный результат нулём не подменяется —
`docs/concept.md` П1, `docs/rules/absent-value-semantics.md`),
`currencyUnresolvedDeals` (число есть, единицы измерения нет) и
`riskUnsizedDeals` (сайзинга на тропе не было).

**Признак ненадёжности — тоже счётчик.** Ненадёжность — не отсутствие:
число есть, но опереться на него как на проверенное нельзя. Сам признак
сделку из сумм не выводит — иначе суммы перестали бы покрывать закрытые
сделки, — а ненадёжность видна счётчиком: «не проверяли» обязано
отличаться от «проверили, всё в порядке» (`docs/concept.md` П1).
Перечня значений здесь нет — он живёт в исполнимой форме и выводится
прогоном (абзац ниже). Признаки отбора едут в
терминальном событии (`docs/architecture/contracts.md`), и отчёт, ради
которого они туда положены, обязан по ним отбирать.

**Каждое значение признака отбора получает исход, и исход проверяется
прогоном.** Счётного клейма о числе признаков и значений здесь нет — оно
старело бы молча; диспозиция у каждого значения ровно одна: **свой
счётчик** — у всякого нездорового значения, потому что без него его число не
хранит ничто, а «не проверяли» складывается с «проверили, всё в порядке»;
**выводимый остаток** — у здорового значения, чьё число есть популяция счёта
за вычетом прочих (выводимое вторым носителем не заводится, `docs/concept.md`
П4); **объявленная недостижимость** — когда значение несовместимо с принятием
риска. Прозой диспозиция не держится: перечень значений каждого признака
объявлен популяцией исполнимой формы
(`docs/spec/statistics-aggregates.json`) и **выводится из перечня общей
доменной модели**, а не из значений, встреченных в примерах.

**Связь признака отбора с доступностью итога охраняется инвариантом, а не
прозой.** «Полнота разбивки не оценивалась» означает, что добыча движений не
выполнялась, — а тогда итога у сделки нет вовсе. Связь живёт в исполнимой
форме охранным инвариантом с контрпримером: сама она счётчиком не
выражается, а нарушенная — молча испортила бы обе величины.

**Две суммы по отдельности — потому что три производные иначе не
вычислимы.** Профит-фактор (сумма прибылей к модулю суммы убытков),
ожидаемость и средний выигрыш из общей суммы и счётчиков **не
восстанавливаются никак** — это не «хуже», а «невозможно». Отсюда
`winResultSum` и `lossResultSum`; их сумма равна `resultBeforeFundingSum`
за вычетом нулевых слагаемых.

**`rSum` хранится отдельно, потому что частное сумм средним R не
является.** `resultBeforeFundingSum / plannedRiskSum` есть результат на
единицу **суммарного** риска; средний R-мультипликатор — среднее по
сделкам. Они совпадают только при равном риске сделок, а база риска следует
за свободным остатком в обе стороны (`docs/concept.md`, о сжатии в
просадке): после просадки сделки берут меньший риск и получают меньший
вес. Смещение направленное — убытки после просадки взвешены ниже, и число
выглядит **лучше** действительного. Хранятся **обе** половины: средний R
есть `rSum / rDenominatorDeals`, и без счётчика сумма ни на что не делится —
`riskBearingDeals` шире её популяции, а `winRateDenominator` считает
другую.

## Выигрышность меряется результатом до финансирования

**Сделка выигрышна, когда её результат до финансирования строго
положителен** — то самое число, которым двигается счётчик серии
(`docs/rules/loss-streak-halt.md` — дом того, чем двигается счётчик).
Состав числа там
и живёт; здесь он не переписывается.

**Что уже вычтено, а что нет — сказано прямо, потому что имя об этом не
говорит.** В обе денежные суммы строки комиссии обеих ног и штраф
принудительного закрытия **уже вошли вычтенными**: слагаемое приходит
биржевым net эпизода (`docs/spec/deal-result.json`). Различаются суммы
ровно на накопленное финансирование. Отсюда `feeSum` и
`liquidationPenaltySum` — **показания величины издержки, а не вычитаемые**:
вычесть их из суммы значит вычесть дважды, и ошибка эта в **разрешающую**
сторону на убыточном периоде — убыток выглядит меньше действительного.

**Имя суммы называет её состав, а не происхождение.** Имя вида «ценовая
сумма» читалось бы как «чисто ценовое» при том, что число уже net по
комиссии; имя со словом gross называло бы gross ровно тот носитель, который
корпус выше по цепочке зовёт **net** (`docs/models/domain/core/Position.md`).
Читатель, выбирающий «сколько я на самом деле заработал», взял бы по таким
именам не то число.

**На уровне сделки та же величина зовётся иначе, и это не рассинхрон.** В
доме энфорсера серии (`docs/spec/loss-streak-halt.json`) она — **ценовой
результат**, и имя там адресует различение с итогом: серия меряет, была ли
допустимая потеря, а финансирование в определение риска не входит. Здесь
имя адресует **состав**, потому что читатель отчёта видит рядом `feeSum` и
без прямого указания вычел бы её второй раз. Величина одна, дом формы один
(указатель — операнд `priceResult` спеки агрегатов), различаются только
имена сумм: у энфорсера потребитель — код, здесь — человек, принимающий
решение о риск-аппетите.

**Почему не итог.** Иначе `winningDeals` и серия, поднявшая ступень,
расходились бы систематически и в обе стороны: carry-доход поверх
ценового убытка показал бы выигрыш там, где энфорсер насчитал убыток, а
carry-расход поверх ценовой прибыли — наоборот. Два числа об одном
предмете, расходящиеся по построению, — второй носитель истины
(`.claude/rules/carrier-levels.md`).

**Итог при этом не прячется:** `netResultSum` стои́т рядом отдельной
величиной, и разница двух сумм равна `fundingSum` — то, что владелец
обязан видеть, когда решает, стоит ли гипотеза своей стоимости
удержания. Равенство держится тем, что все три суммы считаются по
**одной** популяции: комиссии и финансирование своей ветви доступности
не имеют — они приходят той же записью закрытия эпизода, что и итог
(`docs/spec/loss-streak-halt.json`, операнд `fundingCost`;
`docs/spec/deal-result.json` — предикат доступности). Разведи популяции
— и владелец, взяв три опубликованных числа, получил бы неравенство.

**Равенство — не клейм прозы, а охранный инвариант с прогоном.**
`fundingDecompositionHolds` (`docs/spec/statistics-aggregates.json`)
считает разность двух сумм и сверяет её с `fundingSum` на каждом примере;
контрпример предъявляет несогласованную тройку операндов и называет, чем
она исключена. Равенство, живущее клеткой таблицы и нотой, не проверяется
ни одним примером и не мерится мутационной пробой — потому у него есть своя
величина.

Какое из двух чисел держатель считает «результатом для оператора» и
нужен ли второй контроль поверх серии — вопрос `RISK-Q2`, и агрегат его
не предрешает: он показывает оба.

## Популяция долей — сделки, принявшие риск

**Сделка, закрытая без входа, в долях не участвует.** Она не торговала:
позиции не было, риск не принимался, а результат её — ноль по расчёту, а
не по исходу (`docs/rules/deal-without-operations.md`,
`docs/models/domain/aggregate/Deal.md` §«Итоговый результат сделки»).
Включённая в знаменатель, она размывает долю выигрышных тем сильнее, чем
чаще срабатывает истечение условия входа, — то есть искажает метрику
ровно в те периоды, когда рынок не давал входов.

`closedDeals` считает **все** закрытые: сколько кандидатов дошло до
терминала — самостоятельный факт, и терять его нельзя. Доли считаются от
`riskBearingDeals`.

## Счётчики происшествий — своё зерно, а не строка сделочного агрегата

**Строка «тенант × биржевой счёт × сутки UTC» — второе зерно**, и в ней
живут счётчики происшествий. Каждый — отбор строк журнала по классу
события; имена и форма — `docs/spec/statistics-aggregates.json`.

| Счётчик | Отбор |
|---|---|
| `openedDeals` | заведённых сделок за сутки |
| `orderDecisions` | решений о создании **обычной** заявки |
| `raisedHolds` | поднятых ступеней — **обе тропы вместе** |
| `hardRaisedHolds` | из них жёстких |
| `manuallyRaisedHolds` | из них поднятых **ручной тропой**, а не проходом |
| `anomalyReports` | отчётов о происшествиях — **обе тропы вместе** |
| `criticalAnomalyReports` | из них критичных |
| `manualOperationReports` | из них заведённых **ручной тропой**, а не детекцией |

**Счётчик над классом, который бывает многократным на предмете, считает
ПРЕДМЕТЫ.** Отбор строк журнала по классу события — форма, верная лишь
тогда, когда у предмета событие ровно одно. Есть класс, у которого это не
так: `DealShutdownInitiated` публикуется на каждом ребре присвоения причины
остановки, а их у одной сделки бывает два
(`docs/architecture/contracts.md`). Счётчик остановок, заведённый общей
формой, дал бы такой сделке вес два — и наблюдалось бы это как рост
активности, а не как дефект. Поэтому у каждого счётчика происшествий
названо, **что** он считает. У классов, над которыми стоя́т счётчики
таблицы выше, событие однократно на своём предмете — заведение сделки,
решение о заявке, подъём ступени, отчёт о происшествии, — и форма отбора по
классу события им верна. **Счётчика остановок среди них нет**, и заводить
его общей формой нельзя: ему нужен отбор по различным сделкам.

**Два разреза у подъёма ступени обязательны, а не желательны.** Без
разреза по ступени три мягких инструментных холда и одно сворачивание
всего счёта читаются одинаково — «поднятых ступеней: 3», — а это разные
решения человека. Без разреза по тропе одно число складывает
противоположные состояния: «система остановила себя» есть сигнал, что
гипотеза не работает, «остановили её снаружи» — вмешательство в контур;
сложенные, они выдают вмешательства за признак отказа гипотезы.
Операнды различения едут в содержимом события сегодня — и ступень, и код
тропы. Что из ручной тропы сегодня не исполнено и чем закрывается —
`docs/rules/manual-halt.md`.

**Разрез зовётся по тропе и различает её КОДОМ, а не актором строки.**
Актор отвечает на вопрос «кем порождён ход», и у джобы, запущенной ручным
триггером, он равен принципалу — контекст обязан переживать смену треда
(`docs/models/domain/other/Auditable.md`). По актору автоматическая
остановка, найденная в ручном прогоне детекции, попала бы в число ручных, то
есть разрез давал бы ровно ту ошибку, против которой заведён.

**Отсюда и популяция обоих ручных счётчиков — ТРОПА, а не человек.** Код
метит операцию ручной поверхности и одинаков у человека и у скрипта, до неё
дошедшего (`docs/models/domain/other/Auditable.md`); «кто именно» отвечает
актор, и он едет своим носителем в содержимое, а операндом разреза не
служит.

**Те же два разреза обязательны у отчёта о происшествии, и по тем же
доводам.** Отчёт заводит не только детекция: ручная поверхность заводит его
и на постановке ступени, и на **снятии** (`docs/rules/manual-halt.md`).
Снятие — действие, обратное постановке; сложенное с происшествиями
автоматики, оно выдаёт ручную операцию за находку детектора, то есть даёт
ровно ту ошибку, от которой разрез по тропе защищает у подъёма ступени.
Второй разрез — по критичности: «kill-switch гонялся» и «не гонялся» в одном
числе неразличимы. Операнды обоих разрезов едут в содержимом события
сегодня.

**Направление операции третьим разрезом не разводится, и это решение, а не
пропуск:** какая именно операция и когда — вопрос к журналу, где коды двух
операций различны, и суточное число на него не отвечает.

**Счётчик решений о заявке считает у́же своего имени, и это названо.** Класс
события порождает исполнитель создания **обычной** заявки; решение об
отдельной условной заявке классом события не выражено вовсе, а перечень
непокрытого есть разность объявленных и построенных классов
(`docs/models/domain/other/AuditRecord.md`) — класс, который не объявлялся,
в эту разность не попадает и читателю о себе не сообщает ничем. Сверх того
перестановка ноги выражается новой сущностью плюс отменой старой
(`docs/rules/replace-not-amend.md`) и даёт своё решение, поэтому число несёт
и перестановки. Разреза у счётчика нет, и это не пропуск: операнд, который
развёл бы вход и перестановку, в содержимом не едет, а завести его — правка
чужого производителя (дом ожидания — секция `.claude/work/backlog.md` о
решении о защите в журнале и разрезе активности заявок).

**Почему не в сделочной строке.** Её зерно содержит определение
стратегии и расчётную валюту, а события подъёма ступени и отчёта о
происшествии не несут **ни того, ни другого** — и не будут: ступень
поднимается на счёте либо на паре «счёт, инструмент», где стратегии нет
по построению, а денежной величины у неё нет вовсе. Уложенные в
сделочную строку, они попали бы в клетку с пустым определением, где
пустота уже занята другим смыслом — «сделка стратегии не имеет», — а два
смысла в одном значении ключа запрещает
`docs/rules/absent-value-semantics.md`.

**Оба зерна складываются из одного журнала** тем же пересчётом и той же
джобой; расходятся только ключи строки.

## Классы закрытой сделки для агрегата

Закрытая сделка попадает в счётчики по двум осям, и они независимы:

| Ось | Значения |
|---|---|
| приняла риск | `true`, `false` |
| результат | `POSITIVE`, `NEGATIVE`, `ZERO`, `UNAVAILABLE` |

**Перечень — полное произведение, а не список встреченного.** Класс, в
который сделка попасть не может, объявляется недостижимым с названной
причиной, а не молчанием: сделка без входа результат имеет всегда, и он
ноль по расчёту (`docs/models/domain/aggregate/Deal.md` §«Итоговый
результат сделки»), поэтому три из восьми классов недостижимы по
построению тропы.

**Величина серии подряд убыточных агрегатом не считается.** Она
последовательная — выводится только упорядоченным проходом, которого у
проекции нет, — и её носитель уже существует: счётчик на биржевом счёте
(`docs/rules/loss-streak-halt.md`). Второй записи той же истины не
заводится.

## Пересчёт — проекция, а не накопитель

**Строка агрегата пересчитывается из журнала целиком, а не двигается
событием.** Довод тот же, которым итог сделки отверг инкремент
(`docs/models/domain/aggregate/Deal.md` §«Итоговый результат сделки»):
повторная доставка события безразлична проекции и задваивает накопитель.

- **Писатель** — джоба пересчёта модуля статистики; **момент** — её тик
  плюс ручной триггер (`.claude/rules/codestyle.md` §Джобы).
- **Как джоба достаёт входы, при том что журнал лежит в ДРУГОЙ базе.**
  Модуль статистики и модуль аудита живут одним процессом; к базе
  `audit` джоба ходит **только на чтение**, и держит это **грант** — на
  том подключении, которое джобе и положено. Состав ролей, направление
  грантов и названный остаток охраны (какое подключение внедрено, грант
  не решает) объявлены домом раскладки
  (`docs/architecture/data-ownership.md`) и здесь не пересказываются.
  Запроса, соединяющего две базы, при этом нет — запрет
  того же дома не нарушается: там запрещён **кросс-базовый запрос**, а
  здесь два независимых запроса к двум базам в одном проходе.
- **Агрегирование выполняется В БАЗЕ ЖУРНАЛА, а не в памяти джобы.**
  Запрос к `audit` группирует строки окна **по ключу зерна собираемой
  строки** и отдаёт **по строке на ключ**; через границу процесса проходит
  число строк зерна, а не
  число событий. Это и есть исполнение правила больших выборок
  (`.claude/rules/codestyle.md`, правило о выборках только окном либо
  пагинацией): «вытащить сутки по всем
  тенантам в память» им прямо запрещено, а объём результата здесь ограничен
  **произведением операндов ключа зерна** — величиной, которая
  растёт с бизнесом, а не с потоком событий. Окно ограничено сверху теми же
  сутками, что и пересчёт, и обслуживается индексом по моменту происшествия
  (`docs/models/domain/other/AuditRecord.md`).
- **Операнды приходят и колонками журнала, и из содержимого, и это не
  спор с «content реляционно не раскладывается».** То правило — о
  **схеме**: колонками вынесены только операнды ключа и радиусы отбора.
  Запрос читать содержимое вправе. **Группировка идёт по ключу зерна
  собираемой строки, и другого ключа у запроса нет.** Расчётная валюта
  сделочного зерна приходит **из содержимого**.
  **Колонка входит в ключ тогда и только тогда, когда она измеряет
  строку агрегата**, и ни одна другая в него не входит ни у одного зерна:
  инструмент и сделка отбирают строку журнала, а класс события отбирает
  строки каждого счётчика происшествий.
  Группировка по сделке дала бы строку на сделку вместо строки на сутки —
  ту, которую upsert по ключу зерна схлопнул бы, оставив числа последней
  записанной. Всё, чем джоба считает, обязано в содержимом **быть** —
  иначе величина агрегатом не становится (перечень несчитаемого ниже).
- **Разъезд на два процесса шов не проходит сам собой**, и ограничение об
  этом названо у инвентаря сервисов — `docs/architecture/services.md`,
  строка о совместном процессе аудита и статистики. Здесь оно не пересказывается
  (`.claude/rules/carrier-levels.md`): дом стои́т у того, кто разъезд
  исполнит.
- **Что пересчитывается за тик — скользящее окно последних суток**,
  число которых назначает владелец. Сутки берутся по моменту
  **происшествия** события: в них и лежит сделка, к которой оно
  относится.
- **Полный пересчёт** — та же джоба по всему журналу. **Писатель тот же,
  момент — ручной триггер держателя** (`.claude/rules/codestyle.md`
  §Джобы: у каждой джобы есть внерасписанный запуск через фасад);
  расписания у него нет намеренно — он нужен после опоздания, о котором
  знает человек, а не периодически. Законен он всегда: проекция от
  порядка не зависит и повтора не боится.

**Отметки последнего пересчёта нет намеренно, и это не упрощение.**
Отметка по моменту приёма выглядит дешевле окна и вносит дефект, который
не наблюдается: `recordedAt` присваивается **кодом до фиксации
транзакции**, поэтому строка, начатая раньше и зафиксированная позже,
получает момент **меньше** уже сдвинутой отметки — и не попадает ни в
один пересчёт. Тихая потеря строки в проекции — ровно то, против чего
проекция и выбрана.

**Названная цена окна.** Событие о сделке старше окна, приехавшее с
опозданием, свои сутки не подвинет до полного пересчёта. Условие
пересмотра — наблюдённое опоздание больше окна; величина окна
калибровочная, и назначает её владелец
(`.claude/processes/question-delegation.md` §«Число: риск-аппетит против
калибровки наблюдения»), направление консервативности — в сторону
бо́льшего окна: лишний пересчёт стоит запроса, пропущенный — неверного
числа у человека.

**Расхождение агрегата с журналом невозможно тихо:** агрегат выводим из
журнала повторным прогоном, и разница двух прогонов есть дефект
пересчёта, а не потерянное событие.

**Строка агрегата несёт момент СВОЕЙ СБОРКИ, и рядом названо, чего эта
сборка не включает.** Число, показанное без своей актуальности, читается
как «сейчас», а является проекцией с лагом (`docs/concept.md`, П1).
Отдаётся при этом то, что действительно есть, — момент прогона,
собравшего строку, — а не «момент, на который число верно»: такой
величины у проекции не бывает, и показывает это соседний пассаж о цене
окна.

- строка **внутри** окна получает свежий момент, **не включив** событие,
  приехавшее с опозданием больше окна: до полного пересчёта её число
  беднее своего момента;
- строка **вне** окна не пересчитывается вовсе, и её момент застывает:
  это означает «пересчитывать нечего», а не «устарело»;
- **журнал, из которого строка собрана, может иметь дыру**, и ветви
  разрыва перечисляет владелец журнала, а не эта строка
  (`docs/models/domain/other/AuditRecord.md`). Момент сборки об этом не
  говорит **ничего**: он
  свежий и у строки, собранной из журнала с дырой. Признак живёт своим
  носителем — durable-строкой состояния приёма
  (`docs/models/domain/other/AuditRecord.md`), — и отдаётся поверхностью
  **вместе с числами**, а копией в строке агрегата не заводится: состояние
  приёма есть свойство группы, а не суток, и в строке оно устаревало бы при
  каждом пересчёте.

Все три оговорки читатель получает вместе с числом. **Писатель момента** — та
же джоба пересчёта; **момент записи** — та же транзакция, что пишет числа
строки.

**С запретом отметки прогресса чтения это не спорит.** Запрет адресован
отметке как **операнду выбора** пересчитываемого: по ней выбиралось бы
окно, и строка, зафиксированная позже своего момента, выпала бы из всех
пересчётов. Момент на строке агрегата — **показание читателю**; его не
читает ни один алгоритм, и выбор окна по-прежнему идёт скользящим окном
суток.

**Реплика модуля в `prod` — одна.** Довод тот же, что у ядра: джоба
пересчёта защищена in-process guard'ом, распределённого замка нет, и две
реплики дали бы два одновременных пересчёта одной строки. Ось числа реплик
— `docs/architecture/platform.md`.

## Чем это отличается от метрик платформы

`docs/architecture/platform.md` §Наблюдаемость объявляет бизнес-метрики
(сделки по терминалам, холды по ступеням, серия убытков) в Prometheus.
Разграничение:

- **агрегат — носитель факта**: персистентная запись, запрашиваемая за
  любой прошлый период (`docs/concept.md` П3 — «носитель наблюдаемости —
  персистентная запись, не лог»);
- **метрика — сигнал**: она ротируется, не переживает срок хранения и
  служит алерту «происходит сейчас».

Одно явление законно считается обоими; **сослаться при разборе** можно
только на агрегат. Метрика агрегату не источник и не потребитель: обе
считаются независимо, каждая от своего входа.

## Чего агрегаты не считают

- **Сигналов и бэктестов** — их предмета не существует до фазы 4
  (`docs/architecture/signal-strategy-allocator.md`). Формулировка «агрегаты
  по … сигналам» получит предмет вместе с ними.
- **Экспозиции и живого риска** — это состояние, а не происшествие;
  их владелец — ядро, и читаются они у него.
- **Ничего, чего нет в журнале.** Величина, операнда которой не несёт ни
  одно событие, агрегатом не становится: агрегат — проекция журнала, а не
  второй читатель чужой базы.
- **Ценовой компоненты до издержек.** Отдельной колонкой она не заводится:
  чтобы получить её из хранимых, не хватает члена чужой валюты, а завести
  оба — две колонки, чей единственный потребитель есть проверка тождества.
  Вместо этого состав каждой суммы назван прямо (раздел о том, чем меряется
  выигрышность), и величина издержки видна своими
  слагаемыми.

### `incident_aggregates`

| Колонка | Тип | Ограничение |
|---|---|---|
| `tenant_id` | `varchar(64)` | `not null`, ключ зерна |
| `exchange_account_internal_id` | `varchar(64)` | `not null`, ключ зерна |
| `bucket_date` | `date` | `not null`, ключ зерна |
| `opened_deals`, `order_decisions`, `raised_holds`, `hard_raised_holds`, `manually_raised_holds`, `anomaly_reports`, `critical_anomaly_reports`, `manual_operation_reports` | `integer` | `not null` |
| `assembled_at` | `timestamptz` | `not null` |

**Счётчики `not null`, потому что ноль у них — исход, а не пробел:** «за
сутки не было ни одного» есть факт, и подменять его пустотой значило бы
терять различие между «не было» и «не считали». Денежные суммы — по тому
же доводу: сумма пустого множества есть ноль.

**Обе таблицы несут момент сборки строки** — колонку, которую пишет джоба
пересчёта той же транзакцией, что и числа. Она не операнд выбора
пересчитываемого, а показание читателю (раздел о пересчёте выше).

**Уникальность — по ключу зерна своей таблицы, и `unique nulls not
distinct` нужен только `deal_aggregates`**, а клауза несущая, а не
украшение: в ключе `incident_aggregates` пустых колонок нет ни одной, а в
ключе `deal_aggregates` их **две** — определение стратегии и расчётная
валюта, — а PostgreSQL по
умолчанию считает пустые значения в уникальном индексе **различными**
(`docs/rules/idempotency-via-unique.md` — дом правила о пустоте в ключе):
молчаливый
`UNIQUE` поверх nullable дедупа не даёт. Без клаузы upsert существующей
строки не находил бы, и проекция росла бы **по строке на каждый прогон
пересчёта** — числа восстановительных сделок и сделок нерезолвленной
валюты умножались бы на число пересчётов, то есть выглядели бы торговой
активностью. Прецедент в этом же репозитории —
`services/market-data/src/main/resources/db/migration/V1__market_data_baseline.sql`.

**Индексы названы именами и колонками**, как требует

  `exchange_account_internal_id`, `bucket_date`) — уникальные, по ключу
  зерна своей таблицы; довод клаузы — абзацем выше.

Отдельного индекса под ключ дедупа событий нет и не заводится: агрегат
событием не двигается, дедуп держит журнал.

Строки обеих таблиц **восполнимы полностью** — выводимы из журнала
повторным пересчётом, поэтому глубины хранения у них нет
(`docs/models/domain/other/AuditRecord.md`).

# Признак «операций по сделке не было»

## На какой вопрос отвечает этот файл

По какому признаку сделка считается не имевшей операций на бирже.

## Зачем отдельный носитель

Признак обслуживает **больше одной задачи** и срабатывает на тропах с
разными достижимыми фактами, поэтому выражается **один раз здесь**, а
потребители на него ссылаются (H7 `DOCS_CHECK_12`, решение пользователя,
вариант 4). Потребителей два:

1. **Ветвление внутри `FINALIZE_DEAL_EXIT_ACTION`** — по истине признака
   действие эмитит сразу звено 2 (`MARK_DEAL_CLOSED_COMMAND`), которое
   пишет `resultProfit = 0` и ставит терминал
   (`docs/components/SystemActionExecutor.md`
   §`FINALIZE_DEAL_EXIT_ACTION`, `docs/components/MarkDealClosedExecutor.md`
   §«Вторая ветка»).
2. **Отбор сделок для отчёта** — сделка без состоявшихся операций не
   принадлежит распределению `R`, на котором меряется ожидаемость.
   **Фильтром эндпоинта этот составной предикат не является** (H6
   `GAPS_CLOSE_13`, решение пользователя): для отбора факт уже выражен
   **статусом сделки** — `status` вместе с `closeReason` говорят, как
   сделка закрылась (терминал без входа), а `status` и `closeReason` —
   поля сделки, индексируемые и воспроизводимые. Отдельной колонки под
   уже выраженное различение не заводится; требование «каждый фильтруемый
   признак — поле сделки» (`docs/models/domain/aggregate/Deal.md`
   §«Признаки отбора для отчёта») этим соблюдено, а не ослаблено.

Прежняя редакция называла потребителем 2 сам составной предикат — и тогда
фильтр отчёта пришлось бы считать join'ом по `deal_cash_flows`/`orders`,
то есть выводом на лету, который правило отбора запрещает. Разведение
снимает это: **предикат обслуживает ветвление действия** (потребитель 1),
где нужен факт движения средств на бирже, **отбор идёт по статусу**.
Определение факта при этом остаётся одно — здесь.

## Правило

**Признак составной по тропам.** Единого операнда у него нет, и это форма,
а не пробел: тропы различаются тем, **дошла ли заявка до биржи**.

| Тропа | Операнд | Почему такой |
|---|---|---|
| `PRECHECK` — истечение условия входа | **статус сделки** | отправки не было по построению: сделка не покидала `PRECHECK` |
| `PRECHECK` — риск-блок (`RISK_CONTROL`) | **статус сделки** | то же: `RiskValidator` отработал **до** создания команды (`docs/rules/risk-validator-scope.md`) |
| `ENTRY_SUBMITTED` — отмена неисполненного входа | **факт движения средств на бирже** | заявка уже на бирже и могла частично исполниться; статус этого не различает |

**Durable-носители факта движения средств** — оба выразимы запросом, что и
требуется исторической выборке:

- строки `DealCashFlow`, прилинкованные к сделке (движение средств и есть
  то, что они фиксируют; `docs/models/domain/other/DealCashFlow.md`);
- со стороны заявки — `Order.accumulatedFillSize > 0`
  (`docs/models/domain/core/Order.md`).

**Почему статуса достаточно на двух верхних тропах.** Обращения к бирже там
не было ни одного, поэтому «проверка факта операций» вырождается в факт,
уже выраженный статусом; тянуть ради него exchange-read значило бы вводить
недостоверный операнд там, где есть достоверный.

**Рестарт дыры не образует.** Сделка, застигнутая рестартом между отправкой
и наблюдением, доводится до нужного статуса рефрешем на **следующем запуске
FSM** — тем же механизмом, которым добывается любой недобытый факт;
отдельной ветки восстановления признак не требует.

## Границы применения

- Признак отвечает **только** на вопрос «были ли операции». Он **не**
  различает торговые исходы состоявшихся сделок (штатный выход /
  ликвидация / принудительное сокращение) — это отдельное поле сделки
  (`docs/models/domain/aggregate/Deal.md` §«Признаки отбора для отчёта»).
- Признак **не** заменяет `closeReason` и **не** выводится из непустоты
  `plannedRiskAmount`: последняя истинна уже у входа, отменённого до
  исполнения.
- Обратный случай («операции были, а `R` пуст») признаком не покрывается —
  `docs/models/domain/aggregate/Deal.md` §«Операции были, а `R` пуст».

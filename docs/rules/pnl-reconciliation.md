# Сверка итогового P&L (bills ↔ net)

## На какой вопрос отвечает этот файл

Какое правило действует для сверки итогового P&L сделки
(bills-разбивка ↔ net positions-history)?

## Что сверяется, когда, кем

- **Число всегда авторитетно = net из positions-history** — bills-сумма
  его **не подменяет**. Расхождение — сигнал целостности разбивки, не
  ошибка числа. Net авторитетен **в своей валюте** (settle-ccy);
  заголовочное `Deal.resultProfit` = net + cross-ccy-слагаемое — состав
  и предикат слагаемого — `docs/models/domain/aggregate/Deal.md`
  §«Итоговый PnL (resultProfit)».
- **Сверяются четыре пары по категориям** (`REALIZED_PNL`, комиссии,
  `FUNDING`, `LIQ_PENALTY`) — слагаемые разбивки `DealCashFlow` против
  чисел записи закрытия на `Position`; суммы идут по строкам settle-ccy
  вне списка исключений биржи. Состав пар и область сверки —
  `docs/components/FinalizeDealExitExecutor.md` §«Расчёт прибыли
  (шаг 7) и сверка», `docs/models/mapping/DealCashFlow.md` §«Область
  сверки задаётся списком исключений по бирже».
- **Когда и кем.** Сверку гоняет `FinalizeDealExitExecutor` в
  исполнении `FINALIZE_DEAL_EXIT_COMMAND` (штатная тропа
  `EXIT_PENDING → CLOSED`); на ветви (a) аварийного терминала — если
  движения уже добыты. Обязанность сверки — составной предикат: запись
  закрытия добыта **и** окно движений закрыто
  (`docs/models/domain/aggregate/Deal.md` §«Признаки отбора для
  отчёта»).

## Допуск (epsilon)

```text
epsilon = max( 0.01 settle-ccy,
               min( 0.5% × Σ|amount|, k × ожидаемая комиссия сделки ) )
```

- **Допуск один на сделку, не на пару:** сравнивается с общим
  расхождением `Δ = Σ|Δᵢ|` по четырём парам; расхождения разных знаков
  не гасят друг друга.
- **Тест двухчастный, срабатывает меньший.** Относительный член
  якорится на **валовой оборот** (Σ|amount|), не на |net|, — охраняет
  ошибку композиции разбивки; омиссионный член (`k × ожидаемая
  комиссия`) охраняет омиссию фиксированного размера; **пол общий,
  вынесен наружу**.
- **Операнды омиссионного члена — persisted write-once числа ноги
  входа** (инвариант «шесть или ни одного»); считается поногово, ставка
  комиссии не перечитывается, навес `InstrumentExternalRules`
  финализатор не читает. Формулы операндов — по домам:
  `docs/models/domain/core/Order.md` §«Плановый риск и его операнды»,
  `docs/components/FinalizeDealExitExecutor.md` §«Расчёт прибыли
  (шаг 7) и сверка».
- **Величины `0.01` / `0.5%` / `k` — провизорны** (калибровка —
  пользователь / бэктест; калибратор `k` — предусловие `CODE` шага 7).
- **Ветка «планового риска нет»** (позиция создана вне приложения):
  сумма по ногам пуста (не ноль), омиссионный член не участвует,
  `epsilon` вырождается в `max(0.01, 0.5% × Σ|amount|)`, факт помечается
  `AnomalyReport` `PLANNED_RISK_MISSING`.
- **Ветки «операнд допуска не резолвится» нет.** Недостача **нашего**
  операнда — нарушение инварианта «шесть или ни одного»; его ловит
  детектирующий контур **отказом операции**, до расчёта допуска пустой
  операнд не доезжает (`docs/models/domain/aggregate/Deal.md`
  §«Обнаружение рассогласования пары носителей»). Биржевой холд не
  ставится: радиус ущерба известен и локализован сделкой
  (`docs/rules/exchange-hold.md` §«Что переводит в HOLD», callout).

## Реакция на расхождение

- Расхождение **сверх epsilon** → `Deal.reconciliationStatus =
  MISMATCHED` + `AnomalyReport` `PNL_RECONCILIATION_MISMATCH`
  (аудит-аномалия для разбора: `scope = INSTRUMENT`,
  `severity = NON_CRITICAL`). Сошлось — `MATCHED`; обязанность сверки
  не наступила — `NOT_RUN` (терминал успешный).
- **Что реакцией НЕ является:** финализация не блокируется — сделка
  идёт в `CLOSED` с net-числом; число bills-суммой не подменяется;
  холд (любого scope) не ставится; runtime-error уровней 1-2 не
  поднимается.
- **Уровня в error-градации у `PNL_RECONCILIATION_MISMATCH` нет** —
  известный открытый вопрос `PNL-Q1` п.3
  (`.claude/work/questions/open-questions.md`;
  `docs/rules/error-handling-policy.md` §«Внутренняя градация»,
  клауза «Незакрытое»). Остаётся открытым.

## Асимметрия троп отказа добычи

Отказ добычи P&L-фактов обрабатывается **по-разному на штатной и
аварийной тропе**; различие кодируется явно.

| Тропа | Отказ добычи | Реакция |
|---|---|---|
| Штатная (`EXIT_PENDING` → `CLOSED`) | `REFRESH_POSITION_COMMAND` / `REFRESH_BILLS_COMMAND` не смогли прочитать | **ретрай по бюджету исполнения `REFRESH_DEAL_CONTEXT_ACTION`**; исчерпание уводит сделку ошибочной тропой в `ERROR` + полный холд инструмента (`docs/rules/instrument-hold.md` §«Серия неудач: реакция на исчерпание бюджета») |
| Аварийный терминал (`ERROR` → `EMERGENCY_CLOSED`) | **отказ канала добычи** (транспорт, парс, исчерпанный цикл) | **ретрай по тому же бюджету**; исчерпание → `FAILED` строки — durable-исход «недоступно» → `resultProfit = null` «неисчислимо» → **терминал ставится**. Радиусная реакция не поднимается: обесценена отчётность одной закрытой сделки, не управление риском |
| Аварийный терминал (`ERROR` → `EMERGENCY_CLOSED`) | **дефект содержимого ответа** (`ControlledExchangeException`) | **как на штатной тропе**: `FAILED` сразу (non-retryable) + бросок ⇒ **биржевая заморозка** (`Exchange.HOLD`, ступень 1 лестницы, без kill-switch — `docs/rules/exchange-hold.md`); сделка параллельно доходит до ошибочного терминала с `resultProfit = null` — ветки не конкурируют |

- **Почему асимметрия, а не единообразие.** На штатной тропе отказ
  значит «факт ещё не получен»: сделка живая, ждать безопасно, повтор
  дешевле неверного числа. На аварийном терминале ждать нельзя: live
  risk снят, осталось довести сделку до терминала — иначе она зависает
  в `ERROR` вопреки инварианту «сделка всегда доходит до терминала»
  (`docs/lifecycles/Deal.md`).
- **Исполнитель приравнивания — `ServiceCommandExecutor`**, предикат —
  durable-факт `Deal.status = ERROR`. Бюджет расходуется **штатно на
  обеих тропах** (`attemptCount`++ → `RETRY_PENDING` → `FAILED`);
  дискриминатор управляет **броском** (радиусной реакцией), не ростом
  счётчика (`docs/components/ServiceCommandExecutor.md` §«Ветка
  `Deal.status = ERROR`»).
- **Приоритет двух живых SYSTEM-исполнений:** добыча раньше терминала —
  `FINALIZE_DEAL_ERROR_ACTION` не эмитится, пока
  `REFRESH_DEAL_CONTEXT_ACTION` не вынесла исход; порядок держит
  `ErrorHandler` (одно действие за проход).
- **Различение «пусто» vs «жёсткий отказ» — только на аварийной
  тропе**: на штатной оба исхода ведут в ретрай, а исчерпание — в
  `ERROR`, откуда работает аварийное правило.
- **Полнота разбивки bills выход не гейтит** (best-effort: недобранные
  движения дают `AnomalyReport` на сверке, не удержание в
  `EXIT_PENDING`); гейтит число факт **закрытия**, добываемый
  `REFRESH_POSITION_COMMAND`.

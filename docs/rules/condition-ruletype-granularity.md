# Именованный `ruleType` vs генерик-сравнение

## На какой вопрос отвечает этот файл

Когда заводить выделенный именованный `StrategyConditionRuleType`, а
когда условие выражается генерик-сравнением (`INDICATOR_COMPARE` /
`PRICE_COMPARE` / `CROSSOVER`).

## Правило

Именованный доменный `ruleType` **оправдан** над генерик-сравнением
только когда инкапсулирует семантику, **не выразимую одним сравнением
операнд-vs-операнд**:

- **составное условие / несколько входов** — буфер + подтверждение +
  ссылка на уровень (`RANGE_BREAKOUT_CONFIRMED`);
- **темпоральная / стейтфул-семантика** — текущее vs прошлое
  (`TREND_CHANGED`);
- **предвычисленный составной флаг/событие**, читаемый готовым (то же
  `RANGE_BREAKOUT_CONFIRMED` — событие структуры);
- **событие / тайминг без сравнения значений** (`CANDLE_CLOSED`);
- **runtime-факт жизненного цикла сделки** вне грамматики рыночных
  операндов (`NO_OPEN_POSITION`, `POSITION_OPENED`, …).

Именованный `ruleType` — **чистый алиас** и **не заводится** (а
существующий — сворачивается), когда сводится ровно к одному
`<X>_COMPARE` над каталожным/рыночным операндом и константой, без
добавочной семантики. Основание — DRY (`codestyle`: «дублирующего кода
быть не должно»): алиас дублирует генерик и обычно ещё и сужает его
(зашитый оператор → теряется вторая сторона сравнения).

## Применение (зафиксированное)

- **`EFFICIENCY_BELOW_THRESHOLD` — свёрнут** в `INDICATOR_COMPARE` над
  ER-операндом каталога (`EFFICIENCY_RATIO`): «ER ниже порога» = ER `LT`
  `CONSTANT`, без добавочной семантики (ER нормирован по определению),
  и ER нужен в обе стороны (`LT` шум/range, `GT` тренд) — алиас сужал бы
  до одной. Решение — `docs/decisions/efficiency-ratio-as-catalog-indicator.md`.
- **Оправданы** (не алиасы): `RANGE_BREAKOUT_CONFIRMED` (предвычисленное
  составное событие структуры — `breakoutEvent`, читается готовым),
  `TREND_CHANGED` (темпоральное), `CANDLE_CLOSED` (тайминг),
  lifecycle-предикаты сделки.
- **`MARKET_STRUCTURE_IS` — проверен точечно, остаётся именованным**
  (Н3-структура, гейт `CODE`): enum-равенство `MarketStructure.Type` ≠
  числовой `INDICATOR_COMPARE` (разные валидационные контракты);
  генерик-`ENUM_COMPARE` в грамматике нет — заводить его ради свёртки
  больший сдвиг, чем именованный тип. Не сворачивается.

## Отложенное точечное применение (не пакетная свёртка)

Критерий применяется **точечно при фиксации контракта каждого**
`ruleType`, а не пакетным аудитом перечня. Кандидаты на проверку (не
трогать, пока их контракт не фиксируется):

- **`VOLUME_FILTER_PASSED`** — sugar-vs-алиас-гранулярность контракта
  **по-прежнему отложена** (может оказаться алиасом «объём `GT` порог»
  или составным «объём vs средняя + подтверждение»). **Роль** объёмного
  условия уже зафиксирована
  (`docs/decisions/volume-condition-semantics.md`): подтверждающий
  фильтр, не единственное основание `ENTRY`. Для **OBV** абсолютный
  `CONSTANT`-compare исключён (только относительные формы) — поэтому
  алиас «OBV `GT` CONSTANT» отпадает; кандидат-алиас касается сырого
  объёма, не OBV.
- **`MARKET_PHASE_IS`** — enum-равенство; формально сводимо к генерик
  `EQ` над enum-операндом, но это бо́льший сдвиг (числовое сравнение vs
  enum-равенство — разные валидационные контракты). Самостоятельная
  развилка. (`MARKET_STRUCTURE_IS` — проверен, оставлен именованным, см.
  §Применение выше.)

Свёртка enum-IS-типов и `VOLUME_FILTER_PASSED` пакетом **не делается**.

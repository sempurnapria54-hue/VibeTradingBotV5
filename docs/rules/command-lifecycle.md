# Жизненный цикл сервисной команды

## На какой вопрос отвечает этот файл

Каков жизненный цикл `ServiceCommand`.

## Правило

**Команда — runtime-объект, не хранимая сущность и не durable-очередь.**
Ожидающие команды в базе не хранятся: после рестарта FSM заново определяет
нужную атомарную команду по актуальным фактам.

**Критерий атомарности — одна ответственность за состояние.** Команда
атомарна, когда выполняются все три клаузы:

1. **один владелец исхода** — ровно одна сущность, чьё состояние команда
   обязана привести к факту; остальное — чтение входа либо журнал;
2. **повтор с нуля безопасен** — повторное исполнение приводит владельца к
   тому же состоянию;
3. **нет внутреннего гейта на подтверждение собственной записи** — внутри
   команды нет ожидания, пока биржа подтвердит результат её же записи.
   Чтение чужих и прежних фактов клаузу не нарушает.

**`CREATE → SUBMIT → REFRESH` — жизненный цикл, а не пакет.** Создание
заводит локальную сущность (на биржу не ходит); отправка отправляет или
восстанавливает факт отправки по стабильному клиентскому идентификатору;
рефреш подтверждает фактическое состояние. FSM двигает статус сделки
только после подтверждения фактов.

**Одна актуальная команда за проход.** Цепочку заранее никто не создаёт.

**Составное — системное действие, а не команда.** Последовательность
команд (добыча фактов, финализация, аварийное завершение) — системное
действие со строкой исполнения, которое ведётся по подтверждённым фактам.
Прочие составные процессы раскладываются на атомарные команды и переходы
FSM.

## Атомарность не означает «один запрос»

**Команда рефреша ходит к источнику столько раз, сколько нужно, и
останавливается, когда добыла искомый факт.** Три следствия, общие для
всего класса:

1. **предикат остановки — «факт добыт», а не «эндпоинт опрошен».** Обход
   обрывается на первом запросе, вернувшем искомое; полный обход — только
   когда факта нет нигде. Лестница эндпоинтов — деталь конкретной команды
   и живёт в её доке;
2. **факт не добыт ⇒ команда не завершена.** Отсутствие искомого — не
   успешное завершение с пустым результатом;
3. **исчерпанный цикл — самостоятельный исход, и он расходует бюджет
   попыток.** Иначе «повторяется по бюджету» не могло бы закончиться, и
   сделка вечно удерживала бы слот инструмента молча. Исключение — классы,
   где отрицательный ответ **сам является терминалом** команды: там
   повторов нет и считать нечего.

**Записанное отрицательное значение терминалом команды не делает.**
Исключение выше — про классы, где отрицательный ответ **и есть искомый
факт** (сущности на бирже нет — это и есть ответ). Если же записанное
значение остаётся **операндом-блокером** ниже по тропе (потребитель без
него не считает и не переходит), то искомый факт не добыт: цикл не
исчерпан, звено не завершено, и повторы идут по бюджету на общих
основаниях. Иначе «отрицательный ответ» стал бы способом выйти из
бюджета, ничего не добыв, — и возвращал бы ровно тот режим, который
запрещает клауза 3.

**Аварийная тропа исключением не является:** отказ канала добычи
расходует бюджет так же, и `FAILED` строки служит durable-носителем исхода
«недоступно», разрешающим эмиссию терминала. Отличается там только то, что
радиусная реакция по отказу канала не поднимается.

**«Команда внутри команды» не допускается** — следствие третьей клаузы: у
вложенной команды нет ни своего прохода FSM, ни канала возврата данных.
Если факту нужно доехать до потребителя, он едет **durable-носителем**, а
добыча оформляется ногой цикла своей команды.

**«Звено сделано» выводится из добытого факта**, а не из значения-дельты и
не из памяти прохода: если факт не изменился, звено повторится безвредно.
Отдельной метки «команда отработала» не требуется.

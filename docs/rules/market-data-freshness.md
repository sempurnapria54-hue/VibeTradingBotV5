# Свежесть рыночных данных

## На какой вопрос отвечает этот файл

Как определяется свежесть рыночных данных и что она ограничивает.

## Правило

**Срок свежести задаёт стратегия** — параметром настройки, породившей
результат. У фазы своего срока нет: она не персистируется, и её свежесть
наследуется от входов.

**Устаревание вычисляется в runtime; состояние свежести в базе не
хранится.**

```text
expiredAt = точка отсчёта + срок свежести настройки-владельца
свежо ⟺ сейчас < expiredAt
```

**Точка отсчёта** — момент данных: у структуры рынка конец окна, у
индикатора время свечи. Момент подтверждения (гейт «использовать без
look-ahead») точкой отсчёта не является.

**Результат ключуется настройкой-владельцем:** у строки ровно один
владелец, и его срок задаёт устаревание.

## Что ограничивает

- **Data-dependent действие по устаревшим данным не выполняется.** Реакция
  задаётся параметром шага стратегии: ждать, заблокировать шаг, выйти
  штатно, аварийно свернуться. Блокировка шага не блокирует рефреш,
  отмену, закрытие и safety.
- **Проблема свежести, обнаруженная при сборе контекста расчёта**, даёт
  контролируемую ошибку расчёта, а не счёт по старым данным.
- **Джобы рыночных данных статус стратегии не меняют.** Активность
  стратегии — административное разрешение, а не гарантия готовности
  данных: нет свежих входов ⇒ джоба нового результата не создаёт, а старый
  постепенно устаревает.

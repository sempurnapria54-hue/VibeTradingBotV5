# Аудит не источник runtime-логики

## На какой вопрос отвечает этот файл

Какое правило запрещает управляющей логике читать историю, чтобы решить,
что делать дальше.

## Правило

**Аудит и история объясняют прошлое. FSM их не читает.**

Для runtime-решения используются только `DealContext`, строки исполнения
(`DealActionState`), сущности графа сделки и подтверждённые факты биржи.

Аудит **не** управляет FSM, не решает, какие команды создать, не заменяет
строку исполнения, не служит единственным источником восстановления после
рестарта, не хранит операционный лок и не работает очередью команд.

## Что аудит фиксирует

- Исполнение команды рефреша баланса попадает в историю: баланс влияет на
  риск-решения.
- `shutdownReason` виден в таймлайне и `closeReason` не заменяет.
- Штатный и аварийный терминал сделки различимы в отчётах; истечение
  условия входа отображается как нормальное закрытие кандидата без живого
  риска, не как авария.
- Подробный контекст входа хранится в истории, а не на сделке.
- Частичный выход объясним через заявки, факты исполнения и строки
  исполнения.

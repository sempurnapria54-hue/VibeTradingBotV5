# У каждого значения назван писатель

## На какой вопрос отвечает этот файл

Какое правило требует называть писателя для каждого значения и перехода.

## Правило

**Объявляя значение поля или переход состояния, док обязан назвать
актора, который его производит, и момент, в который тот это делает.**
Значение без писателя — не спецификация, а описание состояния, в которое
система не умеет попасть.

Требование применяется к:

- **каждому значению перечисления**, включая «пусто»: если пустота
  объявлена значением, у неё есть писатель — тот, кто наблюдает
  исчезновение операнда;
- **каждому переходу матрицы состояний**, включая те, которых никто не
  эмитит командой;
- **каждому признаку отбора**, объявленному на терминальном ребре.

**Пассивный залог писателя не называет.** «Строка закрывается», «поле
остаётся пустым», «признак проставляется» — описание исхода, а не
назначение актора. Нет подлежащего-компонента — требование не выполнено.

## Писатель обязан быть достижим

**Назвать компонент недостаточно: у назначенного актора обязан быть
достижимый момент вызова на каждом сценарии, ради которого он назван.**
Писатель, чей метод на этом сценарии никто не вызывает, оставляет
значение недостижимым ровно так же, как неназванный, — только
недостижимость спрятана на уровень глубже.

Проверка обратная — от **сценария** к **вызову**: назвать точку, в
которой актор получает управление, и убедиться, что сценарий до неё
доходит (попадает ли объект в выборку прохода, называет ли кто-нибудь
нужный тип, жив ли объект к этому моменту).

## Как проверять

1. выписать все объявленные значения поля, включая «пусто», и все
   переходы, которых касается правка;
2. по каждому назвать **компонент** и **момент** — транзакцию, проход,
   ребро;
3. по каждому моменту пройти обратную проверку достижимости;
4. пустая клетка — либо назначить писателя, либо записать явно, что
   состояние **недостижимо**, и чем именно.

Последний исход законен. Незаконно только молчание.

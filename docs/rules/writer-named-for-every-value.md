# У каждого объявленного значения и перехода назван писатель

## На какой вопрос отвечает этот файл

Какое правило требует называть писателя для каждого объявленного
значения поля и каждого перехода состояния.

## Правило

**Объявляя значение поля или переход состояния, док обязан назвать
актора, который его производит, и момент, в который тот это делает.**
Значение без писателя — не спецификация, а описание состояния, в которое
система не умеет попасть.

Требование применяется к:

- **каждому значению енума**, включая «пусто» — если пустота объявлена
  значением («операнда нет ⇒ поле пусто»), у неё есть писатель: тот, кто
  наблюдает исчезновение операнда;
- **каждому переходу матрицы состояний** — включая переходы, которые
  никто не эмитит командой (`SKIPPED`, отмена по неактуальности);
- **каждому признаку отбора**, объявленному на терминальном ребре.

**Формулировка в пассивном залоге писателя не называет.** «Строка
закрывается `SKIPPED`», «поле остаётся пустым», «признак проставляется»
— это описание исхода, а не назначение актора. Если в тексте нет
подлежащего-компонента, требование не выполнено.

## Почему правилом, а не оговоркой

Формулировка **существовала** — как граница чужого правила:
`docs/rules/absent-value-semantics.md` §«Чего правило не решает»
(«Правило говорит, какое значение пишется, а не кто и в какой момент его
пишет; **актор называется на каждой тропе отдельно**»). Записанная
исключением, она не работала как требование: пробел чинился поштучно и
воспроизводился на следующем артефакте.

Поштучные починки одного класса, каждая своим прогоном:

| Артефакт | Что оставалось без писателя |
|---|---|
| `riskBenchmarkAvailability = NOT_APPLICABLE` | колонка оставалась пустой на терминализованной сделке (`docs/components/MarkDealClosedExecutor.md`) |
| `breakdownIncomplete` на аварийном терминале | признак не имел здесь писателя вовсе (`docs/components/MarkDealEmergencyClosedExecutor.md`) |
| `Deal.plannedRiskCurrency` на тропах без входа | «без назначенного писателя колонка оставалась…» (`docs/rules/deal-without-operations.md`) |
| `DealActionState → SKIPPED` | переход в матрице есть, множество писателей статуса его произвести не может (`docs/lifecycles/DealActionState.md`) |
| `protectionRelievedRiskAmount = пусто` | таблица триггеров перечисляла только события **появления** операнда (`docs/models/domain/aggregate/Deal.md`) |

Последние два найдены **одним** прогоном (`DOCS_CHECK_19`) — то есть
класс, а не совпадение.

## Писатель обязан быть достижим

**Назвать компонент недостаточно: у назначенного актора обязан быть
достижимый момент вызова на каждом сценарии, ради которого он назван.**
Писатель, чей метод на этом сценарии никто не вызывает, оставляет
значение недостижимым ровно так же, как неназванный, — только
недостижимость спрятана на уровень глубже и грепом по имени не ловится.

Проверка — обратная: от **сценария** к **вызову**. По каждому сценарию,
объявленному рядом со значением, назвать точку, в которой актор получает
управление, и убедиться, что до неё сценарий доходит: попадает ли объект
в выборку прохода, называет ли кто-нибудь нужный тип/аргумент, жив ли
объект к этому моменту.

*Кейс: писателем терминального значения назван компонент, вызываемый
**по названному типу действия**, а на обоих объявленных сценариях
нужный тип уже не называет ни один вызывающий — объект к этому моменту
выпал из выборки прохода. Значение с названным писателем оказалось
недостижимым.*

## Как проверять

Механически, при закрытии любой правки, вводящей значение или переход:

1. выписать все объявленные значения поля (включая «пусто») и все
   переходы, которых касается правка;
2. по каждому назвать **компонент** и **момент** (транзакция, проход,
   ребро);
3. по каждому названному моменту пройти обратную проверку
   достижимости (§выше): что именно приводит актора к вызову на этом
   сценарии;
4. пустая клетка — либо назначить писателя, либо записать явно, что
   состояние **недостижимо**, и чем именно недостижимо.

Последний исход законен: «ветка недостижима по построению тропы» — тоже
ответ. Незаконно только молчание.

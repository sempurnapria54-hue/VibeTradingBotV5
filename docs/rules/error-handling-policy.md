# Error-политика: внешняя поверхность и внутренняя градация

## На какой вопрос отвечает этот файл

Какое у нас правило обработки ошибок: как ошибки выходят наружу (HTTP) и
как градируются внутри торгового контура.

## Внешняя поверхность приложения

- **Единый глобальный обработчик** (`@ControllerAdvice`) + **единый
  error-DTO**. Все ошибки контроллеров маппятся в HTTP в одном месте; не
  per-endpoint. FSM/оркестрация наружу не торчат, потому внешний контракт
  **тонкий**.
- Альтернатива (обработка пер-эндпоинт) отвергнута — единая поверхность,
  без дублирования; ретро-майоры шагов 2/4 (500 вместо 422/409,
  невыровненные коды реджектов — `.claude/work/backlog.md` §Ретро-ревью
  шагов 1-3 / §Хвост шага 4) лечатся в одном месте.

### Async-фасад ручного триггера джобы

Ручной триггер джобы (через `@Async`-фасад,
`.claude/rules/codestyle.md` §Джобы) отвечает только за **запуск**, не за
исход работы джобы:

```text
чистый запуск                              -> 202
проблема при запуске (вкл. отказ блокировки -> 409
  «уже бежит», JobExecutionGuard / БД-лок)
```

Что происходит в потоке джобы дальше, наружу **не транслируется** — уходит
во внутреннюю градацию ниже.

### Коды и документирование

- Конкретный **набор HTTP-кодов** и политика 409-vs-идемпотентности —
  **провизорно, хвост пользователя** (policy-выбор); фиксируются по мере
  закрытия ретро-майоров. Здесь зафиксирована форма (единый advice +
  единый DTO), не перечень кодов.
- Глубина документирования ошибок на контроллере (`@ApiResponses`) — **по
  конвенции** (`.claude/rules/codestyle.md` §Контроллеры/API), не отдельным
  правилом на каждый эндпоинт.

## Внутренняя градация ошибок (4 уровня)

Внутри торгового контура ошибка градируется по серьёзности; реакция растёт
от лога до полного биржевого блока:

1. **Ожидаемые, ретрай не нужен** → лог.
2. **Требуют ретрая** → ретрай (общий механизм повторов,
   `docs/components/RetryPolicyService.md`) + лог.
3. **Финансовые по инструменту** (серия неудач подряд, нарушение
   риск-политики) → **холд инструмента** + kill-switch + `AnomalyReport`;
   холд снимается **вручную** после разбора человеком
   (`docs/rules/instrument-hold.md`). **Реакция на серию неудач
   (исчерпание бюджета попыток) — единая полная**, с kill-switch (H6
   `DOCS_CHECK_14` в части единства формы + H8 `DOCS_CHECK_16`, решение
   держателя `GAPS_CLOSE_16` в части самой формы: мягкой у этого типа не
   осталось; разводка по стороне ноги снята — резолв идёт по типу
   исключения, `docs/rules/instrument-hold.md` §«Форма реакции на
   исчерпание бюджета попыток», там же довод отладки и условие
   пересмотра). Полная реакция уровня 3 — также за нарушением
   риск-политики.
4. **Неожиданное поведение биржи** (концептуальное правило держателя,
   2026-08-26): не нашли сущность там, где ожидали; нарушен контракт
   интеграции (не пришли ожидаемые поля и т. п.) или инварианты её
   контракта (>1 позиции на инструмент, не-isolated маржа и т. п.) →
   **сворачиваемся и ручной разбор**: `Exchange.TRADE_BLOCKED` +
   kill-switch flatten всей биржи + каскад активных сделок в `ERROR` +
   `AnomalyReport` + снятие вручную. Площадке, повёдшей себя неожиданно,
   больше ничего не шлём: после teardown блокируются все команды
   permission `Trade`, открыт только read (ревизия держателя,
   `GAPS_CLOSE_18`). Scope — по радиусу ущерба (см. ниже): штатно вся
   биржа (`docs/rules/exchange-hold.md`, ступень 2); тропа несвежести
   ставки комиссии — **мягкая реакция**
   (`docs/rules/instrument-hold.md` §«Несвежесть ставки комиссии»).
   **Второй триггер той же ступени — живой риск без защиты** (нарушение
   инварианта системы, `docs/rules/risk-creating-entry-protection.md`).
   Ступень 1 (`Exchange.HOLD`) — **ручной** гейт новых сделок,
   автоматических триггеров не имеет. Лестница двух ступеней (границы,
   эскалация, снятие) — дом `docs/rules/exchange-hold.md`; решение —
   `docs/decisions/exchange-safety-ladder.md`.

**Общий исполнитель реакций уровней 3-4 — `HoldService`** (H8
`DOCS_CHECK_12`): детектор зовёт сервис, передавая **самодостаточный**
сигнал — радиус, силу реакции и идентичность объекта блокировки
(`docs/components/HoldService.md`, `docs/components/models/HoldSignal.md`).

**Перечень детекторов-писателей открыт** (H12 `GAPS_CLOSE_13`, решение
пользователя): прежняя формулировка «собственного пути к статусу scope ни
у одного детектора нет» **снята**. Писателей может быть сколько угодно —
детектор, у которого нет причин отклоняться от штатной последовательности,
зовёт сервис; детектор, ставящий статус сам (журнальная тропа синка
ставок), берёт на себя идемпотентность по статусу scope и эскалацию
`ENTRY_BLOCKED → TRADE_BLOCKED`.

**`PNL_RECONCILIATION_MISMATCH` размещён: уровень 4, ступень 1**
(решение держателя, `GAPS_CLOSE_19`). Расхождение сверки bills ↔ net —
единственный детектор недосчёта заголовочного числа — при
**калиброванном** допуске даёт `Exchange.HOLD` + ручной разбор; в
разведочном режиме допуска — только журнальный отчёт, лестница не
триггерится (дом реакции — `docs/rules/pnl-reconciliation.md` §«Реакция
на расхождение»).

- **Ступень 1, а не 2** — по оси «на что пало подозрение»: расхождение
  сверки указывает на **наш счёт**, а не на поведение площадки. Ступень 2
  сносит живой риск и вместе с ним материал разбора.
- **Асимметрия, названная H21 `DOCS_CHECK_12`, снята.** Прежде
  несвежести ставки (портит прогноз комиссии одного будущего входа) был
  дан sticky-холд, а неверному `resultProfit` (портит измеренную
  ожидаемость **всей** системы) — самая слабая реакция реестра, вопреки
  собственному критерию «радиус ущерба ограничивает реакцию».
  Соотношение выправлено: у расхождения сверки радиус **биржевой**, у
  несвежести — инструментный.
- **`PNL-Q1` п.3 закрыт** этим же решением; от рантайм-факта N11 он не
  зависел и не зависит.

### Радиус ущерба задаёт scope

**Уровень задаёт реакцию, радиус ущерба — scope.** Это разные оси, и
уровень 4 не означает автоматически «холд биржи».

- **Уровень** отвечает на «насколько серьёзно» → отсюда набор реакции (лог /
  ретрай / **запрет новых входов + `AnomalyReport` + ручное снятие** /
  холд + kill-switch + `AnomalyReport` + ручное снятие). Полный перечень —
  §«Перечень scope и реакций».
- **Радиус ущерба** отвечает на «что именно обесценил сломавшийся факт» →
  отсюда scope холда. Сломался факт, без которого нельзя доверять **всей
  площадке** (внешний статус биржи, нарушенный инвариант её контракта) →
  холд биржи. Сломался факт, повреждающий **конкретные инструменты** →
  холд этих инструментов; остальная биржа исправна, и останавливать её
  незачем.

**Кейс, на котором это выведено (H3/H4, `GAPS_CLOSE_4`).** Несвежесть ставки
комиссии — по классу триггера уровень 4 (сломан контракт интеграции: чтение
`trade-fee` не доезжает). Но происходит она на **исправной** бирже и
обесценивает справочное число **одной комиссионной группы** ⇒ радиус —
инструменты этой группы. Прежняя редакция вывела scope из уровня и подключила
триггер к exchange-блок-сету — а тот спроектирован под «биржа сломана» и
блокирует `SUBMIT_ALGO_ORDER_COMMAND`, то есть не только вход, но и
`MAIN_PROTECTION`, ремодел трейлинга и reduce-only partial exit. Итог:
устаревшее **справочное** число деградировало **боевой** контур управления
позициями по всей бирже. Дом тропы —
`docs/rules/instrument-hold.md` §«Несвежесть ставки комиссии».

**Радиус ущерба ограничивает и реакцию** (H2, `GAPS_CLOSE_5`). У реакции,
как и у scope, есть адресаты: kill-switch адресует **живые сделки**, запрет
входов — **будущие**. Элемент реакции, адресующий сущности вне радиуса
ущерба, не применяется — иначе реакция «снимает» риск, которого нет, и
платит за это реальную цену (рыночное закрытие: полспреда + усечение
правого хвоста R). Кейс: несвежесть ставки обесценивает только сайзинг
новых входов — в `R` живой сделки (задан стопом на бирже) и в её
`resultProfit` (считается из фактов) ставка не участвует ⇒ реакция —
запрет новых входов + `AnomalyReport`, **kill-switch по несвежести снят**;
живые сделки доживают под своим стопом (`docs/rules/instrument-hold.md`
§«Несвежесть ставки комиссии»).

### Нарушение контракта интеграции — радиус по неизвестности поражения

**При нарушении контракта интеграции радиус реакции определяется не
радиусом наблюдаемого ущерба, а неизвестностью радиуса поражения; такой
случай требует ручного разбора человеком.**

Правило «радиус ущерба ограничивает реакцию» работает, когда радиус
поражения **известен**: сломавшийся факт назван, и видно, что именно он
обесценил. Когда источник **отвечает не так, как обещает контракт**
(обязательное поле пусто, ответ структурно иной), наблюдаемый ущерб —
лишь то место, где нарушение впервые замечено; сколько ещё ответов того же
источника нарушают контракт незамеченно, из самого нарушения не выводится.
Реакция такого случая соразмеряется с этой неизвестностью (штатно — холд
биржи, `docs/rules/exchange-hold.md`), а снятие — только вручную, после
разбора человеком: восстановление доверия к интеграции не наблюдаемо
автоматикой по построению.

Различение с тропой несвежести (мягкая реакция выше): несвежесть — отказ
**канала добычи** с известным радиусом обесцененного факта (справочное
число группы/аккаунта); здесь радиус ущерба работает и реакцию
ограничивает. Нарушение контракта — дефект **содержимого ответа**; радиус
поражения неизвестен, и ограничивать реакцию наблюдаемым ущербом нечем.
Кейс, на котором записан инвариант: пустой/неизвестный `closeType` в
добытой записи positions-history — наблюдаемый ущерб равен одному
отчётному признаку одной закрытой сделки, но реакция определяется не им
(`docs/rules/exchange-hold.md` §«Что переводит в HOLD»).

**Правило действует на обеих тропах сделки одинаково** (H4
`DOCS_CHECK_15`, решение пользователя). Прежде аварийная тропа
(`Deal.status = ERROR`) приравнивала **любой** жёсткий отказ чтения к
«недоступно» — то есть проглатывала и нарушение контракта, там же, где
оно наблюдается впервые. Послабление **снято**: контролируемое исключение
бросается и на аварийной тропе, реакция — та же биржевая ступень 2
(`Exchange.TRADE_BLOCKED`).
Сама сделка при этом **закрывается терминальным ошибочным статусом**;
ветки не конкурируют — терминал разрешён durable-исходом добычи
(`docs/decisions/pnl-finalization-mechanics.md` §«Асимметрия троп отказа
добычи»). Разграничитель выше («дефект содержимого ответа» против «отказ
канала добычи») остаётся в силе и на аварийной тропе: отказ канала там
по-прежнему даёт «недоступно» без радиусной реакции — радиус его ущерба
известен и равен отчётности одной закрытой сделки.

**Обязанность, наступившая и не исполненная, этому классу не
принадлежит** (H2 `DOCS_CHECK_15`). Когда недостаёт **нашего** операнда
(уровень стопа по предикату селекции защиты; дизъюнкт «`ctVal` навеса»
снят H5 `DOCS_CHECK_16` — значение персистится write-once на ноге), радиус
ущерба **известен** и локализован
сделкой: реакция — ошибочный терминал сделки + журнальный `AnomalyReport`,
**без** биржевого холда. Класс формулируется через обязанность («должны
были и не сделали»), а не через природу причины, — иначе интеграционный
радиус натягивался бы на не-интеграционный отказ
(`docs/components/FinalizeDealExitExecutor.md` §epsilon).

### Обязанность добычи решает, аларм это или норма

**Правило (сквозное, решение держателя `GAPS_CLOSE_16`).** Ненайденное само
по себе ни аларм, ни норма — решает **обязанность добычи**:

- **обязанность наступила и не исполнена** ⇒ **аларм**: журнальный отчёт
  плюс реакция по внутренней градации (§выше);
- **обязанность не наступала** ⇒ **норма**: факт выражается **значением**
  признака, а не сигналом (`docs/rules/absent-value-semantics.md`).

**Обязанность — durable-предикат из существующих полей**, названный там,
где вводится добыча. Необъявленная обязанность делает молчание
неотличимым от нормы: потребитель не может сказать, «не нашли, потому что
нечего» или «не нашли, потому что не сработало».

**Правило сквозное — одинаково для любого объекта добычи:** операнда
признака, записи источника, строки движения, сущности, разыскиваемой
поиском. Прежде оно жило **тремя частными применениями** и ни одного
общего: ячейкой таблицы в `absent-value-semantics.md` («сигнал нужен, если
операнд обязан был прийти»), клаузой одного класса ниже («обязанность,
наступившая и не исполненная, этому классу не принадлежит») и принципом
одной тропы у финализаторов («должны были посчитать и не посчитали —
ошибка»).

**Разграничение с `absent-value-semantics.md`.** То правило отвечает, **как
выражать** отсутствие (пустота против явного значения); это — **как на него
реагировать**. Признак может нести явное значение «не определено» и при
этом не быть алармом, если обязанность не наступала.

### Перечень scope и реакций

Полный перечень реакций (по возрастанию тяжести):

| Реакция | Состав |
|---|---|
| лог | запись в лог (уровень 1) |
| ретрай | повтор + лог (уровень 2, `docs/components/RetryPolicyService.md`) |
| **запрет новых входов** (мягкая) | блок создания нового риска по scope (risk-creating / risk-increasing; граница — `docs/rules/risk-validator-scope.md`) + `AnomalyReport` **по тропе** (см. таблицу scope × reaction ниже: серия неудачных исполнений его не производит) + **снятие вручную**; живые сделки сопровождаются штатно (защита, трейлинг, reduce-only выход, закрытие) |
| **мягкий холд биржи** (`Exchange.HOLD`) | биржа выпадает из entry-скана ⇒ **новые сделки не создаются**; командного блок-сета нет, живые сделки сопровождаются полностью; kill-switch не гоняется; снимается **вручную** (`docs/rules/exchange-hold.md`, ступень 1). Автоматический триггер один — расхождение сверки P&L за калиброванным допуском |
| **холд с kill-switch** | блок по scope + kill-switch (снятие live risk) + `AnomalyReport` + снятие вручную; exchange-scope форма — `Exchange.TRADE_BLOCKED` (`docs/rules/exchange-hold.md`, ступень 2): после teardown блокируются **все** команды permission `Trade`, открыт только read |

**Снятие — вручную у всех блокирующих реакций** (H2, `GAPS_CLOSE_6`;
мягкий холд биржи — той же конвенцией, `docs/rules/exchange-hold.md`).
Автоматического снятия по восстановлению признака нет ни у одной: у
kill-switch-класса — потому что принудительно снятый live risk возобновляет
человек; у мягкой — потому что её триггер есть сбой пайплайна добычи
фактов, который человек и так идёт разбирать (human-in-the-loop; довод и
форвард на авто-снятие — `docs/rules/instrument-hold.md` §Снятие).

Полный перечень scope (радиусов ущерба): **инструмент** / **группа
инструментов** (комиссионная группа: обесценен факт, общий для группы) /
**биржа/аккаунт**.

**Перечень радиусов ущерба и енум `HoldScope` — не одно и то же, и это
намеренно** (H14 `DOCS_CHECK_15`). Здесь перечислены радиусы **ущерба**;
енум описывает **субъект одной строки** — статуса блокировки или отчёта, —
и группового значения в нём нет (`docs/components/models/HoldSignal.md`
§«Енум `HoldScope`»). Групповой и аккаунтный радиусы выражаются
**набором строк**: набором статусов `ENTRY_BLOCKED` по инструментам
радиуса и — с `GAPS_CLOSE_15` — набором отчётов, по одному на затронутый
инструмент (`docs/models/domain/other/AnomalyReport.md` §Инварианты
структуры). Это то же ратифицированное «радиус — набором строк, не
отдельным статусом» (`docs/rules/instrument-hold.md`), распространённое с
блокировки на журнал.

Сводная таблица scope × reaction (чем занята каждая клетка):

| Scope \ Реакция | запрет новых входов (мягкая) | мягкий холд биржи (`HOLD`) | холд с kill-switch | `AnomalyReport` на тропе |
|---|---|---|---|---|
| инструмент | — **клетка пуста** с H8 `DOCS_CHECK_16` (решение держателя): исчерпание бюджета попыток мягкой формы больше не имеет | — (форма exchange-scope) | исчерпание бюджета попыток — **единая полная форма на всех тропах** (`docs/rules/instrument-hold.md` §«Форма реакции на исчерпание бюджета попыток»); плюс риск-условия уровня 3 **при живой защите** (живой риск **без** защиты — не сюда, а ступень 2 exchange-scope) | исчерпание — реактивный отчёт производит последовательность холда; риск-условия — да |
| группа инструментов | несвежесть ставки/ключа группы, режим «группа отсутствует в ответе» | — | — | **да** — производит синк, **по одному отчёту на каждый инструмент группы** (H14 `DOCS_CHECK_15`) |
| биржа/аккаунт | несвежесть ставки/ключа группы, режим «вызов не прошёл» | уровень 4, ступень 1 (`Exchange.HOLD`, `docs/rules/exchange-hold.md`): **расхождение сверки P&L за калиброванным допуском** — единственный автоматический триггер (`GAPS_CLOSE_19`); плюс ручная постановка и спуск со ступени 2 | уровень 4, ступень 2 (flatten, `docs/rules/exchange-hold.md`): **неожиданное поведение биржи** (controlled exceptions, safety-каскад, нарушение контракта интеграции) **либо** живой риск без защиты | **да** — по несвежести: **на каждый затронутый инструмент** (H14 `DOCS_CHECK_15`); по ступени 1: журнальный `EVENT` от детектора + `STATE` от холда; по ступени 2: один, радиуса `EXCHANGE` |

**Отчёт принадлежит тропе, а не классу реакции** (H14 `GAPS_CLOSE_13`).
Колонка выше — часть перечня, а не примечание к нему: мягкая реакция
несвежести отчёт производит (его заводит **детектор** — синк), мягкая
реакция серии неудачных исполнений — **нет** (серия аномалией не
является). Формулировка «мягкая = блок + `AnomalyReport` + снятие вручную»
как свойство **класса** снята: она давала писателю отчёт на каждое
исчерпание бюджета, причём через точку входа, жёстко ставящую `CRITICAL`,
то есть превращала мягкую реакцию в полную.

**Мягкие клетки группового и аккаунтного радиуса выразимы** набором
вызовов `instrumentSoft(code, instrumentId)` по инструментам радиуса
(`docs/components/models/HoldSignal.md` §Фабрики): радиус — набор строк,
а не отдельное значение `HoldScope`.

Enforcement блокирующих реакций — **разными статусами инструмента**
(`ENTRY_BLOCKED` — мягкая, `TRADE_BLOCKED` — с kill-switch), потому что
`TRADE_BLOCKED` в оркестраторе уводит активные сделки в `ERROR`
(`docs/rules/instrument-hold.md` §Enforcement, H3 `GAPS_CLOSE_6`).

Реакции лог/ретрай scope-оси не имеют (ничего не блокируют). «Синк
выключен» (`enabled = false`) — **не источник холда**: штатная
эксплуатационная операция, а не отказ интеграции
(`docs/rules/instrument-hold.md` §«Несвежесть ставки комиссии», радиус по
режиму отказа).

### Реконсиляция с существующим (не плодить параллель)

- **Уровни 1-2** ложатся на `docs/rules/runtime-error-classification.md`
  (классы `EXCHANGE_ERROR` retryable / `INTERNAL_ERROR` /
  `VALIDATION_ERROR`) + retry-policy (`docs/components/RetryPolicyService.md`).
- **Уровень 4** — на существующую тропу `EXCHANGE_INVARIANT_VIOLATION →
  safety` (`docs/rules/controlled-exchange-exceptions.md`) +
  `docs/rules/exchange-hold.md` (при радиусе «биржа»).
- **Уровень 3** вводит **новый холд инструмент-scope**
  (`docs/rules/instrument-hold.md`): `exchange-hold` есть, инструмент-холда
  не было. Его триггеры — **риск-условия** (серия неудач, нарушение
  риск-политики), а не код-исключения, поэтому часть уровня 3 по природе
  ближе к risk/safety-слою, чем к таксономии runtime-исключений.
- **`instrument-hold` — не только уровень 3.** Тропа несвежести ставки
  комиссии приезжает туда с уровня 4 по радиусу ущерба (§выше). Файл
  ключуется **scope'ом**, а не уровнем.

### Порог «несколько неудач подряд» — провизорный

Сколько именно неудач подряд по инструменту запускает уровень 3 — **не
выдумывается** (паттерн STRUCT-Q1): провизорное число, калибруется
бэктестом / пользователем.

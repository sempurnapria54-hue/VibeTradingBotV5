# Error-политика: внешняя поверхность и внутренняя градация

## На какой вопрос отвечает этот файл

Какое у нас правило обработки ошибок: как ошибки выходят наружу (HTTP) и
как градируются внутри торгового контура.

## Внешняя поверхность приложения

- **Единый глобальный обработчик** (`@ControllerAdvice`) + **единый
  error-DTO**. Все ошибки контроллеров маппятся в HTTP в одном месте; не
  per-endpoint. FSM/оркестрация наружу не торчат, потому внешний контракт
  **тонкий**.
- Альтернатива (обработка пер-эндпоинт) отвергнута — единая поверхность,
  без дублирования; ретро-майоры шагов 2/4 (500 вместо 422/409,
  невыровненные коды реджектов — `.claude/work/backlog.md` §Ретро-ревью
  шагов 1-3 / §Хвост шага 4) лечатся в одном месте.

### Async-фасад ручного триггера джобы

Ручной триггер джобы (через `@Async`-фасад,
`.claude/rules/codestyle.md` §Джобы) отвечает только за **запуск**, не за
исход работы джобы:

```text
чистый запуск                              -> 202
проблема при запуске (вкл. отказ блокировки -> 409
  «уже бежит», JobExecutionGuard / БД-лок)
```

Что происходит в потоке джобы дальше, наружу **не транслируется** — уходит
во внутреннюю градацию ниже.

### Коды и документирование

- Конкретный **набор HTTP-кодов** и политика 409-vs-идемпотентности —
  **провизорно, хвост пользователя** (policy-выбор); фиксируются по мере
  закрытия ретро-майоров. Здесь зафиксирована форма (единый advice +
  единый DTO), не перечень кодов.
- Глубина документирования ошибок на контроллере (`@ApiResponses`) — **по
  конвенции** (`.claude/rules/codestyle.md` §Контроллеры/API), не отдельным
  правилом на каждый эндпоинт.

## Внутренняя градация ошибок (4 уровня)

Внутри торгового контура ошибка градируется по серьёзности; реакция растёт
от лога до холда биржи:

1. **Ожидаемые, ретрай не нужен** → лог.
2. **Требуют ретрая** → ретрай (общий механизм повторов,
   `docs/components/RetryPolicyService.md`) + лог.
3. **Финансовые по инструменту** (серия неудач подряд, нарушение
   риск-политики) → **холд инструмента** + kill-switch + `AnomalyReport`;
   холд снимается **вручную** после разбора человеком
   (`docs/rules/instrument-hold.md`).
4. **Нарушение контракта интеграции** (не пришли ожидаемые поля и т. п.)
   **или** инвариантов системы (>1 позиции на инструмент, не-isolated
   маржа и т. п.) → **холд биржи** + kill-switch + `AnomalyReport`; снятие
   вручную (`docs/rules/exchange-hold.md`).

### Реконсиляция с существующим (не плодить параллель)

- **Уровни 1-2** ложатся на `docs/rules/runtime-error-classification.md`
  (классы `EXCHANGE_ERROR` retryable / `INTERNAL_ERROR` /
  `VALIDATION_ERROR`) + retry-policy (`docs/components/RetryPolicyService.md`).
- **Уровень 4** — на существующую тропу `EXCHANGE_INVARIANT_VIOLATION →
  safety` (`docs/rules/controlled-exchange-exceptions.md`) +
  `docs/rules/exchange-hold.md`.
- **Уровень 3** вводит **новый холд инструмент-scope**
  (`docs/rules/instrument-hold.md`): `exchange-hold` есть, инструмент-холда
  не было. Его триггеры — **риск-условия** (серия неудач, нарушение
  риск-политики), а не код-исключения, поэтому часть уровня 3 по природе
  ближе к risk/safety-слою, чем к таксономии runtime-исключений.

### Порог «несколько неудач подряд» — провизорный

Сколько именно неудач подряд по инструменту запускает уровень 3 — **не
выдумывается** (паттерн STRUCT-Q1): провизорное число, калибруется
бэктестом / пользователем.

## Первоисточник и смежное

Правило сквозное по контроллерам/командам/safety (единого
владельца-сущности нет, `.claude/decisions/rule-source-of-truth.md`).
Снимает TBD error-конвенции `.claude/rules/codestyle.md` §«Обработка
ошибок». Смежное:

- `docs/rules/runtime-error-classification.md` (`RuntimeErrorCode`,
  retryable);
- `docs/components/RetryPolicyService.md` (механизм повторов);
- `docs/rules/controlled-exchange-exceptions.md` (контракт/инвариант →
  safety);
- `docs/rules/exchange-hold.md` (уровень 4), `docs/rules/instrument-hold.md`
  (уровень 3);
- `docs/models/domain/other/AnomalyReport.md` (журнал инцидента).

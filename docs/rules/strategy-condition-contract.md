# Контракт авторинга условия стратегии

## На какой вопрос отвечает этот файл

Как автор стратегии записывает условие.

## Источник истины — объектная модель настроек

Домен работает только с объектной моделью: правило ссылается на настройку
по ключу, операнды — структуры. Строка-метка с инлайновыми параметрами —
**форма ввода** API, а не второй источник истины: при сохранении API
резолвит метки в ссылки на настройки.

Доки задают **контракт авторинга** — какие поля заполнить для валидного
правила.

**Истинность правила — не деталь вычислителя.** Формулы, **предикаты** и
закрытые перечни живут в машинно-проверяемой форме одним экземпляром
(`docs/concept.md`), поэтому предикат каждого типа правила имеет **дом** —
исполнимую форму; деталью вычислителя остаётся только то, как он до
операндов добирается, а не что предикат означает.

**Заведённые дома:** `docs/spec/market-phase-condition.json`
(`MARKET_PHASE_IS`, `TREND_CHANGED`) и `docs/spec/deal-condition.json`
(девять величин: `positionOpened`, `noOpenPosition`,
`entryOrderFinalized`, `attachedStopLossExists`, `mainProtectionExists`,
`moveOperandsAvailable`, `signedMovePercents`, `profitPercentsReached`,
`lossPercentsReached`).

**Без дома остались семь типов:** `NO_ACTIVE_DEAL`,
`RANGE_BREAKOUT_CONFIRMED`, `MARKET_STRUCTURE_IS`, `INDICATOR_COMPARE`,
`PRICE_COMPARE`, `CROSSOVER`, `VOLUME_FILTER_PASSED`.
Каждый получает дом на шаге, который его достигает; перечень здесь —
чтобы «дома ещё нет» отличалось от «дом не нужен».

## Настройка индикатора

Индикаторы объявляются в стратегии набором настроек формы
`{ key, indicatorType, params }`:

- **`key`** — стабильный ключ настройки; по нему ссылается индикаторный
  операнд условия;
- **`indicatorType`** — тип индикатора;
- **`params`** — параметры: таймфрейм, математические параметры по типу,
  опционально прогрев.

**Инлайновые параметры на правиле источником истины не являются:** они
дублировали бы конфигурацию индикатора в каждом правиле и ломались бы на
сравнении индикатора с индикатором — непонятно, чей период.

**Тип строкой вида `EMA(15, 200)` не используется:** позиционная запись
требует парсера, не валидируется и не индексируется по полю.

## Прогрев выводится, override возможен

Прогрев по умолчанию выводится реализацией индикатора из типа и периода:
оконные — период, рекурсивные — кратно периоду, составные — от старшего
периода. Автор может задать явный override; эффективное значение —
`override ?? выведенное`.

Потребитель — загрузка свечей: объявленный прогрев задаёт глубину
истории. Пропуск зоны прогрева при расчёте — ответственность джобы
индикаторов.

## Правило и операнды

Структура правила единая: тип, оператор, левый и правый операнды, процент.
Тип источника живёт на операнде и на правиле не дублируется.

**Какие поля правило несёт, задаёт его тип — и задаёт точно.** Строка
таблицы называет **все** поля правила своего типа, и каждое из них
обязательно; правило без названного поля и правило с полем, которого строка
не называет, отвергают создание стратегии — в обоих контекстах, у условия
шага и у клаузы классификации фазы (`docs/rules/strategy-validation.md`).
Поле порядка `level` общее у всех типов и в строках не называется: ответ
конъюнкции от порядка правил не зависит (дом связки — компонент-док
`docs/components/StrategyConditionEvaluator.md`).

**Скалярный операнд** — индикаторный, ценовой либо константа числового типа
(`NUMBER`, `PERCENT`): только их оценка сравнивает числом.

| Тип правила | Поля правила — ровно эти |
|---|---|
| `PROFIT_PERCENTS_REACHED`, `LOSS_PERCENTS_REACHED` | процент |
| `RANGE_BREAKOUT_CONFIRMED` | оператор `EQ` либо `NE`; два операнда на любых сторонах — структура рынка и константа со значением перечня направления пробоя, `UP` либо `DOWN` |
| `MARKET_STRUCTURE_IS` | оператор `EQ` либо `NE`; два операнда на любых сторонах — структура рынка и константа со значением перечня типов структуры, при любом объявленном типе значения; пустое значение перечню не принадлежит |
| `MARKET_PHASE_IS` | оператор `EQ` либо `NE`; два операнда на любых сторонах — фаза рынка и константа со значением перечня фаз, при любом объявленном типе значения; пустое значение перечню не принадлежит |
| `INDICATOR_COMPARE` | оператор сравнения — `EQ`, `NE`, `GT`, `GTE`, `LT`, `LTE`; два скалярных операнда, хотя бы один — индикаторный |
| `PRICE_COMPARE` | оператор сравнения — те же шесть; два скалярных операнда, хотя бы один — ценовой |
| `CROSSOVER` | оператор `CROSSED_ABOVE` либо `CROSSED_BELOW`; два скалярных операнда; ценовой — только в паре с индикаторным (раздел о прошлом цены ниже) |
| `VOLUME_FILTER_PASSED` | левый операнд — индикаторный (там же); ни оператора, ни правого операнда |
| `NO_OPEN_POSITION`, `NO_ACTIVE_DEAL`, `ENTRY_ORDER_FINALIZED`, `POSITION_OPENED`, `ATTACHED_STOP_LOSS_EXISTS`, `MAIN_PROTECTION_EXISTS`, `TREND_CHANGED` | ни одного: предмет такого правила — состояние сделки либо фазы, а не величина, названная автором |

**Довод у названных полей: без них оценка не может ответить ничем, кроме
константы.** Сравнение без операнда, пересечение без оператора пересечения,
пробой без направления оценка читает ложью всегда, и правило не срабатывает
никогда, молча. У трёх типов над перечнем — пробоя, структуры и фазы —
оценка читает значение константы строкой, не глядя на её объявленный тип, а
прочие операторы, кроме равенства и его отрицания, — ложью: значение вне
перечня и иной оператор делают ответ независимым от рынка. Нескалярный
операнд в сравнении и пересечении оценка числом не разрешает, и правило
ложно всегда. Смысл направления пробоя —
`docs/models/domain/other/MarketStructure.md`.

**Довод у неназванных — тот же, с другой стороны:** оценка их не читает, и
ответ от них не зависит. Объявленное автором, такое поле читается им как
часть условия — оператор и порог у объёмного фильтра, фаза у смены тренда,
операнд-порог у правила хода, — а исполняется правило без него, не сообщая
об этом (раздел о грамматике исполняемого ниже).

Когда именованный тип правила оправдан, а когда это алиас
генерик-сравнения — `docs/rules/condition-ruletype-granularity.md`.

## Условие непусто

**Условие шага и условие клаузы классификации фазы несут хотя бы одно
правило.** Оценка читает пустое условие истиной — нейтральным элементом
конъюнкции (дом семантики — `docs/components/StrategyConditionEvaluator.md`), —
и поэтому пустое условие не бывает авторской формой ни у шага, ни у
клаузы: у шага входа оно было бы входом без единого критерия, у клаузы —
фазой, назначаемой каждому инструменту на каждом проходе, за которой
следующие клаузы не читаются вовсе. Безусловного шага и безусловной фазы
грамматика не объявляет; пустое условие отвергает создание
(`docs/rules/strategy-validation.md`).

## Прошлое цены задаёт индикатор-пара

Пересечение сравнивает обе стороны в настоящем и в прошлом. У ценового
операнда своего прошлого нет: его прошлое — цена закрытия свечи, на
которой посчитано предыдущее значение **индикатора на другой стороне**
того же правила (дом второй половины времени —
`docs/components/StrategyConditionEvaluator.md`). Отсюда контракт:

- **пересечение с ценовым операндом** пишется только в паре с
  индикаторным операндом; цена против константы либо цены пересечением не
  выражается;
- **объёмный фильтр** читает прошлое своего левого операнда, и операнд
  этот — индикатор; ценовой операнд в фильтре прошлого не имеет.

Обе формы вне контракта отвергает создание
(`docs/rules/strategy-validation.md`): оценка читала бы их ложью всегда, и
правило не срабатывало бы никогда, молча.

## Грамматика объявляет только исполняемое

**Элемент грамматики объявлен, только когда оценка его читает: значение
перечня — вместе с ветвью, которая его исполняет, поле — вместе с чтением.
Объявленное сверх этого отвергает создание.** Молчаливая ложь исходом не
является: правило, которое не может выполниться, по поведению системы
неотличимо от правила, которое ещё не выполнено. Перечни грамматики — типы
правил, типы источника операнда, операторы, типы константы — несут поэтому
только исполняемые значения (перечни — `docs/models/domain/aggregate/Strategy.md`,
раздел условий), а значение возвращается в перечень той же правкой, что заводит
его исполнение. Почему грамматика сужена, а не достроена, —
`.claude/decisions/condition-grammar-executable-only.md`.

**Набор полей задан точно — у правила и у операнда.** У правила — таблицей
типов правила выше; у операнда — его типом источника:

| Тип источника | Поля операнда — ровно эти | Что оценка берёт |
|---|---|---|
| `INDICATOR` | ключ настройки индикатора; адресный компонент — у многокомпонентного типа (раздел об адресном компоненте ниже) | значение индикатора по ключу, последнее либо предыдущее |
| `MARKET_STRUCTURE` | ключ настройки структуры | структуру рынка по ключу |
| `MARKET_PHASE` | ни одного | фазу прохода |
| `PRICE` | ни одного | последнюю цену сделки инструмента в момент оценки |
| `CONSTANT` | тип значения и значение | литерал |

**Ценовой операнд условия — последняя цена сделки, и источника цены он не
несёт.** Индикаторы, с которыми цену сравнивают, посчитаны по закрытиям
свечей, а прошлое цены в пересечении — закрытие свечи индикатора-пары
(раздел о прошлом цены выше): обе половины сравнения берутся
одной ценой. Бид либо аск на стороне настоящего сравнивался бы с последней
ценой на стороне прошлого. Источник рыночной цены объявляет только
размещение (дом — блок размещения цены в
`docs/models/domain/aggregate/Strategy.md`).

**Поля, которых доменная форма не несёт вовсе, отвергаются тем же
отказом:** таймфрейм у правила и источник цены у операнда. Отказ не зависит
от того, как поверхность создания читает неизвестное поле, — иначе
объявленный автором бид исполнялся бы последней ценой молча.

## Тип без операнда не объявляется

**Тип правила входит в перечень только вместе с операндом, который оценка
умеет прочесть.** Типу, которому мерить нечего, оценка может ответить лишь
константой, а у защитного типа константная истина снимала бы ровно тот
барьер, которым тип объявлен, — направление такой ошибки разрешающее.

**Защиты от заглядывания вперёд — «свеча таймфрейма закрыта» — типом
правила нет.** Операнда закрытия свечи контекст оценки не несёт ни одним
полем, поэтому такого типа в перечне нет, и имя вне перечня создание
отвергает (`docs/rules/strategy-validation.md`). Тип вводится вместе с
операндом закрытия свечи объявленного таймфрейма; поля таймфрейма у
правила до тех пор нет (раздел о грамматике исполняемого выше).

## Адресный компонент индикаторного операнда

Индикаторный операнд **многокомпонентного** типа называет компонент —
какую часть значения индикатора сравнивать (`indicatorComponent`). Так
снимается масштаб-зависимость абсолютного сравнения: линия MACD в ценовых
единицах межинструментно нестабильна, и автор берёт осмысленную часть.

| Тип индикатора | Допустимые компоненты | Поле значения, которое компонент выбирает |
|---|---|---|
| `MACD` | `MACD_LINE`, `SIGNAL_LINE`, `HISTOGRAM` | `macdLine`, `signalLine`, `histogram` |
| `STOCHASTIC` | `STOCH_K`, `STOCH_D` | `k`, `d` |
| `BOLLINGER_BANDS` | `UPPER_BAND`, `MIDDLE_BAND`, `LOWER_BAND`, `BANDWIDTH`, `PERCENT_B` | `upperBand`, `middleBand`, `lowerBand`, `bandwidth`, `percentB` |

Прочие типы — `ATR`, `EMA`, `RSI`, `OBV`, `EFFICIENCY_RATIO` —
**однокомпонентны**: значение у них одно, и компонент не пишется.

Контракт авторинга отсюда трёхчастный: у многокомпонентного типа компонент
**обязателен**, у однокомпонентного **запрещён**, и названный компонент
обязан принадлежать строке своего типа. Нарушение любой части отвергает
создание стратегии (`docs/rules/strategy-validation.md`). Поля значения по
типу — доменный док `docs/models/domain/other/IndicatorValue.md`.

# OKX contracts: серверное время

## На какой вопрос отвечает этот файл

Каков контракт операции чтения серверного времени API (`public/time`).

## Внешний источник правды

Дистиллят официального дока OKX (`https://www.okx.com/docs-v5/en/`,
раздел «Public Data → REST API», секция «Get system time»). При
расхождении с офдоком побеждает офдок; синхронизация — перевыкачка +
дифф при каждом заходе интегратора по источнику и по задаче
«актуализируй» (`.claude/processes/api-docs-completion.md`, канал
чтения — `.claude/skills/integration-okx.md`). Последняя сверка:
2026-06-11 (поле-уровневая дистилляция).

## Статус использования

**Используется с шага 7** —
как **якорь биржевого временного домена** там, где у события нет
собственной метки источника:

- верхняя граница запроса `REFRESH_BILLS_COMMAND`
  (`[Deal.billsWindowBegin, t_source]`) и записываемое значение
  `Deal.billsFetchedThrough`
  (`docs/components/RefreshBillsExecutor.md`,
  `docs/models/domain/aggregate/Deal.md`). Обе величины сравниваются с биржевым `uTime`, а
  границы биржевых окон сравниваются только с биржевыми таймстампами
  (`docs/rules/time-utc.md`);
- **биржевой момент создания сделки** — `Deal.externalCreatedAt`, он же
  суррогат **нижней** границы того же окна при пустом
  `Deal.billsWindowBegin` (П7-B, вариант (г)). Читает
  `EntryScannerJob` перед вызовом `DealOpeningService`; отказ эндпоинта
  ⇒ сделка не создаётся (`docs/components/EntryScannerJob.md`).

**Замер дрейфа локальных часов — отдельная, диагностическая роль.**
Подпись private-запросов несёт `OK-ACCESS-TIMESTAMP`, и при дрейфе
локальных часов биржа отклоняет запросы; `public/time` — эталон для
сверки. Операндом биржевых окон корректированное системное время
**не становится** (там же).

## GET /api/v5/public/time

Rate limit 10 req / 2 s по IP. Параметров нет. Ответ `data[0]`:
`ts` — серверное время, Unix-миллисекунды строкой.

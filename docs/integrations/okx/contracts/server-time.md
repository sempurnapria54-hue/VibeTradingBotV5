# OKX contracts: серверное время

## На какой вопрос отвечает этот файл

Каков контракт операции чтения серверного времени API (`public/time`).

## Источник правды вне репозитория

Официальный док OKX (`https://www.okx.com/docs-v5/en/`, раздел «Public
Data → REST API», секция «Get system time»). Процедура сверки и
приоритет офдока — `.claude/rules/external-source-sync.md`. Последняя
сверка: 2026-06-11 (поле-уровневая дистилляция).

## Статус использования

**Используется с шага 7** —
как **якорь биржевого временного домена** там, где у события нет
собственной метки источника:

- верхняя граница запроса `REFRESH_BILLS_COMMAND`
  (`[Deal.billsWindowBegin, t_source]`) и записываемое значение
  `Deal.billsFetchedThrough`
  (`docs/components/RefreshBillsExecutor.md`,
  `docs/models/domain/aggregate/Deal.md`). Обе величины сравниваются с биржевым `uTime`, а
  границы биржевых окон сравниваются только с биржевыми таймстампами
  (`docs/rules/time-utc.md`);
- **биржевой момент создания сделки на штатной тропе** —
  `Deal.externalCreatedAt`, он же суррогат **нижней** границы того же
  окна при пустом `Deal.billsWindowBegin` (П7-B, вариант (г); на
  восстановительной тропе поле пишет детектор временем открытия
  наблюдённой позиции — `docs/models/domain/aggregate/Deal.md`). Читает
  `EntryScannerJob` перед вызовом `DealOpeningService`; отказ эндпоинта
  ⇒ сделка не создаётся (`docs/components/EntryScannerJob.md`).

**Выравнивание метки подписи — вторая роль, и она построена.** Подпись
приватного запроса несёт `OK-ACCESS-TIMESTAMP`, и метку, разошедшуюся с
часами источника больше чем на 30 секунд, источник отвергает кодом `50102`
(`docs/integrations/okx/rules/request-signing.md`). Коннектор поэтому ставит
в подпись не часы хоста, а **момент площадки**: часы хоста плюс смещение,
измеренное этим эндпоинтом.

- **Смещение — серверное время минус середина собственного запроса** к
  `public/time`: половина круга сети отнесена к каждой стороне. Живёт оно в
  памяти процесса, одно на процесс: часы хоста у всех счетов общие.
- **Мерится по отказу, а не по расписанию.** До первого отказа смещение
  нулевое; отказ `50102` перемеряет его, и следующий запрос подписан новым
  моментом. Тика синхронизации нет: дрейф наблюдается только отказом, и
  мерить его в его отсутствие значило бы тратить лимит эндпоинта впустую.
  Отсюда же лимит соблюдён — после удачного замера отказы прекращаются.
- **Неудачный замер прежнего смещения не трогает:** ответ без серверного
  времени, неразбираемая метка либо молчание источника оставляют прежнее
  значение, и повтора, ради которого мерили, не будет.
- **Повтор отвергнутого запроса и класс отказа, пережившего замер, — не
  здесь:** их дом — граница интеграции (`docs/components/IntegrationService.md`)
  и классификация (`docs/rules/runtime-error-classification.md`).

**Операндом биржевых окон выровненный момент не становится.** Он годен
ровно на то, чтобы источник принял метку; границы окон по-прежнему берут
серверное время из ответа этого эндпоинта, а не часы хоста со смещением:
смещение мерено с точностью до круга сети и устаревает до следующего
отказа.

## GET /api/v5/public/time

Rate limit 10 req / 2 s по IP. Параметров нет. Ответ `data[0]`:
`ts` — серверное время, Unix-миллисекунды строкой.

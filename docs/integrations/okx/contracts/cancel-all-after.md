# OKX contracts: cancel all after (dead-man's switch)

## На какой вопрос отвечает этот файл

Каков контракт операции Cancel All After (серверная отмена всех
pending-ордеров по таймауту).

## Внешний источник правды

Дистиллят официального дока OKX (`https://www.okx.com/docs-v5/en/`,
раздел «Order Book Trading → Trade», секция «POST / Cancel All
After»). При расхождении с офдоком побеждает офдок; синхронизация —
перевыкачка + дифф при каждом заходе интегратора по источнику и по
задаче «актуализируй» (`.claude/processes/api-docs-completion.md`,
канал чтения — `.claude/skills/integration-okx.md`). Последняя
сверка: 2026-06-11 (поле-уровневая дистилляция).

## Статус использования

Не используется. Форвард-кандидат для safety: серверная
страховка на потерю связи **поверх** явного kill-switch teardown
(реактивный side-executor, не команда), не вместо него. Передан владельцу
внедрения safety заметкой.

## Endpoint

`POST /api/v5/trade/cancel-all-after`. Permission `Trade`; rate limit
1 req / s по User ID + tag. Применим ко всем order-book-инструментам
(кроме Spread trading).

### Request

| Поле | Тип | Обяз. | Семантика |
|---|---|---|---|
| `timeOut` | String | да | Обратный отсчёт отмены, секунды. Допустимо `0` и [10, 120]. `0` — выключить CAA. |
| `tag` | String | нет | Tag-level CAA: отменяются только ордера с этим тегом (тег ставится при place). Без `tag` — CAA уровня аккаунта (все pending всех order-book-инструментов суб-аккаунта). |

### Response (`data[0]`)

| Поле | Семантика |
|---|---|
| `triggerTime` | Время срабатывания отмены; `0` — CAA выключен. |
| `tag` | Тег CAA. |
| `ts` | Время приёма запроса. |

## Семантика (офдок)

- Рекомендован **heartbeat раз в секунду** (повторный вызов сдвигает
  отсчёт). При срабатывании движок отменяет ордера по одному —
  операция может занять до нескольких секунд.
- Нормативная оговорка офдока: механизм — **защитный** («protection
  mechanism for clients only»), не часть торговой стратегии.
- Tag-level CAA: одновременно живых до 20 на суб-аккаунт (превышение
  — ошибка 51071); считаются только живые (сработавшие/снятые не в
  счёт).
- Покрытие algo-ордеров в секции офдока **не специфицировано**
  (нормативный текст говорит о pending orders). Не додумываем; при
  внедрении уточнить отдельно — отмена algo имеет свой
  контракт (`algo-order.md`).

# OKX contracts: account rate limit

## На какой вопрос отвечает этот файл

Каков контракт операции чтения аккаунт-уровневого rate limit
(fill-ratio-based лимит суб-аккаунта).

## Внешний источник правды

Дистиллят официального дока OKX (`https://www.okx.com/docs-v5/en/`,
раздел «Order Book Trading → Trade», секция «GET / Account rate
limit»). При расхождении с офдоком побеждает офдок; синхронизация —
перевыкачка + дифф при каждом заходе интегратора по источнику и по
задаче «актуализируй» (`.claude/processes/api-docs-completion.md`,
канал чтения — `.claude/skills/integration-okx.md`). Последняя
сверка: 2026-06-11 (прогон 3, поле-уровневая дистилляция).

## Статус использования

Не используется (диагностика лимитов; низкий приоритет — поведение
бота далеко от потолков).

## Endpoint

`GET /api/v5/trade/account-rate-limit`. Rate limit 1 req / s по
User ID. Permission в секции офдока не указан (private read).
Без параметров запроса.

## Семантика (офдок)

- В аккаунт-уровневый лимит считаются только **place / amend**
  запросы; batch-запрос считается поэлементно (по числу ордеров).
- Лимит привязан к **fill ratio** суб-аккаунта (механика «Fill ratio
  based sub-account rate limit»); расширенные поля применимы к
  fee tier ≥ VIP 5, прочим возвращается `""`.

### Response (`data[0]`)

| Поле | Семантика |
|---|---|
| `accRateLimit` | Текущий лимит суб-аккаунта (запросов / 2 s). |
| `nextAccRateLimit` | Ожидаемый лимит следующего периода мониторинга (VIP 5+, иначе `""`). |
| `fillRatio` | Fill ratio суб-аккаунта за период (VIP 5+; `""`/`0`/`9999` — спец-значения по офдоку). |
| `mainFillRatio` | Агрегированный fill ratio мастер-аккаунта (VIP 5+). |
| `ts` | Время данных (VIP 5+ — генерация раз в сутки 08:00 UTC; прочим — текущее время). |

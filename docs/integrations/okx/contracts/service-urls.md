# OKX Service URLs

## На какой вопрос отвечает этот файл

Какие URL у OKX по окружениям (production, demo) и регионам.

## Источник правды вне репозитория

Официальный док OKX (`https://www.okx.com/docs-v5/en/`, разделы Overview
/ REST Authentication / WebSocket; смена доменов — changelog `log_en/`,
напр. вывод AWS-доменов 2025-04-28). Процедура сверки и приоритет офдока
— `.claude/rules/external-source-sync.md`. Последняя сверка: 2026-06-11
(существование/пути; поле-уровневая перевычитка — при заходе по теме).

## Production

### EEA (по документации OKX)

- **REST:** `https://eea.okx.com`
- **WS public:** `wss://wseea.okx.com:8443/ws/v5/public`
- **WS private:** `wss://wseea.okx.com:8443/ws/v5/private`
- **WS business:** `wss://wseea.okx.com:8443/ws/v5/business`

### Глобальные (часто используются в практике)

- **REST:** `https://www.okx.com`
- **WS public:** `wss://ws.okx.com:8443/ws/v5/public`
- **WS private:** `wss://ws.okx.com:8443/ws/v5/private`
- **WS business:** `wss://ws.okx.com:8443/ws/v5/business`

## Demo trading

- **REST:** `https://eea.okx.com` (тот же, demo flag через header).
- **WS public/private/business:** `wss://wseeapap.okx.com:8443/ws/v5/...`.

**Чей это выбор.** Заголовок ниже — форма, которой контур выражается в
запросе к OKX; **какой контур у счёта** и какие контуры допускает
окружение — не предмет этого дока
(чем различаются окружения — `docs/architecture/platform.md`).

**Header для demo (REST и WS login):** `x-simulated-trading: 1`. Без
него запросы будут уходить в production-окружение даже при demo-ключах
— возможна ошибка несоответствия окружения/ключа.

**Контур есть только у приватного запроса; публичное чтение уходит в
production всегда.** Заголовок ставится на клиента конкретного счёта по
контуру его ключей; публичный клиент коннектора (листинг, правила
инструментов, свечи, срезы цен, время) собирается без заголовка и о
контуре не знает. Довод: у публичного чтения нет счёта, а значит и
контура, — рыночные данные в системе одни на все счета, а `prod`
допускает счета обоих контуров сразу (`docs/architecture/platform.md`).
Заголовок на процесс приписал бы все рыночные данные одному контуру и в
`prod` отдал бы боевым счетам цены демо-контура; контур на вызове
потребовал бы от владельца рыночных данных второго, демо-экземпляра
каждого ряда — вдвое больший сбор ради счетов, которые капитала не
двигают.

**Цена названа: у DEMO-счёта инструменты, их биржевые правила и цены
приходят из production-контура, а заявки ставятся в демо.** Совпадают
ли перечень инструментов, лимиты и цены между контурами, офдок не
говорит (сверка 2026-09-29) — это допущение, а не факт источника.
Расхождение обнаруживается реджектом площадки на постановке заявки
демо-счёта, а не раньше. У LIVE-счёта расхождения нет по построению:
его контур и есть контур публичного чтения.

## Правило выбора

URL **выбирается по региону** доступа и наличию ключа (EEA vs
глобальные) в client-layer; жёстко не фиксируется в коде, конфигурируется
извне (Spring profile / config / Vault). Для production по умолчанию —
EEA-вариант; глобальные `www.okx.com`/`ws.okx.com` — fallback.

## WS-каналы

WS-каналы OKX (имена: `account`, `positions`, `orders`,
`balance_and_position`, `tickers`, `candle<bar>`, `instruments`,
`algo-orders`, `algo-advance` и др.) — полноценно не задокументированы
в текущем заходе (REST-only миграция). Список и контракты WS-каналов —
отдельный заход.

REST `okx-*-mapping.md` указывают WS-альтернативу там, где она есть, но
не описывают её детально.

# OKX timeframes: case-sensitive, только константы

## На какой вопрос отвечает этот файл

Какое у нас правило обращения со строками таймфреймов OKX.

## Правило

- Строки таймфреймов OKX (`bar`) **case-sensitive**: `1H ≠ 1h`,
  `1Dutc ≠ 1DUTC`. Регистр — часть значения.
- В коде используются **только константы** (например,
  `OkxTimeframes`), не строковые литералы вразброс.
- **Запрет нормализации в lower-case** (как и любой другой
  переписки регистра) над строками таймфреймов: нормализация
  ломает соответствие контракту OKX.
- Маппинг доменный `TimeFrame` ↔ строка OKX строгий, без
  `lowerCase` / `upperCase` — точное соответствие строк (см.
  `docs/models/mapping/TimeFrame.md`).

## Почему

OKX принимает `bar` буквально и регистрозависимо (см.
`docs/integrations/okx/contracts/candle.md` — «Регистр важен»).
Любая нормализация регистра приведёт к отклонённому запросу или
к молчаливо неверному таймфрейму.

# Architecture Decision Records

Журнал значимых архитектурных решений на проекте.

## Что такое ADR

ADR — короткий документ, фиксирующий **одно** архитектурное решение с обоснованием. Принципы:

- **Append-only.** Принятый ADR не редактируется задним числом.
- **Одно решение — один ADR.** Не смешивать.
- **С альтернативами.** Если альтернатив не было — это не ADR, это просто факт.
- **С последствиями.** Что меняется в коде / документации.

## Когда создавать ADR

Создавай ADR для решений, которые:
- Трудно отменить.
- Имеют альтернативы.
- Влияют более чем на один модуль или документ.
- Будут влиять на проект дольше нескольких недель.

Не создавай ADR для:
- Мелких выборов реализации.
- Конвенций — это в `docs/conventions/` или CLAUDE.md.
- Описания текущего состояния — это в спецификации.

## Статусы ADR

- **Proposed** — обсуждается, не принято.
- **Accepted** — принято, действует.
- **Superseded by ADR-NNNN** — заменено другим ADR. Старый остаётся для истории.
- **Deprecated** — больше не действует, но и замены нет (редко).

Изменение статуса (например, на `Superseded`) — единственное допустимое изменение принятого ADR.

# Q5. `CLOSE_POSITION` и OKX `autoCxl`: использовать ли автоотмену ордеров

Приоритет: `MUST_DECIDE_BEFORE_CODE`

В текущих доменных договорённостях:

```text
CLOSE_POSITION = атомарная команда полного закрытия позиции.
CANCEL_ORDER / CANCEL_ALGO_ORDER = отдельные атомарные команды отмены ордеров.
```

Но в OKX `POST /api/v5/trade/close-position` есть параметр:

```text
autoCxl = автоматически отменить активные ордера по инструменту перед закрытием позиции
```

Нужно решить, как executor должен работать с этим параметром.

Варианты:

```text
1. Всегда не передавать autoCxl / передавать false.
   Тогда CLOSE_POSITION остаётся строго атомарной командой закрытия позиции,
   а cleanup ордеров выполняется отдельными ServiceCommand.

2. Передавать autoCxl=true только в emergency / kill-switch flow.
   Тогда обычный CLOSE_POSITION остаётся атомарным,
   но аварийный flow может использовать биржевую автоочистку.

3. Вернуть autoCancelOrders в ClosePositionCommandPayload.
   Этот вариант нежелателен, потому что смешивает закрытие позиции и отмену ордеров в одной команде.
```

Предварительно безопаснее для текущей архитектуры:

```text
не использовать autoCxl в ClosePositionExecutor;
отмену ordinary orders и algo-orders делать отдельными командами;
если для kill-switch понадобится исключение — описать его отдельно как safety-flow policy.
```

Что нужно зафиксировать после решения:

```text
ClosePositionExecutor использует / не использует autoCxl;
может ли kill-switch отличаться от обычного CLOSE_POSITION;
нужно ли явно указывать это в `02. Сервисные команды`;
нужно ли обновить OKX playbook `Закрыть позицию по рынку REST` с нашим проектным комментарием.
```

Связанные документы:

* `02. Сервисные команды`
* `FSM этапы сделки`
* `01. Жизненный цикл сделки`
* `05. Аудит и история исполнения`
* `Закрыть позицию по рынку REST`

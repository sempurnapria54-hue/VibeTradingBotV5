# Формирователь цены на основе стратегии

> Модель стратегии: Strategy.md
>
> Связанная дока: `Управление сделкой на основе стратегии и атомарных сервисных команд`.

---

# 1. Цель

Формирователь цены — отдельный runtime-модуль, который рассчитывает цены для команд на основании:

* `StrategyAction`;
* параметров стратегии;
* текущей цены;
* цены входа;
* диапазона рынка;
* спецификации инструмента;
* типа ордера;
* типа algo-condition;
* направления сделки.

Формирователь цены не принимает торговых решений.

Он не решает:

* входить или не входить;
* выходить или не выходить;
* двигать stop-loss или нет;
* достаточно ли прибыли;
* сломался ли тренд.

Он только отвечает на вопрос:

> Если действие уже выбрано, какую цену нужно поставить в команду?

---

# 2. Место в архитектуре

```text
StateHandler
  -> StrategyConditionEvaluator
  -> StrategyActionInterpreter
     -> StrategyPriceResolver
     -> SizeCalculator
     -> RiskCalculator
     -> ServiceCommandFactory
  -> ServiceCommandExecutor
  -> Executor
```

Формирователь цены вызывается до executor.

Executor получает уже готовую цену или price policy.

---

# 3. Что должен уметь формирователь цены

Он должен покрывать все price-related кейсы из стратегии:

1. Market-like обычные ордера.
2. Limit ordinary orders.
3. Grid entry orders.
4. Amend ordinary order price.
5. Attached stop-loss внутри entry order.
6. Standalone stop-loss algo-order.
7. OCO_FULL: stop-loss + take-profit.
8. Partial take-profit.
9. Partial stop-loss, если появится в condition type.
10. Trailing stop activation price.
11. Перенос stop-loss к entry / breakeven-like уровню.
12. Расчёт цены от `RANGE_LOW`.
13. Расчёт цены от `RANGE_HIGH`.
14. Расчёт цены от `ENTRY_PRICE`.
15. Расчёт цены от `MARKET_PRICE` с `LAST / INDEX / MARK`.
16. Округление по `tickSz`.
17. Валидацию невозможности расчёта.

---

# 4. Главный принцип

Стратегия хранит схему расчёта цены, но не готовую биржевую цену.

Пример из стратегии:

```text
baseType = RANGE_LOW
offsetSide = ABOVE
percents = 10
```

Формирователь цены превращает это в:

```text
basePrice = rangeLow
offset = rangeWidth * 10%
rawPrice = basePrice + offset
roundedPrice = roundByTickSz(rawPrice)
```

После этого `ServiceCommand` получает уже конкретную цену.

# 8. Источники цены

Формирователь цены должен уметь брать базовую цену из разных источников.

## 8.1. MARKET_PRICE

Если `baseType = MARKET_PRICE`, используется `marketPriceType`:

* `LAST` -> `snapshot.lastPrice`;
* `MARK` -> `snapshot.markPrice`;
* `INDEX` -> `snapshot.indexPrice`.

Если `marketPriceType` не указан, это ошибка конфигурации.

---

## 8.2. ENTRY_PRICE

Если `baseType = ENTRY_PRICE`, используется:

1. `activePosition.avgPrice`, если позиция уже открыта.
2. `entryOrder.avgPrice`, если позиция ещё не загружена, но order уже исполнен.
3. Иначе — ошибка невозможности расчёта.

---

## 8.3. RANGE_LOW

Если `baseType = RANGE_LOW`, используется нижняя граница диапазона из `MarketPhase`.

`MarketPhase` должен содержать или отдавать через derived/service:

```text
rangeLow
rangeHigh
```

Если range low отсутствует — ошибка невозможности расчёта.

---

## 8.4. RANGE_HIGH

Если `baseType = RANGE_HIGH`, используется верхняя граница диапазона из `MarketPhase`.

Если range high отсутствует — ошибка невозможности расчёта.

---

# 9. StrategyPricePlacement

`StrategyPricePlacement` используется в `StrategyOrderAction`.

```java
public class StrategyPricePlacement {

    private StrategyPriceBaseType baseType;

    private TriggerPriceType marketPriceType;

    private StrategyPriceOffsetSide offsetSide;

    private BigDecimal percents;
}
```

Семантика:

* `baseType` — от чего считаем;
* `marketPriceType` — какую текущую цену брать, если base = MARKET_PRICE;
* `offsetSide` — куда смещаемся;
* `percents` — величина смещения.

---

# 10. Расчёт placement

## 10.1. Общая формула

```text
basePrice = resolveBasePrice(baseType)
offset = resolveOffset(baseType, percents)

if offsetSide = ABOVE:
    rawPrice = basePrice + offset

if offsetSide = BELOW:
    rawPrice = basePrice - offset

roundedPrice = roundByTickSize(rawPrice)
```

---

## 10.2. Offset от обычной цены

Для `MARKET_PRICE` и `ENTRY_PRICE`:

```text
offset = basePrice * percents / 100
```

Пример:

```text
basePrice = 3000
percents = 0.5
offset = 15
```

---

## 10.3. Offset от диапазона

Для `RANGE_LOW` и `RANGE_HIGH` есть два возможных подхода.

## Вариант A. Процент от самой цены

```text
offset = basePrice * percents / 100
```

Минус: для range-логики это менее удобно.

## Вариант B. Процент от ширины диапазона

```text
rangeWidth = rangeHigh - rangeLow
offset = rangeWidth * percents / 100
```

Рекомендация: для `RANGE_LOW/RANGE_HIGH` использовать процент от ширины диапазона.

Тогда:

```text
RANGE_LOW + ABOVE 10%
  -> rangeLow + 10% ширины диапазона

RANGE_HIGH + BELOW 10%
  -> rangeHigh - 10% ширины диапазона
```

Это лучше подходит для grid.

---

# 11. Округление цены

Формирователь цены должен округлять по `tickSize`.

## 11.1. Базовое правило

```text
roundedPrice = roundToTick(rawPrice, tickSize, roundingMode)
```

## 11.2. RoundingMode зависит от смысла цены

Для лимитного BUY:

* если хотим не ухудшить цену — округлять вниз;
* если хотим повысить шанс исполнения — можно округлять вверх.

Для лимитного SELL:

* если хотим не ухудшить цену — округлять вверх;
* если хотим повысить шанс исполнения — можно округлять вниз.

Для stop-loss trigger:

* LONG SL ниже entry — обычно округлять вниз;
* SHORT SL выше entry — обычно округлять вверх.

Для take-profit trigger:

* LONG TP выше entry — обычно округлять вверх;
* SHORT TP ниже entry — обычно округлять вниз.

Рекомендация:

Ввести `PriceRoundingPolicy`.

```java
public enum PriceRoundingPolicy {
    CONSERVATIVE,
    AGGRESSIVE,
    NEAREST
}
```

На первом этапе можно использовать безопасный conservative mode.

---

# 12. Market-like обычные ордера

Для market / optimal_limit_ioc не всегда нужна цена в request.

Формирователь должен вернуть не конкретную limit price, а price policy.

Пример результата:

```text
priceMode = MARKET_LIKE
roundedPrice = null
sendPriceToExchange = false
referencePrice = mark/last
```

Зачем всё равно нужна reference price:

* для расчёта размера позиции;
* для расчёта риска;
* для расчёта attached stop-loss;
* для логов;
* для проверки отклонения цены.

---

# 13. Limit ordinary orders

Если `StrategyOrderAction.placement != null`, формирователь считает конкретную limit price.

Пример:

```text
baseType = MARKET_PRICE
marketPriceType = MARK
offsetSide = BELOW
percents = 0.2
```

Расчёт:

```text
base = markPrice
rawPrice = markPrice - 0.2%
roundedPrice = roundByTickSz(rawPrice)
```

Результат уходит в `CREATE_ORDER.price`.

---

# 14. Grid entry orders

Grid выражается как несколько `StrategyOrderAction` внутри одного `StrategyStep`.

Каждый action имеет:

* `direction`;
* `allocationPercents`;
* `level`;
* `placement`.

Пример LONG grid:

```text
level 1: RANGE_LOW ABOVE 10%
level 2: RANGE_LOW ABOVE 25%
level 3: RANGE_LOW ABOVE 40%
level 4: RANGE_LOW ABOVE 55%
```

Формирователь для каждого level считает свою цену.

Важно:

* `level` не влияет на формулу сам по себе;
* `level` нужен для идемпотентности, сортировки и связи с order;
* цена задаётся через `placement`.

---

# 15. Attached stop-loss

Attached protection находится внутри `StrategyOrderAction.attachedProtection`.

```java
public class StrategyAttachedProtectionSettings {

    private AttachedAlgoOrder.Type attachedType;

    private StopLossSettings stopLossSettings;
}
```

Формирователь должен рассчитать trigger price для attached SL.

Источник base price зависит от этапа:

* если entry order ещё не исполнен, base price может быть planned entry price;
* если это market-like order, base price берётся как reference market price;
* после исполнения фактическая цена уточняется refresh’ем.

Для первичного attached SL допустимо считать от reference price.

После entry finalized standalone main protection должна считаться уже от фактической entry/avg price.

---

# 16. StopLossSettings

```java
public class StopLossSettings {

    private String calculationType;

    private BigDecimal distancePercents;

    private TriggerPriceType triggerPriceType;
}
```

Поддерживаемые `calculationType`:

```text
ENTRY_PRICE_PERCENT
ATR_PERCENT
MARKET_STRUCTURE_BUFFER_PERCENT
```

---

# 17. ENTRY_PRICE_PERCENT

Используется для breakeven-like и обычного SL от entry.

## LONG

```text
SL = entryPrice - entryPrice * distancePercents / 100
```

Если `distancePercents = 0.10`, то SL ставится на 0.10% ниже entry.

## SHORT

```text
SL = entryPrice + entryPrice * distancePercents / 100
```

Если `distancePercents = 0.10`, то SL ставится на 0.10% выше entry.

---

# 18. ATR_PERCENT

Используется для SL на расстоянии от ATR.

В стратегии `distancePercents = 150` означает:

```text
150% ATR = 1.5 * ATR
```

## LONG

```text
SL = basePrice - ATR * distancePercents / 100
```

## SHORT

```text
SL = basePrice + ATR * distancePercents / 100
```

Источник ATR должен быть в context или отдельном indicator snapshot.

Формирователь цены не должен сам считать ATR по свечам.

Если ATR отсутствует — цена не может быть рассчитана.

---

# 19. MARKET_STRUCTURE_BUFFER_PERCENT

Используется для SL за уровнем структуры рынка.

Примеры:

* LONG SL ниже swing low;
* SHORT SL выше swing high;
* grid SL за границей диапазона.

## LONG

```text
structureBase = swingLow или rangeLow
buffer = structureBase * distancePercents / 100
SL = structureBase - buffer
```

## SHORT

```text
structureBase = swingHigh или rangeHigh
buffer = structureBase * distancePercents / 100
SL = structureBase + buffer
```

Источник структуры должен быть подготовлен заранее:

* `MarketPhase`;
* `MarketStructureSnapshot`;
* indicator service.

---

# 20. Take-profit

Для `StrategyAlgoOrderAction` take-profit задаётся через:

```java
private BigDecimal triggerProfitPercents;
private TriggerPriceType triggerPriceType;
```

## LONG

```text
TP = entryPrice + entryPrice * triggerProfitPercents / 100
```

## SHORT

```text
TP = entryPrice - entryPrice * triggerProfitPercents / 100
```

Пример:

```text
entryPrice = 3000
triggerProfitPercents = 3
LONG TP = 3090
SHORT TP = 2910
```

---

# 21. OCO_FULL

Если `conditionType = OCO_FULL`, формирователь должен вернуть сразу две цены:

* stop-loss trigger;
* take-profit trigger.

Правила:

* SL считается из `stopLossSettings`;
* TP считается из `triggerProfitPercents`;
* `triggerPriceType` задаёт тип цены TP;
* `stopLossSettings.triggerPriceType` задаёт тип цены SL;
* `closeFractionPercents` определяет долю позиции, но не цену.

Результат:

```text
ResolvedAlgoOrderPrice {
  stopLossPrice = ...
  takeProfitPrice = ...
}
```

---

# 22. Partial take-profit

Если `conditionType = PARTIAL_TAKE_PROFIT`, цена считается как обычный TP.

Отличие:

* `closeFractionPercents` меньше 100;
* `level` задаёт TP1/TP2/TP3;
* каждый action создаёт отдельный price result.

Пример:

```text
TP1: triggerProfitPercents = 1, closeFraction = 25%
TP2: triggerProfitPercents = 2, closeFraction = 25%
TP3: triggerProfitPercents = 3, closeFraction = 50%
```

Формирователь возвращает три разные TP цены при обработке трёх actions.

---

# 23. Trailing stop

`TrailingSettings`:

```java
public class TrailingSettings {

    private BigDecimal activationProfitPercents;

    private BigDecimal callbackPercents;

    private BigDecimal activationBufferPercents;
}
```

Формирователь должен рассчитать:

* active price;
* callback ratio/percents;
* trigger price type.

## 23.1. Если activationProfitPercents = null

Trailing активируется сразу.

```text
activePrice = null
```

или:

```text
sendActivePrice = false
```

## 23.2. Если activationProfitPercents задан

## LONG

```text
activePrice = entryPrice + entryPrice * activationProfitPercents / 100
```

Если есть `activationBufferPercents`:

```text
activePrice = activePrice + entryPrice * activationBufferPercents / 100
```

## SHORT

```text
activePrice = entryPrice - entryPrice * activationProfitPercents / 100
```

Если есть `activationBufferPercents`:

```text
activePrice = activePrice - entryPrice * activationBufferPercents / 100
```

`callbackPercents` передаётся в algo-order как trailing distance.

---

# 24. Перенос stop-loss в breakeven

В стратегии это не отдельная модель, а обычный `StrategyAlgoOrderAction AMEND`.

Пример:

```text
condition:
  POSITION_OPENED
  PROFIT_PERCENTS_REACHED 1%

action:
  ALGO_ORDER AMEND STOP_LOSS
  stopLossSettings:
    calculationType = ENTRY_PRICE_PERCENT
    distancePercents = 0.10
```

Формирователь считает:

## LONG

```text
newSL = entryPrice - 0.10%
```

## SHORT

```text
newSL = entryPrice + 0.10%
```

Это breakeven-like SL с небольшим буфером.

---

# 25. Position close price

`StrategyPositionAction CLOSE_FULL/CLOSE_PARTIAL` обычно не требует цены, если закрытие идёт через market close-position.

Формирователь может вернуть reference price:

```text
priceMode = MARKET_LIKE
sendPriceToExchange = false
referencePrice = markPrice или lastPrice
```

Reference price нужен для:

* логов;
* предварительной оценки PnL;
* проверки проскальзывания;
* отчётности.

---

# 26. AMEND order price

Для `StrategyOrderAction AMEND` поле `placement` означает новую целевую схему цены.

Пример:

```text
AMEND ORDER
placement:
  baseType = MARKET_PRICE
  marketPriceType = MARK
  offsetSide = BELOW
  percents = 0.2
```

Формирователь считает новую цену:

```text
newPrice = markPrice - 0.2%
```

Команда получает:

```text
AMEND_ORDER.newPrice = roundedPrice
```

---

# 27. CANCEL order price

Для `StrategyOrderAction CANCEL` цена обычно не нужна для биржи.

Но `placement` может использоваться как часть идентификации grid-level.

Формирователь в этом случае не обязан считать цену.

Можно вернуть:

```text
priceMode = NOT_REQUIRED
sendPriceToExchange = false
```

Идентификацию лучше делать по:

* dealId;
* strategyId;
* stepType;
* actionType;
* action level;
* order role.

---

# 28. Ошибки расчёта цены

Формирователь должен бросать controlled exception или возвращать error-result, если:

* нет текущей цены;
* нет mark/last/index при выбранном `TriggerPriceType`;
* нет entry price;
* нет range low/high;
* нет ATR для `ATR_PERCENT`;
* нет market structure для `MARKET_STRUCTURE_BUFFER_PERCENT`;
* `percents` пустой там, где он обязателен;
* `offsetSide` пустой для placement;
* `baseType = MARKET_PRICE`, но `marketPriceType = null`;
* рассчитанная цена <= 0;
* цена не проходит ограничения инструмента;
* после округления цена стала невалидной.

---

# 29. Валидация результата

После расчёта нужно проверить:

* цена больше 0;
* цена соответствует `tickSize`;
* цена не выходит за min/max, если такие лимиты известны;
* SL стоит с правильной стороны от entry;
* TP стоит с правильной стороны от entry;
* LONG SL ниже entry;
* LONG TP выше entry;
* SHORT SL выше entry;
* SHORT TP ниже entry;
* trailing callback > 0;
* close price для market-like не отправляется на биржу, если не нужен.

---

# 31. Что формирователь цены не должен делать

Он не должен:

* выбирать strategy step;
* проверять все условия стратегии;
* решать, надо ли создавать order;
* решать, надо ли переносить stop-loss;
* решать, надо ли закрывать позицию;
* ходить на биржу за live-ценой;
* сохранять order/algo-order;
* вызывать executor;
* менять deal status.

Он должен получать уже готовый snapshot цен.

---

# 32. Итоговая схема

```text
StrategyAction
  -> StrategyPriceResolver
     -> resolve base price
     -> apply offset / SL / TP / trailing formula
     -> round by tickSize
     -> validate result
  -> ResolvedPrice
  -> ServiceCommand payload
  -> Executor
```

Главное правило:

> Формирователь цены считает цену для уже выбранного действия.
>
> Он не выбирает действие и не принимает торговое решение.

# 1. Главная идея

Калькуляторы действий стратегии отвечают за подготовку runtime-параметров для сервисных команд.

FSM выбирает допустимое действие стратегии, но не считает цену, размер и risk-policy.

Executor исполняет команду, но не принимает торговых решений и не пересчитывает параметры.

Между ними находится `StrategyActionCalculator`.

```text
FSM / StateHandler
  -> выбрал StrategyAction
  -> StrategyActionCalculator
     -> собирает свежий CalculationContext
     -> PriceCalculator
     -> SizeCalculator
  -> CalculatedStrategyAction
  -> handler / orchestration flow
  -> RiskValidator, если action создаёт риск, увеличивает риск или ослабляет контроль риска
  -> ServiceCommandFactory
  -> ServiceCommand
```

Главное правило:

> `StrategyActionCalculator` получает `StrategyAction + DealContext`, сам собирает свежие данные для расчёта и возвращает готовые параметры команды.

# Архитектурные инварианты calculator-layer

Эта часть фиксирует текущие правила для калькуляторов.

* `StrategyActionCalculator` не должен рассчитывать data-dependent action, если FSM уже определила, что данные step устарели и `StrategyStep.marketDataExpiredSetting` запрещает выполнение.
* Свежесть готовых `IndicatorValue`, `MarketStructure`, `MarketPhase` проверяется через `MarketDataExpirationChecker`, описанный в `04. Расчёт индикаторов и рыночных данных`.
* `entryReason` и `entryStepType` не участвуют в формулах расчёта цены/размера/риска.
* Условность `PROTECTION_SWITCHED` влияет только на выбор protection-switch flow, но не меняет формулы расчёта защиты.
* `ServiceCommand` — runtime object. Калькулятор возвращает рассчитанные параметры, но не создаёт persisted command-row.
* `CLOSE_POSITION` используется только для полного закрытия позиции.
* Direct partial close позиции запрещён как постоянный инвариант стратегии и приложения.
* Partial exit рассчитывается только для reduce-only `StrategyOrderAction` / `StrategyAlgoOrderAction`.
* `SizeCalculator` должен уметь считать размер partial exit для Order / AlgoOrder.
* Для reduce-only partial exit `RiskValidator` не вызывается. Handler выполняет safety / invariant checks: reduce-only intent, размер, направление уменьшения позиции, принадлежность к текущей `Deal` и актуальные exchange facts.

* `CalculationContext` собирается отдельно для каждого рассчитываемого `StrategyAction`.
* Один action = один свежий `CalculationContext`.
* `CalculationContext` не собирается один раз на весь `StrategyStep` и не переиспользуется между actions.
* Controlled calculation errors возвращаются как error-result калькулятора.
* Unexpected exceptions не превращаются в `CalculationError` и обрабатываются на границе `DealOrchestratorJob` / FSM execution boundary.
* `StrategyActionCalculator` не вызывает `RiskValidator` напрямую.
* Финальное решение по блокирующему риску принимает risk-layer: `RiskValidator` + `RiskBlockResolver`, описанные в документе `Оценка рисков`.
* `StrategyActionCalculator` не возвращает `CalculatedRiskMetrics`. Метрики, которые нужны для решения `ALLOWED / WARNING / BLOCKED`, считаются внутри `RiskValidator` / risk-layer.
* `CalculationContext` может включать `BalanceContainer` как input для расчёта размера, но не обновляет его.
* `StrategyActionCalculator` не вызывает `REFRESH_BALANCE`, `ClientService` или OKX adapter.
* Свежесть `BalanceContainer` перед risk-sensitive flow обеспечивает FSM / handler.
* Если action зависит от баланса, а `BalanceContainer` absent/stale, handler должен сначала создать `REFRESH_BALANCE`, а не запускать калькулятор/risk-flow вслепую.

# 2. Почему расчёт делается в runtime

Нельзя полностью полагаться на данные, собранные в `DealContext` заранее.

Причина:

```text
DealContext собрали
  -> FSM выбрала action
  -> выполняются команды
  -> проходит несколько секунд
  -> цена могла измениться
```

Поэтому перед формированием команды нужно иметь возможность собрать свежий `CalculationContext`:

* актуальную рыночную цену `MarketPriceData`;
* свежий bid / ask;
* актуальные внешние правила инструмента `InstrumentExternalRules`;
* актуальный ATR или другие готовые `IndicatorValue`;
* актуальные уровни структуры рынка `MarketStructure` / `MarketPriceLevel`;
* актуальную фазу рынка `MarketPhase`, если она нужна для условия;
* актуальный `BalanceContainer`, если действие требует расчёта размера или последующей risk-policy проверки.

Это особенно важно для:

* market-like entry;
* SL/TP;
* trailing;
* расчёта размера в контрактах;
* подготовки данных для последующей risk-policy проверки перед отправкой risk-creating / risk-modifying order.

# 3. StrategyActionCalculator

`StrategyActionCalculator` — оркестратор расчёта параметров действия стратегии.

Он не является только калькулятором цены.

Он объединяет:

* `CalculationContextFactory`;
* `PriceCalculator`;
* `SizeCalculator`;


Рекомендуемый интерфейс:

```java
public interface StrategyActionCalculator {

    /**
     * Рассчитать runtime-параметры для выбранного действия стратегии.
     *
     * @param action действие стратегии, выбранное FSM
     * @param dealContext текущий контекст сделки
     * @return рассчитанные параметры для создания ServiceCommand
     */
    CalculatedStrategyAction calculate(
            StrategyAction action,
            DealContext dealContext
    );
}
```

Результат:

```java
public class CalculatedStrategyAction {

    /**
     * Исходное действие стратегии.
     */
    private StrategyAction sourceAction;

    /**
     * Рассчитанная цена или набор цен.
     */
    private CalculatedPrice calculatedPrice;

    /**
     * Рассчитанный размер order/algo/position action.
     */
    private CalculatedSize calculatedSize;


    /**
     * Пояснение для логов и аудита.
     */
    private String explanation;
}
```


## 3.1. Уточнение после Q3: результат калькулятора

Для реализации после Q3 рекомендуется отделить:

```text
успешно рассчитанное действие
и
контролируемую ошибку расчёта
```

Для этого внешний контракт калькулятора может возвращать wrapper-result:

```java
public class StrategyActionCalculationResult {

    /** Итог расчёта: SUCCESS / ERROR. */
    private Status status;

    /** Рассчитанное действие. Заполнено только при SUCCESS. */
    private CalculatedStrategyAction calculatedAction;

    /** Контролируемая ошибка расчёта. Заполнена только при ERROR. */
    private CalculationError error;

    public enum Status {
        SUCCESS,
        ERROR
    }
}
```

`CalculatedStrategyAction` в финальном варианте должен описывать именно успешный расчёт:

```java
public class CalculatedStrategyAction {

    /** Исходное действие стратегии. */
    private StrategyAction sourceAction;

    /** Рассчитанная цена или набор цен. */
    private CalculatedPrice calculatedPrice;

    /** Рассчитанный размер order/algo/position action. */
    private CalculatedSize calculatedSize;


    /** Комментарий / пояснение расчёта для логов и будущего аудита. */
    private String description;
}
```

Важно:

```text
`StrategyActionCalculator` не возвращает `RiskValidationResult` как часть успешного расчёта.
После успешного расчёта price/size handler / orchestration flow отдельно решает, нужен ли `RiskValidator`.
`RiskValidator` вызывается только для actions, которые создают риск, увеличивают риск или ослабляют контроль риска.
`RiskBlockResolver` превращает результат risk-policy проверки в `RiskBlockAction`.
```

Если в старом коде или тексте встречается поле `explanation`, его можно считать legacy-именем для будущего `description` / `comment`.

## 3.2. CalculationError

`CalculationError` используется только для контролируемых ошибок расчёта.

Примеры:

```text
нет актуальной цены;
нет entry price;
нет ATR для ATR-based SL;
нет market structure для structure-based SL;
невозможно округлить цену по tick size;
невозможно рассчитать размер из-за minSz / lotSz;
не хватает обязательных input data для конкретного action.
```

Модель:

```java
public class CalculationError {

    /** Машинный код ошибки расчёта. */
    private String code;

    /** Тип ошибки расчёта. */
    private CalculationErrorType type;

    /** Человекочитаемое описание. */
    private String message;

    /** Можно ли повторить расчёт позже без изменения стратегии. */
    private boolean retryable;
}
```

```java
public enum CalculationErrorType {

    /** Временная ошибка: данные задержались, сервис временно недоступен. */
    TEMPORARY,

    /** Постоянная ошибка: action невозможно корректно рассчитать в текущей конфигурации. */
    PERMANENT
}
```

Политика:

```text
TEMPORARY
  -> DealActionState = RETRY_PENDING
  -> весь текущий StrategyStep ждёт retry текущего action
  -> следующие actions этого step не выполняются до разрешения текущего action

PERMANENT
  -> DealActionState = FAILED
  -> Deal -> ERROR для runtime-статусов, где live risk уже есть или мог появиться
  -> дальше ErrorHandler / safety-flow
```

# 4. CalculationContext

`CalculationContext` — рабочий runtime-контекст калькуляторов.

Он собирается внутри `StrategyActionCalculator`.

Он не заменяет `DealContext`.

Он строится из:

```text
DealContext
  + StrategyAction
  + свежие runtime-data
```

Пример модели:

```java
public class CalculationContext {

    /**
     * Сделка, для которой выполняется расчёт.
     */
    private Deal deal;

    /**
     * Инструмент сделки.
     */
    private Instrument instrument;

    /**
     * Pinned StrategyDetail сделки.
     */
    private StrategyDetail strategyDetail;

    /**
     * Действие стратегии, для которого считаются параметры.
     */
    private StrategyAction action;

    /**
     * Внешние правила инструмента: tick size, lot size, min size,
     * contract value, max leverage, state и другие биржевые ограничения.
     */
    private InstrumentExternalRules instrumentExternalRules;

    /**
     * Runtime-данные рыночных цен.
     *
     * Не хранятся в БД.
     * Получаются через REST ticker перед расчётом.
     */
    private MarketPriceData marketPriceData;

    /**
     * Готовые значения индикаторов, если они нужны для расчёта.
     *
     * Калькулятор их не считает, а получает через IndicatorService.
     */
    private List<IndicatorValue> indicatorValues;

    /**
     * Готовые структуры рынка, если они нужны для расчёта.
     *
     * Калькулятор их не считает, а получает через MarketStructureService.
     */
    private List<MarketStructure> marketStructures;

    /**
     * Актуальная фаза рынка, если она нужна для проверки условия или расчёта.
     */
    private MarketPhase marketPhase;

    /**
     * Контейнер баланса для расчёта размера и подготовки risk-policy check.
     *
     * Это persisted snapshot из DealContext / БД.
     * CalculationContext не обновляет баланс и не вызывает ClientService.
     */
    private BalanceContainer balanceContainer;

    /**
     * Активная позиция, если она уже открыта.
     */
    private Position activePosition;

    /**
     * Entry order, если он уже создан.
     */
    private Order entryOrder;

    /**
     * Состояние позиций по инструменту.
     */
    private PositionContext positionContext;

    /**
     * Настройки риска из StrategyDetail или глобальной risk policy.
     */
    private RiskSettings riskSettings;

    /**
     * Направление стратегии: LONG / SHORT.
     */
    private StrategyTradeDirection strategyDirection;
}
```

Важно:

> `CalculationContext` должен быть собран максимально близко ко времени создания команды.


## 4.1. Scope CalculationContext после Q7

`CalculationContext` собирается отдельно для каждого рассчитываемого `StrategyAction`.

Правило:

```text
один action = один свежий CalculationContext
```

Не собираем один общий context:

```text
на весь StrategyStep;
на весь handler;
на весь проход DealOrchestratorJob.
```

Причина:

```text
actions выполняются последовательно;
после каждого action могут измениться Order / AlgoOrder / Position / Balance / market facts;
если action зависит от баланса, перед новым расчётом handler должен убедиться, что `BalanceContainer` всё ещё fresh;
StrategyStep не является atomic transaction;
следующий action не должен считать параметры по устаревшему context.
```

Flow:

```text
action1
  -> collect CalculationContext
  -> calculate price/size
  -> handler decides whether RiskValidator is needed
  -> ServiceCommandFactory

action2
  -> collect новый CalculationContext
  -> calculate price/size
  -> handler decides whether RiskValidator is needed
  -> ServiceCommandFactory
```


## 4.2. BalanceContainer в CalculationContext

`BalanceContainer` может входить в `CalculationContext`, если он нужен для sizing или подготовки risk-policy проверки.

Правила:

* `CalculationContext` получает `BalanceContainer` как input;
* `CalculationContextFactory` не вызывает `ClientService`;
* `StrategyActionCalculator` не создаёт `REFRESH_BALANCE`;
* calculator-layer не решает, достаточно ли balance fresh для risk-policy;
* freshness precondition обеспечивает FSM / handler;
* defensive-блокировка absent/stale/invalid balance остаётся в `RiskValidator`.

Если перед расчётом action balance absent/stale, правильный flow такой:

```text
handler
  -> REFRESH_BALANCE
  -> новый проход FSM
  -> новый DealContext
  -> CalculationContext
```

# 5. Источники данных для CalculationContext

Перед сбором `CalculationContext` FSM уже должна проверить freshness конкретного `StrategyStep`.

Но `CalculationContextFactory` всё равно должен работать защитно:

```text
если обязательное готовое значение отсутствует;
если значение явно устарело;
если сервис рыночных данных не может вернуть актуальную цену;
```

то калькулятор должен вернуть controlled error/result или бросить контролируемое исключение, а не молча считать action по старым данным.


`StrategyActionCalculator` использует специальные сервисы:

```text
MarketPriceDataService
InstrumentExternalRulesService
IndicatorService
MarketStructureService
MarketPhaseService
BalanceService / BalanceContainerRepository
RiskSettingsService
```

Пример:

```java
public class DefaultStrategyActionCalculator implements StrategyActionCalculator {

  private final CalculationContextFactory calculationContextFactory;
  private final PriceCalculator priceCalculator;
  private final SizeCalculator sizeCalculator;

  @Override
  public StrategyActionCalculationResult calculate(StrategyAction action, DealContext dealContext) {
    CalculationContext context = calculationContextFactory.build(action, dealContext);

    CalculatedPrice price = priceCalculator.calculate(context);
    CalculatedSize size = sizeCalculator.calculate(context, price);
    CalculatedStrategyAction calculatedAction = new CalculatedStrategyAction(
            action,
            price,
            size
    );

    return StrategyActionCalculationResult.success(calculatedAction);
  }
}
```

Важно:

```text
Пример выше не вызывает RiskValidator.
RiskValidator вызывается отдельно handler / orchestration flow после успешного расчёта, если action требует risk-policy validation.
```

## 5.1. Важное правило по тяжёлым данным

`StrategyActionCalculator` не считает тяжёлые данные сам.

Он только читает готовые результаты:

```text
IndicatorValue
MarketStructure
MarketPhase
InstrumentExternalRules
```

Тяжёлые расчёты выполняют:

```text
IndicatorJob
MarketStructureJob
MarketPhaseJob
InstrumentExternalRulesSyncJob
```

## 5.2. MarketPriceData — исключение

`MarketPriceData` не хранится в БД и не считается заранее.

Он нужен прямо перед расчётом.

Flow:

```text
Client model OKX ticker
  -> MarketPriceDataExternalSnapshot
  -> MarketPriceData
  -> CalculationContext
```

Кэш на первом этапе не используем.

Чтобы не плодить REST-запросы, правило такое:

> В рамках одного `CalculationContext` `MarketPriceData` получаем один раз и переиспользуем для всех расчётов этого context.


## 5.3. Где выполняется RiskValidator относительно calculator-layer

`RiskValidator` не вызывается внутри `StrategyActionCalculator`.

Правильная orchestration-схема:

```text
FSM / handler
  -> StrategyActionCalculator
     -> собирает CalculationContext
     -> PriceCalculator
     -> SizeCalculator
     -> StrategyActionCalculationResult.SUCCESS
  -> handler решает, нужна ли risk-policy validation
  -> RiskValidator, если action создаёт риск, увеличивает риск или ослабляет контроль риска
  -> RiskBlockResolver, если risk result = BLOCKED / WARNING policy
  -> ServiceCommandFactory
```

`RiskValidator` вызывается только для risk-creating / risk-modifying actions, например:

```text
CREATE_ORDER
AMEND_ORDER
CREATE_ALGO_ORDER
AMEND_ALGO_ORDER
```

Для reduce-only partial exit `RiskValidator` не вызывается.
Handler выполняет только safety / invariant checks:

```text
reduce-only intent;
размер не превышает текущую позицию;
направление уменьшает позицию, а не увеличивает;
target относится к текущей Deal;
есть актуальные exchange facts.
```

`RiskValidator` не вызывается перед read-only refresh-командами:

```text
REFRESH_POSITION
REFRESH_PENDING_ORDERS
REFRESH_ALGO_ORDERS
REFRESH_ORDER_HISTORY
REFRESH_ALGO_ORDER_HISTORY
REFRESH_FILLS
```

`RiskValidator` не вызывается для cleanup / safety commands:

```text
CANCEL_ORDER
CANCEL_ALGO_ORDER
CLOSE_POSITION
EXECUTE_KILL_SWITCH
```

Причина:

```text
refresh-команды только обновляют факты;
cleanup / safety commands снимают или локализуют уже существующий риск;
reduce-only partial exit уменьшает позицию и проверяется через safety / invariant checks, а не через risk-policy validation.
```

# 6. InstrumentExternalRules

`InstrumentExternalRules` — актуальные внешние правила инструмента от биржи.

Они нужны калькуляторам для:

* округления цены;
* округления размера;
* расчёта размера в контрактах;
* проверки `minSize` / max limits;
* проверки плеча;
* проверки, можно ли торговать инструмент.

Хранится в БД как актуальный snapshot правил инструмента.

Обновляется пока только через REST.

```java
public class InstrumentExternalRules extends Auditable {

  /** Технический ID записи. */
  private Long id;

  /** Внутренний ID инструмента в нашей системе. */
  private Long instrumentId;

  /** Нормализованный тип инструмента. */
  private InstrumentType instrumentType;

  /** Нормализованный тип контракта. */
  private ContractType contractType;

  /** Нормализованный статус инструмента. */
  private Status status;

  /** Тип инструмента на стороне биржи. */
  private String externalInstrumentType;

  /** ID инструмента на стороне биржи. */
  private String externalInstrumentId;

  /** Базовая валюта инструмента. */
  private String externalBaseCurrency;

  /** Котируемая валюта инструмента. */
  private String externalQuoteCurrency;

  /** Валюта расчёта / маржи. */
  private String externalSettleCurrency;

  /** Тип контракта на стороне биржи. */
  private String externalContractType;

  /** Размер одного контракта. */
  private String externalContractValue;

  /** Валюта, в которой задан размер контракта. */
  private String externalContractValueCurrency;

  /** Минимальный шаг цены. */
  private String externalTickSize;

  /** Шаг размера ордера. */
  private String externalLotSize;

  /** Минимальный размер ордера. */
  private String externalMinSize;

  /** Максимальный размер одного limit order. */
  private String externalMaxLimitSize;

  /** Максимальный размер одного market order. */
  private String externalMaxMarketSize;

  /** Максимальный размер trigger order. */
  private String externalMaxTriggerSize;

  /** Максимальный размер stop order. */
  private String externalMaxStopSize;

  /** Максимальное плечо, разрешённое биржей. */
  private String externalMaxLeverage;

  /** Состояние инструмента на стороне биржи. */
  private String externalState;

  public enum Status {
    LIVE,
    SUSPEND,
    PREOPEN,
    EXPIRED,
    TEST,
    UNKNOWN
  }
}
```

# 7. MarketPriceData

`MarketPriceData` — runtime value object.

Не хранится в БД.

Историю тикеров не ведём.

Кэш на первом этапе не используем.

# 16. Формулы PriceCalculator

## 16.1. Limit placement

```text
basePrice = resolveBasePrice(source)
offset = resolveOffset(basePrice, source, percents)

if offsetSide = ABOVE:
  rawPrice = basePrice + offset

if offsetSide = BELOW:
  rawPrice = basePrice - offset

roundedPrice = roundByTickSize(rawPrice)
```

Для обычной цены:

```text
offset = basePrice * percents / 100
```

Для диапазона:

```text
rangeWidth = rangeHigh - rangeLow
offset = rangeWidth * percents / 100
```

---

## 16.2. Stop-loss by entry percent

LONG:

```text
SL = entryPrice - entryPrice * distancePercents / 100
```

SHORT:

```text
SL = entryPrice + entryPrice * distancePercents / 100
```

---

## 16.3. Stop-loss by ATR

`distancePercents = 150` означает `1.5 ATR`.

LONG:

```text
SL = basePrice - ATR * distancePercents / 100
```

SHORT:

```text
SL = basePrice + ATR * distancePercents / 100
```

ATR берётся из `AtrValue`.

`PriceCalculator` не считает ATR по свечам.

---

## 16.4. Market structure stop-loss

LONG:

```text
structureBase = swingLow или rangeLow
buffer = structureBase * distancePercents / 100
SL = structureBase - buffer
```

SHORT:

```text
structureBase = swingHigh или rangeHigh
buffer = structureBase * distancePercents / 100
SL = structureBase + buffer
```

---

## 16.5. Take-profit

LONG:

```text
TP = entryPrice + entryPrice * triggerProfitPercents / 100
```

SHORT:

```text
TP = entryPrice - entryPrice * triggerProfitPercents / 100
```

---

## 16.6. Trailing activation

Если `activationProfitPercents = null`:

```text
activePrice = null
sendActivePrice = false
```

LONG:

```text
activePrice = entryPrice + entryPrice * activationProfitPercents / 100
```

Если есть `activationBufferPercents`:

```text
activePrice = activePrice + entryPrice * activationBufferPercents / 100
```

SHORT:

```text
activePrice = entryPrice - entryPrice * activationProfitPercents / 100
```

Если есть `activationBufferPercents`:

```text
activePrice = activePrice - entryPrice * activationBufferPercents / 100
```

# 19. Связь calculator-layer и risk-layer

Calculator-layer отвечает за расчёт параметров action:

```text
price;
size;
side / direction;
reduce-only intent;
closeFraction для reduce-only partial exit;
reference price для full close или audit;
описание расчёта.
```

`StrategyActionCalculator` не возвращает `RiskValidationResult` и не возвращает `CalculatedRiskMetrics`.

Причина:

```text
CalculatedStrategyAction должен быть результатом расчёта параметров команды,
а не результатом risk-policy проверки.
```

Метрики, которые нужны для решения `ALLOWED / WARNING / BLOCKED`, считаются внутри risk-layer:

```text
CalculatedStrategyAction
  -> handler / orchestration flow
  -> RiskValidator, если action требует risk-policy validation
  -> RiskValidationResult
  -> RiskBlockResolver
  -> RiskBlockAction
  -> FSM handler
```

`RiskValidator` может сам рассчитать или запросить необходимые risk-метрики на базе:

```text
CalculatedPrice;
CalculatedSize;
DealContext;
BalanceContainer;
Position;
InstrumentExternalRules;
RiskSettings.
```

Примеры таких метрик:

```text
risk amount;
risk percent от депозита;
estimated leverage;
estimated margin;
notional;
SL distance;
liquidation guard distance;
position exposure после действия.
```

Эти метрики могут попасть в `RiskCheckResult.details`, логи или аудит, но не являются частью `CalculatedStrategyAction`.

Граница ответственности:

```text
StrategyActionCalculator
  -> рассчитывает параметры action;
  -> не вызывает RiskValidator напрямую;
  -> не принимает решение ALLOWED / BLOCKED;
  -> не возвращает risk-policy result.

RiskValidator
  -> проверяет конкретное рассчитанное действие;
  -> сам считает нужные risk-метрики;
  -> возвращает RiskValidationResult;
  -> не переводит Deal в ERROR;
  -> не создаёт ServiceCommand.

RiskBlockResolver
  -> получает risk result + DealContext + StrategyAction + текущий Deal.Status;
  -> решает, является ли риск блокирующим;
  -> возвращает RiskBlockAction;
  -> не исполняет команды сам.

FSM handler
  -> получает RiskBlockAction;
  -> принимает runtime-решение: retry / skip / close candidate / ERROR / safety-flow.
```

Для reduce-only partial exit calculator-layer рассчитывает только параметры уменьшения позиции:

```text
closeFraction;
sizeContracts;
notional, если нужен для команды или аудита;
reference price;
ожидаемое направление уменьшения позиции.
```

Проверка, что partial exit действительно безопасен, выполняется handler'ом как safety / invariant checks, а не `RiskValidator`:

```text
action имеет reduce-only intent;
размер не превышает текущую позицию;
направление уменьшает позицию, а не увеличивает;
target относится к текущей Deal;
есть актуальные exchange facts;
recovery возможен через Order / AlgoOrder + DealActionState + fills/history/refresh.
```

Direct partial close через `StrategyPositionAction` считается ошибкой валидации стратегии и не должен доходить до runtime-расчёта.

Упрощённая политика:

```text
PRECHECK + BLOCKED + live risk ещё нет
  -> закрыть candidate Deal без ERROR

ENTRY_SUBMITTED / ENTRY_FINALIZED / PROTECTION_SWITCHED / MANAGING + BLOCKED
  -> Deal -> ERROR
  -> дальше ErrorHandler / safety-flow

reduce-only partial exit
  -> RiskValidator не вызывается
  -> handler выполняет safety / invariant checks

cleanup / safety commands
  -> RiskValidator не вызывается
  -> handler выполняет minimal domain / exchange safety checks

WARNING / неблокирующий риск
  -> не блокирует action
  -> фиксируется в логах / будущей истории исполнения
```

# 20. Ошибки расчёта

Ошибки расчёта должны быть согласованы с `StrategyStep.marketDataExpiredSetting`.

Если причина ошибки — expired/missing market data, FSM должна трактовать это как результат freshness-проверки step, а не как произвольную техническую ошибку калькулятора.

Если причина ошибки — невозможность безопасно рассчитать цену, размер или обязательные параметры action, это `CalculationError`.

Если price/size рассчитаны, но действие нарушает risk-policy или торговые invariants, это не `CalculationError`:

```text
risk-creating / risk-modifying action -> RiskValidator / RiskBlockResolver;
reduce-only partial exit -> safety / invariant checks handler'а;
cleanup / safety command -> minimal domain / exchange safety checks.
```


Калькуляторы должны возвращать controlled error/result или бросать контролируемое исключение, если:

* нет актуальной цены;
* нет `externalTickSize`;
* нет `externalLotSize`;
* нет `externalContractValue`;
* нет entry price;
* нет ATR для ATR-based SL;
* нет market structure для structure-based SL;
* нет range low/high для range placement;
* невозможно получить данные баланса, если они нужны для расчёта размера;
* невозможно округлить размер по lot size;
* невозможно привести размер к минимально допустимой торговой единице;
* цена стала невалидной после округления;
* невозможно рассчитать обязательные параметры action.

Нарушения risk-policy и exchange/domain invariants после успешного расчёта не должны маскироваться под `CalculationError`.


## 20.1. Controlled errors vs unexpected exceptions после Q8

`CalculationError` используется только для контролируемых ошибок расчёта.

Unexpected exceptions не превращаем в `CalculationError`.

Unexpected exception ловится на границе:

```text
DealOrchestratorJob / FSM execution boundary
```

Для unexpected exceptions используются 3 базовых кода:

```java
public enum RuntimeErrorCode {

  /** Баг приложения, NPE, mapper, неожиданное состояние, внутренняя техническая проблема. */
  INTERNAL_ERROR,

  /** Timeout, connection reset, gateway/API error, ошибка клиента биржи. */
  EXCHANGE_ERROR,

  /** Нарушение инварианта/валидации, которое не должно попасть в runtime. */
  VALIDATION_ERROR
}
```

Runtime-реакция:

```text
Deal -> ERROR
дальше ErrorHandler / safety-flow
```

Если ошибка связана с конкретным action:

```text
retryable EXCHANGE_ERROR
  -> DealActionState = RETRY_PENDING

INTERNAL_ERROR / VALIDATION_ERROR
  -> DealActionState = FAILED
```

`EXCHANGE_ERROR` используется вместо отдельных `UNKNOWN_RESULT` / `EXCHANGE_TIMEOUT`.

FSM не строит отдельную ветку по `EXCHANGE_ERROR`: каждый проход FSM сначала обновляет exchange facts через refresh/search/history, затем анализирует DealContext, DealActionState и runtime-сущности.

# 21. Связь с сервисными командами

`StrategyActionCalculator` не создаёт команды сам.

Он возвращает рассчитанные параметры.

`ServiceCommandFactory` на их базе создаёт команды.

Пример:

```text
StrategyOrderAction CREATE ENTRY
  -> StrategyActionCalculator
     -> price
     -> size
  -> handler / orchestration flow
     -> RiskValidator, если action требует risk-policy validation
  -> ServiceCommandFactory
     -> CREATE_ORDER
     -> SUBMIT_ORDER
```

Пример для OCO:

```text
StrategyAlgoOrderAction CREATE OCO_FULL
  -> StrategyActionCalculator
     -> SL price
     -> TP price
     -> close fraction
     -> size
  -> handler / orchestration flow
     -> RiskValidator, если action требует risk-policy validation
  -> ServiceCommandFactory
     -> CREATE_ALGO_ORDER
     -> SUBMIT_ALGO_ORDER
```


## 21.1. ServiceCommandFactory после Q4

После Q4 `ServiceCommandFactory` создаёт не всю цепочку команд заранее, а только одну актуальную команду на текущий момент.

Правило:

```text
один проход FSM / handler
  -> одна актуальная ServiceCommand для конкретного action,
     если именно она сейчас нужна по фактам
```

Пример:

```text
Если AlgoOrder ещё не создан локально:
  -> CREATE_ALGO_ORDER

Если AlgoOrder уже создан локально, но не отправлен:
  -> SUBMIT_ALGO_ORDER

Если AlgoOrder отправлен, но факт не подтверждён:
  -> REFRESH_ALGO_ORDER / REFRESH_ALGO_ORDERS
```

`CREATE_ALGO_ORDER -> SUBMIT_ALGO_ORDER -> REFRESH_ALGO_ORDER` остаётся логической цепочкой, но не обязана создаваться как список команд за один раз.

Причина:

```text
после каждой команды могут измениться runtime-сущности и exchange facts;
следующую команду безопаснее выбирать по свежему DealContext.
```

# Инвариант partial exit для калькуляторов

Калькуляторы не рассчитывают прямой partial close позиции.

```text
StrategyPositionAction -> только CLOSE_FULL
```

Для partial exit калькуляторы работают только с:

```text
StrategyOrderAction reduce-only
StrategyAlgoOrderAction partial TP / reduce-only
```

`SizeCalculator` считает размер в контрактах для уменьшения позиции.
Calculator-layer не возвращает risk-policy result и не возвращает risk metrics для partial exit.

Для reduce-only partial exit handler не вызывает `RiskValidator`, а проверяет только safety / invariant условия:

```text
reduce-only intent;
размер не превышает текущую позицию;
направление уменьшает позицию, а не увеличивает;
target относится к текущей Deal;
есть актуальные exchange facts;
recovery возможен через Order / AlgoOrder + DealActionState + fills/history/refresh.
```

Если partial exit невозможно безопасно посчитать, калькулятор должен вернуть controlled error/result.
Если partial exit рассчитан, но нарушает safety / invariant checks, handler не создаёт команду и переводит flow по правилам FSM / safety-flow.

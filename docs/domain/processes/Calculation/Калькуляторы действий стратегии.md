# 1. Главная идея

Калькуляторы действий стратегии отвечают за подготовку runtime-параметров для сервисных команд.

FSM выбирает допустимое действие стратегии, но не считает цену, размер и риск.

Executor исполняет команду, но не принимает торговых решений и не пересчитывает параметры.

Между ними находится `StrategyActionCalculator`.

```text
FSM / StateHandler
  -> выбрал StrategyAction
  -> StrategyActionCalculator
     -> собирает свежий CalculationContext
     -> PriceCalculator
     -> SizeCalculator
     -> RiskCalculator
  -> рассчитанные параметры
  -> ServiceCommandFactory
  -> ServiceCommand
```

Главное правило:

> `StrategyActionCalculator` получает `StrategyAction + DealContext`, сам собирает свежие данные для расчёта и возвращает готовые параметры команды.

# Зафиксированные решения lifecycle / FSM

В эту версию документа встроены решения Q1–Q4.

Для калькуляторов это означает:

* `StrategyActionCalculator` не должен рассчитывать data-dependent action, если FSM уже определила, что данные step устарели и `StrategyStep.marketDataExpiredSetting` запрещает выполнение.
* Свежесть готовых `IndicatorValue`, `MarketStructure`, `MarketPhase` проверяется через `MarketDataExpirationChecker`, описанный в `04. Расчёт индикаторов и рыночных данных`.
* `entryReason` и `entryStepType` не участвуют в формулах расчёта цены/размера/риска; это поля Deal для API/UI/аналитики/аудита.
* Условность `PROTECTION_SWITCHED` влияет только на то, будет ли вообще выбран action для protection-switch flow; сами формулы расчёта защиты не меняются.

# 2. Почему расчёт делается в runtime

Нельзя полностью полагаться на данные, собранные в `DealContext` заранее.

Причина:

```text
DealContext собрали
  -> FSM выбрала action
  -> выполняются команды
  -> проходит несколько секунд
  -> цена могла измениться
```

Поэтому перед формированием команды нужно иметь возможность собрать свежий `CalculationContext`:

* актуальную рыночную цену `MarketPriceData`;
* свежий bid / ask;
* актуальные внешние правила инструмента `InstrumentExternalRules`;
* актуальный ATR или другие готовые `IndicatorValue`;
* актуальные уровни структуры рынка `MarketStructure` / `MarketPriceLevel`;
* актуальную фазу рынка `MarketPhase`, если она нужна для условия;
* актуальный balance/risk snapshot, если действие требует risk-check.

Это особенно важно для:

* market-like entry;
* SL/TP;
* trailing;
* расчёта размера в контрактах;
* проверки риска перед отправкой order.

# 3. StrategyActionCalculator

`StrategyActionCalculator` — оркестратор расчёта параметров действия стратегии.

Он не является только калькулятором цены.

Он объединяет:

* `CalculationContextFactory`;
* `PriceCalculator`;
* `SizeCalculator`;
* `RiskCalculator`.

Рекомендуемый интерфейс:

```java
public interface StrategyActionCalculator {

    /**
     * Рассчитать runtime-параметры для выбранного действия стратегии.
     *
     * @param action действие стратегии, выбранное FSM
     * @param dealContext текущий контекст сделки
     * @return рассчитанные параметры для создания ServiceCommand
     */
    CalculatedStrategyAction calculate(
            StrategyAction action,
            DealContext dealContext
    );
}
```

Результат:

```java
public class CalculatedStrategyAction {

    /**
     * Исходное действие стратегии.
     */
    private StrategyAction sourceAction;

    /**
     * Рассчитанная цена или набор цен.
     */
    private CalculatedPrice calculatedPrice;

    /**
     * Рассчитанный размер order/algo/position action.
     */
    private CalculatedSize calculatedSize;

    /**
     * Результат проверки риска.
     */
    private RiskValidationResult riskValidationResult;

    /**
     * Пояснение для логов и аудита.
     */
    private String explanation;
}
```

# 4. CalculationContext

`CalculationContext` — рабочий runtime-контекст калькуляторов.

Он собирается внутри `StrategyActionCalculator`.

Он не заменяет `DealContext`.

Он строится из:

```text
DealContext
  + StrategyAction
  + свежие runtime-data
```

Пример модели:

```java
public class CalculationContext {

    /**
     * Сделка, для которой выполняется расчёт.
     */
    private Deal deal;

    /**
     * Инструмент сделки.
     */
    private Instrument instrument;

    /**
     * Pinned StrategyDetail сделки.
     */
    private StrategyDetail strategyDetail;

    /**
     * Действие стратегии, для которого считаются параметры.
     */
    private StrategyAction action;

    /**
     * Внешние правила инструмента: tick size, lot size, min size,
     * contract value, max leverage, state и другие биржевые ограничения.
     */
    private InstrumentExternalRules instrumentExternalRules;

    /**
     * Runtime-данные рыночных цен.
     *
     * Не хранятся в БД.
     * Получаются через REST ticker перед расчётом.
     */
    private MarketPriceData marketPriceData;

    /**
     * Готовые значения индикаторов, если они нужны для расчёта.
     *
     * Калькулятор их не считает, а получает через IndicatorService.
     */
    private List<IndicatorValue> indicatorValues;

    /**
     * Готовые структуры рынка, если они нужны для расчёта.
     *
     * Калькулятор их не считает, а получает через MarketStructureService.
     */
    private List<MarketStructure> marketStructures;

    /**
     * Актуальная фаза рынка, если она нужна для проверки условия или расчёта.
     */
    private MarketPhase marketPhase;

    /**
     * Контейнер баланса для расчёта размера и риска.
     */
    private BalanceContainer balanceContainer;

    /**
     * Активная позиция, если она уже открыта.
     */
    private Position activePosition;

    /**
     * Entry order, если он уже создан.
     */
    private Order entryOrder;

    /**
     * Состояние позиций по инструменту.
     */
    private PositionContext positionContext;

    /**
     * Настройки риска из StrategyDetail или глобальной risk policy.
     */
    private RiskSettings riskSettings;

    /**
     * Направление стратегии: LONG / SHORT.
     */
    private StrategyTradeDirection strategyDirection;
}
```

Важно:

> `CalculationContext` должен быть собран максимально близко ко времени создания команды.

# 5. Источники данных для CalculationContext

Перед сбором `CalculationContext` FSM уже должна проверить freshness конкретного `StrategyStep`.

Но `CalculationContextFactory` всё равно должен работать защитно:

```text
если обязательное готовое значение отсутствует;
если значение явно устарело;
если сервис рыночных данных не может вернуть актуальную цену;
```

то калькулятор должен вернуть controlled error/result или бросить контролируемое исключение, а не молча считать action по старым данным.


`StrategyActionCalculator` использует специальные сервисы:

```text
MarketPriceDataService
InstrumentExternalRulesService
IndicatorService
MarketStructureService
MarketPhaseService
BalanceService
RiskSettingsService
```

Пример:

```java
public class DefaultStrategyActionCalculator implements StrategyActionCalculator {

    private final CalculationContextFactory calculationContextFactory;
    private final PriceCalculator priceCalculator;
    private final SizeCalculator sizeCalculator;
    private final RiskCalculator riskCalculator;

    @Override
    public CalculatedStrategyAction calculate(StrategyAction action, DealContext dealContext) {
        CalculationContext context = calculationContextFactory.build(action, dealContext);

        CalculatedPrice price = priceCalculator.calculate(context);
        CalculatedSize size = sizeCalculator.calculate(context, price);
        RiskValidationResult risk = riskCalculator.validate(context, price, size);

        return new CalculatedStrategyAction(action, price, size, risk);
    }
}
```

## 5.1. Важное правило по тяжёлым данным

`StrategyActionCalculator` не считает тяжёлые данные сам.

Он только читает готовые результаты:

```text
IndicatorValue
MarketStructure
MarketPhase
InstrumentExternalRules
```

Тяжёлые расчёты выполняют:

```text
IndicatorJob
MarketStructureJob
MarketPhaseJob
InstrumentExternalRulesSyncJob
```

## 5.2. MarketPriceData — исключение

`MarketPriceData` не хранится в БД и не считается заранее.

Он нужен прямо перед расчётом.

Flow:

```text
Client model OKX ticker
  -> MarketPriceDataExternalSnapshot
  -> MarketPriceData
  -> CalculationContext
```

Кэш на первом этапе не используем.

Чтобы не плодить REST-запросы, правило такое:

> В рамках одного `CalculationContext` `MarketPriceData` получаем один раз и переиспользуем для всех расчётов этого context.

# 6. InstrumentExternalRules

`InstrumentExternalRules` — актуальные внешние правила инструмента от биржи.

Они нужны калькуляторам для:

* округления цены;
* округления размера;
* расчёта размера в контрактах;
* проверки `minSize` / max limits;
* проверки плеча;
* проверки, можно ли торговать инструмент.

Хранится в БД как актуальный snapshot правил инструмента.

Обновляется пока только через REST.

```java
public class InstrumentExternalRules extends Auditable {

    /** Технический ID записи. */
    private Long id;

    /** Внутренний ID инструмента в нашей системе. */
    private Long instrumentId;

    /** Нормализованный тип инструмента. */
    private InstrumentType instrumentType;

    /** Нормализованный тип контракта. */
    private ContractType contractType;

    /** Нормализованный статус инструмента. */
    private Status status;

    /** Тип инструмента на стороне биржи. */
    private String externalInstrumentType;

    /** ID инструмента на стороне биржи. */
    private String externalInstrumentId;

    /** Базовая валюта инструмента. */
    private String externalBaseCurrency;

    /** Котируемая валюта инструмента. */
    private String externalQuoteCurrency;

    /** Валюта расчёта / маржи. */
    private String externalSettleCurrency;

    /** Тип контракта на стороне биржи. */
    private String externalContractType;

    /** Размер одного контракта. */
    private String externalContractValue;

    /** Валюта, в которой задан размер контракта. */
    private String externalContractValueCurrency;

    /** Минимальный шаг цены. */
    private String externalTickSize;

    /** Шаг размера ордера. */
    private String externalLotSize;

    /** Минимальный размер ордера. */
    private String externalMinSize;

    /** Максимальный размер одного limit order. */
    private String externalMaxLimitSize;

    /** Максимальный размер одного market order. */
    private String externalMaxMarketSize;

    /** Максимальный размер trigger order. */
    private String externalMaxTriggerSize;

    /** Максимальный размер stop order. */
    private String externalMaxStopSize;

    /** Максимальное плечо, разрешённое биржей. */
    private String externalMaxLeverage;

    /** Состояние инструмента на стороне биржи. */
    private String externalState;

    public enum Status {
        LIVE,
        SUSPEND,
        PREOPEN,
        EXPIRED,
        TEST,
        UNKNOWN
    }
}
```

# 8. IndicatorValue для калькуляторов

Калькуляторы не считают индикаторы.

Они получают готовые `IndicatorValue` через `IndicatorService`.

```java
public abstract class IndicatorValue extends Auditable {

    /** Технический ID значения индикатора. */
    private Long id;

    /** Внутренний ID инструмента. */
    private Long instrumentId;

    /** Настройка стратегии, по которой было рассчитано значение. */
    private StrategyIndicatorSetting setting;

    /** Время свечи, на которой рассчитан индикатор. */
    private OffsetDateTime candleTimestamp;

    public enum Type {
        ATR,
        EMA,
        RSI,
        MACD,
        STOCHASTIC,
        BOLLINGER_BANDS,
        OBV
    }
}
```

Пример для ATR:

```java
public class AtrValue extends IndicatorValue {

    /** Значение ATR. */
    private BigDecimal atr;
}
```

Правила:

```text
confirmed не храним
warmup не храним
IndicatorJob сохраняет только значения после warmup-зоны
индикаторы считаются только по закрытым свечам
```

# 9. MarketStructure для калькуляторов

Калькуляторы не ищут уровни по свечам.

Они получают готовую `MarketStructure` через `MarketStructureService`.

```java
public class MarketStructure extends Auditable {

    /** Технический ID результата расчёта. */
    private Long id;

    /** Внутренний ID инструмента. */
    private Long instrumentId;

    /** Настройка стратегии, по которой была рассчитана структура. */
    private StrategyMarketStructureSetting setting;

    /** Тип структуры рынка. */
    private Type type;

    /** Начало окна свечей, по которому рассчитана структура. */
    private OffsetDateTime windowStartAt;

    /** Конец окна свечей, по которому рассчитана структура. */
    private OffsetDateTime windowEndAt;

    /** Свеча, на которой структура была подтверждена. */
    private OffsetDateTime confirmedAt;

    /** Ценовые уровни структуры. */
    private List<MarketPriceLevel> levels;

    public enum Type {
        RANGE,
        UPTREND,
        DOWNTREND,
        UNKNOWN
    }
}
```

`MarketStructure.Status` не нужен.

Актуальность проверяется через `MarketDataExpirationChecker` по:

```text
StrategyMarketStructureSetting.expirationDuration
MarketStructure.confirmedAt / windowEndAt
```

Подробности см. в документе `04. Расчёт индикаторов и рыночных данных`.

# 10. MarketPhase для калькуляторов

`MarketPhase` — результат расчёта фазы рынка.

Её считает `MarketPhaseJob`, а калькулятор только читает при необходимости.

```java
public class MarketPhase extends Auditable {

    /** Технический ID результата расчёта. */
    private Long id;

    /** Внутренний ID инструмента. */
    private Long instrumentId;

    /** Настройка стратегии, по которой была рассчитана фаза. */
    private StrategyMarketPhaseSetting setting;

    /** Тип рассчитанной фазы рынка. */
    private Type type;

    /** Время свечи, на которой рассчитана фаза. */
    private OffsetDateTime candleTimestamp;

    /** Время, с которого фазу можно использовать без look-ahead. */
    private OffsetDateTime confirmedAt;

    /** Уверенность алгоритма в выбранной фазе. */
    private BigDecimal confidenceScore;

    public enum Type {
        BULL_TREND,
        BEAR_TREND,
        RANGE,
        UNKNOWN
    }
}
```

`MarketPhase.Status` не нужен.

Если фаза стала неопределённой, сохраняется новый результат:

```text
MarketPhase.type = UNKNOWN
```

# 11. PriceCalculator

`PriceCalculator` отвечает только за расчёт цен.

Он не считает размер.

Он не проверяет полный риск сделки.

Он не решает, нужно ли выполнять action.

```java
public interface PriceCalculator {

    /**
     * Рассчитать цену или набор цен для выбранного action.
     */
    CalculatedPrice calculate(CalculationContext context);
}
```

# 16. Формулы PriceCalculator

## 16.1. Limit placement

```text
basePrice = resolveBasePrice(source)
offset = resolveOffset(basePrice, source, percents)

if offsetSide = ABOVE:
  rawPrice = basePrice + offset

if offsetSide = BELOW:
  rawPrice = basePrice - offset

roundedPrice = roundByTickSize(rawPrice)
```

Для обычной цены:

```text
offset = basePrice * percents / 100
```

Для диапазона:

```text
rangeWidth = rangeHigh - rangeLow
offset = rangeWidth * percents / 100
```

---

## 16.2. Stop-loss by entry percent

LONG:

```text
SL = entryPrice - entryPrice * distancePercents / 100
```

SHORT:

```text
SL = entryPrice + entryPrice * distancePercents / 100
```

---

## 16.3. Stop-loss by ATR

`distancePercents = 150` означает `1.5 ATR`.

LONG:

```text
SL = basePrice - ATR * distancePercents / 100
```

SHORT:

```text
SL = basePrice + ATR * distancePercents / 100
```

ATR берётся из `AtrValue`.

`PriceCalculator` не считает ATR по свечам.

---

## 16.4. Market structure stop-loss

LONG:

```text
structureBase = swingLow или rangeLow
buffer = structureBase * distancePercents / 100
SL = structureBase - buffer
```

SHORT:

```text
structureBase = swingHigh или rangeHigh
buffer = structureBase * distancePercents / 100
SL = structureBase + buffer
```

---

## 16.5. Take-profit

LONG:

```text
TP = entryPrice + entryPrice * triggerProfitPercents / 100
```

SHORT:

```text
TP = entryPrice - entryPrice * triggerProfitPercents / 100
```

---

## 16.6. Trailing activation

Если `activationProfitPercents = null`:

```text
activePrice = null
sendActivePrice = false
```

LONG:

```text
activePrice = entryPrice + entryPrice * activationProfitPercents / 100
```

Если есть `activationBufferPercents`:

```text
activePrice = activePrice + entryPrice * activationBufferPercents / 100
```

SHORT:

```text
activePrice = entryPrice - entryPrice * activationProfitPercents / 100
```

Если есть `activationBufferPercents`:

```text
activePrice = activePrice - entryPrice * activationBufferPercents / 100
```

# 17. Округление цены

Цена должна округляться по `InstrumentExternalRules.externalTickSize`.

Рекомендуемый enum:

```java
public enum PriceRoundingPolicy {

    /** Безопасное округление, которое не ухудшает смысл защитной цены. */
    CONSERVATIVE,

    /** Более агрессивное округление для повышения шанса исполнения. */
    AGGRESSIVE,

    /** Округление к ближайшему tick. */
    NEAREST
}
```

Первый этап:

```text
использовать CONSERVATIVE
```

Правила:

```text
LIMIT BUY conservative  -> вниз
LIMIT SELL conservative -> вверх
LONG SL                 -> вниз
SHORT SL                -> вверх
LONG TP                 -> вверх
SHORT TP                -> вниз
```

# 18. SizeCalculator

`SizeCalculator` отвечает за размер order/algo/position action.

Он не считает цену.

Он может использовать цену как входной параметр.

```java
public interface SizeCalculator {

    /**
     * Рассчитать размер в контрактах для выбранного action.
     */
    CalculatedSize calculate(
            CalculationContext context,
            CalculatedPrice calculatedPrice
    );
}
```

Результат:

```java
public class CalculatedSize {

    /** Размер в контрактах после округления по lot size. */
    private BigDecimal sizeContracts;

    /** Доля закрытия позиции от 0 до 1. */
    private BigDecimal closeFraction;

    /** Номинал позиции в USDT, если он рассчитывался. */
    private BigDecimal notionalUsdt;

    /** Пояснение расчёта. */

}
```

Для SWAP/FUTURES:

> `sz` в OKX API — это контракты, не USDT.

Общий расчёт для линейного контракта:

```text
baseQty = usdtNotional / price
contracts = baseQty / ctVal
contractsRounded = roundByLotSize(contracts)
```

Где:

* `ctVal` — `InstrumentExternalRules.externalContractValue`;
* `lotSz` — `InstrumentExternalRules.externalLotSize`;

# 19. RiskCalculator

`RiskCalculator` отвечает за проверку риска.

Он не исполняет команду.

Он не создаёт order.

Он отвечает на вопрос:

> Можно ли выполнить рассчитанное действие при текущем риске?

```java
public interface RiskCalculator {

    /**
     * Проверить рассчитанную цену и размер относительно risk policy.
     */
    RiskValidationResult validate(
            CalculationContext context,
            CalculatedPrice calculatedPrice,
            CalculatedSize calculatedSize
    );
}
```

Результат:

```java
public class RiskValidationResult {

    /** Можно ли выполнять действие. */
    private boolean allowed;

    /** Код причины отказа, если действие запрещено. */
    private String rejectCode;

    /** Человекочитаемое пояснение. */
    private String explanation;

    /** Расчётный риск в процентах депозита. */
    private BigDecimal riskPercent;

    /** Расчётное плечо. */
    private BigDecimal leverage;
}
```

Что проверяет:

* риск на сделку не выше лимита;
* плечо не выше разрешённого;
* плечо не выше лимита биржи из `InstrumentExternalRules`;
* isolated margin;
* торговля только своими средствами;
* нет borrow / debt признаков;
* размер не меньше `minSz`;
* размер соответствует `lotSz`;
* размер не выше max limits инструмента;
* SL стоит с правильной стороны;
* TP стоит с правильной стороны;
* SL не слишком близко к liquidation price;
* хватает баланса / доступной маржи.

# 20. Ошибки расчёта

Ошибки расчёта должны быть согласованы с `StrategyStep.marketDataExpiredSetting`.

Если причина ошибки — expired/missing market data, FSM должна трактовать это как результат freshness-проверки step, а не как произвольную техническую ошибку калькулятора.

Если причина ошибки — нарушение risk/instrument constraints, это уже результат `RiskCalculator` и может вести к `MARK_DEAL_ERROR`, graceful shutdown или kill-switch по правилам FSM.


Калькуляторы должны возвращать controlled error/result или бросать контролируемое исключение, если:

* нет актуальной цены;
* нет `externalTickSize`;
* нет `externalLotSize`;
* нет `externalContractValue`;
* нет entry price;
* нет ATR для ATR-based SL;
* нет market structure для structure-based SL;
* нет range low/high для range placement;
* не хватает баланса;
* расчётный размер меньше min size;
* цена стала невалидной после округления;
* риск выше лимита;
* обнаружен не-isolated режим;
* обнаружены признаки borrow/debt.

# 21. Связь с сервисными командами

`StrategyActionCalculator` не создаёт команды сам.

Он возвращает рассчитанные параметры.

`ServiceCommandFactory` на их базе создаёт команды.

Пример:

```text
StrategyOrderAction CREATE ENTRY
  -> StrategyActionCalculator
     -> price
     -> size
     -> risk allowed
  -> ServiceCommandFactory
     -> CREATE_ORDER
     -> SUBMIT_ORDER
```

Пример для OCO:

```text
StrategyAlgoOrderAction CREATE OCO_FULL
  -> StrategyActionCalculator
     -> SL price
     -> TP price
     -> close fraction
     -> size
     -> risk allowed
  -> ServiceCommandFactory
     -> CREATE_ALGO_ORDER
     -> SUBMIT_ALGO_ORDER
```

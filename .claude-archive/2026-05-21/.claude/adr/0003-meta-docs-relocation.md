# ADR-0003: Разделение продуктовой документации и работы с Claude

## Status

Accepted — 2026-05-15

## Context

К моменту настоящего ADR в репозитории сложилась смешанная структура:
meta-документация про работу с Claude (`working-with-claude.md`, `playbook.md`,
`project-instructions.md`, `pipeline-evolution-log.md`) лежит в `docs/`
рядом с продуктовой документацией (модели, API, спеки, конвенции).

То же касается рабочих артефактов: ADR смешаны (продуктовые и пайплайновые
в одном каталоге), backlog содержит и продуктовые задачи (миграция
RestTemplate → RestClient, ADR-кандидаты про reconcile), и пайплайновые
(создать скилл, доработать агента). Папка `.claude/` сейчас содержит только
`agents/` и `skills/`.

Граница между «документацией продукта» и «документацией работы над проектом»
размыта. Структура репозитория не самообъясняется: новому читателю
непонятно, по какому принципу `playbook.md` лежит в `docs/`, а `agents/` —
в `.claude/`.

Решение должно быть принято **до начала массовой миграции
`docs/domain/processes/` в `docs/spec/`** — иначе образуется большое
количество ссылок, которые придётся обновлять при последующем переезде.

## Decision

Вводится **семантическое разделение двух папок верхнего уровня**:

- **`docs/`** — продуктовая документация: описание системы (модели, API,
  конвенции, спеки, термины, операционные заметки про продукт). Это
  «результат»: что бот собой представляет.

- **`.claude/`** — всё, что связано с работой над проектом через Claude:
  рабочие артефакты (ADR, backlog), процесс работы (playbook,
  working-with-claude, pipeline-evolution-log), конфигурация для Claude
  (project-instructions, agents, skills), исторические снимки стратегии.

Критерий разделения — **природа артефакта**, не тема его содержания.
ADR-0001 (про reconcile в торговом боте) лежит в `.claude/adr/`, потому
что ADR — это **рабочий артефакт фиксации решения**, даже если решение
содержательно про продукт. Последствия решения — изменения в `docs/spec/`,
там и лежат содержательные описания.

### Структура `.claude/`

```
.claude/
├── working-with-claude.md         # концепция работы
├── project-instructions.md        # резерв Custom Instructions для claude.ai
├── pipeline-evolution-log.md      # история пайплайна
├── agents/                        # system prompts субагентов
├── skills/                        # переиспользуемые знания и процедуры
├── adr/                           # все Architecture Decision Records проекта
├── flow/                          # операционные процедуры (playbook)
├── planning/                      # рабочие планы (backlog)
├── strategy-summary/              # версионированные снимки стратегии
└── notes/                         # журналы наблюдений (создаётся при появлении)
```

**Принцип расположения:**

| Уровень | Содержимое |
|---|---|
| `.claude/<имя>.md` (корень) | Опорные документы, которые читаются часто и напрямую |
| `.claude/<подпапка>/` | Группировка по жанру (agents, skills, adr, flow, planning, strategy-summary, notes) |

Подпапки добавляются по факту появления соответствующих артефактов.

### Переезд конкретных файлов

| Старый путь | Новый путь |
|---|---|
| `docs/working-with-claude.md` | `.claude/working-with-claude.md` |
| `docs/playbook.md` | `.claude/flow/playbook.md` |
| `docs/project-instructions.md` | `.claude/project-instructions.md` |
| `docs/pipeline-evolution-log.md` | `.claude/pipeline-evolution-log.md` |
| `docs/planning/backlog.md` | `.claude/planning/backlog.md` |
| `docs/adr/README.md` | `.claude/adr/README.md` (с расширенным алгоритмом) |
| `docs/adr/0000-template.md` | `.claude/adr/0000-template.md` |
| `docs/adr/0001-reconcile-via-anomaly-report.md` | `.claude/adr/0001-reconcile-via-anomaly-report.md` |
| `docs/adr/0002-spec-document-standard.md` | `.claude/adr/0002-spec-document-standard.md` |
| `docs/setup-strategy-summary.md` | `.claude/strategy-summary/strategy-summary-v1.md` (переименование + переезд) |

`docs/adr/` после переезда **не создаётся**. Указание места ADR — в
`CLAUDE.md` и `docs/README.md`.

`docs/planning/` остаётся (там продолжают жить долгосрочные планы и вехи),
backlog весь в `.claude/`.

### Принцип «один общий backlog»

Backlog **не разделяется** на продуктовый и пайплайновый. Это **рабочий
список задач, который ведётся вместе с Claude** — независимо от того, к
какому жанру относится результат каждой задачи. При выполнении задачи
изменения вносятся туда, где они должны быть по существу — в `docs/`, в
`.claude/`, в коде. Место **задачи** не определяет место **результата**.

### Принцип «все ADR в одном месте»

ADR **не разделяются** по жанру решения. ADR — это **рабочий артефакт
фиксации решения с альтернативами**. Все ADR проекта лежат в
`.claude/adr/` независимо от содержания (продуктовое решение или
пайплайновое).

### Версионированные снимки (новый паттерн)

Документы класса «снимок состояния проекта на момент времени» (типа
`strategy-summary`) **не редактируются задним числом**. Эволюция —
через **новые версии** в виде отдельных файлов.

**Правила паттерна:**

1. Файлы именуются с явной версией: `<base-name>-v1.md`, `<base-name>-v2.md` и т.д.
2. Все версии живут в одной подпапке (например, `.claude/strategy-summary/`).
3. Содержание принятой версии **не редактируется**.
4. Физические операции (переименование файла, перемещение, изменение
   расширения) — допустимы и не считаются редактированием. Это
   техническая оболочка, не содержание.
5. Новая версия в шапке ссылается на предыдущую и поясняет, что
   изменилось в целом, без переписывания тела.

В рамках настоящего ADR:
- `docs/setup-strategy-summary.md` (v1) переименовывается и переезжает
  в `.claude/strategy-summary/strategy-summary-v1.md`. Содержание не
  редактируется.
- Создаётся `.claude/strategy-summary/strategy-summary-v2.md` —
  актуальный снимок на 2026-05-15 (после переезда).

### Расширение алгоритма работы с ADR

В `.claude/adr/README.md` добавляется раздел с детальным алгоритмом:

**Принцип append-only:** принятый ADR — снимок решения на момент принятия.
Содержание не редактируется задним числом.

**Что считается редактированием (запрещено):**
- Изменение Decision, Context, Alternatives, Consequences по существу.
- Обновление технических ссылок на пути файлов при переезде целевых файлов.

**Что НЕ считается редактированием (разрешено):**
- Изменение Status (Proposed → Accepted, Accepted → Superseded by N, и т.д.).
- Исправление опечаток без изменения смысла.
- Физическое перемещение/переименование файла (содержание не меняется).
- Добавление примечаний в строго определённый блок (см. ниже).

**Два типа примечаний:**

1. **Технические примечания** — разрешены в любом статусе. Формат:
   фиксированный блок в конце документа.

   ```
   ## Примечания

   ### Технические
   - [YYYY-MM-DD] Файлы, на которые ссылается этот ADR, частично
     переехали (см. ADR-NNNN). Актуальные пути — в CLAUDE.md.
   ```

   Назначение: навигационные / ссылочные пометки, не меняющие
   решение. Каждая запись датируется и не редактируется после
   добавления (append-only внутри append-only).

2. **Содержательные примечания** — разрешены **только** в статусах
   Superseded и Deprecated. Назначение: ретроспективные комментарии
   после того, как решение устарело. «Почему пришлось пересматривать»,
   «что не учли», «какой опыт получили».

   ```
   ### Содержательные
   - [YYYY-MM-DD] Решение пересмотрено в ADR-NNNN. Главный фактор —
     не учли X.
   ```

   Также append-only, датированы. Не отменяют само решение —
   комментируют задним числом.

**Битые ссылки после переезда целевых файлов:** ссылки внутри принятого
ADR не обновляются. Они остаются как есть — это часть исторического
контекста. Читатель ориентируется по CLAUDE.md и `docs/README.md` для
актуальных путей. Опционально — техническое примечание с указанием на
переезд.

**При крупных рефакторингах:**
1. ADR переезжают физически согласно решению из ADR о рефакторинге.
2. Тела ADR не редактируются.
3. В блок «Технические примечания» добавляется запись со ссылкой на
   ADR о рефакторинге.
4. ADR о рефакторинге в Consequences явно перечисляет все ADR,
   которых коснулся переезд.

### Применение алгоритма к ADR-0001 и ADR-0002 в рамках этого ADR

Оба ADR переезжают в `.claude/adr/` без изменения содержания. В конец
каждого добавляется блок «Технические примечания» с записью:

```
## Примечания

### Технические
- [2026-05-15] Принят ADR-0003. Файлы, на которые ссылается этот ADR,
  частично переехали из `docs/` в `.claude/`. Актуальные пути —
  в CLAUDE.md.
```

Это техническое примечание, разрешённое в Accepted статусе.

## Alternatives

### Альтернатива 1 — оставить всё в `docs/` (статус-кво)

Не менять структуру. Meta-документация остаётся в `docs/`, ADR в
`docs/adr/`, backlog в `docs/planning/`.

**Отклонено**: смешение жанров в `docs/` сохраняется. Структура не
самообъясняется. Проблема, поднявшая ADR, не решается.

### Альтернатива 2 — Модель А (разделение по домену содержания)

`docs/` содержит документацию продукта; `.claude/` содержит документы,
**содержательно** про работу с Claude. ADR-0001 (про reconcile продукта)
остаётся в `docs/adr/`, ADR-0002 (про стандарт документа) переезжает в
`.claude/adr/`. Backlog разделяется: продуктовые задачи в `docs/`,
пайплайновые в `.claude/`.

**Отклонено**: создаёт постоянный пограничный вопрос «к какому домену
относится этот артефакт?». ADR на стыке (типа ADR-0002) — отдельная
головная боль. Двойная нумерация ADR или коллизии имён. Дисциплина
классификации каждой задачи в backlog. Дороже в долгой перспективе.

### Альтернатива 3 — отдельная папка `meta/` в корне

`meta/` для документации про работу над проектом, `.claude/` остаётся
только для инструментальных артефактов (agents, skills).

**Отклонено**: добавляет ещё одну папку верхнего уровня. Между `meta/`
и `.claude/` всё равно нужно проводить грань (notes/ — это `meta/` или
`.claude/`?). Не упрощает структуру существенно по сравнению с
объединением в `.claude/`.

### Альтернатива 4 — подпапка `.claude/docs/`

Гибрид: всё meta-про-Claude уходит в `.claude/docs/`, корень `.claude/`
остаётся для инструментального.

**Отклонено**: не даёт значимых плюсов по сравнению с группировкой по
жанру внутри `.claude/` (через подпапки `flow/`, `planning/`, `adr/`,
`notes/`). Семантика `.claude/docs/` неочевидна.

## Consequences

### Изменения в файловой структуре

**Создаются новые папки в `.claude/`:**
- `.claude/adr/`
- `.claude/flow/`
- `.claude/planning/`
- `.claude/strategy-summary/`

**Переезжают файлы (10 файлов):** см. таблицу в разделе Decision.

**Создаётся новый файл:**
- `.claude/strategy-summary/strategy-summary-v2.md` — актуальный снимок
  стратегии на 2026-05-15.

**Не создаются:**
- `.claude/notes/` — отложено до появления первого артефакта (журнала
  наблюдений).
- `docs/adr/` после переезда — не воссоздаётся.

### Изменения в документации

**`CLAUDE.md`** — обновление путей ко всем переехавшим файлам;
переработка раздела Repository layout; добавление параграфа про
разделение `docs/` vs `.claude/`; обновление пути к ADR в Source of
truth hierarchy.

**`docs/README.md`** — удаление упоминаний переехавших meta-файлов;
добавление указания места ADR (`.claude/adr/`); раздел «Работа с Claude»
заменяется на короткое перенаправление.

**`.claude/adr/README.md`** — содержание расширяется детальным
алгоритмом работы с ADR (см. раздел в Decision).

**`.claude/adr/0001-reconcile-via-anomaly-report.md`** и
**`.claude/adr/0002-spec-document-standard.md`** — после переезда
добавляется блок «Технические примечания» (см. выше).

**`.claude/agents/knowledge-curator.md`** — обновляются ссылки на
`pipeline-evolution-log.md` и `backlog.md`.

**`.claude/skills/spec-document-workflow/SKILL.md`** — обновляются
ссылки на playbook и backlog.

**`.claude/planning/backlog.md`** — пункт «ADR-0003 (?): разделение
документации проекта vs пайплайна работы с Claude» перемещается в раздел
«Закрытые» с датой и ссылкой на этот ADR. Пункт «ADR-0003 (?): Каталог
аномалий» переномеровывается на **ADR-0004**.

**`.claude/pipeline-evolution-log.md`** — добавляется запись о принятии
ADR-0003 и проведённом переезде.

### setup-strategy-summary

`docs/setup-strategy-summary.md` переезжает в
`.claude/strategy-summary/strategy-summary-v1.md` с переименованием.
Содержание не редактируется. Этот переезд — техническая операция в
рамках паттерна «версионированные снимки».

Создаётся `.claude/strategy-summary/strategy-summary-v2.md` —
актуальный снимок стратегии работы на 2026-05-15 с учётом принятых
ADR-0001, ADR-0002, ADR-0003.

### Project Knowledge в claude.ai

Требуется ручное обновление после коммита:
- Удалить старые прикрепления (`docs/working-with-claude.md`,
  `docs/playbook.md`, `docs/adr/README.md`).
- Загрузить новые (`.claude/working-with-claude.md`,
  `.claude/flow/playbook.md`, `.claude/adr/README.md`).
- Обновить прикрепления `CLAUDE.md` и `docs/README.md` (пути не
  поменялись, но содержание — да).
- Обновить **Custom Instructions** Проекта из нового
  `.claude/project-instructions.md`.

### Затронутые внешние ссылки

Все ссылки в репозитории на старые пути переехавших файлов обновляются
в одной волне. Затронуты как минимум:
- `CLAUDE.md`
- `docs/README.md`
- `.claude/agents/knowledge-curator.md`
- `.claude/skills/spec-document-workflow/SKILL.md`
- Взаимные ссылки между переезжающими файлами

**Исключение — принятые ADR-0001 и ADR-0002**: согласно принципу
append-only ссылки внутри их тел не обновляются. Вместо этого
добавляются «Технические примечания» (см. выше).

**Исключение — setup-strategy-summary-v1**: содержание не редактируется.
Ссылки внутри документа остаются с устаревшими путями. Документ —
исторический снимок 2026-05-14.

### Долгосрочные последствия

- Будущему читателю проекта (новому разработчику) ADR находятся в
  нестандартном месте (`.claude/adr/` вместо классического `docs/adr/`).
  Это компенсируется явным указанием в `CLAUDE.md` и `docs/README.md`.
- Введён новый паттерн «версионированные снимки», применимый к будущим
  документам того же жанра.
- Закреплены детальные правила работы с ADR (два типа примечаний,
  алгоритм при рефакторингах), которых раньше не было.

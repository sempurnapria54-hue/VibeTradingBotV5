# ADR-0004: Расположение шаблонов spec-документов

## Status

Accepted — 2026-05-15

## Context

ADR-0002 (Стандарт документа `docs/spec/`) зафиксировал расположение
шаблонов spec-документов в `docs/spec/_templates/`. Это решение
принималось до ADR-0003.

ADR-0003 (Разделение продуктовой документации и работы с Claude)
ввёл принцип: критерий разделения `docs/` и `.claude/` — природа
артефакта, не тема его содержания. `docs/` — продуктовая
документация (что бот собой представляет). `.claude/` — рабочие
артефакты, процесс, конфигурация для Claude.

Шаблоны spec-документов — это **инструмент создания** продуктовой
документации, а не сама продуктовая документация:

- Их читает не пользователь документации, а тот, кто документ создаёт
  (человек или Claude через скилл `spec-document-workflow`).
- Они не описывают систему — они описывают, как описывать систему.
- Контроль соблюдения стандарта (ADR-0002, §7) использует их как
  механизм уровня 1.

По принципу ADR-0003 шаблоны должны жить в `.claude/`. На момент
принятия ADR-0002 этот принцип не был сформулирован, поэтому шаблоны
оказались в `docs/spec/_templates/`.

Прецедент: шаблон ADR (`0000-template.md`) лежит в `.claude/adr/`,
не в `docs/`. Расположение шаблонов spec-документов в `docs/` —
расхождение с этим прецедентом.

Решение должно быть принято до начала массовой миграции
`docs/domain/processes/` в `docs/spec/` — после миграции количество
ссылок на шаблоны вырастет, переезд станет дороже.

## Decision

Шаблоны spec-документов переезжают из `docs/spec/_templates/` в
`.claude/templates/documents/`. Папка `docs/spec/_templates/`
удаляется целиком (чистый перенос).

### Структура `.claude/templates/`

```
.claude/templates/
├── README.md                       # навигационный реестр шаблонов
└── documents/                      # шаблоны документов
    ├── model.md                    # шаблон для docs/spec/models/<Name>.md
    ├── lifecycle.md                # шаблон для docs/spec/lifecycle/<Name>.md
    ├── process.md                  # шаблон для docs/spec/processes/<Name>.md
    ├── integration-mapping.md      # шаблон для docs/spec/integrations/<exchange>/<name>.md
    ├── reference.md                # шаблон для docs/spec/references/<name>.md
    └── invariant.md                # шаблон для docs/spec/invariants/<name>.md
```

### Принципы именования

- **Корневая папка `.claude/templates/`** — шаблоны (всех видов).
- **Подпапка `documents/`** — шаблоны документов. Сейчас все шаблоны
  относятся к этой категории. Если в будущем появятся шаблоны иного
  назначения (например, `prompts/`, `workflows/`), они получат свои
  подпапки рядом.
- **Плоская структура внутри `documents/`** — шесть файлов без
  дополнительной вложенности.
- **Имена файлов — по типу описываемого объекта**, латиница,
  расширение `.md`. Без префикса/суффикса `template` — это понятно
  из пути `.claude/templates/`.
- **README в `.claude/templates/`**, не глубже. Навигационная точка
  на входе. Содержит список шаблонов с одной-двумя строками описания
  «когда этот шаблон» и ссылкой на ADR-0002, §1 для полной
  спецификации категорий.

### Связь с ADR-0002

Положения ADR-0002 о стандарте документа `docs/spec/` (жанры, правило
атомарности, эволюция, терминология, стиль, техника, контроль
соблюдения) **действуют без изменений**. ADR-0004 уточняет одну деталь
Consequences ADR-0002 — физическое расположение шаблонов.

ADR-0002 остаётся в статусе Accepted. В блок «Технические примечания»
ADR-0002 добавляется запись о переезде согласно правилам работы с ADR
(см. `.claude/adr/README.md`). Новый тип отношений между ADR не
вводится — существующие правила (техническое примечание, описанное в
ADR-0003) покрывают ситуацию.

## Alternatives

### Альтернатива 1 — оставить шаблоны в `docs/spec/_templates/`

Не переносить. ADR-0002 действует в том виде, в котором был принят.

**Отклонено**: расходится с принципом ADR-0003 (природа артефакта —
инструмент работы Claude, не продуктовая документация). Создаёт
постоянный пример «исключения из правила» — при работе с шаблонами
читатель видит их в `docs/`, что противоречит общему правилу.
Прецедент с шаблоном ADR в `.claude/adr/` теряет универсальность.

### Альтернатива 2 — `.claude/templates/spec/` вместо `documents/`

Корневая подпапка зеркалит структуру `docs/spec/`.

**Отклонено**: сейчас в `templates/` нет других категорий, и
название `spec/` сужает смысл артефактов. Если завтра появятся
шаблоны иного назначения, придётся вводить ещё одну подпапку.
Название `documents/` — точное описание содержания (шаблоны
документов), расширяемое в будущем.

### Альтернатива 3 — с подпапками по жанрам внутри `documents/`

Зеркалить структуру `docs/spec/` точно: шесть подпапок (`models/`,
`lifecycle/`, ...), в каждой `template.md`.

**Отклонено**: шесть файлов в одной плоской папке — нормальная
навигационная нагрузка. Подпапки добавляют шаг навигации без выигрыша
в семантике. Имя `model.md` в плоской структуре читается так же
ясно, как `models/template.md` в иерархической, и короче в ссылках
из скилла и playbook.

### Альтернатива 4 — расширить алгоритм работы с ADR (ввести «Refined by»)

Ввести новый тип отношений между ADR для случаев частичного пересмотра.

**Отклонено**: существующие правила (`.claude/adr/README.md`,
раздел «Битые ссылки после переезда целевых файлов») уже описывают
ситуацию — техническое примечание в исходный ADR, новый ADR
фиксирует решение. Новый тип отношений вводится без наблюдённой
потребности — лишняя сущность. Если в будущем накопится несколько
подобных кейсов, и появится практическая необходимость в отдельной
маркировке — это будет основанием для отдельного ADR с обоснованием.

## Consequences

### Изменения в файловой структуре

**Создаётся:**
- `.claude/templates/` — корневая папка под шаблоны.
- `.claude/templates/README.md` — навигационный реестр.
- `.claude/templates/documents/` — шаблоны документов.
- Шесть файлов внутри `documents/`: `model.md`, `lifecycle.md`,
  `process.md`, `integration-mapping.md`, `reference.md`,
  `invariant.md`.

**Переезжают (с переименованием) физически:**

| Старый путь | Новый путь |
|---|---|
| `docs/spec/_templates/<имя для models>` | `.claude/templates/documents/model.md` |
| `docs/spec/_templates/<имя для lifecycle>` | `.claude/templates/documents/lifecycle.md` |
| `docs/spec/_templates/<имя для processes>` | `.claude/templates/documents/process.md` |
| `docs/spec/_templates/<имя для integrations>` | `.claude/templates/documents/integration-mapping.md` |
| `docs/spec/_templates/<имя для references>` | `.claude/templates/documents/reference.md` |
| `docs/spec/_templates/<имя для invariants>` | `.claude/templates/documents/invariant.md` |

Точное соответствие старых имён новым устанавливается по содержимому
файлов при переносе.

**Удаляется:**
- `docs/spec/_templates/` — целиком, после переноса. Никаких маркеров
  `[MIGRATED]` — шаблоны не имеют внешних ссылок «извне» репозитория,
  это внутренний инструмент.

### Изменения в документации

**`.claude/adr/0002-spec-document-standard.md`** — добавляется
запись в блок «Технические примечания».

**`.claude/adr/README.md`** — индекс пополняется строкой ADR-0004.

**`CLAUDE.md`** — раздел Repository layout: добавляется
`.claude/templates/` в схему `.claude/`. Любые упоминания
`docs/spec/_templates/` убираются или заменяются на новый путь.

**`docs/README.md`** — упоминания `docs/spec/_templates/` (если есть)
убираются.

**`.claude/working-with-claude.md`** — раздел «Поэтапная миграция
документации» содержит ссылку на `docs/spec/_templates/`. Заменяется
на `.claude/templates/documents/` с пояснением, что шаблоны
переехали по ADR-0004.

**`.claude/flow/playbook.md`** — Сценарий 7 ссылается на
`docs/spec/_templates/<жанр>.md`. Заменяется на
`.claude/templates/documents/<имя>.md` с учётом новой схемы именования.

**`.claude/skills/spec-document-workflow/SKILL.md`** — ссылки на
шаблоны обновляются на новые пути.

**`.claude/planning/backlog.md`** — добавляется пункт в «Закрытые».

**`.claude/pipeline-evolution-log.md`** — добавляется запись о
принятии ADR-0004 и проведённом переезде.

**`.claude/strategy-summary/strategy-summary-v2.md`** — **не
редактируется** (правило версионированных снимков из ADR-0003).
Появление ADR-0004 как нового события зафиксируется в следующем
снимке `strategy-summary-v3.md`, когда он будет создан.

### Project Knowledge в claude.ai

Затронуты прикреплённые файлы:

- `CLAUDE.md` — обновляется в PK.
- `.claude/working-with-claude.md` — обновляется в PK.
- `.claude/flow/playbook.md` — обновляется в PK.
- `.claude/adr/README.md` — обновляется в PK.

Состав PK не меняется. Содержание четырёх файлов меняется — PK
обновляется вручную после коммита.

### Долгосрочные последствия

- Закреплён прецедент применения правил работы с ADR (техническое
  примечание + новый ADR) для случаев частичного пересмотра ADR.
- Папка `.claude/templates/` создана как точка для будущих
  категорий шаблонов (если возникнут — `prompts/`, `workflows/` и т.п.).
- Прецедент `0000-template.md` (шаблон ADR в `.claude/adr/`)
  остаётся отдельным паттерном — шаблон лежит рядом с экземплярами.
  Альтернативно его можно было бы перенести в
  `.claude/templates/adr/0000-template.md`, но это выходит за scope
  настоящего ADR и может быть рассмотрено отдельно при необходимости.

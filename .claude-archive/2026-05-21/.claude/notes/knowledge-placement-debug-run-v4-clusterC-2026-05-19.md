### Фрагмент 4 full: Knowledge capture rules — распределённая ответственность всех агентов

**Источник:** `.claude/working-with-claude.md`, раздел «Knowledge
capture rules». v3-full отчёт, раздел «Фрагмент 4».

**Цитата:**

> «В системные промпты **всех** агентов вшита инструкция: при
> принятии решения или обнаружении паттерна — предложить, где его
> задокументировать. Это распределённая ответственность, не
> только Curator.»

**Результат применения скилла v4:**

```
Классификация:
- Измерение: PIPELINE
- Основные категории: L-CONV PIPELINE + L-AGENT
  (Шаг 1(в): правило (что должно быть в промпте каждого агента)
  — L-CONV PIPELINE; влияние на содержание самих агентов
  — L-AGENT.)
- Основной вопрос:
  - L-CONV PIPELINE: «что должно быть в промпте каждого агента
    как минимально обязательная часть?»
- Тег: precedent (правило-шаблон для жанра L-AGENT).

Место хранения:
- Целевой файл (L-CONV PIPELINE): сейчас раздел в working-with-
  claude. Кандидат на `.claude/conventions/agent-template.md`.
- Влияние: каждый L-AGENT файл должен включать секцию «Knowledge
  capture»; уже наблюдается в architect.md, domain-expert.md,
  risk-engineer.md, trading-risk-officer.md, knowledge-curator.md.
- Промежуточное хранение: текущее место.

Связные обновления:
- Все агенты (5 файлов) содержат «Knowledge capture» секцию,
  применяя это правило. Если правило меняется — править все
  5 файлов.
- Конфликт с существующим ADR (Шаг 3(ж)): нет.

Паттерн-конфликт (Шаг 3(ж') сработал):
- Подвид: тиражирование (β)
- Артефакты, где правило фигурирует: `.claude/working-with-claude.md`
  (формулировка правила), `.claude/agents/architect.md`,
  `.claude/agents/domain-expert.md`, `.claude/agents/risk-engineer.md`,
  `.claude/agents/trading-risk-officer.md`,
  `.claude/agents/knowledge-curator.md` (применение в каждой
  секции «Knowledge capture»).
- Тип повтора: переформулировка (общая норма в working-with-claude
  + конкретизированные секции в каждом агенте).
- Источник, который должен быть единственным (по Принципу 7):
  единый L-CONV `.claude/conventions/agent-template.md`
  или раздел в working-with-claude как источник нормы; секции
  в агентах — частное применение со ссылкой.
- Решение: править структуру (вынести в источник + ссылки) —
  предпочтительный вариант. Альтернатива: оставить дубли с
  обязательством sync, если шаблон агента (M-FORM) не вводится.
  Развилка системная — связана с (е)/(д) Шага 2.

Развилка конвенции (Шаг 2(ж)):
- Категория классифицирована: L-CONV PIPELINE («что должно
  быть в каждом агенте»).
- Конвенция размещения для случая «правило-шаблон для жанра
  L-AGENT» отсутствует. Нет ни единого M-FORM (шаблон агента),
  ни L-CONV (правило о структуре).
- Варианты решения конвенции:
  (а) `.claude/templates/documents/agent.md` — шаблон агента;
  (б) `.claude/conventions/agent-structure.md` — convention;
  (в) раздел в working-with-claude (как сейчас).
```

**Сравнение с v3:**
- Что изменилось: Шаг 3(ж') сработал, подвид (β). Поле
  «Паттерн-конфликт» заполнено содержательно — перечислены 6
  артефактов (working-with-claude + 5 агентов), тип повтора
  «переформулировка», предложен единственный источник по
  Принципу 7. v3-full фиксировал «структура жанра без места»,
  но не паттерн-конфликт явно.
- Адресует ли правка v4 буксование: да. v3-full сигнал был
  «правило структуры жанра, для которого нет специального места»
  — это **частный случай** β (правило живёт в одном месте-норме
  + N-местах-применений). v4 явно подсвечивает паттерн.
- Побочные эффекты: фрагмент пересекается с Шагом 2(ж) (развилка
  конвенции про шаблон агента). Это не противоречие — паттерн-
  конфликт (β) и развилка конвенции (M-FORM не введён)
  усиливают друг друга, оба фиксируются параллельно.

```
Классификация:
- Измерение: PIPELINE (правило применения реестра)
- Основные категории: L-CONV PIPELINE + L-ADR
  (Шаг 1(б): обоснование «реестр — отражение» с альтернативой
  «реестр — гейт» → L-ADR; правило применения → L-CONV.)
- Основной вопрос:
  - L-ADR: «почему MODELS.md — отражение созданных документов,
    а не гейт?»
- Тег: precedent (паттерн «реестр vs гейт» применим ко всем
  будущим реестрам пайплайна).

Место хранения:
- Целевой файл (L-ADR): уже в ADR-0008 §2/§4 (классификация

Связные обновления:

Паттерн-конфликт (Шаг 3(ж') сработал):

  теста.

### Фрагмент 14 full: «Целевые spec-документы в трекере не предзаявляются»

**Источник:** `.claude/planning/migration-tracker.md` строка 14;
ADR-0009 (стратегия миграции) частично. v3-full отчёт, раздел
«Фрагмент 14».

**Цитата:**

> «Целевые spec-документы в трекере не предзаявляются. Они
> перечисляются по факту создания — при миграции
> соответствующего legacy-документа.»

**Результат применения скилла v4:**

```
Классификация:
- Измерение: PIPELINE
- Основные категории: L-CONV PIPELINE + L-ADR
  (Шаг 1(б): обоснование «не предзаявлять, чтобы избежать
  дрейфа» с альтернативой → L-ADR; правило «по факту создания»
  → L-CONV.)
- Основной вопрос:
  - L-ADR: «почему трекер не предзаявляет целевые документы?»
- Тег: precedent (паттерн «реестр — отражение, не план»
  применим ко всем реестрам и трекерам — см. фрагмент 8).

Место хранения:
- Целевой файл (L-ADR): ADR-0009 (стратегия миграции) частично.
- Целевой файл (L-CONV PIPELINE): шапка
  `.claude/planning/migration-tracker.md`.
- Промежуточное хранение: не нужно.

Связные обновления:
- Скилл `spec-cluster-migration` — финализация кластера
  обновляет трекер по факту.
- Конфликт (Шаг 3(ж)): нет.

Паттерн-конфликт (Шаг 3(ж') сработал):
- Подвид: тиражирование (β)
- Артефакты, где правило фигурирует:
  `.claude/planning/migration-tracker.md` (шапка),
  ADR-0009 (обоснование).
- Тип повтора: переформулировка (правило в шапке трекера —
  операционная формула; в ADR-0009 — обоснование с альтернативой).
- Источник, который должен быть единственным (по Принципу 7):
  ADR-0009 как обоснование; шапка трекера — операционная
  ссылка на ADR. Согласованное распределение (ADR — почему,
  трекер — что делать).
- Решение: оставить как есть (согласованный дубль —
  разновидность β); формулировки различаются по роли, правка
  одного места без правки другого не имеет смысла.

Метапаттерн (отметка, не часть Шага 3(ж')):
- Фрагмент 14 + фрагмент 8 — два разных правила, но один
  глубинный паттерн «реестр — отражение, не гейт/план». Это
  не β-тиражирование одного правила, а **повтор паттерна
  на разных реестрах**. Сейчас v4 не различает «одно правило
  в N местах» (β) и «один паттерн применён к N разным
  правилам». См. сводный вердикт.
```

**Сравнение с v3:**
- Что изменилось: Шаг 3(ж') сработал, но фрагмент укладывается
  как «согласованный дубль» — правило живёт в ADR (обоснование)
  и в трекере (операционная формула), правка структуры не
  нужна. v4 явно различает «обязательный refactor» (β с одним
  правилом в нескольких местах одной природы) и «согласованный
  дубль» (β с разным распределением по ролям).
- Адресует ли правка v4 буксование: частично. Локальный
  фрагмент укладывается в (β). Но v3-full сигнал был
  «пятый случай паттерн-конфликта; с фрагментом 8 семья —
  два реестра, один общий принцип». Это **метапаттерн**
  (повтор паттерна на разных правилах), который v4 не
  фиксирует формально — нет слота «family of rules with
  shared pattern». См. сводный вердикт, сигнал к v5.
- Побочные эффекты: квалификация «согласованный дубль»
  применяется тут более уверенно, чем для фрагмента 8 —
  здесь распределение по ролям (ADR vs трекер) явное, не
  субъективное.

### Фрагменты 17+18 full: Rule 13/14 о стиле чата (раздвоение по адресату)

**Источник:** `.claude/project-instructions.md` строки 128-142
(Rule 13 — terse chat style) + строки 144-169 (Rule 14 —
discussion format). v3-full отчёт, разделы «Фрагмент 17» и
«Фрагмент 18». Обрабатывается как один паттерн раздвоения.

**Цитата (Rule 13):**

> «Baseline behavior in chat is terse: short bullet-style answers,
> "на пальцах". No preamble, no restating the question. No
> wrap-up summary at the end ("so, what I did was…"). … When in
> doubt — shorter.»

**Цитата (Rule 14):**

> «When reviewing documents, working through design forks, or
> discussing substantive choices in chat, use this format:
> Short, focused statement of the question. List of options
> (usually 2-4). Short recommendation. Wait for the user's
> choice — do NOT apply the decision until the user signals
> which option they pick.»

**Результат применения скилла v4:**

```
Классификация:
- Измерение: PIPELINE
- Основные категории: L-CONV PIPELINE (для адресата «Claude в
  чате»)
- Основной вопрос: «как Claude отвечает по умолчанию в чате
  claude.ai (стиль + формат обсуждения)?»
- Тег: precedent (стиль и формат применимы во всех будущих
  чатах).

Место хранения:
- Целевой файл (L-CONV PIPELINE для чата): project-instructions
  Rule 13 + Rule 14 как сейчас.

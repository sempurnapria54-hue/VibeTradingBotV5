# Справочник по доменным моделям торгового бота

## 1. Модели

Это короткий справочник по доменным моделям проекта.
Задача документа — быстро объяснить:

* где должен лежать класс;
* зачем он нужен;
* что он хранит по смыслу;
* какие у него главные инварианты.

---

## 1.1. `domain.model.trade`

Это **торговые модели**.
Они описывают:

* стратегию;
* рыночный контекст;
* свечи и тикеры.

### `Strategy`

**Для чего:** корневая модель стратегии для конкретного инструмента.

**Главные инварианты:**

* привязана к одному инструменту;
* хранит версию стратегии;
* не должна молча переписываться задним числом.

### `StrategyDetails`

**Для чего:** настройки стратегии для конкретной фазы рынка.

**Главные инварианты:**

* принадлежат одной стратегии;
* относятся к одной фазе рынка;
* для одной стратегии не должно быть двух одинаковых деталей на одну фазу рынка.

### `MarketPhase`

**Для чего:** текущая фаза рынка по инструменту.

**Главные инварианты:**

* определяется явно;
* `UNKNOWN` лучше, чем `null`;
* относится к конкретному инструменту.

### `Candle`

**Для чего:** одна рыночная свеча.

**Главные инварианты:**

* относится к одной группе свечей;
* время хранится в UTC;
* для одной группы не должно быть дублей по времени.

### `CandleGroup`

**Для чего:** группа свечей одного инструмента и таймфрейма.

**Главные инварианты:**

* одна группа = один инструмент + один таймфрейм;
* хранит границы покрытия истории;
* статус группы отражает жизненный цикл загрузки свечей.

### `PriceTicker`

**Для чего:** снимок текущей цены инструмента.

**Главные инварианты:**

* относится к одному инструменту;
* хранит актуальные рыночные цены;
* timestamp должен быть биржевым и в UTC.

## 1.2. `domain.model.core`

Это **основные доменные модели**.
Они описывают живые сущности торговой системы:

* сделку;
* ордера;
* защиту;
* позицию;
* инструмент;
* баланс;
* факты исполнения.

### `Deal`

**Для чего:** главная модель одной торговой сделки.

**Главные инварианты:**

* одна сделка относится к одному инструменту;
* в каждый момент у сделки один текущий статус;
* закрытая сделка должна иметь понятный финал.

### `Order`

**Для чего:** обычный биржевой ордер, связанный со сделкой.

**Главные инварианты:**

* имеет внутренний и внешний идентификатор;
* относится к одной сделке;
* live/final semantics должны определяться централизованно.

### `AttachedAlgoOrder`

**Для чего:** защитный algo-ордер, прикреплённый к обычному ордеру.

**Главные инварианты:**

* принадлежит родительскому `Order`;
* не должен жить отдельно от контекста родительского ордера;
* lifecycle должен быть ограничен допустимыми переходами.

### `AlgoOrder`

**Для чего:** самостоятельный algo-ордер сопровождения сделки.

**Главные инварианты:**

* имеет свой внешний algo-id;
* имеет понятный тип и статус;
* live/final semantics должны быть едиными для всей системы.

### `Position`

**Для чего:** текущая позиция по инструменту.

**Главные инварианты:**

* активная позиция — это запись с ненулевым размером;
* закрытие позиции — это перевод в финальное состояние, а не удаление;
* закрытая позиция должна иметь причину закрытия.

### `BalanceContainer`

**Для чего:** snapshot баланса аккаунта целиком.

**Главные инварианты:**

* это snapshot аккаунта, а не lifecycle-сущность;
* привязан к одной бирже;
* содержит актуальный набор валютных балансов.

### `Balance`

**Для чего:** баланс аккаунта по одной валюте.

**Главные инварианты:**

* принадлежит одному `BalanceContainer`;
* относится к одной валюте;
* отражает актуальный валютный snapshot.

### `Instrument`

**Для чего:** торгуемый инструмент биржи.

**Главные инварианты:**

* имеет единый identity внутри системы;
* привязан к одной бирже;
* operational status инструмента должен быть явным.

### `Exchange`

**Для чего:** биржа, с которой работает бот.

**Главные инварианты:**

* имеет уникальное имя;
* хранит базовый URL;
* её статус должен явно отражать состояние использования в системе.

### `TradeFill`

**Для чего:** одно фактическое исполнение сделки на бирже.

**Главные инварианты:**

* относится к конкретному ордеру и инструменту;
* хранит фактическую цену и объём исполнения;
* timestamp должен быть биржевым.

### `TradeFillsArchive`

**Для чего:** информация о файле архива исполнений.

**Главные инварианты:**

* хранит ссылку на архив;
* хранит статус подготовки архива;
* отражает ответ биржи как snapshot.

## 1.3. `domain.model.core` — snapshot-модели внешнего состояния

Это тоже **core-модели**, но отдельного типа.

Их смысл:

* это **снимки фактов с биржи**;
* они **не заменяют** доменные сущности;
* по ним система **обновляет доменные сущности**;
* они нужны для refresh-flow, reconcile и восстановления правды после рестарта.

### `PositionExternalSnapshot`

**Для чего:** внешний snapshot позиции с биржи.

**Главные инварианты:**

* относится к одному инструменту на бирже;
* отражает внешний факт позиции;
* по нему обновляется доменная `Position`.

### `OrderExternalSnapshot`

**Для чего:** внешний snapshot обычного ордера.

**Главные инварианты:**

* хранит внешний статус и параметры ордера;
* может содержать attached protection snapshot;
* по нему обновляется доменный `Order`.

### `AttachedAlgoOrderExternalSnapshot`

**Для чего:** внешний snapshot прикреплённого algo-ордера из `attachAlgoOrds`.

**Главные инварианты:**

* относится к attached-защите обычного ордера;
* хранит внешние идентификаторы и защитные параметры;
* по нему обновляется доменный `AttachedAlgoOrder`.

### `AlgoOrderExternalSnapshot`

**Для чего:** внешний snapshot самостоятельного algo-ордера.

**Главные инварианты:**

* хранит внешний статус, тип и идентификаторы;
* содержит внешний снимок условия;
* по нему обновляется доменный `AlgoOrder`.

### `InstrumentExternalSnapshot`

**Для чего:** внешний snapshot спецификации инструмента.

**Главные инварианты:**

* хранит параметры инструмента в терминах биржи;
* нужен для расчёта размеров и валидации;
* по нему обновляется доменный `Instrument`.

### `BalanceContainerExternalSnapshot`

**Для чего:** внешний snapshot баланса аккаунта целиком.

**Главные инварианты:**

* привязан к одной бирже;
* содержит агрегированные значения аккаунта;
* по нему обновляется доменный `BalanceContainer`.

### `BalanceExternalSnapshot`

**Для чего:** внешний snapshot баланса по одной валюте.

**Главные инварианты:**

* относится к одной валюте;
* отражает внешний ответ биржи;
* по нему обновляется доменный `Balance`.

## 1.4. Базовые и общие модели

Это модели, которые не относятся напрямую ни к trade, ни к core live-сущностям, но используются по всему домену.

### `Auditable`

**Пакет:** `domain.model`

**Для чего:** базовый класс с audit-полями.

**Главные инварианты:**

* хранит внутренние audit-поля системы;
* хранит внешние audit-поля биржи;
* используется как общая база для доменных сущностей.

---

## 1.5. Модели диагностики и аварийного управления

Это модели для:

* аномалий;
* kill-switch;
* снимков состояния при аварийной обработке.

### `AnomalyReport`

**Пакет:** `domain.model.anomaly`

**Для чего:** отчёт о глобальной аномалии системы.

**Главные инварианты:**

* относится к бирже или инструменту;
* хранит before/after состояние;
* имеет собственный lifecycle обработки.

### `KillSwitchResult`

**Пакет:** `domain.model.kill_switch`

**Для чего:** результат выполнения kill-switch.

**Главные инварианты:**

* хранит success/fail итог;
* хранит after-состояние;
* хранит пояснение результата.

### `StateSnapshot`

**Пакет:** `domain.model.kill_switch`

**Для чего:** снимок внутреннего и внешнего состояния для kill-switch/anomaly flow.

**Главные инварианты:**

* хранит отдельно internal и external состояние;
* может хранить active и related inactive сущности;
* используется как техническая модель диагностики.

## 1.6. Модели параметров поиска

Это служебные модели для фильтрации и поиска данных.
Они не описывают бизнес-сущность, а описывают **условия выборки**.

### `AlgoOrderSearchParams`

**Для чего:** параметры поиска algo-ордеров.

### `BalanceSearchParams`

**Для чего:** параметры поиска баланса.

### `CandleSearchParams`

**Для чего:** параметры поиска свечей.

### `InstrumentSearchParams`

**Для чего:** параметры поиска инструментов.

### `OrderSearchParams`

**Для чего:** параметры поиска ордеров.

### `PriceTickerSearchParams`

**Для чего:** параметры поиска тикера.

### `TradeFillsSearchParams`

**Для чего:** параметры поиска исполнений.

## 1.7. Короткий итог по раскладке

### `domain.model.trade`

Только торговые и рыночные модели:

* `Strategy`
* `StrategyDetails`
* `MarketPhase`
* `Candle`
* `CandleGroup`
* `PriceTicker`

### `domain.model.core`

Основные доменные сущности:

* `Deal`
* `Order`
* `AttachedAlgoOrder`
* `AlgoOrder`
* `Position`
* `BalanceContainer`
* `Balance`
* `Instrument`
* `Exchange`
* `TradeFill`
* `TradeFillsArchive`

### `domain.model.core` snapshot layer

Внешние snapshot-модели, по которым обновляются доменные сущности:

* `PositionExternalSnapshot`
* `OrderExternalSnapshot`
* `AttachedAlgoOrderExternalSnapshot`
* `AlgoOrderExternalSnapshot`
* `InstrumentExternalSnapshot`
* `BalanceContainerExternalSnapshot`
* `BalanceExternalSnapshot`

### Отдельные служебные группы

* base: `Auditable`
* anomaly / kill-switch: `AnomalyReport`, `KillSwitchResult`, `StateSnapshot`
* search params: все `*SearchParams`

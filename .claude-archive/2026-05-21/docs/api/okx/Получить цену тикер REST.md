### X.Y Получить цену (тикер) — REST и WS

Тикер нужен боту для:

* расчёта размера ордера (USDT → контракты)
* быстрой оценки текущей цены (перед отправкой ордера)
* мониторинга (без свечей)

Мы разделяем:

* **REST** — snapshot «прямо сейчас»
* **WS** — поток обновлений (быстро и без опроса)

---

## 1) REST snapshot

**Endpoint:** `GET /api/v5/market/ticker`

**Query параметры:**

* `instId` *(обяз.)* — инструмент, например `ETH-USDT-SWAP`

**Доступ / лимиты / аутентификация:**

* Public endpoint (auth **не нужен**)
* Rate limit: **20 requests / 2 seconds**
* Rule: **IP + Instrument ID**

**Пример запроса (curl):**

```bash
curl -X GET 'https://www.okx.com/api/v5/market/ticker?instId=ETH-USDT-SWAP'
```

**Пример ответа (примерный):**

```json
{
  "code": "0",
  "msg": "",
  "data": [
    {
      "instType": "SWAP",
      "instId": "ETH-USDT-SWAP",

      "last": "3116.7",
      "lastSz": "10",

      "askPx": "3116.8",
      "askSz": "25",
      "bidPx": "3116.6",
      "bidSz": "30",

      "open24h": "3050.0",
      "high24h": "3150.0",
      "low24h": "3020.0",

      "volCcy24h": "123456789.12",
      "vol24h": "39500.123",

      "sodUtc0": "3070.0",
      "sodUtc8": "3080.0",

      "ts": "1769253296789"
    }
  ]
}
```

### Описание полей (простыми словами)

**Верхний уровень:**

* `code` — `0`, если успех.
* `msg` — текст ошибки/сообщение.
* `data[0]` — тикер инструмента.

**data[0]:**

* `instType` — тип инструмента (SWAP/...).

* `instId` — имя инструмента.

* `last` — последняя цена сделки (last traded price). Часто это и есть «цена».

* `lastSz` — размер последней сделки.

* `askPx` / `askSz` — лучшая цена продажи и объём в стакане (лучший ask).

* `bidPx` / `bidSz` — лучшая цена покупки и объём в стакане (лучший bid).

* `open24h` — цена открытия 24 часа назад.

* `high24h` / `low24h` — максимум/минимум за 24 часа.

* `vol24h` — объём за 24 часа (в базовой валюте, например ETH).

* `volCcy24h` — объём за 24 часа в котируемой валюте (например USDT).

* `sodUtc0` — цена на начало дня по UTC+0 (Start Of Day).

* `sodUtc8` — цена на начало дня по UTC+8.

* `ts` — время тикера (ms Unix).

## 2) WS поток тикера

**Public WS:** `wss://ws.okx.com:8443/ws/v5/public`

**Канал:** `tickers`

### 2.1 Subscribe

```json
{
  "op": "subscribe",
  "args": [
    {
      "channel": "tickers",
      "instId": "ETH-USDT-SWAP"
    }
  ]
}
```

### 2.2 Пример push-сообщения

```json
{
  "arg": {
    "channel": "tickers",
    "instId": "ETH-USDT-SWAP"
  },
  "data": [
    {
      "instType": "SWAP",
      "instId": "ETH-USDT-SWAP",

      "last": "3116.7",
      "lastSz": "10",

      "askPx": "3116.8",
      "askSz": "25",
      "bidPx": "3116.6",
      "bidSz": "30",

      "high24h": "3150.0",
      "low24h": "3020.0",
      "open24h": "3050.0",

      "vol24h": "39500.123",
      "volCcy24h": "123456789.12",

      "sodUtc0": "3070.0",
      "sodUtc8": "3080.0",

      "ts": "1769253296789"
    }
  ]
}
```

### 2.3 Что важно для бота

* WS лучше для live-торговли, потому что не нужно поллить REST.
* Для расчёта размера можно брать:

    * `last` (быстро)
    * или `bidPx/askPx` (если хочешь консервативно: buy по ask, sell по bid).

---

## 3) Как выбирать между REST и WS

* **При старте приложения:** REST snapshot (чтобы быстро получить текущую цену, даже если WS ещё не поднят).
* **В рантайме:** WS `tickers` как основной источник.
* **Fallback:** если WS упал — временно используем REST.

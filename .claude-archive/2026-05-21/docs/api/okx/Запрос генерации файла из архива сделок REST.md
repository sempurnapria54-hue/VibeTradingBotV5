## Получить архив сделок: **запросить генерацию** (REST)

> Эта операция нужна, когда тебе нужны **fills старше 3 месяцев**.
>
> Логика у OKX такая:
>
> * **последние 3 месяца** — берёшь обычным `GET /api/v5/trade/fills-history`;
> * **старше 3 месяцев и до ~2 лет** — через архив: сначала **POST (запросить генерацию)**, потом **GET (взять ссылку на файл)**.

---

### Endpoint: `POST /api/v5/trade/fills-archive`

**Что делает:**

* Запрашивает подготовку файла с историей сделок (fills) **за выбранный квартал**.
* Покрытие: **до 2 лет назад**, но **не включает последние 3 месяца**.
* Обычно **текущий квартал недоступен** (биржа не отдаёт архив “за текущий квартал”, пока он не завершён).

**Доступ / лимиты / аутентификация:**

* Permission: **Read**
* Rate limit: **10 запросов в день**, правило — **User ID**
* Auth headers (REST private):

    * `OK-ACCESS-KEY`
    * `OK-ACCESS-SIGN`
    * `OK-ACCESS-TIMESTAMP` (ISO строка в UTC, например `2026-01-24T12:34:56.789Z`)
    * `OK-ACCESS-PASSPHRASE`
    * `Content-Type: application/json`
* Demo trading: добавить `x-simulated-trading: 1` (только для demo)

***Как считается подпись (важно для “рабочего” реквеста):***

* `prehash = timestamp + method + requestPath + body`, затем `HMAC_SHA256(secret, prehash)` и Base64.
* Для этого запроса body **не пустое** (JSON с year/quarter).

---

## 1) Параметры запроса

**Body (JSON):**

* `year` *(String, required)* — год из **4 цифр**, например `2025`.
* `quarter` *(String, required)* — квартал: `Q1`, `Q2`, `Q3`, `Q4` (**регистр важен**, только так).

---

## 2) Пример запроса

```bash
curl -X POST 'https://www.okx.com/api/v5/trade/fills-archive' \
  -H 'Content-Type: application/json' \
  -H 'OK-ACCESS-KEY: <api_key>' \
  -H 'OK-ACCESS-SIGN: <base64_hmac_sha256_signature>' \
  -H 'OK-ACCESS-TIMESTAMP: 2026-01-24T12:34:56.789Z' \
  -H 'OK-ACCESS-PASSPHRASE: <passphrase>' \
  -d '{
    "year": "2025",
    "quarter": "Q3"
  }'
  # -H 'x-simulated-trading: 1'   # только для demo
```

---

## 3) Пример ответа

```json
{
  "code": "0",
  "data": [
    {
      "result": "false",
      "ts": "1646892328000"
    }
  ],
  "msg": ""
}
```

---

## 4) Описание полей ответа (простыми словами)

**Верхний уровень**

* `code` — `"0"`, если успех.
* `msg` — текст ошибки/сообщение.
* `data[0]` — результат по запросу генерации:

**data[0]**

* `result` — **есть ли уже готовая ссылка на файл** для этого года+квартала:

    * `"true"` — ссылка **уже существует** (скорее всего ты уже когда-то запрашивал этот квартал), можно сразу идти за ссылкой через `GET /api/v5/trade/fills-archive`.
    * `"false"` — ссылки ещё нет, биржа **начала генерацию**.
* `ts` — время, когда сервер **впервые принял** этот запрос (Unix ms).

**Про ожидание (важно):**

* Если `result=false`, OKX пишет, что файл может генерироваться **долго (порядка десятков часов)**.
* Если прошло **сильно больше 48 часов** и ссылки всё ещё нет — обычно рекомендуют писать в поддержку.

---

## 5) Что делать дальше (связанный шаг)

После `POST` ты периодически дергаешь:

* `GET /api/v5/trade/fills-archive?year=YYYY&quarter=Qn`

Он вернёт:

* `state`: `ongoing` (ещё делает) или `finished` (готово)
* `fileHref`: ссылку на файл

> Важно: `fileHref` обычно **временная ссылка** (по времени жизни зависит от правил OKX), поэтому скачивать лучше сразу.
